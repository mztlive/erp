# API 供应商批量选品入库执行合同

版本：V1 设计待确认。日期：2026-10-27。

## 1. 效力与交付顺序

1. 本合同规定 API 供应商品库的批量选品、公司销售参考价计算、建档资料补齐、预览确认和异常恢复。执行主体为具备相应权限及数据范围的采购、运营人员。
2. 本次交付顺序固定为：合同落盘 → 各页面及关键状态效果图 → 用户全部确认 → 开发 → 质量检查 → 按合同与确认稿逐项验收。
3. 页面效果图未全部获得用户明确确认前，不得修改生产前后端代码，不得将效果图确认推定为已完成开发或运行验收。
4. 当前设计与确认登记见 [页面设计与确认清单](designs/supplier-api-batch-adoption/README.md)。全部条目初始为“待确认”；仅收到对应用户确认后更新。
5. 现有商品身份、自动匹配、来源单位、条码、资料同步、供给与上架规则继续执行 [供应商 API 商品与自动履约执行合同](supplier-api-product-contract.md)。界面执行 [ERP 界面设计合同](erp-ui-design.md)。
6. 本合同新增的显式批量定价规则在用户确认并完成开发后生效；不得据此改变当前运行行为。禁止隐式从供应商条款推断公司价格的原约束继续有效，新增例外仅为“用户主动选择计算规则、查看逐项结果并确认保存”。
7. 开发时必须同步修订主合同第 4.11 条，登记上述显式计算例外，并在主合同和界面合同补充本合同入口；不得保留互相矛盾的现行条款。
8. 工作区已有改动必须保留。提交、推送、重启、部署及真实页面验收分别记录，不得将其中任一项视为其他项已完成。

## 2. 业务边界与价格归属

| 对象 | 本次允许行为 | 禁止行为 |
| --- | --- | --- |
| 接口原始报价 | 只读展示、作为用户选择的计算基础 | 手工改价、缺失时补造价格 |
| API 采购供给价 | 按现行合同使用来源采购价，保留来源关联与修订历史 | 因公司加价规则而改变采购成本、虚构集采条款 |
| 公司销售参考价 | 为本次新建 SKU 显式计算或人工填写代发价、集采价及起订量 | 自动覆盖已存在 SKU 的价格 |
| 公司商品资料 | 新建时补齐公司分类、名称等必要资料；沿用已有商品身份规则 | 修改来源原文、强制合并冲突身份 |
| 仓库与财务 | 无写入 | 选品入库生成库存、收货、应付或付款事实 |
| 上架状态 | 新建 SKU 保持未上架；结果提供现有公司商品入口 | 入库时自动上架；重新启用已有停用商品 |

1. “代发价”“集采价”在批量定价界面均须标明为公司销售参考价（含税）；接口价格须标明为“接口采购报价”。
2. 来源只支持代发时，可以维护公司集采参考价，但不得由此宣称该来源支持集采采购。有关行必须显示“本供给仅支持代发”；集采采购资格仍执行供给能力与条款校验。
3. 未提供接口采购报价的来源 SKU 不得通过手工填公司售价绕过入库限制。明确零价为有效来源报价，不得与空值混淆。
4. 新增规格按新建 SKU 定价；自动关联已有 SKU 时，该 SKU 的原公司价格、上架状态及展示资料全部保留，本次只建立符合原合同的供给关联。
5. 本次不得新增目标 SKU 选择器，不得提供强制新建、强制关联或忽略身份冲突的操作。

## 3. 版本范围与场景覆盖

### 3.1 本次必须交付

1. 按单个或多个来源分类、品牌、关键词、接口采购报价闭区间、可供状态与选品状态组合筛选。
2. 分类层级由来源明确提供时支持“包含子分类”；来源无可靠层级时禁用该选项并说明原因，不得按名称猜测父子关系。
3. 按当前页、跨页人工勾选或全部筛选结果选择；全部筛选结果支持逐项排除与恢复。
4. 以来源 SKU 为选择单位；支持从一个来源商品中只选择部分规格。显示商品数及 SKU 数，不混用计数。
5. 可选择只处理未入库项；混合批次识别已完成、新建、已有商品新增规格、关联已有 SKU 和异常项。
6. 公司代发、集采参考价独立配置：不设置、按接口采购报价加比例、增加固定金额、指定金额。集采另支持“与公司代发价相同”。
7. 批量设置公司集采起订量，且与公司集采参考价同时填写或同时留空。
8. 公司分类批量设置与来源分类映射；批量补齐进项税率、供给有效期及配送模板，保持现行供给约束。
9. 所有批量补值区分“仅填空值”和“覆盖本批未入库项”；保护单项人工调整，明确清空与未填写的差别。
10. 提供逐项预览、单项例外修改、来源版本复核、按项提交、结果汇总和仅重试明确失败项。
11. 提交后后台持续处理，支持离开页面和刷新后查看结果；不得要求用户每 50 条重复点击确认，不得将前端循环视为可靠后台任务。

## 4. 选择范围与冻结

1. 每批只能来自同一 API 连接及其所属供应商；跨连接选品须建立不同批次。
2. 同一筛选项的多个分类或品牌按“或”匹配；不同筛选项按“且”匹配。空区间不限；区间允许单边，金额非负，最低值不得高于最高值。
3. 列表表头复选框只选择当前页；选择条另提供“选择全部 N 个 SKU”。文案必须同时显示当前页数量、总结果数量、已排除数量及最终已选数量。
4. 翻页和排序保留选择。应用不同筛选条件时清空选择及排除项，并明确提示；不得将旧选择悄悄带入新筛选范围。
5. 全筛选选择由服务端创建有归属的选择快照，记录筛选条件、当时匹配的来源 SKU 集合及排除项。浏览器不得只提交已加载页冒充全部结果。
6. 下一步进入作业批次时使用冻结集合；之后新同步的商品不得自动加入。来源值变化不改变成员集合，但必须触发对应行重新核对。
7. 首次选择状态与最终匹配结果分别保存；来源已选品状态在预览或提交前变化时，按真实绑定重新分类，不得重复建品。
8. 返回修改选择且批次中已有编辑时，应明确提示需重新核对受影响项；已提交批次不能修改范围。
9. 分类、SKU、供应商、品牌和成本读取均须经过当前用户的权限及数据范围校验。无成本权限不能通过价格筛选、公式结果、错误信息或导出推算隐藏成本。

## 5. 定价与单项值合并

### 5.1 计算方法

以 B 表示本行已核验的接口含税采购报价，以 r 表示用户输入百分数，以 a 表示加价金额，以 p 表示指定金额。

| 方法 | 计算 | 校验 |
| --- | --- | --- |
| 不设置 | 保持本行现有草稿值；新行为空 | 不等于清空 |
| 按比例加价 | B × (1 + r / 100) | r 非负，最多四位小数；本版不提供负比例降价 |
| 增加固定金额 | B + a | a 非负，最多两位小数 |
| 指定金额 | p | p 非负，最多两位小数 |
| 集采与代发相同 | 取本行最终公司代发价 | 先处理本行代发例外，再计算集采；代发为空时阻断联动 |

1. 公司销售参考价最终统一保留两位小数，使用定点十进制、四舍五入（非负数半入）。完整乘法后仅在最终结果舍入一次；前后端必须一致。
2. 所有规则从选定来源 B 重新计算，不得在上次生成的销售价上继续叠加。重新应用加 15% 不得变成加 32.25%。
3. 比例、金额、起订量使用十进制字符串传输；禁止二进制浮点、Number、parseFloat 或 epsilon 比较。
4. 计算结果须展示来源金额、规则和公司最终金额。示例：100.00 × 1.15 = 115.00；10.10 × 1.15 = 11.62。
5. 毛利率不属于本版方法，不得将加价比例标为毛利率。
6. 基础报价为空时比例与加额法不产生结果；不能取零或来源市场价代替。报价明确为零时可正常计算。
7. 指定金额不依赖 B 计算，但该行入库仍必须满足来源报价等原合同资格。
8. 规则只作用于本批新建 SKU，包括已有商品新增规格；已存在 SKU 的原售价只读展示并标“保留原价”。
9. 本版不批量重算公司市场价。新 SKU 维持现有来源市场价预填、单项修改和显式清空规则。
10. 公司集采价与公司集采起订量须成对存在；起订量大于零且最多六位小数。不得将供应商 MOQ 自动复制为公司门槛。
11. 公司集采价高于代发价、公司销售价低于本行接口采购报价时列为待确认提示，不自动改价。用户逐项或按同类明确确认提示后可按现行价格合法性规则提交；该提示不表示完整经营利润。

### 5.2 合并顺序

1. 值来源须区分：来源预填、批量规则、单项人工、明确清空、已有 SKU 保留。不得仅用空字符串表示所有状态。
2. “仅填空值”是默认模式：只填写尚未设置且未被用户明确清空的本批新建项；已有关联 SKU 不参与。
3. 用户选择“覆盖本批未入库项”时，重算批量规则生成值及可替换的预填值；默认保留单项人工值和明确清空值。
4. 覆盖单项人工值必须额外明确选择，并在应用前显示影响行数；操作完成后不得仍标为人工保留。
5. 单项保存时显示“已单独调整”；可以恢复为批量规则。恢复后按最新已核验来源重算，原预览失效。
6. “集采与代发相同”只对未单独覆盖集采价的行保持联动；单项覆盖集采价时解除该行联动并明确显示。
7. 编辑规则、映射、税率、配送或逐项值均使相关最终预览失效；未重新预览前不得提交。

## 6. 资料补齐

1. 来源分类映射只影响允许新建的公司商品；已有商品新增规格沿用既有分类、品牌与类型。关联已有 SKU 保留原资料。
2. 可将多个来源分类统一映射为一个启用公司分类，也可逐来源分类分别映射；不得自动新建公司分类。分类必须与商品类型一致。
3. 同一来源商品的多个规格必须归入同一公司商品；映射冲突按该来源商品整体标记，禁止按不同类目拆成多个商品绕过冲突。
4. 进项税率、供给生效与失效时间、配送模板按照现有供给规则补齐。配送模板必须属于当前供应商，不得扩大来源配送能力。
5. 供给失效时间必须晚于生效时间。税率修改不得反向改变接口含税采购报价。
6. 单位继续执行现有来源值与建议核对；本版仅允许单项选择，不提供无条件整批换单位。
7. 公司名称、介绍与图片等继续复用现有资料合同。来源图片未核验时展示真实提示，仅使用已核验图片，不伪造素材齐全。

## 7. 页面与交互合同

### 7.1 页面清单

| 设计号 | 页面或状态 | 入口与主要动作 | 必须呈现 |
| --- | --- | --- | --- |
| P01 | 供应商品库与批量选择 | 现有商品库；“配置入库” | 分类品牌筛选、报价区间、可供与选品状态、跨页全选与排除、商品/SKU 数量 |
| P02 | 批量入库：设置售价 | P01 后进入独立工作区标签；“下一步：补齐资料” | 来源范围摘要、代发与集采独立方法、公司集采门槛、填值模式、计算样例 |
| P03 | 批量入库：补齐资料 | “下一步：核对入库” | 来源分类映射、供给税率与有效期、配送模板、待补项数量 |
| P04 | 批量入库：核对入库 | “确认入库 N 个 SKU” | 自动匹配类别、原始报价与最终售价、保留原价、人工例外、就绪与待处理项 |
| P05 | 单项调整对话框 | P04 行“调整”；“保存调整” | 当前来源身份及只读报价、公司售价与门槛、名称与单位等可编辑项、恢复批量规则 |
| P06 | 入库结果：部分完成 | 提交后与批次重开；“处理待办” | 总量、成功、失败、待补、待核实与剩余进度、公司商品入口 |
| P07 | 待处理商品：修正与重试 | P06；“重新核对 N 项” | 按原因分类、可编辑修正项、来源变化对比、结果待核实的独立处理 |

1. P02、P03、P04、P06、P07 复用同一批次工作区身份与主路由，例如 `/supplier-api/catalog/adoptions/[batchId]`，步骤由可恢复的页面状态区分，不增加五个一级菜单。
2. P05 使用编辑 Dialog，不把可编辑表单放进只读轻预览 Sheet。商品库原有点读保持只读轻预览。
3. 顶部保留供应商名称、批次业务编号与步骤；底部保留上一步、主动作及影响数量。多商品操作使用完整作业面，禁止把千行任务塞进固定高度的小弹窗。
4. P02/P03 离开或关闭时，未保存修改须提示；提交后的任务允许离开并持续执行。草稿保存使用服务端持久化，明确保存中、已保存与保存失败，保存失败时不能假定刷新可恢复。
5. P04 的“可入库”范围默认全部选中；异常项保持未选且不可直接提交。确认文字明确本次只提交就绪项，待补项保留在同一批次。
6. P04 提交范围不得隐含所有预览项。需显示“将入库 N 个 SKU，M 个待处理，K 个已完成跳过”。
7. 列表数值列右对齐，名称与规格组合显示；主要列控制数量，低频字段通过列设置或单项对话框查看。
8. 主要按钮使用现行中性主色；成功、待处理、失败使用现行语义状态色。遵守 ERP 字体、圆角、密度与间距令牌，不创设新配色体系。
9. 桌面设计以 1440 × 1024 为基准；窄窗口保留所有操作、表格内横向滚动、工具栏换行，页面整体不得横向撑破。
10. 所有生产交互目标使用稳定唯一原生 DOM id，沿用现有可复用 id，新增采用 `supplier-catalog-batch-*` 语义前缀及稳定业务键。

### 7.2 状态矩阵

| 状态 | 用户呈现 | 可执行动作 |
| --- | --- | --- |
| 无匹配商品 | 空结果与当前筛选 | 修改或清空筛选；禁用配置入库 |
| 读取或保存失败 | 具体失败原因，保留筛选与输入 | 重试读取或保存 |
| 连接不可用 | 原因与 API 设置入口 | 查看设置；禁用新增确认 |
| 无成本权限 | 不返回或显示成本，不提供依赖成本的计算 | 仅按现有授权浏览或操作 |
| 无入库权限 | 保留可读内容并解释不可操作原因 | 不提供可绕过入口 |
| 计算或匹配中 | 真实进度或加载状态 | 不允许提交过期结果 |
| 只有待补项 | 待补原因与数量 | 补齐、排除；不允许零项提交 |
| 来源或目标版本变化 | 受影响行的新旧信息 | 重新核对；旧结果不得继续提交 |
| 部分成功 | 各类结果数量与明细 | 查看成功商品，处理剩余项 |
| 结果待核实 | 明确与失败区分 | 查询原操作结果；禁止直接重提 |
| 批次全部完成 | 成功、跳过及排除数量 | 查看公司商品，返回商品库 |
| 草稿恢复 | 已保存内容及重新核对提示 | 恢复编辑；预览后提交 |

## 8. 批次、后台执行与恢复

1. 批次服务端保存供应商与连接、归属账号、选择快照、规则及版本、逐项输入、人工覆盖、最后预览、确认记录和执行结果。业务编号使用现有统一编号机制，页面不显示内部 ID。
2. 批次读写和任务结果查询必须重新核对当前权限及数据范围；不能只检查创建人，也不能因同角色自动授予访问。
3. 批量计算与匹配由服务端产生权威结果。前端样例只用于辅助预览，提交金额由服务端核对。
4. 批次确认冻结本次执行集合及载荷。客户端不得在提交中途改价或更改映射。
5. 后台任务复用现有任务基础设施，分页处理、有界并发、保留真实进度；逐项事务写入商品、SKU、条码、供给及来源关系，继续遵守原合同中单位创建的独立事务约定。
6. 一行明确失败不回滚其他成功行。跨行共享商品及来源身份的处理遵守现有自动匹配与并发约束。
7. 任务重启从可证明的结果恢复。相同来源 SKU、相同操作号不得重复建品；异载荷必须拒绝。
8. 将状态至少区分为待补齐、可提交、处理中、成功、明确失败、结果待核实和已完成跳过。批次排除记录不属于执行失败。
9. 明确失败项修正后先重新匹配与定价，再对新确认载荷发起操作。原操作结果未知时保持原身份查证，禁止生成新操作号重放。
10. 同一批次内来源报价变更时，受影响行必须重新计算并由用户确认；禁止后台采用未展示的新售价。未受影响的就绪项可按用户确认范围继续。
11. 结果统计必须互斥且总量闭合；后台取消、断线或刷新不得将未处理项标为成功。
12. 不得将本批全部行放进一个长数据库事务，不得在事务内调用供应商接口或下载素材。

## 9. 设计确认与实现约束

1. P01—P07 各提供独立图片，统一示例供应商、批次数量、商品与价格口径。图片只用于设计确认，示例数量不得冒充真实业务数据。
2. 设计说明必须给出控件行为、计算与状态规则，图片不能替代行为合同。图片与本合同冲突时先修订不一致内容，再提交确认，不得擅自选择实现方向。
3. 默认不使用浏览器或电脑控制。现阶段通过现有源码、主题及合同建立视觉依据，不宣称图片是当前页面截图。
4. 用户要求改图时先更新图片与设计说明，再确认。未经确认的新版图不得替换已确认开发基线。
5. 全部页面与关键交互确认后，才开始后端方案细化与编码。改后端前读取 `backend/AGENTS.md`、crate 目录及所属 README；改前端前读取 `erp-client/AGENTS.md` 和本地 Next 文档。
6. 实现遵守领域依赖方向，业务计算由领域/Process 拥有，Handler 与前端不得复制权威业务规则。权限生成物随真实权限改动生成，不得手写。
