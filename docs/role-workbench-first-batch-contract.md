# 岗位工作台第一批实施与验收合同

## 1. 范围与发布条件

本批次限于销售（WB-01）、采购（WB-03）、出纳（WB-04）。其他模板不得出现在可选岗位中。

本文件定义已实现接口和候选页面的验收口径。发布必须完成产品规格 AC-01～AC-19 中适用场景的真实账号、数据和交互验收；编译及单元测试不得替代发布验收。未经核验的指标不得补成零值或历史趋势。

| 模板 | 独立地址 | 核心入口权限 | 页面分析 |
| --- | --- | --- | --- |
| 销售 | `/workspace/roles/WB-01` | `sales_order:list`、`sales_inquiry:list`、`work_item:list` | 当前销售单阶段；客户跟进任务时限 |
| 采购 | `/workspace/roles/WB-03` | `purchase_order:list`、`procurement_inquiry:list`、`work_item:list` | 当前采购执行阶段；采购任务时限 |
| 出纳 | `/workspace/roles/WB-04` | `customer_receipt:list`、`supplier_payment:list`、`work_item:list` | 收款及付款未分配余额；付款任务时限 |

权限仅为入口最低条件。每个业务接口必须继续执行原有对象范围和金额授权，任务必须继续核验本人实际处理资格。

## 2. 角色映射与入口

- 角色创建、更新、列表使用 `workbenches` 字段。取值仅允许 `WB-01`、`WB-03`、`WB-04`，重复值去重；未知编号拒绝。
- 旧角色文档缺省字段解析为空集合。更新请求省略字段保持原值；显式空集合清除映射。
- 映射修改复用角色配置授权、审计和策略版本事务。不得通过配置工作台增加权限策略或数据范围。
- 当前账号资料返回启用角色显式映射与核心权限的交集。角色展示名称不得参与匹配，超级管理员权限不得自动产生岗位映射。
- 显式新建内建 `role-sales`、`role-procurement`、`role-cashier` 时持久化推荐映射。现有内建角色不得自动改写；管理员须进入角色编辑页确认配置。
- `/workspace` 无查询参数时解析岗位首页。顺序为：本账号上次使用、默认岗位、唯一可用岗位、岗位选择页。首次多岗位选择须同时保存默认项。
- 本浏览器使用 `erp:role-workbench:<userid>` 保存上次与默认选择。存储被禁用时仍允许进入；不保证跨浏览器同步。页头“设为默认首页”或账号菜单“个人首页设置”（`/account/workbench`）修改默认项。
- `/workspace?queue=1` 为我的全部待办。已有带筛选参数的工作台链接、任务/审批/抄送详情继续可达。岗位返回地址只允许本批三个固定地址。
- 没有可用映射时，有待办权限的账号进入统一待办；否则显示暂无可用工作台。深链接失去入口资格时停止挂载岗位数据组件。

## 3. 指标与图表登记

销售单与采购单必须叠加当前账号负责人筛选；询价与账款显示各自实际授权范围，不得统称为本人金额。

所有列表计数必须取服务端 `total`，不得累计分页条目。所有余额必须取服务端 `summary`，不得累计分页金额。每项下钻复用原查询条件和权限接口。

除新增销售单外，下列数据均为“截至当前”，不随期间筛选变化。新增销售单按 Asia/Shanghai 创建日期统计，默认本月迄今，支持上月、本季迄今及自定义起止日；接口使用现有秒级包含端点日期合同。金额沿来源资金服务含税余额口径展示为元，不执行汇率换算。

| 标识/图表 | 业务对象与去重 | 纳入条件及计算 | 接口与下钻 | 分类/责任岗位 |
| --- | --- | --- | --- | --- |
| `sales-created` | 销售单 ID | 创建日期在选定期间；包含草稿；数量不代表成交 | `/admin/sales-orders` 创建日期筛选；指标详情同条件 | A / 销售 |
| `sales-review` | 销售单 ID | 当前 `pending_review` 总数 | 销售单列表相同状态 | A / 销售 |
| `sales-feedback` | 询价 ID | 当前 `awaiting_sales` 总数 | 销售询价列表相同状态 | A / 销售 |
| `purchase-inquiries` | 询价 ID | 本人开放询价责任关联的询价总数；同询价多任务不重复计单 | 采购询价列表 `task_status=open` | A / 采购 |
| `purchase-review` | 采购单 ID | 当前审批中采购单总数 | 采购单列表 `metric=review` | A / 采购 |
| `purchase-fulfill` | 采购单 ID | 当前 `EFFECTIVE` 总数；不得解释为有承诺日期的待到货数 | 采购单列表相同状态 | A / 采购 |
| `purchase-partial` | 采购单 ID | 当前 `PARTIAL` 总数 | 采购单列表相同状态 | A / 采购 |
| `receivable-balance` | 应收子账 ID | 资金服务应收未收汇总 | 客户往来应收视图及指标详情 | A / 销售、出纳 |
| `receivable-overdue` | 应收子账 ID | 资金服务逾期未收汇总；不得从当前页计算 | 客户往来应收视图及指标详情 | A / 出纳 |
| `payable-balance` | 应付子账 ID | 资金服务应付未付汇总 | 供应商往来应付视图及指标详情 | A / 出纳 |
| `receipt-balance` | 回款记录 ID | 资金服务未分配余额；分配不算新增收款 | 客户往来回款视图及指标详情 | A / 出纳 |
| `payment-balance` | 付款记录 ID | 资金服务未分配余额；分配不算新增付款 | 供应商往来付款视图及指标详情 | A / 出纳 |
| 销售阶段 | 销售单 ID | 草稿、审核中、生效、作废分别统计；状态互斥 | 每个柱条旁的状态入口打开同状态明细 | A / 销售 |
| 采购阶段 | 采购单 ID | 草稿、审核中、生效、部分执行分别统计；仅表示所列状态 | 每个柱条旁的状态入口打开同状态明细 | A / 采购 |

任务时限接口在 `/admin/work-items/stats` 增加 `work_item_type_timing`，与 `work_item_type_counts` 使用同一次授权扫描及 `as_of`。无截止时间不计入今日或超期。今日到期与超期可以重叠，禁止相加为总任务数。滚动部署遇到缺少时限字段时显示不可用，不补零。

## 4. 业务分析与紧要事项

### 4.1 页面结构

三个岗位首页以核心指标、阶段或资金分布及任务时限分析为主体。常用业务入口保留在分析区域。页面不得按任务或审批类型铺开处理清单，不得为零任务类型展示独立空态。

岗位任务时限按以下固定类型统计，与紧要事项分别展示，不得把紧要事项的已加载条数当作统计数量。

| 岗位 | 任务时限统计类型 |
| --- | --- |
| 销售 | `SALES_INQUIRY_PROCESSING`、`CUSTOMER_ACCEPTANCE_REGISTRATION` |
| 采购 | `PROCUREMENT_ORDER_CREATION`、`PURCHASE_PAYMENT_ARRANGEMENT`、`PURCHASE_SOURCE_UPDATE` |
| 出纳 | `SUPPLIER_PAYMENT_EXECUTION`、`PURCHASE_RETURN_REFUND` |

### 4.2 紧要事项筛选与排序

1. 紧要事项使用本人完整开放且可处理队列 `scope=mine`，包含审批及兼岗任务；不得按当前岗位固定类型截断。岗位、期间切换不改变该筛选范围。
2. 依次展示已超期、今日到期、服务端优先级 `urgent`、服务端优先级 `high` 的事项。普通及低优先级事项只有命中前两项时才纳入；缺截止时间不得自行判为今日到期或超期。
3. 超期与今日到期边界复用任务服务的 Asia/Shanghai 规则。今日已超期任务可同时命中两个来源，但只展示一次，原因为“已超期”。
4. 使用既有 `/admin/work-items` 接口分别传入 `due=overdue`、`due=today`、`priorities=1`、`priorities=2`；服务端须先完成筛选与授权再分页，各来源只读取第一页 5 项，排序为 `due_asc`。
5. 按上述来源顺序、截止时间、稳定任务 ID 排序；无截止时间的优先级事项按现有服务端空日期优先规则排序。按任务 ID 去重后，整个紧要事项区域最多展示 5 项，不得改为每类 5 项。
6. 各来源前 5 项合并只用于选取首页条目，不得求和或根据去重后的候选数量推算紧要事项总数。
7. 每条仅展示业务对象、事项类型、紧要原因、截止时间及“查看待办”入口，进入既有处理页并保留工作台返回地址。提交时仍由服务端重新核验处理资格。
8. 所有来源成功且均无匹配项时，仅显示“当前无紧急待办”和完整待办入口，不得解释为全部工作已完成。
9. 任一来源失败时须明确显示列表可能不完整并提供重试，不得显示无紧急待办；成功来源可继续展示，失败来源缓存不得作为当前结果展示。
10. 页面始终保留“我的全部待办”入口。非紧要事项及未进入首页前 5 项的事项继续在完整待办中心处理。

全局角标继续调用本人完整开放任务计数，不得将上述来源数量、类型数量或各岗位数量相加。

## 5. 刷新与故障

- 任务统计与紧要事项每 60 秒刷新，业务汇总每 5 分钟刷新；隐藏页面不进行周期刷新。
- 相同账号、权限版本、组织版本和来源查询共享缓存；岗位映射参与概览缓存身份。
- 已知写操作成功后立即失效岗位查询；手动刷新失效工作台查询集合。
- 模块单独显示加载、失败及重试；失败数据不得继续作为当前数值展示。
- 各业务模块显示来源范围与更新时间；任务时限显示服务端统计时点。不得把客户端当前时间冒充来源更新时间。
- 图形旁必须提供可读数值表和键盘可达下钻。金额比例仅用于绘图，保留定点金额作为显示与业务依据。

## 6. 迁移、回滚与部署顺序

1. 先部署支持角色字段、账号岗位集合、任务类型时限及询价范围元数据的后端。
2. 部署前端；使用角色配置权限为现有角色选择岗位，不得直接覆盖权限策略或责任配置。
3. 不要求全量 Mongo 回填；旧文档空映射采用待办回退。
4. 回滚入口时先回滚前端；后端新增字段保持兼容。需要停用某角色岗位时通过角色更新接口写入 `workbenches: []`，保留审计和策略版本更新。禁止通过直改数据库绕过缓存失效。
5. 本批不得执行业务数据迁移、审批配置迁移或任务改派。

## 7. 验收执行与未交付项

验收须分别使用销售、采购、出纳、兼岗、自定义角色、无范围、受限金额和被撤权账号。固定数据快照逐项对拍指标详情、状态分布与任务筛选；覆盖日期边界、同日已超期、缺截止日期、部分分配和撤销权限。核对 1440/1024/768 宽度、键盘操作、失败重试、返回筛选和账号切换。性能记录须包含数据规模、并发、缓存状态、首批及完整模块延迟。

本批不发布生效订单金额历史、采购生效金额趋势、实际收付款历史趋势、未来应付到期结构、供应商准时率、转化率、目标完成率和重大风险评分。其余七个岗位须在三样板验收后实施。

以下项目不计为已验收交付：真实业务数据对拍、多账号授权验收、浏览器布局与交互、性能基线、跨浏览器默认首页同步。
