# 工作台查询与筛选合同

## 1. 页面与责任范围

1. 工作台仅保留一层范围导航：待我处理、我发起的审批、抄送给我、处理记录、范围内待办。导航可见性沿用账号权限；范围内待办仍受管理范围约束。
2. 任务和审批类型不设置第二层 Tab。待办、本人发起审批及处理记录统一使用“事项类型”多选框，类型名称须区分审批和执行事项。
3. 处理记录沿用后端 `history` 授权合同，包括本人可读记录及具备管理资格时可读的范围内记录，不标为“我处理的”。
4. 抄送收件箱保留接收人授权、阅读状态、审批类型、单号查询和每页 20 条；审批类型使用下拉框，不再设置类型按钮导航。
5. 工作台其他范围每页 50 条。总数由服务端计算；本人发起审批必须支持完整结果翻页。

## 2. 查询条件与交互

1. 常用查询区提供关键词、事项类型、往来方及截止快捷条件。更多筛选提供处理人、来源销售单、来源采购单、办理状态、仓库、业务类型和时间区间。
2. 同字段多选按“任一符合”，不同字段与关键词按“同时符合”。往来方、仓库和业务类型使用当前授权资料中的名称精确匹配；处理人和来源单据使用稳定身份。
3. 时间区间按上海时区自然日计算，包含开始日与结束日。任务支持进入时间、截止时间；处理记录另支持处理时间；本人发起审批支持提交时间。无时间值不等于零，不纳入有界日期区间；“未设置所选时间”独立筛选。
4. 今日到期、已超期沿用服务端到期窗口定义。截止快捷条件与自定义日期区间不得同时生效。
5. 查询条件编辑后点击“查询”统一生效。已生效条件显示可逐项移除的标签，并提供全部清除。查询条件写入 URL；旧类型、处理人、来源单据、到期和受阻参数须恢复成可见条件。
6. 待办、本人发起、管理范围、处理记录之间切换保留关键词；当前页面生命周期内分别保留各范围的条件。切换范围、查询或排序后回到第一页。
7. 受阻筛选必须复用正式任务投影的审批上下文、负责人资格和办理状态，不得通过原因码或显示文字猜测。

## 3. 服务端检索

1. 业务关键词、结构化匹配、候选项检索、总数与分页必须由服务端完成。前端不得对已加载事项进行本地搜索、筛选或推算总数。
2. 关键词采用忽略大小写的字面量包含匹配，不解释正则表达式。检索字段包括单号、来源单号、往来方、处理人姓名、商品名称和规格、可读事项摘要。内部 ID 不作为关键词字段。
3. 销售、卡券销售及采购提交按事项的精确单据身份与提交版本读取全部商品行，并支持 SKU 编号。采购分派任务只搜索该任务责任范围内的全部商品行；履约任务搜索实际装配的交付明细。
4. 审批已冻结关联销售版本时，来源单号、客户及全部商品名称、规格须从该冻结版本读取。版本身份不一致或读取故障须返回错误；历史缺少冻结关联资料时不得读取当前单据补齐。
5. 其他事项只检索其已授权的业务摘要字段，不推断未保存的商品或来源。搜索命中不授予关联对象的额外读取权限。
6. 每项最多返回三条 `search_matches`，说明命中字段及业务内容。列表显示命中说明，完整结果仍沿用原有服务端排序。
7. 选项从完整授权候选集中取得，不受当前结果页限制。每个字段默认返回最多 100 个候选，并保留当前授权范围内已选条件的显示名称；输入检索词后在服务端完整候选集中重新匹配。无法取得名称时不得显示内部 ID。
8. 账号无权限、授权事实缺失、数据范围变化、网络及服务端错误必须保留错误反馈，不得展示为合法零条。

## 4. 接口与一致性

1. `GET /admin/work-items` 沿用 `scope`、`q`、排序及分页参数，新增 `filters` JSON 字符串；返回新增 `filter_options`，事项新增 `search_matches`。
2. `filters` 支持 `item_types`、`counterparties`、`handlers`、`sales_orders`、`purchase_orders`、`warehouses`、`business_types`、`statuses`、`due`、`date_field`、`date_from`、`date_to`、`undated`、`blocked`、`include_options`、`option_query`。数组最多 100 项，单值最多 256 字，候选检索词最多 128 字；未知字段和非法日期须拒绝。
3. 事项类型值采用 `approval:<document_type>` 或 `task:<work_item_type>`。`task:DOCUMENT_APPROVAL` 表示全部审批任务，兼容原任务类型入口。
4. `GET /admin/approval-instances?view=started&page=1&limit=50` 启用工作台内容查询，支持 `q` 和相同 `filters`。页码模式不得与游标混用；其他视图不得使用该页码模式。旧游标模式保持原合同。
5. 页码模式的 `total` 为完整授权集经过所有查询条件后的数量，`next_cursor` 为空。`document_type_counts` 为结构化条件应用前、当前运行查询范围内的审批类型数量；页面范围导航使用独立的无筛选统计。
6. 待办查询在同一事务内完成授权、匹配、计数、分页和投影。后续页必须回传第一页的 `scope_version`；范围或结果版本变化须拒绝拼页，刷新返回第一页。
7. 本人发起审批使用有界游标批次扫描，事务内完成精确版本资料检索、匹配和分页，不逐页重复计算全量类型统计。

## 5. 验证要求

1. 后端库单元测试覆盖字面量查询、跨维度组合、日期首尾日及空值、完整内容先筛选后分页、候选超出首批后仍可检索、精确版本身份，以及 HTTP 页码与游标互斥。
2. 前端完成 lint、格式、TypeScript 和生产构建检查；后端完成格式、编译、Clippy、库单元测试及领域、BPM、权限漂移检查。
3. 静态检查和库单元测试不作为真实业务流程或浏览器视觉验收结论。
