# 工作台展示一致性核查与验收清单

核查日期：2026-09-08。适用范围：工作台列表、详情、审批跟踪和单据查看入口。

## 1. 验收口径

1. 同一业务对象、同一提交版本、同等数据阅读权限下，审批发起人与处理人必须读取同一组服务端摘要字段。金额、往来方和明细不得由角色名称决定。
2. 操作区必须服从服务端 `allowed_actions`。只读任务不挂载建单、付款、开票、导入确认或重放表单；履约责任管理独立于执行队列，仅在具有 `REASSIGN` 时保留。
3. 不同业务类型保留其业务字段。退款、回款、付款、冲正和应收未收余额不得被统一标为“含税金额”。不同含义的字段不得因数值相同而删除。
4. 审批跟踪必须按不可变提交读取。无独立提交快照的单据，只允许展示可证明属于当前非草稿审批版本的内容；旧版本或已撤回草稿返回摘要缺失。
5. 右上角文档图标用于查看。查看链接不得自动打开登记表单；变更单必须携带父单据与精确变更单身份，缺少父单据时不构造错误路径。
6. 概览明细保留现有最多 3 行与剩余行数提示。完整明细进入单据查看；不得把概览行数上限解释成接口明细丢失。
7. 代码核查、自动化检查与真实角色验收分别记录，不相互替代。工作台外完整对象中心的视觉验收不在本清单范围内。

## 6. 数据与验收限制

1. 客户回款、客户退款、供应商退款、两类冲正和库存调整未保存可恢复的全字段历史审批快照。现有数据无法重建旧内容；版本不匹配时必须显示缺失。当前非草稿同版本的读取不受影响。
2. 销售/采购变更的金额与明细有不可变提交；变更原因以及销售变更类型没有独立历史快照。旧提交不得沿用当前可编辑头字段。采购变更的历史 CS 序列须完整且与当前审批计数一致；迁移缺号或计数不一致时，只按实体明确绑定的当前提交展示，不推测历史版本。
3. `MASTER_MAPPING_TASK` 为已移除功能的残留注册，当前无数据装载与处理页。不得通过渲染测试把它认定为已恢复的正式流程。
4. 其余真实角色验收须提供相同单据、相同版本的发起人和处理人样本，逐项比较公共字段；对付款、开票、履约等执行任务同时核对只读账号不出现提交动作。无样本不得出具通过结论。
5. 执行任务的公共摘要不等同于专用作业面全字段。履约公共摘要目前主要包含来源单据及金额，数量、批次与履约证据仍由专用作业面读取；未证明所有角色都能在工作台查看这些完整字段。不得将只读操作隔离的测试通过表述为全部业务内容完全一致。
6. 本清单证明代码范围已覆盖；不出具“所有单据、所有状态、所有角色均已业务验收通过”的结论。
