# 品牌批量导入执行合同

## 入口与文件

- 品牌列表提供「批量导入」，提交与失败行下载复用 `product_brand:create` 权限。
- 提供 XLSX 模板下载。首行包含「品牌名称」，可选「品牌代码」；每个文件最多 1000 条非空数据、5 MB，工作表物理行数不得超过 10001。
- 优先读取「品牌」工作表，否则读取第一张工作表。空白行跳过；公式、错误值、日期单元格须转为文本。读取异常须随源行保存，后台将该行记为失败，不按公式缓存值创建品牌。
- 名称去首尾空白后为 1–128 个字符，代码至多 64 个字符。代码空白时服务端使用品牌编号器取号。新建品牌统一启用，Logo 留空。

## 提交与后台执行

- 客户端一次提交全部行：`POST /admin/product-brands/import/jobs`。请求包含 `request_id`、`file_name` 和 `rows[{row_number,name,brand_code,error?}]`；行号为原 Excel 行号，不可重复。
- 服务端验证请求、当前账号及权限后，将完整输入加密保存到对象存储，再原子登记统一任务及全部行明细。只有持久化登记完成才返回 `BackgroundJobView`。
- 每次选文件产生稳定 UUID。同一提交身份、提交人和完整内容必须返回同一任务；同一身份更换内容必须拒绝。提交响应不确定时，页面保留原身份和内容，用「重试核对」读取原任务，禁止自动更换提交身份。
- 任务类型为 `BRAND_IMPORT`，后台任务页显示「品牌导入」。提交成功后关闭弹窗并提示任务去向，允许关闭页面；任务由独立 `erp-worker` 执行。
- 每轮最多扫描四个任务，每任务按十行或一秒软预算切片。必须完成当前行的事务提交后才让出；两分钟未推进的任务允许按版本竞争恢复。
- 每行必须在同一事务内重读任务状态及版本、核验提交人有效账号和当前品牌创建权限，再写入品牌、审计、行结果及进度。取消或任务被接管后禁止继续写入。账号或权限失效须停止任务。
- 行内业务错误记为失败并继续其他行；数据库错误和提交结果不确定不得标记为业务失败，不自动重放当前命令。下轮执行先读已持久化的任务和行结果，跳过已完成行，再恢复未提交行。
- 已取消任务保留成功行和统计，剩余行不再执行。品牌名称未新增全局唯一约束；不同任务或其他建档入口的并发同名提交仍遵循既有字典约束。

## 查重与结果

- 查重依次核对本次导入的稳定品牌身份、已提供代码、未删除记录的精确名称。相同名称且代码未填或一致时跳过，保留原状态和 Logo；名称与代码冲突时失败。停用品牌不自动启用，已删除身份或代码不复用。
- 后台任务展示已写入、跳过、未成功、未处理计数，以及原 Excel 行号、品牌名称、逐行说明和品牌引用。
- 失败、取消、停止任务的待处理行通过 `GET /admin/product-brands/import/jobs/{id}/failures` 获取。服务端必须核验任务类型、终态、原提交人及其当前有效账号和创建权限；其他用户即使可管理后台任务，也不能下载原始行。
- 待处理清单包含失败和未执行行，排除成功和跳过行。下载为 XLSX，保留品牌名称、代码、原始行号及原因。修正后使用新提交身份重新导入。
- 输入缓存只缓存校验过的不可变内容，不缓存任务状态或授权结论；重启后必须能够从对象存储重读输入。

## 发布与回滚

1. 在目标库检查并执行 `backend/scripts/migrations/20261106-brand-import-name-index.mongosh.js`；显式设置 `APPLY_BRAND_IMPORT_INDEX=1` 才创建品牌名称索引。既有后台任务及明细索引继续复用，不新增任务集合。
2. 同步发布后端 API、`erp-worker` 和前端；检查 worker 已注册 `BrandImportTaskAdapter`，对象存储与敏感数据编解码配置可用。本地已执行索引不代表生产库已执行。
3. 回滚前停止接收新品牌导入并排空或取消现存品牌任务。不得只回滚 worker 后遗留无人消费的任务。保留已导入品牌、任务、结果和源文件。
4. 品牌名称索引为 `{name:1,deleted_at:1}` 非唯一索引，不回填、不修改历史品牌。回滚应用时保留该索引；需要删除时须先停止导入流量。
5. 上线验收须覆盖：模板下载、提交后关闭页面、重复提交和异载荷拒绝、逐行失败、停用与已删除品牌、取消与重启恢复、权限撤回、原提交人失败行下载及越权拒绝。静态检查与库单测不替代页面、worker、数据库和对象存储验收。
