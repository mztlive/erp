# W01 · 我的工作台

> 状态：已确认
> 页面模式：M1 工作台 + 页内列表/详情主从
> 主要路由：`/workspace`
> 旧路由：`/workspace/tasks` 永久重定向到 `/workspace`，不保留第二套页面
> 主要角色：全部已登录用户；登录默认着陆
> 最后更新：2026-08-23
> 权威合同：`../approval-workflow-contract.md` §16.4、§13.2
> 废止页面：W02；本页承接其查询、筛选、排序、分页和连续处理能力

## 1. 定位与目标

### 1.1 用户目标

用户打开 ERP 后，应在**这一个页面**内回答并完成：

1. 今天最需要我处理什么？
2. 选中一条后，不必跳页就能看懂单据摘要、审批上下文和下一步；
3. 审批任务直接在右侧提交通过或驳回，成功后自动进入下一条。

### 1.2 业务目标

- `work_item` 是当前人工责任的唯一事实源；审批推进只走审批运行时，正式业务事实只走强类型领域命令。
- 全部任务创建即指定到具体用户。页面只有「待我处理」口径，不存在团队待处理、未分派或可领取。
- 指标数量与列表使用同一权限快照，由服务端计算；前端不得对已加载条目求和。
- 任一角色从着陆到提交第一条审批决定不超过一次选中。

### 1.3 不在本工作面完成

- 不提供通用完成表单或公共 `complete_work_item`。
- 非审批任务的正式动作仍在对应业务工作面提交；本页只展示摘要与「打开单据」。
- 不提供批量通过、批量驳回、批量转交、领取、开始处理或退回团队。
- 不在预警区修改正式单据、映射或同步结果。
- 不把经营指标、大图表或全公司排行榜塞入本页；管理分析进入 M6。

## 2. 用户、权限与数据范围

### 2.1 角色入口

| 角色 | 默认着陆 | 本页主要内容 | 需要深挖时去向 |
| --- | --- | --- | --- |
| 销售 | W01 | 本人待办、我发起的审批 | W05 销售单中心 / 编辑工作区 |
| 销售领导 | W01 | 被已发布定义指定给本人的销售单审批节点 | 必要时打开单据中心 |
| 采购 | W01 | 销售单采购确认节点、履约与采购相关待办 | W08 采购单（选源在建单时完成） |
| 财务 | W01 | 被已发布定义指定给本人的单据审批节点、票款复核 | W11 / W12 / W13 |
| 仓储 | W01 | 被已发布定义指定给本人的库存调整审批节点、履约任务 | W09 / W10 |
| 运营 | W01 | 卡券销售单审批节点、映射与协同异常 | W17 / W21 / W22 |
| 管理层 | 可主动进入 W01 | 仅本人需要处理的任务 | 对应对象中心 |
| 系统管理员 | 可主动进入 W01 | 受阻审批、同步失败；有权时使用管理视图 | W17 / W29 |

采购不再着陆到已废止的 W07。选源、成本、交期和履约方式在销售单生效后创建采购单时录入。

### 2.2 权限表达

| 情况 | 本页行为 |
| --- | --- |
| 无工作台模块权限 | 不展示入口；直接访问显示无权限页 |
| 有模块权限但没有任何数据范围 | 展示“当前角色无数据范围”，不展示虚假的 0 指标 |
| 有数据范围但当前没有任务 | 口径胶囊显示 0，主面板展示单个空态“当前没有待处理事项”，不拆左右双空态 |
| 有权查看任务但不能处理 | 任务可见；决定按钮禁用并展示 `action_blockers`，允许「打开单据」时保留该入口 |
| 无敏感字段权限 | 保留字段标签和布局，值使用掩码；不得在提示或客户端缓存中泄露原值 |
| 页面打开期间权限被收回 | 清除当前缓存中的敏感值，页面切换为无权限或无数据范围状态 |
| 无运行管理权限 | 不展示「管理视图」与受阻取消；指标不计入他人任务 |

### 2.3 数据范围原则

- 列表由服务端按当前用户、角色、组织和数据范围过滤。
- 前端不得先取全量任务再隐藏无权数据。
- 服务端不得返回 `owner_user_id` 为空的开放任务。
- 指标数量必须按与列表相同的权限快照计算。
- 管理视图与本人口径分开计数，不得并入「待我处理」。

## 3. 入口、路由与任务页签

| 场景 | 入口 | URL / 页签行为 | 返回位置 |
| --- | --- | --- | --- |
| 登录默认着陆 | 登录成功或根路由 | 打开固定页签「我的工作台」，URL 为 `/workspace` | 不适用 |
| 点击顶栏待办角标 | `GlobalTopbar` | 聚焦本页签并保留当前筛选 | 原业务页签仍保留 |
| 点击口径胶囊 | 主面板工具条 | 写入 URL 查询并筛选左列，不跳路由 | 浏览器后退恢复上一筛选 |
| 选中任务 | 左列条目 | 写入 `currentWorkItemId`；右侧渲染详情 | 保留列表筛选与滚动位置 |
| 打开单据 | 详情次入口 | 聚焦已存在的对象页签，或创建对象中心页签 | 返回本页时恢复选中项 |
| 访问旧路由 | `/workspace/tasks` 及任意 query | 永久重定向到 `/workspace`，query 只保留本页仍合法的键 | 本页 |
| 刷新浏览器 | 任意本页状态 | 恢复 URL 中可分享的筛选与当前项；滚动位置不要求跨刷新恢复 | 本页 |

TaskTabs 身份仍固定为 `workspace:today:{userId}`。同一用户重复打开本页只聚焦已有页签，不创建副本。顶栏待办角标只指向本页。

合法 URL 查询键：`view`、`due`、`blocked`、`family`、`type`、`q`、`sort`、`currentWorkItemId`。不得出现 `scope=team`、`scope=mine` 作为责任池开关。

### 4.2 区域说明

| 区域 | 目的 | 主组件 | 规则 |
| --- | --- | --- | --- |
| 页头 | 页面身份、当前条数、数据更新时间、刷新 | `PageHeader` `DataFreshness` | 标题固定为「我的工作台」；只展示一条待办新鲜度；不放业务正式主动作；禁止问候语当 H1 |
| 口径胶囊 | 切换口径并筛选左列 | 主面板工具条 `ToggleGroup` | 按钮语义与选中态；数量来自服务端统计；点击不跳页 |
| 类型页签 | 按任务族收敛列表 | 分段控件 | 只筛选，不改变指标数量口径；不加前端求和的族计数 |
| 搜索与排序 | 收敛左列 | `InputGroup` 原生排序 | 与口径胶囊同一工具条 |
| 左列 | 跨领域混排的唯一待办列表 | `WorkTaskItem` compact | 独立滚动；当前项有文字选中态；全页只渲染一份 |
| 右侧详情 | 单据摘要、审批上下文、决定 | 按任务类型分派的只读区 + 吸底决定区 | 审批在页内提交；非审批只给「打开单据」 |
| 预警 | 需关注但不一定立即处理的异常 | `Alert` | 可折叠，不占用详情主区；最多 5 条 |

### 4.3 布局固定规则

1. 口径胶囊是筛选器，不是跳转入口，也不是经营 KPI 卡。点击写入 URL 并筛选左列。
2. 左列承接原 W02 的查询、排序、分页和连续处理能力；条目跨领域混排，按类型页签收敛。
3. 右侧详情只读渲染服务端事实，不得根据单据状态或动作日志推断当前责任人。
4. 审批任务在详情内提交通过或驳回；成功后自动选中列表下一条。
5. 非审批任务在详情内只展示摘要与「打开单据」。
6. 详情区不得提供批量通过、批量驳回或批量转交。
7. 列表和详情的可执行性一律由服务端 `allowed_actions` 与 `action_blockers` 决定，每次提交仍由服务端重验。
8. 刷新、跨页返回和浏览器重开后必须重新查询服务端，不得从本地状态恢复责任事实。
9. 移动端与窄屏下详情降级为全屏抽屉，返回后保留列表筛选与滚动位置；待办列表仍只渲染一份，不得桌面/窄屏各画一份。
10. 主工作面是一张表面：有任务时内部分栏，无任务或筛选为空时只出现一个空态。

## 5. 展示内容与字段

### 5.1 页头与指标

| 区域 | 字段 | 用户文案 | 数据来源 | 口径 |
| --- | --- | --- | --- | --- |
| 页头 | 工作面名 | `我的工作台` | 固定文案 | 不得用问候语或内部角色 ID 当 H1 |
| 页头 | `total` | `当前共 {n} 项` | 与列表同一权限快照的服务端总数 | 当前筛选结果数 |
| 页头 | `workItemsUpdatedAt` | 数据更新时间 | 待办查询更新时间 | 绝对时间 + 新鲜/陈旧状态；页头只展示这一条，不并列「工作台汇总」 |
| 指标 | `inboxCount` | 待我处理 | 服务端聚合 | `OPEN + owner_user_id=当前用户`；审批与非审批同一口径 |
| 指标 | `overdueCount` | 已超期 | 服务端聚合 | 待我处理中 `due_at < now`；数量大于 0 时用 `destructive` |
| 指标 | `blockedCount` | 受阻 | 服务端聚合 | 待我处理中关联实例或执行为 `BLOCKED` |
| 指标 | `startedCount` | 我发起的 | 服务端聚合 | `approval_process_instance.started_by=当前用户` |

「今日到期」不再作为独立指标；需要时用筛选 `due=today`。类型页签（审批 / 履约 / 财务 / 集成）只筛选左列，不作为独立数量口径。

### 5.2 左列条目

| 字段 | 用户文案 / 表现 | 数据来源 | 说明 |
| --- | --- | --- | --- |
| `workItemTypeLabel` | 销售单审批、票款复核等 | 固定类型映射 | 原始类型代码不直接展示 |
| `businessObject` | 稳定单号 / 名称 | 对象查询投影 | 不把对象名当作任务身份 |
| `counterpartyName` | 客户 / 供应商 | 对象查询投影 | 无权限时掩码或不返回 |
| `listSummary` | 一行事项摘要 | 类型白名单投影 | 例如「客户A · 12.8万 · 8行」 |
| `dueAt` | 截止 / 已超期 | `work_item.due_at` | 未设置时不上屏 |
| `priority` | 紧急 / 高 | `work_item.priority` | 普通优先级不重复显示徽章 |
| 受阻标记 | 受阻 | 实例或执行为 `BLOCKED` | 独立受阻样式，不得伪装为普通待办 |
| `ownerUserLabel` | 由你处理 / 由{姓名}处理 | `owner_user_id` | 禁止写「团队待处理」「当前处理人」 |

组内排序固定为：已超期优先 → `priority` 降序 → `due_at` 升序 → `created_at` 升序。排序由服务端完成。

### 5.3 右侧详情

| 内容 | 审批任务 | 非审批任务 |
| --- | --- | --- |
| 单据摘要 | 单号、往来方、金额、行数 | 同左，按类型白名单 |
| 审批上下文 | 流程名与版本、当前轮次、当前节点、当前审批人、最近驳回与原因 | 不展示 |
| 历史 | 按轮次分组的节点执行；已结束执行只读 | 不展示 |
| 受阻说明 | blocker 分类、可用恢复路径 | 若任务不可执行则展示 `action_blockers` |
| 主操作 | 通过 / 驳回 | 打开单据 |
| 次操作 | 打开单据 | 无通用完成、关闭或转交 |

审批详情必须直接展示：审批状态、当前轮次、当前节点、当前审批人、最近驳回和驳回原因。实例 `BLOCKED` 必须使用独立受阻样式。

历史使用游标分页，按 `round_no` 分组、按 `execution_no` 排序。同一节点跨轮次必须显示多条记录，不得按 `node_key` 去重。首屏只消费受控 `recent_history`。

## 6. 搜索、筛选、排序与默认视图

### 6.1 默认状态

- 默认视图：`view=inbox`（待我处理），无时限、无类型收敛。
- 默认排序：`sort=priority_due`。
- 左列使用游标分页，禁止前端全量过滤 DataScope。
- 新任务到达只显示“有 N 条新任务”，不得使当前项突然跳位。

### 6.2 筛选契约

| 能力 | 默认值 | URL | 行为 |
| --- | --- | --- | --- |
| 待我处理 | 是 | `view=inbox` 或省略 | `OPEN + owner_user_id=当前用户` |
| 已超期 | 关 | `due=overdue` | 待我处理中超期子集 |
| 受阻 | 关 | `blocked=1` | 待我处理中受阻子集 |
| 我发起的 | 关 | `view=started` | 实例 `started_by=当前用户`；列表只读 |
| 管理视图 | 关 | `view=managed` | 仅运行管理权限；与本人口径分开计数 |
| 任务族 | 全部 | `family=approval\|finance\|fulfillment\|exception` | 只筛选，不改指标口径 |
| 任务类型 | 全部 | `type={fixedCode}` | 连续处理时可收敛到单类型 |
| 搜索 | 空 | `q=` | 搜稳定单号、对象或往来方；服务端过滤 |
| 排序 | 超期与优先级 | `sort=priority_due\|due_asc\|created_desc` | 服务端排序 |
| 当前项 | 无 | `currentWorkItemId` | 深链允许；服务端仍重验可见性 |

口径筛选改变后：

1. 对应口径胶囊设置 `aria-pressed=true`；
2. 左列标题和结果数量使用 `aria-live=polite` 播报；
3. 请求期间保留旧列表并显示轻量刷新状态；
4. 筛选变更一律 `router.replace`，不膨胀历史；
5. 浏览器后退恢复之前的筛选，而不是重置到首页。

`view=started` 与 `view=managed` 无任务时走「当前筛选无结果」空态，并提供回到「待我处理」。

## 7. 操作契约

| 操作 | 入口 | 权限 / 前置条件 | 确认 | 成功结果 | 失败恢复 |
| --- | --- | --- | --- | --- | --- |
| 刷新 | 页头 | 本页可访问 | 无 | 更新统计与列表；页头展示一条待办新鲜度 | 保留旧数据并提供重试 |
| 口径过滤 | 工具条胶囊 | 对应口径可见 | 无 | 左列在原页过滤 | 请求失败恢复原列表和原筛选 |
| 选中任务 | 左列 | 任务对当前用户可见 | 无 | 右侧渲染详情；URL 写入当前项 | 不可见时安全错误，不泄露对象 |
| 通过 | 详情主按钮 | `APPROVE` 在 `allowed_actions`，无 blocker | 原因按合同可选 | 用响应事实更新实例、单据和任务；自动选中下一条 | `409` 刷新任务和实例，展示“责任或版本已变化”，不得自动重放 |
| 驳回 | 详情主按钮 | `REJECT` 在 `allowed_actions` | 原因必填 | 单据与 `subject_version` 不变，轮次加一；自动选中下一条 | 同通过；停留当前项直至用户确认 |
| 打开单据 | 详情次入口 | 有对象查看权限 | 无 | 聚焦或创建对象中心页签；本页签保留 | 无权限时转为明确无权限态 |
| 恢复当前审批人 | 受阻详情 | 服务端 `recovery_options` 授权 | 无选人 | 展示新执行和新 OPEN 任务 | `409` 刷新后重新确认 |
| 改派当前审批人 | 受阻详情 | 人员失效且存在合格目标 | 原因必填；资格搜索选人 | 展示新的当前责任人和恢复状态 | `409` 刷新事实并要求重新确认 |
| 取消受阻审批 | 受阻详情 | 非人员一致性 blocker 且有运行管理权限 | 展示不可恢复提示 | 调用专用受阻取消端口 | 不得调用通用 WorkItem close |
| 打开预警 | 预警条目 | 有目标模块权限 | 无 | 打开负责处理该预警的工作面 | 目标权限已变化时显示无权限态 |

### 7.1 决定请求

决定弹窗只能提交 `work_item_id`、`APPROVE|REJECT`、原因、`expected_task_version` 和幂等键。

- 请求进行中禁用重复提交；
- 幂等键在同一次用户意图重试时保持不变，用户修改决定或原因后生成新键；
- 页面不得提交下一节点、驳回目标或下一审批人；
- 「稍后处理」只移动当前列表焦点，不改变任务状态或当前责任。

### 7.2 禁止出现的动作

以下动作已按合同 §13.2 从全系统删除，任何任务类型都不得显示：

- 领取、开始处理、退回团队；
- 通用转交、通用关闭（审批任务）；
- 重试当前步骤、自动换成角色池。

非审批任务的管理员改派若服务端允许，只出现在 `view=managed`，并走专用改派端口，不得伪装成领取。

## 8. 数据契约

本节定义 UI 所需的查询形状，不固定 HTTP 路径；正式 endpoint 和错误码在 API 文档中固化。

### 8.1 查询参数

```ts
type WorkspaceQuery = {
  view: "inbox" | "started" | "managed"
  due?: "today" | "overdue"
  blocked?: boolean
  family?: "approval" | "finance" | "fulfillment" | "exception"
  workItemType?: string
  query?: string
  sort: "priority_due" | "due_asc" | "created_desc"
  cursor?: string
  currentWorkItemId?: string
  timezone: string
}
```

本页必须分别调用任务列表与统计接口。两次查询必须使用相同的 `view`、`family`、`due`、`blocked` 和 `timezone` 口径；禁止由当前分页条目计算或修正指标总量。

约束：

- `timezone` 必须使用当前工作角色所属组织的已确认时区；界面必须展示该工作时区。
- `view=inbox` 只接受或默认 `status=OPEN`；`view=started` 读审批实例而非把他人开放任务并入口径。
- 查询必须由 TanStack Query 管理；组件内禁止裸 `fetch`。
- Query Key 至少必须包含用户身份、当前角色、权限版本、数据范围版本、筛选和时区。

### 8.3 数据新鲜度

| 数据 | 更新口径 | 前端职责 |
| --- | --- | --- |
| 正式待办条目 | 业务事务内同步更新，提交后立即可见 | 格式化时间、状态和业务文案；不修改状态 |
| 工作台指标 | 统计查询，允许 ≤1 分钟延迟 | 数量展示在工具条口径胶囊；页头只展示一条待办新鲜度；不得用当前加载条目修正服务端总数 |
| 预警 | 统计查询，允许 ≤1 分钟延迟 | 展示严重度和发生时间；不推导正式结果 |
| 超期时长 | 服务端返回 `dueAt` 和当前时钟基准 | 不以本地计算结果改变正式优先级 |

## 9. 页面状态矩阵

| 状态 | 页面表现 | 可执行动作 | 恢复方式 |
| --- | --- | --- | --- |
| 初载 | 页头与单张主面板 Skeleton | 应用壳导航可用 | 查询完成后原位替换 |
| 刷新 | 保留旧口径数量和列表，页头显示“正在刷新” | 已选中项的决定是否允许由服务端重验 | 成功更新时间；失败显示重试 |
| 无任务 | 口径胶囊为 0，主面板单个空态“当前没有待处理事项” | 查看预警、进入有权限的业务模块 | 新任务到达或手动刷新 |
| 筛选无结果 | 保留口径数量，主面板显示“当前筛选没有待办” | 清除筛选，回到待我处理 | 返回待我处理 |
| 无数据范围 | 不显示 0 指标；展示数据范围说明 | 查看当前角色 | 权限或范围更新后重查 |
| 查询失败且无缓存 | `BusinessFailureState`，区分权限、系统和网络失败 | 重试、返回其它模块 | 重试成功 |
| 查询失败但有缓存 | 保留旧内容并标记“刷新失败” | 允许查看；决定动作提交前重验 | 重试成功 |
| 审批受阻 | 详情使用独立受阻样式，普通决定禁用 | 只显示服务端授权的恢复 / 改派 / 取消 | 恢复成功后刷新为新任务 |
| 责任或版本已变化 | 详情只读，展示可展示的当前责任人 | 刷新后由用户重新确认 | 不得自动重放决定 |
| 正式动作成功 | 固定业务结果后再选中下一条 | 用户无需回列表 | 无下一条时显示“本筛选项已处理完” |
| 结果未知 | 不显示成功，不移动下一项 | 查询原结果或沿同一幂等键重试 | 得到确定结果后才移动 |
| 权限收回 | 清除敏感缓存，转无权限/无范围状态 | 返回有权模块 | 权限恢复后重查 |

### 10.2 键盘与焦点

- `⌘K` 聚焦应用壳全局搜索，不被本页覆盖。
- Tab 顺序：页头刷新 → 口径胶囊 → 搜索/排序 → 类型页签 → 左列 → 详情决定区 → 预警。
- 口径胶囊使用原生按钮与 `aria-pressed`；不能用可点击 `div`。
- 列表切换后焦点落到新对象标题，`aria-live=polite` 播报任务类型和对象。
- 筛选完成后焦点不跳走，结果数量通过 `aria-live=polite` 播报。
- 从对象中心返回时，焦点恢复到原任务条目；任务已完成则落到下一项。
- 色彩不是唯一状态表达；所有超期、受阻和失败均有文字。
- 所有触控目标不小于 44×44px。

## 12. 验收清单

### 12.1 体验与布局

- [ ] 销售用户登录后，选中首条审批任务即可在右侧提交决定。
- [ ] 任一有任务角色从着陆到提交第一条审批决定不超过一次选中。
- [ ] 1440×900 下口径胶囊、左列当前项和右侧决定同屏可见；无独立统计卡。
- [ ] 口径胶囊点击后有明确选中态、筛选摘要和正确结果数量，且不跳页。
- [ ] 无任务时主面板只有一个空态；待办列表全页只渲染一份。
- [ ] 审批任务能在详情内回答对象、轮次、当前节点、最近驳回和下一步。
- [ ] 页面不出现领取、开始处理、退回团队、通用转交或通用关闭。
- [ ] `/workspace/tasks` 重定向到 `/workspace`，不存在第二套待办页面。

### 12.2 数据与权限

- [ ] 指标和列表使用同一权限/数据范围版本，数量不由前端当前页求和。
- [ ] 服务端不返回空 `owner_user_id` 的开放任务。
- [ ] 页头只展示一条待办新鲜度，不并列工作台汇总。
- [ ] 无模块权限、无数据范围、无任务和筛选无结果四种状态可区分。
- [ ] 权限收回后不残留敏感字段或预警描述。
- [ ] 管理视图与本人口径分开计数。

### 12.3 导航与恢复

- [ ] 筛选进入 URL，刷新和浏览器后退能恢复。
- [ ] 审批决定成功后自动选中下一条；无下一条时显示“本筛选项已处理完”。
- [ ] `409` 时刷新事实，不自动重放决定。
- [ ] 人员受阻只提供服务端授权的恢复或改派；非人员一致性受阻只对运行管理员显示取消。
- [ ] 从对象中心返回后恢复原筛选和任务焦点。

### 12.4 状态与响应式

- [ ] §9 全部状态完成组件测试或浏览器验证。
- [ ] 1440、1280、1024、768、375 五档视口通过 §10.1 验收。
- [ ] 键盘可完成筛选、选中任务、提交决定和返回。
- [ ] 读屏器能够识别口径选中态、当前项、受阻状态和结果数量变化。
- [ ] 页面可见文案不出现 `POOL`、`DIRECT`、instance、execution、binding、retry、内部 ID、「团队待处理」「领取」。
