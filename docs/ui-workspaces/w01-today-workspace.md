# W01 · 今日工作台

> 状态：样板
> 页面模式：M1 角色工作台
> 主要路由：`/workspace`
> 主要角色：全部已登录用户；销售与销售领导默认着陆
> 最后更新：2026-08-01

## 1. 定位与目标

### 1.1 用户目标

用户打开 ERP 后，应在一个工作面内回答三个问题：

1. 今天最需要我处理什么？
2. 哪些事项已经超期或正在影响业务？
3. 点击哪里可以直接开始处理，而不是先进入另一个列表继续找？

### 1.2 业务目标

- 以正式 `work_item` 为待办事实源，把不同领域的任务汇聚为个人工作入口。
- 用统计查询呈现任务数量、预警和数据更新时间，但不把统计结果冒充正式业务事实。
- 让任一角色从着陆到处理第一条待办不超过两次点击。
- 把处理动作送入对应 M3 队列或对象工作面；W01 本身不承载正式审批、核销或建单。

### 1.3 不在本工作面完成

- 不在指标卡上直接执行通过、驳回、作废或冲正。
- 不在工作台复制 W02 的完整查询、批量选择和任务治理能力。
- 不在预警区修改正式单据、映射或同步结果。
- 不把经营指标、大图表或全公司排行榜塞入个人工作台；管理分析进入 M6 工作面。

## 2. 用户、权限与数据范围

### 2.1 角色入口

| 角色 | 默认着陆 | W01 中的主要内容 | 主要去向 |
| --- | --- | --- | --- |
| 销售 | W01 | 销售单补充、验收、异常协同、与本人相关的审批结果 | W05 销售单中心 / 编辑工作区 |
| 销售领导 | W01 | 审批类待办、超期销售事项 | 对应 M3 审批队列 |
| 采购 | W07，可主动进入 W01 | 二次确认、待建采购、供应商与履约异常 | W07 / W08 / W09 |
| 财务 | W11 或审核队列，可主动进入 W01 | 财务审核、票款复核、结算与纠错任务 | W11 / W12 / W13 / 审核队列 |
| 仓储 | 仓储作业队列，可主动进入 W01 | 入库、仓发、库存调整审核任务 | W09 / W10 |
| 运营 | 映射或审批队列，可主动进入 W01 | 映射、发布、卡券审批和协同异常 | W17 / W21 / W22 |
| 管理层 | M6 经营分析，可主动进入 W01 | 仅本人需要确认的管理任务 | 对应审批队列 |
| 系统管理员 | 同步监控，可主动进入 W01 | 同步失败、结果未知、业务异常 | W17 / W29 |

### 2.2 权限表达

| 情况 | W01 行为 |
| --- | --- |
| 无 W01 模块权限 | 不展示入口；直接访问显示无权限页 |
| 有模块权限但没有任何数据范围 | 展示“当前角色无数据范围”，不展示虚假的 0 指标 |
| 有数据范围但当前没有任务 | 指标显示 0，主区展示“当前没有待处理事项” |
| 有权查看任务但不能处理 | 任务可见；“处理”禁用并展示 `actionBlocker`，允许进入只读对象中心时提供“查看” |
| 无敏感字段权限 | 保留字段标签和布局，值使用掩码；不得在提示、埋点或客户端缓存中泄露原值 |
| 页面打开期间权限被收回 | 清除当前缓存中的敏感值，页面切换为无权限或无数据范围状态 |

### 2.3 数据范围原则

- 任务列表由服务端按当前用户、角色、组织和数据范围过滤。
- 前端不得先取全量任务再隐藏无权数据。
- 指标数量必须按与任务列表相同的权限快照计算；不能用当前已加载的前几十条任务在浏览器中求和。
- “待我处理”指标与默认列表必须仅计入已分配到当前用户的个人任务；未分配到个人、仅分配给角色池的任务不得计入“待我处理”。
- 角色池任务必须与个人任务分开展示；服务端必须分别返回个人任务数与角色池任务数，前端不得把两者合并为单一“待我处理”口径。

## 3. 入口、路由与任务页签

| 场景 | 入口 | URL / 页签行为 | 返回位置 |
| --- | --- | --- | --- |
| 登录默认着陆 | 登录成功或根路由 | 打开固定页签“今日工作台”，URL 为 `/workspace` | 不适用 |
| 点击顶栏待办角标 | `GlobalTopbar` | 聚焦 W01 页签并滚动到待办主区；保留当前指标筛选 | 原任务页签仍保留 |
| 点击指标 | W01 指标区 | 更新 URL 查询，例如 `/workspace?due=overdue` | 浏览器后退恢复上一筛选 |
| 点击“处理” | 任务条目 | 聚焦已存在的对象/队列页签，或创建新任务页签 | 返回 W01 时保留筛选与滚动位置 |

TaskTabs 身份固定为 `workspace:today:{userId}`。同一用户重复打开 W01 只聚焦已有页签，不创建副本。

### 4.2 区域说明

| 区域 | 目的 | 主组件 | 规则 |
| --- | --- | --- | --- |
| 页头 | 明确当前角色、数据更新时间和刷新入口 | `PageHeader` `PageActions` `DataFreshness` | 不放业务正式主动作 |
| 指标区 | 快速判断任务数量并过滤主区 | `MetricStrip` `MetricFilterItem` | 指标全部使用按钮语义和选中态 |
| 待办主区 | 在当前上下文找到并开始处理任务 | `WorkTaskItem` | 按任务族分组，组内按超期、优先级、截止时间排序 |
| 预警区 | 展示需要关注但不一定立即处理的异常 | `Alert` / `AsyncSectionState` | 只显示当前权限范围内的预警 |
| 最近打开 | 回到最近对象与队列上下文 | `TaskTabs` 最近记录的只读投影 | 不作为正式业务数据来源 |

### 4.3 待办分组

服务端返回固定任务类型，前端只按展示映射归入下列任务族，不创造新的 `work_item_type`：

| 任务族 | 典型 `work_item_type` | 默认展开 |
| --- | --- | --- |
| 审批与确认 | `PROCUREMENT_CONFIRMATION`、`LOW_MARGIN_MANAGER_CONFIRMATION`、`IMPORT_BUSINESS_CONFIRMATION`、销售审批、采购审核 | 是 |
| 票款与结算 | `CARD_FUNDS_REVIEW`、`CARD_FUNDS_DELTA_REVIEW`、`SUPPLIER_SETTLEMENT_REVIEW`、财务纠错 | 有任务时展开 |
| 履约与库存 | 库存调整审核、履约相关 `BUSINESS_EXCEPTION` | 有超期时展开，否则折叠 |
| 数据治理与异常 | `INTEGRATION_RESULT_UNKNOWN`、`BUSINESS_EXCEPTION` （映射任务使用 `business_object_type=MASTER_MAPPING_TASK`） | 管理员/责任角色展开，其余按权限隐藏 |

组内排序固定为：已超期优先 → `priority` 降序 → `due_at` 升序 → `created_at` 升序。排序由服务端完成，前端不因本地时间差重排正式优先级。

### 5.1 页头与指标

| 页头 | `roleSummary` | 角色摘要 | 当前有效角色 | 多角色时展示当前工作角色 | 允许用户切换的角色另由应用壳负责 |
| 页头 | `statsUpdatedAt` | 工作台数据更新时间 | 统计查询更新时间 | 绝对时间 + 新鲜/陈旧状态 | 全员可见 |
| 指标 | `assignedActiveCount` | 待我处理 | 服务端聚合 | 当前权限快照内、已分配到当前用户的有效个人任务数；不得计入角色池任务 | 不用加载列表求和 |
| 指标 | `dueTodayCount` | 今日到期 | 服务端聚合 | 以当前工作角色所属组织的已确认时区计算“今日”截止边界；该时区必须在界面明确展示 | 全员可见指标值；时区展示不得省略 |

| 指标 | `exceptionCount` | 同步异常 / 异常待处理 | 服务端聚合 | 当前角色有权处理的结果未知与业务异常 | 无对应模块权限时整项不展示 |

### 5.2 任务条目

| 字段 | 用户文案 / 表现 | 数据来源 | 说明 |
| --- | --- | --- | --- |
| `workItemTypeLabel` | 采购二次确认、票款复核等 | 固定类型映射 | 原始类型代码不直接展示 |
| `businessObject` | 对象类型 + 稳定单号 / 名称 | `business_object_type/id` 查询投影 | 点击“查看”进入对象中心，不直接用对象名作为身份 |
| `counterpartyName` | 客户 / 供应商 | 对象查询投影 | 无权限时掩码或不返回 |
| `statusLabel` | 待领取、待处理、处理中等 | `work_item.status` | 文字 + tone，不用纯色点 |
| `enteredAt` | 进入时间 | `work_item.created_at` | 展示相对时间，提示中提供绝对时间 |
| `dueAt` | 截止 / 已超期时长 | `work_item.due_at` | 服务端返回时间，前端按工作时区格式化 |
| `responsibleParty` | 责任角色 · 当前责任人 | `owner_role/user_id` | 角色池任务无个人责任人时明确写“待领取” |
| `reason` | 产生原因 | `reason_code` 的固定文案 + 安全参数 | 不直接展示内部错误堆栈 |
| `impact` | 业务影响 | `impact_summary` | 必须是业务语言，例如“可能影响 8 月 3 日交付” |
| `priority` | 紧急 / 高 / 普通 | `work_item.priority` | 普通优先级不重复显示徽章 |
| `allowedActions` | 处理 / 查看 | 服务端权限结果 | 禁用时使用 `actionBlockers` 说明原因 |

任务条目默认不展示金额、完整明细或审批意见；这些事实进入对应队列或对象中心读取，避免 W01 退化为多个详情页拼盘。

### 5.3 右侧区域

| 内容 | 数据来源 | 展示规则 | 操作 |
| --- | --- | --- | --- |
| 预警 | 服务端预警统计 | 最多展示 5 条；按严重度和发生时间排序。正式高风险（`severity` / 业务规定的高风险）预警必须展示，用户不得订阅隐藏；信息类（`info`）预警仅当角色规则允许时可由用户配置显示/隐藏 | 打开对应 Wxx，不在卡片内直接修复 |
| 数据陈旧提示 | 统计数据更新时间 | 超过 1 分钟显示 warning；刷新失败显示 failed | 刷新或进入后台任务中心 |
| 最近打开 | 服务端用户偏好（按用户维度） | 最多 6 项；仅保存稳定对象身份、展示标题和最近时间 | 聚焦已有页签或重开对象页签 |

“最近打开”不是审计记录，不影响业务事实。必须作为服务端用户偏好按用户持久化以实现跨设备一致；仅允许保存稳定身份、展示标题与时间，禁止保存金额、状态、权限结论或其它业务字段快照。

## 6. 搜索、筛选、排序与默认视图

### 6.1 默认状态

- 默认视图：`scope=mine`、`due=all-active`（`scope=mine` 仅含个人任务；角色池任务仅当 `scope=role_pool` 时展示）。scope 控件文案「我的待办 / 团队待认领」。
- 默认展示全部有权任务族；无任务的组不渲染空容器。
- 每组首批数量必须使用服务端工作台配置的 `pagePreviewLimit`；超过时必须显示“查看该组全部 N 条”并进入 W02。仅当服务端未返回配置时，前端必须以 5 条作为展示回退，并标记 `previewLimitSource=TEMPORARY_FALLBACK`；该回退值禁止写入正式接口契约，也不得作为验收硬约束数字。
- W01 禁止无限滚动；跨组浏览和批量治理必须进入 W02。

### 6.2 筛选契约

| 能力 | URL 示例 | 行为 |
| --- | --- | --- |
| 待我处理 | `/workspace` | 清除时限筛选，保留当前责任范围 |
| 今日到期 | `/workspace?due=today` | 所有任务族仅显示今日到期任务 |
| 已超期 | `/workspace?due=overdue` | 所有任务族仅显示超期任务 |
| 异常待处理 | `/workspace?family=exception` | 仅显示当前角色有权处理的异常任务族 |
| 任务族 | `/workspace?family=approval` | 从组标题或 W02 返回时恢复 |

指标筛选改变后：

1. 指标设置 `aria-pressed=true`；
2. 主区标题和结果数量使用 `aria-live=polite` 播报；
3. 请求期间保留旧任务并显示轻量刷新状态；
4. 浏览器后退恢复之前的筛选，而不是重置到首页。

筛选/指标变更一律 `router.replace`，不膨胀历史（P2）。`scope` 计入激活筛选：`scope=role_pool` 无任务时走「当前筛选无结果」空态并提供「清除筛选」。

工作台不提供对象全文搜索；稳定单号和基础资料名称使用应用壳全局搜索，复杂任务查询进入 W02。

## 7. 操作契约

| 操作 | 入口 | 权限 / 前置条件 | 确认 | 成功结果 | 失败恢复 |
| --- | --- | --- | --- | --- | --- |
| 刷新 | 页头 | W01 可访问 | 无 | 更新统计与任务查询；分别展示两类更新时间 | 保留旧数据并提供重试 |
| 指标过滤 | 指标卡 | 对应指标可见 | 无 | 主区在原页过滤 | 请求失败恢复原列表和原筛选 |
| 处理任务 | 任务条目主按钮 | `PROCESS` 在 `allowedActions` 中，且无 blocker | W01 不确认正式动作 | 打开对应 M3 / M4 / M5；W02 类目标的任务焦点经 `sessionStorage` 传递（内部 ID 不进地址栏） | 导航失败留在 W01；不提前领取或完成任务 |
| 查看对象 | 任务条目次入口 | 有对象查看权限 | 无 | 聚焦或创建对象中心页签 | 无权限时转为明确无权限态 |
| 查看全部待办 | 主区标题 / 组尾 | 有 W02 权限 | 无 | 打开 W02 并携带当前筛选 | 无 W02 权限时不展示入口 |
| 打开预警 | 预警条目 | 有目标模块权限 | 无 | 打开负责处理该预警的工作面 | 目标权限已变化时显示无权限态 |
| 继续最近任务 | 最近打开 | 仍有对象权限 | 脏页签关闭规则沿用全局契约 | 聚焦已有页签或按稳定 ID 重开 | 权限收回时只保留对象身份，不显示陈旧敏感值 |

### 7.1 “处理”按钮的边界

- W01 点击“处理”只负责导航，不在后台静默执行正式动作。
- 是否领取任务由目标 M3 队列在进入时按 W02 统一领取契约完成。
- 任务身份使用 `workItemId`（内部 ID）。W02 类目标队列的任务焦点不写入 URL，经 `sessionStorage` 传递，避免内部 ID 出现在地址栏；外部链接仍可携带 `currentWorkItemId` 深链参数，W02 优先采纳。W18 按其受控 handler 契约原样传递 `workItemId`、`confirmationScope` 与 `queueContextId`。
- 前端根据服务端返回的 `destinationWorkspaceId` 和稳定对象身份查本地路由注册表；不接受服务端任意 URL，避免开放跳转。
- 已被他人有效领取的任务仍可按权限查看，但处理按钮禁用并显示领取人。
- `IMPORT_BUSINESS_CONFIRMATION` 固定路由到 W18：以 `LEGACY_IMPORT_BATCH` 的稳定批次身份生成
  `section=confirm&confirmationScope={scope}&workItemId={workItemId}&queueContextId={queueContextId}`。
  `confirmationScope` 仅用于定位被分派的责任确认，`workItemId` 仍是唯一任务身份；领取、完成和返回均由 W18 的受控 handler 处理。

## 8. 数据契约

本节定义 UI 所需的查询形状，不固定 HTTP 路径；正式 endpoint 和错误码应在 API 文档中另行固化。

### 8.1 查询参数

```ts
type TodayWorkspaceQuery = {
  scope: "mine" | "role_pool"
  due?: "today" | "overdue"
  family?: "approval" | "finance" | "fulfillment" | "exception"
  timezone: string
}
```

约束：

- `timezone` 必须使用当前工作角色所属组织的已确认时区；禁止仅依赖浏览器本地时区猜测。界面必须展示该工作时区。
- `pagePreviewLimit` 必须由服务端工作台配置随任务组返回；前端禁止通过查询参数自行选择，也禁止按视口硬编码另一套每组条数。
- 仅当配置缺失时，前端必须以 5 条作为展示回退、标记 `previewLimitSource=TEMPORARY_FALLBACK`，并暴露配置缺失诊断；该数字禁止写入正式接口、响应式或验收硬约束。
- 查询必须由 TanStack Query 管理；组件内禁止裸 `fetch` 或自行维护缓存竞态。
- Query Key 至少必须包含用户身份、当前角色、权限版本、数据范围版本、筛选和时区。

### 8.2 响应形状

```ts
type TodayWorkspaceView = {

    activeRoleLabel: string
    timezone: string
  }
  freshness: {
    workItemsUpdatedAt: string

  workItemId: string
  workItemType: string
  workItemTypeLabel: string
  businessObjectType: string
  businessObjectId: string
  stableNumber?: string
  objectTitle: string
  counterpartyName?: string
  subjectVersion?: string
  status: WorkItemStatus
  statusLabel: string
  priority: number
  createdAt: string
  dueAt?: string
  ownerRoleLabel: string
  ownerUserLabel?: string
```

`WorkspaceWorkItem.status` 直接复用 W02 `WorkItemStatus`；每条正式待办都返回 `workItemId` 和 `queueContextId`（数据字段，非 URL 参数）。W01 对 W02 类目标队列把 `workItemId` 写入 `sessionStorage` 作为当前项焦点，不创建新的任务身份或队列上下文别名；W18 不是 W02 队列位置，按其受控 handler 契约原样传递 `workItemId`、`confirmationScope` 与 `queueContextId`。

### 8.3 数据新鲜度与计算边界

| 数据 | 更新口径 | 前端职责 |
| --- | --- | --- |
| 正式待办条目 | 业务事务内同步更新，提交后立即可见 | 格式化时间、状态和业务文案；不修改状态 |
| 工作台指标 | 统计查询，允许 ≤1 分钟延迟 | 展示数据更新时间；不得用当前加载条目修正服务端总数 |
| 预警 | 统计查询，允许 ≤1 分钟延迟 | 展示严重度和发生时间；不推导正式结果 |
| 超期时长 | 服务端返回 `dueAt` 和当前时钟基准，前端只做显示 | 不以本地计算结果改变正式优先级 |
| 最近打开 | 服务端用户偏好（非正式业务事实） | 只保存稳定身份与展示标题，禁止缓存敏感业务内容 |

### 8.4 提交与正式动作

W01 没有业务写提交接口。

- 刷新是查询失效与重新获取，不创建正式记录。
- 指标筛选只改变查询状态。
- 任务领取、审批、确认、驳回和暂挂全部在目标工作面完成，并遵守其领取、版本和结果反馈契约。

## 9. 页面状态矩阵

| 状态 | 页面表现 | 可执行动作 | 恢复方式 |
| --- | --- | --- | --- |
| 初载 | 页头、四指标和两栏结构 Skeleton；尺寸与成稿一致 | 应用壳导航可用 | 查询完成后原位替换 |
| 刷新 | 保留旧指标和任务，页头显示“正在刷新” | 已有任务可查看；正式处理是否允许由目标页重新校验 | 成功更新时间；失败显示重试 |
| 无任务 | 指标为 0，主区显示“当前没有待处理事项” | 查看最近打开、进入有权限的业务模块 | 新任务到达或手动刷新 |
| 筛选无结果 | 保留指标，主区显示当前筛选摘要 | 清除筛选 | 返回全部有效任务 |
| 无数据范围 | 不显示 0 指标；展示数据范围说明 | 查看当前角色 / 申请权限（若系统支持） | 权限或范围更新后重查 |
| 查询失败且无缓存 | `BusinessFailureState`，区分权限、系统和网络失败 | 重试、返回其它模块 | 重试成功 |
| 查询失败但有缓存 | 保留旧内容并标记“刷新失败” | 允许查看；处理动作由目标页重新校验 | 重试成功 |
| 统计陈旧 | 指标与预警标记陈旧，正式任务区仍可独立保持 fresh | 刷新 | 统计追平更新时间 |
| 统计刷新失败 | 页头 warning，指标不得显示成“实时” | 任务处理仍按正式待办查询决定 | 刷新成功 |
| 字段级隐藏 | 字段标签保留，值掩码；布局不跳动 | 其余有权操作保持可用 | 权限更新后重新获取 |
| 权限收回 | 清除敏感缓存，转无权限/无范围状态 | 返回有权模块 | 权限恢复后重查 |

## 10. 响应式、键盘与无障碍

### 10.1 响应式

| 视口 | 布局变化 | 必须保留 | 允许降级 |
| --- | --- | --- | --- |
| 1440×900 | 侧栏展开；指标四列；主区 62/38 两栏 | 页头更新时间、全部指标、首组任务与进入全部入口、预警 | 无 |
| 1280×800 | 侧栏可折叠；主区约 60/40 | 任务主操作和截止时间 | 最近打开按可用高度收敛，不固定为某一条数 |
| 1024×768 | 侧栏图标模式；两栏改为约 65/35 | 指标值、超期任务、处理按钮 | 指标说明文案可隐藏，任务原因/影响最多两行 |
| 768×1024 | 导航抽屉；指标 2×2；右栏移到任务主区之后 | 指标、任务身份、截止、状态、处理 | 最近打开折叠；预警按可用高度收敛并保留“查看全部”入口 |
| 375×812 | 单列；指标 2×2；任务改紧凑卡片 | 待办查看、简单确认入口、数据更新时间 | 不显示最近打开；复杂处理进入目标页，W01 不展开详情 |

### 10.2 键盘与焦点

- `⌘K` 聚焦应用壳全局搜索，不被 W01 覆盖。
- Tab 顺序：页头刷新 → 指标 → 分组控制 → 任务处理/查看 → 预警 → 最近打开。
- 指标使用原生按钮与 `aria-pressed`；不能用可点击 `div`。
- 折叠任务组使用 `aria-expanded` 和稳定标题关联。
- 筛选完成后焦点不跳走，结果数量通过 `aria-live=polite` 播报。
- 从目标页返回 W01 时，焦点恢复到原任务条目；任务已完成则落到同组下一项或组标题。
- 色彩不是唯一状态表达；所有超期、警告和失败均有文字。

## 11. 与其他工作面的关系

| 来源 / 去向 | Wxx | 携带上下文 | 返回规则 |
| --- | --- | --- | --- |
| 统一待办队列 | W02 | `scope`、`family`、`due`；任务焦点经 `sessionStorage`（内部 ID 不进 URL） | 返回保留 W01 筛选与任务焦点 |
| 销售单 | W05 | 稳定销售单 ID、来源 `workItemId` | 关闭/返回聚焦原任务 |
| 二次确认队列 | W07 | `currentWorkItemId=workItemId`、`queueContextId` | 队列页签保留；处理完成可回 W01 |
| 采购与履约 | W08 / W09 | 采购/履约对象 ID、来源 `workItemId` | 返回原任务或 W01 |
| 客户/供应商往来 | W11 / W12 | 往来主体、应收/应付对象、来源 `workItemId` | 正式结果完成后 W01 任务刷新 |
| 卡券票款复核 | W13 | `workItemId`、`queueContextId`、客户或销售单上下文 | 队列完成后返回 W01 |
| 同步与映射 | W17 / W21 / W29 | 异常/映射 `workItemId`、`queueContextId` | 解决后等待工作台统计刷新 |

跨工作面导航只传稳定身份和筛选上下文，不传金额、状态或权限结论作为事实。
