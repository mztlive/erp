# W14 · 基础资料

> 状态：正式
> 页面模式：M2 高密度查询列表 + M4 对象中心
> 主要路由：`/master-data/:resource`
> 主要角色：采购、运营、仓储；销售及财务按职责只读
> 最后更新：2026-08-04

## 1. 定位与目标

### 1.1 用户目标

用户在一个工作面内维护和核对会被销售、采购、履约及库存共同引用的基础资料族：

- 公司商品与 SKU（含主图/轮播/详情媒体、销售可见价/市场价及 W21 多供应商供给；销售查询中称为「公司商品池」）；
- 商品分类；
- 品牌；
- 卡券类目；
- 供应商、供应商能力、商务资料和资质；
- 仓库及仓库 SKU 预警策略。

用户应能回答：对象当前是否可用、当前生效的是哪个版本、何时生效或失效、为什么发生变更。对象详情中可展示「哪些业务场景可选用」的摘要；**不在列表页提供「业务选单预览 / 哪里能选到」类主动作或演示面板**。

### 1.2 业务目标

- 以稳定主对象 + 不可变修订表达基础资料变化，不覆盖历史版本。
- 销售、采购等业务页的选品/选供应商能力只返回当前场景真实可用的对象，并在提交时再次校验；该查询在各自业务工作面完成，不在 W14 列表重复做选单模拟。
- 把资质、能力、有效期和供应关系的业务约束放在同一对象上下文中展示。
- 让历史单据继续引用当时版本和结构化快照，不因基础资料后续变更而变化。
- 使用同一列表、对象中心和版本语言维护一组紧密关联的基础资料，而不是拆成多个互不相通的一级工作面。

### 1.3 不在本工作面完成

- 客户及客户归属在 W03 客户中心维护，不并入 W14。
- 正式销售单、采购单、库存流水和库存余额分别进入 W05、W08、W10；W14 不提供“修改历史单据”或“编辑库存”。
- 逐供应商供给由 W21 维护，API 连接由 W20 维护，商城发布由 W22 维护；W14 以稳定 SKU 展示关联摘要并提供新增供给入口。
- 商城玩法、限购、绑定、余额扣减和员工端陈列不进入 ERP 基础资料。
- 不在列表中直接覆盖当前版本；任何正式变更都形成新修订并保留原因和生效区间。
- **不在 W14 列表页提供「哪里能选到 / 选择器影响」按钮或候选清单演示**；业务页能否选到某主数据，以 W05 / W07 / W08 / W10 等页面的选品、选供应商、选仓库查询为准。

## 2. 用户、权限与数据范围

| 角色 | 默认资源 | 可见范围 | 主要动作 |
| --- | --- | --- | --- |
| 采购 | `products` / `suppliers` | 全部采购相关基础资料 | 新建、更新资料、停用公司商品与 SKU；维护供应商能力与资质；维护分类/品牌字典 |
| 运营 | `voucher-categories` / `categories` / `brands` | 卡券类目、分类、品牌及授权商品摘要 | 新建和变更卡券类目、分类、品牌；核对商城关联；不可维护商城玩法 |
| 仓储 | `warehouses` | 授权仓库及 SKU 策略 | 仅只读查询仓库资料、策略和库存摘要；禁止维护 |
| 销售 | 无默认模块入口 | 当前符合销售资格的公司 SKU、商品和卡券类目的只读结果 | 查看选择依据和失效原因，不可维护 |
| 财务 | `suppliers` 只读 | 供应商商务结算版本及授权敏感字段 | 在 W14 核对付款条件、税务、银行、开票与合同资料的授权摘要；银行资料完整维护必须从 W12 财务上下文进入 |
| 系统管理员 | 无业务默认入口 | 基础资料身份、版本和审计元数据 | 技术排障、权限配置；不得替采购或运营确认业务内容 |

权限规则：

- 无 W14 模块权限时不展示导航；直接访问返回无权限页。
- `resource` 级权限独立控制；有商品权限不等于有供应商银行资料权限。
- 有对象查看权但无维护权时，版本、有效期和使用影响可见，动作禁用并显示 `actionBlocker`。
- 银行账号、联系人、仓库地址和资质附件使用字段级权限；无权时保留标签并掩码，不向前端返回可逆明文。供应商银行账号等敏感商务字段：W14 供应商中心仅展示授权摘要；完整银行资料维护必须从 W12 财务上下文进入，禁止仅在 W14 完成银行资料全量维护。
- 页面打开期间权限被收回时，立即清除已揭示敏感值并切换到无权限态。
- 服务端按组织、区域和角色过滤列表；前端不得获取全量后再隐藏。
- 仓库资料及仓库 SKU 策略的查询必须可用。新建、形成版本、停用与策略维护必须禁止；服务端必须对上述写操作统一返回 `WAREHOUSE_WRITE_OWNER_UNCONFIRMED`。仓储与系统管理员均不得写入。仅当权限策略已发布唯一业务写责任方时，才向该责任方授予对应写权限；否则一律 fail-closed。

## 3. 入口、路由与任务页签

`resource` 使用固定注册值：`products`、`categories`、`brands`、`voucher-categories`、`suppliers`、`warehouses`。公司商品池不是独立 `resource`：它是公司 Product/SKU 在销售资格条件下的查询视图。未知值返回工作面内的“资源不存在”，不得回落到任意默认列表掩盖错误链接。

| 场景 | 入口 | URL / 页签行为 | 返回位置 |
| --- | --- | --- | --- |
| 从侧栏进入 | 基础资料导航：公司商品与 SKU（销售查询称公司商品池）/ 商品分类 / 品牌 / 卡券类目 / 供应商与资质 / 仓库 | `/master-data/{resource}` 直接进入对应资源 | 固定 W14 列表页签 |
| 角色默认落地 | 采购→公司商品与 SKU；运营→卡券类目；仓储→仓库；财务→供应商 | `/master-data` 按 `demoRole` 重定向，缺失或未知回落采购默认 | 重定向后进入对应资源列表 |
| 切换资源 | 工作面资源导航 | 替换 `:resource`，保留各资源自己的 Saved View | 浏览器后退恢复上一资源和筛选 |
| 打开对象 | 列表行、业务页“查看资料” | `/master-data/:resource/:stableId?section=overview`；**商品与 SKU 不使用侧边 sheet，直接进详情页**；同对象只聚焦已有页签 | 关闭后恢复原行、筛选和滚动位置 |
| 新建商品 | 列表「新建」 | `/master-data/products/new` 详情页（与查看同一套可编辑表单） | 成功后 `replace` 为 `/master-data/products/:id`，继续在同页维护 |
| 查看 / 更新商品 | 列表行、查看、更新资料 | `/master-data/products/:stableId` **详情即编辑**，保存形成新版本；无 `?mode=edit`、无侧边 sheet | 返回列表 |
| 查看历史版本 | 对象中心“变更历史” | URL 写入 `revision={revisionNo}`，当前版本与历史版本共用对象页签 | 后退恢复之前查看的版本 |
| 从业务页进入主数据 | W05 / W07 / W08 / W10 | 携带 `returnContext` 的稳定引用，不携带候选字段快照作为事实 | 返回时由业务页重新查询可选主数据 |
| 新建其他对象 | 非商品资源列表主动作「新建」 | 在当前资源任务页签打开资源专属对话框；未保存关闭时确认；商品与 SKU 不走此入口 | 成功后可打开稳定对象页签 |

TaskTabs 身份：列表为 `master-data:{resource}`，对象为 `master-data:{resource}:{stableId}`。历史修订号不是页签身份，避免同一对象打开多个版本副本。

刷新恢复当前资源、筛选、对象和修订号；不要求恢复临时确认框。未保存新建/变更草稿关闭时必须确认。对象权限被收回时保留稳定身份和返回上下文，不展示缓存内容。

## 4. 页面布局

### 4.1 桌面布局

```text
┌ PageHeader：基础资料 · 当前资源             [导出] [新建]
├ 资源导航：公司商品与 SKU（销售查询称公司商品池） | 商品分类 | 品牌 | 卡券类目 | 供应商与资质 | 仓库
├ ListToolbar：Saved View | 搜索 | 启用状态 | 版本状态 | 有效期 | 负责人 | 高级筛选
├──────────────────────────────────┬────────────────────────────────────┐
│ M2 资源列表                      │ M4 对象中心 / detail 预览           │
│ 资料编号 · 名称 · 当前版本        │ 身份、启用状态、生效期间、责任人     │
│ 启用状态 · 版本状态 · 关键关系     │ 概览 | 变更历史 | 引用与选用 | 操作记录 │
│ 行级：[查看] [更新资料] [停用]    │ 资源专属内容与业务引用摘要           │
└──────────────────────────────────┴────────────────────────────────────┘
```

列表页头仅保留 **导出** 与 **新建**；不提供「哪里能选到 / 选择器影响」主动作。  
列表单击：非商品资源可先开 `detail` 半屏核对；**商品与 SKU 直接打开对象详情页**（SPU + 规格 + SKU 表）。需要维护版本、查看完整关系或操作记录时进入对象中心任务页签。行级 **更新资料** 用于变更已有对象（形成新版本），与列表 **新建** 分离。

**新建 / 更新入口：**

| 资源 | 入口 | 布局 |
| --- | --- | --- |
| 商品与 SKU | **详情页即查看也是编辑**（`/master-data/products/new` 与 `/master-data/products/:id`） | SPU 信息（含独立商品类型）\| 规格维度（组合 SKU）\| SPU 轮播/详情图 \| SKU 表（产品编码/主图/条码/销售可见价/市场价、W21 供给入口、W10 库存入口）；页底变更历史/引用/审计；商品编辑主体不得使用 Dialog、Sheet 或 `?mode=edit`，仅允许关联 W10 的只读库存抽屉 |
| 商品分类 | **树形维护**（`/master-data/categories`） | 左侧可展开树 + 右侧节点详情；「新建根分类」/ 选中后「新建子分类」/「更新资料」/「停用」；详情面板提供「打开完整资料」进入对象中心；**无生效期间**；上级不可选自身与子树（防环） |
| 品牌 | 列表 + 标准对话框（`/master-data/brands`） | 行点击/回车打开侧栏预览 sheet（与其他资源一致）；「更新资料」仅保留在明确按钮上；字段：名称、品牌代码、**Logo（1:1 正方形）**；**无生效期间** |
| 其他资源 | 标准对话框（约 `max-w-lg`） | 单列资源专属字段 |

### 4.3 资源专属对象中心

| 资源 | 必须包含的子区 |

## 5. 展示内容与字段

### 5.1 通用字段

| 区域 | 字段 | 用户文案 | 数据来源 | 口径 / 格式 | 权限规则 |
| --- | --- | --- | --- | --- | --- |
| 列表 | `stableNo` | 基础资料编号 | 稳定主表 | 不随版本变化，可复制 | 有对象查看权可见 |
| 列表 | `name` | 名称 | 当前或所选未来修订 | 历史视图明确标“版本 N” | 字段权限 |

| 列表 | `scheduledLifecycleStatus` | 待生效后启用 / 停用 | 所选未来修订 | 仅 `revisionTiming=FUTURE` 且启停将变化时展示 | 全部有权用户 |
| 列表 | `revisionTiming` | 当前 / 待生效 | 当前或所选修订与 `effectiveAt` 的关系 | `CURRENT` / `FUTURE`；历史版本仅在对象时间线显示 `HISTORICAL` | 全部有权用户 |
| 列表 | `revisionNo` | 版本 | 当前或所选修订 | `v{n}` | 全部有权用户 |
| 列表 | `effectiveFrom/To` | 生效区间 | 当前或所选修订 | 业务时区；无截止写“长期” | 全部有权用户 |
| 列表 / 详情 | `selectorEligibility` | 哪些业务场景可选用（摘要） | 服务端可用性投影 | 可选 / 不可选 + 原因；仅作对象上下文说明，**不**在列表页展开候选清单演示 | 按业务权限返回 |
| 中心 | `changeReason` | 变更原因 | 修订事实 | 原文安全展示 | 有版本查看权 |
| 中心 | `usageSummary` | 使用影响 | 服务端关系投影 | 历史引用数与选用摘要，不作为正式计数事实 | 按关联对象范围过滤 |
| 中心 | `audit` | 创建、变更和停用记录 | `audit_event` | 操作人、时间、字段名；敏感值不显示 | 审计权限 |

#### 5.2.1 商品与 SKU 表单字段（详情页维护，SPU + 规格 → SKU）

以 **SPU 为列表/详情主对象**，规格维度取值**组合生成 SKU**。规格名和值由用户在当前 SPU
内直接维护，不要求提前创建全局规格属性或枚举值。界面**不展示、不手填「规格标识」**
（`specification_signature` 由当前 SPU 的规格名和值系统内部派生）。

规格编辑必须先按规范化规格名/值计算组合并展示“保留 / 新增 / 将重新启用 / 将停用”摘要。当前启用且
签名未变的组合沿用原 `skuId`；从未存在的新组合不携带旧 `skuId`，由服务端分配新身份；历史上
存在但已停用的签名再次出现时，必须显示原 `skuNo`、原 `skuId` 和阻塞摘要，由用户明确确认
“重新启用”并填写变更原因，提交原 `expectedSkuRevisionId`，不能静默当作新 SKU；被移除的组合
不从历史中删除，而在同一保存事务中停用原 SKU。`skuNo` 允许为全新组合生成或由业务覆盖，
但只是全局唯一业务编码，不能按编号、行序号或“当前仅一行”恢复旧 `skuId`，也不能重用已
停用 SKU 的编号绑定新组合。

### 5.3 版本与有效期表达

- 默认展示“当前时点生效版本”；未来版本明确标“待生效”，历史版本明确标“已结束”。启用/停用始终作为独立生命周期字段展示，不把 `FUTURE` 或 `HISTORICAL` 填入启停状态。
- 同一对象同类修订的生效区间不得重叠；创建新版本时服务端返回冲突位置。
- 停用不是删除。已被历史单据引用的身份和版本永久保留。
- 当前 SPU 内的规格名和值组合决定 SKU 身份；系统内部计算 `specification_signature`，UI 不展示手填「规格标识」，保存不得依赖全局规格字典。同一 SKU 不得通过修订改掉已落库的规格身份组合。编辑时按签名原子完成：未变组合保留身份、从未存在的新组合创建新 SKU、历史签名再次出现则复用原 `skuId` 并显式重新启用、移除组合停用旧 SKU；`skuNo` 不能参与身份匹配。
- 已被正式单据使用的 SKU 不得修改基础单位；界面提供“停用并新建 SKU”，不提供强行修改。
- 仓库仍有库存或有效预占时不得停用；阻塞原因必须展示数量摘要和 W10 钻取入口。
- 待生效修订：仅当该修订未被任何正式提交引用且尚未生效时，允许取消并必须记录审计；否则禁止取消，必须以新的纠正版本结束。

| 重新启用历史规格 SKU | 商品详情规格编辑产生“将重新启用”组合 | `REENABLE` + `CREATE_REVISION`；固定原 `skuId`、`expectedSkuRevisionId`，服务端 `actionBlockers` 为空 | 展示原产品编码、停用时间、历史引用、库存/预占与其他业务阻塞；用户明确确认并填写变更原因 | 原 SKU 追加修订并重新启用；不创建新身份；与本次其他保留/新增/停用变化原子提交 | 任一权限、资料完整性、库存/预占策略、合规或并发阻塞使整次规格编辑回滚，保留草稿 |
| 维护商品分类 | 资源导航「商品分类」树形页 | 字典 `CREATE` / `CREATE_REVISION` | 树节点 + 对话框；`parent_category_id` 可空（根）；代码稳定不可复用；禁止挂到自身/下级；**不填生效期间（立即生效）** | 形成字典版本；商品表单 `CategoryCombobox` 只展示当前启用项并显示路径 | 已被引用的字典停用不删除历史 SKU 上的引用快照 |
| 维护品牌 | 资源导航「品牌」列表 | 字典 `CREATE` / `CREATE_REVISION` | 标准对话框（无侧栏 sheet）；`brand_code` + 可选 Logo；**不填生效期间（立即生效）** | 形成字典版本；商品表单 `BrandCombobox` 只展示当前启用项 | 同上 |
| 停用 | 行级 / 对象中心 | `DISABLE`；无不允许的当前业务占用 | 确认停用时点及受影响场景 | 形成停用版本；历史引用不变 | 阻塞时显示具体业务条件和钻取入口 |
| 维护资质 | 供应商中心 | 采购资质权限；附件已上传 | 新增/换证展示适用能力和有效期 | 追加资质修订，更新到期预警 | 保留输入与安全扫描结果；扫描状态不阻断保存，不覆盖旧证据 |
| 维护合同与授权 | 供应商中心 | 采购维护权；附件已上传 | 展示合同/授权书编号、有效期与文件 | 追加修订并更新到期预警 | 保留输入与安全扫描结果；扫描状态不阻断保存，不覆盖旧证据 |
| 维护开票与评估 | 供应商中心 | 采购维护权 | 展示发票类型/税点、评分与评级 | 追加修订 | 保留输入；不覆盖旧证据 |
| 维护仓库 SKU 策略 | 仓库中心 | 仅当权限策略已发布唯一业务写责任方且服务端授予对应策略权限；数量单位与 SKU 一致 | 展示生效区间 | 形成有效期策略；不改库存余额 | 未发布唯一写责任时只读并返回 `WAREHOUSE_WRITE_OWNER_UNCONFIRMED`；仓储与系统管理员不得绕过 blocker |
| 查看/下载附件 | 资质或版本区 | 附件字段权限 | 完整敏感附件揭示需短时授权 | 使用受控下载并记录访问审计 | 授权失效即关闭内容，不泄露长期 URL |
| 导出 | 工具栏 | `EXPORT`；范围和字段已授权 | 大范围导出显示范围与用途 | 后台任务生成 7 天有效文件 | 失败保留任务记录并可重试，不导出无权字段 |
| 取消待生效修订 | 对象中心变更历史 | 具备版本维护权；修订 `revisionTiming=FUTURE`、尚未生效且未被任何正式提交引用 | 展示修订号、拟生效区间与引用检查结果；必须填写取消原因 | 待生效修订取消成功并写入审计；当前版本指针不变 | 已被引用或已生效时禁止取消，必须追加纠正版本 |
| 维护供应商银行资料 | W12 财务上下文 | 财务银行字段维护权 | 在 W12 完成完整维护 | 银行资料以 W12 写入结果为准；W14 仅刷新授权摘要 | 无 W12 权限时禁止在 W14 绕过维护 |

所有创建、版本变更和停用提交携带幂等键、`lockVersion`、基准修订和业务生效时间。结果不确定时不本地切换版本，停留当前对象并提供“查询提交结果”；确认无结果后才允许使用原幂等键重试。

禁止建设跨资源的统一基础资料复核/审批流；是否需要复核仅按各资源已定规则执行。所有正式版本必须保留审计。

## 8. 数据契约

### 8.1 查询

```ts
type MasterDataResource =
  | "products"
  | "categories"
  | "brands"
  | "voucher-categories"
  | "suppliers"
  | "warehouses"

type MasterDataListQuery = {
  resource: MasterDataResource
  q?: string
  lifecycleStatus?: "enabled" | "disabled" | "all"
  revisionTiming?: "current" | "future" | "all"
  effectiveAt?: string
  kind?: string[]
  capability?: string
  qualification?: string[]
  regionId?: string
  ownerUserId?: string
  savedViewId?: string
  sort: string
  cursor?: string
  pageSize: number
}

type MasterDataListItem = {
  objectType: string
  stableId: string
  stableNo: string
  name: string
  lifecycleStatus: "ENABLED" | "DISABLED"
  lifecycleStatusLabel: string
  scheduledLifecycleStatus?: "ENABLED" | "DISABLED"
  revisionTiming: "CURRENT" | "FUTURE"
  revisionTimingLabel: string
  currentRevisionId: string
  displayedRevisionId: string
  revisionNo: number
  effectiveFrom: string
  effectiveTo?: string
  keyFacts: Array<{ label: string; value: string; sensitive?: boolean }>
  selectorEligibility: Array<{
    context: string
    eligible: boolean
    blockerCodes: string[]
  }>
  allowedActions: string[]
  actionBlockers: Array<{ action: string; code: string; message: string }>
  lockVersion: number
}

type MasterDataListResult = {
  rows: MasterDataListItem[]
  nextCursor?: string
  totalCount: number
  permissionVersion: string
  effectiveAsOf: string
  eligibilityAsOf: string
  relationshipAsOf?: string
  queriedAt: string
}
```

- 列表与对象中心由 TanStack Query 管理，Query Key 包含资源、权限版本、数据范围版本、有效时点和筛选。
- 列表使用服务端分页、排序和过滤；有效期与对象级可用性摘要由服务端计算。
- 对象中心分别返回稳定身份、当前修订、修订时间线、资源专属关系、授权操作及 `effectiveAsOf/eligibilityAsOf/relationshipAsOf`。
- 业务页选品/选供应商等查询独立于 W14 列表缓存；正式提交前必须由业务接口重校验，不得以 W14 列表或详情中的可用性摘要代替提交校验。

### 8.2 提交

```ts
type CreateMasterDataRevisionCommand = {
  objectType: string
  stableId: string
  baseRevisionId: string
  lockVersion: number
  effectiveFrom: string
  effectiveTo?: string
  changeReason: string
  fields: Record<string, unknown>
  idempotencyKey: string
}

type MasterDataRevisionResult = {
  stableId: string
  stableNo: string
  revisionId: string
  revisionNo: number
  revisionState: "CURRENT" | "FUTURE"
  effectiveFrom: string
  recordedAt: string
  nextActions: string[]
}
```

正式 API 必须按资源使用强类型字段，不得直接采用示例中的通用 `Record` 作为长期契约。商品与 SKU 的 `fields` 至少包含：`spu`、必填 `productKind`、可选 `description`、`baseUnit`（单位字典 ID/代码）、`categoryId`、`brandId`、规格维度、`skus[]`；`productKind` 写入 `product.product_kind`，创建后不可变，不得从 `categoryId` 推导。每个 SKU 含 `skuNo`（产品编码，系统生成可覆盖）、属性值、`mainImage`、可选 `barcode`、`salesVisiblePrice` 与 `marketPrice`；编辑既有且签名未变的行还须携带稳定 `skuId` 与 `expectedSkuRevisionId`，新增签名不得由客户端指定或猜测旧 `skuId`。历史停用签名再次出现时，服务端返回原 `skuId`、`skuNo`、`expectedSkuRevisionId`、`actionBlockers` 和 `requiresExplicitReenable=true`；提交必须包含明确重新启用意图与 `changeReason`。服务端规范化属性代码/值代码后核对签名，以商品期望修订和所有受影响 SKU 期望修订原子提交“保留 / 新建 / 重新启用 / 停用”集合；不得按 `skuNo`、数组位置或单行回退匹配身份。两项价格属于 `sku_revision`，不是独立商品池条目或修订。SPU 可含 `carouselImages` / `detailImages`。商品与 SKU 契约**不得**包含默认 `supplierId`、`fulfillmentResponsibility`、`inputTaxRate`、`dropship*` 或 `bulk*` 供给字段；这些字段只进入 W21 的强类型 `supplier_offering` 契约。分类字段含 `code`、可选 `parent` / `productKind`；分类的适用类型只用于校验与筛选，不能成为公司商品类型的事实来源。品牌字段含 `code`。供应商 `fields` 至少包含：`company`（企业主体）、`contactName` / `contactPhone` / `address`、`settlement` / `capability` / `businessCategory` / `signingEntity` / `paymentEntity`、`qualification` / `contractFile` / `authorizationFile` / `foodLicense` / `legalPersonIdCard` 及对应合同与授权有效期、`taxNo` / `bankName` / `bankAccount` / `invoiceType` / `invoiceTaxRate`、`initialScore` / `supplierRating` / `currentScore`。所有表单使用 TanStack Form；生效区间、规格身份、基础单位、商品类型与分类兼容性、分类/品牌启用状态、主图完整性、供应商能力/资质及仓库占用由服务端最终校验。

公司商品池只读 API 固定为 `GET /admin/sellable-skus`。请求可包含 `q`、`product_kind`、`eligibility_as_of`、`page`、`page_size`；`eligibility_as_of` 缺省时由服务端取业务日。响应必须返回稳定 `sku_id`、`sku_version`、精确 `sku_revision_id`、`sku_revision_no`、修订生效区间、商品与 SKU 编码/名称、规格、基础单位、销售可见价、市场价、主图、有效供应商数量及供给区域。查询结果只允许包含同时满足以下条件的 SKU：稳定商品及其当前修订启用且处于有效区间；稳定 SKU 启用；稳定 SKU 指向的当前修订启用、处于有效区间且配置销售可见价；至少一条稳定 offering 启用，其当前修订可供且处于有效区间。API 不得投影供应商身份、采购成本、税率、起订量，不得产生独立商品池 ID、修订或写命令。销售单创建、草稿保存和提交必须使用同一资格规则校验 `sku_id + sku_revision_id` 精确对，并在各自写事务内复核；提交还须在形成提交快照前再次校验，任一引用失效即整单 fail-closed。

当 `objectType/resource="warehouses"` 时，查询契约不变，但 `allowedActions` 不得包含创建、形成版本、停用或策略维护；所有仓库写命令必须由服务端以 `WAREHOUSE_WRITE_OWNER_UNCONFIRMED` fail-closed。客户端禁止通过通用 `CreateMasterDataRevisionCommand`、管理员身份或隐藏入口绕过该门禁。仅当权限策略已发布唯一业务写责任方时，才允许在 `allowedActions` 中出现对应写动作。

### 8.3 前端边界

- 前端只格式化日期、金额、数量、状态文案和掩码。
- 前端可临时预览“即将到期”“本次变更字段数”，但不能据此决定对象正式可用性。
- 生命周期状态、版本状态、当前修订、有效期冲突、规格签名、资质适用性、历史引用数、对象级可用性摘要和 `allowedActions` 必须完全采用服务端返回；前端不得从日期把停用推成待生效，或把未来修订推成停用。
- 公司 SKU 修订中的销售可见价只用于销售选品/报价；采购成本只来自 W21 已确认供给修订，正式预计、确认和实际成本由采购及履约事实形成。前端禁止把 `product_pool_entry`、`sellable-items` 或其 mock 当作独立稳定资源、ID 或写入对象；必须使用公司 Product/SKU 与有效 offering 的查询投影。
- 历史单据使用的名称、单位、供应商和税务快照不得从当前基础资料回填重算。
- 卡券类目只表达 ERP 销售项，不接收、缓存或展示商城玩法规则。

| 财务 / 银行资料 | W12 | 供应商稳定 ID、银行字段维护上下文 | 完整银行资料必须在 W12 维护；返回 W14 时仅刷新授权摘要，不得以 W14 表单覆盖银行全量 |
| 导入与期初 | W18 | 来源身份、导入批次、候选对象 | 业务确认后形成 W14 正式身份/版本 |
| 权限与审计 | W19 | 对象类型、稳定 ID、审计时间范围 | 返回原对象审计子区 |

跨工作面只传稳定身份和精确修订引用。显示名称、状态、有效性和权限结论均由目标工作面重新查询。
