# W14 · 基础资料

> 状态：草稿
> 页面模式：M2 高密度查询列表 + M4 对象中心
> 主要路由：`/master-data/:resource`
> 主要角色：采购、运营、仓储；销售及财务按职责只读
> 最后更新：2026-08-01

## 1. 定位与目标

### 1.1 用户目标

用户在一个工作面内维护和核对会被销售、采购、履约及库存共同引用的基础资料族：

- 可销售项目；
- 商品与 SKU；
- 卡券类目；
- 供应商、供应商能力、商务资料和资质；
- 仓库及仓库 SKU 预警策略。

用户应能回答：对象当前是否可用、当前生效的是哪个版本、何时生效或失效、为什么发生变更，以及哪些业务选择器会受到影响。

### 1.2 业务目标

- 以稳定主对象 + 不可变修订表达基础资料变化，不覆盖历史版本。
- 让销售和采购选择器只返回当前场景真实可用的对象，并在正式提交时再次校验。
- 把资质、能力、有效期和供应关系的业务约束放在同一对象上下文中展示。
- 让历史单据继续引用当时版本和结构化快照，不因基础资料后续变更而变化。
- 使用同一列表、对象中心和版本语言维护一组紧密关联的基础资料，而不是拆成多个互不相通的一级工作面。

### 1.3 不在本工作面完成

- 客户及客户归属在 W03 客户中心维护，不并入 W14。
- 正式销售单、采购单、库存流水和库存余额分别进入 W05、W08、W10；W14 不提供“修改历史单据”或“编辑库存”。
- 二期 API 连接、外部商品映射、固定供给和商城发布分别进入 W20、W21、W22；W14 只展示其对正式商品的关联摘要。
- 商城玩法、限购、绑定、余额扣减和员工端陈列不进入 ERP 基础资料。
- 不在列表中直接覆盖当前版本；任何正式变更都形成新修订并保留原因和生效区间。

## 2. 用户、权限与数据范围

| 角色 | 默认资源 | 可见范围 | 主要动作 |
| --- | --- | --- | --- |
| 采购 | `sellable-items` / `suppliers` / `products` | 全部采购相关基础资料 | 新建、形成新版本、停用可销售项目；维护供应商能力与资质 |
| 运营 | `voucher-categories` | 卡券类目及授权商品摘要 | 新建和变更卡券类目；核对商城关联；不可维护商城玩法 |
| 仓储 | `warehouses` | 授权仓库及 SKU 策略 | 只读查询仓库资料、策略和库存摘要；Q1 未确认前不能维护 |
| 销售 | 无默认模块入口 | 当前可选可销售项目、商品和卡券类目的只读结果 | 查看选择依据和失效原因，不可维护 |
| 财务 | `suppliers` 只读 | 供应商商务结算版本及授权敏感字段 | 核对付款条件、税务和银行资料；维护入口按单独权限开放 |
| 系统管理员 | 无业务默认入口 | 基础资料身份、版本和审计元数据 | 技术排障、权限配置；不得替采购或运营确认业务内容 |

权限规则：

- 无 W14 模块权限时不展示导航；直接访问返回无权限页。
- `resource` 级权限独立控制；有商品权限不等于有供应商银行资料权限。
- 有对象查看权但无维护权时，版本、有效期和使用影响可见，动作禁用并显示 `actionBlocker`。
- 银行账号、联系人、仓库地址和资质附件使用字段级权限；无权时保留标签并掩码，不向前端返回可逆明文。
- 页面打开期间权限被收回时，立即清除已揭示敏感值并切换到无权限态。
- 服务端按组织、区域和角色过滤列表；前端不得获取全量后再隐藏。
- 仓库资料及仓库 SKU 策略的查询保持可用；在 Q1 明确唯一业务写责任并写入权限策略前，服务端对仓库新建、形成版本、停用和策略维护统一返回 `WAREHOUSE_WRITE_OWNER_UNCONFIRMED`，仓储与系统管理员都不得作为临时写入人。

## 3. 入口、路由与任务页签

`resource` 使用固定注册值：`sellable-items`、`products`、`voucher-categories`、`suppliers`、`warehouses`。未知值返回工作面内的“资源不存在”，不得回落到任意默认列表掩盖错误链接。

| 场景 | 入口 | URL / 页签行为 | 返回位置 |
| --- | --- | --- | --- |
| 从侧栏进入 | 基础资料导航：可销售项目 / 商品与 SKU / 卡券类目 / 供应商与资质 / 仓库 | `/master-data/{resource}` 直接进入对应资源 | 固定 W14 列表页签 |
| 角色默认落地 | 采购→可销售项目；运营→卡券类目；仓储→仓库；财务→供应商 | `/master-data` 按 `demoRole` 重定向，缺失或未知回落采购默认 | 重定向后进入对应资源列表 |
| 切换资源 | 工作面资源导航 | 替换 `:resource`，保留各资源自己的 Saved View | 浏览器后退恢复上一资源和筛选 |
| 打开对象 | 列表行、选择器“查看依据” | `/master-data/:resource/:stableId?section=overview`；同对象只聚焦已有页签 | 关闭后恢复原行、筛选和滚动位置 |
| 查看历史版本 | 对象中心“版本” | URL 写入 `revision={revisionNo}`，当前版本与历史版本共用对象页签 | 后退恢复之前查看的版本 |
| 从业务选择器进入 | W05 / W07 / W08 / W10 | 携带 `returnContext` 的稳定引用，不携带候选字段快照作为事实 | 返回时重新执行选择器查询 |
| 新建对象 | 列表主动作 | 在当前资源任务页签打开新建工作区；未保存时页签标脏 | 成功后转为稳定对象页签 |

TaskTabs 身份：列表为 `master-data:{resource}`，对象为 `master-data:{resource}:{stableId}`。历史修订号不是页签身份，避免同一对象打开多个版本副本。

刷新恢复当前资源、筛选、对象和修订号；不要求恢复临时确认框。未保存新建/变更草稿关闭时必须确认。对象权限被收回时保留稳定身份和返回上下文，不展示缓存内容。

## 5. 展示内容与字段

### 5.1 通用字段

| 区域 | 字段 | 用户文案 | 数据来源 | 口径 / 格式 | 权限规则 |
| --- | --- | --- | --- | --- | --- |
| 列表 | `stableNo` | 基础资料编号 | 稳定主表 | 不随版本变化，可复制 | 有对象查看权可见 |
| 列表 | `name` | 名称 | 当前或所选未来修订 | 历史视图明确标“版本 N” | 字段权限 |
| 列表 | `lifecycleStatus` | 当前启用 / 当前停用 | 稳定对象当前业务状态 | 与版本时序独立；未来修订拟改变启停时另显示 `scheduledLifecycleStatus`，不得提前改当前状态 | 全部有权用户 |
| 列表 | `scheduledLifecycleStatus` | 待生效后启用 / 停用 | 所选未来修订 | 仅 `revisionTiming=FUTURE` 且启停将变化时展示 | 全部有权用户 |
| 列表 | `revisionTiming` | 当前 / 待生效 | 当前或所选修订与 `effectiveAt` 的关系 | `CURRENT` / `FUTURE`；历史版本仅在对象时间线显示 `HISTORICAL` | 全部有权用户 |

| 列表 | `effectiveFrom/To` | 生效区间 | 当前或所选修订 | 业务时区；无截止写“长期” | 全部有权用户 |
| 列表 | `selectorEligibility` | 当前可被哪些场景选择 | 服务端可用性投影 | 可用 / 不可用 + 原因，不由前端推导 | 按业务权限返回 |
| 中心 | `changeReason` | 变更原因 | 修订事实 | 原文安全展示 | 有版本查看权 |
| 中心 | `usageSummary` | 使用影响 | 服务端关系投影 | 历史引用数、当前选择器影响，不作为正式计数事实 | 按关联对象范围过滤 |
| 中心 | `audit` | 创建、变更和停用记录 | `audit_event` | 操作人、时间、字段名；敏感值不显示 | 审计权限 |

### 5.2 资源关键字段

| 资源 | 列表关键字段 | 对象中心关键事实 | 数据来源 | 口径 / 新鲜度 | 权限规则 |
| --- | --- | --- | --- | --- | --- |
| 可销售项目 | 项目编号、SKU、参考供应商、参考含税成本、服务区域、交期、有效期、启停状态、修订时序 | 精确 `sellable_item_revision_id`、税率、允许履约方式、资质校验摘要 | 稳定对象、不可变修订及服务端资格投影 | 金额明确含税；资格返回 `eligibilityAsOf` | 销售可选字段与采购成本字段分权 |
| 商品与 SKU | 商品/SKU 编号、类型、名称、规格、分类、基础单位、启停状态、修订时序 | 规格属性与不可变签名、媒体版本、条码冲突、重量体积、历史引用 | 商品/SKU 稳定对象和当前修订 | 版本按 `effectiveAt`；关系摘要带 `relationshipAsOf` | 运营/采购维护；销售按选择器只读 |
| 卡券类目 | 类目编号、名称、启停状态、修订时序、有效期 | `product_kind=VOUCHER` 的 SKU、ERP 类目描述；不展示或保存玩法字段 | ERP 卡券类目修订 | 仅销售项口径，按有效时点 | 运营维护；不返回商城玩法字段 |
| 供应商与资质 | 供应商编号、名称、能力、资质到期、负责人、启停状态、修订时序 | 主体版本、商务版本、能力版本、证照编号/机构/有效期/适用能力、受控附件 | `party` 供应商角色、能力与资质修订 | 资质资格由服务端按业务日期计算并带 `eligibilityAsOf` | 采购维护；敏感商务/附件分权 |
| 仓库 | 仓库代码、名称、区域、启停状态、修订时序、有效期 | 加密地址/联系人、SKU 预警策略、库存/预占只读摘要 | 仓库修订、策略修订；W10 只读摘要 | 基础资料按有效时点；库存摘要带独立正式水位 | 查询按仓库范围与敏感字段权返回；Q1 未确认前不授予任何仓库写操作 |

### 5.3 版本与有效期表达

- 默认展示“当前时点生效版本”；未来版本明确标“待生效”，历史版本明确标“已结束”。启用/停用始终作为独立生命周期字段展示，不把 `FUTURE` 或 `HISTORICAL` 填入启停状态。
- 同一对象同类修订的生效区间不得重叠；创建新版本时服务端返回冲突位置。
- 停用不是删除。已被历史单据引用的身份和版本永久保留。
- 商品规格身份变化必须新建 SKU，不允许通过同一 SKU 修订改变 `specification_signature`。
- 已被正式单据使用的 SKU 不得修改基础单位；界面提供“停用并新建 SKU”，不提供强行修改。
- 仓库仍有库存或有效预占时不得停用；阻塞原因必须展示数量摘要和 W10 钻取入口。

## 6. 搜索、筛选、排序与默认视图

| 能力 | 默认值 | URL 状态 | 行为 |
| --- | --- | --- | --- |
| 搜索 | 空 | `q` | 按稳定编号、名称、SKU/供应商/仓库代码搜索；不对敏感字段全文检索 |
| 启停状态 | 启用 | `lifecycleStatus=enabled` | 只筛稳定对象当前的启用/停用业务状态；不包含“待生效”或未来拟变更值 |
| 修订时序 | 当前 | `revisionTiming=current` | 可切当前、待生效、全部；历史修订从对象时间线进入 |
| 有效期 | 当前时点 | `effectiveAt` | 查看某业务日期可用版本；时间由服务端解释 |
| 资源专属筛选 | 无 | `kind`、`capability`、`region`、`qualification` 等 | 只显示当前资源适用筛选 |
| 负责人 | 全部有权数据 | `owner` | 服务端数据范围过滤 |
| 排序 | 名称 / 稳定编号 | `sort` | 到期预警视图按 `validTo` 升序 |
| Saved View | 最近使用 | `view` | 保存资源、筛选、排序和列；不保存敏感字段值 |

1440×900 下列表需露出至少 6–8 行。可销售项目和供应商的到期视图提供“30 天内到期”“已过期”；到期状态由服务端返回，不以浏览器时钟改变正式可用性。

业务选择器不复用 W14 的任意 Saved View，而使用场景化查询：

| 选择器场景 | 服务端必须校验 |
| --- | --- |
| 销售选品 | 可销售项目启用、当前有效、区域匹配、履约方式允许，返回精确修订 ID |
| 采购确认/建单选供应商 | 供应商角色启用、能力匹配、适用资质有效、业务日期有效 |
| 选择商品/SKU | SKU 启用、规格身份稳定、基础单位存在；场景需要时同时校验可销售项目 |
| 选择卡券类目 | `product_kind=VOUCHER`、当前版本启用有效；不读取商城玩法 |
| 仓储选择仓库 | 仓库当前有效、数据范围允许；库存操作另由 W10 校验 |

## 7. 操作契约

| 操作 | 入口 | 权限 / 前置条件 | 确认 | 成功结果 | 失败恢复 |
| --- | --- | --- | --- | --- | --- |
| 新建稳定对象 | 列表主动作 | 对应资源 `CREATE` | 提交前展示身份与初始版本摘要 | 创建稳定编号和 v1，固定结果区给出对象号 | 保留表单；重复提交按幂等键返回同一对象 |
| 形成新版本 | 行级动作 / 对象中心 | `CREATE_REVISION`；基准版本仍为当前 | `BusinessDiffPanel` 展示前后值、生效时间和选择器影响 | 追加不可变修订；即时生效时原子更新 `currentRevisionId`，未来修订只按有效区间保持待生效，当前指针不得提前切换 | 版本冲突不覆盖，提供刷新比较 |
| 停用 | 对象中心更多动作 | `DISABLE`；无不允许的当前业务占用 | 确认停用时点及受影响场景 | 形成停用版本；历史引用不变 | 阻塞时显示具体业务条件和钻取入口 |
| 维护资质 | 供应商中心 | 采购资质权限；附件安全检查通过 | 新增/换证展示适用能力和有效期 | 追加资质修订，更新到期预警 | 保留输入与安全扫描结果；不覆盖旧证据 |
| 维护仓库 SKU 策略 | 仓库中心 | Q1 已确认唯一写责任且服务端授予对应策略权限；数量单位与 SKU 一致 | 展示生效区间 | 形成有效期策略；不改库存余额 | Q1 未确认时只读并返回 `WAREHOUSE_WRITE_OWNER_UNCONFIRMED`；不得让仓储或系统管理员绕过 blocker |
| 查看/下载附件 | 资质或版本区 | 附件字段权限 | 完整敏感附件揭示需短时授权 | 使用受控下载并记录访问审计 | 授权失效即关闭内容，不泄露长期 URL |
| 导出 | 工具栏 | `EXPORT`；范围和字段已授权 | 大范围导出显示范围与用途 | 后台任务生成 7 天有效文件 | 失败保留任务记录并可重试，不导出无权字段 |

所有创建、版本变更和停用提交携带幂等键、`lockVersion`、基准修订和业务生效时间。结果不确定时不本地切换版本，停留当前对象并提供“查询提交结果”；确认无结果后才允许使用原幂等键重试。

## 8. 数据契约

### 8.1 查询

```ts
type MasterDataResource =
  | "sellable-items"
  | "products"
  | "voucher-categories"
  | "suppliers"
  | "warehouses"

type MasterDataListQuery = {
  resource: MasterDataResource
  q?: string
  lifecycleStatus?: "enabled" | "disabled" | "all"
  revisionTiming?: "current" | "future" | "all"
  effectiveAt?: string
  kind?: string[]
  capability?: string
  qualification?: string[]
  regionId?: string
  ownerUserId?: string
  savedViewId?: string
  sort: string
  cursor?: string
  pageSize: number
}

type MasterDataListItem = {
  objectType: string
  stableId: string
  stableNo: string
  name: string
  lifecycleStatus: "ENABLED" | "DISABLED"
  lifecycleStatusLabel: string
  scheduledLifecycleStatus?: "ENABLED" | "DISABLED"
  revisionTiming: "CURRENT" | "FUTURE"
  revisionTimingLabel: string
  currentRevisionId: string
  displayedRevisionId: string
  revisionNo: number
  effectiveFrom: string
  effectiveTo?: string
  keyFacts: Array<{ label: string; value: string; sensitive?: boolean }>
  selectorEligibility: Array<{
    context: string
    eligible: boolean
    blockerCodes: string[]
  }>
  allowedActions: string[]
  actionBlockers: Array<{ action: string; code: string; message: string }>
  lockVersion: number
}

type MasterDataListResult = {
  rows: MasterDataListItem[]
  nextCursor?: string
  totalCount: number
  permissionVersion: string
  effectiveAsOf: string
  eligibilityAsOf: string
  relationshipAsOf?: string
  queriedAt: string
}
```

- 列表、对象中心和选择器均由 TanStack Query 管理，Query Key 包含资源、权限版本、数据范围版本、有效时点和筛选。
- 列表使用服务端分页、排序和过滤；有效期、资格状态和选择器可用性全部由服务端计算。
- 对象中心分别返回稳定身份、当前修订、修订时间线、资源专属关系、授权操作及 `effectiveAsOf/eligibilityAsOf/relationshipAsOf`。
- 列表结果允许短缓存；正式提交前不能依赖缓存中的 `eligible=true`，必须重校验。

### 8.2 提交

```ts
type CreateMasterDataRevisionCommand = {
  objectType: string
  stableId: string
  baseRevisionId: string
  lockVersion: number
  effectiveFrom: string
  effectiveTo?: string
  changeReason: string
  fields: Record<string, unknown>
  idempotencyKey: string
}

type MasterDataRevisionResult = {
  stableId: string
  stableNo: string
  revisionId: string
  revisionNo: number
  revisionState: "CURRENT" | "FUTURE"
  effectiveFrom: string
  recordedAt: string
  nextActions: string[]
}
```

正式 API 必须按资源使用强类型字段，不得直接采用示例中的通用 `Record` 作为长期契约。所有表单使用 TanStack Form；生效区间、规格身份、基础单位、供应商能力/资质及仓库占用由服务端最终校验。

当 `objectType/resource="warehouses"` 时，Q1 未确认期间查询契约不变，但 `allowedActions` 不得包含创建、形成版本、停用或策略维护；所有仓库写命令由服务端以 `WAREHOUSE_WRITE_OWNER_UNCONFIRMED` fail-closed。客户端不能通过通用 `CreateMasterDataRevisionCommand`、管理员身份或隐藏入口绕过该门禁。

### 8.3 前端边界

- 前端只格式化日期、金额、数量、状态文案和掩码。
- 前端可临时预览“即将到期”“本次变更字段数”，但不能据此决定对象正式可用性。
- 生命周期状态、修订时序、当前修订、有效期冲突、规格签名、资质适用性、历史引用数、选择器可用性和 `allowedActions` 必须完全采用服务端返回；前端不得从日期把停用推成待生效，或把未来修订推成停用。
- 参考成本只用于选品提示；正式预计、确认和实际成本由销售、采购及履约事实形成。
- 历史单据使用的名称、单位、供应商和税务快照不得从当前基础资料回填重算。
- 卡券类目只表达 ERP 销售项，不接收、缓存或展示商城玩法规则。

| 权限收回 | 清除敏感值，内容切无权限态 | 返回有权模块 | 权限恢复后重查 |
