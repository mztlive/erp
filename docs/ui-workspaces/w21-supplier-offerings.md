# W21 供应商供给

> 本文件是 W21 的界面、接口和验收执行合同。

## 1. 业务目标

W21 维护公司 SKU 与供应商之间的正式供给关系。公司 `product` / `sku` 是唯一商品主数据；
W21 不创建供应商商品、供应商 SPU/SKU 主档、商品映射或商品池对象。

固定操作顺序：

1. 在 W14 创建公司商品及 SKU；
2. 为具体公司 SKU 添加供应商供给；
3. 后续分别修订商业条款或更新当前可供情况。

## 2. 路由与权限

| 项目 | 合同 |
| --- | --- |
| 主路由 | `/procurement/supplier-offerings` |
| SKU 筛选 | `?skuId={sku_id}` |
| 返回地址 | `?returnTo={encoded_path}` |
| 查看 | `supplier_offering:list` |
| 新增 | `supplier_offering:create` |
| 修订条款/状态 | `supplier_offering:update` |
| 更新可供 | `supplier_offering_availability:update` |
| 查看成本 | `supplier_offering_cost:detail` |

前端权限只用于裁剪入口。服务端必须对每个请求重新鉴权；无成本权限时列表响应必须清除
价格、税率和费用字段。

## 3. 数据所有权

| 数据 | 唯一所有者 | 规则 |
| --- | --- | --- |
| 商品名称、规格、条码、单位、销售可见价、市场价 | W14 `product` / `sku` 修订 | W21 只读展示，不得复制或修改 |
| 供应商、供应商商品编码、供应商订货 SKU 编码、来源 | `supplier_offering` | 稳定供给身份 |
| 一件代发价、集采价、税率、费用、集采起订量、区域、能力、有效期 | `supplier_offering_revision` | 不可变追加修订 |
| 可供状态、可供数量、来源更新时间 | `supplier_offering_availability` | 每条供给唯一一行的可变投影 |
| 历史下单供应商编码 | `supplier_fulfillment_item` 快照 | 不从当前供给反查 |

## 4. 列表合同

列表必须以供给关系为行，不得以供应商商品、SPU 或映射为行。

| 列 | 内容 |
| --- | --- |
| 公司商品 / SKU | 公司商品名称、SKU 编码、规格 |
| 供应商 / 订货编码 | 供应商名称、`supplier_sku_code`、来源 |
| 供给价格 | 一件代发含税价、集采含税价；无成本权限时显示空值 |
| 起订量 / 区域 | 集采起订量、可供区域 |
| 当前可供 | 可供状态、可供数量 |
| 关系状态 | 启用、暂停、停止及当前条款修订号 |
| 操作 | 更新可供、修订条款 |

常驻筛选只包含供应商 SKU 编码、公司 SKU、供应商和关系状态。列表不提供商品变化队列、
同款匹配、关联、反向建品、入池或映射动作。

## 5. 添加供给

入口包括：

- W14 商品详情 SKU 行的“添加供给”；
- W21 页头的“添加供给”。

W14 入口必须固定 `sku_id`；W21 通用入口必须先选择一个已启用公司 SKU。

### 5.1 必填字段

| 字段 | 规则 |
| --- | --- |
| 公司 SKU | 必须存在且启用；固定入口不可改 |
| 供应商 | 必须存在、启用并满足供给准入 |
| 供应商 SKU 编码 | 必填；同一供应商内唯一；用于下单与对账 |
| 一件代发供给价（含税） | 非负，最多 4 位小数 |
| 集采供给价（含税） | 非负，最多 4 位小数 |
| 进项税率 | UI 使用百分比，提交为 0–1 小数 |
| 集采起订量 | 大于 0，最多 6 位小数 |
| 可供区域 | 至少一项 |
| 生效日期 | 必填业务日期 |
| 初始可供状态 | 可供、不可供、停止供应、数据已过期 |
| 登记原因 | 必填 |

供应商商品编码、失效日期、快递说明、运费、服务费和当前可供数量可空。可供数量为空表示
供应商未返回数量上限，不表示零。

### 5.2 原子性

新增命令必须在一个服务事务内完成：

1. 创建 `supplier_offering`；
2. 创建首版 `supplier_offering_revision`；
3. 创建 `supplier_offering_availability`；
4. 写幂等结果和审计日志。

任一步失败必须整体回滚。客户端不得分三次请求补齐初始状态。

## 6. 修订商业条款

修订必须提交 `expected_revision_no`、完整新条款、可选关系状态、变更原因和幂等键。
成功后形成新的不可变修订并更新当前修订指针。不得覆盖旧修订，不得修改公司 SKU，也不得
同时覆盖当前可供投影。

暂停或停止关系必须通过修订命令明确提交。暂停/停止后不得参与新采购选源；历史订单不变。

## 7. 更新当前可供

可供更新只提交：期望投影版本、可供状态、可供数量、来源时间/版本、变更原因和幂等键。

- 来源时间早于当前投影时必须拒绝；
- 数量不得为负；
- 数量为零时不得参与采购选源；
- 更新成功不得增加商业条款修订号；
- API 同步与人工更新使用同一投影合同。

## 8. HTTP 合同

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| `GET` | `/admin/supplier-offerings` | 查询供给列表 |
| `POST` | `/admin/supplier-offerings` | 新增供给、首版条款和初始可供投影 |
| `POST` | `/admin/supplier-offerings/{id}/revisions` | 追加商业条款修订 |
| `POST` | `/admin/supplier-offerings/{id}/availability` | 更新当前可供投影 |

旧 `/admin/supplier-catalog/*` 路由不得保留或兼容。

## 9. 状态与失败处理

| 情况 | 页面行为 |
| --- | --- |
| 空数据 | 提示先创建公司商品，再添加供给 |
| 筛选无结果 | 保留筛选并提供清除入口 |
| 列表失败 | 保留已输入筛选，展示重试 |
| 并发冲突 | 不乐观覆盖；刷新当前版本后重新提交 |
| 幂等结果未知 | 使用原幂等键查询或重试，不生成第二条供给 |
| 成本无权限 | 身份与可供信息可见，成本字段为空 |

## 10. 验收清单

- [ ] 项目不存在供应商商品/SPU/SKU 主档及映射数据类型。
- [ ] W14 创建商品后可直接为每个 SKU 添加多家供应商供给。
- [ ] 新增供给同时形成身份、首版条款和初始可供投影。
- [ ] 修改条款只增加修订号，不改公司 SKU 或可供投影。
- [ ] 更新可供只增加投影版本，不增加条款修订号。
- [ ] 采购选源同时校验关系状态、条款有效期和当前可供投影。
- [ ] 履约明细保存供应商订货编码快照，不引用供应商目录 SKU ID。
- [ ] 无成本权限的响应不包含价格、税率和费用。
- [ ] 旧商品库、映射、入池、正向和反向入口全部不存在。
