# W28 · 卡券消费台账与经营分析

> 状态：草稿
> 页面模式：M6 只读分析
> 主要路由：`/analytics/card-business`
> 主要角色：财务、管理层；销售、运营按数据范围只读
> 最后更新：2026-08-01

## 1. 定位与目标

### 1.1 用户目标

- 财务和管理层能按期间、客户、销售单和卡券类目查看销售、消费、余额、成本及经营结果，并理解每个指标的含税/不含税口径。
- 用户看到任何利润类金额时，同时看到成本覆盖率和 `ACTUAL`、`STANDARD`、`NONE` 构成，知道结果的可信范围。
- 销售能在授权客户范围内从汇总下钻到原销售单和消费事实；运营能定位消费、供应商履约或成本覆盖异常。

### 1.2 业务目标

- 把卡券企业销售、员工消费、商城退款、供应商成本、直接履约费用和未履约余额形成可追溯的只读经营投影。
- 允许在成本覆盖不足时展示经营结果，但必须清楚标识其偏乐观性质，禁止把 `NONE` 当成零成本。
- 分开卡券支付和微信支付：微信支付成本正常进入供应商结算，但不污染企业卡券消费与利润指标。
- 保持分析为可重建投影；页面和导出不能反向修改任何正式事实。
- 分析投影消费正式 outbox 后延迟不超过 60 秒，保存已消费 outbox 水位，并每天从正式版本、流水、关键事实和核销明细全量核对及重建；重建只修复查询投影，不修改正式事实。

### 1.3 不在本工作面完成

- 不登记或纠正消费、退款、余额、成本、应收、应付、回款和发票。
- 不在分析页修改成本口径；`ACTUAL`、`STANDARD`、`NONE` 由正式成本评估链决定。
- 不把卡券全部消费视为履约完成；卡券履约仍以销售单履约期限到期为唯一条件。
- 不把“当前经营贡献”命名或解释为最终利润。
- 不展示完整卡号、卡密、绑定手机号，也不建设员工画像。

## 2. 用户、权限与数据范围

| 角色 | 默认入口 | 可见范围 | 主要动作 |
| --- | --- | --- | --- |
| 财务 | 卡券经营总览 | 财务授权组织、客户与期间 | 查看全口径指标、成本构成、下钻、导出 |
| 管理层 | 经营总览 | 管理数据范围 | 查看汇总、趋势、客户/类目排名和风险，不默认查看员工履约明细 |
| 销售 | 我的客户 | 当前及历史参与客户范围 | 查看客户、销售单和卡券汇总；下钻授权销售单 |
| 运营 | 消费与覆盖 | 负责商城、类目和商品范围 | 查看消费、成本覆盖、未归集和供应商履约关联 |
| 系统管理员 | 投影水位 | 仅运行状态与授权汇总 | 查看投影/回填新鲜度，进入 W29/W30；无默认利润明细权限 |

权限与范围规则：

- 无模块权限隐藏入口；直接访问显示无权限页。
- 所有聚合由服务端在当前数据范围内计算，前端不得先取全公司数据再筛选。
- 销售人员不因能看客户汇总而自动获得全部消费商品、员工标识或供应商成本明细。
- `mallUserRef`、稳定卡实例引用、供应商成本和利润分别使用字段权限；卡实例仅显示不可逆稳定引用摘要。
- 无成本明细权限时仍可看到经授权的成本覆盖率和风险等级，但具体成本金额按字段规则隐藏。
- 权限版本变化后，所有分析 Query Key 失效；已下载导出链接在下载时再次鉴权。

## 5. 展示内容与字段

### 5.1 核心指标

| 指标 | 用户文案 | 数据来源 | 口径 / 格式 | 权限规则 |
| --- | --- | --- | --- | --- |
| `cardSalesAmountGross` | 卡券销售金额（含税） | 正式卡券销售明细 | 企业客户正式成交金额 | 销售按客户范围 |
| `cardFaceValueGross` | 可消费总额度（含税） | 面值 + 配赠 | 服务端聚合 | 授权汇总可见 |
| `cumulativeCardConsumptionGross` | 累计卡券消费（含税） | 卡券支付消费 − 卡券退款 | 不含微信支付 | 按消费范围 |
| `unconsumedBalanceGross` | 未消费余额（含税） | 商城有效余额快照 | 展示快照时间，不用 ERP 推导余额冒充实时 | 按客户范围 |
| `consumptionRate` | 消费率 | 累计卡券消费 ÷ 可消费总额度 | 比率；分母为 0 时返回不可计算 | 授权汇总可见 |
| `coveredConsumptionGross` | 已覆盖消费（含税） | 当前成本评估为 ACTUAL/STANDARD 的消费金额 | 覆盖率分子 | 成本权限可看金额；否则看比率 |
| `costCoverageRate` | 成本覆盖率 | 已取得成本的卡券消费金额 ÷ 累计卡券消费金额 | 含税同口径比值 | 所有利润查看者强制可见 |
| `consumptionCostNet` | 实际消费成本（不含税） | `ACTUAL + STANDARD` 成本 − 供应商成本退款 | `NONE` 不贡献 0，只排除 | 成本金额权限 |
| `consumptionMarginNet` | 消费毛差（不含税） | 不含税卡券消费 − 不含税分摊成本 | 必须与覆盖率同屏 | 利润权限 |
| `currentContributionNet` | 当前经营贡献（不含税） | 卡券销售收入净额 − 已发生成本净额 − 直接履约费用净额 | 不是最终利润；同屏显示未履约余额 | 利润权限 |
| `unfulfilledBalanceGross` | 未履约余额（含税） | 尚未消费且仍承担履约责任的额度 | 不与净利润相减 | 授权汇总可见 |
| `finalProfitNet` | 最终经营盈亏（不含税） | 履约期限到期后的完整收入 − 成本 − 直接费用 | 未到期范围不展示为最终利润 | 利润权限 |

### 5.2 成本口径构成

| 口径 | 页面文案 | 成本来源 | 是否进入利润 | 展示规则 |
| --- | --- | --- | --- | --- |
| `ACTUAL` | 实际成本 | 供应商下单/履约/结算、人工确认或商城订单成本快照 | 是 | 展示消费金额、成本金额、占比和来源下钻 |
| `STANDARD` | 标准成本 | 消费发生时点有效的供应商供给版本价 | 是 | 明确“按历史有效供给价估算”，不得写“实际” |
| `NONE` | 无可用成本 | 商城成本不可用且消费时点无有效供给；或税口径不足无法计算 | 否 | 只进入消费额和覆盖率分母；不得显示成本 0 或利润 |

`ACTUAL + STANDARD + NONE` 的卡券消费金额必须等于当前筛选下累计卡券消费金额。成本来源是逐笔消费属性，不按卡券售出时间、卡实例或整张卡一次性分组。

### 5.3 图表与明细

| 区域 | 字段 / 维度 | 数据来源 | 展示与口径 |
| --- | --- | --- | --- |
| 趋势 | 销售、消费、退款、余额 | 分析投影 | 时间粒度随期间切换；销售与消费不可用同一日期语义时图例明确 |
| 覆盖构成 | ACTUAL/STANDARD/NONE 消费金额和占比 | 成本评估链尾投影 | 三段必须可读，不能只用颜色 |
| 经营趋势 | 消费毛差、当前贡献、覆盖率 | 分析投影 | 利润金额不含税，覆盖率作为同屏辅助轴/标注 |
| 客户/类目构成 | 客户、销售单、卡券类目 | 销售与消费归集 | 排名不越过数据范围；“其他”可展开 |

| 新鲜度 | `projectionUpdatedAt`、`consumedOutboxWatermark`、`sourceFactWatermark`、`balanceSnapshotAt`、`lagSeconds/slaState` | 投影、正式事实 outbox 与商城快照 | 投影、正式事实、余额快照分别显示；分析投影 SLA 固定 60 秒，余额快照时间独立，不合并成一个“实时” |

筛选改变时保留旧图表并显示轻量刷新；指标、图表和明细必须使用同一筛选摘要、权限版本和投影水位。所有可点击图表点、图例和指标使用按钮语义或明确链接语义；纯展示指标不显示交互暗示。

`periodPreset` 仅是 URL 快捷值；路由层将其归一化为明确的 `from/to` 并写回 URL。查询与跨 W 下钻只使用已解析的 `from/to`，不使用另一套 `period` 参数。

## 8. 数据契约

### 8.1 查询

```ts
type CardBusinessAnalyticsQuery = {
  from: string
  to: string
  dateBasis: "consumption" | "sales" | "expiry"
  dimension: "customer" | "sales_order" | "voucher_category" | "card_instance"
  customerId?: string
  salesOrderId?: string
  voucherCategoryId?: string
  costBasis?: Array<"ACTUAL" | "STANDARD" | "NONE">
  expiryState?: "active" | "expired"
  coverage?: "below_threshold" | "none"
  compare?: "previous_period"
  sort: string
  page: number
  pageSize: number
}

type CardBusinessAnalyticsView = {
  scope: { timezone: string; currency: "CNY"; filterDigest: string }
  freshness: {
    projectionUpdatedAt: string
    consumedOutboxWatermark: string
    sourceFactWatermark: string
    balanceSnapshotAt?: string
    lagSeconds: number
    maxLagSeconds: 60
    slaState: "WITHIN_SLA" | "BREACHED" | "REBUILDING" | "FAILED"
    state: "fresh" | "stale" | "rebuilding" | "failed"
  }
  coverage: {
    coveredConsumptionGross: string
    totalConsumptionGross: string
    rate: string | null
    threshold: string
    status: "complete" | "acceptable" | "warning" | "insufficient"
    byBasis: Array<{
      basis: "ACTUAL" | "STANDARD" | "NONE"
      consumptionGross: string
      costNet?: string
      share: string
    }>
  }
  metrics: AuthorizedCardMetric[]
  trends: CardBusinessSeries[]
  breakdowns: CardBusinessBreakdown[]
  rows: Page<CardBusinessRow>
}
```

服务端必须为每个金额指标返回 `taxBasis: "GROSS" | "NET"`、`currency`、`valueState` 和说明代码；不可计算返回 `null + reasonCode`，不能返回 0 冒充。Query Key 包含用户、角色、权限和数据范围版本、全部筛选、投影版本及页面粒度。

投影处理每个正式 outbox 事件后更新 `consumedOutboxWatermark`，并以服务端统一安全时间计算 `lagSeconds`。`maxLagSeconds` 固定为 60；超过即返回 `slaState=BREACHED`，页面标陈旧并进入监控告警，不得仍显示“实时”。系统每天从正式销售版本、消费/退款/余额事实、成本与分配、供应商履约及核销明细执行全量核对和可重建投影；重建失败保留最近成功结果和水位，只影响查询新鲜度。`balanceSnapshotAt` 仅表示商城有效余额快照时间，不参与投影 SLA 计算，也不能由 ERP 推导余额替代。

### 8.2 提交

本工作面没有业务 mutation。

- 保存个人视图属于非正式 UI 偏好，不改变分析或业务事实。
- 导出只创建 `background_job`，引用不可变选择/筛选快照并在下载时重新鉴权。
- 发现错误必须进入来源对象、W29 或 W30 的正式纠错/治理路径，分析页面不提供“改数”。

### 8.3 前端边界

- 指标、覆盖率、成本构成、利润、税额换算和阈值判断全部使用服务端返回。
- 前端不得把 `NONE` 成本填成 0、不得用当前供给价替换历史标准成本、不得用销项税率换算进项成本。
- 前端只格式化金额、比率、日期、图表比例和口径文案；图表汇总必须与服务端 totals 校验一致。
- 不使用浏览器当前页明细求总计、排名、覆盖率或“其他”。

## 12. 验收清单

### 12.1 口径与可信度

- [ ] 任何消费毛差、当前经营贡献和最终盈亏均与成本覆盖率同屏。
- [ ] `ACTUAL`、`STANDARD`、`NONE` 的消费金额和占比同时可见，三者合计等于累计卡券消费。
- [ ] `NONE` 不显示为零成本，也不进入成本和利润指标。
- [ ] 成本覆盖不足阈值时利润明确标记“成本不完整，结果仅供参考”。
- [ ] 销售/面值/消费/余额使用含税口径，成本和利润使用不含税口径，页面逐项标注。
- [ ] 消费毛差两侧均为不含税；进项税率不被销项税率替代。
- [ ] 当前经营贡献与未履约余额同屏，未到期范围不展示“最终利润”。
- [ ] 微信支付消费与成本不进入企业卡券消费和利润指标。
- [ ] Q2 默认日期口径未配置时不静默采用“本月/消费发生日”，也不显示虚假 0 指标；用户显式选择的 `from/to/dateBasis` 完整进入 URL 和 Query Key。

### 12.2 数据与权限

- [ ] 成本口径按消费记录而非整张卡分组，历史变更不覆盖旧评估。
- [ ] 投影、正式事实 outbox 和余额快照分别展示水位；`lagSeconds`、固定 60 秒 SLA 与越界告警可见，陈旧数据不宣称实时。
- [ ] 每日从正式版本、流水、关键事实和核销明细全量核对并可重建分析投影；重建失败不修改正式事实。
- [ ] 销售只能查看有权客户，管理层汇总不会泄露员工或敏感履约明细。
- [ ] 稳定卡实例引用不可反推卡号/卡密，页面不存在卡号、卡密和绑定手机号字段。
- [ ] 导出包含口径、筛选、数据水位和覆盖率，并在下载时重新鉴权。

### 12.3 体验与响应式

- [ ] 指标、图表、明细使用同一筛选摘要和数据水位。
- [ ] 图表具备键盘和读屏等价数据，不依赖颜色或 hover。
- [ ] 浏览器刷新、后退和跨对象下钻能恢复分析上下文。
- [ ] §9 状态和 §10 五档视口全部通过。
- [ ] 页面没有业务写入口，不存在“编辑台账”或“手工改利润”。
