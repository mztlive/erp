# W12 · 供应商往来

> 状态：已定
> 页面模式：M2 高密度查询列表 + M5 分摊/核销工作区
> 主要路由：`/finance/supplier-accounts`
> 主要角色：财务；采购和管理层按授权只读
> 最后更新：2026-08-05

## 1. 定位与目标

### 1.1 用户目标

- 财务按供应商查看采购单或供应商结算单形成的应付、实际付款、进项发票和待核销余额。
- 一次完成“登记实际付款 + 分配到同一供应商的多笔应付”，或“登记进项发票 + 分配到同一供应商的多个可收票对象”。
- 从采购单或履约付款门禁直接进入已预选的付款会话，完成后返回原单并看到服务端重新判定的门禁结果。
- 从原付款、进项发票或应付上下文发起供应商退款、付款冲正或红票纠错，保留全部原事实。

### 1.2 业务目标

- 把应付、付款、进项发票保持为三类独立事实；付款核销和进项票核销分别多对多。
- 同一供应商的付款可核销采购单应付和第二期供应商结算单应付；不同供应商绝不混入同一会话。
- 付款、发票和核销结果在事务内同步更新，供 W08/W09 的付款门禁和 W27 结算结果立即查询。
- 一期采购与二期 API 供应商结算复用同一付款/进项票内核，不为来源类型另建平行票款页面。

### 1.3 不在本工作面完成

- 不审核或修改采购单，不确认供应商结算差异；分别进入 W08 和 W27。
- 不把财务审核通过当作实际付款，也不把银行附件或未核销付款当作先款后货门禁完成。
- 不合并付款和进项发票轨道；收票不表示已付款，付款不表示已收票。
- 不跨供应商核销；相同名称但稳定供应商 ID 不同仍必须分会话。
- 不编辑已过账付款、已登记发票、应付分录和已过账分配；纠错追加退款、冲正、红票及反向分配。
- 不在 W12 处理供应商订单执行、取消或结算差异，只展示它们形成的正式应付来源。

## 2. 用户、权限与数据范围

| 角色 | 默认入口 | 可见范围 | 主要动作 |
| --- | --- | --- | --- |
| 财务经办 | W12 | 授权组织和供应商的应付、付款、进项票 | 登记、分配、保存草稿、发起纠错 |
| 财务复核 | W02 财务纠错/审核队列 | 待复核纠错及原事实 | 只读核对；在队列完成正式复核 |
| 采购 | W08/W26/W27 链入 | 本人采购与供应商协作范围的付款、收票进度 | 只读，不登记或核销 |
| 仓储 | W09 链入 | 完成付款门禁判断所需的状态摘要 | 必须仅见“已满足/未满足及原因”；禁止见已付/差额金额及无关金额 |
| 管理层 | 分析入口 | 授权组织汇总与必要明细 | 只读，不显示写入口 |

权限规则：

- 无 W12 模块权限时隐藏导航；直接访问显示无权限页。
- 服务端按组织、供应商和来源单据范围过滤；前端不得获取全量后裁剪。
- 有模块权限但无数据范围时显示无范围状态，不展示 0 元假结论。
- 供应商银行账户和付款凭证默认掩码；完整揭示由字段权限和短时授权控制，日志永不记录完整值。
- 有应付查看权但无付款/发票登记权时，动作禁用并展示服务端 `actionBlocker`。
- 普通供应商付款正式过账不要求财务复核；禁止为普通付款增加复核流程。仅付款纠错、供应商退款和进项红票必须遵守财务经办/复核分离，服务端校验实际用户不能相同。
- 仓储角色在付款门禁中必须仅见完成作业所需的「已满足/未满足及原因」；禁止向仓储披露具体已付金额、差额金额或其它无关金额明细。
- 页面期间权限被收回时清除敏感字段、导出结果和会话缓存；禁止继续正式提交。

## 3. 入口、路由与任务页签

| 场景 | 入口 | URL / 页签行为 | 返回位置 |
| --- | --- | --- | --- |
| 侧栏进入 | 供应商往来 | `/finance/supplier-accounts?view=payable`，聚焦固定 W12 列表页签 | 原页签保留 |
| 从采购单进入 | W08 票款子区 / `PrepaymentGate` | 携带供应商、应付账户/分录、采购单和来源页签 ID | 完成后回 W08 并重新查询门禁 |
| 从履约门禁进入 | W09 | 携带采购单和来源作业；目标仍由应付事实确定 | 完成后回原作业，门禁由服务端重判 |
| 从结算单进入 | W27 | 携带供应商结算单、应付账户和来源页签 | 完成后回 W27 原票款区 |
| 选择供应商后登记 | W12 工具栏 | 创建稳定草稿会话 ID，在同一 W12 TaskTab 进入 M5 工作区 | 返回原列表筛选和行焦点 |
| 浏览器刷新/后退 | 任意列表/会话 | 恢复 URL 筛选与稳定草稿会话；敏感揭示状态不恢复 | 原视图 |

固定列表页签身份为 `workspace:supplier-accounts:{viewerScopeId}`。核销会话身份为 `allocation:supplier:{draftSessionId}`，标题为 `核销 · {供应商简称}`。对象详情与编辑状态在同一 TaskTab 内切换，不制造 `/new`、`/edit` 平行路由树；同一草稿重复打开只聚焦已有会话。

### 4.3 区域与视图规则

| 区域 / 视图 | 目的 | 规则 |
| --- | --- | --- |
| 应付台账 | 看采购单/结算单来源的开放应付和到期情况 | 只读派生，不提供“编辑应付” |
| 付款 | 看实际付款事实及净有效分配 | 财务审核结果不能出现在此处冒充付款 |
| 进项发票 | 看蓝/红进项票及净有效分配 | 与付款进度独立 |
| 待核销 | 看存在有效剩余的付款和进项票 | 分区展示，两类余额不相加 |
| detail 预览 | 列表内读来源、金额、付款/收票进度和反向关系 | 768px 双栏；重作业进入核销会话 |
| 核销工作区 | 同供应商多对多分配 | 来源类型可混合，供应商不可混合 |

## 5. 展示内容与字段

### 5.1 应付台账

| 字段 | 用户文案 | 数据来源 | 口径 / 格式 | 权限规则 |
| --- | --- | --- | --- | --- |
| `supplierName` / `supplierId` | 供应商 | `payable_account.supplier_id` | 核销主体稳定身份 | 必须可见才能进入会话 |
| `sourceType` | 来源类型 | `PURCHASE_ORDER` / `SUPPLIER_SETTLEMENT` | 用户文案为“采购单/供应商结算单” | 按来源模块权限 |
| `sourceDocumentNo` | 来源单据 | `source_document_id` 的授权投影 | 稳定业务编号，可钻取 | 按对象查看权 |
| `grossTotal` | 应付总额 | `payable_account` 同步汇总 | 含税人民币，服务端返回 | 金额权限 |
| `settledTotal` / `openTotal` | 已核销付款 / 开放应付 | 净有效付款分配汇总 | `APPLY - REVERSE`，前端不重算 | 金额权限 |
| `invoicedTotal` / `openInvoiceableTotal` | 净已收票 / 剩余可收票 | 净有效进项票分配汇总 | 与付款轨道独立 | 金额权限 |
| `dueDate` | 到期日 | `payable_entry` | 自然日；到期判断由服务端返回 | 可见 |
| `status` | 未结 / 部分结清 / 已结清 | `payable_account.status` | 不根据采购状态或收票状态猜测 | 可见 |
| `paymentGateSummary` | 付款门禁 | 采购版本条件 + 有效已过账付款净核销投影 | 只展示服务端结论、门槛和差额 | 有采购票款权限时显示 |

应付 detail 还需显示分录类型、增加/减少方向、正数含税金额、来源事实/版本、到期日，以及 `payable_entry_offset` 冲减关系。采购变更、结算差额和供应商退款只追加分录，不修改已确认应付。

### 5.2 付款与分配

| 字段 | 用户文案 | 数据来源 / 口径 |
| --- | --- | --- |
| `paymentNo` | 付款单号 | `supplier_payment.payment_no`，正式形成后唯一 |
| `supplierName` | 收款供应商 | 必须等于全部目标应付的供应商 |
| `paidAt` | 实际付款时间 | 业务发生时间；与记录时间分开 |
| `amount` | 付款金额 | 正数含税金额 |
| `bankReference` / attachment | 银行流水 / 付款凭证 | 敏感值掩码；附件不等于付款已完成 |
| `allocatedTotal` / `unallocatedAmount` | 净已分配 / 未分配 | 服务端按有效 `APPLY - REVERSE` 返回 |
| `status` | 草稿 / 已过账 / 已冲正 | 原付款保留，冲正追加反向事实 |
| 分配明细 | 来源类型、来源单号、应付分录、序号、动作、金额、时间、反向来源 | `payment_allocation` |

只有**有效已过账且已核销到相关采购应付**的净付款金额才可参与 `PREPAY` 门禁。W12 不用“付款附件已上传”“付款草稿已保存”替代该结论。

### 5.3 进项发票与分配

| 字段 | 用户文案 | 数据来源 / 口径 |
| --- | --- | --- |
| `invoiceCode` / `invoiceNo` | 发票代码 / 号码 | 统一 `invoice`；按方向和规范化号码去重 |
| `invoiceKind` | 蓝票 / 红票 | 红票必须引用原蓝票 |
| `invoiceDate` | 开票日期 | 业务日期 |
| `gross/net/taxAmount` | 含税 / 不含税 / 税额 | 服务端正式金额，前端只格式化 |
| `roundingAdjustmentAmount/reason` | 发票尾差 / 原因 | 独立记录，不反改采购单价 |
| `allocatedTotal` / `unallocatedAmount` | 净已分配 / 未分配 | 服务端净有效分配；付款分配不参与 |
| 分配明细 | 采购单/结算单、应付账户、含税/不含税/税额、动作和反向来源 | `purchase_invoice_allocation` |

## 6. 搜索、筛选、排序与默认视图

| 能力 | 默认值 | URL 状态 | 行为 |
| --- | --- | --- | --- |
| 视图 | `payable` | `view` | 切换时保留供应商和单号筛选 |
| 供应商 | 全部有权供应商 | `supplierId` | 核销会话创建后锁定 |
| 来源类型 | 全部 | `sourceType` | 采购单 / 供应商结算单；二期启用后同表展示 |
| 单号搜索 | 空 | `q` | 采购单、结算单、付款单、发票号服务端搜索 |
| 状态 | 开放优先 | `status` | 未结、部分结清、已结清等服务端枚举 |
| 到期 | 全部开放 | `due` | 未到期 / 今日到期 / 已到期由服务端判定 |
| 付款门禁 | 全部 | `paymentGate` | 仅用于有采购来源的应付 |
| 排序 | 服务端应付优先级策略 | `sort`（仅显式排序） | 默认顺序由 `payablePriorityPolicyId/version` 决定，不在前端硬编码到期日或来源号；显式排序不改正式分配优先级 |

- 核销池只返回当前 `supplierId` 的开放应付，可同时包含采购单和结算单来源。
- 查询响应必须返回本次排序所用的 `payablePriorityPolicyId/version` 和可用状态。策略缺失、失效或版本不一致时，不提供采购单与结算单混合自动分配，也不声称存在默认优先级；用户必须显式逐项选择目标，或先按来源类型分组处理。
- 1440×900 下指标、工具栏和分页同时存在时至少露出 6–8 条有效行。
- 金额列右对齐，供应商/来源单号与行级主动作固定；服务端分页使用稳定 row ID。
- 导出使用当前权限和筛选的服务端冻结快照；不在浏览器遍历全量页。
- 应付台账列头标注口径：「应付（含税）/ 开放（含税）」「已付（净）/ 已收票（净）」；用户对比两列时基数一致。
- 应付台账支持按到期日、供应商、开放金额列头排序（显式排序不改正式分配优先级）。
- 待核销视图提供「轨道」筛选（全部/付款/进项票），避免混排两轨道数字与指标不对应。
- 「清除筛选」同时清除深链带入的 `purchaseOrderId`，采购单筛选导致空结果时可一键还原。
- 从应付行发起核销时，分配金额与记录金额均按开放余额预填，避免双份输入；发票代码不预填演示值，为空值 + 必填提示。
- 进项发票提交校验「不含税 + 税额 = 含税」（允许 1 分钱差异）；红票号码必填，不允许回退生成时间戳号码。
- 待核销视图「继续核销」若无法解析出原付款/发票，按钮禁用并提示回到对应视图操作，禁止静默降级为新单登记。

## 7. 操作契约

| 操作 | 入口 | 权限 / 前置条件 | 确认 | 成功结果 | 失败恢复 |
| --- | --- | --- | --- | --- | --- |
| 登记付款并核销 | 页头、供应商行、W08/W09/W27 | 有登记权；供应商已确定；目标应付有效；满足服务端提交策略 | 正式提交确认 | 形成付款单和有效分配，显示付款单号、未分配余额及来源返回入口 | 保留草稿；并发冲突刷新双侧余额；结果未知查询原操作 |
| 对已有付款继续核销 | 付款/待核销行 | 付款已过账且有有效余额 | 正式提交确认 | 追加 `APPLY` 分配，不改原付款 | 超额时保留选择并显示最新余额 |
| 登记进项发票并核销 | 页头、供应商行、W08/W27 | 号码唯一、供应商一致、金额校验通过 | 正式提交确认 | 形成独立发票与分配，显示票号和净剩余 | 重复票号定位已有发票，不创建副本 |
| 对已有进项票继续核销 | 发票/待核销行 | 蓝票存在有效余额 | 正式提交确认 | 追加进项票 `APPLY` 分配 | 并发变化后重新确认 |
| 保存会话草稿 | 核销工作区 | 草稿可写、无他人占用 | 无 | 保存输入、附件和目标选择，不形成正式事实 | 保留输入；处理权丢失时禁止正式提交 |
| 发起供应商退款/付款冲正 | 原付款或应付 detail | 有纠错发起权和业务依据 | 确认原事实和影响金额 | 形成纠错草稿并进入财务复核 | 保留原因与附件；结果未知查询操作号 |
| 发起进项红票 | 原蓝票 detail | 有红票权限及有效可红冲分配 | 确认原票和金额；红票号码必填 | 形成独立红票及必要反向分配 | 超额/并发时刷新原票有效余额 |
| 导出当前往来 | 列表工具栏 | `EXPORT`；范围、字段和供应商均已授权 | 大范围时展示筛选、行数、金额口径和遮罩规则 | 创建服务端快照与后台任务，返回任务号和 7 天下载入口 | 任务失败可按原快照重试；不在浏览器拼全量数据 |

付款/进项票正式过账是否必须一次分配完，必须由服务端提交策略返回；禁止在前端硬编码分配完毕策略。UI 必须始终展示未分配余额与正式结果。仅当服务端策略允许时，可保留未分配余额进入待核销队列；否则提交必须被拒绝并展示策略阻断原因。禁止通过先登记后跳转另一菜单掩盖未核销状态。

- 成功结果横幅可收起；工具条摘要不重复展示「N 条」计数（分页条已有「共 N 条」）。
- 「门禁/过账」类术语按术语表 G5 替换为「先款条件/已入账」：「返回来源并重新校验先款条件」「先款条件已满足/未满足」「先款条件待满足」；策略标识（`id@v版本`）不上屏，改为业务口径说明。
- 演示控件（策略、权限、异常路径）折叠为「演示选项（仅演示环境）」；提交结果被「已有发票」阻断时提供「前往进项发票视图」跳转按钮，兑现文案承诺。

## 8. 数据契约

### 8.1 查询

```ts
type SupplierAccountsQuery = {
  view: "payable" | "payment" | "purchase_invoice" | "unallocated"
  supplierId?: string
  sourceType?: "PURCHASE_ORDER" | "SUPPLIER_SETTLEMENT"
  q?: string
  status?: string[]
  due?: "not_due" | "due_today" | "overdue"
  paymentGate?: "satisfied" | "unsatisfied"
  occurredFrom?: string
  occurredTo?: string
  cursor?: string
  pageSize: number
  sort?: string[]
}

type PayablePriorityPolicyView = {
  payablePriorityPolicyId?: string
  payablePriorityPolicyVersion?: number
  state: "AVAILABLE" | "MISSING" | "STALE"
  mixedAutoAllocationAllowed: boolean
  blockerMessage?: string
}
```

查询响应至少包含权限/范围版本、数据更新时间、稳定对象 ID、服务端总数、分页游标、金额币种与口径、`PayablePriorityPolicyView`、`allowedActions/actionBlockers`。列表、核销池和来源门禁分别由 TanStack Query 管理；Query Key 包含用户、角色、供应商范围版本、主体、来源、优先级策略 ID/版本和全部筛选。

### 8.2 提交

付款提交至少包含：稳定草稿 ID、供应商、实际付款时间、正数含税金额、银行引用/附件、追加式目标分配、应付基线版本和请求幂等键。进项发票提交还包含发票方向、蓝/红类型、号码、含税/不含税/税额、尾差和原因、原票引用（红票适用）。

使用服务端优先级顺序或混合自动分配时，命令必须回传查询时取得的 `payablePriorityPolicyId/version`；策略缺失、未配置或提交时已变化则服务端 fail-closed，客户端不得退化为“到期日 + 来源号”自行排序，也不得声称存在默认优先级。混合自动分配与默认优先级仅当有效 `payablePriorityPolicyId/version` 可用时开放；否则用户必须显式逐项选择目标，或先按来源类型分组处理。用户显式逐项选择或按来源类型分组时仍由服务端校验每个目标，不得把选择顺序提升为全局默认规则。

服务端必须在一个事务或等价一致性机制中：

1. 校验权限、供应商、发票号码和来源状态；
2. 按稳定顺序锁定付款/发票、全部目标应付账户和分录；
3. 重算双侧净有效余额，拒绝跨供应商和超额分配；
4. 写正式事实与追加式分配；
5. 更新应付、付款、收票同步汇总；
6. 返回正式对象号、操作号、更新时间和付款门禁重查提示。

重复提交沿用同一幂等键。超时后按操作号查询最终结果；不得更换新键重复付款或重复登记发票。来源页在返回时必须重新查询门禁，不能信任 W12 传回的布尔值。

### 8.3 前端边界

- 开放应付、净付款、净收票、未分配余额和付款门禁均采用服务端结果。
- 前端拟分配合计仅用于当前表单提示，不是正式核销事实。
- 付款分配目标是 `payable_entry`；进项票分配目标是 `payable_account`，不可混用无类型 ID。
- 供应商结算差额和退款追加应付分录，不改写原应付；W12 不计算结算差异。
- 采购审核状态、付款进度和履约进度分别记录；UI 不根据其中一项推断其它状态。

## 9. 页面状态矩阵

| 状态 | 页面表现 | 可执行动作 | 恢复方式 |
| --- | --- | --- | --- |
| 优先级策略缺失/陈旧 | 显示策略 blocker；不显示混合默认顺序 | 显式逐项选择目标、按来源类型分组、刷新策略 | 取得有效 `payablePriorityPolicyId/version` 后才开放混合自动分配 |
| 初载 | 指标、工具栏、表格或核销双栏 Skeleton | 应用壳导航可用 | 原位替换 |
| 刷新 | 保留旧金额和来源，显示数据更新时间 | 查看；正式提交前重校验 | 成功更新，失败可重试 |
| 空数据 | “当前范围尚无供应商往来事实” | 清除筛选、进入有权采购/结算来源 | 应付形成后刷新 |
| 筛选无结果 | 保留筛选摘要 | 清除筛选 | 返回有权数据 |
| 无数据范围 | 不显示 0 元指标 | 查看角色/申请范围 | 范围更新后重查 |
| 查询失败且无缓存 | `BusinessFailureState`，不显示 0 元或门禁已满足结论 | 重试、返回来源 | 查询恢复 |
| 失败有缓存 | 保留旧数据并标陈旧 | 查看；依赖门禁的作业不得信任旧结论 | 重试成功 |
| 字段级隐藏 | 银行/金额按权限掩码，结构保持 | 其它有权动作 | 权限更新后重查 |
| 草稿保存中/失败 | 禁止重复保存，输入不丢 | 重试 | 保存成功 |
| 正式提交失败 | 主动作附近显示错误，保留分配 | 修正、用同一草稿重试 | 服务端校验通过 |
| 版本冲突 | 显示目标应付变化，不静默重排分配 | 刷新并重新确认 | 接受新基线后提交 |
| 正式动作成功 | `FormalActionResult` 固定展示付款/发票号、分配、未分配余额、时间和下一步 | 返回 W08/W09/W27、继续核销 | 来源页重查应付和门禁 |
| 结果不确定 | 固定结果区显示操作号，不更新付款门禁 | 查询最终结果、联系支持 | 确认终态后刷新来源 |
| 后台导出 | `BackgroundJobProgress` 显示筛选快照、金额口径和任务号 | 查看任务 | 完成后下载；失败按原快照重试 |
| 权限收回/处理权丢失 | 清除敏感值并禁止提交 | 返回列表 | 权限恢复后重取 |
