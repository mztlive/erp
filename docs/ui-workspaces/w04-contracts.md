# W04 · 合同 PDF 档案

> 状态：已实现
> 页面模式：M2 高密度查询列表 + M4 只读对象中心
> 主要路由：`/sales/contracts`；对象路由 `/sales/contracts/:contractId`
> 主要角色：销售、销售领导；财务与历史单据参与者按权限只读
> 最后更新：2026-08-03（W05 列表合同号可下载原始 PDF）

## 1. 定位与确定规则

W04 是已签署合同电子档的归档和查询工作面，不是合同起草、编辑或审批工具。

以下规则为确定规则：

1. ERP 不提供“新建合同”、合同正文编辑、空合同草稿或“提交生效”能力。
2. 合同进入 ERP 的唯一入口是上传电子档，当前只接受单个 PDF，单文件不超过 20 MB。
3. 上传成功同时形成 `contract` 稳定身份、首个不可变 `contract_revision` 和 PDF 文件资产关联；不允许先创建空对象再补文件。
4. 后续补充协议或换签版本也必须上传签署后的 PDF，并形成新的不可变版本；历史销售单继续引用原版本。
5. 新建销售单只能选择已有有效合同；无合同时可在合同选择框旁点加号，复用与 W04 相同的「上传合同 PDF」Dialog 原地归档并刷新可选列表，再选中新合同。
6. 一份合同允许关联多张销售单。合同不汇总成另一套应收、回款、开票或履约账本。

## 2. 用户目标与边界

用户需要完成：

- 按合同号、客户、结算主体、状态、有效期和负责人快速定位合同；
- 上传已签署合同 PDF 并补充检索与销售引用所需的最小元数据；
- 查看合同 PDF、安全检查状态、版本时间线、审计与关联销售单；
- 从有效合同直接进入 W05，新销售单固定引用当前合同版本。

本工作面不完成：

- 合同拟稿、在线编辑、用印、签署、审批或正文内容生成；
- 根据 PDF 在浏览器内自行推导正式付款、开票、金额或状态；
- 修改已生效销售单、应收、回款或发票；
- 从关联销售单金额反推“合同金额”。当前业务模型没有该正式事实。

## 3. 用户、权限与数据范围

| 角色 | 默认入口 | 可见范围 | 主要动作 |
| --- | --- | --- | --- |
| 负责销售 | 我的合同 | 当前负责客户合同与已参与历史单据所引用版本 | 上传合同 PDF、从合同建销售单 |
| 协作销售 | 协作客户合同 | 有效协作期内可见；历史按参与权 | 按 `allowedActions` 查看或上传 |
| 销售领导 | 团队合同 | 本团队客户合同 | 查看、按授权终止、建销售单 |
| 财务 | 销售单/往来深链 | 票款职责范围内合同结算与开票摘要 | 只读核对 |
| 历史单据参与者 | 历史销售单合同链接 | 该历史单据固定的合同版本 | 只读 |

权限规则：

- 列表、对象、PDF 元数据和下载分别鉴权；下载使用短时链接并记录审计。
- 动作由服务端 `allowedActions` 与 `actionBlockers` 决定，前端不根据角色名推导。
- 页面打开期间权限收回时，清除未提交的文件、下载 URL 和敏感缓存，保留安全的返回上下文。
- 客户停用时不允许上传新合同或创建销售单，历史合同与销售引用继续可读。

## 4. 入口、路由与页签

| 场景 | 入口 | URL / 页签行为 | 返回位置 |
| --- | --- | --- | --- |
| 查询合同 | 侧栏“合同” | `/sales/contracts`，筛选写入 URL | 保留原任务页签 |
| 从客户中心进入 | W03 合同摘要/上传动作 | `/sales/contracts?customerId=...`，预设客户范围并打开上传层 | 返回 W03 原客户子区 |
| 单击列表行 / Enter | 合同列表 | 开启 detail 半屏，URL 可保留 `preview={contractId}` | 关闭后焦点回原行 |
| 打开合同中心 | detail 底栏、全局搜索 | `/sales/contracts/:contractId`，聚焦稳定对象页签 | 关闭后回来源页签 |
| 上传合同 PDF | 列表或 W03 | 在 Dialog 内选择 PDF 并补充元数据；成功后可打开对象中心 | 失败保留文件与输入 |
| 从合同建销售单 | 合同中心主动作 | W05 携带 `customerId`、`contractId`、`contractRevisionId` | 保存/提交后可回合同中心 |

列表页签身份为 `contracts:list:{userId}`；对象页签身份为 `contract:{contractId}`。上传层不是独立路由，刷新不恢复本地文件选择。

## 5. 页面布局与交互设计

### 5.1 M2 列表（1440×900）

```text
┌ PageHeader：合同                                  [上传合同 PDF] ┐
├ MetricStrip：全部 | 有效 | 30天内到期 | 已到期                 ┤
├ ListToolbar：搜索 | 客户 | 状态 | 有效期 | 负责人 | 导出         ┤
├──────────────────────────────────────────────────────────────┤
│ 合同编号↑ | 客户 | 结算主体 | 有效期 | 状态 | 版本 | 销售单 | 负责人 | 操作 │
│ 36px 紧凑数据行，1440×900 首屏至少 6–8 条                        │
└──────────────────────────────────────────────────────────────┘
```

- 页头唯一主动作是“上传合同 PDF”，不出现“新建合同”。
- 指标全部是筛选按钮，使用 `aria-pressed`、选中态和当前筛选摘要。
- 单击行空白或 Enter 打开 detail 半屏；明确“打开合同中心”才创建对象页签。

### 5.2 上传 Dialog

字段顺序固定为：

1. 合同 PDF；
2. 合同编号；
3. 客户（`CustomerCombobox`）与结算主体（`SettlementPartyCombobox`）；
4. 付款条件（`OptionCombobox` / 码表，不自由长文本录入）；
5. 签订日期、有效期起、有效期止；
6. “上传并归档”。

PDF 为必填。文件类型、扩展名、空文件和大小在选择后就地校验；正式归档仍由服务端复验并完成安全扫描。元数据用于检索、选择与销售快照，完整合同正文始终以 PDF 为准。客户与结算主体禁止自由文本录入。

### 5.3 detail 半屏

detail 显示合同号、客户、状态、版本、签订日、有效期、结算/付款摘要、PDF 数量与关联销售摘要。底栏提供“关闭”“纸质预览”“打开合同中心”，不提供编辑或生效动作。

### 5.4 M4 只读对象中心

```text
┌ PageHeader：销售 › 合同 › HT-2026-0088        [返回] [纸质预览] ┐
├ DocumentHeader：东方企业 [生效] HT-2026-0088 · v3 [新建销售单] │
├ PDF 电子档归档 · 有效期 · 负责人                              │
├ 锚点：概览 | 结算与开票 | 合同 PDF | 关联销售单 | 版本与审计    │
├──────────────────────────────────────────────────────────────┤
│ 只读元数据、付款/开票摘要、PDF 安全状态、销售引用和审计          │
└──────────────────────────────────────────────────────────────┘
```

对象中心不出现“创建修订”“编辑草稿”“提交生效”或通用附件上传。需要归档新签署版本时，从合同列表统一上传入口按合同号进入版本归档能力；该能力必须继续要求 PDF。

## 6. 展示字段

| 区域 | 字段 | 口径 | 权限 |
| --- | --- | --- | --- |
| 列表 | 合同号、客户、结算主体、状态、版本、签订日、有效期 | 服务端正式查询 | 按客户范围 |
| PDF | 文件名、类型、大小、版本、上传者/时间、安全状态 | 只有 `application/pdf` 可成为合同正文 | 列表与下载分别鉴权 |
| 结算摘要 | 结算主体、付款条件、开票要求 | 上传时登记的结构化摘要；正文以 PDF 为准 | 销售/财务字段权限 |
| 关联销售 | 单号、业务性质、合同版本、状态、三轨进度、含税金额 | 金额只作单据摘要 | 按每张销售单裁剪 |
| 版本 | 版本号、有效区间、上传时间、文件身份 | 历史版本不可覆盖 | 需版本查看权 |
| 审计 | 上传、下载、终止等动作 | 敏感值只记摘要 | 按审计权限 |

合同状态只使用 `EFFECTIVE`、`TERMINATED`、`EXPIRED`。W04 不产生 `DRAFT` 合同。

## 7. 操作契约

| 操作 | 前置条件 | 成功结果 | 失败恢复 |
| --- | --- | --- | --- |
| 上传合同 PDF | `UPLOAD_CONTRACT_PDF`；客户启用；单个合法 PDF；合同号、签订日和有效期完整 | 原子形成合同身份、v1、文件关联和审计；返回合同 ID、版本 ID、文件名、时间和操作号 | 不创建空合同；保留选择和输入；重复请求使用同一幂等键 |
| 归档后续 PDF 版本 | 已存在合同；新签署 PDF；版本前置校验通过 | 追加不可变版本并切换当前版本；历史销售引用不变 | 冲突后重查当前版本，不覆盖历史 |
| 终止合同 | `TERMINATE`；服务端完成影响校验 | 合同转终止，新销售不可选，历史引用不变 | 阻断时列出需先处理对象 |
| 纸质预览/下载 | 合同可见且 PDF 安全检查完成 | 通过短时链接查看或下载并写审计 | 扫描中或隔离时不可下载 |
| 他页引用下载 | W05 销售单列表点合同号等 | 解析合同中心可下载正文 PDF 并触发下载（`downloadOriginalContractPdf`）；生产用短时签名 URL | 与上相同：扫描中/隔离不可下；无合同时可用合同号兜底文件名（演示） |
| 新建销售单 | 当前合同有效、客户启用、`CREATE_SALES_ORDER` | 打开 W05 并固定当前版本 | 条件变化时留 W04 并显示 blocker |
| 导出 | `EXPORT`、当前筛选有数据 | 创建服务端筛选快照与后台任务 | 失败可重试，不在浏览器拼全量 CSV |

上传命令必须带 `idempotencyKey`。文件资产可先进入临时安全区，但只有合同事务提交后才能成为正式合同版本；事务失败时临时文件按保留策略清理。

## 8. 数据契约

```ts
type ContractStatus = "EFFECTIVE" | "TERMINATED" | "EXPIRED"

type UploadContractPdfCommand = {
  pdfFile: File
  contractNo: string
  customerId: string
  settlementPartyId: string
  paymentTermsSummary: string
  signedAt: string
  validFrom: string
  validTo: string
  idempotencyKey: string
}

type UploadContractPdfResult = {
  contractId: string
  contractNo: string
  revisionId: string
  revisionNo: number
  fileAssetId: string
  fileName: string
  uploadedAt: string
  operationId: string
}

type ContractCenterView = {
  contractId: string
  contractNo: string
  status: ContractStatus
  lockVersion: number
  currentRevision: ContractRevisionView
  pdfFiles: ContractPdfView[]
  relatedSalesOrders: RelatedSalesOrderSummary[]
  revisionTimeline: ContractRevisionSummary[]
  auditTimeline: AuditEventView[]
  allowedActions: Array<
    "UPLOAD_CONTRACT_PDF" | "TERMINATE" | "PRINT" | "CREATE_SALES_ORDER" | "EXPORT"
  >
  actionBlockers: ActionBlocker[]
  sourceAsOf: string
  queriedAt: string
}
```

服务端约束：

- `contract_no` 唯一，大小写规范由服务端统一；
- PDF 文件扩展名、MIME、大小、内容签名和安全扫描均需服务端校验；
- 每个合同版本至少且恰好关联一份合同正文 PDF；
- 销售单保存具体 `contract_revision_id` 和关键结构化快照；
- 新版本不得覆盖旧版本或改绑历史销售单；
- 金额、状态和可选资格不得由浏览器从 PDF 或列表行推导。

## 9. 页面状态与失败恢复

| 状态 | 页面表现 | 可执行动作 | 恢复方式 |
| --- | --- | --- | --- |
| 无合同 | “当前范围尚无合同” | 有权时上传合同 PDF；或在 W05 建单页点加号复用同一 Dialog | 上传成功 |
| 文件格式错误 | 文件字段就地显示“合同只支持 PDF” | 移除并重选 | 选择合法 PDF |
| 文件过大 | 显示 20 MB 上限 | 移除并重选 | 压缩或选择合法文件 |
| 安全扫描中 | PDF 显示 processing，不可下载或建单引用 | 刷新状态 | 扫描完成 |
| 文件被隔离 | 显示原因和不可用状态 | 重新上传 PDF | 新文件通过扫描 |
| 合同号重复 | 阻断归档并提示选择已有合同 | 打开已有合同或修改编号 | 服务端确认唯一 |
| 上传失败 | 保留元数据和文件选择，不创建合同身份 | 同幂等键重试 | 返回明确终态 |
| 结果未知 | 固定显示原操作号，不重复归档 | 查询原操作 | 得到成功/失败终态 |
| 权限收回 | 清除本地文件和下载 URL | 返回有权列表 | 权限恢复后重查 |

## 10. 响应式、键盘与无障碍

- 1440×900 首屏保留页头、四项指标、筛选和至少 6–8 行。
- 1024px 以下对象中心单列；375px 仅提供查询与只读摘要，上传和复杂建单引导到桌面端。
- `/` 聚焦搜索；方向键或 `j/k` 移动行；Enter 打开 detail；Esc 关闭并恢复原行焦点。
- 上传字段可通过键盘触发，错误与字段关联；状态不能只靠颜色表达。
- 文件选择后显示文件名、类型、大小和移除动作；上传中禁止重复提交。

## 11. 与其他工作面的关系

| 来源 / 去向 | Wxx | 携带上下文 | 返回规则 |
| --- | --- | --- | --- |
| 客户中心 | W03 | `customerId` | 上传成功后刷新合同摘要 |
| 销售单 | W05 | `customerId`、`contractId`、`contractRevisionId`；建单页可复用上传 Dialog 后选中新合同 | 建单后刷新合同关联销售摘要 |
| 客户往来 | W11 | 客户、销售单、合同版本 | 返回只读合同摘要 |
| 商城同步差异 | W17 | 外部合同映射身份 | 映射修复不覆盖合同 PDF 版本 |

跨工作面只传稳定身份和返回上下文。客户名、状态、权限与合同当前版本由目标工作面重新查询。
