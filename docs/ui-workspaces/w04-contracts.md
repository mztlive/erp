# W04 · 合同 PDF 档案

> 状态：已实现
> 页面模式：M2 高密度查询列表 + M4 只读对象中心
> 主要路由：`/sales/contracts`；对象路由 `/sales/contracts/:contractId`
> 主要角色：销售、销售领导；财务与历史单据参与者按权限只读
> 最后更新：2026-08-03

## 1. 定位与确定规则

W04 是已签署合同电子档的归档和查询工作面；禁止作为合同起草、编辑或审批工具。

确定规则：

1. ERP 禁止提供“新建合同”、合同正文编辑、空合同草稿或“提交生效”能力。
2. 合同进入 ERP 的唯一入口必须是上传电子档；仅接受单个 PDF，单文件不得超过 20 MB。
3. 上传成功必须同时形成 `contract` 稳定身份、首个不可变 `contract_revision` 和 PDF 文件资产关联；禁止先创建空对象再补文件。
4. 后续补充协议或换签版本也必须上传签署后的 PDF，并形成新的不可变版本；历史销售单必须继续引用原版本。
5. 新建销售单仅允许选择已有有效合同；无合同时可在合同选择框旁点加号，复用与 W04 相同的「上传合同 PDF」Dialog 原地归档并刷新可选列表，再选中新合同。
6. 一份合同允许关联多张销售单。禁止将合同汇总成另一套应收、回款、开票或履约账本。

## 2. 用户目标与边界

用户需要完成：

- 按合同号、客户、结算主体、状态、有效期和负责人快速定位合同；
- 上传已签署合同 PDF 并补充检索与销售引用所需的最小元数据；
- 查看合同 PDF、安全检查状态、版本时间线、审计与关联销售单；
- 从有效合同直接进入 W05，新销售单固定引用当前合同版本。

本工作面不在范围内：

- 合同拟稿、在线编辑、用印、签署、审批或正文内容生成；
- 根据 PDF 在浏览器内自行推导正式付款、开票、金额或状态；
- 修改已生效销售单、应收、回款或发票；
- 从关联销售单金额反推“合同金额”。业务模型不提供该正式事实；禁止反推。

## 3. 用户、权限与数据范围

| 角色 | 默认入口 | 可见范围 | 主要动作 |
| --- | --- | --- | --- |
| 负责销售 | 我的合同 | 当前负责客户合同与已参与历史单据所引用版本 | 上传合同 PDF、从合同建销售单 |
| 协作销售 | 协作客户合同 | 有效协作期内可见；历史按参与权 | 按 `allowedActions` 查看或上传 |
| 销售领导 | 团队合同 | 本团队客户合同 | 查看、按授权终止、建销售单 |
| 财务 | 销售单/往来深链 | 票款职责范围内合同结算与开票摘要 | 只读核对 |
| 历史单据参与者 | 历史销售单合同链接 | 该历史单据固定的合同版本 | 只读 |

权限规则：

- 列表、对象、PDF 元数据和下载必须分别鉴权；下载必须使用短时签名链接并记录审计。
- 动作必须由服务端 `allowedActions` 与 `actionBlockers` 决定；前端禁止根据角色名推导。
- 页面打开期间权限收回时，必须清除未提交的文件、下载 URL 和敏感缓存，仅保留安全的返回上下文。
- 客户停用时禁止上传新合同或创建销售单；历史合同与销售引用必须继续可读。

## 4. 入口、路由与页签

| 场景 | 入口 | URL / 页签行为 | 返回位置 |
| --- | --- | --- | --- |
| 查询合同 | 侧栏“合同” | `/sales/contracts`，筛选写入 URL | 保留原任务页签 |
| 从客户中心进入 | W03 合同摘要/上传动作 | `/sales/contracts?customerId=...`，预设客户范围并打开上传层 | 返回 W03 原客户子区 |
| 单击列表行 / Enter | 合同列表 | 开启 detail 半屏，URL 可保留 `preview={contractId}` | 关闭后焦点回原行 |
| 打开合同中心 | detail 底栏、全局搜索 | `/sales/contracts/:contractId`，聚焦稳定对象页签 | 关闭后回来源页签 |
| 上传合同 PDF | 列表或 W03 | 在 Dialog 内选择 PDF 并补充元数据；成功后可打开对象中心 | 失败保留文件与输入 |
| 从合同建销售单 | 合同中心主动作 | W05 携带 `customerId`、`contractId`（当前修订由建单页自动选择，不携带内部修订 ID 进 URL） | 保存/提交后可回合同中心 |

列表页签身份为 `contracts:list:{userId}`；对象页签身份为 `contract:{contractId}`。上传层不是独立路由，刷新不恢复本地文件选择。

## 5. 页面布局与交互设计

### 5.1 M2 列表（1440×900）

```text
┌ PageHeader：合同                              [导出] [上传合同 PDF] ┐
├ MetricStrip：全部 | 有效 | 30天内到期 | 已到期 | 已终止           ┤
├ ListToolbar：搜索 | 当前客户锁定 chip（customerId 来源，可清除） | 共 N 条 | 清除筛选 ┤
├──────────────────────────────────────────────────────────────┤
│ 合同编号↑(链接进详情) | 结算主体 | 有效期 | 状态 | 版本 | 销售单 | 负责人 | 操作 │
│ 36px 紧凑数据行，1440×900 首屏至少 6–8 条                        │
└──────────────────────────────────────────────────────────────┘
```

- 页头唯一主动作必须是“上传合同 PDF”；禁止出现“新建合同”。
- 状态轴仅允许 MetricStrip 一套（全部/有效/30 天内到期/已到期/已终止）；禁止叠加状态 ToggleGroup 与有效期下拉。
- 指标全部是筛选按钮，必须使用 `aria-pressed`、选中态和当前筛选摘要。
- 排序必须对整表生效（翻页不得丢序）：默认“将到期优先”，点击表头按列全量排序；「操作」列不得参与排序。
- 单击行空白或 Enter 必须打开 detail 半屏；合同号必须是进详情页的链接；预览仅由行点击/「预览」按钮负责。
- 筛选/分页/排序写 URL（URL-first，后退/刷新恢复）；搜索 300ms 防抖 + Enter + `/` 聚焦；排序与分页均入 URL。
- 「清除筛选」清搜索、指标与客户锁定，保留排序；客户锁定 chip 用共享 `FilterChip` 可单独移除。
- 空态统一 `BusinessEmptyState`：无数据/筛选无结果（带清除按钮）/无权限范围三种区分。

### 5.2 上传 Dialog

字段顺序固定为：

1. 合同 PDF；
2. 合同编号；
3. 客户（`CustomerCombobox`）与结算主体（`SettlementPartyCombobox`）；
4. 付款条件（`OptionCombobox` / 码表，不自由长文本录入）；
5. 签订日期、有效期起、有效期止；
6. “上传并归档”。

PDF 为必填。文件类型、扩展名、空文件和大小必须在选择后就地校验，并由服务端复验；安全检查状态只作治理记录，不得阻断归档、下载或建单引用。元数据仅用于检索、选择与销售快照；完整合同正文必须以 PDF 为准。客户与结算主体禁止自由文本录入。

### 5.3 detail 半屏

detail 必须显示合同号、客户、状态、版本、签订日、有效期、结算/付款摘要、PDF 数量与关联销售摘要。底栏仅提供“关闭”“纸质预览”“打开合同中心”；禁止提供编辑或生效动作。

### 5.4 M4 只读对象中心

```text
┌ PageHeader：销售 › 合同 › HT-2026-0088        [返回] [纸质预览] ┐
├ DocumentHeader：HT-2026-0088 [生效] · 客户 东方企业 · 负责人 · v3 │
├ 30 日内将到期（如适用）· PDF 电子档已归档（全部附件安全通过时）  │
├ 锚点：概览 | 结算与开票 | 合同 PDF | 关联销售单 | 版本与审计    │
├──────────────────────────────────────────────────────────────┤
│ 只读元数据、付款/开票摘要、PDF 安全状态、销售引用和审计          │
└──────────────────────────────────────────────────────────────┘
```

对象中心禁止出现“创建修订”“编辑草稿”“提交生效”或通用附件上传。归档新签署版本时，必须从合同列表统一上传入口按合同号进入版本归档能力；该能力必须继续要求 PDF。

## 6. 展示字段

| 区域 | 字段 | 口径 | 权限 |
| --- | --- | --- | --- |
| 列表 | 合同号、客户、结算主体、状态、版本、签订日、有效期 | 服务端正式查询 | 按客户范围 |
| PDF | 文件名、类型、大小、版本、上传者/时间、安全状态 | 只有 `application/pdf` 可成为合同正文 | 列表与下载分别鉴权 |
| 结算摘要 | 结算主体、付款条件、开票要求 | 上传时登记的结构化摘要；正文以 PDF 为准 | 销售/财务字段权限 |
| 关联销售 | 单号、业务性质、合同版本、状态、三轨进度、含税金额 | 金额只作单据摘要 | 按每张销售单裁剪 |
| 版本 | 版本号、有效区间、上传时间、文件身份 | 历史版本不可覆盖 | 需版本查看权 |
| 审计 | 上传、下载、终止等动作 | 敏感值只记摘要 | 按审计权限 |

合同状态仅允许 `EFFECTIVE`、`TERMINATED`、`EXPIRED`。W04 禁止产生 `DRAFT` 合同。

## 7. 操作契约

| 操作 | 前置条件 | 成功结果 | 失败恢复 |
| --- | --- | --- | --- |
| 上传合同 PDF | `UPLOAD_CONTRACT_PDF`；客户启用；单个合法 PDF；合同号、签订日和有效期完整 | 原子形成合同身份、v1、文件关联和审计；返回合同 ID、版本 ID、文件名、时间和操作号 | 不创建空合同；保留选择和输入；重复请求使用同一幂等键 |
| 归档后续 PDF 版本 | 已存在合同；新签署 PDF；版本前置校验通过 | 追加不可变版本并切换当前版本；历史销售引用不变 | 冲突后重查当前版本，不覆盖历史 |
| 终止合同 | `allowedActions` 含 `TERMINATE`；用户完成影响确认；无未解除的 `actionBlockers`。未下发 `TERMINATE` 时禁止展示终止入口 | 合同状态必须转为 `TERMINATED`；新销售单禁止选择该合同；历史销售引用必须保持不变 | 被阻断时必须列出需先处理对象且不得改状态 |
| 纸质预览/下载 | 合同可见且 PDF 文件资产存在 | 必须通过短时签名链接查看或下载并写审计 | 安全检查状态只展示，不阻断下载 |
| 他页引用下载 | W05 销售单列表点合同号等 | 必须解析合同中心可下载正文 PDF 并触发下载（`downloadOriginalContractPdf`）；必须使用短时签名 URL | 安全检查状态不阻断下载；无合同时文件名必须以合同号兜底 |
| 新建销售单 | 当前合同有效、客户启用、`CREATE_SALES_ORDER` | 打开 W05 并固定当前版本 | 条件变化时留 W04 并显示 blocker |
| 导出 | `EXPORT`、当前筛选有数据 | 客户端按当前筛选生成 CSV；界面必须以业务文案呈现（文件/行数）；禁止展示任务号或权限版本 | 失败可重试；禁止在界面暴露内部任务标识 |

上传命令必须带 `idempotencyKey`。文件资产可先进入临时安全区，但仅当合同事务提交成功后才能成为正式合同版本；否则事务失败时临时文件必须按保留策略清理。

## 8. 数据契约

```ts
type ContractStatus = "EFFECTIVE" | "TERMINATED" | "EXPIRED"

type UploadContractPdfCommand = {
  pdfFile: File
  contractNo: string
  customerId: string
  settlementPartyId: string
  paymentTermsSummary: string
  signedAt: string
  validFrom: string
  validTo: string
  idempotencyKey: string
}

type UploadContractPdfResult = {
  contractId: string
  contractNo: string
  revisionId: string
  revisionNo: number
  fileAssetId: string
  fileName: string
  uploadedAt: string
  operationId: string
}

type ContractCenterView = {
  contractId: string
  contractNo: string
  status: ContractStatus
  lockVersion: number
  currentRevision: ContractRevisionView
  pdfFiles: ContractPdfView[]
  relatedSalesOrders: RelatedSalesOrderSummary[]
  revisionTimeline: ContractRevisionSummary[]
  auditTimeline: AuditEventView[]
  allowedActions: Array<
    "UPLOAD_CONTRACT_PDF" | "TERMINATE" | "PRINT" | "CREATE_SALES_ORDER" | "EXPORT"
  >
  actionBlockers: ActionBlocker[]
  sourceAsOf: string
  queriedAt: string
}
```

服务端约束：

- `contract_no` 必须唯一，大小写规范必须由服务端统一；
- PDF 文件扩展名、MIME、大小和内容签名必须由服务端校验；安全检查状态只作治理记录；
- 每个合同版本必须至少且恰好关联一份合同正文 PDF；
- 销售单必须保存具体 `contract_revision_id` 和关键结构化快照；
- 新版本不得覆盖旧版本或改绑历史销售单；
- 金额、状态和可选资格不得由浏览器从 PDF 或列表行推导。

## 9. 页面状态与失败恢复

| 状态 | 页面表现 | 可执行动作 | 恢复方式 |
| --- | --- | --- | --- |
| 无合同 | “当前范围尚无合同” | 有权时上传合同 PDF；或在 W05 建单页点加号复用同一 Dialog | 上传成功 |
| 文件格式错误 | 文件字段就地显示“合同只支持 PDF” | 移除并重选 | 选择合法 PDF |
| 文件过大 | 显示 20 MB 上限 | 移除并重选 | 压缩或选择合法文件 |
| 安全扫描中 | PDF 显示 processing，不限制下载或建单引用 | 可继续业务操作或刷新状态 | 扫描状态更新 |
| 文件被隔离 | 显示隔离状态，不限制下载或建单引用 | 可继续业务操作或重新上传 PDF | 新文件上传成功 |
| 合同号重复 | 必须阻断归档并提示选择已有合同 | 打开已有合同或修改编号 | 服务端确认唯一 |
| 上传失败 | 保留元数据和文件选择；禁止创建合同身份 | 同幂等键重试 | 返回明确终态 |
| 结果未知 | 固定显示原操作号；禁止重复归档 | 查询原操作 | 得到成功/失败终态 |
| 权限收回 | 必须清除本地文件和下载 URL | 返回有权列表 | 权限恢复后重查 |

## 10. 响应式、键盘与无障碍

- 1440×900 首屏必须保留页头、四项指标、筛选和至少 6–8 行。
- 1024px 以下对象中心必须单列；375px 仅提供查询与只读摘要；上传和复杂建单必须引导到桌面端。
- `/` 必须聚焦搜索；方向键或 `j/k` 移动行；Enter 打开 detail；Esc 关闭并恢复原行焦点。
- 上传字段必须可通过键盘触发，错误必须与字段关联；状态禁止只靠颜色表达。
- 文件选择后必须显示文件名、类型、大小和移除动作；上传中禁止重复提交。

## 11. 与其他工作面的关系

| 来源 / 去向 | Wxx | 携带上下文 | 返回规则 |
| --- | --- | --- | --- |
| 客户中心 | W03 | `customerId` | 上传成功后刷新合同摘要 |
