# W21 · 供应商商品库与供给管理

> 状态：已确认业务方向，接口与持久化待实现
> 页面模式：M2 供应商商品库 + M3 变化/异常队列 + M4 供应商商品中心
> 主要路由：`/procurement/supplier-catalog`、`/procurement/supplier-catalog/:supplierProductId`
> 主要角色：采购；运营只看发布准备信息，销售只消费公司商品池
> 最后更新：2026-08-02

## 1. 结论

W21 不再是“API 供应商的供应商商品异常页”，而是所有供应商商品进入 ERP 的统一入口。

- Excel、API、手工录入只是三种来源渠道，进入后都形成相同的供应商 SPU/SKU。
- 采购先拥有完整的供应商商品库，再从中选择商品关联或新建公司 SKU，并加入公司商品池。
- 一个公司 SKU 可以关联多个供应商 SKU；每个关联分别维护成本、税率、费用、MOQ、区域、供给方式和有效期。
- 公司商品池价格由采购发布给销售；它不是供应商成本，也不能从最低成本自动推导。
- 销售查询、导出和下单只使用公司商品池，不读取供应商商品库和采购成本。

原先“商品主档与供给关系分离”的方向保留；错误在于把供给关系的创建入口绑定到了 API，同样也没有给手工商品提供逐供应商成本维护入口。

## 2. 对象所有权

| 对象 | 主责 | 说明 |
| --- | --- | --- |
| 公司商品 SPU/SKU | W14 基础资料 | 公司统一商品身份、规格、图文和生命周期 |
| 供应商商品 SPU/SKU | W21 供应商商品库 | 保存供应商自己的编码、名称、规格及来源修订 |
| 供应商 SKU 映射 | W21 | 一条供应商 SKU 映射到一条公司 SKU；多条映射可指向同一公司 SKU |
| 供应商供给及修订 | W21 | `公司 SKU × 供应商 SKU × 供给修订`，采购成本的唯一事实来源 |
| 公司商品池条目及修订 | W14/W21 共用命令边界 | 面向销售的可选状态、销售可见价和有效期；不能含供应商成本 |
| 商品发布 | W22 | 商城渠道售价、图文和上下架版本，不反写商品池或供给成本 |
| 销售单商品快照 | W05 | 固定公司商品池修订、成交价及必要展示快照 |

## 3. 三种录入流程

### 3.1 Excel

1. 采购选择供应商并上传供应商商品表。
2. 系统校验列映射、供应商 SPU/SKU 唯一性、金额与规格，生成批次预览。
3. 采购确认后，合法行逐条形成供应商商品及不可变来源修订；错误行保留在批次错误清单。
4. 导入成功不等于加入公司商品池，也不自动创建公司 SKU。
5. 采购从供应商商品库选择部分商品，映射已有公司 SKU 或先进入 W14 新建公司商品，再确认供给和商品池价格。

### 3.2 API

1. W20 管理连接、凭证引用和同步任务。
2. 同步任务把远端商品规范化为与 Excel 相同的供应商商品及来源修订。
3. 新增、关键变化、停供和错误进入 W21 变化队列；正常目录仍可在商品库浏览。
4. 入池、映射、供给成本和商品池价格的后续流程与 Excel 完全相同。

API 连接是可选来源信息。Excel 和手工商品不得伪造 `connection_id`。

### 3.3 手工录入

有两个入口：

- W21“手工录入供应商商品”：先进入供应商商品库，再选择是否入池。
- W14 商品 SKU 行“添加供应商并登记成本”：固定当前公司 SKU，选择一个供应商并一次性填写该供应商 SKU、采购成本和供给条件。

同一 SKU 需要多个供应商时，重复添加供给行。界面可以表现为多选/多行编辑，但提交必须拆成逐供应商供给记录；禁止只保存 `supplier_ids[]` 而没有对应成本和有效期。

## 4. 加入公司商品池

采购在供应商商品库选择“加入公司商品池”后必须完成：

1. 关联已有公司 SKU；若不存在，打开 W14 创建公司商品和 SKU，保存后返回当前供应商商品。
2. 确认当前供应商的含税成本、进项税率、费用、MOQ、区域、供给方式和有效期。
3. 设置销售可见价及商品池生效期。
4. 服务端原子写入供应商 SKU 映射、供给修订和商品池修订，返回各稳定 ID/修订 ID。

如果同一公司 SKU 已在商品池中，再增加第二家供应商时只新增映射和供给修订；只有销售可见价或商品池状态发生变化时才形成新的商品池修订。

来源报价与采购确认成本必须分开：

- `source_quoted_price_gross` 是供应商原始报价快照。
- `confirmed_cost_gross` 是采购确认后生效的供给成本。
- `sales_visible_price` 是公司给销售选品/报价使用的商品池价格。

三者不能互相覆盖，也不能自动保持相等。

## 5. 页面

### 5.1 供应商商品库

默认路由：`/procurement/supplier-catalog?mode=list`

页面提供：

- 来源筛选：全部、Excel、API、手工录入。
- 供应商、供应商 SPU/SKU、名称/规格、映射状态、供给状态、是否已入池。
- “导入 Excel”“手工录入”“加入公司商品池”“打开商品中心”。
- 从 W14 携带 `skuId` 进入时，只显示映射到该 SKU 的供给；即使尚无供给，也必须保留 W14 的 SKU 上下文和新增入口。

### 5.2 变化与异常队列

路由：`/procurement/supplier-catalog?mode=queue`

- API 同步和后续 Excel 重导产生的新增、变化、停供、错误可进入队列。
- 停供、不可供、库存为零或新鲜度超时仍按既有安全规则暂停相关发布。
- 正常目录浏览不依赖任务；只有需要人工领取/终结的异常才使用 W02 的租约和幂等信封。
- 来源是 Excel/手工时不显示“API 连接”链接。

### 5.3 供应商商品中心

路由：`/procurement/supplier-catalog/:supplierProductId`

展示供应商商品身份、来源修订、公司 SKU 映射历史、供给修订、商品池状态、发布影响和审计。成本区仅采购及明确授权的财务角色可见；销售、运营、管理员和技术角色返回掩码。

### 5.4 W14 商品编辑页

每个公司 SKU 行展示：

- 销售可见价（公司商品池价格投影）；
- 已关联供应商数量及供应商摘要；
- “添加供应商并登记成本”；
- “查看全部供给”；
- 独立库存台账入口。

新商品先保存以取得稳定 `sku_id`，随后在同页增加一家或多家供应商。SKU 保存时服务端必须分配稳定 ID，供给关系只能引用该 ID。

## 6. 写命令与事务边界

### 6.1 导入/手工录入供应商商品

```text
CreateSupplierCatalogItem {
  source_type: EXCEL | API | MANUAL
  supplier_id
  source_reference?
  supplier_spu_code?
  supplier_sku_code
  name / specification / category
  source_quoted_price_gross / input_tax_rate
  idempotency_key
}
```

只创建供应商商品时不要求公司 SKU。W14 固定 SKU 入口可以在同一业务事务中继续创建映射、供给修订和商品池修订。

### 6.2 选择入池

```text
PromoteSupplierProductToPool {
  supplier_product_id
  target_company_sku_id
  confirmed_cost_gross
  input_tax_rate / fees / minimum_order_quantity
  supply_mode / supply_region / valid_from / valid_to?
  sales_visible_price
  expected_source_revision
  expected_pool_revision?
  idempotency_key
}
```

成功结果至少返回 `supplier_product_id`、`supplier_offering_revision_id`、`product_pool_entry_revision_id`、审计引用和记录时间。并发冲突、来源修订已变化或价格无效时整体失败，不允许只完成一半。

## 7. 权限与保密

| 角色 | 供应商目录 | 采购成本 | 销售可见价 | 写权限 |
| --- | --- | --- | --- | --- |
| 采购 | 可见授权范围 | 可见 | 可见 | 录入、映射、确认供给、发布商品池价格 |
| 销售 | 不直接消费 | 不返回字段 | 可见 | 选品、导出、下销售单 |
| 运营 | 可见必要摘要 | 掩码 | 可见 | 查看发布准备；不确认采购成本 |
| 财务 | 按职责只读 | 经字段授权可见 | 可见 | 核对，不改供给 |
| 管理员/技术 | 技术元数据 | 掩码 | 非必要不返回 | 修复连接/同步，不做采购决策 |

成本字段不能通过列表摘要、搜索索引、CSV 导出、错误文案、审计详情或前端隐藏字段泄露。权限判断必须在服务端投影层完成。

## 8. 销售消费边界

- 销售选品查询只返回已生效、可销售的公司商品池修订。
- 销售导出包含公司商品/SKU、规格、销售可见价、可售区域和必要图文，不包含供应商、成本、进项税、MOQ 或连接信息。
- 销售单行固定 `product_pool_entry_revision_id` 和成交价；后续成本或商品池价格变化不改历史订单。
- 采购执行时再按已确认策略选择供给修订；不能让销售端直接选择供应商成本。

## 9. 验收标准

1. Excel、API、手工三种来源都能形成统一供应商 SPU/SKU，且非 API 来源没有虚假连接。
2. Excel/API 入库后商品默认只在供应商商品库，未选择入池前销售不可见。
3. 采购能把供应商 SKU 关联到已有公司 SKU，也能进入 W14 新建公司商品后返回继续。
4. 一个公司 SKU 能维护至少两家供应商，分别拥有不同成本、MOQ、区域和有效期。
5. W14 SKU 行显示供应商数量，并能直接新增一条带成本的手工供给。
6. 加入公司商品池同时形成映射、供给修订和商品池修订；失败时没有半完成状态。
7. 采购成本与销售可见价明确分栏，销售和运营请求中成本值为掩码或根本不返回。
8. 销售查询和导出只依赖公司商品池；未入池供应商商品不可被下单。
9. API 停供/不可供仍触发安全暂停，且不改写历史订单快照。
10. 所有写命令有幂等键、期望修订、审计记录和明确的冲突/未知结果处理。
