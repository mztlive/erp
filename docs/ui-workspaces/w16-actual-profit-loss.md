# W16 · 实际经营盈亏

> 状态：草稿
> 页面模式：M6 只读分析
> 主要路由：`/analytics/profit-loss`
> 主要角色：财务、管理层；销售和销售经理按数据范围只读
> 最后更新：2026-08-01

## 1. 定位与目标

### 1.1 用户目标

用户按统计期间、客户、销售单和业务构成查看非卡券业务已经形成的实际经营盈亏，识别亏损、低利润、成本未完整和成本异常对象，并下钻到正式销售、履约和成本依据。

页面必须让用户明确区分：

- 实际经营盈亏与预计/确认阶段的预计盈亏；
- 含税销售和票款金额与不含税利润口径；
- 成本完整的可比较结果与尚未形成完整实际成本的对象；
- 非卡券实际盈亏与另由 W28 负责的卡券消费经营结果。

### 1.2 业务目标

- 以不可变销售版本、实际履约和 `ACTUAL` / `REDUCTION` 成本事实形成只读投影。
- 使用统一公式：不含税销售收入 − 不含税实际采购成本 − 不含税实际履约费用。
- 同屏展示成本覆盖收入、成本未覆盖收入和覆盖率，避免缺失成本被视为零成本。
- 允许按客户、销售单、福利场景、履约方式和成本类型下钻，但不在分析页修改任何事实。
- 投影可在 1 分钟内异步刷新并每天从正式事实核对重建。

### 1.3 不在本工作面完成

- 不录入、修改或删除成本费用；应从销售单、采购/履约事实或财务凭证入口形成 `cost_entry`。
- 不登记回款、付款和发票；票款进入 W11/W12。
- 不改变销售收入、税率、成本阶段或成本归属。
- 不将 `EXPECTED`、`CONFIRMED` 成本计入“实际经营盈亏”；这些值仅可作为执行期对照。
- 不计算卡券销售单实际盈亏；卡券收入和直接履约费用不进入本页利润，二期消费结果进入 W28。
- 不提供法定利润表、会计凭证或总账能力。

## 2. 用户、权限与数据范围

| 角色 | 默认入口 | 可见范围 | 主要动作 |
| --- | --- | --- | --- |
| 财务 | W16 | 授权公司/组织的收入、成本和利润明细 | 核对实际成本、识别缺口、下钻正式依据、导出 |
| 管理层 | 经营默认着陆 | 授权公司汇总与明细 | 查看利润趋势、构成、亏损与成本覆盖 |
| 销售 | 从 W03 / W05 / W15 进入 | 自己负责客户及保留历史参与权的销售单 | 查看本范围结果和成本缺口；不可改成本 |
| 销售经理 | 从 W15 进入 | 团队客户与销售单 | 比较团队经营结果 |
| 系统管理员 | 无业务默认入口 | 投影更新数据和后台任务元数据 | 技术重建排障；不得改经营结果 |

权限规则：

- 无 W16 模块权限时入口隐藏，直接访问显示无权限页。
- 汇总、趋势、构成和明细必须使用同一数据范围和字段权限，不得先返回公司汇总再对明细裁剪。
- 销售无成本明细权限但有利润结果权限时，可显示授权的合计/利润率，供应商、成本凭证和单项成本值按字段策略隐藏。
- 无利润字段权限时保留页面结构，指标和图表显示无权限，不通过排序位置、tooltip 或导出泄露。
- 权限收回后立即清理已加载成本明细和导出链接。

### 4.3 明细层级

- 默认“销售单”维度，一行对应一个授权非卡券销售单的期间归属结果。
- 客户、场景、履约方式和成本类型是服务端分组投影，不从销售单当前页二次聚合。已实现：客户/场景/履约按行聚合金额与覆盖状态；成本类型按成本记录聚合；聚合行不提供单对象下钻。
- 销售单行可展开销售明细贡献，但不允许嵌套完整销售单中心。
- 成本 detail 展示不可变事实和分配关系；需要更正时只能转到原业务对象并使用正式变更/冲减流程。

## 5. 展示内容与字段

### 5.1 核心公式与覆盖

```text
实际经营盈亏（不含税）
= 非卡券不含税销售收入
− 非卡券不含税实际采购成本
− 非卡券不含税实际履约费用
```

只汇总 `cost_scope = NON_VOUCHER_FULFILLMENT` 且 `cost_stage IN (ACTUAL, REDUCTION)` 的净额。`REDUCTION` 以反向效果进入；预计和已确认成本不进入实际值。

| 字段 | 用户文案 | 数据来源 | 口径 / 格式 | 权限规则 |
| --- | --- | --- | --- | --- |
| `netSalesRevenue` | 不含税销售收入 | 生效销售版本及期间归属投影 | 仅非卡券；明细舍入后汇总 | 销售金额权限 |
| `actualProcurementCostNet` | 实际采购成本 | 履约形成的 `ACTUAL` + 采购退货/退款 `REDUCTION` | 不含税净额 | 成本权限 |
| `actualFulfillmentCostNet` | 实际履约费用 | 经复核的印刷、仓储、配送、平台、服务等成本 | 不含税净额 | 成本权限 |
| `actualProfitLossNet` | 实际经营盈亏 | 服务端公式投影 | 不含税；允许负数 | 利润权限 |
| `marginRate` | 实际利润率 | 服务端投影 | 盈亏 / 适用不含税收入；分母为 0 时不可用 | 利润权限 |
| `coveredNetRevenue` | 成本覆盖收入 | 成本完整性投影 | 有足够实际成本依据的收入 | 利润权限 |
| `uncoveredNetRevenue` | 成本未覆盖收入 | 成本完整性投影 | 不能按零成本进入利润比较 | 利润权限 |
| `costCoverageRate` | 成本覆盖率 | 服务端投影 | 覆盖收入 / 适用收入 | 利润权限 |
| `projectionUpdatedAt` | 数据更新时间 | 投影更新时间 | 绝对时间 + 状态 | 全部有权用户 |

### 5.2 成本构成

实际履约费用至少按固定类型展示：商品、物流、印刷、仓储、配送、平台/技术服务、线下服务、返点、其他。返点和成本冲减必须显示为反向贡献，不把负数隐藏在“其他”。

可选执行期对照区展示 `EXPECTED` 和 `CONFIRMED` 成本时，必须：

- 标题明确为“预计/已确认成本参考”；
- 与实际成本使用不同线型/文字，不参与实际盈亏或实际利润率；
- 不用页面切换值改变正式成本阶段；
- 点击后仍只读查看来源版本。

### 5.3 销售单明细表

| 字段 | 用户文案 / 格式 | 数据来源 | 说明 |
| --- | --- | --- | --- |
| `salesOrderNo` | 销售单号 | 稳定销售单 | 固定身份列；点击 W05 |
| `customerName` | 客户 | 销售版本快照 | 历史快照，不取当前名称替换 |
| `benefitScenarios` | 福利场景 | 销售明细版本 | 多值紧凑展示 |
| `fulfillmentModes` | 履约方式 | 销售/履约事实 | 公司仓发、供应商直发、电子、服务 |
| `netSalesRevenue` | 不含税收入 | 服务端投影 | 等宽右齐 |
| `actualProcurementCostNet` | 实际采购成本 | 成本分配 | 可下钻成本事实 |
| `actualFulfillmentCostNet` | 实际履约费用 | 成本分配 | 可下钻类型构成 |
| `reductionsNet` | 成本冲减 | 反向成本事实 | 显式显示，不覆盖原成本 |
| `actualProfitLossNet` | 实际盈亏 | 服务端投影 | 负值文字 + tone，不只靠红色 |
| `marginRate` | 实际利润率 | 服务端投影 | 不可用显示原因，不显示 0% |
| `coverageState` | 完整 / 部分 / 未覆盖 | 成本完整性投影 | 带缺口原因和待补事实类型 |
| `latestCostOccurredAt` | 最近实际成本发生 | 成本事实 | 判断数据时效，不等于投影更新时间 |

### 5.4 成本事实 detail

detail 展示：费用类型、阶段、范围、供应商、含税金额、税率、税额、不含税金额、发生时间、来源事实/单据/明细/版本、销售单和销售明细分配、调整的原成本、凭证授权摘要。

页面不得展示“删除成本”或“直接改金额”。后续更权威成本只追加差额，成本冲减引用原 `cost_entry`。

## 6. 搜索、筛选、排序与默认视图

| 能力 | 默认值 | URL 状态 | 行为 |
| --- | --- | --- | --- |
| 统计期间 | 本自然月截至当前日 | `periodPreset` 或 `from/to` | 期间边界与归属基准同时展示 |
| 期间归属 | 服务端已配置基准；未配置时为空 | `periodBasis` | 先读取允许值和配置版本；无配置时必须由用户显式选择并写入 URL，前端不得根据日期或“当前建议”静默默认 |
| 数据范围 | 当前角色默认范围 | `scope` | 服务端过滤 |
| 成本覆盖 | 成本完整 | `coverage=covered` | 默认利润比较只含可靠结果；可切全部/未覆盖 |
| 客户 | 全部有权客户 | `customerId` | 从 W15/W03 进入时预置 |
| 销售单 | 全部 | `salesOrderId` | 从 W05 进入时聚焦单对象 |
| 福利场景 | 全部 | `benefitScenario` | 服务端按销售明细分组 |
| 履约方式 | 全部 | `fulfillmentMode` | 支持多选 |
| 成本类型 | 全部实际类型 | `costType` | 只影响成本构成和下钻；总利润过滤行为明确显示 |
| 下钻维度 | 销售单 | `dimension` | 销售单 / 客户 / 场景 / 履约 / 成本类型 |
| 排序 | 实际盈亏升序 | `sort` | 默认先显示亏损对象；表头排序入口与 `sort` 参数双向接线，作用于全量（维度聚合后）行，不只当前页；可按收入、利润率、覆盖状态排序 |
| 搜索 | 空 | `q` | 销售单号、客户编号/名称 |

筛选改变时指标、图表和明细一起更新，页面显示当前范围摘要。切换到“全部覆盖状态”时，利润汇总必须把不可靠部分标为 partial，并同时显示未覆盖收入；不能把未覆盖对象悄悄当零成本并入排名。趋势图与成本构成图为固定口径序列（不随期间/覆盖筛选联动），页面在卡片描述与明细表说明中明确标注，避免图文互证误导。

`periodPreset` 仅是 URL 快捷值；路由层将其归一化为明确的 `from/to` 并写回 URL。查询与跨 W 下钻只使用已解析的 `from/to`，不再传递另一套 `period` 参数。

页面先读取服务端 `periodBasis` 配置。若已配置，界面在发起盈亏查询前将该明确值写入 URL 并持续展示；若未配置，则展示阻断式口径选择，用户选定允许值后才构造查询。Q1 的“当前建议”不是正式配置，不能作为前端 fallback，也不能仅凭入口来源推断口径。

## 7. 操作契约

W16 没有修改经营事实或公式的业务提交动作。

| 操作 | 入口 | 权限 / 前置条件 | 确认 | 成功结果 | 失败恢复 |
| --- | --- | --- | --- | --- | --- |
| 选择或切换期间/口径 | 页头 / 阻断式口径选择 | 对应范围可见；值来自服务端允许集合 | 无 | 将明确 `periodBasis` 写入 URL，指标、图表、明细和导出使用同一口径重查 | 失败恢复原明确口径；未选择时继续阻断，不猜默认值 |
| 切换覆盖范围 | CoverageNotice | 有利润权限 | 无 | 明确更新可靠性和样本范围 | 失败保留上一状态 |
| 切换下钻维度 | 维度导航 | 对应字段可见 | 无 | 服务端返回新分组和结果数 | 失败保持原维度 |
| 查看销售单 | 表格行 | 有 W05 对象权限 | 无 | 新任务页签打开 W05 经营/概览子区 | 返回聚焦原行 |
| 查看成本事实 | 金额单元格 / 构成图 | 有成本明细权限 | 无 | 打开只读 detail，展示来源和分配 | 无权限时只保留授权合计 |
| 前往纠错来源 | 成本 detail | 原业务对象允许相应变更/冲减 | W16 不执行确认 | 打开 W05/W08/W09 或财务成本入口 | W16 保留上下文，等待投影刷新 |
| 导出 | 页头 | `EXPORT`；范围和字段已授权 | 展示期间、期间基准、覆盖口径、更新时间和行数 | 后台生成 7 天有效分析文件 | 任务失败可重试，不降低敏感字段限制 |
| 刷新 | 页头 | W16 可访问 | 无 | 重新获取投影更新时间 | 保留旧数据并标刷新失败 |

任何来源纠错完成后，W16 不本地改金额；固定提示“正式事实已更新，经营投影将在数据追平后刷新”。

```ts
  rows: {
    dimension: string
    items: ProfitLossRow[]
    total: number
    nextCursor?: string
  }
}

type ProfitLossRow = {
  rowId: string
  objectType: string
  objectId?: string
  identityLabel: string
  customerId?: string
  customerLabel?: string
  netSalesRevenue: string
  actualProcurementCostNet: string
  actualFulfillmentCostNet: string
  reductionsNet: string
  actualProfitLossNet?: string
  marginRate?: string
  coverageState: "COVERED" | "PARTIAL" | "UNCOVERED"
  coverageBlockers: Array<{ code: string; message: string }>
  latestCostOccurredAt?: string
  allowedDrilldowns: string[]
}
```

- 页面先独立查询 `ProfitLossPeriodBasisConfig`；正式盈亏 Query 仅在 URL 中已有经允许集合校验的明确 `periodBasis` 后启用。
- 查询由 TanStack Query 管理，Query Key 包含期间、明确归属基准、口径配置版本、公式版本、权限/范围版本、覆盖口径和全部筛选。
- 指标、趋势、成本构成和各维度汇总由服务端计算；当前分页只负责展示。
- 投影允许异步延迟不超过 1 分钟并保存来源消息消费位置；页面和导出必须带更新时间。
- 每天从销售版本、履约、成本、退货/退款与纠错事实全量核对重建；重建失败不修改事实。

### 8.2 提交

W16 无业务 mutation。筛选、维度切换和打开 detail 均为查询状态。

导出提交后台任务，至少冻结：查询参数、数据范围/权限版本、公式版本、期间基准、投影更新时间、字段授权和导出用途。任务结果不得成为新的经营事实。

### 8.3 前端边界

- 前端只格式化人民币、不含税标签、负数、百分比、时间、图表坐标和状态 tone。
- 前端不得重算实际盈亏、利润率、成本覆盖、成本类型归类或销售/成本期间归属，也不得把待确认建议、本地偏好或入口上下文当成默认 `periodBasis`。
- 金额全部采用服务端定点数结果；不得使用 JavaScript 浮点重新求和后覆盖服务端总计。
- `EXPECTED`、`CONFIRMED`、`ACTUAL`、`REDUCTION` 阶段由事实来源决定，页面不能让用户自由选择或转换。
- 不可靠结果返回 `undefined + reliability/explanation`，前端显示原因，不替换为 0。
- 卡券直接履约费用和 `MALL_CONSUMPTION` / `WECHAT_COST` 不进入本页实际盈亏。
