# W24 · 审批流程配置

> 状态：已确认
>
> 页面模式：M2 高密度目录 + M4 定义对象中心
>
> 主要路由：`/system/approval-processes`
>
> 主要角色：流程管理员；运行管理员只读
>
> 最后更新：2026-08-17

## 1. 页面责任

W24 必须完成固定 `DocumentType` 的审批政策目录、草稿编辑、发布、退役、历史版本查询和未提交单据绑定升级。页面只配置节点顺序、节点名称和具体审批人；不得配置业务动作、状态机、条件表达式、角色池、候选人集合、任意连线、回调或运行时开关。

W24 不得承担下列职责：

- 不处理审批决定、撤回、恢复、改派或受阻取消；运行任务统一进入 W01；
- 不修改业务单据、业务对象快照或运行实例；
- 不允许管理员把 `NO_APPROVAL` 类型改成需要审批；
- 不允许管理员为 `PROCESS_REQUIRED` 类型绕过已发布定义；
- 不执行具体单据的 DataScope 或对象读取权校验；这些校验在绑定、启动、进入节点和决定时由服务端执行。

## 2. 权限与数据边界

各页面动作必须按下表通过其列明的动作级权限与类型级门禁；表中明确“不要求管理员类型权限”的固定目录读取只校验动作级权限：

| 页面动作 | 动作级权限 | 类型级权限 | 约束 |
| --- | --- | --- | --- |
| 查看固定目录 | `approval_process:read` | 不要求管理员类型权限 | 固定返回 20 行非敏感目录，不含节点或审批人详情 |
| 查看定义版本和详情 | `approval_process:read` | `<prefix>:approval_definition_admin` 或 `<prefix>:approval_runtime_admin` | 仅 `PROCESS_REQUIRED`；运行管理员只读 |
| 创建草稿 | `approval_process:create` | `<prefix>:approval_definition_admin` | 同类型最多一个活动草稿 |
| 编辑草稿 | `approval_process:edit` | `<prefix>:approval_definition_admin` | 只允许 `DRAFT` |
| 发布 | `approval_process:publish` | `<prefix>:approval_definition_admin` | 必须通过图、人员和用途校验 |
| 退役 | `approval_process:retire` | `<prefix>:approval_definition_admin` | 不影响已绑定单据和运行实例 |
| 升级未提交单据绑定 | `approval_instance:upgrade_binding` | `<prefix>:approval_definition_admin` | 目标单据仍未提交且版本一致 |

普通审批人、制单人和仅有运行管理权限的用户不得编辑定义；运行管理员只能读取其获授权类型的版本与详情。前端隐藏无权限动作不能替代服务端校验。页面打开期间权限被收回时，必须清除草稿编辑缓存和候选人搜索结果并切换为无权限状态。

## 3. 路由与 URL 合同

| 场景 | URL | 行为 |
| --- | --- | --- |
| 流程目录 | `/system/approval-processes?policy&status&q&page` | 筛选进入 URL；未知参数返回 422 页面状态 |
| 定义详情 | `/system/approval-processes/{documentType}` | 默认打开当前发布版本；无发布版本显示配置缺失 |
| 草稿编辑 | `?view=draft` | 同类型无草稿时显示创建入口 |
| 历史版本 | `?view=history&version={n}` | 历史只读，不复制为页签身份 |
| 未提交单据升级 | `?view=bindings&documentType={type}` | 只列可升级单据；从对象打开时追加稳定对象引用 |

`policy`、`status`、`q`、`page`、`view`、`version` 必须有对应控件和清除入口。定义编辑表单不写入 URL；有未保存修改时离开或关闭必须确认。

## 4. 目录视图

目录必须逐行展示合同固定的 20 个 `DocumentType`，不得从已有定义反推类型集合。

```text
┌ PageHeader：审批流程配置                         [新建草稿]
├ MetricStrip：需要审批 12 | 配置缺失 | 有草稿 | 已退役
├ ListToolbar：审批政策 | 配置状态 | 搜索 | 清除筛选
├ BusinessTableFrame
│ 单据类型 | 审批政策 | 当前版本 | 配置状态 | 草稿 | 最近发布 | 操作
└ Detail：当前版本摘要 / 草稿 / 历史 / 绑定升级
```

| 字段 | 用户文案 | 服务端来源 | 展示规则 |
| --- | --- | --- | --- |
| `documentTypeLabel` | 单据类型 | 固定政策目录 | 不显示枚举原值 |
| `approvalRequirement` | 审批政策 | 政策目录 | 显示「必须审批」或「无需审批」 |
| `publishedVersion` | 当前版本 | 当前发布定义 | 无定义显示「配置缺失」 |
| `configurationStatus` | 配置状态 | 服务端投影 | 已发布、配置缺失、有草稿、已退役 |
| `draftVersion` | 草稿版本 | 活动草稿 | 无草稿显示「—」 |
| `publishedAt/publishedBy` | 最近发布 | 发布审计 | 使用业务时区和安全显示名 |

`NO_APPROVAL` 行固定显示「无需审批 / 不适用」，不得提供新建、编辑、发布、退役或绑定升级入口。`PROCESS_REQUIRED` 且无已发布定义必须显示阻断状态，不得伪装为无需审批。

## 5. 草稿编辑

编辑表单必须使用 TanStack Form 与 Zod。请求只允许：定义名称、预期草稿锁版本、节点 ID（编辑现有节点时）、节点名称、显示顺序和审批人用户 ID。客户端不得提交 `node_key`、`node_type`、`node_purpose`、连线、决定集合、业务动作、权限名或处理器。

节点编辑器必须满足：

1. 至少一个节点，顺序从 1 连续递增；
2. 每个节点恰好选择一个具体用户；
3. 新节点 key 由服务端生成；已有节点 key 不得变化；
4. 候选人查询只做定义期账号状态和静态审批资格过滤，不宣称完成具体单据 DataScope 校验；
5. 通过和驳回连线由服务端按顺序生成，页面不得提供连线编辑器；
6. `SalesOrder + 空白流程` 可预置一个名为「采购确认」的普通节点，允许删除、改名和调整顺序。发布不再要求该节点或该用途；其他类型不得出现该用途；
7. `VoucherSalesOrder` 不得预置代码固定的「销售领导 / 运营」结构；管理员按普通节点配置。

节点拖拽必须在本地更新连续顺序，保存时提交完整节点顺序和 `expectedDefinitionLockVersion`。并发冲突不得自动覆盖；页面必须保留本地草稿，展示服务端最新版本并允许用户重新应用修改。

## 6. 发布与退役

发布确认必须展示：单据类型、定义版本、完整节点顺序、每个审批人、将退役的当前版本和受影响范围。发布动作必须由服务端在单一事务中完成校验、退役旧发布版本、发布新版本和审计写入。

发布失败必须按下列类别恢复：

| 错误类别 | 页面动作 |
| --- | --- |
| 图或顺序非法 | 定位到首个非法节点并保留表单 |
| 审批人账号或静态资格失效 | 标记对应节点并要求重新选择 |
| 草稿版本冲突 | 展示差异，不自动重试写入 |
| 已有发布版本变化 | 刷新发布确认并要求再次确认 |

退役只影响新单据绑定。已有绑定、审批实例、节点执行和历史仍引用原定义版本。退役后该 `PROCESS_REQUIRED` 类型若无发布版本，创建新单据必须失败关闭；页面必须在确认框中明确这一结果。

## 7. 历史与绑定升级

历史版本按 `definitionVersion desc` 稳定分页，展示状态、节点快照、发布/退役审计和版本差异。历史版本只读，不得直接修改或重新发布同一版本。

未提交单据升级必须：

- 只列 `DRAFT` 且未启动审批的单据；
- 显示当前绑定版本、目标发布版本、单据业务编号和当前绑定版本号；
- 请求携带 `expectedApprovalBindingVersion` 和幂等键；
- 服务端在写事务中重验单据状态、定义状态、审批人动态资格、对象读取权、DataScope 和岗位分离；
- 成功后整体替换绑定并写审计；失败不得留下部分字段更新；
- 已提交、运行中或终态单据不得升级。

## 8. 页面状态

| 状态 | 必须表现 |
| --- | --- |
| 加载 | 保留页面骨架和筛选，不显示伪造行 |
| 无权限 | 清除数据缓存和编辑草稿，提供返回入口 |
| 配置缺失 | `PROCESS_REQUIRED` 行显示阻断原因和有权用户的新建草稿入口 |
| 无搜索结果 | 保留筛选并提供清除筛选 |
| 保存失败 | 保留输入、节点顺序和审批人选择 |
| 发布结果不确定 | 按原幂等键查询结果，不重复创建版本 |
| 版本冲突 | 展示服务端版本与本地改动，不静默覆盖 |

用户可见文案必须使用「审批流程、审批节点、当前版本、配置缺失、发布、退役、更新审批流程版本」。不得显示 `ProcessKind`、instance、execution、binding、CAS、幂等键、内部 ID、`DIRECT` 或 `POOL`。
