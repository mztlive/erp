# W10 · 库存台账

> 状态：草稿
> 页面模式：M2 高密度查询列表 + M6 只读分析
> 主要路由：`/inventory`
> 主要角色：仓储；采购、财务和管理层按授权只读
> 最后更新：2026-08-01

## 1. 定位与目标

### 1.1 用户目标

- 仓储按“仓库 + SKU”快速确认账面现存、有效预占和可用数量，并追溯每次变化的正式来源。
- 采购核对采购入库是否已经形成库存和销售预占；销售相关人员从销售单上下文核对本单预占，不在 W10 浏览其它业务库存。
- 仓储从当前余额上下文发起盘盈、盘亏或损坏调整，并在原位置查看复核与过账结果。

### 1.2 业务目标

- 把 `stock_movement` 作为库存事实源，把 `stock_balance` 作为可重建、事务内同步的只读余额。
- 在同一工作面连接余额、流水、销售预占和调整单，但不提供“编辑库存数量”。
- 明确区分 ERP 自有实物库存与供应商直发、电子交付、线下服务、实体卡库存，避免把非库存履约伪装成库存。

### 1.3 不在本工作面完成

- 不直接修改 `on_hand_quantity`、`reserved_quantity` 或 `available_quantity`。
- 不在流水或预占行上提供删除、改数量、手工释放入口；纠错必须形成库存调整、采购退货或正式冲正事实。
- 不登记采购入库或仓发作业；这些动作在 W09 完成，W10 只展示其结果和来源。
- 不展示卡号、卡密或实体卡库存；实体卡不进入 ERP 自有库存。
- 不把供应商外部可供量并入 ERP 自有库存；外部供给进入 W21。
- 期初库存导入在 W18 完成，且必须来自基准日实盘，不在 W10 手工补写期初数。

## 2. 用户、权限与数据范围

| 角色 | 默认入口 | 可见范围 | 主要动作 |
| --- | --- | --- | --- |
| 仓储经办 | W09 或 W10 | 被授权仓库的余额、流水、预占和调整 | 查询、发起库存调整、查看结果 |
| 仓储复核 | W02 队列，可进入 W10 | 被授权仓库及待复核调整 | 查看台账；复核动作在队列完成 |
| 采购 | W08 / W09 链入 | 与本人采购及履约相关的库存结果 | 只读追溯入库和预占 |
| 财务 | 调整复核队列链入 | 涉及成本影响的调整及必要库存上下文 | 只读核对；财务确认在队列完成 |
| 销售/协作销售 | W05 链入 | 有权销售单对应的预占摘要 | 只读，不进入全仓库存浏览 |
| 管理层 | 分析入口 | 授权组织的只读库存摘要 | 只读，不显示调整入口 |

权限规则：

- 无 W10 模块权限时隐藏导航；直接访问显示无权限页。
- 仓库数据范围由服务端过滤，前端不得先取全仓数据后隐藏。
- 有模块权限但无仓库范围时显示“当前角色未配置仓库数据范围”，不能显示为库存为 0。
- 库存余额允许查看但无调整权限时，保留“库存调整”动作位置并禁用，展示服务端 `actionBlocker`。
- 调整经办、仓储复核、财务确认必须岗位分离；服务端返回 `allowedActions`，前端不得仅按角色名称推断。
- 页面打开期间权限被收回时，清除余额、流水、导出结果和已展开来源详情缓存。

## 3. 入口、路由与任务页签

| 场景 | 入口 | URL / 页签行为 | 返回位置 |
| --- | --- | --- | --- |

### 4.3 四个视图

| 视图 | 默认粒度 | 主要回答 |
| --- | --- | --- |

## 5. 展示内容与字段

### 5.1 指标与余额

| 区域 | 字段 | 用户文案 | 数据来源 | 口径 / 格式 | 权限规则 |
| --- | --- | --- | --- | --- | --- |
| 指标 | `balanceDimensionCount` | 库存组合 | 服务端余额查询汇总 | 当前筛选下仓库 + SKU 组合数 | 按仓库范围返回 |
| 指标 | `reservedDimensionCount` | 有效预占组合 | 服务端查询投影 | 有有效预占的组合数，不汇总跨单位数量 | 同上 |
| 指标 | `zeroAvailableDimensionCount` | 零可用组合 | 服务端查询投影 | `available_quantity = 0` 的组合数 | 同上 |
| 指标 | `pendingAdjustmentCount` | 待处理调整 | 正式调整单 | 当前范围内未到终态的调整数量 | 仅有调整查看权时显示 |
| 余额 | `warehouseName` | 仓库 | `warehouse` 当前可见修订 | 名称 + 仓库编号 | 仓库范围过滤 |
| 余额 | `skuName` / `skuCode` | SKU | `sku` 与修订 | 名称、规格、稳定编码 | 按商品字段权限 |
| 余额 | `onHandQuantity` | 账面现存 | `stock_balance` | 最多 6 位小数 + SKU 基础单位 | 只读 |
| 余额 | `reservedQuantity` | 有效预占 | `stock_balance` | 最多 6 位小数 + 同一基础单位 | 只读 |
| 余额 | `availableQuantity` | 可用数量 | `stock_balance` | 服务端已确认值；前端不自行相减 | 只读 |
| 余额 | `lastMovementId` / `lastMovementAt` | 最后变动 | `stock_balance` + 流水投影 | 业务发生时间与记录时间可展开查看 | 只读 |

### 5.2 流水、预占与调整

| 视图 | 必须显示 | 数据来源 / 口径 |
| --- | --- | --- |
| 流水 | 流水类型、增加/减少、数量、发生时间、记录时间、来源单据、冲正关系、记录人 | `stock_movement`；数量为正数，方向单独表达；原流水永不被覆盖 |
| 预占 | 仓库、SKU、销售单/销售明细、采购分配、入库来源、建立量、已消耗、已释放、状态 | `stock_reservation` 与 entry；不设置“自动过期”倒计时 |
| 调整 | 调整单号、仓库、原因类型、状态、SKU、方向、数量、经办人、仓储复核人、财务确认人、过账结果 | `stock_adjustment` 与正式流水；经办/复核身份清晰可见 |

来源单据显示业务编号和类型，点击后按权限打开 W08、W09、W05 或调整详情。接口不得只返回任意跳转 URL；前端使用稳定对象类型和 ID 匹配本地路由注册表。

### 5.3 明确排除的字段

- 不显示或存储卡号、卡密、绑定手机号。
- 不把旧商城 `stock`、`total_stock` 当作当前或期初库存。
- 不把供应商直发、电子交付、线下服务数量作为自有库存流水。
- 不展示跨 SKU 的“总库存数量”；不同基础单位不可直接相加。

## 6. 搜索、筛选、排序与默认视图

| 能力 | 默认值 | URL 状态 | 行为 |
| --- | --- | --- | --- |
| 视图 | `balance` | `view` | 切换后保留可复用的仓库/SKU 筛选 |
| 仓库 | 当前授权全部 | `warehouseId` | 只能选择服务端允许的仓库 |
| SKU/商品搜索 | 空 | `q` | 匹配稳定 SKU 编码、名称和规格投影；防抖请求服务端 |
| 余额状态 | 全部 | `availability=all|positive|zero|reserved` | 由服务端按正式余额筛选 |
| 流水类型 | 全部 | `movementType` | 仅在流水视图生效 |
| 业务日期 | 最近 30 天（流水） | `occurredFrom/To` | 余额视图不受日期限制 |
| 排序 | 仓库编码、SKU 编码 | `sort` | 数量排序必须限定同一 SKU/基础单位语境 |

- 余额表服务端分页；流水以 `occurred_at + id` 稳定排序，翻页期间新增流水不得造成重复或遗漏。
- 指标筛选后主表显示筛选摘要和结果数，并用 `aria-live=polite` 播报。
- 当前所有导出都只提交当前权限和筛选的服务端冻结快照，由后台任务生成并保留 7 天，过程展示 `BackgroundJobProgress`；在 Q4 的同步阈值确认前，不提供浏览器同步导出或小范围即时下载。
- Saved View 只保存查询偏好，不保存结果快照或扩大数据权限。

## 7. 操作契约

| 操作 | 入口 | 权限 / 前置条件 | 确认 | 成功结果 | 失败恢复 |
| --- | --- | --- | --- | --- | --- |
| 刷新 | 页头 | W10 可访问 | 无 | 重新取得余额水位和当前页数据 | 保留旧数据并显示重试 |
| 查看来源 | 流水/预占/调整行 | 有目标对象查看权 | 无 | 聚焦对应对象页签 | 权限变化时显示无权限，不泄露来源字段 |
| 发起库存调整 | 余额行/详情 | `CREATE_ADJUSTMENT` 允许；仓库与 SKU 仍有效 | 创建草稿不确认；提交时正式确认 | 形成调整草稿或待复核调整单号，余额不提前变化 | 保留输入；创建结果未知时按幂等键查询 |
| 提交调整 | 调整工作区 | 原因、方向、数量和必要凭证校验通过；版本有效 | `FormalActionConfirmDialog` | 状态进入待仓储复核，显示单号与下一责任方 | 校验失败聚焦摘要；冲突保留输入并刷新基线 |
| 查看调整进度 | 调整视图 | 有调整查看权 | 无 | 展示仓储复核、财务确认和过账结果 | 查询失败保留最后一次已知状态并标陈旧 |
| 导出 | 工具栏 | `EXPORT` 允许 | 展示筛选范围、字段和用途 | 始终返回后台任务与下载入口 | 任务可重试；不在浏览器拼全量数据，也不降级为同步下载 |

库存调整的复核、财务确认和最终过账在 W02 连续队列执行。W10 不提供绕过复核的“立即改库存”。过账成功必须在同一事务追加库存流水、更新余额和适用预占；前端只展示服务端正式结果。

## 8. 数据契约

### 8.1 查询

```ts
type InventoryQuery = {
  view: "balance" | "movement" | "reservation" | "adjustment"
  q?: string
  warehouseId?: string
  skuId?: string
  salesOrderLineId?: string
  availability?: "all" | "positive" | "zero" | "reserved"
  movementType?: string[]
  occurredFrom?: string
  occurredTo?: string
  cursor?: string
  pageSize: number
  sort: string[]
}
```

查询响应至少返回：权限版本、查询水位、稳定行 ID、服务端总数、分页游标、数量和基础单位、`allowedActions/actionBlockers`。Query Key 包含用户、角色、仓库数据范围版本、视图和全部筛选；由 TanStack Query 管理，不在组件内裸 `fetch`。

### 8.2 提交

库存调整草稿和提交至少携带：

- 稳定 `stockAdjustmentId`、`warehouseId`、明细 `skuId`；
- 原因类型、方向、正数数量、业务发生时间、原因说明和必要凭证；
- 余额 `lockVersion` 或服务端提供的等价基线版本；
- 请求幂等键和客户端请求追踪号。

重复提交使用同一幂等键；超时后查询原操作最终结果，不生成新键盲目重试。结果不确定时不得在本地修改余额，也不得跳转到“调整成功”。

### 8.3 前端边界

- 前端仅格式化数量、单位、日期、状态和来源文案。
- `available_quantity` 必须采用服务端返回；前端即使知道公式，也不得以本地重算值覆盖正式余额。
- 指标组合数、流水总数和导出总数由服务端计算，不能从当前页求和。
- 正式库存事实来自 `stock_movement`；`stock_balance` 可重建但日常提交后必须立即可见。
- 任何过账后数量都不得为负；这是服务端事务不变量，按钮禁用不能替代服务端校验。

## 9. 页面状态矩阵

| 状态 | 页面表现 | 可执行动作 | 恢复方式 |
| --- | --- | --- | --- |
| 初载 | 指标、工具栏和 6–8 行等高 Skeleton | 应用壳导航可用 | 查询完成原位替换 |
| 刷新 | 保留旧行，页头显示刷新中 | 可查看已有详情；正式动作提交时重新校验 | 成功更新水位；失败可重试 |
| 空数据 | 明确“当前仓库尚无 ERP 自有库存事实” | 清除筛选、进入 W18 期初导入（有权限时） | 产生正式流水后刷新 |
| 筛选无结果 | 保留筛选摘要 | 清除单项或全部筛选 | 返回有权数据 |
| 无数据范围 | 不显示 0 指标和空库存结论 | 查看角色/申请范围 | 范围更新后重查 |
| 失败且无缓存 | `BusinessFailureState` | 重试、返回其它模块 | 重试成功 |
| 失败但有缓存 | 保留旧数据并标记查询时间 | 查看；调整提交前强制重查 | 重试成功 |
| 数据陈旧/水位不一致 | 显示最后流水水位和风险提示 | 查询来源；禁用依赖陈旧基线的调整提交 | 水位追平或后台重建完成 |
| 字段级隐藏 | 敏感来源字段掩码，表格结构保持 | 其它有权动作 | 权限更新后重查 |
| 保存中/失败 | 禁止重复提交；保留调整输入 | 查询结果、重试同一操作 | 确认最终结果后刷新余额 |
| 版本冲突 | 展示余额已变化及服务端最新值，不静默覆盖 | 重新校验调整内容 | 用户确认新基线后再提交 |
| 正式动作成功 | `FormalActionResult` 固定展示调整单号、提交版本、时间和下一复核人 | 查看调整、进入下一工作 | 复核/过账后按正式水位刷新余额 |
| 正式结果不确定 | 固定结果区显示操作号和“正在查询最终结果” | 查询最终结果、联系支持 | 得到服务端终态后更新 |
| 后台任务 | 导出或台账重建显示任务号、范围、进度和水位 | 查看任务、取消未开始项 | 完成后下载/追平；失败可重试 |

| 375×812 | 单列余额/流水只读卡片 | 单个仓库 SKU 的现存、预占、可用和最后变动 | 不提供库存调整编辑、列设置和全量导出；说明需桌面完成 |

键盘顺序：页头 → 指标筛选 → 视图 → 工具栏 → 表头 → 行 → 固定动作。`/` 聚焦列表搜索；方向键移动行；Enter 打开详情；Esc 关闭详情并恢复原行焦点。数量变化、筛选结果和正式动作结果使用读屏可感知的文字，不以颜色或正负箭头作为唯一表达。触控目标不小于 44px。
