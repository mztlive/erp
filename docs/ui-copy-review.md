# ERP 前端文案审查报告（2026-08-02）

## 审查范围与方法

- 范围：`erp-client/features/` 下 10 个特征页面（access-audit、integration-errors、ownership-migration、mall-sync、history-backfill、import-opening、unified-task-queue、fulfillment-operations、inventory、master-data），逐文件通读所有用户可见文案（标题、描述、Alert、按钮、空态、tooltip、aria-label、placeholder、结果提示）。
- 三类问题标记：
  - **[A] 冗余文案**：同一信息在页面内重复出现，可删除其一。
  - **[B] 车轱辘话 / 冗长**：一句话内同义反复、堆砌从句，可大幅精简。
  - **[C] 技术名词 / 内部术语**：英文标识符、变量名、实现细节直接暴露给用户。
- 行号以审查当日文件内容为准。

## 系统性结论

1. **"演示"开关大规模混入正式业务界面**（mall-sync 1827/1932、inventory 1920/1937/1134、import-opening 765/780、master-data 各对话框、unified-task-queue 演示控制）：与"提交""确认"等正式按钮同排，用户无法分辨产品功能与测试开关。建议统一收敛到带明显边框的"演示"分组卡片，并在组标题处一次性说明。
2. **"服务端/前端/客户端/浏览器/缓存/基线/终态/门禁" 等实现词全站高频出现**：抽查的 10 个文件里出现 20+ 处。属于后台类页面（access-audit、integration-errors、history-backfill）可酌情保留，但 inventory、master-data、unified-task-queue、fulfillment-operations 面向日常业务用户，必须替换为业务口径。
3. **同一规则多文件重复**（"检查通过≠已提交"在 ownership-migration 出现 2 次、"仓库写不可用"在 master-data 出现 3 次、"服务端返回值"在 inventory 出现 3 次）：应各自收敛为一处权威文案，其余复用。
