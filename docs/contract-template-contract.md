# 合同模板与申请执行合同

版本：1.0。适用范围：签约前 Word 模板管理、销售领号、带编号下载及 Word 打印。

## 1. 业务边界

1. 管理员必须上传已有合同正文的 Word（DOCX）模板，并指定我方签约公司、模板名称和合同编号组。ERP 只填写编号，不起草或修改合同正文。
2. 销售必须选择对应签约公司的启用模板申请编号；申请成功后下载带编号的 DOCX，用 Word 打开、填写其他内容并打印。
3. 领号记录不得作为已签合同、有效合同或审批结果。签署版 PDF 必须按现有合同归档入口上传，销售单继续引用已归档合同版本。
4. 模板文件、签约公司和编号组必须保持不可变。替换正文必须上传新模板；旧模板可以停用，历史申请必须继续读取原模板与原号码。
5. 本功能不引入审批链。模板维护和销售申请必须分别授权。

## 2. 编号规则

合同号必须使用 `{编号组}-S-{两位年度}{四位年度流水}`；年度必须使用 Asia/Shanghai 业务日期，`S` 固定表示销售。

| 编号组 | 适用我方主体 | 2026 年已用流水 | 首个新申请编号 |
| --- | --- | ---: | --- |
| FSY | 福尚云科技、食品、研发、科技深圳分公司 | 452 | FSY-S-260453 |
| ZHYF | 智慧云福 | 22 | ZHYF-S-260023 |
| GYL | 朱太帅；原名称为供应链，必须沿用 GYL | 15 | GYL-S-260016 |
| BDKJ | 炳达科技 | 24 | BDKJ-S-260025 |

1. 管理员必须按上表将真实公司主体 ID 绑定到编号组；不得根据当前名称临时猜测或自动切换编号组。同一公司首次绑定后，后续模板必须沿用同一组；公司改名不得改变编号组。
2. FSY 四个主体必须共用同一年度流水。其他组必须独立计数；每份新申请占用一个号码。
3. 2026 年未持久化的计数器必须使用上表起点。首次成功申请必须将承接后的流水、申请记录及审计一起提交。
4. 新年度必须从 0001 开始；不得修改过去年度申请。两位年号的支持范围为 2000 至 2099 年；四位流水用尽时必须拒绝新申请，不得截断或回绕。
5. 已用流水只允许管理员向前校准，并必须携带当前版本；首次手动持久化不得低于上表起点。不得回收、删除申请或回退流水来复用号码。
6. 已签合同档案占用候选号码时，领号必须按索引检查并有界跳过；连续 100 个候选号已占用时必须拒绝并要求管理员校准流水。
7. 一次申请的重复下载、打印和同内容重试必须沿用原合同号。相同申请键携带不同模板或用途必须返回冲突。

## 3. Word 文件处理

1. 上传必须同时验证 `.docx` 扩展名、标准 DOCX MIME、压缩包结构和 Word 主文档类型；单文件不得超过 20 MB。
2. 压缩包不得超过 2048 个条目，单条目展开不得超过 32 MiB，累计展开不得超过 100 MiB；XML 不得超过 10 MiB。重复条目、路径穿越、宏项目、包签名及无法解析的文档必须拒绝。
3. 只允许标准 WordprocessingML DOCX；旧 `.doc`、PDF、宏 Word 文件不得作为模板上传。普通合同 PDF 与销售凭证的现有上传格式不得因此扩大。
4. 编号必须写入第一节的独立首页页眉，右对齐、黑色、10 磅。必须保留原正文、图片、普通页眉和页脚，后续节不得继承新增编号。
5. 模板首页页眉右上角必须留出编号位置。管理员必须下载标识为 `{编号组}-S-SAMPLE` 的编号样张，在 Word 中核对首页排版；样张不得占流水。
6. 下载必须使用申请时固定的模板文件和合同号。DOCX 不在浏览器内转换或直接打印；用户必须下载后使用 Word 打印。
7. 文件处理必须在有界输入和异步阻塞线程中执行，单 API 进程同时展开 DOCX 的任务不得超过两个；对象存储 I/O 必须位于 MongoDB 事务外。正常数据库失败必须补偿删除新上传对象；提交结果未知时必须保留对象用于核对。

## 4. 权限与接口

管理端接口必须经过 JWT 与 RBAC；权限生成物必须由 Handler 注解生成。

| 接口 | 权限 | 行为 |
| --- | --- | --- |
| `GET /admin/contract-templates` | `contract_template:list` | 分页读取共享模板目录，默认只返回启用模板 |
| `POST /admin/contract-templates` | `contract_template:manage` | multipart：唯一 `command` JSON 与唯一 `file` DOCX；字段顺序不限 |
| `POST /admin/contract-templates/{id}/status` | `contract_template:manage` | `{version, enabled}`，只修改启停状态 |
| `GET /admin/contract-templates/{id}/sample` | `contract_template:manage` | 下载不占流水的编号样张 |
| `GET /admin/contract-number-counters` | `contract_template:manage` | 返回当前业务年度四组已用流水；未持久化版本为 `null` |
| `POST /admin/contract-number-counters` | `contract_template:manage` | `{group, year, last_sequence, version}`，只允许向前校准 |
| `GET /admin/contract-applications` | `contract_application:list` | 只分页读取当前申请人记录 |
| `POST /admin/contract-applications` | `contract_application:create` | `{command_id, template_id, purpose}`，用途可留空，最多 256 字 |
| `GET /admin/contract-applications/{id}/download` | `contract_application:download` | 只下载本人申请的带编号 DOCX |

1. 模板命令必须为 `{name, company_id, group}`；`group` 只允许 `FSY`、`ZHYF`、`GYL`、`BDKJ`。
2. 申请人必须来自认证上下文，接口不得接受指定他人的申请人参数。越权下载必须统一返回不存在，不得暴露他人号码。
3. 共享模板目录不得读取客户合同或扩大客户 DataScope。申请资格不得授予模板维护、流水调整、已签合同读取或销售单资格。
4. 预定义销售角色必须授予模板读取及本人申请、读取、下载；系统管理员必须授予模板读取与维护，不自动授予代他人领号。
5. 下载必须返回标准 DOCX MIME、带合同号的附件文件名、`private, no-store` 和 `nosniff`；对象存储键不得进入公开视图。
6. 模板、申请目录必须在数据库中稳定排序后分页，页容量上限为 100。
7. 非法输入返回参数错误；模板停用、流水耗尽返回业务拒绝；版本或申请内容冲突返回 409。事务提交未知不得自动重放写入。

## 5. 页面执行

1. 销售导航必须提供“合同模板与申请”，地址为 `/sales/contract-templates`；页面必须提供“合同模板”和“我的合同申请”。
2. 申请弹窗必须显示模板、签约公司和编号组；成功必须显示生成的合同号并下载 Word。文件下载失败不得重新领号，必须提供原编号重新下载。
3. 申请请求发出前必须保留同一申请键和申请内容；结果未确认时必须锁定内容并提供继续核对。当前浏览器标签页刷新后必须能够恢复该请求，禁止把重试转成新申请。
4. 管理员必须能上传、下载样张、启停模板及向前校准年度流水；销售不得看到或执行这些维护动作。
5. 所有按钮、输入、选项、分页及列设置必须使用稳定的原生 DOM id。表格必须复用现有 DataTable 和工具栏；窄窗口必须保留上传、申请和下载操作。

## 6. 上线迁移与回退

1. 本版本新增 `contract_templates`、`contract_company_numbering`、`contract_number_counters`、`contract_applications` 四个集合，不改写既有合同和修订。
2. 开放申请前必须在 `backend/` 执行 `cargo run -p cli --locked -- --config-path <目标配置> migrate-contract-templates`。该命令必须只调用合同领域公开索引入口，不创建管理员、不修改角色、不清库、不写历史流水。
3. API 启动必须再次幂等登记同一索引。模板、主体绑定、计数器和申请 ID 必须唯一；申请人加申请键、申请合同号必须具有全局唯一索引。
4. 上线后管理员必须确认我方主体目录，上传对应的真实 Word 模板并核对样张。已有更大线下流水时必须先向前校准再开放申请。
5. 回退前必须停用新增领号入口，保留四个集合及模板对象备份。旧二进制必须忽略新增集合；不得删除已发号码、回退计数器、覆盖模板或清除申请审计。
6. 重新上线必须继续使用保留的模板、绑定与流水；历史号段不得按初始值重新创建。
