# 销售审批人链条展示合同

## 适用范围

实物及服务销售单、卡券销售单、销售变更单的工作台审批任务须展示本次审批的完整有序链条。销售单详情的审批页须使用同一链条数据。

## 数据与授权

1. 链条必须取自精确审批实例绑定的定义版本及实例冻结指派。组织负责人变更不得改变已启动审批的展示人员。
2. 节点须按定义的展示顺序排列。同一节点的全部或签人员须一起显示。
3. 读取链条须先通过既有实例读取授权。未来节点中的人员不得仅凭配置身份取得当前实例读取权。
4. 节点状态须由服务端提供。前端不得根据角色、人员顺序或当前组织配置推算节点状态。

## 读取协议

`GET /admin/approval-instances/{id}/history` 的无游标首页增加可选字段 `route`：

- `round_no`：实例当前轮次。
- `nodes`：本轮全部节点，不受历史页大小和排序方向影响。
- 节点字段：`node_key`、`node_name`、`assignee_name`、`result`、`execution`。
- `execution`：本轮该节点最近执行的历史项；未进入节点时为空。

非销售类审批及带游标的历史分页不返回 `route`。原有 `items`、`next_cursor`、`has_more` 的分页含义保持不变。

冻结运行图缺失，或定义版本、流程种类、执行归属及节点顺序不一致时，须返回冲突错误并提示刷新。不得以当前发布定义或现任负责人替代。

## 展示状态

| 服务端状态 | 展示要求 |
| --- | --- |
| `APPROVED` | 已通过，保留审批意见 |
| `ACTIVE` | 当前审批，突出当前节点 |
| `BLOCKED` | 已受阻，突出受阻节点并保留受阻提示 |
| `REJECTED` | 已驳回，保留驳回意见 |
| `CANCELLED` | 已撤回 |
| `PENDING` | 待审批；仅用于运行中或受阻实例的未进入节点 |
| `NOT_REACHED` | 未执行；用于已结束实例的未进入节点 |

链条须独立完整展示；分页历史须保留各次执行、恢复和历史轮次记录，不得按节点去重后替代执行历史。

## 验收要求

须覆盖已通过、当前审批、后续待审批并存；驳回及撤回后的未执行节点；受阻与恢复；动态负责人冻结；同节点或签；历史分页截断；错误实例、轮次、节点及定义版本拒绝。
