# 销售单全流程时间线合同

## 1. 功能落点

1. 销售单详情提供「全流程」页签；概览展示最近 5 条动态并提供全流程入口。
2. 全流程按时间倒序展示，支持销售、审批、采购、履约、客户票款、供应商票款、退货与调整筛选；默认隐藏草稿保存和资料修改，可切换展示。
3. 工作台审批面与办理面统一在页头辅助操作区提供「办理记录」入口，正文不展示动态卡片。点击入口后打开详情宽度的右侧抽屉，显示当前客户或业务对象、业务单号及时间倒序记录；记录按日期分组，当前单据身份不在每条记录中重复，其他关联单据保留身份及已授权入口。未打开抽屉时不请求记录，读取失败在抽屉内重试，不得阻断审批或办理表单。
4. 工作台通过详情宽度侧栏查看销售单全流程，保留当前办理内容。多销售来源分别列入口，不默认取第一张销售单。
5. 已有详情入口的销售单、采购单、付款申请、开票申请、收付款、发票、退款和冲正提供原单链接。尚无独立详情路由的履约及退货单据展示单据类型、编号与动作，不生成无效链接。
6. 手动刷新、窗口重新聚焦、成功业务变更使已打开的动态重新读取；不提供定时推送保证。

## 2. 事实及关联

1. 时间线为只读投影，不承担业务状态迁移、资金余额计算或审批决定。
2. 普通业务动作取成功的结构化审计；单据工作流动作取追加式记录；审批取实际运行实例、轮次及节点决定记录；销售提交取不可变提交记录；票款归属取正式分配行。
3. 销售单沿实际外键关联销售变更、采购、采购变更、收货、发货、验收、电子交付、服务履约、退货、客户票款及供应商票款。禁止按客户或供应商相同推定关联。
4. 票款沿子账、分录及分配关联；待审批回款沿提交的待核销明细关联。付款申请同时读取当前来源与不可变提交快照，重新提交不得使旧销售来源失去追溯入口。
5. 销售单关闭不截断查询；后续开票、回款、付款、退款和冲正继续展示。
6. 历史缺少结构化记录时保持缺失，不使用当前状态或更新时间补造过去动作。失败尝试不显示为业务成功。
7. 审批意见保留实际轮次、决定人快照及决定时间；没有决定时间的活动节点不得显示为已经通过或驳回。
8. 不合并不同来源的业务事实。节点决定、审批最终结束和单据业务生效分别保留；同一事件按稳定身份去重。

## 3. 金额与时间

1. 合并收付款、合并发票只展示归属本销售单的每次分配金额；不得显示整笔金额作为本单金额。
2. 冲减显示独立正数金额及「冲减」方向；原分配记录、原金额和原时间保留。
3. 财务单据的普通审计不直接输出整单金额事实及金额字段变化。金额以本单分配记录为准。
4. 审计、工作流、分配按正式记录时间排列；审批启动、结束和节点决定使用其明确的发生时间。缺少操作人姓名时显示缺失提示，不以当前责任人冒充历史操作人。
5. API 时间使用 Unix 秒；页面显示用户浏览器时区。同一秒按稳定事件 ID 倒序，ID 顺序不表示因果关系。
6. 审批提交时间之后的动态标记「提交后发生」。同秒动作不推断先后。最新动态不得覆盖或替代本次冻结提交资料。

## 4. 授权边界

1. 销售单全流程先校验销售详情对象范围，再逐张校验关联原单的详情资格。
2. 合并财务单据须满足全部来源的详情资格；部分来源可见不得返回整单审计和审批意见。无法证明资格时同时隐藏该单据分配事件。
3. 付款申请历史阅读须同时覆盖当前来源和所有已冻结提交来源，不能仅凭当前版本判断历史资格。
4. 工作台入口先通过现有任务详情资格；已发起审批入口先后复核审批实例阅读资格及主体版本。任务资格不自动授予其他销售单或原单详情权限。
5. 工作台允许展示当前任务的动作摘要。无原单详情资格时隐藏原单链接、审计字段明细和历史审批意见；本次审批材料仍由现有审批入口提供。关联销售动态与全流程入口须独立通过销售详情授权。
6. 返回结果不包含原始审计载荷、内部操作人 ID、无权查看的单据列表或隐藏条数。
7. 非权限拒绝、非对象缺失的授权基础设施错误继续返回错误，不吞掉为「无记录」。

## 5. API

| 方法及路径 | 资格 | 返回 |
| --- | --- | --- |
| `GET /admin/sales-orders/{id}/timeline` | `sales_order:detail` 及对象范围 | `TimelinePage` |
| `GET /admin/work-items/{id}/timeline` | `work_item:detail` 及任务阅读资格 | `TaskTimeline` |
| `GET /admin/approval-instances/{id}/timeline` | `approval_instance:read` 及实例阅读资格 | `TaskTimeline` |

查询参数：

- `page_size`：1–100，默认 30；概览及工作台使用 5。
- `category`：可选，`sales / approval / procurement / fulfillment / receivable / payable / returns`。
- `include_details`：默认 `false`，控制草稿及资料修改动作。
- `cursor`：服务端返回的不透明游标；前端不得拆解或自行构造。

`TimelinePage` 返回 `items`、`next_cursor` 和覆盖说明 `notice`。每条事件返回稳定 ID、时间、分类、中文动作、操作人显示名、来源单据、可用链接、允许展示的明细及可选本单金额。

`TaskTimeline` 返回 `timeline`、独立授权后的 `sales_orders` 和可选 `submitted_at`。不支持销售来源的任务返回当前可用动态或空列表。

分类、权限和游标条件先于分页截取。按 `(occurred_at, id)` 倒序翻页；同秒记录不得遗漏。分类改变须重新从第一页读取。并发新增记录通过刷新查看；分页不承诺跨请求数据库快照。

关联超过 2,000 张单据或 10,000 条分配及提交事实时明确返回范围错误，不静默截断；审批节点超过 10,000 条时同样拒绝。审计和工作流按每批 100 条读取。

## 6. 部署与索引

不修改既有业务数据，不执行历史回填。新增非唯一索引由原领域索引入口在服务启动时幂等登记：

| 集合 | 索引名 |
| --- | --- |
| `audit_logs` | `idx_audit_logs_resource_timeline` |
| `workflow_actions` | `idx_workflow_actions_timeline` |
| `purchase_payment_requests` | `idx_purchase_payment_requests_purchase`、`idx_purchase_payment_requests_legacy_account` |
| `purchase_payment_request_snapshots` | `idx_purchase_payment_request_snapshots_purchase` |
| `customer_refunds` | `idx_customer_refunds_entry`、`idx_customer_refunds_return` |
| `supplier_refunds` | `idx_supplier_refunds_entry`、`idx_supplier_refunds_return` |

索引迁移与回退脚本：`backend/scripts/migrations/20261020-sales-timeline-indexes.mongosh.js`；默认登记索引，设置 `ERP_INDEX_ROLLBACK=1` 仅移除本功能新增索引。

部署顺序：构建后端并校验权限生成物；执行库单元测试、边界检查和前端检查；部署匹配的 API 与前端；确认上述命名索引建立成功。

回退时先回退前端入口，再回退 API；可保留新增普通索引。需要移除时，逐项执行 `db.getCollection(集合名).dropIndex(索引名)`，只移除本节列出的新增索引，不删除业务记录或既有索引。

## 7. 验收要求

1. 多次审批、驳回重提、多个采购与履约单的历史可归集，按分类筛选正确。
2. 同秒事件翻页不重复、不漏；改变分类后游标重置。
3. 合并付款只显示本单分配；冲正保留原记录；进项发票进入供应商票款分类。
4. 未完成节点不得显示决定；审批资料与提交后动态同时存在且含义分明。
5. 无权限来源不产生原单链接或敏感明细；权限收回后重新请求失败关闭。
6. 销售单关闭后的票款记录可继续读取。
7. 工作台打开、关闭全流程侧栏后，原表单内容和待执行动作保持不变。
8. 办理记录抽屉独立滚动；关闭后保留主页面滚动位置与已填内容，焦点返回入口。切换任务时关闭抽屉，禁止残留上一任务的记录。付款条件、待补资料、驳回原因等影响当前办理的信息仍在办理区展示。

库单元测试和静态构建不能替代上述真实页面及数据验收。真实数据、浏览器验收按项目执行授权另行开展。
