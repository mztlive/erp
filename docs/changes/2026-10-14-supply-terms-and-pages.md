# 增量 PRD：供给条款精简与供给相关页面改版

- 状态：merged（2026-10-14 经 Tao Mao 在会话中确认并实现，合入 `docs/erp-phase-1.md`、`docs/supplier-portal-contract.md`、`docs/supplier-offering-batch-contract.md`、`docs/erp-phase-2.md`，本文冻结）
- 日期：2026-10-14
- 发起人：Tao Mao（Claude Code 会话起草）
- 需求落点：增强现有模块（第 4.4 节供给），建立在 [供应商配送模板与按地区选源](2026-10-14-supplier-delivery-template.md) 与 [公司商品池按配送地区筛选](2026-10-14-product-pool-region-filter.md) 之上

## 一、背景

用户反馈：

1. 商品编辑页不好操作、不好看；
2. 供给资料页全是文字，没有层次，配送模板入口不清晰；
3. 商品详情里给 SKU 添加供给关系的操作不清晰；
4. 添加供给 Dialog 不能直接选配送模板，补充信息里的字段没有意义。

核对代码后确认：配送模板上线后，供给条款里的运费、服务费、快递说明只存储和展示，没有任何计算或判定使用，且与“系统不记录、不计算运费金额”冲突；可供区域自由文本与配送模板职责重叠，只剩商品池文本筛选与“全国可供”快捷视图在用。

## 二、决定

| 项 | 决定 |
| --- | --- |
| 运费、服务费、一件代发快递说明 | 彻底下线：供给条款写入合同、实体、当前资料、历史、门户、批量配置与导出均删除 |
| 可供区域 | 下线，由配送模板取代；删除商品池与开单选品的“可供区域”筛选、列表列、导出列和“全国可供”快捷视图，选品冻结条件不再含区域 |
| 新增供给选模板 | `POST /admin/supplier-offerings` 增加可选 `delivery_template_id`，须存在且属于所选供应商，与供给同一命令写入；留空跟随供应商默认模板 |
| 商品详情的供给 | 新增“供应商供给”分区，按 SKU 分组列出供应商并就地添加；规格与 SKU 表格不再有供给列 |

## 三、用户可见变化

1. 添加供给 Dialog 分“供应商 / 报价 / 配送 / 有效期与可供”四区；供应商商品编码选填；选好供应商后选择配送模板并即时看到代发、集采规则；可新建模板；失效日期留空为长期有效；可供数量留空为供应商未提供；不再要求填写登记说明。
2. 供给资料页页头下方为价格、税率、当前可供摘要；当前供给分为配送范围、商业条款、供给资料三张卡片；配送范围卡片展示模板来源与规则，提供“更换配送模板”“管理模板”，供应商没有模板时引导新建。
3. 商品详情：分区为“商品资料 / 供应商供给 / 图片与详情 / 变更记录与引用”；商品资料内基础信息与规格各成一张卡片，规格表在常见桌面宽度下不再横向滚动，库存入口并入状态列。
4. 修订条款 Dialog 只保留价格、税率、起订量、有效期、关系状态和变更原因。

## 四、兼容与数据

项目未上线，不做兼容迁移。已有供给修订文档中的旧字段读取时忽略，下次写入不再保存；写入请求携带旧字段会被拒绝（条款合同拒绝未知字段）。种子脚本与 E2E 夹具同步去掉旧字段。
