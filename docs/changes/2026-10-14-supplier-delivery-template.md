## 一、需求背景与目标

供应商对同一商品的供货条件随收货地区变化：

1. **集采**：同一个集采单价，广东省内包邮，省外运费另计；新疆、西藏等地区不发货。
2. **一件代发**：代发价已包含全部运费，但也有不配送的地区。
3. 一个供应商可能有多套配送政策，分别适用于不同 SKU（例如常温品全国发、冷链品只发江浙沪）。

当前系统表达不了这些条件：

- 供给的"区域"是一段自由文本（如"全国"），不能和收货地址比对；
- 销售分地址交付的地址、仓库地址都是一整段文本，没有省市区编码；
- 供给分配只按履约方式取价：直发一律取代发价，集采价只用于入仓。集采直接发到客户地址这种实际业务做不出来；
- 选供应商时不看收货地，可能选中不发货的供应商，或漏掉另付的运费。

不做的后果：采购单发出后才发现供应商不送；省外集采运费漏记，订单利润被高估；集采直发只能按代发价下单，成本失真。

成功后：

- 采购按供应商维护配送模板，并给每条供给指定模板；
- 销售录入收货地址时选择省市区，系统提示哪些地址没有可配送的供给；
- 供给分配为每条明细列出代发直发、集采直发、集采入仓三种方案，逐个地址标出包邮、运费另计或不配送；不配送的地址不能分给该方案；
- 运费另计的采购由采购追加费用采购单（物流类）支付运费，或标记供应商不收运费；在这之前订单实际经营盈亏不宣称成本完整。

## 二、目标用户与使用场景

| 角色 | 入口 | 触发时机 | 典型操作 |
| --- | --- | --- | --- |
| 采购 | 供给列表"配送模板"管理、供给资料页 | 新签供应商或供应商调整配送政策 | 按供应商新建模板，设置默认模板，给供给批量指定模板 |
| 销售 | 销售单新建、销售改单的分地址交付 | 填写收货地址 | 选择省/市/区县并填写详细地址；看到"该地址暂无可配送供给""该地址仅支持集采发货，需另付运费"等提示 |
| 采购 | 供给分配 | 销售单生效后 | 比较三种方案，查看每个地址的配送判定，确认分配 |
| 采购 | 销售单详情采购分区、采购单详情 | 采购单含运费另计行 | 追加物流类费用采购单，或标记"供应商不收运费"并填写原因 |
| 仓储、运营 | 仓库资料 | 新建或修改仓库 | 选择仓库所在省/市/区县 |
| 财务、管理层 | 实际经营盈亏 | 查看订单利润 | 存在未处理的运费另计时看到阻断原因"运费待追加" |

前置条件：配送判定只适用于实物与服务销售单的实物商品明细。虚拟商品（电子交付）和线下服务不做配送判定。

异常与权限场景：

- 供给未指定模板且供应商没有默认模板：按"全国配送、代发与集采均包邮"判定，界面标明"未设置配送模板"；
- 销售明细未填写收货地址：供给分配不做地址判定，直发方案照常可选；
- 无 `supplier_offering:update` 的账号：只能查看模板，不能新建、修改、删除或给供给指定模板。

## 三、用户可见方案

### 3.1 地区与地址

1. 系统内置国家统计用行政区划（省、市、区县三级，6 位代码）。东莞、中山、儋州、嘉峪关等不设区县的地级市以市为最末级；台湾、香港、澳门以省级为最末级。
2. 销售分地址交付的每个地址改为"省/市/区县 + 详细地址"，必须选到最末级。展示时拼成完整地址。
3. 仓库资料增加"所在地区"，必须选到最末级。
4. 采购单冻结的收件资料同时冻结地区代码，供应商采购单、纸质预览展示完整地址。

### 3.2 配送模板

模板归供应商所有，一个供应商可以有多个。每个模板包含名称、是否默认，以及代发、集采两部分规则：

```
配送模板「XX食品-常温」（默认）
  代发（价格已含运费）
    其他地区：配送
    新疆、西藏、台湾、香港、澳门：不配送
  集采
    其他地区：运费另计
    广东省：包邮
    新疆、西藏：不配送
```

1. 代发判定只有"配送 / 不配送"两种；集采判定有"包邮 / 运费另计 / 不配送"三种。系统不记录、不计算运费金额。
2. 每部分先设"其他地区"的判定，再按地区列出例外。例外可以选省、市或区县；同一地区只能出现一次。判定时取最具体的一条：区县 > 市 > 省 > 其他地区。
3. 模板名称在同一供应商内不能重复。一个供应商最多一个默认模板；把某个模板设为默认时，原默认模板自动取消默认。
4. 被供给引用的模板不能删除。删除默认模板后，该供应商没有默认模板。
5. 每次修改模板，版本号加一；已建采购单冻结当时的判定结果，不随模板修改变化。

### 3.3 供给指定模板

1. 供给列表、供给资料页展示"配送模板"：
   - 指定了模板：显示模板名称；
   - 未指定、供应商有默认模板：显示"供应商默认（模板名称）"；
   - 都没有：显示"未设置（全国配送、包邮）"。
2. 采购可在供给资料页为单条供给指定模板，也可在供给列表勾选多条同一供应商的供给批量指定，或改回"跟随供应商默认"。
3. 指定模板不产生供给条款修订，不改变价格、起订量、有效期和可供状态。
4. 原供给"区域"文本保留展示和筛选，不参与配送判定。

### 3.4 销售录入地址时的提示

销售在新建或改单时填写收货地址后，系统按该 SKU 当前全部有效且可供的供给即时提示，不暴露供应商：

| 情况 | 提示 |
| --- | --- |
| 所有供给的代发和集采都不配送该地址 | 警告"该地址暂无可配送供给" |
| 所有供给的代发都不配送，集采可配送但都要运费另计 | 提示"该地址仅支持集采发货，需另付运费" |
| 其他 | 不提示 |

提示不阻断保存和提交：自有仓库的现货仍可发货，最终由采购在供给分配确认。如需向客户收取运费，按第 7.5.1 节由销售改单添加服务明细。

### 3.5 供给分配

1. 实物商品每个有效供给形成三种采购方案：

| 方案 | 履约责任 | 成本单价 | 配送判定依据 |
| --- | --- | --- | --- |
| 代发直发 | 供应商直发 | 一件代发价 | 模板代发规则 × 各收货地址 |
| 集采直发 | 供应商直发 | 集采价 | 模板集采规则 × 各收货地址 |
| 集采入仓 | 仓库履约 | 集采价 | 模板集采规则 × 目标仓库所在地区 |

2. 方案卡片显示配送模板名称和判定汇总（如"2 个地址运费另计、1 个地址不配送"）；地址分配表逐行标出判定。
3. 直发方案的地址分配中，不配送的地址不可分配；所有地址都不配送的方案不出现在推荐中。服务端在创建采购单的事务内重新判定，拒绝分给不配送地址或不配送仓库的请求。
4. 集采直发要求本次向同一条供给采购的数量合计不少于该供给的集采起订量；不足时不能确认，并提示起订量。集采入仓沿用现状，不校验起订量。
5. 集采入仓选择目标仓库后显示该仓库的判定；仓库不配送时不能确认。
6. 自动推荐沿用"现有库存优先、直发优先、可全量覆盖优先"；同一优先级内，全部地址包邮的方案排在含运费另计的方案之前，再比含税成本、交期、可供量和供应商名称。运费金额未知，推荐不把运费另计方案的单价当作完整成本。
7. 同一供应商的代发采购与集采采购拆成两张采购单。

### 3.6 采购单

1. 采购商品行冻结：价格依据（代发 / 集采）、配送模板名称和版本、是否运费另计。
2. 采购单详情行上标出"代发 / 集采"和"运费另计"。
3. 采购改单调整数量或地址分配时不重新判定配送范围（见边界）。

### 3.7 运费另计的跟进

1. 生效或审批中的采购单存在运费另计行时，销售单详情采购分区和采购单详情显示"运费待追加"：列出采购单号、供应商和商品。
2. 以下任一情况视为已处理，提示消失：
   - 同一销售单已有该供应商未作废的费用采购单，其中有物流类费用行归属该销售明细，或不归属具体明细；
   - 采购在采购单上标记"供应商不收运费"并填写原因（不超过 200 字）。标记记录操作人和时间，不可撤销。
3. 销售单详情的待追加条目提供"追加运费"，打开现有"追加附加费用"并预填收款供应商、费用类别"物流"和归属明细。
4. 存在未处理的运费另计时，实际经营盈亏显示阻断原因"运费待追加"，该单收入不计入成本覆盖收入。

## 四、边界与非目标

1. 系统不计算、不估算运费金额；运费按第 7.5.1 节通过费用采购单支付。
2. 原供给"区域"自由文本保留，不参与判定。移除它涉及商品池筛选、供应商门户和批量导入，另行处理。
3. 供应商门户、供给批量导入不支持选择模板；门户和导入建立的供给跟随供应商默认模板，由采购在 ERP 中调整。
4. 选品册客户收件信息不改为地区代码。
5. 不支持乡镇、街道级规则。
6. 采购改单不重新判定配送范围，也不重新校验集采起订量。
7. 集采入仓不新增起订量校验。
8. 虚拟商品与线下服务不做配送判定。
9. 模板不受部门数据范围约束；模板不含成本信息。
10. 不新增菜单、通知或后台任务。

## 五、验收标准

**地区与地址**

1. Given 销售新建实物与服务销售单，When 添加收货地址，Then 必须选择省/市/区县并填写详细地址才能保存；详情和审批材料展示"省市区 + 详细地址"。
2. Given 仓库资料，When 新建或修改仓库未选择所在地区，Then 保存被拒绝。

**配送模板**

3. Given 采购为供应商 A 新建模板"常温"并设为默认，When 再新建模板"冷链"并设为默认，Then "常温"自动取消默认。
4. Given 模板集采规则"其他地区运费另计、广东省包邮、深圳市不配送"，When 判定深圳市南山区，Then 为不配送；判定广州市天河区为包邮；判定上海市浦东新区为运费另计。
5. Given 同一模板中广东省出现两次，When 保存，Then 拒绝并提示地区重复。
6. Given 模板被供给引用，When 删除，Then 拒绝。
7. Given 供给未指定模板、供应商无默认模板，Then 供给列表显示"未设置（全国配送、包邮）"，供给分配按包邮判定。

**销售提示**

8. Given SKU 只有一条有效供给，其模板代发与集采都不配送新疆，When 销售录入乌鲁木齐地址，Then 地址行显示"该地址暂无可配送供给"，仍可保存提交。

**供给分配**

9. Given 销售明细 10 件分两个地址（广州、乌鲁木齐），供给模板代发不配送新疆，When 打开供给分配，Then 代发直发方案只能分配广州地址的数量，乌鲁木齐地址标"不配送"。
10. Given 集采起订量 50 的供给，When 选择集采直发采购 30 件并确认，Then 拒绝并提示起订量；采购 50 件时成功，采购单价为集采价，行标"集采"。
11. Given 集采规则省外运费另计，When 集采直发到上海地址并创建采购单，Then 采购行标"运费另计"。
12. Given 绕过界面直接提交把数量分给不配送地址的请求，Then 服务端拒绝，不创建采购单。
13. Given 目标仓库所在地区为集采不配送，When 选择集采入仓该仓库，Then 不能确认，服务端同样拒绝。
14. Given 同一供应商同一销售单同时确认代发直发和集采直发，Then 形成两张采购单。

**运费跟进**

15. Given 生效采购单有运费另计行，Then 销售单详情采购分区显示"运费待追加"，实际经营盈亏显示阻断原因"运费待追加"。
16. Given 上述情况，When 采购点"追加运费"并提交物流类费用采购单（归属该明细），Then 提示消失，阻断解除。
17. Given 上述情况，When 采购标记"供应商不收运费"但未填原因，Then 拒绝；填写原因后提示消失。

## 六、方案与取舍

**为什么模板挂在供应商上，由供给引用**：供应商通常一套政策覆盖大部分商品，少数 SKU 例外。按 SKU 逐条录入要重复几百遍，修改也要逐条改。模板 + 默认模板 + 供给覆盖，既覆盖"一套政策"也覆盖"多套政策对应不同 SKU"。

**为什么供给引用模板不产生条款修订**：模板本身会改，供给修订冻结不了模板内容；采购单冻结判定结果已足够追溯。指定模板走独立命令，避免批量换模板时生成大量价格未变的修订。

**为什么系统不计算运费**：商品重量和体积未建档，供应商运费规则各异；按件估算会误导成本判断。系统只负责"能不能送、要不要另付"，运费金额以供应商实际账单走费用采购单。

**为什么推荐时包邮优先**：运费另计方案的单价不是完整成本。推荐优先选成本已知的方案，采购可手动改选运费另计方案。

**为什么代发与集采分单**：采购单按依据范围合并行，价格依据不同的行混在一张单里需要改造合并逻辑；分单对供应商也更清楚。

**对既有规则的澄清（不视为推翻）**：

| 原文 | 本方案后的含义 |
| --- | --- |
| §7.4"一件代发采购价包含发货、包装等全部费用，不重复登记物流费用" | 不变；代发只判定能否配送 |
| §7.4 采购单拆分维度"供应商、采购类型、付款条件和履约责任" | 增加价格依据（代发 / 集采） |
| §7.4 采购推荐"含税成本低优先" | 同一优先级内先比较是否全部包邮，再比较含税成本 |
| §7.4 采购成本取价：入仓取集采价、直发取代发价 | 由采购方案的价格依据决定；直发可取集采价 |

## 七、章节变更草案

### §2.1 术语表（新增）

| 术语 | 含义 |
| --- | --- |
| **配送模板** | 供应商维护的配送政策，按地区规定代发是否配送，以及集采包邮、运费另计或不配送。供给引用模板，未引用时跟随供应商默认模板，见第 4.4 节 |
| **运费另计** | 集采发往某地区时供应商另收运费。系统不计算金额，由采购追加物流类费用采购单或标记供应商不收运费，见第 7.5.1 节 |

### §4.4 公司商品池与采购二次确认（新增两条，置于"可供状态和数量独立保存"之后）

- 供应商可维护多个配送模板，每个模板含名称、是否默认，以及代发、集采两部分规则。代发判定为配送或不配送；集采判定为包邮、运费另计或不配送。每部分先设其他地区的判定，再按省、市或区县列出例外，同一地区只能出现一次；判定取最具体的一条（区县 > 市 > 省 > 其他地区）。同一供应商内模板名称唯一，最多一个默认模板；被供给引用的模板不能删除；
- 供给可指定本供应商的一个配送模板，未指定时跟随供应商默认模板，二者都没有时按全国配送、代发与集采均包邮判定。指定模板使用独立命令，不产生条款修订；供给列表、资料页展示当前模板。原"区域"文本只作展示与筛选，不参与配送判定。读取模板沿用 `supplier_offering:list`，维护模板及指定模板沿用 `supplier_offering:update`；模板不受部门数据范围约束。

### §4.4.3 销售商品分地址交付（修改第 1 条，新增第 9 条）

1. 实物与服务销售行可填写 `delivery_allocations`，每项包含收货人、联系电话、收货地区（行政区划最末级 6 位代码）、详细地址及基础单位数量。每行最多 100 个地址，数量必须为正数，合计必须严格等于该销售行数量，不得用浮点数近似比较。展示时以"省市区 + 详细地址"拼成完整地址。

9. 销售录入地址后，系统按该 SKU 当前全部有效且可供供给的配送模板即时提示：代发和集采均不配送时警告"该地址暂无可配送供给"；代发均不配送、集采只能运费另计时提示"该地址仅支持集采发货，需另付运费"。提示不阻断保存与提交，不暴露供应商。

### §7.4 供给分配与采购单规则（修改）

"采购推荐必须优先选择供应商直发……"一条替换为：

- 实物商品的每条有效供给形成代发直发（一件代发价）、集采直发（集采价）和集采入仓（集采价）三种采购方案；虚拟商品与线下服务只形成按一件代发价的电子交付或服务履约方案。采购推荐必须优先选择供应商直发，减少新增采购入库；存在有效且可供的直发方案时，不得仅因入仓方案成本更低或可全量覆盖而优先推荐入仓。同一优先级内按可全量覆盖优先、全部地址包邮优先、含税成本低优先、预计交付日早优先、最大可供量大优先、供应商名称稳定排序。直发供给不足时按实际可供量推荐并保留未分配缺口，允许操作人调整或拆分；无可用直发方案时继续推荐其他有效采购方案，不得虚增库存或供应商可供量；

新增：

- 直发方案按供给配送模板逐个收货地址判定（代发用代发规则，集采直发用集采规则），集采入仓按目标仓库所在地区判定。不配送的地址不得分配给该方案，不配送的仓库不得作为目标仓；服务端在创建事务内重新判定并拒绝。销售明细未填写地址时不做地址判定；
- 集采直发要求一次确认中向同一条供给采购的数量合计不少于该供给的集采起订量；集采入仓不校验起订量；
- 采购商品行冻结价格依据（代发 / 集采）、配送模板名称与版本及是否运费另计；采购改单不重新判定配送范围；

"同一销售单内，供应商、采购类型、付款条件和履约责任一致的采购明细合并为一张采购单""……任一不同，拆分采购单"两条中的拆分维度增加"价格依据"。

### §7.5.1 附加费用（新增"运费另计跟进"小节，置于"财务登记"之后）

**运费另计跟进**

- 生效或审批中的采购单含运费另计行时，销售单详情采购分区与采购单详情显示"运费待追加"，列出采购单号、供应商和商品；销售单详情可从条目"追加运费"，预填收款供应商、费用类别"物流"和归属明细；
- 同一销售单存在该供应商未作废的费用采购单，且其中有物流类费用行归属该明细或不归属具体明细时，视为已处理；采购也可在采购单上标记"供应商不收运费"并填写原因（不超过 200 字），标记不可撤销；

### 与本文方案的差异（已按实现写入基线）

1. 集采直发不进入自动推荐，由采购按需改选；自动推荐在直发内只比较代发直发。原因：集采直发须与供应商确认集采订单，且自动切换会改变默认成本。
2. 直发推荐数量不超过本方案可配送地址的剩余需求；不配送地址在分配表中锁定为 0。
3. 采购单的价格依据、逐行判定和免收标记保存在采购单表头，按稳定销售行记录，不进入采购行版本；采购单详情以提示区展示运费另计状态，侧栏单列“价格依据”。
4. 本规则上线前建立的仓库修订可以没有所在地区，读取不失败；这类仓库不能作为集采入仓目标仓，须修改仓库资料补地区。开发种子 `seed-dev-foundation.mjs` 为固定仓库自动补地区。仓库资料仍只能经接口维护，前端未提供仓库编辑页。
5. 销售单详情的“运费待追加”只对具备 `purchase_order:create` 的账号返回，避免向销售暴露供应商名称。
6. 区划数据取自 modood/Administrative-divisions-of-China 整理版的省、市、区县三级，东莞、中山、儋州、嘉峪关的乡镇级条目未纳入。
