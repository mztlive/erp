- 状态：merged（2026-10-14 经 Tao Mao 在会话中要求修复并实现，合入 `docs/erp-phase-1.md`，本文冻结）
- 日期：2026-10-14
- 发起人：Tao Mao（Claude Code 会话起草）
- 需求落点：增强现有模块（第 4.4 节公司商品池与供给）；承接 [公司商品池按配送地区筛选](2026-10-14-product-pool-region-filter.md) 的未完成项
- 涉及章节：`docs/erp-phase-1.md` §4.4

## 一、背景与目标

上线后公司商品池将录入几万个 SKU。实测 36,036 个可售 SKU、51,051 条供给时：

- 页面一次取回全部结果，按每页 100 条顺序请求约 360 次；
- 每次请求都对全部 SKU 重新关联修订与供给判定资格，单页耗时 7.7–8.2 秒，带关键字或价格条件也要 2.8 秒；
- SKU、SKU 修订、商品、商品修订、供给修订、计量单位等集合没有稳定主键 `id` 索引，按 `id` 关联退化为逐行集合扫描。

另有两项遗留：按配送地区筛选后不能按筛选条件发起选品；供给条款失效日期的口径在各处不一致。

目标：几万个 SKU 下商品池翻页、筛选、排序在百毫秒内返回；选品册支持配送地区；失效日期口径统一。

## 二、用户可见方案

1. 商品池表格按服务端分页与排序，卡片视图滚动到底按页追加；翻页与排序保留勾选，筛选变化清空勾选；全选改为“全选已显示”；按勾选导出只取回勾选的商品。
2. 刚修改的 SKU、价格、上下架或供给，下一次打开商品池即可看到；大批量导入在后台逐批生效。
3. 按配送地区筛选后可按筛选条件发起选品，选品册冻结配送地区、范围与运费另计，准备与重新准备按冻结条件取商品；重新准备的条件说明显示地区名称与范围。
4. 供给条款有效期为生效日期（含）至失效日期（不含）：失效日期当天起不再有效。供给资料与门户的有效期显示改为“X 起，Y 失效”；门户批量录入与后端一致，要求失效日期晚于生效日期。

## 三、边界与非目标

- 资格业务日期不是当天的查询仍按实时聚合，速度不变（日常界面不暴露该参数）。
- 销售单提交、采购选源与建单仍按实时事实判定，不读取投影。
- 以 `_id` 为主键、文档不含 `id` 字段的集合不加 `id` 索引，见九、实施说明。

## 四、验收标准

1. 36,036 个可售 SKU 下：首页、深页、关键字、类型、价格、排序、配送地区、按 SKU 查询均在 100 毫秒内返回（实测见十）。
2. 新建 SKU 与供给后立即查询商品池能看到该 SKU。
3. 改一个 SKU 修订后再查询，结果反映修改。
4. 失效日期为今天的供给条款，今天起不再参与商品池资格、采购选源与建单。
5. 按配送地区筛选后按筛选条件生成的选品册只包含满足配送条件的商品。

## 五、方案与取舍

- **预算投影而非逐次聚合**：资格需要关联 SKU 修订、商品、商品修订、单位、供给、供给修订与可供状态，几万个 SKU 时无法逐次计算；投影每 SKU 一条，列表一次索引查询完成筛选、排序、计数与分页。
- **重算复用实时聚合**：投影由后台对待重算的 SKU 调用原资格聚合生成，资格口径只有一处；销售单提交仍走实时复核。
- **读取前追平**：列表读取时扫描最新变化并同步重算不超过 200 个 SKU，保证“改完就能看到”；更大批量交给后台，避免读请求变慢。`updated_at` 精确到秒，追平时包含当前这一秒，进度只推进到当前秒，下一次再扫一遍。
- **换日全部重算**：资格含生效、失效日期，换日后全部标记重算，比逐 SKU 记录日期更简单可靠。
- **失效日期取左闭右开**：字段在全部录入界面名为“失效日期”，后端要求失效日期晚于生效日期，SKU 修订、客户归属与组织成员也按左闭右开判定；采购、门户与配送覆盖改为同一口径。

## 六、章节变更草案

已合入 `docs/erp-phase-1.md` §4.4：

- 商品池服务端分页、排序、勾选与导出规则，接口参数 `sort_by`、`sort_dir`、`sku_ids`；
- 预算投影查询、读取前追平、换日重算与实时聚合的分工；
- 按筛选条件发起选品冻结配送地区条件；
- 供给条款有效期左闭右开口径。

## 七、影响面清单

- 权限点：不涉及，沿用 `sellable_sku:list`。
- 菜单、DataScope、通知、搜索、AI：不涉及。
- 状态口径：涉及供给有效期边界，见二.4。
- 后台任务：新增统一后台执行器任务 `sellable_sku_projection_refresh`。
- 多端：只做 Web 管理端。

## 九、实施说明

### 实现落点

| 能力 | 位置 |
| --- | --- |
| 变更扫描进度 | `erp-core` `change_scan.rs`（即时扫描、延迟复扫、读取前追平时间窗）；配送覆盖进度改为共用 |
| 待重算标记 | `persistence-core` `dirty_marks.rs`（按主键标记与占位、读取一批、按标记序号保存）；配送覆盖存储改为共用；`persisted_document` 公开，供投影按原生 BSON 保存金额 |
| 商品池投影 | `erp-catalog` `repository/catalog/sellable_projection.rs`：`sellable_sku_projections`（每 SKU 一条，`row` 为当天可售行或空）与 `sellable_sku_projection_state`；变更扫描、筛选排序分页查询与索引 |
| 后台与追平 | `erp-processes` `sellable_projection_refresh.rs`（每 2 秒一轮，每轮最多 10 批 × 200 个 SKU；首次构建完成前列表走实时聚合）；`adapters/catalog_supply_query/repository/sellable_search.rs` 决定走投影或实时聚合 |
| 排序与 SKU 限定 | `SellableSkuFilter.sort`、`sku_ids`；实时聚合与投影排序字段一致 |
| 稳定主键索引 | `skus`、`sku_revisions`、`products`、`product_revisions`、`product_brands`、`unit_of_measures`、`supplier_offerings`、`supplier_offering_revisions`、`supplier_offering_availabilities`、`supplier_delivery_templates` 新增 `id` 唯一索引；`skus`、`sku_revisions`、`products`、`product_revisions` 新增 `updated_at` 索引 |
| 其余已有数据集合的稳定主键索引 | 合同、客户、文件、待办与财务责任规则、往来方资料、采购责任规则、采购单及提交、应收、销售单全部明细与修订、销售变更、供应商资料与资质、仓库、商品修订媒体与卡券类目资料、供给命令共 44 个集合新增 `uk_<集合>_id` 唯一索引；新增前核对开发库中 `id` 均存在且无重复 |
| 其余空集合的稳定主键索引 | 发票、应付、付款、库存、采购付款申请及快照、退货退款、收货、交付与验收、供应商履约、结算与接口、选品册、导入、集成、文档关系、权限与用户角色等 95 个集合新增 `uk_<集合>_id` 唯一索引。逐个核对文档类型均为带生成 `id` 的实体；确定性 `id`（付款申请提交快照、健康检查记录、集成错误任务）每个来源只写一次。以 `_id` 为主键、不含 `id` 字段的 `casbin_rules`、`casbin_policy_state`、`demo_master_records`、`sales_selection_rate_windows`、`background_job_inputs` 与两类投影及其进度不加；按全新库启动核对，除这些集合外全部集合均已有 `id` 唯一索引 |
| 选品册配送地区 | `erp-sales` `PoolFilterSnapshot` 新增 `delivery_region_code`、`delivery_extent`、`include_freight_extra`，冻结时校验地区代码 |
| 有效期口径 | `BusinessDate::is_within`；采购选源复核、采购创建依据、供应商门户条款校验、配送覆盖改用之 |
| 前端 | 商品池 `use-sellable-list-data.ts`（表格单页查询、卡片追加查询）、`use-sellable-gallery-selection.ts`（跨页勾选）、`lib/sellable-sort.ts`；选品册条件说明；供给与门户有效期显示 |

### 实测（36,036 个可售 SKU、51,051 条供给）

| 查询 | 改前 | 改后 |
| --- | --- | --- |
| 首页 20 条 | 7.7–7.9 s | 11–15 ms |
| 第 300 页 100 条 | 8.2 s | 28 ms |
| 关键字 | 2.8 s | 52 ms |
| 商品类型 | 6.7 s | 11 ms |
| 价格区间 | 2.8 s | 8 ms |
| 按集采价降序 / 供应保障排序 | — | 29 ms |
| 配送地区（深圳市全部可送） | 1.2 s | 87 ms |
| 按 100 个 SKU 查询 | — | 8 ms |
| 修改 3 个 SKU 后立即查询（含追平） | — | 26 ms |
| 资格业务日期为明天（实时聚合） | 7.8 s | 7.8 s |

后台重算约 360 个 SKU/秒（投影）与 200 个 SKU/秒（配送覆盖）；一次导入几万个 SKU 需数分钟逐批生效，期间列表按已重算的结果返回。

### 遗留风险

- 延迟复扫会对大批量变化再重算一遍，大批量导入的后台总耗时约为单次的两倍。
