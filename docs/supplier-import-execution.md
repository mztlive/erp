# 供应商导入执行规范

## 1. 生效范围

本次交付包含供应商模板导入、公司主体维护及下拉选择、供应商常用进项税率、自然周期结算、供给税率候选和采购发票分配税额。供应商编号继续由系统按 `SUP-` 规则生成。模板内旧编号不得作为新供应商编号或覆盖依据。

供应商常用进项税率仅作为供给录入候选；同一供应商的不同 SKU 可采用不同税率。实际供给保存一个税率，采购单行冻结该税率。变更供应商候选税率不得改写已有供给、采购单或销售税率。空税率表示未登记，零税率表示明确登记为零，两者不得互换。

## 2. 公司主体准备

1. 在“主数据 → 公司主体”维护我方公司全称、简称、导入别名及启停状态。名称、简称、别名的匹配键不得跨公司重复。
2. 导入只匹配已启用公司；不得按近似名称猜测公司，不得从供应商或客户名称自动推断我方公司身份。
3. 表内缺少签约主体时使用付款主体，缺少付款主体时使用签约主体；二者均为空时该行失败。
4. 已有主体不得重新创建为另一条公司。存量主体按第 6 节映射登记，保留原 Party ID、名称修订、账户资料及供应商历史引用。
5. 停用公司不再用于新选择；历史资料保留原公司名称回显。

## 3. 导入规则

1. 使用原模板 `.xlsx`，保留第 1 行原有 23 列表头；每次 1–500 行，文件不超过 10 MB。空白行跳过，结果保留 Excel 行号。
2. 供应商全称、结算方式、发票类型及互补后的公司主体为必填项。联系人和联系方式、银行账号和开户行分别成对填写；整组为空时不创建该组资料。
3. 税率、地址、合同和评级等可选资料缺失时保持空值。填写评级资料时必须同时提供评级和合作中评分；不得补零分或默认评级。
4. 常用税率支持 `9%、13%`、`9%，13%` 等写法，去重后保存。数字百分比单元格按百分比显示语义转换。不得将无法识别的税率设为默认值。
5. “一年”“半年”等无法确定日期的合同有效期留空。明确到期日缺少合同编号时整行失败。合同起始日期缺失时保存为空，不使用导入日补齐；明确到期日按原值保存，包括已过去的日期。合同起止日期不完整时标记“有效期未核实”，不得自动视为有效资质。
6. 附件名称、链接和浮动图片不能替代上传资产；包含不能安全导入附件的行返回失败。授权书有效期未伴随完整授权资料时返回失败。
7. 电话、银行账号和编号按文本保存。超过 Excel 数字精度的数值单元格、公式及错误单元格返回读取失败；原文件不得被修改。
8. 按供应商当前全称精确去重，忽略空白、英文大小写及中英文括号差异；系统已存在或此前已成功导入的供应商跳过，不覆盖其资料。同文件同名供应商至多成功创建一次。
9. 前台向 `/admin/supplier-profiles/import/jobs` 提交文件名、固定请求身份和模板行，服务端登记 `SUPPLIER_IMPORT` 后台任务。每行由统一后台执行器调用既有供应商根命令原子提交；完整行独立处理，保留成功、重复跳过、失败、结果待确认四种结果。
10. 提交成功后进入“后台任务”，离开页面不停止执行。提交响应未知时保留原内容和请求身份，使用“重试核对”回读原提交；相同身份更换内容必须拒绝。执行中无法确认的行在任务明细显示“结果待确认”，计入需处理行；该统计不得解释为业务写入已回滚。原提交人可在任务结束后下载待处理行、修正后重导，系统按原供应商根命令检查既有结果。
11. 读取失败的单元格在失败文件中以“【待修正】”文本保留原内容，公式不得作为可执行公式导出。重新导入前须核实并替换这些单元格，处理完该行全部读取问题后清空“待处理读取错误（修正后清空）”列；未修正的标记继续阻止该行写入。

### 3.1 后台执行与结果查询

1. 任务、逐行记录同事务登记；源内容使用现有敏感数据编解码器加密后写入配置对象存储的 `supplier-import/` 前缀，不生成明文公共下载地址。任务元数据只保存源摘要、供应商名称、文件名称摘要、Excel 行号和脱敏结果。
2. 执行器每轮最多读取四项任务；使用任务版本认领，最近两分钟仍在推进的任务不得抢占。未完成任务超过两分钟无进度可恢复，已记录结果的行不得重做。单行执行超过一分钟时记录“结果待确认”，不得假定事务已回滚。
3. 每行结果与累计进度同事务保存。取消后停止领取后续行；已经开始的行可能完成，已经创建的供应商不得因取消而删除。取消时尚未登记结果的行纳入待处理清单，再次导入时核对既有供应商。
4. 通用后台任务列表、详情和行明细沿用后台任务权限及本人／管理员可见范围。逐行结果按 100 行分页，保留原 Excel 行号。失败、取消或部分完成任务必须展示已完成数量和剩余处理入口。
5. 待处理清单通过 `/admin/supplier-profiles/import/jobs/{id}/failures` 查询，要求供应商创建权限且操作者为原提交人；管理员查看他人任务不授予该任务源数据下载权限。运行中的任务不得下载待处理清单。
6. 新前端只调用后台任务提交接口；原 `/admin/supplier-profiles/import` 同步接口保留给旧客户端。部署须先上线后端及生成权限清单，再上线前端。回滚前须停止并核对未完成的供应商导入任务，禁止遗留任务由不支持该类型的执行器承担。

已关联到采购／供给能力的合同须至少有一份日期已核实且处于有效期内，否则阻止该能力用于新业务。无已关联合同的供应商维持现有临时放行政策，不自动新增必备合同约束。非合同资质继续要求起始日期，截止日期为空仍表示长期有效。

## 4. 自然周期及付款日期

| 结算方式 | 周期边界 |
| --- | --- |
| 周结 | 周一至周日 |
| 月结 | 自然月首日至月末 |
| 季结 | 1–3、4–6、7–9、10–12 月 |
| 半年结 | 1–6、7–12 月 |
| 年结 | 1 月 1 日至 12 月 31 日 |

采购计划付款日取本单最晚预计交付日所属自然周期末，再加供应商配置的付款天数。导入默认期末后 15 个自然日，维护页面可设置为 0–366 天。不得因自然周期自动拆分采购单或归并付款单。

现结和预付款沿用现有审批日规则。既有 `POSTPAY_NET15`、`POSTPAY_NET30` 继续按预计交付日后 15／30 天计算；历史版本不得批量改为月结。新建资料提供周结、月结、季结、半年结和年结；编辑历史货到后付资料可保留原规则。

## 5. 发票税额分配

一张采购发票只核销一笔应付时，使用整票税额。核销多笔应付时，逐笔填写分配税额，按“分配含税金额 − 分配税额”计算净额。每笔税额须在零与该笔含税金额之间，分配税额合计须等于整票税额，含税合计仍按既有核销约束校验。不得向每个核销目标重复写入整票净额和税额。

## 6. 发布、迁移与回滚

### 6.1 发布准备

1. 备份目标数据库，暂停主体、供应商及关联业务写入。明确备份标识、操作人及恢复窗口。
2. 使用 `backend/scripts/migrations/20260910-supplier-companies.mongosh.js`。默认 `check` 只读；数据库连接使用运维环境变量，禁止写入文档或日志。
3. 在独立 JSON 文件登记已批准的现有我方主体，格式为 `[{"party_id":"既有主体 ID","aliases":["已核实的表内简称"]}]`。使用 `ERP_COMPANY_MAPPING_FILE` 指向该文件。空库可使用空数组；不得自动补出真实公司全称。
4. 执行检查：

```sh
ERP_COMPANY_MIGRATION_MODE=check mongosh "$ERP_MONGO_URI" --file backend/scripts/migrations/20260910-supplier-companies.mongosh.js
```

5. 检查必须满足：公司匹配键无重复、映射主体均为有效企业且有当前名称修订、所有现有供应商当前签约及付款主体均完成公司身份登记。存在缺口时修正映射后重新检查。

### 6.2 执行迁移

```sh
ERP_COMPANY_MIGRATION_MODE=apply ERP_MIGRATION_ACTOR="实际操作人" mongosh "$ERP_MONGO_URI" --file backend/scripts/migrations/20260910-supplier-companies.mongosh.js
```

脚本登记公司角色及名称匹配键，创建 `uk_company_names`、`idx_company_status` 及按能力查询合同的 `idx_supplier_capability_qualifications`；公司角色写入与备份在同一事务内完成。备份集合为 `migration_20260910_supplier_companies`。脚本不改写存量税率、结算方式、合同日期或采购快照；新程序直接兼容历史单税率字段及合同起始日期字符串。已有合同缺少任一日期时按未核实状态参与新业务校验，历史单据保持原记录。

先部署后端和生成的权限清单，再部署前端。为使用人员分配公司查询／详情权限；维护人员另需创建／更新权限；导入沿用供应商创建权限。放开写入前检查公司列表、主体选择和导入失败反馈。新旧程序不得同时承担供应商写入。

### 6.3 回滚条件

停止新版写入后执行 `ERP_COMPANY_MIGRATION_MODE=rollback`，并设置操作人。自动回滚仅适用于尚未写入新周期结算、空／多税率商务版本、未知起始日合同及其修订、未新增公司且已迁移公司未继续修改的窗口。脚本发现不满足条件即拒绝覆盖，保留备份记录。

满足条件时，脚本撤销本次登记的公司角色并移除新增索引，保留主体身份和原业务资料，版本号继续递增。若已经产生旧程序无法读取的新业务数据，须按发布前备份执行完整恢复；不得截取多税率中的第一项、补零税率或改写周期条件来强行回退。

## 7. 验收边界

单元测试、静态检查和模拟接口页面核对分别记录。模拟界面检查不得作为真实入库、MongoDB 唯一索引竞争或事务回滚的验收证据。正式验收须在批准的数据库环境核对：完整行成功、缺失行零写入、重复重试零新增、公司别名冲突、自然周期计划付款日以及多笔发票分配合计。

## 8. 开发种子准备

开发环境使用 `scripts/prepare-dev.sh` 统一清理并恢复开单基础资料。该命令会清理业务数据和目录主数据；执行须显式设置 `E2E_RESET=1`，远程开发库另须设置 `E2E_ALLOW_REMOTE_RESET=1`。不得将其用于保留现有业务数据的结构迁移。

1. 种子通过 `/admin/companies` 登记示例公司“北京福尚云科技有限公司”，简称“福尚云”，导入别名“福尚云开发示例”。不得推断“朱太帅”“科技”对应的真实主体。
2. 采购岗位拥有公司查询和详情权限；系统管理员另有创建及更新权限。启动时补齐预定义角色缺失权限，保留已有额外授权。种子须用采购和系统管理员账号核对公司列表、别名选择与详情读取。
3. 正常开单供应商具有日期完整、当前有效且关联适用能力的开发合同；狮峰茶叶的常用进项税率为 9% 和 13%，两项茶叶 SKU 分别按 9% 和 13% 登记供给。销售税率维持既有规则。
4. 周期样例覆盖周结期末后 0 天、月结 15 天、季结 27 天、半年结 15 天、年结 366 天；另保留预付款及现结样例。附加周期供应商为同一茶叶 SKU 提供可供选择，用于验证采购付款日期。
5. `SUP-DEV-UNVERIFIED` 为合同起始日未核实样例，`SUP-DEV-EXPIRED` 为合同已到期样例。两者只建档，不生成供给；补齐有效合同后才可用于后续供给登记。
6. 重复运行目录种子时，按稳定编号复用公司、供应商与供给，并核对当前商务字段、合同、适用能力和供给税率。旧普通主体未登记公司角色、资料被修改或合同过期时必须报错，不得覆盖业务资料或重复创建身份。仅缺少种子公司别名时允许追加，保留其他别名。
7. 种子 Node 单元测试与 Rust 请求、领域单元测试共同使用 `scripts/fixtures/dev-supplier-profiles.json`。固定日期夹具须与实际请求构造器一致；修改构造器后必须同步夹具并通过双方校验。测试不得连接真实数据库。
