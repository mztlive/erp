# 财务责任规则与负责人池合同

## 1. 配置与匹配

1. 财务责任规则由业务操作、匹配范围、负责人池、分配策略和启停状态组成。供应商付款使用 `SUPPLIER_PAYMENT`，销项开票使用 `SALES_INVOICE`。
2. 每项业务优先匹配启用的指定往来方规则；未命中时使用该业务唯一启用的默认规则。同一业务、同一匹配条件只允许一个启用池。新增成员必须编辑已有池，不得新增同条件启用规则。
3. `owner_user_ids` 保存 1 至 100 个后台账号，数组顺序为分配顺序。保存时去除账号首尾空白；空账号、超长账号、重复成员和空池必须拒绝。付款和开票分别核验成员的完整执行权限及账号可用性。
4. `strategy` 只接受 `ROUND_ROBIN`。未知策略和未知请求字段必须拒绝，不得静默降级。
5. 保存、启用规则及修改池成员时必须核验全池资格。停用未改变成员的规则允许保留失效人员，便于管理员停用问题配置。候选刷新必须保留表单、已选成员及顺序，失效候选须明确标记。
6. 配置变更只影响之后新建的任务，不改写既有任务负责人、责任键或历史参与记录。

## 2. 分配与事务

1. 每个规则池独立保存最近成功分派的成员。首次取首人；之后取当前名单中最近成员的下一人，末位后回到首人。最近成员已移除时从首人开始。重排后按新名单定位，服务重启不得清空位置。
2. 财务任务每次新建占用其命中池的一次轮次。付款申请批准、付款冲正后新建任务、销项开票任务和复用财务责任规则的退货财务任务均适用。继续办理已有任务、手动转派、列表读取和保存配置不占轮次。
3. 轮次推进与任务创建必须使用调用方同一事务。后续权限检查、任务创建或业务写入失败时，轮次必须一起回滚。命令回执重放和已存在任务的复用不得再次调用分配入口。
4. 轮到的人员失效或缺少当前任务所需权限时拒绝整个分派，提示维护财务责任配置；不得跳过人员。退货财务任务另行核验退货退款或红票执行权限。
5. `finance_dispatch_rotation` 以规则 ID 为 `_id`，保存 `last_owner_user_id` 和 `revision`。规则维护更新并发版本并保留位置。首次并发插入或版本竞争统一作为冲突处理，调用方须重试整个原命令；提交结果未知时沿用命令回执恢复。
6. 财务与采购共用池成员校验、分配策略及轮次版本比较机制。领域分别拥有匹配规则、资格校验与轮次集合，禁止互相依赖或共享实际轮次位置。

## 3. 接口与界面

1. 创建 `POST /admin/finance-responsibility-rules` 和整项更新 `PUT /admin/finance-responsibility-rules/{id}` 接收 `operation`、`scope`、`counterparty_id`、`owner_user_ids`、`strategy`、`status`；更新额外要求 `version`。
2. 停止接收旧的单人字段 `owner_user_id`。列表和保存响应返回 `owner_user_ids`、同序的 `owner_names` 和 `strategy`；缺失姓名保留对应位置的 `null`，不得缩短姓名数组。
3. 管理页面使用与采购共用的负责人池及分配方式控件。成员可多选，选择顺序决定轮询顺序；需要重排时移除后重新选择。列表显示完整成员名单和“轮询”。
4. 空池、重复成员及其他配置形状错误返回业务校验错误；同条件重复启用和并发更新返回冲突，沿用统一错误信封和请求编号。负责人失效或缺少执行权限必须返回具体原因，不得以空结果代替错误。

## 4. 发布、迁移与回滚

1. 发布前停止旧版写入，备份 `finance_responsibility_rules` 与 `finance_dispatch_rotation`。前后端同批发布，禁止新旧接口字段混用。
2. 新版启动在创建财务责任索引前将旧 `owner_user_id` 转为单元素 `owner_user_ids`，填充缺失的 `ROUND_ROBIN` 策略，再移除旧单人字段。已有池和策略保持原值；迁移中断后可以重复执行。启用规则的唯一性约束保持不变。
3. 增加池成员索引 `idx_finance_responsibility_pool_owner`；保留旧单人索引以便备份恢复后回滚。新轮次集合使用 MongoDB 自带 `_id` 唯一索引，无需预先创建轮次记录。
4. 独立迁移入口为 `scripts/migrate-finance-responsibility-pools.js`，须在停写与备份后连接目标库执行。启动自动迁移成功后无需重复手工执行。
5. 回滚须停止新版写入，恢复发布前规则和轮次集合，再切换旧前后端。上线后新增或变更的池须另行登记并人工转换，不得任意将多成员池压成单人；已经创建的业务任务不得随配置回滚删除。
6. 发布验收须覆盖真实数据库迁移重入、同池并发、任务失败回滚和重放不占轮次。库单元测试与静态构建不能替代上述验收，未执行项目必须在交付记录中列明。
