# 费用采购入口与权限拒绝响应合同

## 1. 操作入口

1. 采购单列表页头提供“新建费用采购单”；具有 `purchase_order:create` 的账号可使用。
2. 创建时先选择归属销售单，再选择供应商、付款条件并填写费用行。提交即发起采购审批，成功后打开新建采购单。
3. 采购单详情提供“追加费用”，预填来源销售单和当前供应商；供应商允许修改。新费用形成独立采购单。
4. 销售单详情的“追加附加费用”保留。采购类型筛选包含“费用”，列表数量、分页与导出均按已生效的类型条件查询。

## 2. 来源查询与写入校验

| 请求 | 功能权限 | 返回内容 |
| --- | --- | --- |
| `GET /admin/purchase-orders/expense-sources` | `purchase_order:create` | 来源销售单号、客户名称、状态与分页 |
| `GET /admin/purchase-orders/expense-sources/{id}` | `purchase_order:create` | 来源摘要及可归属费用的当前销售明细 |
| `POST /admin/sales-orders/{id}/expense-purchases` | `purchase_order:create`；提交阶段重验既有采购提交资格 | 创建并提交采购审批 |

1. 来源查询读取当前账号配置的 `sales_order:detail` 人员范围；不要求 `sales_order:list`、`sales_order:detail` 功能权限，不授予完整销售详情访问权。
2. 候选限定为已生效、未作废的实物与服务销售单，包含已关闭销售单。历史参与事实不单独授予费用建单资格。
3. 列表使用 `q` 搜索，最多 100 字；`page` 从 1 起，每页 20 条。第二页起须携带前页 `scope_version`；范围变化返回 `DATA_SCOPE_CHANGED`，调用方返回第一页重新查询。
4. 无来源范围时返回空集合及 `empty_reason: no_scope`，不得回退全公司范围。范围外和不存在的单据保持同一拒绝语义。
5. 来源明细仅返回当前生效版本中数量大于零的实物服务明细身份及名称；不得通过此入口读取价格、合同和审批材料。
6. 创建必须在原事务内重新校验操作人、来源范围、来源状态、明细归属及既有供应商结算和审批规则；候选查询成功不构成长期授权。
7. 费用发生确认、应付、付款及实际盈亏继续执行既有规则。询价来源扩展按第 4 节执行；无询价来源的历史单据按原流程读取。

## 4. 已接受询价费用

1. 创建费用行可携带 `inquiry_source`，字段为 `inquiry_id`、`feedback_round`、`fee_id`、`allocation_id`。该引用不扩大费用来源销售的数据范围；提交仍须通过本合同第 2 节全部资格。
2. 服务器必须在同一事务核对已接受反馈、关联销售、已确认费用、未含商品价、ERP 付款要求、有效条件、预先明确的分摊金额以及跨轮次剩余额度，并生成来源占用。客户端不得通过填写引用宣称拥有可转额度。
3. 收款供应商、付款条件及付款主体分别核验，结算条件不同须分别建单。每张费用采购仍为 1–50 行，创建即提交审批。
4. 来源引用随草稿、提交、生效版本及正式变更保留；不能通过编辑删除或更换引用。撤回、驳回继续占用；作废或正式减少仅释放未办理部分。已发生、已付款和财务已登记的事实继续占用。
5. 财务办理 ERP 外费用时必须关联同一稳定询价费用及分摊，登记即记已办理额度，不再生成费用采购或应付。财务冲减不得自动恢复采购额度。
6. 来源字段为可选新增字段；既有无来源费用不得被伪造为询价费用。迁移和回退按[询价接口与存储合同](sales-inquiry-api-contract.md)执行。

## 3. 权限拒绝响应

1. 缺少明确功能权限时保持 HTTP 403、`code: PERMISSION_DENIED`、`success: false`，新增可选字符串字段 `requiredPermission`，值为实际被拒绝的 `resource:action`。
2. 路由鉴权拒绝须返回实际校验的权限；应用授权层明确报告单项缺权时，HTTP 边界须保留该权限。数据范围、单据资格、账号失效及同角色组合要求不满足，不得猜测为缺少某个功能权限。
3. 界面须显示权限中文名称、权限码及处理方式，例如“缺少「查询销售单列表」权限（sales_order:list），请联系管理员授权后重试”。未识别中文名称时仍显示权限码。
4. 授权服务异常返回系统错误，不得误报缺权；未登录保持 401。请求编号和既有错误码继续保留。
5. 新字段为向后兼容扩展：旧界面可继续读取 `errorMessage`；新界面收到无该字段的旧响应时沿用既有错误说明。回滚时可同时撤回本次入口与响应扩展，不修改人员权限或业务单据。
