## 1. 使用要求

1. 业务与验收执行 [批量选品入库执行合同](../../supplier-api-batch-adoption-contract.md)。本目录图片为设计效果图，非现有系统截图，非实现或运行验收证据。
2. 全部七个页面及各关键状态图、对应交互获得用户明确确认后，方可开始编码。逐页确认有效；不得由一张图的确认推定其他页面已经确认。
3. 修改图稿生成新版本并重新登记确认，不覆盖已确认基线。修订必须同步本清单及合同中受影响条款。
4. 生成方式为内置 imagegen；完整生成提示记录在 `prompts.md`。设计依据为当前 `erp-client/AGENTS.md`、`docs/erp-ui-design.md`、`erp-client/app/globals.css` 和商品库、选品组件源码。
5. 未使用浏览器或电脑控制，未取得当前页面截图。效果图依照源码主题与布局规范设计，不声明与当前实机页面逐像素一致。

## 3. 统一视觉规格

1. 基准画布 1440 × 1024，桌面 ERP 工作区。中性灰白画布、白色内容面、石墨黑主操作，绿色完成、琥珀色待处理、红色失败。仅状态使用强调色。
2. 中文无衬线字体，标题约 26px，正文与输入 14px，辅助文字 12px。信息优先使用留白、对齐及细分隔线分组，不堆叠装饰卡片。
3. 全局顶部栏 48px，展开导航约 240px；页面横向留白 24—32px，表头约 44px，双行商品数据行约 64px，控件约 36px。
4. 同一批次只开一个工作区标签；顶端为供应商身份与步骤，底端为持久操作区。单项编辑使用居中 Dialog；只读轻预览继续使用现有 Sheet。
5. 图中数量、金额、日期均为设计示例。示例供应商“华选供应链”，并非当前接入能力或真实业务记录声明。日期锚点为 2026-10-27。

## 4. 示例数据合同

1. P01 筛选命中 240 个 SKU，排除 4 个，最终选择 236 个，涉及 180 个来源商品。
2. P04 的 236 个 SKU 分为：216 个可入库、12 个待补、8 个已完成跳过。216 个就绪项中 180 个新建 SKU、16 个已有商品新增规格、20 个关联已有 SKU；180 是 SKU 数，不能标为新建商品数。
3. P06 执行 216 个后：成功 210、明确失败 4、结果待核实 2；另保留未提交待补 12、已完成跳过 8。五组总和为 236。待处理共 18 = 4 + 2 + 12。
4. P07 从待处理 18 项中展示：待补 12、失败 4、待核实 2；示例选择已修正的 3 项重新核对。待核实项不能直接重试。
5. 价格示例：五常大米 5kg，接口报价 100.00，规则 +15%，公司代发 115.00，公司集采 115.00，公司集采起订量 10。公司售价规则不改变供应商集采能力。
6. 其他示例：葵花籽油 5L，80.00 → 92.00；小麦粉 5kg，40.00 → 46.00；香米 5kg，60.00 → 69.00。人工例外为五常大米代发 118.00、集采 115.00。
7. P03 来源分类计数为大米 132、食用油 92、面粉杂粮 12，合计 236；其中面粉杂粮 12 个 SKU 的公司分类待补。
8. 公司集采门槛使用各 SKU 的公司基础单位：大米和香米为袋、葵花籽油为桶、食用油礼盒为盒。P02 不提供批量换单位控件。P05 来源已明确为袋时，公司单位只读。
9. P07 的待核实商品使用“花生油礼盒 1.8L×2”，与 P06 已成功的“食用油礼盒 2L×2”区分，不得将同一来源 SKU 同时标为成功与待核实。

## 5. 页面交互核对要点

| 页面 | 确认重点 |
| --- | --- |
| P01 | 分类品牌是否易筛选；是否区分选当前页、全部结果和排除项；配置入库入口是否清楚 |
| P02 | 两价同价时一套规则；分别设置时两行规则；更多设置折叠；执行 [P02 简化交互合同](P02-v4-interaction.md) |
| P03 | 分类映射是否直观；统一字段与逐类映射是否分开；已有公司商品资料保留是否清楚 |
| P04 | 能否在提交前判断建什么、关联什么、价格是什么、哪些项会跳过或待补 |
| P05 | 单项例外是否易修改和识别；不能编辑来源成本；能否恢复批量规则 |
| P06 | 部分完成是否被如实表达；五类结果是否清楚；成功商品与待处理入口是否明确 |
| P07 | 哪些能修正重试、哪些必须先查结果；处理后是否先重新核对而非直接写入 |
