# P04 核对入库紧凑交互合同

版本：V2。实施授权：2026-10-29 用户同意按单页审查建议直接修改。状态：待实际页面视觉与交互验收。

## 1. 信息布局

1. 标题行展示供应商、商品数与 SKU 数；保留紧凑四步进度。返回商品库入口位于页头，继续执行未保存修改提示。
2. 核对摘要使用紧凑横排，突出可入库数量及非零异常数量；不为零值单独占位。新建 SKU、新增规格、关联已有 SKU 的非零数量并入摘要。
3. 草稿恢复或修改后，主状态为“待重新核对”，已有结果明确标记为“上次核对结果”。未执行的 READY 行显示“待重新核对”，不得暗示可直接提交。
4. 无异常且状态单一时收起无效筛选；存在原因或已生效筛选时保留对应控件与重置入口。列设置继续位于表格工具栏最右侧。

## 2. 明细与说明

1. 核对表以规格为主文字、商品名为次文字；公司售价突出于接口采购报价。来源变化、人工修改、价格提示、单位推断及待处理原因保持可见。
2. 供应商供货能力与公司销售价格分开表达。全批仅代发时集中显示“供应商供货：仅代发”；混合供货能力时逐行标明“供货：仅代发”。不得据此隐藏公司集采价或改变采购能力。
3. 核对页不展示“入库规则”入口及新建 SKU 未上架、关联已有 SKU 保留原资料与价格的固定说明；对应业务行为保持有效。

## 3. 操作与验收

1. 底部保留保存状态、已选数量、非零异常数量、保存草稿、上一步及核对或提交操作。
2. 未完成当前核对时突出“重新核对”，确认入库继续禁用；完成核对后突出“确认入库 N 个 SKU”。权限、处理中、结果待核实和零选择等提交限制保持有效。
3. 核查恢复草稿、修改后失效、核对完成、异常混合、全异常、结果待核实、筛选清空、列显隐、窄窗口和返回提示。静态检查不得登记为视觉或交互验收。
