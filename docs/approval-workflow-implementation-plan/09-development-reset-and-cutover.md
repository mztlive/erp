# 阶段 09：开发环境重置与硬切换

> 阶段性质：P5 开发环境切换工作包
>
> 阶段目标：在项目尚未产生需要保留的业务数据的前提下，清空旧审批业务数据，删除旧模型入口，并以空库状态启用新运行时
>
> 数据合同：不迁移旧定义、旧实例、旧步骤、旧审批任务或旧业务单据；不建设 legacy history、迁移收据、checkpoint、双写或旧运行时回退

## 1. 文件责任

本阶段只负责：

- `backend/scripts/reset-dev-business-data.sh`（执行入口）；
- `backend/scripts/reset-dev-business-data.mongosh.js`；
- `backend/scripts/reset-dev-business-data.md`；
- `backend/scripts/test-reset-dev-business-data.sh`；
- 新旧审批集合、审批 WorkItem 和索引的开发重置 allowlist；
- preview/execute/verify 证据。

`docs/runbooks/approval-workflow.md` 归 **DOC-D**，不由本阶段创建；本阶段只提供该 runbook 需要引用的脚本参数、集合清单和验证输出格式。

本阶段不得新增迁移应用、人员映射、旧历史实体、旧模型 Repository 或兼容读取 API。生产代码不得因为开发环境清理而保留旧审批类型。

## 2. 数据前提

执行硬切换前必须由项目负责人确认：

1. 当前环境是开发环境；
2. 不存在必须保留的业务单据、审批实例、审批任务或审批审计；
3. 账号、RBAC、组织、主数据、对象存储和系统配置仍按现有重置脚本保护合同保留；
4. 目标数据库、主机和数据库名已经通过现有安全门禁；
5. reset preview 已列出准确集合和预计删除数量。

任一条件不成立时禁止执行本阶段，也不得临时恢复迁移方案。需要保留数据时必须另行建立新的数据治理合同。

## 3. 重置范围

开发业务数据重置必须覆盖：

- 旧审批定义、步骤定义、实例和步骤实例集合；
- 新 BPM 定义、节点、连线、实例、节点执行、实例审批人和命令收据集合；
- 审批业务对象快照和通知 outbox；
- `work_items` 中旧卡券审批类型、带 `approval_step_instance_id` 的任务、`DocumentApproval` 任务和带 `approval_node_execution_id` 的任务；
- 依赖被删除审批实例的业务单据和关联业务数据；
- 旧审批索引和与目标合同冲突的部分唯一索引。

不得只删除审批实例而保留引用它们的业务单据或 WorkItem。脚本必须继续保护账号、RBAC、组织、供应商/商品主数据、`source_systems`、`file_assets`、对象存储、审计记录和计数器；保护范围变化必须单独审批。

## 4. 脚本安全合同

重置入口继续使用 `backend/scripts/reset-dev-business-data.sh`。执行规则固定为：

1. 先运行 preview，输出目标主机、数据库名、集合 allowlist 和预计删除数量；
2. 完整连接串、Token、密码和证书不得出现在日志、报告或进程参数回显；
3. 本地开发库执行必须显式传入 `--execute --confirm-db <database>`；
4. 远程开发库还必须显式传入 `--allow-remote`，并由 `ERP_RESET_ALLOWED_REMOTE_HOSTS` 精确允许主机；
5. 系统库、未确认数据库和 allowlist 外集合必须失败关闭；
6. 脚本不得调用 `dropDatabase()`，只能按固定集合和固定过滤条件删除；
7. preview 与 execute 的目标或集合摘要不一致时必须拒绝执行；
8. 实际执行前必须由用户对 preview 的准确目标和范围作出明确确认。

## 5. 演练与硬切换顺序

本方案**不设置**全局审批运行开关。按合同 §17.2，启用边界由数据事实天然表达：某 `PROCESS_REQUIRED` 类型不存在已发布定义时，该类型单据创建失败关闭并返回 `APPROVAL_PROCESS_NOT_CONFIGURED`；管理员发布定义即该类型实质启用。因此不得新增运行模式配置项、不得引入 `DISABLED`/`ENABLED` 状态，也不得据此建立第二条运行路径。

P5 只交付脚本、测试和 runbook，不得自行删除开发环境数据。P6-PILOT 必须在专用空数据库中执行一次试点演练；演练只创建试点定义，不得触碰共享开发环境。P6-FINAL 在全部目标 DocumentType 完成 P3/P4 和启用前验收项后，必须对共享开发环境执行下列硬切换：

1. 停止 Web API、前端开发服务、通知 worker 和所有可能写业务数据的进程；
2. 运行 reset preview 并保存脱敏报告；
3. 取得准确目标和范围的明确确认后运行 reset execute；
4. 运行 reset verify，证明旧审批集合、旧审批 WorkItem 和业务数据均为空；
5. 部署只包含新审批模型的新后端和前端。此时全部 12 个 `PROCESS_REQUIRED` 类型尚无已发布定义，其创建自动失败关闭，等效于未启用；
6. 创建并验证全部新索引；任一索引失败时不得继续发布定义；
7. 运行 readiness、权限种子、边界扫描和全仓旧符号清零检查；
8. 执行 P6-FINAL 全部启用前门禁，证明索引、readiness、政策、权限和空数据不变式全部通过；
9. 由流程管理员先为唯一试点 `StockAdjustment` 创建并发布定义，完成创建、绑定、提交、决定、恢复、改派、取消和通知冒烟；
10. 试点冒烟通过后，逐个为其余 11 个 `PROCESS_REQUIRED` 类型发布定义并完成同一组冒烟。任一类型失败时，只退役该类型的已发布定义以停止其新单据进入审批，不影响已通过的类型；
11. 全量冒烟通过后完成 P6-FINAL，恢复其他开发服务并保存切换证明。

逐类型发布是唯一的启用粒度，这比全局开关更安全：单个类型失败不需要让全部类型停摆。不得启用旧新双写，不得启动旧审批 runtime，不得在新代码中读取旧集合。

## 6. 回退合同

硬切换后不支持回退到旧审批模型。出现阻断时必须：

1. 立即退役受影响 `DocumentType` 的已发布定义，使其新单据创建失败关闭；必要时退役全部已发布定义；
2. 停止产生新审批和业务数据；
3. 保留日志、correlation ID、索引和失败证据；
4. 修复代码或合同并前向部署；
5. 若需要重新开始，按本阶段安全合同再次重置开发业务数据；
6. 重新完成索引、readiness 和 P6-FINAL 全部启用前门禁后才能重新发布定义；重新发布后必须重做试点与全量冒烟。

退役只阻止新单据绑定，不影响已运行实例。若必须同时终止在途实例，只能通过合同 §12.5 受阻取消或 §12.1 业务撤回逐单处理，不得直接改库。

不得恢复旧二进制继续写入，不得重新建立旧索引，不得把新数据改写成旧结构。

## 7. 验证合同

`reset verify` 和阶段 11 必须共同证明：

- 旧审批集合为空且新代码无任何读取或写入入口；
- `work_items` 中不存在旧卡券审批类型或 `approval_step_instance_id`；
- 新运行集合在启用前为空，启用后只产生目标模型；
- 每个新实例恰有一个业务对象快照；
- 每个 ACTIVE 执行恰有一个 OPEN `DocumentApproval` WorkItem；
- BLOCKED 执行没有 OPEN WorkItem；
- 账号、RBAC、组织、主数据、对象存储和受保护审计未被删除；
- 旧符号扫描除重置脚本的删除条件外零命中。

## 8. 完成条件

- [ ] 文档只保留“无数据搬运”的边界声明，不包含数据搬运步骤、旧历史投影、双写、旧实例取消重提或兼容读取方案。
- [ ] reset preview/execute/verify 使用同一目标和集合摘要。
- [ ] 删除范围已显式确认，脚本未使用 `dropDatabase()`。
- [ ] 旧审批业务数据和旧审批 WorkItem 已清零。
- [ ] 新索引创建成功，readiness 和旧符号扫描通过。
- [ ] P6-PILOT 已在专用空数据库完成试点演练，且未触碰共享开发环境。
- [ ] 共享开发环境只在 P6-FINAL 启用前门禁通过后逐类型发布定义；全量冒烟通过才能完成 P6-FINAL。
- [ ] 不存在全局审批运行开关或运行模式配置项；启用粒度只有「该类型是否有已发布定义」。
- [ ] 回退只允许退役定义、停写、前向修复和必要时重新重置，不恢复旧运行时。
