# 发起人审批进展提醒合同

## 1. 计数与消除规则

- “我发起的审批”导航徽标只表示当前账号发起、尚有未读进展的审批单数。零条时隐藏徽标。
- 列表总数、分类数量和历史记录继续按列表查询条件统计，不使用未读数替代。
- 他人推进、通过、驳回、触发受阻、恢复或取消审批时，标记该实例为未读。同一实例多次变化只计一条。
- 本人提交、办理、恢复或撤回不生成新的个人提醒，也不自动清除此前尚未查看的他人进展。
- 打开审批进度并成功展示最新记录后，客户端显式确认展示版本。仅打开菜单、读取列表、预取或停留在后台标签页不得确认已读。
- 旧版本确认不得清除更新版本的提醒；重复确认无副作用。已读确认不得改变审批实例版本、状态、任务或审计时间。

## 2. 存储合同

集合为 `approval_process_instances`，追加以下可选字段：

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `initiator_progress_version` | BSON Int64 | 最近一次他人操作提交后的实例版本 |
| `initiator_unread` | Boolean | 最近他人进展是否尚未查看；缺失按 false 处理 |

提醒字段必须随审批实例 CAS 在原事务内写入；事务失败不得留下提醒。本人操作不得覆盖已有提醒字段。所有实例推进入口必须传递实际操作人。

确认已读须先在同一事务内检查有效账号、`approval_instance:read` 权限、实例发起人和版本范围，再按以下条件更新：

1. 实例 ID 和 `started_by` 均匹配当前账号。
2. 实例未软删除且 `initiator_unread = true`。
3. `initiator_progress_version <= observed_instance_version`。
4. 只写入 `initiator_unread = false`。

计数索引固定为 `idx_approval_process_instances_started_unread`，键为 `{ started_by: 1, initiator_unread: 1, deleted_at: 1 }`。

## 3. HTTP 合同

以下路径均位于 `/admin`，复用 `approval_instance:read`，账号仅来自认证上下文。

| 请求 | 入参 | 成功响应 data |
| --- | --- | --- |
| `GET /approval-instances/started-unread-count` | 无 | `{ "unread_count": 2 }` |
| `POST /approval-instances/{id}/progress-read` | `{ "observed_instance_version": "4" }` | `null` |

`GET /approval-instances/{id}/history` 在请求者为发起人，且本页包含最新记录时，追加 `observed_instance_version` 十进制字符串。倒序首页或正序最后一页满足此条件。其他读取者和不完整的旧记录页不提供确认版本。

已读确认请求拒绝额外字段、空版本、非正整数字符串及超出范围的版本。协议错误、未来或不可持久化版本返回 400，无权或实例缺失返回 404；基础设施错误沿用审批错误目录。旧版本和重复确认返回成功，不清除新进展。

## 4. 发布、历史数据与回滚

1. 发布前运行 `backend/scripts/migrations/20261104-approval-progress-index.mongosh.js` 检查索引；设置 `APPLY_APPROVAL_PROGRESS_INDEX=1` 后执行创建。服务启动索引登记须与脚本一致。
2. 发布后端，再发布前端。新前端依赖新增计数和确认接口；接口失败时不得退回历史总数冒充未读数。
3. 历史实例不补未读标记、不批量重写。发布后第一次他人进展才生成提醒。历史审批记录保持可查。
4. 回滚时先回滚前端，再回滚后端；保留新增可选字段及索引，旧代码可忽略它们。不得通过删除实例或执行历史回滚此功能。
5. 如需删除索引，在全部服务均已回滚后只删除上述命名索引。停用期间的进展不补发；重新启用后从后续进展继续提醒。

## 5. 验收要求

- 发起一单后未读数不增加；他人多次办理该单后只增加一条。
- 查看该单最新进展后计数减少；有更新后再次增加。
- 展示版本 4 后发生版本 5，再确认版本 4，版本 5 仍须未读。
- 本人操作不新增提醒；其他账号不得确认发起人的提醒。
- 未读为零时菜单不显示数字，列表仍展示全部符合条件的记录。
- 刷新页面及同账号跨设备查看使用相同服务端已读状态；导航在确认成功后立即刷新，其他页面按现有 60 秒轮询更新。
