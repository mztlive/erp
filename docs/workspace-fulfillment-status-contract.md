# 工作台履约行付款状态合同

## 返回字段

1. 工作项列表及单项详情的 `WorkItemView` 增加可选字段 `fulfillment_status`。适用范围为已授权、开放且仍匹配草稿版本的发货、电子交付和服务履约任务。
2. `fulfillment_status` 必须包含以下字段；不得在列表中附带付款申请、银行资料、回单或完整来源单据。

| 字段 | 取值 | 含义 |
| --- | --- | --- |
| `payment_state` | `UNPAID`、`PARTIAL`、`PAID`、`NOT_REQUIRED`、`null` | 采购整单未付款、部分付款、已付清、无需付款、付款事实缺失或不适用 |
| `gate_state` | `SATISFIED`、`BLOCKED`、`NOT_APPLICABLE` | 付款放行条件满足、未满足、按约定无需预付 |

3. 付款进度必须使用采购应付子账的 `settled_total` 和 `open_total`，与履约付款详情保持一致。不得使用付款申请审批状态替代实际付款。
4. 放行条件必须复用履约队列现有计算：采购冻结付款条件、最低金额与比例门槛、有效付款核销净额及相同舍入规则。仓库自有库存发货沿用现有不受供应商付款门槛限制的规则。
5. 部分付款达到先款门槛，或后付条件允许先履约时，可以显示“可发货”；其他任务阻断仍优先显示“暂不可发货”。正式提交继续执行原有服务端校验。

## 读取与展示

1. 后端须在对象授权及分页完成后，以当前页任务 ID 集合执行一次批量聚合；列表、付款事实和放行状态共用原读取事务。无适用任务时不得新增数据库查询。
2. 聚合须核验任务与履约草稿的对象身份、版本、责任岗位、原因和责任组织。不得扫描全部履约队列后在前端关联，不得逐项调用详情接口。
3. 前端行组件只能消费列表字段，不得额外请求付款摘要或履约队列。状态随工作台列表的刷新和轮询更新。
4. 付款事实缺失时显示“付款状态待核对”；摘要缺失时显示“发货条件待核对”或“履约条件待核对”，不得推断可发货。聚合读取失败须沿列表错误处理，不得伪造成功状态。

## 发布与验证

1. 本变更只增加响应字段，不写业务数据，不新增集合或索引，无数据迁移。前后端须一同发布；旧后端缺少字段时新前端显示待核对。
2. 单元验证覆盖付款进度、部分付款已放行、未付款后付、缺失事实、未知放行码和响应序列化。前端执行格式、lint、类型检查和构建。
3. 库单元测试与编译不替代真实 MongoDB 聚合及页面验收；实际发货资格以提交时校验为准。
