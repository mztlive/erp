# 管理端工作页签合同

## 1. 适用范围

- 管理端 `app/(workspace)` 使用全局工作页签；登录页、供应商门户和客户选品页沿用各自入口。
- 页签状态保留仅覆盖当前浏览器页面会话。浏览器刷新、关闭或退出登录后，内存中的页面实例释放；跨刷新草稿恢复由各业务已有草稿机制负责。

## 2. 打开与切换

- 左侧菜单打开工作页签；已打开的入口激活已有页签并保留其筛选、分页、滚动及编辑状态。
- 不同单据路径独立成页签。同一路径的筛选、分页、详情分区变化保留在当前页签内。
- `mode=create`、`action=create`、`create=1` 和 `/new` 创建入口与列表独立。创建来源参数参与页签身份，防止不同来源覆盖同一草稿。
- 单据标题使用业务页标题；使用 `DetailPageHeader.documentNumber` 的页面追加业务单号，不追加内部 ID。
- 页签内的共享详情页头 `DetailPageHeader` 不显示返回按钮；没有来源说明时，导航行及其占用间距一并收起。标题、状态、来源说明及业务操作保留；页面切换通过全局页签完成。非页签场景沿用原有返回入口。
- 页签栏使用全局顶部栏高度、白色内容表面及淡底部分隔线，与列表内容复用横向留白令牌。页签不设置卡片外框或顶部强调线；选中态使用适度字重和底部指示线，指示线随图标及标题区域宽度伸缩，不覆盖关闭按钮，不使用仅落在图标下的固定短线。图标沿用对应导航入口。列表页头上方间距统一使用 `workspace-block-start-lg` 令牌，桌面为 20px。
- 仅溢出时显示滚动按钮。右侧显示已打开页面数量并提供页面切换列表；隐藏的关闭按钮在鼠标悬停、键盘聚焦或触屏环境中必须可见。
- 页面内普通工作区链接与 `router.push` 打开目标页签；`router.replace` 跨页跳转替换来源页签，用于保存完成、入口兼容重定向等场景。
- 后台页面异步完成跳转时不得抢占当前活动页签。
- 同页筛选、分页和分区参数更新使用替换历史；页签切换写入顶层浏览器历史。工作台打开任务、审批及抄送详情时新增历史记录；浏览器后退恢复来源队列页签及其筛选、分页、滚动位置，前进恢复详情页签。处理完成后自动进入下一项使用替换导航，关闭已完成任务页签并打开下一任务详情。已关闭页签在历史导航时重新创建。
- 工作台任务办理页不显示顶部返回、面包屑、队列序号及下一项导航栏，不保留对应空白和加载占位。底部返回队列与业务办理操作保留。
- 外部链接、下载、原生新窗口操作和页面锚点保留原有行为。

### 2.1 工作台详情路由

| 页面 | 路由 | 读取身份 |
| --- | --- | --- |
| 任务办理，含待办审批任务 | `/workspace/tasks/[workItemId]` | 任务 ID |
| 我发起的审批详情 | `/workspace/approvals/[instanceId]` | 审批实例 ID |
| 抄送详情 | `/workspace/copies/[receiptId]` | 当前账号的抄送收件记录 ID |

- `/workspace` 仅承载队列、筛选及分页，不挂载任务、审批或抄送详情。
- 点击队列事项必须进入独立详情路由并打开独立工作页签；不得以工作台元素的显示、隐藏或选中参数承载详情。
- 详情按路由 ID 独立读取。复制地址、直接访问或刷新不得依赖已打开的队列、列表分页或内存中的选中对象；无权、不存在和读取失败必须显示明确失败状态。
- 审批详情通过实例授权接口读取运行状态，通过材料接口读取该次审批冻结资料；不得从当前业务单据拼接历史审批内容。
- `returnTo` 仅接受 `/workspace` 队列地址。任务开启连续办理时，按来源队列条件读取后续任务；该查询失败不阻止当前任务办理，完成后返回来源队列。
- 旧 `/workspace?currentWorkItemId=…` 与 `copyReceiptId` 链接仅负责重定向至对应详情路由，不保留旧详情渲染分支。新生成链接必须使用独立详情路由。

## 3. 页面保留与数据更新

- 每个页签使用独立同源 iframe 承载业务页面。页签切换只改变可见性，不修改 iframe 初始地址、不卸载页面。关闭页签释放对应 iframe。
- 页签内部仅渲染业务内容，不重复渲染侧栏和全局页签栏。路由参数、DOM ID、弹窗、键盘焦点和滚动容器按文档隔离。
- 隐藏页签通过 TanStack Query `focusManager` 暂停默认后台轮询；不取消已发出的提交请求。
- 业务 mutation 成功后，其他页签的查询缓存标记为过期。再次激活时，未修改且未提交的页面刷新过期活动查询；修改中的表单不由页签管理器强制刷新。
- 身份、权限与 DataScope 校验继续执行现有机制。登录 token 被清除或跨窗口替换时，退出当前工作区并释放全部页面。
- 页签不做自动淘汰。有输入内容的页面不得因打开更多页签被静默销毁；用户使用关闭、关闭其他和关闭右侧释放资源。

## 4. 关闭保护

- 统一 `useAppForm` 登记相对默认值发生修改的表单及提交状态。业务保存后应按原有流程 `reset` 更新表单基准；未更新基准时保守提示“输入已修改”。
- 关闭前同时检查业务已有 `beforeunload` 保护；未保存提示不得只依赖页签圆点。
- 正在提交的页签禁止关闭。含修改内容的页签经明确确认后才能关闭；批量关闭执行相同规则。
- 切换页签不弹出丢弃确认。浏览器刷新或离开时，存在修改或提交中的表单触发浏览器原生离开提示。

### 4.1 键盘关闭

- `Alt+Shift+W` 关闭当前 ERP 页签；macOS 对应 `Option+Shift+W`。焦点在侧栏、页签栏、业务页面或输入框时均接入同一关闭流程。
- Mac 的 `Cmd+W`、其他桌面系统的 `Ctrl+W` 仅在浏览器将可取消的键盘事件交给网页时尝试处理。普通浏览器保留组合键不能保证被网页接管，不得将其标为可靠的 ERP 快捷键。
- 页签菜单提供“关闭当前页签”并展示 `Alt+Shift+W`；当前页签关闭按钮提供同一快捷键提示。
- 快捷键与鼠标关闭共用提交中保护及未保存确认。关闭确认已经打开时，重复快捷键不确认丢弃、不另开确认。
- 忽略输入法组合输入及 AltGraph；长按只处理首次按下，禁止连续关闭多个页签；隐藏页面不得发起关闭。
- 关闭活动页签后，键盘焦点移至新的活动页签。关闭最后一个页签时回到工作台，不调用浏览器窗口关闭。

## 5. 接入约束

- 管理端业务导航的 `useRouter` 从 `@/lib/navigation` 导入。路由适配器只使用 Next.js 公共 API，不导入内部 Router Context。
- `WorkspaceFrame` 使用原生 Next router 执行页签内部地址更新；鉴权 Provider 使用原生 router 退出工作区。
- 新增工作区一级路由时，同步登记 `lib/workspace-tabs.ts` 的工作区路径范围。
- iframe 内的查询缓存独立；跨页变更通知不得复制响应数据或跨账号复用缓存。
- 浏览器自动化访问业务控件时必须进入活动的 `iframe[data-workspace-frame][data-workspace-active="true"]`；侧栏、全局页签及关闭确认仍在顶层文档。

## 6. 交互验收

1. 在销售询价列表设置筛选、分页和滚动位置；打开询价后切回列表，状态不变。
2. 在新建询价填写客户、需求行和备注；打开商品资料后切回新建询价，输入不变。
3. 同时打开两张询价单，各自的分区、输入和弹窗不相互影响。
4. 打开超过三个页签再切回第一个页签，原页面不被路由缓存淘汰。
5. 关闭修改中的页签，取消后继续编辑；确认关闭后再打开，重新创建页面。
6. 保存新建单据后显示目标详情；在后台保存完成时，当前工作页保持不变。
7. 单据更新后返回未修改的列表，过期数据重新获取；编辑中的表单不被强制覆盖。
8. 检查前进、后退、复制地址直达、旧入口重定向、退出登录和跨窗口失效。
9. 检查横向滚动、键盘左右切换、关闭其他、关闭右侧和窄窗口布局。
10. 在顶层导航、业务输入框及弹窗中分别按关闭快捷键，检查未保存取消、确认、提交中阻止、长按不连续关闭、最后一页返回工作台及焦点恢复。
11. 分别从任务、我发起的审批、抄送队列打开事项，检查独立路由、独立页签和详情按 ID 读取；复制地址直达与刷新后内容仍可读取，工作台队列不挂载详情。浏览器后退恢复来源队列，前进恢复详情；连续办理后后退仍回到来源队列。
12. 检查任务顶部办理导航栏及其加载占位已移除；直接访问无权或不存在的任务、审批及抄送地址须显示失败反馈，不得显示空队列或永久加载。
