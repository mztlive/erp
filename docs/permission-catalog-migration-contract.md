# 显式权限目录迁移合同

## 目标与边界

以 `d551faa0d7d1d55e2871fb00d9b776931fe51aed` 为基线，在独立 worktree 完成迁移。删除权限属性宏及其生成函数；权限定义由普通 Rust 常量提供，路由显式引用权限定义。业务处理、角色授权、数据范围、数据库结构与部署状态保持不变。 合并验收以 `59ea90c2cde152fbba982feb415fbf141d744093` 为目标基准，保留该提交的供应商售后实现及退款结果接口新路径；权限迁移不得回退 main 的既有变更。

## 定义规则

1. 每个权限代码只定义一次；保留原代码，不重命名、不增删授权能力。
2. 权限分组名称与分组说明只定义一次。
3. 同一权限允许供多个接口使用；各接口既有说明与展示分组必须保留，不得因代码去重合并或改写展示信息。
4. 路由直接引用显式目录常量。处理函数不得保留权限属性宏或生成权限键函数。
5. 构建阶段从同一目录及路由生成前端权限目录和后端授权文件校验目录。目录缺失、引用错误、重复注册必须使构建失败，不得静默跳过受保护路由。
6. 非 HTTP 政策权限继续由拥有领域定义，应用目录引用其定义，不复制权限代码。

## 行为不变要求

- 保留所有 HTTP 方法、路径、处理函数、权限代码、认证挂载与其他路由层。
- 保留前端权限生成物的内容及顺序；后端权限代码白名单集合保持一致。
- 未登录、权限拒绝、权限允许、授权服务故障时，HTTP 状态、响应内容、下游执行次数及权限检查入参保持一致。
- 保留同权限多路由、跨分组展示、公开入口和独立领域政策权限。
- 业务函数实现保持不变；与旧宏绑定的测试改为验证显式权限定义。

## 验收门禁

先执行基线工作区库测试并冻结权限注解、路由源文件、生成物与鉴权响应。迁移后执行：

1. 路由绑定逐项对比，生成物逐字节对比，权限白名单对比。
2. 真实鉴权中间件的允许、拒绝、未认证、服务异常单元测试；检查响应与下游调用。
3. 显式目录及构建生成器的有效输入、缺失引用、重复定义和多路由复用测试。
4. `cargo fmt --all -- --check`、`cargo check --workspace --locked`、`cargo clippy --workspace --all-targets --all-features --locked -- -D warnings`。
5. `env -u ERP_TEST_MONGO_URI cargo test --workspace --lib --locked`。
6. BPM 边界、领域边界、权限生成物漂移及 `git diff --check`。
7. 复核有效源码、Cargo 依赖、当前指导文档中旧权限宏体系已退出。

库单元测试与静态合同对比不声明为真实数据库、浏览器或部署验收；本次不执行真实外部服务集成测试，不重启或部署应用。
