# 历史期初业务迁移专项执行要求

## 1. 启用条件

历史期初导入在业务执行器完成前保持禁止启动和失败重试。规范化数据引用、试算通过、责任确认或外部结果登记，均不得作为业务单据已写入的证据。

专项必须明确并逐类实现期初业务对象、字段映射、币种与税口径、数量精度、责任归属、历史状态和原始凭证引用。不得把自由 JSON 直接写入业务集合，不得绕过领域规则或跨销售 DataScope。

## 2. 实施顺序

1. 建立逐类对象映射合同，列明来源唯一键、目标单据种类、必填字段、关联主数据和允许的历史状态；未支持的对象类型在试算时明确拒绝。
2. 为各类对象实现命名 Process，调用拥有领域的用例；业务单据、来源映射、行回执、行状态、批次计数和审计必须在同一事务提交。
3. 按批次、来源行及映射版本生成稳定命令身份。重复执行只恢复原结果，异内容使用同键必须拒绝；提交结果未知时不得直接重做。
4. 接入后台任务执行权、心跳、恢复和逐行结果，明确依赖顺序、失败隔离、取消边界及重试范围。
5. 完成下列验收并保留证据后，解除 `LEGACY_IMPORT_EXECUTOR_UNAVAILABLE` 阻断，更新前端可用动作及行为合同。

## 3. 验收要求

- 每个对象类型至少覆盖合法创建、字段拒绝、缺失关联、重复来源、异内容同键、跨责任越权、状态冲突和精度边界。
- 持久化结果必须能追溯到真实业务单据、来源行、命令回执和审计；不得只增加“成功数量”。
- 中断与恢复必须证明同一来源不会形成重复业务单据；部分失败只允许恢复未确认项。
- 取消只影响尚未应用项；已经应用的事实通过各业务领域的纠错流程处理，不实施整批无条件回滚。
- 金额、税额、库存数量及往来余额按领域口径对账，明确期初与后续业务的衔接日期和重复计算防护。
- 本地仅运行库单元测试；涉及真实数据库、对象存储和业务验收的数据集及执行环境另行授权，不使用开发库清空操作代替验收。

## 4. 交付边界

专项交付包含对象映射合同、领域执行器、任务恢复、逐行反馈和验收证据。未实现的对象类型必须保持阻断，不允许以全局“已接通”开关放行。
