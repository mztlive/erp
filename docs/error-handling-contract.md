# 错误响应与展示执行合同

## 1. 适用范围

1. 本合同适用于管理端、供应商门户和公开业务入口的请求校验、业务拒绝、读取失败及提交结果查证。
2. 领域错误由所属领域维护；共享结构归 `application-core`，HTTP 映射归 `web-api`，禁止为统一错误引入业务领域之间的依赖。
3. 统一错误处理不得改变权限检查、事务边界、原操作身份或命令恢复规则。

## 2. 响应合同

1. 失败响应使用真实 HTTP 状态和 `ApiResponse`：`success=false`、`errorMessage`、`code`、`retryable`，可附带 `fieldErrors`、`requiredPermission`。请求编号经 `X-Trace-Id` 返回并允许跨域读取。
2. `errorMessage` 必须说明具体原因和下一步。数据库、第三方响应、凭据、输入原值和调用栈不得直接进入该字段。
3. `fieldErrors` 使用接口字段路径作为键，使用公开校验说明作为值。数组下标从零开始，例如 `bank_accounts[1].bank_name`；页面必须展示为第二行银行账户的银行名称。
4. `ValidationIssues` 必须跨领域错误、Process、ReadModel 和 HTTP 边界原样传递。禁止将 `validator::ValidationErrors` 的 Display 字符串作为字段错误合同。手动校验嵌套集合时必须补齐父字段和行号。
5. 无自定义说明的长度、范围、邮箱等校验必须生成对应规则说明；不得把 validator 的 `value` 参数送到前端。
6. JSON 类型、缺字段、语法和查询参数错误必须使用统一提取器。字段解码错误使用 `REQUEST_FIELD_INVALID`；JSON 语法错误使用 `REQUEST_BODY_INVALID`；查询参数错误使用 `QUERY_INVALID`。禁止回显非法值或框架原始错误正文。
7. 已有业务错误码保持稳定。审批码在通用入口和专用审批入口使用同一份公开说明。新增业务错误必须由拥有领域声明稳定语义，禁止依赖提示文本分类。

## 3. 前端执行要求

1. 标准错误信封的公开说明由服务端负责，前端不得再次通过英文词、文件扩展名或缩写过滤整句业务提示。非标准响应及本地异常继续使用安全兜底。
2. 字段错误必须显示在持久错误摘要中；能够匹配表单字段时，同时写入 TanStack Form 的字段状态并定位首个匹配字段。接口与表单命名不同的字段由业务入口提供显式映射。
3. 错误摘要必须独立于表单有效性保存；不含字段错误的拒绝不得将 `state.canSubmit` 锁为 false。字段绑定顺序为显式映射、已注册原始路径、命名转换。同步、异步、失焦及动态校验不得清除未修改字段的服务端错误；重置表单和开始新提交时清理旧摘要。
4. `useAppForm` 必须承接未被业务处理的提交错误，保留原异常的失败语义。已转为业务结果的入口必须保留原 `ApiError`，通过 `applyApiFormError` 接入字段提示，或完整展示错误摘要。
5. `getErrorMessage` 的文本降级必须保留可读字段说明和请求编号。公共失败组件与全局 Mutation 提示必须展示字段明细。
6. 返回 `{outcome, message}` 等业务结果的适配器必须保留原错误对象。禁止用固定 `VALIDATION` 覆盖服务端已有错误码。
7. 422 业务规则阻断不得统一归为填写错误；存在字段错误或明确字段协议错误时才使用输入校验提示。
8. 提交失败不得清空草稿、关闭编辑面或报告成功。字段修改可以清除对应旧错误，不能替用户重放请求。

## 4. 查询失败与局部可用

1. 仅主对象查询明确返回 404 时可以转换为不存在。认证失败、权限不足、网络失败及系统错误必须进入查询错误状态。
2. 财务分录、发票分配和编辑所需修订读取失败不得返回空集合或列表摘要。
3. 单位、品牌、分类、关联单号等辅助读取可以局部失败，但必须携带并显示失败原因；不得把失败解释为未填写或正常空结果。
4. 合同主查询成功后，客户补充资料的读取失败必须作为局部警告展示，不得新增客户详情权限作为合同查看门槛；合同主查询仍执行原授权规则。
5. 局部降级不得放宽对象读取权限。页面须继续使用当前任务或对象已有授权入口。
6. 审批历史与恢复操作必须分别展示读取失败原因；历史分页失败须允许重试失败页，已有记录可以保留，但不得表示记录完整。恢复操作读取失败时不得沿用缓存中的可操作列表。
7. 验收资格、费用发生情况等决定业务可操作性的查询失败，不得解释为资格不满足或费用未发生。相关操作必须暂停并显示原因；保留已输入草稿，重新读取成功后恢复操作。

## 5. 恢复与诊断

1. 读取失败可以重新加载。写请求发生网络中断、响应解析失败、408 或无法确认结果的 5xx 时，提示用户先查询处理结果，不提供无条件重新提交指引。
2. 结果未知时必须保留原操作身份和原载荷，按所属业务的查证或恢复入口继续处理。不得自动建立新操作身份。
3. 错误边界记录稳定码、HTTP 状态、公开说明和字段路径，关联当前请求追踪上下文。不得记录 validator 输入值、完整请求体或原始数据库错误。
4. 内部故障和提交结果未知可补充固定诊断类别及使用进程随机盐的错误摘要标识，用于同一进程内的故障关联。随机盐不得记录，摘要不得替代请求编号；诊断分类不得参与业务判定或重试决策。认证和字段校验错误不得记录输入摘要。
5. 进项发票登记结果未知时须保留原提交身份与载荷，显示结果查证入口；查证未确认成功前不得清空本次操作或转为明确失败。
6. 登录失败由登录表单显示凭证错误或网络错误，不重复弹出会话过期提示。

## 6. 验收要求

1. 通过领域及组合层传递的字段校验错误仍具有完整字段路径和规则说明。
2. 报价表格式错误明确说明 `.xlsx` 或 Excel；图片格式错误明确说明支持的图片类型。
3. 缺字段和类型错误返回 JSON 信封，保留可定位的字段路径且不泄漏非法输入。
4. 供应商退款、付款和应付详情的 403、500 不得显示为未找到；发票分配请求失败不得显示为零记录。
5. 客户资料嵌套行校验能定位具体行；未匹配字段仍在错误摘要中可见。
6. 同一审批错误码在各入口具有相同公开说明；写请求结果未知时保留查证语义。

## 7. 兼容与回滚

1. 保留现有响应字段及业务错误码；本次字段明细属于已有 `fieldErrors` 的实际接通，不修改持久化数据。
2. 新前端兼容缺少 `fieldErrors` 的旧响应，使用原说明或安全兜底；旧前端继续读取 `errorMessage`。
3. 前后端可回滚至改造前版本，无需数据迁移。回滚不得删除命令回执或改变未确认操作的身份。
