# 审批抄送发布执行合同

## 1. 发布范围

1. 前后端必须同步部署。个人收件、详情、已读及附件接口统一使用 `/account/approval-copies`，要求有效内部登录及本人收件校验；原 `/admin/approval-copies` 路径停用。实例抄送历史仍走管理端实例权限。
2. 新增集合为 `approval_copy_configs`、`approval_copy_receipts`。现有 BPM 和业务集合字段不删除、不重命名。
3. 后端启动通过工作流领域索引入口登记定义 ID 唯一索引、收件 ID 唯一索引、实例事件接收人唯一索引及个人收件、未读查询索引。不得复制索引定义到组合根。
4. 首次发布不改历史实例，不补发旧事件。只有配置并发布了抄送规则的定义产生新收件。

## 2. 权限与配置

1. 审批抄送不设独立角色权限。所有有效内部账号均可被配置为接收人并进入个人收件箱；供应商门户账号不进入内部抄送范围。历史 `approval_copy:read` 授权不再参与判断，不要求批量补授权。
2. 配置管理员在草稿中选择抄送时机和人员，保存后核对发布预览。存在停用、删除或非内部账号时，修正配置后重新发布。
3. 已绑定单据继续使用原定义版本。需要采用新版本的未提交单据，应执行现有绑定升级操作；不得后台替换运行中实例的定义。

## 3. 验证要求

1. 验证提交、节点通过、最终通过、驳回、撤回分别产生对应收件；多名或签审批人竞争时不得重复抄送。
2. 验证重复命令零重复收件；恢复零重复抄送；新轮次形成新的未读记录。
3. 验证无业务角色或无审批权限的有效内部账号可进入工作台收件箱，不能凭抄送审批或读取当前票款和其他提交。
4. 验证非接收人、停用账号、外部账号以及不在允许清单的附件均被拒绝；文件变更、隔离、销毁后不可读取。仅移除业务角色或审批权限，不得阻断有效内部账号读取本人抄送。
5. 验证未读数、类型统计、过滤及分页一致；打开失败不得变为已读；重复已读保留首次时间。
6. 自动化验证仅运行仓库允许的库单元测试及前端静态检查。真实数据库事务、并发和页面运行验收应单独记录，不以库测试结果替代。

## 4. 回滚

1. 前后端按同一版本同步回滚，确保个人抄送接口路径一致；保留集合及索引，不删除已产生的收件或已读记录。
2. 回滚到要求独立抄送权限的版本时，按该版本原有角色授权执行，不自动补授权。回滚到不支持抄送的版本时，不产生新收件；不得将未送达事件标记为已送达。
3. 恢复新版本后继续处理新事件，不自动追补回滚期间事件。补发须另行确定事件身份、接收人和去重范围。
4. 不自动回收角色权限或删除流程配置；权限回收须由管理员依据实际授权记录执行。
