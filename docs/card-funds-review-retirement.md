# 卡券票款复核退役约束

生效日期：2026-09-08。本文约束优先于既有文档中的 W13 票款复核流程；未来商城对接必须另行确定业务合同，不得直接恢复旧复核规则。

## 保留范围

1. ERP 卡券销售单的创建、编辑、提交、审批、生效、变更、关闭及既有卡券协同能力必须保留。
2. 销售生效必须继续形成应收分录和销项开票任务；销售金额变更必须继续调整应收及可开票金额。
3. 客户回款审批、核销、冲正、退款、销项发票登记、分配和红冲必须保留原金额约束及事务边界。
4. 本次不调整商城对接的其他接口、任务或执行路径。

## 撤销范围

1. 删除 `/finance/card-funds-review` 页面、菜单、工作台处理器、复核记录面板及复核筛选和计数。
2. 删除以下管理端接口及专用命令、记录写入、复核任务工厂：
   - `POST /admin/receivable-funds-reviews`
   - `POST /admin/card-funds-review/receipts`
   - `POST /admin/card-funds-review/invoices`
3. 新建销售应收不再进入期初待复核；销售金额变更不得被历史复核状态阻挡，也不得产生差额复核任务。
4. 工作台队列、统计及详情导航不得暴露旧复核任务。财务责任配置不得新增或执行旧复核操作。

## 存量数据

1. 不删除或改写已存储的销售单、回款、发票、历史复核记录、任务及审计数据。
2. 旧复核枚举和应收持久化字段仅用于兼容存量数据；不得用其判断当前票款是否可办理，不得将未核实历史记录标成已复核。
3. 新建及发生金额变更的应收使用“不适用”复核状态；应收金额、已收、已开票仍以正式台账记录计算。
4. 历史复核集合不再注册读写能力和索引创建入口；本次不执行数据库清理或迁移。

## 验收要求

1. 卡券销售审批生效、应收形成与销项开票任务继续通过回归验证。
2. 卡券销售金额增加、减少均可处理；新总额不得低于已核销或已开票等既有金额约束。
3. 历史复核状态不影响销售金额变更；旧复核任务不得通过显式类型筛选重新进入工作台。
4. 前端不存在旧页面路由和跳转入口；权限生成物不再包含三个已撤销接口。
