## 1. E3 查询投影

| 项 | 值 |
| --- | --- |
| 分支 | `feat/erp-e3-projection` |
| 依赖 | C-G1、C-G7、C-G10 |
| owns | `backend/services/src/projection/**`、`backend/apps/web-api/src/core/handler/projection/**` |
| 阻塞 | P4 的 F7 |
| 集成测试 | 延期至 P6 的 I-X3 |

数据模型 §12 把维护责任分成两类，实施必须严格照此划分：

**事务内同步维护**（属于 P3 各域，E3 只做校验脚本或文档对照）：
单据当前版本与状态、正式待办、库存余额与预占、应收应付开放余额、
收付款与发票核销进度、销售履约/回款/开票进度。

**允许一分钟内异步刷新**（E3 建设）：
工作台汇总、客户经营质量、订单实际经营盈亏、卡券消费/成本覆盖率/经营结果、
供应商履约分析、预警与管理报表。

要求：

- 投影由定时任务从正式版本、流水、关键事实和核销明细刷新，**无需水位与核对**。
- 必须可重建：提供全量重建入口；重建失败只影响查询新鲜度，不修改正式事实。
- 每个投影接口返回 `as_of`（数据更新时间），前端展示。
- 卡券利润指标接口必须同屏返回：成本覆盖率、`ACTUAL`/`STANDARD`/`NONE` 金额构成、
  未消费余额或未履约余额、期初票款复核进度（§12 末段）。

**验收（本阶段）**：

- 投影服务与 handler 可编译挂载，重建入口可用
- 接口返回 `as_of` 与约定指标字段
- 门禁：`cargo fmt` / `check` / `clippy` / `cargo test --workspace`（无 `include-ignored` 强制）
- PR 列出将由 I-X3 覆盖的测试意图（幂等重建、新鲜度上界、失败不污染正式事实）

## 2. E4 数据治理与安全基线

| 项 | 值 |
| --- | --- |
| 分支 | `feat/erp-e4-governance` |
| 依赖 | 全部 C 单元 |
| owns | `backend/scripts/**`、`backend/docs/**`、CI 配置 |

| 项 | 要求 | 依据 |
| --- | --- | --- |
| 索引完整性 | 脚本比对数据模型 §6 必需索引与实际库中索引，差异即失败 | §13.1 |
| 状态邻接固化 | 脚本校验所有状态 `enum` 的邻接矩阵为编译期常量，无运行时扩展点 | §13.3 |
| 精度一致 | 全仓 grep 无 `f64` 金额；舍入实现唯一 | §13.4 |
| 事实键唯一 | 外部消息规范化、指纹、`business_fact_key` 算法唯一实现且有唯一索引 | §13.5 |
| 表名一致 | 集合名与数据模型表名逐一对齐，无同义表 | §13.7、§13.8 |
| 敏感数据 | 日志与接口不出现明文银行账号、手机号、卡密、token；加密列与 HMAC 指纹生效 | §4.5、`AGENTS.md` 安全基线 |
| 保留期 | 导入成功包长期保留、失败诊断 30 天、导出 7 天，TTL 索引落地且资产拆分 | §4.5.7 |
| 迁移预案 | 每个集合的索引变更有迁移脚本与回滚预案 | `AGENTS.md` 数据治理 |
| 限流 | 登录、验证码、上传等高频敏感接口具备限流 | `AGENTS.md` 安全基线 |

**验收**：上述校验全部脚本化并接入 CI；一次全量执行的报告附在 PR。
（§13.6 并发/故障恢复的**测试证据**在 P6 I-X2，不在本 PR 强制。）
