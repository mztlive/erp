P1–P3 在域内保证正确性，P5 保证**跨域正确性与生产就绪**。
`docs/erp-data-model.md` §13「物理设计强制要求」明确：这些验证未通过，
模型不得作为生产模型发布。P5 就是把第 13 章逐条落成可执行证据。

## 1. E1 跨域事务不变量验证

| 项 | 值 |
| --- | --- |
| 分支 | `feat/erp-e1-invariants` |
| 依赖 | C-G4、C-G5、C-G6、C-G7 |
| owns | `backend/apps/web-api/tests/invariants/**` |

把数据模型第 8 章的每一条不变量写成一个跨域集成测试。P3 各域已在自己范围内测过，
E1 测的是**多域协同后的最终一致性**。

必须覆盖（每条给出正例 + 中途失败的回滚例）：

- §8.1.1 销售单采购确认通过：销售提交锁定、覆盖校验、销售版本、当前版本与状态、
  应收原始分录、采购待办、审计 —— 七项同时生效或同时不生效
- §8.1.3 变更生效：基准版本仍为当前版本；追加差额；**不修改已发生事实**
- §8.1.4 采购财务审核通过：逐行引用已确认的采购确认分配；应付分录 + `CONFIRMED` 成本
- §8.1.5 `PREPAY` 门槛：付款净核销达阈值才允许履约；后续冲正只阻断新履约，不回滚已发生事实
- §8.2 入库过账：入库行 + 库存增加流水 + 余额 + 沿分配自动建立销售预占 +
  `ACTUAL` 成本 + 采购履约进度
- §8.2 仓发过账及其余条目
- §8.3 票款与发票：核销不超额；红票与冲正
- §8.4 商城与供应商：组合支付分摊、退款与余额恢复

同时验证第 9 章「关键业务断言」逐条成立。

**验收**：每条不变量一个具名测试函数，PR 附「章节条目 ↔ 测试函数名」对照表，无遗漏。

## 2. E2 并发与故障恢复

| 项 | 值 |
| --- | --- |
| 分支 | `feat/erp-e2-concurrency` |
| 依赖 | C-G6、C-G7 |
| owns | `backend/apps/web-api/tests/concurrency/**` |

数据模型 §13.6：**每个正式过账入口**必须具备并发、重复提交、超额核销、负库存和
故障恢复测试，测试未通过不得发布。

| 场景 | 断言 |
| --- | --- |
| 并发过账 | 同一单据两个请求并发，恰好一个成功，另一个 409；无双重事实 |
| 重复提交 | 相同幂等键重复提交只产生一条正式事实 |
| 超额核销 | 核销金额超过开放余额被拒，余额不变 |
| 负库存 | 并发出库超过可用量被拒，`stock_balance` 不为负 |
| 预占竞争 | 并发预占同一批可用量，总预占不超过可用量 |
| 提交结果未知 | 注入 `UnknownTransactionCommitResult`，断言返回 `OutcomeUnknown` 且不自动重放 |
| 故障恢复 | 事务中途中断后重启，无半写状态；待办与状态可自愈或有明确人工入口 |

**验收**：过账入口清单（销售确认、采购审核、入库、发货、电子交付、服务确认、
收款、付款、开票、退款、库存调整、商城消费、供应商结算确认）逐个有测试，PR 附清单。

## 3. E3 查询投影

| 项 | 值 |
| --- | --- |
| 分支 | `feat/erp-e3-projection` |
| 依赖 | C-G1、C-G7、C-G10 |
| owns | `backend/services/src/projection/**`、`backend/apps/web-api/src/core/handler/projection/**` |
| 阻塞 | P4 的 F7 |

数据模型 §12 把维护责任分成两类，实施必须严格照此划分：

**事务内同步维护**（属于 P3 各域，E3 只做校验脚本）：
单据当前版本与状态、正式待办、库存余额与预占、应收应付开放余额、
收付款与发票核销进度、销售履约/回款/开票进度。

**允许一分钟内异步刷新**（E3 建设）：
工作台汇总、客户经营质量、订单实际经营盈亏、卡券消费/成本覆盖率/经营结果、
供应商履约分析、预警与管理报表。

要求：

- 投影由定时任务从正式版本、流水、关键事实和核销明细刷新，**无需水位与核对**。
- 必须可重建：提供全量重建入口；重建失败只影响查询新鲜度，不修改正式事实。
- 每个投影接口返回 `as_of`（数据更新时间），前端展示。
- 卡券利润指标接口必须同屏返回：成本覆盖率、`ACTUAL`/`STANDARD`/`NONE` 金额构成、
  未消费余额或未履约余额、期初票款复核进度（§12 末段）。

**验收**：投影重建幂等性测试（重建两次结果一致）、新鲜度延迟上界测试、
重建失败不污染正式事实的测试。

## 4. E4 数据治理与安全基线

| 分支 | `feat/erp-e4-governance` |
| 依赖 | 全部 C 单元 |
| owns | `backend/scripts/**`、`backend/docs/**`、CI 配置 |

| 项 | 要求 | 依据 |
| --- | --- | --- |
| 索引完整性 | 脚本比对数据模型 §6 必需索引与实际库中索引，差异即失败 | §13.1 |
| 状态邻接固化 | 脚本校验所有状态 `enum` 的邻接矩阵为编译期常量，无运行时扩展点 | §13.3 |
