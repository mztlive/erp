# 询价、销售与采购衔接需求合同

版本：1.0。确认日期：2026-10-21。状态：需求基线已确认；本地实现、检查及业务验收状态以执行计划登记为准，本文不替代验收结果。

执行计划：[询价业务执行计划](sales-inquiry-implementation-plan.md)。

## 1. 目标与适用范围

1. 建立“客户选品 → 销售提交询价 → 采购反馈 → 销售确认 → 销售开单 → 供给分配 → 商品采购及费用采购”的可追溯业务链。
2. 询价支持销售与采购多轮往返。销售可针对商品、供给价、交期和额外成本要求重新询价。
3. 销售只接收采购给出的供给结论、最终供给价、交期及额外成本，不得通过询价业务读取供应商身份、原始报价、比价和内部议价资料。
4. 采购必须逐商品确认可供应、部分可供应或不供应，不得仅用是否填写价格表达供给结论。
5. 询价支持额外成本，并支持在关联销售单生效后转换为独立费用采购单。
6. 本合同适用于实物与服务销售。实物商品执行配送地址规则；虚拟商品和服务按其交付要求处理，不强制填写实物收货地址。卡券销售、商城兑换及供应商自动接单不纳入本次范围。
7. 保留直接创建销售单的既有流程。询价不是所有销售单的强制前置条件。
8. 询价、反馈及销售接受均不产生应收、应付、库存预占、供应商采购订单或付款授权。

## 2. 单据职责与主流程

| 对象 | 业务职责 |
| --- | --- |
| 询价需求 | 客户、商品、数量、配送要求、交期和销售参考价 |
| 采购内部报价 | 供应商、原始报价、供给身份及适用条件 |
| 对销售反馈结果 | 逐商品供给结论、供给价、可供数量、交期、额外成本及公开说明 |
| 销售单 | 客户成交事实、销售成交价、交付承诺及来源询价关联 |
| 供给分配 | 当前实际库存与采购供给的选择、数量及地址分配 |
| 商品采购单 | 实际供应商、采购数量、采购成本、付款和履约条件 |
| 费用采购单 | 我方承担且需要通过 ERP 付款的额外费用 |

主流程：客户填写选品 Excel → 销售导入并确认需求 → 提交采购 → 采购处理并发布反馈 → 销售接受或要求重询 → 从已接受结果创建销售草稿 → 销售审批生效 → 采购确认供给分配及费用采购 → 按既有审批、履约、票款流程执行。

## 3. 角色与数据隔离

| 操作或内容 | 销售 | 当前责任采购 |
| --- | --- | --- |
| 客户需求、商品、数量、地址 | 创建和维护 | 查看责任范围内必要信息 |
| 销售参考价及销售成交价 | 维护 | 不因询价任务取得读取权 |
| 对销售反馈的供给价、数量、交期 | 查看已发布结果 | 维护并发布 |
| 不供应结论及对销售说明 | 查看 | 维护并发布 |
| 额外成本名称、确认金额及公开说明 | 查看、接受或要求重询 | 维护并发布 |
| 供应商、供给身份、原始报价、比价 | 不返回 | 按当前责任及内部权限读取 |
| 内部议价说明、收款对象和供应商附件 | 不返回 | 按当前责任及内部权限读取 |

1. 销售接口与采购接口使用独立响应结构。不得先返回完整数据再由前端隐藏字段。
2. 销售列表、详情、历史轮次、导出、打印、通知、错误信息和来源轻预览执行相同隔离规则；销售侧不得读取费用内部依据附件。
3. 对销售说明与内部说明分别存储。不得自动复制供应商名称、联系人、报价单文件名或内部备注到公开字段。
4. 询价详情下载的客户模板只含对客商品信息及销售确认的对客参考价，不含内部供给价、供应商或采购报价资料。公司商品池统一沿用原导出，保留其全部既有列、图片及销售展示价格，并增加选品与配送填写能力；该文件保留供应商编号、供应保障，销售负责在发送客户前删除不对客的信息。导入只消费需求白名单字段，不得将原导出的供应商资料或展示价格写成询价反馈。
5. 采购询价任务只授予责任行和必要客户身份、配送信息的访问权，不授予普通销售单、客户完整档案、合同及整单销售金额的读取权。
6. 任务完成、关闭、改派或账号失效后，原任务授权立即失效。历史参与不得自动取得当前写入权；历史资料读取执行独立范围校验。
7. 供应商内部信息的访问权不得由销售身份取得。独立管理或采购权限不通过销售视图透出内部字段。

## 4. 需求结构与 Excel 导入

### 4.1 需求字段

| 层级 | 必要内容 |
| --- | --- |
| 单头 | 稳定 ID、单号、客户、销售负责人、业务组织、询价截止时间、状态、当前需求版本 |
| 商品行 | 稳定行 ID、SKU、名称/规格/单位快照、需求数量、交付期限、可选销售参考价 |
| 配送分配 | 稳定分配 ID、商品行 ID、收货人、电话、地区代码及名称快照、详细地址、数量 |
| 版本 | 需求版本号、提交人、提交时间、变更原因及变更范围 |

1. 商品使用公司 SKU 稳定身份，不得以商品名称作为关联主键。换 SKU 必须形成新需求行，不得改写旧行身份。
2. 同一 SKU 可有不同交期或商业条件的需求行，不得只按 SKU 无条件合并。
3. 保存草稿允许地址数量合计不足或超过商品需求数量；提交询价时每条实物商品须补齐收件资料，地址数量合计不得少于需求数量。超量允许保存与提交，保留销售填写的需求数量和地址数量，不自动调整任一数量；页面显示超出数量提醒，不将超量视为配送未完成。报价供量及转单仍按商品需求与有效供给额度校验。
4. 当前销售及采购模型的每商品行 100 地址上限作为首版限制；超限必须提示并拒绝，不得截断。扩大上限须同步修改询价、销售、采购和履约校验后交付。
5. 金额、数量、税率采用十进制值，接口使用十进制字符串；单位精度和金额舍入沿用现有业务规则。
6. 商品需求表支持按需求行勾选及全选后批量设置要求交付日。应用前须显示影响行数及覆盖原日期的提示；仅更新已选行的交付日，保留未选行及其它需求字段。应用结果进入当前需求草稿，仍须保存需求后同步至服务端；未选商品、未选日期或需求不可编辑时不得应用。

### 4.2 Excel 处理

1. 公司商品池只保留原导出入口；勾选导出及当前筛选结果导出统一生成含「选品」「配送需求」「填写说明」的 XLSX。选品页保留原有全部列及图片，新增需求数量、销售参考价、需求备注及询价适用说明；配送需求每行表达一个 SKU、一个收件地址、一个交付要求下的数量。询价详情原有三表客户模板继续支持。选品页未填写需求数量的商品不参与询价导入，配送页只预填 SKU 且未填写配送内容的行不参与导入。卡券保留在原导出清单中，但不得作为询价需求导入。
2. 商品清单保留 SKU 编码、名称、规格和单位；编码及电话按文本处理，保留前导零。
3. 导入按 SKU 编码精确匹配当前授权且可选的公司商品，不得按名称猜测、不自动创建商品或供应商。
4. 不存在、无权选用、下架、单位不符、数量或精度非法、地区无法唯一匹配、地址缺失等错误必须定位工作表及行号。无权与不存在使用统一对外语义。
5. 相同 SKU、收件信息和交付条件的重复行在预览中标记并给出合并结果；由销售确认，不得静默丢弃。
6. 客户填写的价格只作为需求或销售参考，不得成为采购确认价。导入不得接受供应商、内部报价或任务责任字段。
7. 销售询价列表提供“导入客户选品”入口。销售在弹窗中选择客户并上传一个工作簿，点击“创建询价草稿”后系统先解析校验，无错误且无需合并确认时自动创建并打开草稿详情；存在重复配送行时先展示合并预览，销售确认后再创建。不得要求先创建空询价。预览或确认失败均不得留下空草稿或部分需求。已有询价详情保留导入替换草稿需求的入口。存在错误时须修正或明确移除错误行后重新预览。
8. 新建预览绑定当前账号、客户和输入指纹；切换客户必须重新预览。确认时重验客户与责任范围权限、商品资格、预览用途及输入指纹，已有询价同时校验需求版本。新建询价、需求、预览处理结果、回执和审计在同一事务写入。重复确认返回原结果；同一命令键异载荷拒绝，同一预览不得重复创建多张询价。
9. 导入模板必须标注版本、文件大小及行数限制；前后端限制一致。实施时将具体限制写入接口合同，不得无限制读取文件。
10. 商品池工作簿的配送页根据选品需求数量自动带出商品名称、SKU 编号、SPU 编号及配送数量，每个可询价商品默认一个配送行，保留地址与商品关联，配送数量默认全部需求数量。多地址须复制该商品整行到页末，并将原行及新增行的数量分别改为实际分配值。配送页显示需求、已分配、剩余数量和文字状态；超量红色、不足黄色、一致绿色，绿色不代表地址完整。商品与配送业务字段仅接受系统生成的商品联动公式，服务端按选品数据重算；数量核对列仅作填写提示，导入时直接丢弃其值、公式及缓存，不因普通公式、共享公式或软件保存改写而拒绝。服务端独立校验数量和地址，其他业务字段的公式须转换为值。导出不得将商品名称等文本当作公式执行。文件、预览及下载均绑定当前询价权限。

### 4.3 配送地址编辑与文本批量添加

1. 配送侧栏以地址清单承载浏览、多选和批量移除。单条地址新增、修改及替换使用独立 Dialog；确认前不得修改需求或地址身份，取消不得留下空地址或替换记录。
2. 批量添加使用独立 Dialog，按行接收文本。列顺序固定为收件人、联系电话、省、市、区、详细地址，可选第七列为配送数量；未提供或留空时按 `1` 处理。允许包含对应表头。Tab 分隔保留空单元格及字段内部空格；空格分隔时，含空格的字段须用英文双引号包裹。
3. 文本最多 100,000 字符，单次最多解析 2,000 行；去重处理后的现有地址与新增地址合计不得超过 100 条。现有地址达到上限时仍允许进入批量处理，确认时按最终地址数校验。电话按文本保留，不得转换成数值；科学计数法电话须提示修正。省、市、区按当前行政区划逐级唯一匹配；目录中无下级区县的城市允许区县留空或填 `—`，街道或镇须写入详细地址。数量须为符合商品精度的正十进制数。
4. 收件人、电话、行政区划编码、详细地址去除首尾空白后全部相同，视为同一收件地址；数量按十进制数值比较。预览按收件地址分组，展示源行号、原数量、导入数量、处理方式及结果数量。粘贴内容中同址同量的重复行默认保留一条；与现有地址同址同量的行默认跳过。存在不同导入数量或与现有数量冲突时，须明确选择保留原值或跳过、采用指定导入数量、填写结果数量，或合并并累加数量；未处理的冲突不得确认。
5. 合并并累加数量仅在用户显式选择后执行，结果为当前地址原数量加该组全部源行数量，重复源行也须计入。现有多个地址均匹配同一收件资料时，不得自动选择更新目标；允许保留原记录并跳过导入，需修改时返回地址清单处理。
6. 原始资料或数量校验失败时，须返回修改文本后重新解析，或明确移除错误行。存在错误、未处理冲突或超过最终地址上限时不得确认。全部预览行均跳过时显示“全部跳过，无需添加”，禁用确认操作。源行或现有地址发生变化后须重新核对处理选择；确认时须校验现有地址仍与预览一致。
7. 确认须一次性应用新增地址及现有地址的数量变更，保留现有地址的收件资料和分配身份。预览展示新增数、更新数、跳过行数及处理后的分配总量；超过需求数量时须明确提示。数量不足允许暂存草稿，超量允许保存与提交采购；提交仍须补齐收件资料且配送合计不得少于需求。已提交收件资料及销售占用地址继续执行不可变与占用保护规则，更新数量不得低于有效占用数量。

## 5. 多轮协作与版本规则

### 5.1 状态与动作

| 当前状态 | 执行人及动作 | 目标状态 |
| --- | --- | --- |
| 草稿 | 销售提交完整需求 | 采购处理中 |
| 采购处理中 | 采购要求补充需求并填写原因 | 待销售补充 |
| 待销售补充 | 销售补充并重新提交 | 采购处理中 |
| 采购处理中 | 采购发布完整反馈 | 待销售处理 |
| 待销售处理 | 销售要求重新询价 | 采购处理中 |
| 待销售处理 | 销售接受结果 | 已确认 |
| 已确认 | 销售对未转需求重新询价 | 采购处理中 |
| 任一未关闭状态 | 有维护资格的销售关闭并填写原因 | 已关闭 |

责任采购任务分配即生效，责任人必须直接办理，不设接手、接受或拒绝任务动作。责任转移须通过改派并填写原因；原责任人在改派成功前继续负责。历史“待采购处理”记录按采购处理中办理，不要求补做接手。

1. “未转、部分已转、全部已转”为独立转单进度；报价过期为独立有效性标记，不混入处理状态。
2. 需求版本与反馈轮次分别编号。仅对价格不满意时可保持同一需求版本并增加反馈轮次；商品、数量、地址或交期变化必须提交新需求版本。
3. 每次提交冻结需求，每次发布冻结完整反馈。不得覆盖已提交需求、已发布结果和销售接受记录。
4. 销售重询必须填写原因，可指定商品、费用和关注项。采购可显式沿用未受影响内容，发布前仍须验证有效性；每轮发布均形成完整快照。
5. 重新询价期间暂停受影响未转需求的转单。已有销售草稿、正式销售和采购保留原来源版本，不自动更新。
6. 已有转单占用或消耗的数量不得通过改版重置。新需求目标低于已占用及已消耗数量时必须拒绝，先按销售草稿或正式变更流程处理。
7. 已关闭询价不得继续询价或新增转单，未完成任务同步关闭；既有销售及采购仍按各自生命周期执行。重新采购意向通过复制为新询价建立来源关系。
8. 需求提交、反馈发布、销售接受、重询和关闭均校验版本，并在同一事务内更新业务状态、任务、审计和命令回执。
9. 提交、补充后重提及重新询价均由系统按现有采购责任配置自动分派，销售不得选择默认采购、逐商品采购或整单费用负责人。规则优先级为 SKU、商品分类（逐级到父分类）、商品类型、默认调度人；多采购参与时按稳定需求行分组，同一采购一个任务。全部责任结果齐备后统一发布，销售不读取采购工作草稿。
   整单费用优先沿用仍参与本轮的原负责人，否则由首个需求商品的责任采购负责。采购侧保留改派，目标人员资格及费用责任迁移须由服务端重验。责任配置缺失、冲突或人员失效时拒绝提交，提示维护采购责任配置，不要求销售补选人员。
10. 退回补充或关闭时冻结当前采购工作内容，重新提交后必须重新校验，不得带着旧任务版本继续发布。

### 5.2 逐行供给结论

| 结论 | 约束 | 转销售规则 |
| --- | --- | --- |
| 可供应 | 可供量等于需求量；填写供给价、税率和有效期；交期沿用需求 | 在已接受且仍有效的范围内转单 |
| 部分可供应 | 可供量大于零且小于需求量；填写价格、税率、有效期及剩余数量说明 | 仅可供部分可转单 |
| 不供应 | 可供量为零；对销售原因必填；不得以零价代替结论 | 禁止转单 |
| 待确认 | 允许采购内部保存处理进度 | 禁止完成本轮发布及转单 |

1. 发布时每个有效需求行必须有最终结论。所有商品均不供应时仍可发布，销售可重询或关闭。
2. 不供应行不得通过删除抹去；后续轮次可以改变结论并保留历史。
3. 可供及部分可供均沿用需求的全部配送地址，反馈不另存地址数量。转销售时须明确本次配送分配，累计数量同时受商品可供总量和各需求地址数量限制。
4. 销售可接受完整结果后，仅选择其中部分可供商品及数量开单；未成交或不供应部分保持可追溯。

### 5.3 采购反馈编辑

1. 主表展示缩略图、商品及规格、需求数量、供给结论、含税供给单价、税率、报价有效至、需求交付日期和供应商报价入口。单价、税率与有效期直接在商品行编辑；单位显示名称，不展示内部编码。
2. 统一税率和报价有效期紧凑排列在表格工具栏右侧，与批量设为可供操作相邻；不单独展示说明卡片。修改统一项时，将该项应用到本任务全部可供及待确认商品，不修改其他项、单价和供给结论；不可供商品不保留报价。统一项写入逐商品草稿并随处理进度保存，不生成独立业务记录。已有商品条件不一致时显示“各商品不同”，不得自动覆盖。
3. 选择可供时，可供数量取完整需求数量；部分可供时填写可供数量及缺货原因；不可供时只填写原因。交期和配送范围统一沿用需求，反馈不重复存储或允许调整。
4. 每件商品仅保留一条报价，其业务字段为含税单价、税率和有效期；报价身份继续用于来源追溯。前后端不提供独立报价数量、最低/最高数量、分批累计条件、交期、配送分配或费用包含说明。商品行不提供“调整”或展开报价入口。
5. 商品反馈直接展示全部需求行，不提供全部、待填写或有问题筛选。勾选商品后可一键将待确认项设为可供；保留已有可供、部分可供、不可供结论和已填价格、税率及有效期。后台刷新不得覆盖未保存输入。
6. 反馈底栏提供保存处理进度与发布本轮反馈；保存不向销售公开，允许商品单价、税率暂未填写，未填写不得以零值替代；发布前须保存并补齐全部责任结果。未开始处理的商品不重复展示缺项清单；处理后及发布校验须提示具体缺项，点击提示定位到对应商品字段。接口最终校验及版本冲突规则继续生效。
7. 有内部报价权限的采购可通过商品行“供应商报价”查看与登记，独立保存；登记内部报价不是填写对销售反馈的前置步骤，不得将内部采购成本和供应商资料作为对销售反馈公开。

8. 额外成本通过商品反馈表格工具栏左侧的按钮打开登记弹窗，按钮显示当前费用项数；反馈表下方不再内嵌费用编辑区。新增、修改及移除费用沿用当前反馈草稿，关闭弹窗保留输入；弹窗内“保存处理进度”同时保存当前商品反馈和费用，成功后关闭，失败时保留输入并显示原因。
   保存前须校验费用名称、含税金额及税率：名称不得为空且不超过 256 字符，金额须为非负数且最多保留 2 位小数，税率须在 0 至 1 之间且最多保留 6 位小数。校验失败时不得提交，须打开费用弹窗、标记错误并定位首个无效字段，保留全部输入供补填或移除；不得将空金额转换为零或静默丢弃费用。未完成的商品报价仍允许保存草稿。

9. 详情页顶部信息、页面操作、提示及页签栏不参与滚动，只有当前页签内容按容器剩余高度滚动；采购可编辑反馈时，保存、发布操作栏固定在内容滚动区之外；独立详情页与工作台嵌入页执行相同布局，禁止通过独立视口高度叠加撑出屏幕。录入页以保存、发布操作栏结束，不追加已发布结果或未发布空提示。有历史发布记录时，通过独立“已发布反馈”页签查看各轮商品及费用；切换页签保留当前编辑输入和滚动位置。销售及采购只读状态继续在“采购反馈”页签核对结果。

10. 操作记录、要求补充需求及改派责任采购放在页头右侧，与生成供应商报价表同属页面操作区；页签栏只保留内容分区入口。

### 5.4 按供应商批量生成报价表

1. 当前责任采购在采购处理中使用页头“生成供应商报价表”。默认选中本任务全部需求商品及匹配供应商，允许取消部分商品或供应商；后台刷新不得清除本次选择。采购下载 ZIP 后解压，并通过现有聊天渠道分别发送供应商。
2. 按需求商品的 SKU 查询当前权限范围内全部供给关系，以供应商稳定身份分组，每家供应商生成一个独立 XLSX。一个商品关联多家供应商时，该需求行进入每家供应商的文件，均保留完整需求数量，不在询价导出时拆分采购份额。同一家供应商的重复供给关系合并货号，不重复生成同一需求行；同 SKU 的不同需求行继续分别保留交期、数量和配送条件。
3. 文件名及表内标题采用“{供应商名称}报价表”，文件扩展名为 `.xlsx`。文件名须清除路径及非法字符；清洗或截断后重名的文件追加序号，禁止覆盖。全部文件统一打包为“{询价单号}-供应商报价表.zip”，任一文件失败时不得下载部分成功包。
4. 报价表自动填写商品主图、名称、规格、SKU 编号、该供应商货号、单位名称、需求数量、要求交付日、交付要求及配送摘要。黄色区域预留含税单价、税率、可供数量、承诺交付日、运费、报价有效期和备注，全部留空，不带入历史报价。税率按百分数填写；运费为本行总额，已含运费填写 0。
5. 有配送需求时增加“配送需求”工作表，按需求行和地区汇总地址数量及配送数量，通过固定询价项次对应报价表“配送要求”中的项次，整行排序不得改变关联。配送数量按原需求汇总，不改写商品询价数量；超量配送继续执行既有需求规则。外发文件不得包含客户身份、收件人、电话、详细地址、销售参考价、销售供给价、内部采购价、其他供应商资料或内部备注。
6. 没有匹配供给关系、取消供应商后未覆盖或缺少商品单位资料的需求行必须明确提示。采购须补齐资料、选择供应商或取消该行后再导出，不得静默漏行。暂停或停止供给关系在预览中标明，由采购核对是否询价；不得仅因旧报价或可供状态失效而隐式排除已有供给关系，导出不得恢复任何供给状态。
7. 预览及下载前须重新读取当前采购任务、完整供给关系和商品图片与单位资料；下载前数据与预览不一致时须重新核对。图片实际读取失败须拒绝本次生成，无图商品明确标注“暂无图片”。文件生成完成后再次核对当前询价及任务资格，失效时不得开始下载。
8. 每次最多处理 200 条需求商品、200 家选中供应商，生成文件合计及 ZIP 均不超过 50 MiB；超限须提示缩小选择，不得截断。数量按十进制原精度输出，SKU 和供应商货号按文本保存；商品名称等外部文本不得作为 Excel 公式执行。
9. 本操作只生成报价材料，不产生发送记录、供应商回复、已采用报价或采购订单。采购收到回复后，继续通过内部供应商报价入口登记及核对。

## 6. 价格与采购内部报价

1. 销售参考价、采购对销售反馈的供给价、销售成交价及供应商实际采购价分别保存，不得共用一个价格字段。
2. 对销售供给价记录含税单价、税率和有效期；可供量取反馈行，地址与交期取对应需求快照。它是成本参考，不直接形成应付或实际利润。
3. 同一商品允许多个供应商及多份报价。内部报价记录供应商与供给身份、报价版本、含税单价、税率、可供量、配送范围、交期、可选失效日期和备注。登记后即可使用，不设置生效日期、起订量、累计分批或付款条件；采购付款条件沿用供应商当前商务资料，在正式采购环节确认。
4. 一条对销售反馈可对应多个内部报价。按不同地址或数量区间价格不同时，分别提供可识别的供给价格明细，不得用平均价抹去适用条件。
5. 采购向销售发布时明确最终供给价。该价与内部采购价分别存储和追溯，不得因隐藏供应商而丢失内部依据。
6. 通用报价只有通过明确的供给维护操作才可更新通用条款；询价反馈不得隐式更新全公司供给价格。
7. 本单专项报价须限定询价、需求行、适用数量和地址及条款版本；供应商明确限定期限时记录失效日期；只能由关联销售采购消费，不进入其他客户的通用推荐。
8. 对销售报价过期或可供余额不足、内部报价已到失效日、地址变化、供应资格或交期条件失效时必须重新确认。不得静默采用旧价、最新通用价或其他供应商价格。
9. 内部报价不设起订量；分批采购按稳定报价余额及地址余额累计校验，不得超量。对销售反馈按商品可供总量与需求地址数量累计校验，不设起订量及数量档位。
10. 登记内部报价默认带入需求数量和交期；唯一可用供应商自动选中，税率取所选供给的当前税率；供给未提供税率时须补填，不得统一补为 13%。采购主要填写含税单价，数量、交期、税率和失效日期按需展开调整，备注选填；不提供报价凭证上传或下载。
11. 新登记报价的配送范围由服务端按本行全部需求地址及原数量生成，采购不得调整。部分可供量不缩减地址范围；地址额度合计允许大于报价可供量，实际采用仍须同时满足报价总余额、各地址余额及本次配送数量守恒。历史报价的冻结范围不自动改写。

## 7. 额外成本

### 7.1 询价费用明细

1. 询价费用只填写名称、含税金额、税率和选填备注；每项费用使用稳定费用行 ID。所有登记金额均为商品价格之外的额外成本，不登记已包含在商品价中的项目。
2. 商品归属由后端确定：新费用由整单费用责任人登记时归属整单，其他采购登记时归属当前责任商品；已有费用保留原商品归属。地址不单独限定，覆盖归属商品的需求地址。
3. 保存费用时，有效期采用对应商品报价中最早的到期时间；未填写报价有效期时允许保存草稿，发布前必须补齐。采购不得单独填写或延长费用有效期。
4. 弹窗按费用分卡片展示，名称在首行、金额与税率在次行、备注在末行；每项提供移除操作，添加后聚焦新费用名称。弹窗正文独立滚动，标题和底部操作保持可见。
5. 费用随本轮商品反馈保存并冻结，销售接受后方可用于后续办理。未接受结果不得直接转换费用采购或财务登记；费用金额、税率或归属变化须形成新反馈并由销售接受，不覆盖旧结果。
6. 本区记录我方承担的成本，不自动向客户收费；客户另付事项按销售服务明细及既有销售变更规则处理。
7. 费用类别、付款路径及收款信息在成交后的费用办理环节确认。费用采购与财务直接登记共用同一来源占用台账，同一额度不得重复办理。
8. 询价费用不再保存 `category`、`allocation_ids`、`included_in_goods_price`、`confirmation`、`requires_erp_payment`、`valid_conditions`，接口拒绝这些旧字段；备注统一保存为 `public_note`。上线前停写并备份，执行 `scripts/migrate-simplify-inquiry-fees.js`；默认预览，`INQUIRY_FEES_MIGRATION=apply` 执行。迁移合并旧有效条件至备注，保留身份、金额、税率、商品归属、历史有效期和办理台账。存在已含价、已发布暂估、指定地址或备注超长的旧费用时必须停止并核对。回滚须在停写期间恢复迁移前数据库备份及配套旧版程序。

### 7.2 转换为费用采购

1. 销售草稿只关联已接受费用结果，不创建费用采购。来源销售单生效且未作废后，由采购发起转换；已关闭销售单按既有费用采购合同允许办理。
2. 转换限定销售已接受、尚在有效期且有可转额度的费用；办理费用采购时选择费用类别、收款供应商及付款条件。已支付或无需生成应付的费用按财务登记办理，并登记同一来源占用，不能重复生成应付。
3. 采购选择费用及归属销售单，补齐收款供应商和付款条件后预览。收款对象和主体不一致的费用分别建单；每单行数和拆单规则沿用费用采购合同。
4. 确认命令原子写入费用来源占用、费用采购、审批及回执。创建即提交审批，不新增未提交费用采购草稿。
5. 费用采购行保存询价 ID、反馈版本、稳定费用行 ID、销售单及费用分配身份。普通销售视图仅返回允许查看的金额及处理进度，不透出收款供应商。
6. 一张询价转多张销售时，必须先明确费用归属或分摊金额。按金额分配并校验合计，不向每张销售单完整复制整单费用。
7. 费用累计占用、已办理及剩余额度按稳定费用行跨反馈版本核算。新轮次不得重置可转金额；减少费用不得低于已有有效占用及已办理金额。
8. 审批中、撤回或驳回但仍可重提的费用采购继续占用额度；只有作废或正式减少费用的业务事实成立后，才能释放对应未办理额度。已付款、已确认发生或已登记的事实不得直接释放。
9. 费用采购重提或改单增加金额时重验来源额度；超出已接受费用额度时先完成新的费用反馈与销售接受，再执行正式采购变更。已确认发生的费用沿用既有禁止修改规则。
10. 转换后询价改版不得自动修改采购单。费用发生确认、应付、付款申请、付款及进项发票继续执行既有合同。
11. 费用采购不参加商品供给分配、不计入供给覆盖、不生成商品履约任务；商品与费用可以在同一工作台办理，但分别执行正式业务命令。

## 8. 询价转销售

1. 仅当前已接受且适用条件有效的结果允许新建转单；关闭或正在重询的受影响范围不得新增转单。
2. 转单复制客户、商品快照、数量、配送分配和交付要求；销售填写或确认成交价，补齐结算主体、合同、付款及凭证要求后执行现有销售审批。
3. 采购供给价只作为销售定价参考。引用为成交价须由销售明确选择，不得自动将采购成本作为客户成交金额。
4. 销售保存询价 ID、需求版本、反馈版本、稳定需求行及配送分配映射；不得保存供应商或将报价候选变成正式选源。
5. 支持按商品、地址及数量部分转单。可转量按需求行及地址跨版本核算：当前有效可供量减有效草稿占用量及已消耗量，任一维度均不得超量。
6. 创建草稿、占用来源数量及回执必须原子完成。同一命令重试返回同一销售草稿。
7. 草稿编辑增加数量、换客户、换 SKU 或改变来源地址时必须重验来源；不再满足原报价条件的内容必须先重新询价，不能保留失真的来源标记。
8. 草稿减少数量、删除来源行或作废时释放相应占用；提交及审批期间不得提前释放。销售生效时将占用转为消耗，不能重复扣减。
9. 正式销售减少或作废是否恢复可转量，必须根据正式生效变更、下游采购/履约处理结果及报价有效性判定；不得仅因前端状态改变直接释放。
10. 销售需求变化、报价失效及新增轮次不得自动改写已存在的销售草稿或正式单据；正式单据继续执行销售改单及采购影响处理。
11. 普通实物与服务销售的新建页须提供“从询价单带入”入口；首屏须将其作为第三项开单方式放入底部“其他开单方式”，沿用“选择已有合同”和“先开单，后补合同”的整行样式，首屏顶部不得重复展示询价提示条。进入普通销售表单后保留来源切换入口。两处入口与询价详情的开单入口共用已接受结果校验及建单流程。已选客户时按该客户筛选，未选客户时允许按询价单号或客户名称搜索；不可转询价须展示原因并禁止选择。确认前须重新核对来源资格及剩余数量，取消或加载失败不得修改当前销售内容。当前页面已有填写内容、合同或文件时，须明确提示放弃内容并取得确认后再切换。已保存销售草稿、销售方案来源、已有询价来源及卡券销售不提供此切换入口；保存或提交进行中、开单结果待核对时禁止切换。

## 9. 供给分配与采购追溯

1. 沿用询价、手动选择和系统推荐共用现有供给分配入口及最终事务校验。
2. 沿用询价只将仍有效的报价候选带入分配草稿；采购必须确认当前供应商、条款、数量、地址和交期。询价不提前锁定最终供应商。
3. 手动改选须记录原因，原询价结果保持不变。实际供给价变化不修改销售成交价或原反馈价格。
4. 系统推荐复用库存优先及既有采购排序规则，并提供推荐理由；不得仅以最低单价选择不可配送或无法按期交付的供给。集采直发继续由采购明确选择。
5. 采购创建依据必须识别通用供给条款与本单专项条款，精确冻结实际采用版本。专项条款不得绕过供应商资格、SKU、配送、数量、税率及付款规则。
6. 供应商原始报价与对销售供给价可以不同；正式采购采用经过验证的实际采购条款，不直接复制销售可见供给价作为供应商成本。
7. 同一商品允许由多个供应商及库存拆分满足；各地址和商品总量均不得超过最新剩余需求及实际可供量。
8. 供应商直发仅携带本次承担的客户地址及数量；采购入仓只登记目标仓，客户地址随销售及仓发流转。库存足够时允许零张商品采购单。
9. 商品采购按供应商、采购类型、付款条件、履约责任及价格依据拆分；当前供应商结算条件不一致时不得错误合单。
10. 采购行分别记录需求来源链和实际报价采用链。更换供应商时需求来源不变，实际采用链不得伪称沿用了原报价。
11. 保持销售生效后正式选源、采购创建即提交审批、库存与采购统一覆盖以及单命令原子落地规则。

## 10. 幂等、并发与历史保护

1. 导入确认、提交需求、发布反馈、接受、重询、转销售、商品选源及费用转换均使用命令幂等键、载荷指纹和强类型回执。同键异参必须拒绝。
2. 状态、当前责任、数据范围、版本、数量及费用余额在写事务内重验；并发命令不得造成重复任务、重复转单或超分配。
3. 提交结果未知时保留原命令核对，不得更换幂等键重建。前端刷新不得丢弃用户正在编辑的需求、报价或费用草稿。
4. 不可变需求、反馈和来源快照独立于当前商品、地址、报价主数据；读取历史不得使用最新主数据覆盖历史事实。
5. 已引用记录不得物理删除。关闭询价、供应商失效或商品下架不删除既有追溯链。
6. 文件访问重验当前权限及准确附件关系；通知和外部 I/O 在事务外执行，需要一致性保证时使用既有 outbox 机制。

### 对销售反馈精简迁移

1. 部署前停止业务写入并备份目标数据库，执行 `scripts/migrate-simplify-inquiry-feedback.js` 预览；确认目标后使用 `INQUIRY_FEEDBACK_MIGRATION=apply` 执行。脚本清理询价历史反馈、采购工作片段及销售来源快照中的已删除报价字段，保留报价身份、含税单价、税率、有效期和占用台账。
2. 同一商品存在多条存量报价时，脚本必须在写入前终止；完成业务核对后再迁移，不得自动选择一条覆盖历史。
3. 迁移完成后部署匹配的前后端。回滚必须停写，恢复迁移前数据库备份及旧版代码；迁移后已发生业务时须先核对新增记录。
