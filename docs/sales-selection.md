# 销售选品

版本：1.3

状态：草案

适用入口：公司商品池（可售商品列表）

关联：`docs/erp-phase-1.md` 第 4.4 节、第 7.1 节「选品与对客报价」

本文约定销售选品的业务对象、状态、操作约束、交付范围和验收标准。本文是产品实施依据；接口字段、集合与索引、错误码、权限标识及部署参数由实施合同另行落实，不得改变本文已确定的业务规则。本文状态为产品草案，不代表功能已经实现或完成验收。

---

## 1. 目标

销售在公司商品池中筛出或勾选可售 SKU，做成一本只发给一家客户的选品册，把链接发给客户。客户在移动端选品后，系统留下一份销售方案，供后续开销售单使用。

选品册有两种形态，创建时选定：

| 形态 | 客户看到什么 | 替代什么 |
| --- | --- | --- |
| **单品** | 商品池里的一个个 SKU，不组合 | 现在把筛选或勾选结果导出 Excel 发给客户的报价方式 |
| **套餐** | 按档位规则组好的套餐（多个 SKU 的组合） | 线下拼礼包/套餐报价 |

两种形态共用：绑定客户、提交方式、商品池快照、公开选品链接、销售方案。差别只在陈列项怎么从商品池得到，以及卡片封面怎么来。

本能力替代一期第 7.1 节中「选品并对客户报价」的线下动作，不替代销售单、审批、履约或商城兑换执行。Excel 导出仍可留作销售内部底稿，不再作为对客确认介质。

必须同时满足：

1. 组合、计价、是否落入档位、方案金额、套餐主图全部由后端计算或生成；前端只收集规则和选择，展示后端结果。
2. 套餐形态下，生成不是穷举全部排列组合，而是按规则搜索有限、可浏览的结果。
3. 套餐不是公司商品，不得写入商品池，不得成为正式 SKU。单品形态也不为陈列新建商品或 SKU。
4. 套餐主图必须经套餐图生成端口产出；调用方不得自行取 SKU 主图填入套餐封面。正式实现生成独立套餐图，P0 明确允许第 7.4.2 节的首张成员图兜底。单品封面使用该 SKU 主图快照，不走该端口。
5. 客户不登录 ERP。

## 2. 术语

正文直接使用本表名称。禁止用「礼盒」指称套餐。

| 术语 | 定义 |
| --- | --- |
| **选品册** | 一次面向唯一客户的选品活动。包含客户、选品形态、提交方式、商品池快照和陈列项。 |
| **选品形态** | 选品册创建时选定、创建后不可改。取值只有「单品」和「套餐」。 |
| **陈列项** | 客户在选品页上选择的单位。单品形态下是一个 SKU；套餐形态下是一个套餐。 |
| **档位** | 套餐形态下选品册内的价格分组，例如 100 元档、200 元档。只用于生成目标和浏览分组，不是成交价。单品形态不要求档位。 |
| **套餐** | 多个独立 SKU 的组合，属于套餐形态选品册的某一档位。有选品册内稳定身份，不是公司商品、不是 SKU。 |
| **套餐售价** | 套餐内各 SKU 当前快照的销售可见含税价之和。 |
| **套餐主图** | 套餐自己的封面图，由套餐图生成端口根据成员 SKU 图片产出。套餐卡片只展示该字段，不把成员 SKU 图拼成封面。 |
| **套餐图生成端口** | 仅套餐形态使用的后端可替换生成能力。输入为套餐成员 SKU 的有序图片 URL，输出为套餐主图 URL。正式算法未就绪时使用第 7.4.2 节兜底，图片资产管理遵守第 7.4.3 节。 |
| **选品链接** | 发给该客户、无需 ERP 登录的公开地址。客户用它浏览陈列项并提交选择。 |
| **选品会话** | 链接上客户尚未提交的勾选和份数。不是正式单据。 |
| **销售方案** | 客户提交后形成的正式业务记录，编号保存。按份采购与商城兑换两种形态不同，见第 5 节。 |
| **提交方式** | 选品册创建时选定、创建后不可改。取值只有「按份采购」和「商城兑换」。与选品形态独立：单品、套餐都可以按份采购或商城兑换。 |
| **商品池** | 本次使用的可售 SKU 集合，来自公司商品池的当前筛选或勾选，准备陈列时冻结为快照。 |
| **准备批次** | 一次整册准备形成的商品池快照及其生成结果。按档或整册重生成套餐沿用该批次商品池；重新取商品池必须创建新批次。 |
| **会话版本** | 后端每次成功保存选择后递增的版本，用于识别多人修改冲突和确定提交内容。 |
| **会话内自定义套餐** | P1 换品、自组形成的会话子对象，使用已发布商品池快照，不改变选品册原始陈列。 |

「销售方案」不是二期明确不建设的卡券「权益方案」。前者是客户确认的选品结果；后者是商城玩法配置，ERP 不建模。

## 3. 范围

### 3.1 做

1. 从公司商品池发起选品册，绑定一家客户，选定选品形态和提交方式。
2. 单品：把商品池快照做成陈列项并发布链接，客户按 SKU 选择。
3. 套餐：后端按档位规则生成套餐，经生成端口写入套餐主图；销售预览后发布，客户按套餐选择。
4. 提交后形成销售方案，销售可在内部查看。

### 3.2 不做

1. 不把套餐写入公司商品池，不为套餐或单品陈列创建 `product` / `sku`。
2. 不在前端计算组合、档位归属或方案金额。
3. 不穷举商品池的全部 SKU 组合。
4. 不把销售方案当作销售单：无审批、无应收、无履约、无库存预占。
5. 本阶段不从销售方案创建销售单。
6. 本阶段不向商城发布陈列项、不下发执行投影、不开卡券销售单。仓库内商城域已移除，商城兑换只把「选了哪些陈列项」记在方案上。
7. 不建设客户 ERP 账号，不要求客户登录。
8. 不把本页做成福利商城：无支付、无员工订单、无积分。
9. 第一期不建设按品类槽位搭配（例如「茶 1 + 坚果 1 + 零食 1」）。
10. 一本选品册不得发给第二家客户；两种提交方式不得写进同一份销售方案；一本选品册不得同时是单品又是套餐。
11. 套餐封面只读取后端生成端口的结果；前端不得自行挑选或拼贴成员图。P0 允许且仅允许第 7.4.2 节的成员图兜底例外。
12. 不以 Excel 文件作为客户确认选品的正式结果。导出仍可保留给销售自己使用。

### 3.3 与现有能力的关系

| 现有对象 | 关系 |
| --- | --- |
| 公司商品池 | 选品入口和 SKU 来源。资格规则不变：启用、已维护销售可见价、业务时点有效且当前可供的供给。 |
| Excel 导出 | 内部底稿。对客报价改走选品链接；不删除导出能力，也不再把导出文件当作客户已确认的方案。 |
| 客户 | 选品册创建时必填，之后不可改绑。 |
| 实物与服务销售单 | 按份采购方案的后续去向：按陈列项份数拆成 SKU 行。本阶段不实现。 |
| 卡券销售单 | 商城兑换方案的可能后续去向（卡券开单 + 商城可兑范围）。本阶段不实现。卡券销售单仍遵守「一单一条卡券明细」；多档位若开卡券单必须按面额等差异拆单。 |
| 福利商城 | 员工兑换的执行场所。本能力不替代商城，不在本阶段写商城。 |

## 4. 对象与生命周期

### 4.1 选品册

必填：客户、选品形态、提交方式、商品池。套餐形态另必填至少一个档位。

状态：

```text
草稿 → 准备中 → 待发布 → 已发布 → 已提交
已发布 → 已关闭（主动关闭或到期）
草稿、待发布 → 已作废
待发布 → 准备中（重生成或整册重新准备）
准备失败 → 首次准备回草稿；从待发布发起则恢复原待发布结果
```

| 状态 | 含义 | 允许的动作 |
| --- | --- | --- |
| 草稿 | 已保存创建字段，尚无完整可预览结果 | 在固定来源类型内改筛选或勾选，改档位规则，开始准备，作废 |
| 准备中 | 后端正在冻结快照或生成套餐及主图 | 查看进度；不得编辑、发布、删除陈列或再次启动任务；失败恢复规则见第 7.6 节 |
| 待发布 | 已有完整可预览陈列项 | 删除陈列项；同批次重生成套餐；整册重新准备；发布；作废 |
| 已发布 | 在链接有效期内且尚未提交 | 客户改会话、提交；销售查看会话、复制或更换链接、关闭链接；不得改快照与陈列 |
| 已提交 | 已形成唯一销售方案，会话已冻结 | 内部查看方案；有效链接只读查看本次提交回执；销售可撤销链接访问 |
| 已关闭 | 未提交即被主动关闭或到期 | 内部只读；公开页只显示结束态；不得重新开启 |
| 已作废 | 发布前终止的选品册 | 内部只读；不得准备、发布或恢复 |

规则：

1. 客户、选品形态、提交方式、商品池来源类型在创建时写入，之后不可修改。需要更换时另建选品册；原册按其状态作废、关闭或保留已提交记录。
2. 发布固定销售确认过的准备批次及删减结果，不重新取价或换图。发布复核遵守第 7.5 节。
3. 一本选品册对应一家客户、一种选品形态、一种提交方式，同时最多有一条有效链接、一份销售方案。未发布时没有公开链接。
4. 已提交、已关闭、已作废均为业务终态。已提交后撤销链接访问不改变已提交状态，不删除或作废方案。
5. 状态变更、删除陈列和启动任务必须校验选品册版本。请求基于旧版本时整次拒绝并提示刷新，不覆盖较新操作。
6. 到期判断以服务端时间为准。即使后台尚未把已发布状态更新为已关闭，已到期请求也必须立即被拒绝。
7. 创建选品册、发布、更换链接、关闭、撤销访问和作废均须有请求幂等键。同键同请求返回原操作事实，同键不同请求拒绝。返回原操作结果前仍须校验当前访问权限；发布或更换链接之后令牌已再次变化的重试，只返回原操作已完成及当前状态，不重新启用或泄漏旧令牌。

### 4.2 档位

仅套餐形态使用。每个档位必须填写：

| 字段 | 含义 |
| --- | --- |
| 名称 | 如「100 元档」 |
| 目标金额 | 生成时套餐售价的瞄准值，含税 |
| 容差 | 套餐售价相对目标金额的允许偏差，含税；必须显式填写 |
| 套餐数量 | 本档希望生成多少个套餐 |
| 每套餐 SKU 数 | 每个套餐包含多少个独立 SKU |

目标金额必须大于 0，容差必须大于或等于 0；金额区间下限按 0 处理。档位名称在册内不得重复；数量和 SKU 数必须为整数并符合第 7.1 节上限。同一套餐每个成员固定为 1 个基础单位，不支持同 SKU 多件；“每套餐 SKU 数”不是成员各自的采购数量。

档位之间允许目标金额接近，但每个套餐只归属创建时指定的那一档，不得因售价同时落入另一档而重复展示。

单品形态不填档位，不按档位生成。客户页按商品池快照陈列；实施合同时可增加按售价或分类的浏览筛选，那是展示过滤，不是生成规则。

### 4.3 陈列项

陈列项是选品册的子对象，准备时写入，发布后冻结。

**单品：** 商品池中每个仍具备销售资格的 SKU 对应一个陈列项。

1. 恰好一个 SKU：稳定身份、修订、所属 SPU、商品类型、名称、结构化规格属性、单位、图片资产引用、销售可见含税价。规格取稳定 SKU 的结构化属性，不从名称猜测或以自由规格文案替代。
2. 售价 = 该 SKU 销售可见含税价。
3. 封面 = 该 SKU 主图快照。无主图时仍可进入选品册，卡片用空态，不得因此整册失败。
4. 不调用套餐图生成端口。

**套餐：** 见第 4.4 节。

销售在待发布状态可以删除个别陈列项。单品形态删除后至少保留 1 个 SKU 才可发布。套餐形态每个档位至少保留 1 个套餐才可发布。

### 4.4 套餐

套餐是套餐形态下的陈列项，生成时写入，发布后冻结。

每个套餐包含：

1. 选品册内稳定身份和所属档位。
2. 有序列表：SKU 稳定身份、SKU 修订、所属 SPU、商品类型、分类、名称、结构化规格属性、单位、图片资产引用、销售可见含税价。同一套餐内 SKU 不得重复。成员图片用于明细和生成端口输入；P0 允许由端口将首张成员图登记为套餐主图。
3. 套餐售价 = 上列销售可见含税价之和，由后端写入，客户端不得回传作为事实。
4. 套餐主图引用，由第 7.4 节生成端口结果登记形成；对外输出经授权的预览 URL。套餐卡片只使用该字段。

销售在待发布状态可以删除个别套餐，或对某一档、整册请求重新生成。不得手工拼装套餐 SKU 列表（换品、自组是客户在已发布链路上的选择方式，见第 8 节，不在销售预览里做）。

### 4.5 选品链接与会话

#### 4.5.1 链接授权与有效期

1. P0 采用持链接者可操作模式，不验证其联系人身份。绑定客户只确定业务归属，不构成联系人身份认证。销售仅向绑定客户发送链接；页面不得显示“已认证联系人”等表述。
2. 发布时生成至少 128 位安全随机令牌，P0 有效期固定为发布后 30 × 24 小时。发布后不得延长原册有效期；到期后需要继续选品时新建选品册。
3. 令牌不使用员工 JWT。校验使用令牌哈希；为支持销售以后再次复制同一链接，另保存经服务端密钥加密的令牌密文。禁止明文落库；密钥不得与令牌密文同库保存。内部复制接口经授权解密返回，并记录复制动作，不记录完整链接或令牌。
4. 已发布期间允许销售“更换链接”：原令牌立即失效，新令牌沿用原到期时间、会话和快照。更换必须校验版本并原子完成。旧页面后续保存、提交和图片请求均失去权限；页面须说明原链接已失效。
5. 关闭未提交选品册、撤销已提交选品册的链接访问后，公开页只展示结束态，不再返回商品、会话、方案或图片。已提交且链接未撤销、未到期时，只允许查看第 4.6 节回执；到期后也只展示结束态。
6. 封面图和成员 SKU 主图走该册令牌授权的预览接口，不复用 `/admin/file-assets`，不直接下发绕过令牌授权的永久对象存储地址。已经下载到客户端的内容不属于撤销可收回的范围。

#### 4.5.2 会话保存与并发

1. 同一选品册共用一份会话，首次发布建立空会话及初始版本。会话不编号、不进入经营账本。
2. 保存请求携带预期会话版本、请求幂等键和完整选择集合。后端仅接受本册允许选择的项；重复项身份、非法份数、超限或其他册的项均使整次保存失败。
3. 后端原子校验版本并保存，成功后递增会话版本，返回完整选择、份数和重新计算的金额；商城兑换不返回成交金额合计。相同幂等键、相同请求重试返回原保存结果，不再次递增版本；同键不同请求拒绝。
4. 旧版本保存或提交必须返回冲突。页面保留本地未保存选择供核对，展示后端最新结果，不得自动覆盖他人修改、静默合并或把旧页面直接重试成成功。
5. 提交前必须完成待保存请求，再展示后端确认清单及其会话版本。若该版本之后被他人修改，必须重新展示最新清单并由客户再次提交。
6. 保存、提交和更换链接发生竞争时，必须同时校验当前令牌版本和选品册状态，不能仅在请求开始时检查一次权限。

### 4.6 销售方案

客户提交成功后创建，一经创建不可改明细。P0 不支持作废方案、替换方案或同册重新提交；错误提交须保留原事实，由销售按现有业务方式跟进，不得把关闭链接表示为撤销客户选择。关联原方案的重新选品及作废操作在 P1 交付。

表头固定包含：方案编号、客户稳定身份及名称快照、选品册、准备批次、选品形态、提交方式、已提交会话版本、服务端提交时间、提交来源（P0 为公开链接）。客户身份和提交方式必须从选品册取值，不能由公开请求改写。明细形态见第 5 节。

提交执行规则：

1. 提交请求携带预期会话版本和请求幂等键。后端以该版本已保存的完整选择为事实来源，重新校验项归属、份数、金额和状态；客户端金额不参与事实写入。
2. 创建方案表头及全部明细、建立册与方案的唯一关系、冻结会话、将册置为已提交，必须在同一原子业务操作中完成。任一步失败全部回滚，不允许存在无明细方案或已提交却无方案的册。
3. 一本选品册唯一关联一份方案须由持久化唯一约束保证。相同幂等键和相同请求的重试返回原方案回执；同键不同请求拒绝。其他请求在册已提交后只返回已提交事实，不再创建方案或改写明细。
4. 关闭与提交竞争时，以原子状态变更成功的一方为准：关闭先成功则提交拒绝；提交先成功则关闭操作不得再把册变成已关闭，销售刷新后可执行撤销链接访问。
5. 网络断开、超时或响应丢失不能视为确定失败。客户端保留幂等键和提交版本，暂停编辑，通过原请求重试或查询回执核对结果；不得另生成幂等键重复提交。令牌已失效时仅展示失效态并提示由销售核对，不越权返回回执。
6. 成功回执包含方案编号、提交时间、客户展示名称和已提交明细；按份采购含份数、金额，商城兑换不含份数与成交合计。公开回执不返回内部管理地址及敏感字段。

## 5. 提交方式

选品册创建时必须选定恰好一种。客户页只提供这一种提交形态。同一客户若两种生意都要做，开两本选品册。单品和套餐都可以使用两种提交方式。

### 5.1 按份采购

客户选择哪些陈列项、每个多少份。份数必须为正整数。

方案明细：

| 层 | 内容 |
| --- | --- |
| 陈列项行 | 陈列项身份、封面、份数、售价、行金额 = 售价 × 份数。套餐形态另记档位。 |
| SKU 行 | 单品：该 SKU，单价为快照销售可见含税价，数量 = 份数。套餐：每个成员 SKU，数量 = 套餐内件数 × 份数。行金额 = 单价 × 数量 |

方案合计 = 全部陈列项行金额之和，并必须等于全部 SKU 行金额之和。P0 每个套餐成员为 1 个基础单位，因此每个成员 SKU 的数量等于套餐份数。不同套餐中相同 SKU 分别保留所属陈列项的明细，不在方案存储时合并；汇总展示可以合计，必须保留来源关系。

后续（不在本文交付）：据此创建实物与服务销售单，明细为 SKU 行，数量和含税单价取方案快照，提交前按当时公司商品池重新校验销售资格。

### 5.2 商城兑换

客户只勾选哪些陈列项，不填份数。这些项表示以后放到商城、由客户员工自行兑换的范围。

方案明细：

| 层 | 内容 |
| --- | --- |
| 陈列项行 | 陈列项身份、封面、售价；份数为空。套餐形态另记档位。 |
| SKU 行 | SKU 快照；数量为空 |

方案**不写**采购份数，**不写**成交金额合计。售价仅供阅读，表示按 SKU 销售价（套餐则为加总）的价值，不表示本方案已向客户收取该金额。

后续（不在本文交付）：不得按本方案拆 SKU 去开实物销售单。若开单，方向是卡券销售单以及把陈列项同步为商城可兑商品；卡券仍须遵守一单一条明细，跨档位须拆单。本阶段只落方案。

### 5.3 禁止混用

1. 按份采购的提交必须带齐每个已选陈列项的份数；缺份数则整单失败。
2. 商城兑换的提交携带份数则整单失败。
3. 一次提交不得部分按份、部分兑换。
4. 未选任何陈列项不得提交。

## 6. 价格

1. 本能力唯一报价及方案计价口径：SKU 的销售可见含税价，来源是准备批次商品池快照中的 `sales_visible_price_gross`。方案金额不构成应收、实收或履约承诺。
2. 单品陈列项售价 = 该 SKU 销售可见含税价。套餐售价 = 其 SKU 销售可见含税价之和。不得把档位目标金额写成售价或方案成交价。
3. 档位目标金额和容差只用于套餐形态：生成时过滤候选、客户浏览时分组。200 元档下出现 198、203 是正常结果。
4. 按份采购的方案金额全部由后端用快照单价和份数重算。客户端上报的金额只可作展示核对，不得作为写入事实。
5. 发布后快照价格不变。商品池此后改价不影响已发布选品册和已形成的销售方案。
6. 本能力不写入供应商成本，不在客户页展示成本或毛利。
7. 币种为人民币，使用现有金额类型按十进制定点运算，不使用二进制浮点数计价。不得在套餐加总前另行截断单价；全部金额须可由现有金额类型精确表达。份数乘法、行金额及合计超出可表示范围时整次拒绝，禁止溢出、截断或按零处理。

## 7. 商品池与准备陈列

### 7.1 进入选品

入口为公司商品池页面，与导出并列，不在列表页内嵌生成器。销售发起时同时选择选品形态和提交方式。

商品池来源二选一，创建时写死：

| 来源 | 何时用 | 后端做什么 |
| --- | --- | --- |
| 当前筛选 | 表格模式，或未勾选时 | 按与列表相同的筛选和销售资格取出 SKU |
| 当前勾选 | 选品模式已勾选 | 按勾选的 SKU 身份取出，并再次校验销售资格 |

前端提交筛选条件或 SKU 身份，以及形态和规则；不提交算好的套餐或方案。后端复用公司商品池的筛选和资格规则，不以浏览器已加载行或当前页代替全部筛选结果。

1. 当前筛选：冻结规范化筛选条件，准备时按服务端当前业务日期执行；分页参数不属于来源条件。浏览时指定的历史资格日期不沿用为对客销售资格日期。
2. 当前勾选：冻结去重后的稳定 SKU 身份集合，准备时按当前修订重新校验。任何一个已选 SKU 不存在或失去资格，整次准备失败并列明失效项，销售调整后重试；不得静默剔除。
3. 筛选结果为空或超出上限时整次失败。集合按稳定 SKU 身份升序排列，单品陈列及套餐成员顺序均采用此顺序，不依赖数据库自然顺序或浏览器勾选顺序。
4. 每批冻结同一读取一致性边界内的成员、精确修订、价格与商品资料，并记录资格业务日期和冻结时间。异步生成开始后不得逐档重新查询当前商品资料。
5. 快照还须包含 SPU 身份、商品类型和分类身份，用于组合偏好及后续追溯；未分类作为缺失事实保存，不得虚构分类。同批次全部陈列使用同一份商品池快照。

P0 采用以下强制限制；这些数字是交付上限，不代表已通过性能实测。变更必须同步本文与验收数据，不得只调整前端限制。

| 项目 | P0 限制 |
| --- | --- |
| 每册商品池 SKU 数 | 1–500 |
| 套餐档位数 | 1–10 |
| 每档期望套餐数 | 1–20 |
| 每套餐独立 SKU 数 | 2–8，且不得超过商品池 SKU 数 |
| 每册陈列项数 | 单品最多 500；套餐最多 200 |
| 每个已选陈列项份数 | 按份采购为 1–100000 的整数；商城兑换禁止携带 |
| 单档搜索预算 | 最多展开 100000 个搜索状态，或累计搜索执行 5 秒，先到者停止 |
| 一次准备任务期限 | 从任务创建起 180 秒，包含排队、快照、搜索、图片和写入；到期失败并执行第 7.6 节恢复规则 |

“搜索状态”指算法访问的一次部分组合或完整组合，包括最终被剪枝的节点；计数不得只统计成功套餐。服务端在创建、准备、保存和提交各入口执行对应限制；超限整次拒绝，不截断后返回成功。

### 7.2 单品：冻结陈列

单品形态不组合、不搜索套餐。

后端按第 7.1 节稳定顺序为每个合格 SKU 写一个陈列项，冻结名称、结构化规格、单位、销售可见价和图片资产引用。销售预览后可删除，然后发布。

无主图的 SKU 仍进入陈列，封面为空态。准备过程可以很快，但仍走「准备中」状态，由后端写快照，不在浏览器里拼客户页数据。

### 7.3 套餐：组合生成

生成是搜索，不是笛卡尔积。仅套餐形态执行本节。

#### 7.3.1 硬条件与去重

1. 每个套餐包含该档规定数量的独立 SKU，每个成员固定为 1 个基础单位。
2. 套餐售价落在目标金额 ± 容差内，包含边界。全部成员来自当前准备批次商品池。
3. 同一套餐内 SKU 不重复。同一 SKU 集合无论顺序如何均为同一组合；同档不得重复，同册跨档也不得重复陈列。
4. 档位按创建顺序处理；同一组合同时满足多档时，归首次实际接纳它的档位。按档重生成须排除未重生成档位已经占用的组合。
5. 不得为凑数量降低上述条件。套餐必须取得有效封面后才计入可交付数量。

#### 7.3.2 搜索偏好与预算

同 SPU 多规格共存、同分类集中、套餐近似均为排序偏好，不是 P0 的硬拒绝条件。在本次预算内已找到的合格候选中，按下列顺序逐个择优，直到达到期望数量：

1. 同套餐重复 SPU 成员数更少的优先。
2. 已知分类种类更多的优先；缺失分类不计为一个新分类。
3. 与本档已接纳套餐的最大 SKU 重合数更少的优先；尚无套餐时此项为 0。
4. 与档位目标金额绝对差更小的优先。
5. 仍相同时按成员稳定 SKU 身份序列升序决定。

候选搜索不得无界穷举。每次运行记录算法版本、搜索顺序或随机种子、展开状态数、耗时和停止原因。任务重试使用同一运行参数；销售主动重生成可以改变搜索种子，但不改变商品池快照和规则，不承诺一定产生不同套餐。

#### 7.3.3 完成与失败

| 结果 | 处理 |
| --- | --- |
| 全部档位达到期望数量 | 准备成功，进入待发布 |
| 每档至少 1 套，但部分档不足期望数量 | 允许进入待发布；逐档显示期望数量、实际数量、停止原因，销售预览确认实际结果后方可发布 |
| 任一档为 0 套 | 整次失败；不得提交其他档的新结果，按第 7.6 节恢复 |
| 搜索预算用尽 | 保留预算内得到的合法候选，按以上数量规则判定；提示“本次搜索达到上限”，不得宣称不存在合法组合 |
| 已完整搜索有限空间或由金额上下界等条件证明无解 | 可以提示“无合法组合”，须记录具体依据；不能将启发式搜索未命中当作证明 |
| 图片失败造成套餐不足或某档为 0 | 分别按不足或失败处理，并单列图片失败数量及原因，不归因为价格无解 |
| 任务到期、服务异常或快照写入失败 | 整次失败；不得以已有部分结果冒充准备成功 |

生成必须作为后端任务执行。页面展示排队、冻结快照、组合搜索、图片处理、写入结果等阶段和已完成档位数，不以不确定的组合空间计算虚假完成百分比。

### 7.4 套餐主图生成

仅套餐形态适用。正式实现必须生成独立套餐图片；P0 明确允许第 7.4.2 节返回首张成员图作为兜底，不以兜底图片验收正式合成效果。两种实现均必须经同一端口，套餐卡片、列表和分享页只读取套餐主图字段。

单品形态不适用本节：单品封面就是该 SKU 主图快照。

真正的合成或绘制算法尚未确定。编码时必须先抽象生成端口，再用可替换实现接入；未就绪前使用本节兜底实现。调用方只依赖端口，不判断当前是兜底还是正式生成。

#### 7.4.1 端口

名称：套餐图生成端口。

| 项 | 约定 |
| --- | --- |
| 输入 | 该套餐成员 SKU 的有序图片 URL 列表，顺序与套餐内 SKU 顺序一致。无图的成员仍占位，URL 为空。 |
| 输出 | 一条套餐主图 URL。 |
| 时机 | 每个套餐在组合确定之后、写入选品册之前调用一次。换品或自组形成新套餐时同样调用。 |
| 失败 | 端口返回失败则该套餐不得写入有效陈列。若因此某档为 0 套，整次生成失败；首次准备或重生成分别按第 7.6 节恢复。 |
| 禁止 | 绕过端口，把某个 SKU 主图 URL 或文件身份直接写入套餐主图字段。 |

端口可以是同步或异步；正式生成若调用外部绘图服务，由实现处理超时和失败，不得把外部细节泄漏到客户页。

预留但不作为本期输入的上下文（档位名称、SKU 名称、套餐售价等）等正式算法确定后再扩，不在兜底实现中使用。

#### 7.4.2 兜底实现

在正式算法就绪前，唯一允许的实现是：**按套餐内 SKU 顺序，取第一张非空图片 URL，作为套餐主图 URL。**

规则：

1. 从左到右扫描成员 URL，跳过空值和只含空白的值。
2. 命中的第一张即为输出；结果确定，不随机。
3. 全部成员都没有可用 URL 时，该套餐生成失败，不得用占位图或空白 URL 冒充已生成。
4. 兜底输出的字符串可以与某一成员 SKU 图片 URL 相同，这是 P0 允许的明确例外。独立保存套餐主图引用并记录生成实现版本，前端只读套餐主图字段。
5. 正式实现替换兜底后，端口改为产出新生成的图片 URL（新文件或新地址）。选品册生成、预览、客户页不因实现替换而改调用方式。
6. 已发布选品册和已提交方案继续引用当时的套餐主图资产，不因后来换了生成实现而重跑；临时访问 URL 的签发不改变图片快照。

兜底不得：

- 在前端挑选封面。
- 把多张 SKU 图在页面上拼成封面冒充「已生成」。
- 把全部成员图 URL 存进套餐主图字段。

#### 7.4.3 图片资产、授权与保留

1. 准备快照时从 SKU 的主图文件资产身份解析图片，固定不可变对象版本；现有资产不能保证内容不变时，复制为选品快照资产。图片不存在或不可读取时按无图处理并在销售预览中提示，不伪造可用 URL。
2. 后端适配层把快照资产转换为供生成端口读取的受控 URL；无图保留空位。端口不读取客户端任意提供的外部 URL。P0 返回成员图时复用该快照资产引用；正式生成返回新图时须先写入受管存储并登记资产，完成后才能接纳套餐。
3. 长期事实保存文件资产身份、不可变对象版本或内容校验信息、生成实现版本。生成端口的临时输入输出 URL 不作为唯一持久化依据；公开响应中的预览 URL 由这些引用转换得到。
4. 公开图片请求每次校验当前令牌、册状态、到期时间及资产是否属于该册授权展示范围。仅持有任意文件 ID 不构成访问授权；P0 不得借图片接口浏览被销售删除、未发布或其他册的商品。
5. 图片响应不得被公共缓存绕过授权；关闭、更换令牌或撤销访问后，旧 URL 再次请求必须被拒绝。内部历史预览仍走管理端权限。
6. 已发布快照及方案引用的图片不得因商品池换图、文件常规清理或更换生成实现而被覆盖、删除。与所引用业务记录一并保留；解除保留须走独立的数据保留规则，不在本功能提供销毁入口。失败任务的临时图片仅在确认无有效引用后清理。

### 7.5 销售预览

待发布时，销售查看陈列项卡片后发布。

单品：卡片为 SKU 主图、名称、规格、售价。可删除单项，不可「重生成组合」。

套餐：按档位查看（套餐主图、SKU 清单、套餐售价、与目标金额的差额），可以删除不合适的套餐，或对某一档、整册重新生成。

销售预览必须显示准备时间、资格业务日期、实际陈列数量、被删项目数量、缺图提示，以及每档期望数与实际数。发布请求携带已确认的选品册版本和准备批次，不接受浏览器回传陈列明细替代后端快照。

发布时按服务端当前业务日期重新校验实际陈列成员的精确 SKU 修订及销售资格；任何陈列成员失效或当前修订变化，整次发布失败并列明项目。不得发布时刷新价格、换图或静默移除成员。销售可以删除受影响陈列项后重新预览发布；需要采用新商品资料时整册重新准备。

复核通过、陈列非空且每档至少一套后，原子固定当前批次及删减结果并发布，生成唯一有效链接。发布重试返回同一发布结果，不创建多条链接。

发布后至链接到期前，客户按已发布快照保存、提交，不再次以当前商品池变化拒绝原快照，不自动改价或移除商品。销售发现不可继续报价时负责关闭链接；本功能不预占库存、不保证后续履约，后续销售单仍须按当时规则复核。

### 7.6 重生成、重新准备与任务恢复

| 动作 | 使用的数据 | 成功替换范围 | 失败结果 |
| --- | --- | --- | --- |
| 草稿首次准备 | 重新读取当前商品池，创建准备批次 | 整册快照和陈列 | 回草稿，保留创建条件及失败原因 |
| 待发布按档重生成套餐 | 当前批次的固定商品池和档位规则 | 仅指定档全部陈列；其他档及其删减结果不变 | 恢复原待发布结果，不丢失原套餐和删除记录 |
| 待发布整册重生成套餐 | 当前批次的固定商品池和档位规则 | 全部档位陈列 | 恢复原待发布结果 |
| 待发布整册重新准备 | 在固定来源类型内修改筛选、勾选或档位规则，重新读取商品池并创建批次 | 整册快照、规则和陈列 | 恢复原待发布结果；失败请求单独留存，不改原有效规则 |

1. 待发布修改商品池或档位规则必须通过整册重新准备，不得在旧陈列上直接覆盖规则。单品不支持组合重生成，但支持整册重新准备。
2. 新结果在独立任务批次内暂存，全部通过后一次替换对应有效结果。重生成范围内此前删除的项允许重新出现，界面必须说明该范围的删减会被重置；失败不得重置。
3. 同册同时最多一个活动准备任务。创建任务与册进入准备中须保持一致；同一幂等键、同一请求重试返回原任务，不重复执行，同键不同请求拒绝。进程重启后任务必须能够恢复或明确失败，不能永久停留在准备中。
4. 工作进程写入结果时必须验证任务身份、运行版本和册版本。已到期、已失败或被后续任务替代的运行结果不得覆盖有效结果；重复完成通知不重复写入。
5. 执行期限到达后系统终止接纳该任务结果，恢复相应业务状态并记录失败。销售重新发起的任务是新运行，不延续旧任务写入权限。

## 8. 客户选品页

公开、移动端优先的浏览和选择页，不是内网工作台的响应式缩放。单品和套餐共用同一类页面，按选品形态切换卡片内容。

### 8.1 共同展示

1. 单品按商品列表展示；套餐按档位分组展示。
2. 每个陈列项卡片的封面：单品用 SKU 主图快照，套餐只用套餐主图。
3. 套餐成员资料展示于套餐明细；封面只读套餐主图字段，P0 允许该字段经端口引用成员图。
4. P0 不展示供应商、成本、内部商品编码、SKU 编号、修订 ID 或用户身份。公开选择所需身份使用该册内的项标识，不直接暴露管理端资料对象。
5. 链接无效、已关闭、到期或已撤销时显示结束态；已提交且链接仍有效时显示只读回执。所有结束态均不得留下可写表单。
6. 页面标明“选品报价不预占库存，后续销售单另行确认”。商城兑换另标明“本次仅确认可选范围，尚未上架商城”。确认按钮文案为“确认并提交选品”，不得显示为支付或开单。

### 8.2 按份采购

客户选择陈列项并填写每个已选项的份数。套餐形态允许跨档位。底部展示已选清单和后端计算的金额合计。提交后形成第 5.1 节形态的销售方案。

### 8.3 商城兑换

客户多选陈列项，不出现份数步进，不出现成交金额合计。可展示已选个数及各售价供阅读。提交后形成第 5.2 节形态的销售方案。

### 8.4 选择方式

为让客户尽快完成，套餐形态应支持多种选择方式。单品形态的主路径就是点选 SKU，不提供换品、自组。交付分批见第 11 节。

| 方式 | 适用形态 | 行为 | 约束 |
| --- | --- | --- | --- |
| **点选商品** | 单品 | 直接选中 SKU | 单品主路径 |
| **整套选** | 套餐 | 直接选中已生成的套餐 | 套餐主路径 |
| **换品** | 套餐 | 以某套餐为底，替换其中若干 SKU | 替换后必须仍在该档容差内，候选由后端给出 |
| **自组** | 套餐 | 从该册已发布商品池快照中自选，并指定来源档位 | SKU 数等于该档规则，售价落入容差，由后端判定 |

换品和自组的结果仍是一个套餐（SKU 组合），按当前提交方式进入会话：按份采购仍要份数，商城兑换仍无份数。新套餐必须再次经过第 7.4 节生成端口写入套餐主图。不得因此把套餐写回公司商品池。

P1 数据归属与约束：

1. 结果保存为会话内自定义套餐，包含独立身份、所属会话、来源档位、来源套餐（换品必填，自组为空）、完整 SKU 快照、价格及图片引用。不得新增、替换或修改已发布选品册的原始陈列。
2. “本档商品池”指本册已发布商品池快照在该档件数、金额规则下可使用的成员，不另建动态商品池，不读取生成之后的实时售价。候选的公开访问仅在 P1 开启该能力后授权。
3. 自定义套餐遵守成员互异、每成员一件、数量、金额和图片规则。会话内相同组合须复用已有项身份；若与原陈列相同则复用原陈列项，不用新身份绕过重复校验。
4. 后端生成及图片登记完成后才可加入会话。异步结果返回时会话版本已变化，必须由客户重新确认加入，不自动覆盖最新选择。任务失败不修改会话。
5. 方案行保留来源类型（原始陈列或会话内自定义）、来源身份及完整快照；不得把所有方案行限定为必须引用原始陈列项。提交后自定义套餐随方案冻结，未提交的生成草稿不构成客户确认结果。
6. P0 接口须拒绝换品、自组请求。P1 上线前须另行锁定自定义套餐数量、生成频率及资源预算，并补齐对应验收，不得沿用 P0 的原始陈列数量上限作为无限生成的授权。

## 10. 权限与公开边界

1. 选品册和方案内部访问走现有管理端认证与 RBAC。实施合同必须分别登记查看选品册、创建及维护、准备及重生成、发布、复制链接、更换链接、关闭或撤销访问、发布前作废、查看方案的权限标识，并配置销售角色；不得以一个管理端登录条件代替操作授权。
2. 客户选品页走公开路由，与 `/admin` 隔离。令牌只授权该选品册的读展示、改会话和提交。
3. 公开接口必须限流。禁止通过链接枚举其它客户的选品册。
4. 公开响应不得包含采购成本、供应商身份、内部用户、毛利。
5. 本公开页是 ERP 自己的客户表单，不是商城 API，也不是一期禁止的外发商城/供应商接口。仍须与内部账本隔离。
6. 内部创建及访问须校验现有客户访问范围；记录创建人、更新人、发布人及关键动作时间。P0 不新增审批类型或工作项类型，也不允许借用销售单编号或审批状态表示方案。
7. 公开接口通过专用响应字段清单返回数据，不直接序列化商品池内部投影、选品册实体或任务实体。错误信息也不得泄漏其他客户、供应商或内部路径。
8. P0 按来源 IP 与册令牌分别限制：读取每分钟 120 次、会话写入每分钟 30 次、提交每分钟 10 次；图片每分钟 600 次。非法令牌按来源 IP 限流，不能为任意输入建立无限限流键。多实例部署必须实现同一逻辑配额；超限返回可重试时间，不重复执行写入。
9. 公开页面和接口的日志、访问分析、错误上报、Referer 及第三方资源请求不得携带完整令牌。页面设置禁止发送 Referer，不接入会采集完整地址的第三方脚本。请求幂等记录至少覆盖该册公开访问有效期，方案与唯一关系按业务记录保留。
10. 正式实施前须完成集合唯一约束、状态条件更新、任务恢复、图片保留、公开路由与限流配置，并将错误码对应到冲突、结束、超限、准备失败和提交结果待核对等业务状态；不得以通用“操作失败”覆盖全部场景。

## 11. 分期

### 11.1 本期（P0）

1. 公司商品池发起选品册：绑定客户、选定选品形态和提交方式、提交商品池；套餐形态另提交档位规则。
2. 单品：后端冻结 SKU 快照为陈列项，销售预览删除后发布，得到链接。
3. 套餐：后端生成套餐，经套餐图生成端口写入套餐主图（P0 使用第 7.4.2 节兜底实现），销售预览删除/重生成、发布得到链接。
4. 客户移动端浏览并提交：单品为点选商品，套餐为整套选。
5. 按份采购与商城兑换两种方案形态都要能落库；客户页按选品册提交方式切换，不在一页混用。
6. 销售可查看选品册和已提交方案。
7. Excel 导出保留，不作为本能力的客户确认步骤。

P0 实施先打通**单品 + 按份采购**，再接套餐与商城兑换。完整 P0 必须验收单品 × 按份采购、单品 × 商城兑换、套餐 × 按份采购、套餐 × 商城兑换四种组合；不得以第一条路径完成代替整个 P0，不得只做后两者的界面开关。本文规定的状态、并发、幂等、任务恢复、快照和图片授权均属于 P0。

### 11.2 随后（P1）

1. 套餐换品、自组；新套餐仍走同一套餐图生成端口。
2. 销售代客户勾选并提交（电话确认后内部代录）。
3. 已提交方案的作废与同客户重新选品的操作路径：保留原方案并建立新旧方案来源关系；不得恢复原册为可提交状态，也不得覆盖原方案。生效规则及作废权限须在 P1 实施前补充验收。
4. 用正式套餐图生成实现替换第 7.4.2 节兜底；已发布快照不回刷。

### 11.3 不在本文（P2）

1. 从按份采购方案创建实物与服务销售单。
2. 从商城兑换方案创建卡券销售单，以及把陈列项同步到商城可兑范围。

P2 必须另写产品说明，并遵守销售单混单禁令和卡券一单一明细。

## 12. 验收

产品验收以业务事实为准，不接受「页面能点」代替规则。

1. 未选客户、未选选品形态或未选提交方式不能创建选品册。
2. 同一选品册不能改绑客户，不能改选品形态，不能把按份采购改成商城兑换。
3. 单品陈列项售价等于该 SKU 销售可见含税价；套餐售价等于其 SKU 销售可见含税价之和；档位目标金额不得被写成售价。
4. 套餐生成结果数量有限，且每个套餐都落在对应档位容差内；任一档未得到可交付套餐时整次失败并恢复规定状态，不返回空档位充当成功，不误将选品册置为已关闭。
5. 客户端不提供计算金额时，提交仍能得到与后端快照一致的方案金额（按份采购）或无份数、无成交合计的方案（商城兑换）；伪造客户端金额不能改变后端写入结果。
6. 按份采购方案：陈列项行金额之和 = SKU 行金额之和 = 表头合计。单品的 SKU 数量 = 份数；套餐的 SKU 数量 = 套餐内件数 × 份数。
7. 商城兑换方案：无份数、无成交合计；携带份数的请求被拒绝。
8. 客户不登录即可打开有效链接；关闭后不能提交；链接不能读到成本或供应商。
9. 公司商品池改价后，已发布选品册和已提交方案的价格不变。
10. 数据库中不存在因本功能创建的公司商品或 SKU。
11. 套餐卡片封面来自套餐主图字段，不是调用方或前端直接取用的某张 SKU 主图。单品卡片封面来自该 SKU 主图快照，不经套餐图生成端口。
12. 套餐主图必须经生成端口写入；P0 兜底为实现「第一张非空成员图 URL」，成员均无图的套餐不得落库。
13. 替换生成实现后，新生成的套餐选品册走新实现，已发布选品册和已提交方案的套餐主图不变。
14. 单品选品册发布后，客户页陈列的 SKU 集合与销售确认发布的快照一致，而不是让客户打开一份 Excel。

### 12.1 P0 必验场景

以下场景必须保留请求结果、对应业务状态及持久化事实。涉及公开页面的场景还须使用未登录浏览器验证。

| 场景 | 必须满足的结果 |
| --- | --- |
| 四种形态与提交方式组合 | 均能创建、准备、发布、保存、提交及内部查阅；仅按份采购产生份数与方案合计 |
| 双击提交、响应丢失后原请求重试 | 同册始终一份方案、同一编号、同一提交内容；返回原回执，不重复写明细 |
| 同幂等键不同请求 | 保存、准备和提交均拒绝，不改变已有结果 |
| 两个浏览器修改同一会话 | 旧版本保存和提交均冲突，客户核对最新清单后才能重新提交；无静默覆盖 |
| 提交与关闭并发 | 只形成已提交且有完整方案，或已关闭且无方案；不得两者同时成功 |
| 提交过程在明细写入处失败 | 无残缺方案、无孤立明细，册和会话未错误冻结 |
| 已提交后继续保存或另键提交 | 不能改明细或新增方案；有效链接只返回只读回执 |
| 准备后改价、换图或失去资格 | 发布复核拒绝受影响陈列；不静默换价、换图、剔除；重准备后须重新预览 |
| 发布后改价、换图或失去资格 | 链接有效且未关闭时，仍按发布快照保存、提交；原图仍可展示；不产生库存预占 |
| 按档重生成及失败恢复 | 沿用原池、原价；其他档保持不变；失败保留原有效陈列及删减结果 |
| 整册重新准备失败 | 原有效规则、快照、陈列保留，失败请求不能部分覆盖原结果 |
| 任务重启、超期、迟到结果、重复完成 | 可恢复或明确失败；旧运行不能覆盖新结果，不永久卡在准备中 |
| 组合重复与偏好 | SKU 顺序变化仍判重复；同册跨档不重复；已知候选按第 7.3.2 节排序，同 SPU 与分类偏好不误作硬拒绝 |
| 数量不足与预算耗尽 | 每档至少 1 套可带不足说明待发布；任一档为 0 则整次失败；预算耗尽不得声称无解 |
| P0 套餐图片为空 | 单品无图可保留；套餐全部成员无图不得成为有效陈列，图片失败与组合无解分开报告 |
| 图片与令牌越权 | 任意替换册、项或文件身份不能访问其他数据；旧令牌在更换、关闭或撤销后不能读图片或提交 |
| 链接复制及到期 | 重新进入管理页仍能复制当前同一链接；到期边界由服务端立即拦截，不依赖后台状态更新 |
| 商品数量和金额边界 | 最小值、最大值、超过上限、非整数、重复项及金额溢出均按规则处理，不截断成功 |
| 保留图片与内部历史 | 商品池换图及常规文件清理不破坏发布快照或方案图片；关闭公开访问后内部仍可按权限查看 |
| 公开字段与移动端 | 未登录浏览器无内部字段及管理端图片依赖；在 375px、390px、430px 宽度可完成浏览、改份数、核对、提交和结果恢复，无横向溢出及被底栏遮挡的操作 |

### 12.2 验收证据与交付门槛

1. 静态检查和单元测试用于验证规则及边界，不能替代真实数据库原子性、并发唯一性、重启恢复与授权验收。
2. 业务验收在独立验收环境执行，按项目既有测试管理要求开展，不向开发者本地常规测试门禁擅自加入集成测试。实际执行的命令、数据集、部署配置及结果须留档。
3. 在商品池 500 SKU、10 档、每档请求 20 套、每套餐 8 SKU 的上限下，分别验收可行、无解或预算耗尽、缺图和异常任务；所有任务必须在第 7.1 节期限内完成或明确失败。报告耗时和实际产出数，不把规定上限宣称为已验证吞吐。
4. P0 验收报告须列出四种组合和第 12.1 节各场景的通过、失败或未执行状态。存在失败或未执行项时不得标记完整 P0 已验收；P1、P2 不得记为 P0 已交付能力。

## 13. 流程总览

```text
销售在公司商品池筛选或勾选
        │
        ▼
创建选品册（客户 + 单品|套餐 + 按份采购|商城兑换）
        │
        ├── 单品：后端冻结 SKU 快照为陈列项
        └── 套餐：后端生成套餐 → 套餐图生成端口写入主图
        │
        ▼
销售预览、删减（套餐可重生成） → 发布 → 得到选品链接
        │
        ▼
客户在移动端选择（单品点选 / 套餐整套选；P1 起套餐可换品、自组）
        │
        ├── 按份采购：陈列项 × 份数
        └── 商城兑换：只勾陈列项
        │
        ▼
原子提交：冻结会话 + 创建唯一销售方案 + 选品册进入已提交
        │
        ├── 有效链接：只读回执；内部：查看方案
        ├── 以后：实物与服务销售单（按份采购）
        └── 以后：卡券销售单 + 商城可兑（商城兑换）
```
