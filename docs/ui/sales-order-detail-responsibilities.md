# 销售单详情职责与票款读取合同

## 页面职责

1. 销售单详情承载销售单维护、跨岗位进度查阅和关联单据追溯。
2. 销售单编辑、提交、发起改单及销售方撤回审批，必须继续遵守服务端允许动作与版本校验。
3. 审批决定、采购分配、履约处理、验收登记与冲正、销项开票必须在对应工作台任务办理。回款登记及核销必须在客户往来办理。
4. 销售单详情内不得根据管理员权限或旧 `mode=register` 参数恢复跨岗位办理表单。查看票款明细时，回款审批摘要和历史必须只读。
5. 详情各分区不得展示独立的相关待办区块，不得为该区块查询任务列表。具有业务跟进价值的责任人应展示在对应审批进度或业务记录中；任务分派及待办队列由工作台承载。

## 票款口径

1. 应收汇总必须完成全部分页后展示；读取中断、失败和无权限不得替换为零金额。
2. 本单回款和本单发票必须独立读取、分页及处理失败，销售单编号不得替代销售单身份筛选。
3. 回款单据到账金额、本单已核销净额、本单拟核销金额必须分栏显示。拟核销只从待审批分配读取，不计入已回款、已核销或应收余额。
4. 回款关联范围必须包含已过账核销对应回款与待审批分配对应回款，二者使用同一销售单或应收子账范围；列表记录与总数必须使用相同过滤条件。
5. 业务性质按销售单事实展示；后端未提供到期状态时不得默认显示未到期。

## 发布与回滚

1. 先发布后端读取改动，再发布前端。后端在回款列表和详情响应中新增 `pending_allocations`；该字段来自既有实体，不新增业务写入或重算历史余额。
2. 随后端现有索引初始化流程建立非唯一索引 `idx_customer_receipts_pending_entry`，键为 `pending_allocations.receivable_entry_id: 1, deleted_at: 1`。发布前核对集合规模与索引构建窗口；发布后核对索引存在，并在实际数据上检查范围查询执行计划。
3. 历史记录缺少 `pending_allocations` 时，后端按空数组读取；新前端连接旧后端时将未返回的拟核销金额显示为待确认。完整的审批中回款关联能力以新后端生效为准。
4. 回滚时先回退前端，再回退后端。新增非唯一索引允许保留；不得删除既有实体待审批分配或核销数据，不执行余额回填。

## 验收要求

1. 以销售、财务、采购、仓储及管理员账号核验页面责任边界；可见范围不得扩大，具备全权限的账号也不得在销售单详情办理跨岗位操作。
2. 核验审批中回款、已核销回款、冲减、跨单分配、无应收、权限不足、查询失败及超过一页记录。
3. 核验详情各分区不提供打开客户往来、打开工作台、查看任务及同类跨模块入口；允许在当前页面预览关联记录，旧验收登记链接必须只读。
4. 单元测试与静态检查不得替代真实审批、回款过账或多角色业务验收。验收记录须分别说明已执行的证据等级。
