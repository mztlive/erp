## 一、页面概述

`/master-data` 是 W14 基础资料模块入口，按演示角色（`demoRole`）302 重定向到对应资源列表（`app/(workspace)/master-data/page.tsx:11`），向下两层形态：

- **列表层**（`master-data-page.tsx`）：资源 Tab 导航 + 指标条 + 搜索/双筛选 + 表格（钉住编号列与操作列）；行点击出侧边预览 sheet（`QuickPreviewSheet` + `MasterDataPreviewPanel`），商品/供应商/品牌走特殊路径。
- **详情层**（`master-data-center-page.tsx`）：面包屑 + `DocumentHeader`（版本/启停/生效期间）+ 分区锚点导航（概览/变更历史/引用与选用/操作记录）+ 更新/停用对话框；商品与供应商直接使用整页详情编辑器（`product-detail-page.tsx` / `supplier-detail-page.tsx`）。
- **操作层**（`master-data-action-dialog.tsx`）：新建/更新/停用三个对话框，含演示模拟控件与结果页。

**整体评价**：信息架构清晰、术语表合规度很高（"停用不是删除""更新资料会保留历史"等业务化表达到位，未发现内部 ID / 枚举原值直出界面正文），四态处理基本齐全，键盘 ` / ` 搜索、行焦点恢复、敏感信息打码 + 15 秒自动隐藏等细节是加分项。主要问题集中在：日期输入与默认值（会造成静默回溯/静默排期）、冲突恢复路径、禁用态语义与演示控件残留、导出文件的内部门面泄漏。

## 二、易用性

### 2.1 入口导航（列表层）

- 资源 Tab（`master-data-page.tsx:67-98`）`role="tablist"` 语义正确，`/` 快捷键聚焦搜索（:108-121）、资源切换后焦点移到结果标题（:123-130）均为可访问性加分项。
- 角色默认跳转（`types.ts:14-22`）合理：采购/销售 → 公司商品池、运营 → 卡券类目、财务 → 供应商与资质、仓储 → 仓库。**但仓储角色落在完全只读的"仓库"页**（见 P1-6），落地即无事可做。
- **P2-8**：入口 Tab 中「公司商品池」（sellable-items）与「商品与 SKU」（products）并存（`types.ts:4-5`），业务用户难以区分两个入口的差异，缺一句引导文案（如"商品池=采购发布给销售的可售项；商品与 SKU=SPU/SKU 主档"）。

### 2.2 详情导航（中心页）

- 分区锚点（`master-data-center-page.tsx:277-296`）用 `?section=` 驱动并平滑滚动，URL 参数与控件一一对应，符合术语表 §5.4 契约。
- **P2-2**：「返回列表」使用 `window.location.href` 整页刷新（:193-195），与本页其他 `Link` 导航不一致，破坏 SPA 状态（滚动位置、筛选条件全部丢失）。

### 2.3 三种资源的入口一致性

- 商品/供应商：查看=编辑同一路由，行点击进详情页，行为统一（:401-407、:698-706）。
- **P2-5**：品牌例外——无预览 sheet、无"查看"按钮，**行点击直接打开"更新资料"编辑对话框**（:702-704、:708-712），而品牌其实有中心详情页（`MasterDataCenterBody` 通用路径），只是界面从不链接过去。查看型点击跳到编辑型交互，且与其它资源行为不一致。

## 三、信息密度

- **列表层：偏密但可接受**。8 列 + 指标条（4 格）+ 双筛选 + 工具栏行数，值均为短文本；stableNo 与操作列钉住（:692-695）保证左右上下文。窄屏下 `flex-wrap` 兜底，指标条与筛选会堆叠为两行，视觉噪音上升——建议窄屏隐藏"版本状态"筛选进下拉或折叠。
- **中心页概览：密度适中**。`dl` 二列网格，最多 4 通用项 + N 个版本字段 + M 个资源事实（:304-341），全部为键值短行，无冗余图表，符合"资料档案"定位。
- **P2-11**：预览 sheet（`master-data-preview.tsx:33-274`）最多 6 个区块（基本信息/关键信息/哪些业务能选用/敏感信息/库存摘要/变更历史/不可用操作），全部平铺无折叠，竖屏下需长滚；建议对"变更历史"与"当前无法进行的操作"做折叠或只在必要时展开。

## 四、交互合理性

### 4.1 加载 / 空 / 错误态

- 中心页四态齐全：骨架屏（:118-128）、`BusinessFailureState` 错误 + 重试（:130-145）、缺失态带返回按钮（:147-161）——质量高。
- **P2-6**：列表页错误态退化为裸"重试"按钮、无错误说明、无 `BusinessFailureState`（`master-data-page.tsx:469-479`），与中心页（:134）不一致；空列表也无专有空态（依赖表格框架默认空文案）。

### 4.2 预览 / 详情交互

- 预览 sheet 加载中显示"正在加载…"（:133-137），关闭后焦点恢复到原行（:726-735）——体验好。
- 敏感信息统一 `SensitiveValue`（打码 + 短时查看 + 15s 自动隐藏），中心页与预览面板行为一致（center:343-370、preview:139-171）。

### 4.3 新建 / 编辑 / 停用对话框

- 成功/阻断/冲突三种结果均有 `FormalActionResult` 事实表，阻断后表单保留可改——好。
- 双提交防护：`idempotencyKey` 每次打开重新生成（:573、:823、:1055），重复点击返回缓存结果——好。
- 详见 P1-1/P1-2/P1-3/P1-4 的问题。

### 4.4 按钮语义与误操作防护

- 主动作命名业务化（"保存更新""确认停用"），阻断原因大多落到正文文案而非只读态——符合术语表。
- **P2-1**：列表行内"更新资料/停用"与 sheet 底部按钮在禁用时只挂 `title`（`master-data-page.tsx:417-418、438-439、778-795`），**浏览器对 disabled 按钮不显示 title 提示**，阻断原因不可悬停发现（仅靠"不可用原因"列缓解，且该列只有 primaryBlocker 一条）。
- **P2-3**：三个对话框均无未保存离开确认——点 X / 按 Esc / 点遮罩直接丢弃已填内容（:578-584、:829、:1062），长表单（供应商 30+ 字段）误触代价大。

## 六、改进建议

1. **日期输入统一改造（P1-1/P1-2，优先）**
   - 全部资源（含对话框）的生效开始/结束改用 `DatePicker`（对齐供应商详情页 `supplier-detail-page.tsx:1001-1021`），删除硬编码默认值，改为：新建/停用默认今天、更新默认当前生效日。
   - zod 补格式与业务校验：`regex(/^\d{4}-\d{2}-\d{2}$/)`、`effectiveTo === "" \|\| effectiveTo >= effectiveFrom`；前端判定"未来/当前"不要依赖字符串比较。
2. **冲突恢复提供应用内出口（P1-3）**：冲突结果卡增加"重新加载"按钮（`refetch` + 重置表单），或冲突时也 `invalidateQueries` 使 `lockVersion` 刷新，避免"关闭-重填-再冲突"死循环。
3. **禁用态语义修正（P1-4/P2-1）**：仓库"新建（暂不可用）"改为真正 `disabled` 且旁边放说明文案；或改为无动作的 `Badge`。列表行内禁用按钮补充 `aria-describedby` 或把阻断原因行内显示（参考术语表 §7"不要摆一排禁用按钮"的做法）。
4. **导出面收敛（P1-5）**：CSV 元信息改用中文映射（启用状态=全部/当前启用/当前停用），去掉 `permissionVersion` 内部版本号；任务号改为业务单号（如 `导出-20260805-0001`），禁止 W 编号。
5. **仓储落地页（P1-6）**：仓储角色落地改到可读可操作资源，或仓库页顶部阻断横幅同时给"去公司商品池/去库存台账"入口，避免死胡同。
6. **对话框草稿保护（P2-3）**：有脏值关闭时弹"放弃本次填写？"确认（仅表单 `dirty` 时拦截）。
7. **模拟控件收敛（P2-4）**：打开对话框时重置 `simulate` 为 `ok`；生产环境按 G6 结论整组隐藏。
8. **入口与品牌交互（P2-5/P2-8）**：品牌行点击改打开预览或中心页，与其它资源一致；为"公司商品池/商品与 SKU"增加一行说明文案。
9. **死代码清理（P2-10）**：删除 `usesWideDialog` 恒 false 分支或统一给对话框加 `max-h` + 内部滚动，保证小屏可用。
