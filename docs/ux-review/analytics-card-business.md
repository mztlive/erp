## 一、页面概述

页面定位为「卡券消费台账与经营分析」：面向财务/运营分析人员，回答"卡券消费了多少、成本覆盖多少、经营贡献多少、谁在消费"。

页面结构自上而下：

1. **页头**：标题 + 数据新鲜度条（分析汇总时间、同步时间、业务记录、余额记录、延迟）+ 操作（口径说明 / 刷新 / 导出）
2. **筛选条**：9 个控件——期间快捷、从、至、日期口径、客户、销售单、成本口径、履约期限、分析视角
3. **提示区**：数据新鲜度告警（陈旧/更新中/失败）、当前筛选与数据时间摘要、成本覆盖卡（CostCoverageNotice）
4. **核心指标条**：4 列 × 2~3 行指标（含税/不含税逐项标注、仅供参考状态）
5. **图表区 2×2**：消费与余额趋势（柱状）、成本口径构成（柱状）、经营贡献与覆盖率（双轴折线）、类目/客户构成
6. **下钻明细表**：客户/销售单/卡实例/消费/退款/成本/覆盖/未履约余额 + W 单据下钻按钮，服务端分页
7. **抽屉**：口径说明、导出预览（免责声明 + 确认导出 → 后台任务进度条）

特殊状态：Q2 无默认日期口径时整页替换为「显式期间与日期口径」表单；无利润权限时图表降级为权限空态。

**总体评价**：页面结构完整、状态覆盖全面（加载/失败/陈旧/重建/权限掩码/空态均有处理），口径透明化的设计（含税/不含税逐项标注、覆盖率前置警示、导出免责声明）是明显亮点。主要问题集中在**筛选与数据的联动真实性**、**表格排序伪交互**、以及若干**文案契约违规**（枚举原值、W 编号上屏）。

## 二、易用性

### 核心任务路径

| 任务 | 路径 | 顺畅度 |
| --- | --- | --- |
| 查看分析 | 进入页面即见指标条 + 图表（默认本月至今） | ✅ 顺畅，一次加载 |
| 切换期间 | 期间快捷下拉 3 个预设 / 从-至两个 DatePicker，改动即触发查询 | ✅ 顺畅 |
| 按客户/销售单下钻 | 筛选条选择 → 明细表行内 W25/W26/W29 按钮跳转 | ⚠️ 筛选只影响明细表，指标/图表不变（见问题 1） |
| 导出 | 导出 → 预览抽屉（口径/筛选/时间免责）→ 确认 → 任务进度条 | ✅ 流程完整，防误操作到位 |
| 口径理解 | 「口径说明」抽屉覆盖含税/不含税、三分法、贡献 vs 利润、微信边界 | ✅ 学习成本的主要出口，内容完整 |

### 优点

- **口径说明一次讲清**：页面把"当前经营贡献 ≠ 最终利润"这类财务上最容易误读的差异，通过「口径说明」抽屉 + 指标旁 inline detail + 覆盖率卡前置三条路径反复交代，对分析类用户决策安全很重要。
- **筛选即时生效、无提交门槛**：所有筛选改动即 patch URL 并触发查询，符合分析场景习惯；且 URL 可分享/回放。
- **权限与数据降级透明**：无成本/利润权限时指标显示"— 无字段权限"而非假 0，图表降级为权限空态并保留覆盖率可见——这是财务数据展示的正确姿势。
- **Q2 阻断态设计良好**：未配置默认口径时整页替换为显式选择表单，明确"不会自动采用本月"，杜绝口径猜测。

### 主要问题

1. 筛选器多达 9 个，但没有「清除全部」；客户/销售单两个实体选择器互不联动，可选出互相矛盾的组合导致空结果（见问题清单 10、11）。
2. 表格的排序、分页交互与筛选器没有形成闭环（见问题 3、4）。
3. 默认视角下「最终利润未展示」横幅常驻，占位但不提供一键切换到期口径的操作入口（文案说"请将日期口径切换为履约到期日"但要手动去下拉切换）。

## 三、信息密度

### 密度评价

- **头部信息过密**：页头 metadata 一次展示 4 个时间点（分析汇总、数据同步、业务记录、余额记录）+ 延迟/上限，普通分析用户只需要"数据是什么时候的"，当前 4 列时间戳 + 括号解释形成认知噪音（`card-business-analytics-page.tsx:870-926`）。
- **横幅堆叠**：正常加载下页面同时最多可出现 4+ 条 Alert/横幅——「当前筛选与数据时间」（1243）、CostCoverageNotice 内嵌 Alert（1048-1057）、「最终利润未展示」（1378）、数据状态类横幅（1138-1182）。同屏 4 条警示横幅造成告警疲劳，重点（覆盖率/参考性）被稀释。
- **口径标注重复**：列头已写「消费(含税)」，单元格 `MoneyValue` 又传 `taxBasis` 渲染「含税」徽章（每格一个）；指标条 label 追加「（含税）」后 value 的 MoneyValue 再渲染徽章。违反 `components/business/README.md` 明示约定"列头/标签已写明口径时不要传"，是全表级视觉噪音（见问题 6）。

### 密度评价（正）

- 指标条 4 列布局 + 「仅供参考」状态徽章 + inline detail 的组合密度合理，符合分析用户扫读习惯。
- 图表均配等价数据表（caption 明示"与图等价"），读屏/键盘/精确数值三覆盖，是分析页少见的高标准做法。
- 关键指标确实突出：成本覆盖率以进度条 + 状态徽章 + 前置解释三重视觉权重呈现，决策信息优先。

## 四、交互合理性

### 做得好的

- **加载/空/错误状态**：首屏骨架屏、查询失败 BusinessFailureState + 重试、无数据空态均存在；筛选变化时保留旧数据（`isPending && !data` 才出骨架）不闪屏。
- **刷新**：刷新中禁用 + 文案变「刷新中」，失败保留旧数据并明示"保留上次成功数据供只读查阅"，SLA 超时有专门 Alert——数据可信度管理到位。
- **误操作防护**：导出走「预览 → 免责声明 → 确认」两步，且导出水印记录口径/筛选/水位，防止"导出后说不清数据是什么"。
- **图表**：recharts 默认悬浮 tooltip 显示完整金额（图内万元 vs tooltip 全值），双轴图（贡献/毛差左轴、覆盖率右轴 [0,100]）分割清晰。
- **安全**：卡实例引用列为不可逆摘要，title 注明"不可反推卡号/卡密"，未展示手机号等敏感字段，表描述也声明"不包含卡号、卡密与绑定手机号"。

### 主要问题

1. **表格排序是"假交互"**（最严重）：DataTable 默认 `manualSorting=true` 且本页列未禁用排序 → 所有表头都渲染可点击排序按钮并切换升降序箭头；但页面既不传 `onSortingChange` 也不回写 URL `sort` 参数，服务端排序恒为 `consumptionGross:desc`，且当前只加载一页数据。用户点表头看到箭头变化、数据顺序不变 → 明确误导（详见问题 3）。
2. **分页与筛选不联动**：翻页后改筛选，pageIndex 不回零，可落在越界空页并显示"第 N/1 页"。
3. **筛选与结果脱节**：除明细表外，指标、趋势图、构成图、覆盖率对任何筛选（客户/成本口径/履约/覆盖）都不响应——这是分析页的核心可信度问题（详见问题 1）。
4. **图表无下钻**：图表仅悬浮读数，点柱/点线无交互；对分析页而言属于可用但可增强项（P2）。
5. **移动端导出不可达**：导出按钮 `mobileVisibility: "hide"` 且无替代入口。

## 六、改进建议（按优先级）

1. **【P0 级修复方向】打通筛选 → 数据的真实联动**：指标条/趋势图/构成卡必须按当前 from/to/dateBasis/客户/口径/履约/覆盖重算（服务端聚合），否则本页无法作为分析工具。若为演示数据限制，至少：筛选生效范围在 UI 上明确区分（明细表"已按 X 过滤"，指标标注"全量口径"），杜绝"摘要暗示全量已过滤"的误解。
2. **【P1】「分析视角」要么实现要么摘除**：按 AGENTS.md"URL 参数与界面控件一一对应"原则，当前 dimension 无任何数据行为，应实现（维度改变行分组与构成卡）或从查询与筛选条中移除。
3. **【P1】修复表格排序**：表头排序按钮接入 URL `sort`（如 `patchUrl({sort})` + 服务端 sort 分支），或禁用列排序避免假箭头。
4. **【P1】分页与筛选联动**：任何筛选变更时重置 pageIndex 为 0（在 patchUrl 侧或 useEffect 监听筛选参数）。
5. **【P1】文案合规**：filterSummary 改用 `DIMENSION_LABEL`/`COVERAGE_FILTER_LABEL` 等中文映射；「W25/W26/W29」按钮改用 `lib/ui-text.ts` 的 `openWorkspaceLabel`/页面中文名。
6. **【P2】降噪**：页头时间戳折叠为 tooltip/次行；合并横幅层级（「最终利润未展示」改为指标条内 inline 提示 + 可点击切换口径）；单元格去除重复「含税」徽章（列头已标注）。
7. **【P2】细节**：preset 与自定义期间双向同步（自定义后高亮"自定义"或回落空值）；「消费与余额趋势」补余额折线或改标题；空态提示补充全部可调筛选；Q2 表单加日期顺序校验；导出成功条提供真实下载链接。
