## 一、页面概述

- **路由**：`/sales/contracts`，SPA 客户端页面（`contracts-list-page.tsx`）。
- **用途**：浏览当前业务范围内全部合同，支持搜索、状态/有效期筛选、快速预览、打印纸质预览、上传合同 PDF、按当前筛选导出。
- **页面构成**：PageHeader（面包屑 + 数据新鲜度 + 导出/上传按钮）→ 结果反馈条（导出任务/上传结果）→ MetricStrip 指标筛选条（全部/有效/30 天内到期/已到期）→ 合同列表卡（工具栏：搜索 + 状态 ToggleGroup + 有效期 OptionCombobox + 计数；表格：9 列、行点击预览、列固定、列设置、分页）→ 右侧 QuickPreviewSheet 预览抽屉 → ContractPaperDialog 纸质预览 → ContractUploadDialog 上传对话框。
- **数据**：TanStack Query 客户端取数（mock `listW04Contracts`），搜索/筛选/分页全部客户端完成（全量拉取后切片）。

**总体印象**：页面骨架成熟（指标条 + 工具栏 + 表格 + 抽屉预览 + 异步任务反馈的分层清晰，空/错/加载态均有兜底），但存在一个 P0 内部 ID 泄漏、若干筛选体系重叠与"伪排序"等明显阻碍效率的问题，详见问题清单。

---

## 二、易用性

**好的一面**

- 行点击直接打开右侧预览抽屉，配合"打开"按钮进详情，读合同信息的路径短。
- 打印按钮在无权限时禁用并给出阻断原因 tooltip（`contracts-list-page.tsx:341-346`），符合"禁用不解释原因"的反例——这里解释了，做得好。
- 上传成功后给出结构化结果卡 + "查看详情"下一步入口（`:132-153`），反馈闭环完整。
- 指标条与工具栏位于同一屏内，筛选入口可达性好。

**问题**

1. **进入详情的入口语义分裂**：合同编号以链接按钮呈现（`:194-208`），点击却是打开**预览抽屉**而非详情页；详情只有独立"打开"按钮（`:327-336`）。用户在列表中最先尝试点击的对象是合同号，结果进入的是一个抽屉而非详情页，与全站"编号点击进详情"的直觉相悖。
2. **客户锁定筛选是隐形状态**：来自 URL `customerId` 的筛选（`:108-110`）在界面上**没有任何提示与清除控件**，用户不知道自己正被锁定在某客户下，也无法退出；且该 ID 直接泄漏进导出文案（P0，见问题清单）。
3. **移动端缺失主操作**：导出与上传按钮 `mobileVisibility: "hide"`（`:403`、`:413`），窄屏用户无法上传合同 PDF / 导出。
4. **搜索范围与实际不符**：placeholder 只写"合同号、客户、结算主体"（`:530`），实际还匹配客户编号、负责人、状态标签（`filter-contracts.ts:42-49`），用户不知道可以搜负责人。

## 三、信息密度

**好的一面**

- 关键业务信号都有视觉强调：状态用彩色 Badge、将到期合同有"将到期"警示（`:251-253`）、销售单列给出"进行中 N"（`:284-289`）、有效期用等宽数字。
- 列固定（合同号左、操作右）与列设置（显隐/排序/固定）由 DataTable 统一提供，横向可滚动不丢主列。

**问题**

1. **客户信息双列重复**：合同号列下方已内嵌客户名（`:209-211`），又单设"客户"列（`:216-229`），同一信息横向占两列宽。可把合同号列合并为"合同编号 + 客户名"主列、去掉独立客户列，为金额/有效期让出空间。
2. **缺金额信息**：列表与预览均无任何金额维度，预览面板还明示"本页不汇总合同金额；金额以各销售单为准"（`contract-preview-panel.tsx:180`）。对销售合同列表而言金额是核心决策信息，若确为业务模型未定义（`mock/contracts.ts:21` 注释），建议产品确认；即便不展示金额，也应在预览中给出"关联销售单含税金额合计"这类替代指标。
3. **列价值排序失衡**：9 列中"版本 vN""负责人""结算主体"信息价值低于金额/到期提醒，但挤占了空间；版本与销售单列同属"关联度"信息，可合并为子行。

## 四、交互合理性

**好的一面**

- 筛选/搜索变化统一重置分页（`resetPagination`，`:96-100`），符合分页心智。
- 导出按钮在无结果时禁用（`:404`），导出按当前筛选快照生成并提示"下载时重新校验权限"（`:172-184`），语义清晰。
- 空态/错误态/加载态均有兜底（`DataTable` 默认空态、错误态重试按钮 `:369-378`）。

**问题**

1. **排序是"伪排序"（当前页内排序）**：`pageRows` 是分页切片（`:114-117`），而 DataTable 默认 `manualSorting = true`（`data-table.tsx:270`）且页面未传排序状态，点击表头只在**当前页 20 行内**排序，翻页后顺序错乱，用户会误以为整表已排序。
2. **状态筛选三套控件重叠且可矛盾**：MetricStrip（全部/有效/30 天内到期/已到期，`:465-506`）+ 有效期 OptionCombobox（含"已终止"，`:553-570`）+ 状态 ToggleGroup（生效/到期/终止，`:537-552`）共同操作同一条状态轴，三套集合互不一致（Strip 无"已终止"、Combobox 无"有效"），且可组合出**恒空条件**（如"30 天内到期 + 状态=到期"永远 0 条），无任何冲突提示。
3. **URL 参数契约违反**：`customerId` 参数无对应控件也无清除途径（AGENTS.md 明令"被 queryFn 消费、却没有控件也无法清除的参数是用户改不动的隐形状态"）；`q`/`search` 双别名（`page.tsx:15`）；搜索/指标/状态/分页**不回写 URL**，刷新全部丢失、无法分享筛选视图。
4. **默认排序声明与数据不符**：描述文案称"按将到期优先排序展示"（`:512`），但 mock 数据实际按 contractId 顺序返回（`mock/contracts.ts` 首行 ct_0312 到期日 2026-12-31，将到期的 ct_0288/ct_0355 排在第 2、7 位），且没有任何排序指示器。
5. **"操作"列可排序**：该列未声明 `enableSorting: false`，表头带排序图标（`data-table.tsx:719`），点击排序无业务意义。
6. **空态无引导**：未传自定义 emptyState，默认文案"当前筛选没有结果"（`data-table.tsx:864-868`），没有"清除筛选 / 上传合同 PDF"行动点。
7. **计数重复**：工具栏"共 X 条"（`:574-576`）与分页区"共 X 条"（`data-table.tsx:1065`）显示两遍。
8. **数据新鲜度恒为"刚刚"**：`updatedAt="刚刚"` 硬编码（`:390`），上传合同后列表已刷新但此处永不变化，失去提示意义。
9. **加载态整页塌缩**：`isPending` 时整页只剩一行标题（`:361-367`），指标条/表格区域全部消失，可提供骨架屏保持布局稳定。

## 六、改进建议（按优先级）

1. **[P0 修复] 清理内部 ID 上屏**：`filterSnapshotLabel` 中 `客户=` 改为客户显示名（或干脆删除客户轴，由搜索承担）；`permissionVersion`、下载文件名中的 jobId 不下发前端或映射为业务词；全页增加术语表扫描断言。
2. **[P1 修复] 收敛状态筛选为单一控件**：建议只保留 MetricStrip（全部/有效/30 天内到期/已到期/已终止五档）作为唯一状态轴，删除 OptionCombobox 与 ToggleGroup；或将 ToggleGroup 改为多选状态，去掉与指标条的重复项。任何情况下需保证三套控件集合一致，且矛盾组合给出空态引导。
3. **[P1 修复] 排序要么全量、要么关闭**：由服务端/全量数据排序（把 `pageRows` 换成对 `filtered` 全量排序后再切片），并给默认排序一个可见指示（"将到期优先"）；若短期内不做，则对表头禁用排序，避免伪排序误导。
4. **[P1 修复] 补 URL 参数契约**：为 `customerId` 提供"当前客户：XX ✕ 清除"chip 控件；搜索/指标/状态/分页回写 `?q=&status=&metric=`，刷新与分享不丢状态；`q`/`search` 双别名取其一。
5. **[P2 改进] 统一详情入口**：合同号改为详情页链接，"预览"按钮与行点击负责抽屉；合并客户双列，腾出空间给金额/到期信息。
6. **[P2 改进] 文案统一**：状态词全页统一为术语表映射（生效/终止/到期），描述文案与实际排序逻辑保持一致；空态补充行动点。
