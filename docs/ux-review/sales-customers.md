# UX 评审：/sales/customers（客户中心列表）

> 评审视角：产品经理 / UX
> 评审对象：`customer-center-page.tsx`、`customer-create-dialog.tsx`、`customer-form.tsx` 及所引用的 `components/business` 组件
> 参考基线：`docs/ui-glossary.md`（v1.2，术语表）
> 日期：2026-08-05

---

## 一、页面概述

客户中心是销售域的客户主数据列表页，承担三个核心任务：**找客户**（搜索/范围/状态筛选）、**新建客户**（对话框 + 共享表单）、**进入详情**（行点击/回车/链接跳转详情页）。

整体设计质量较高：筛选器与 URL 参数一一对应（`scope/status/q`，默认值不写 URL）、搜索 Enter 提交、新建表单最小必填（仅法定名称 + 负责销售）、联系人/地址/银行账户三区可选、脏数据有离开拦截（对话框 + beforeunload）、行交互与键盘（上下箭头 + Enter）完备、客户列固定左侧。主要问题集中在**错误状态缺失**、**表头排序假交互**、**内部实现细节上屏**三处。

---

## 二、易用性

**查找客户**：路径顺畅。工具栏常驻搜索（Enter 提交）+ 范围 ToggleGroup（我的/协作/团队）+ 状态下拉 + 「搜索」按钮，筛选结果进入 URL 可分享。搜索提交后 `resetPagination` 归位正确。

**新建客户**：页头「新建客户」按钮 → 对话框 → 提交成功自动跳详情。表单必填项只有 2 个，三个明细区（联系人/地址/银行账户）均可跳过并在详情页补录，阻断成本低——这是本页最好的设计。存在重复候选时只提示不自动合并，符合主数据谨慎性原则。

**进入详情**：行内名称链接、单击行、键盘 Enter 三入口一致跳详情；客户列固定左侧、列宽可调、列可显隐。

**扣分项**：
- 移动端页头「新建客户」被 `mobileVisibility: "hide"` 隐藏且无任何替代入口（除空态外），移动场景无法新建（见 P2-1）。
- 表头排序按钮存在但无效果（见 P1-2），点击后用户会产生"已按该列排序"的错误预期。

## 三、信息密度

8 列：客户（名称 + 编号 + 关注标签）、负责销售（含协作人数）、状态徽章、有效合同、进行中销售单、未结清、逾期、最近业务。

- **密度适中**：对销售找客户场景，核心识别信息（名称、状态、逾期、未结清）都齐了，金额列等宽数字 + 右对齐语义，逾期金额有警示色（customer-center-page.tsx:199-207），风险一眼可见。
- **状态突出**：状态徽章独立一列，符合"状态说结果"。
- **等级**：本页数据模型没有客户等级字段（types.ts 的 `CustomerDirectoryItem` 无等级），列表自然不展示——若产品有"重点客户/等级"概念，当前缺失；若没有，此项不成立。
- **轻微过疏**：「最近业务」仅截取前 10 位日期（customer-center-page.tsx:217-221），同日内无法区分先后；「负责销售」列对无协作者客户只显示一行名字，行高偏矮但可接受。
- **冗余**：总数在工具条「共 X 家」与分页「共 X 条」出现两处（见 P2-5）。

## 四、交互合理性

**加载态**：`isPending` 整卡替换为「正在加载客户目录…」，无骨架屏、不保留旧数据（见 P2-9）。

**错误态**：**缺失**。查询失败时无任何错误分支，用户看到的是「当前筛选无结果」（见 P1-1），这是本页最严重的问题。

**空态**：四种空态区分清晰（无权限范围 / 范围内无客户 / 筛选无结果），描述带当前筛选上下文，且提供「新建客户」或「清除筛选」动作，文案业务化。

**筛选与 URL**：scope/status/q 全部与控件一一对应，默认值省略、`router.replace` 不污染历史。但分页不在 URL 中（见 P2-2）。

**分页**：客户端切片 + 本地 state。当前为全量拉取后前端切片（customer-center-page.tsx:104-107），数据量大时不可扩展（demo 可接受，但契约上 `fetchCustomerDirectory` 无分页参数）。

**新建表单**：字段量合理；校验即时反馈（Zod onChange），错误文案业务化（「请填写法定名称」「请选择负责销售」）；提交按钮「创建客户/提交中…」是动作词。扣分：底部「演示结果」模拟控件暴露在正式表单（P2-6）、成功态一闪而过无反馈节点（P2-3）。

**按钮语义**：新建客户/创建客户/取消/完成均为动作词，与术语表一致；对话框内「完成」按钮在成功即关闭的场景下实际不可见（与 P2-3 同源）。

## 五、问题清单（按严重度）

### P0（阻断操作）— 0 个

无。

### P1（明显阻碍效率）— 2 个

**P1-1 查询失败无错误分支，误报「当前筛选无结果」**
- 位置：`erp-client/features/customers/customer-center-page.tsx:284-320`
- 描述：页面只处理 `isPending` / `hasCustomerScope=false` / `totalInScope===0` / `items.length===0` 四种状态。查询失败（`directoryQuery.isError`）时 `data` 为 undefined，会落入第 307 行的 `items.length === 0` 分支，向用户展示「当前筛选无结果 · 清除筛选」——把**系统故障**伪装成**业务上没有客户**，且「清除筛选」按钮对此毫无帮助。用户会反复试错或误判客户数据。
- 建议：补 `isError` 分支（参考 `BusinessFailureState`），文案按术语表「数据加载失败 + 下一步（重试）」。

**P1-2 表头排序按钮是无效交互（点击无任何效果）**
- 位置：`customer-center-page.tsx:95`（`sort: "recent_business"` 硬编码）、`customer-center-page.tsx:109-226`（列未禁用排序）、`components/business/data-table.tsx:270`（`manualSorting = true` 默认）、`data-table.tsx:719-736`（表头排序按钮）
- 描述：所有 accessorFn 列默认 `enableSorting` 为 true，表头渲染可点击排序图标（含 aria-sort 变化）；但页面把排序硬编码为「最近业务」且 `manualSorting=true`，点击列头只翻转排序图标，行序完全不变（也不发起新查询）。销售想按「逾期」降序找高风险客户会被静默欺骗。
- 建议：二选一——要么支持全局排序（把 `sort` 纳入 URL/query 并实现 `name/overdue_desc`，`filter-customers.ts:54-67` 已有现成逻辑），要么给列传 `enableSorting: false` 去掉排序入口。

### P2（体验瑕疵）— 12 个

**P2-1 移动端无新建客户入口**
- 位置：`customer-center-page.tsx:270-281`（`mobileVisibility: "hide"`）
- 描述：「新建客户」在 `max-sm` 下隐藏，页面无 FAB/抽屉等替代入口，空态除外移动端销售无法新建客户。组件注释（page.tsx:265-266）说明这是"写操作移动端隐藏"的产品决策，但本页没有给任何降级入口。

**P2-2 分页不在 URL 中，刷新/分享丢失页码**
- 位置：`customer-center-page.tsx:76-79`（`pagination` 纯本地 state）
- 描述：筛选条件全部落 URL 可分享，唯独页码不落；用户在团队客户第 5 页刷新后回到第 1 页。与「URL 参数与界面控件一一对应」契约不一致。

**P2-3 新建成功无显式反馈（成功态一闪而过）**
- 位置：`customer-create-dialog.tsx:54-57`、`customer-form.tsx:750-775`
- 描述：提交成功后 `onOpenChange(false)` 立即关弹窗并跳详情，`FormalActionResult` 的「客户已创建」结果卡与「完成」按钮在弹窗内实际不可见（form 卸载），用户没有"创建成功"的确认节点，只能靠跳转感知。建议加成功 toast（如「客户 KH-000001 已创建」）。

**P2-4 搜索占位符与匹配字段不一致**
- 位置：`customer-center-page.tsx:348`（placeholder「名称、编码、统一社会信用代码」）、`features/customers/filter-customers.ts:42-51`（实际还匹配 `ownerName`）
- 描述：实际搜索能命中负责销售姓名，占位符却没说；反之一线用户想搜联系人手机号（业务常用）则搜不到。占位符与实际行为对齐即可。

**P2-5 总数双处展示**
- 位置：`customer-center-page.tsx:411-417`（工具条「共 X 家」）、`components/business/data-table.tsx:1065`（分页「共 X 条」）
- 描述：同一总数在工具栏与分页条各显示一次，且单位不一致（家/条）。建议保留一处（分页条已内置），工具条处留作筛选摘要或移除。

**P2-6 「演示结果」模拟控件暴露在正式新建表单**
- 位置：`customer-form.tsx:725-748`
- 描述：新建客户对话框底部默认渲染「演示结果：正常成功」下拉（含「重复候选冲突」「结果不确定」等选项），用户会误以为这是必填/可选业务字段，选择非默认项还会人为制造冲突或不确定结果。术语表 G6 已备案"演示标记保留"，但建议收敛为演示环境开关（默认不渲染），并隐藏冲突/未知两个选项到 demo 专用入口。

**P2-7 成功事实表泄漏内部 lockVersion（「版本号」）**
- 位置：`customer-form.tsx:770`（`{ label: "版本号", value: String(result.lockVersion) }`）
- 描述：编辑成功后的事实表把并发控制版本号直接上屏（v3、v5…），这是实现细节；术语表口径是「数据版本」。建议删除该行或改为「数据版本 v{n}」样式与上一行「新版本」合并。

**P2-8 结果不确定态渲染原始幂等键**
- 位置：`customer-form.tsx:782`（`reference={result.idempotencyKey}`，形如 `create-m1x2-k3j4f5`）
- 描述：术语表把「幂等键」翻译为「原任务号」，这里把内部键值原样展示给用户。建议展示业务可读的「原任务号」（如 `KH-xxxxxx` 或截断友好串）。

**P2-9 切换筛选整卡闪烁，无骨架保留**
- 位置：`customer-center-page.tsx:284-289`、`queries.ts:112-117`
- 描述：scope/status 切换产生新 queryKey → `isPending` → 整表替换为「正在加载客户目录…」卡片，用户视线跳变；同域内可保留旧数据渲染 + 行级骨架（DataTable 已有 `loading` 骨架能力，data-table.tsx:655-663）。

**P2-10 屏幕阅读器读到内部 ID**
- 位置：`components/business/data-table.tsx:820`（`aria-label={rowLabel?.(row.original) ?? row.id}`）
- 描述：页面未传 `rowLabel`，读屏用户听到的是行内部 ID（如 `cst_*`）而非客户名。传 `rowLabel` 即可修复，且符合术语表"内部 ID 不得进用户感知"。

**P2-11 「记审计」为内部实现词**
- 位置：`customer-form.tsx:646`（「完整显示需授权并记审计」）
- 描述：「审计」是内部机制表述，业务化说法如「完整显示需授权，操作会留记录」。

**P2-12 「搜索」按钮冗余**
- 位置：`customer-center-page.tsx:397-407`
- 描述：搜索框已支持 Enter 提交（342-346），旁边的「搜索」按钮与 Enter 完全同义（还和 Enter 行为不一致——输入框失焦后无任何提示可提交），建议删除按钮或改为清除输入。

## 六、改进建议（按优先级）

1. **补错误分支（P1-1，最高优先）**：`isError` 时展示业务化失败态（数据加载失败 + 重试按钮），杜绝"故障伪装成无客户"。
2. **修掉假排序（P1-2）**：把 `sort` 做成真实功能（复用 `filter-customers.ts` 已有的 `name/overdue_desc` 排序，`sort` 进 URL），或禁用列头排序。
3. **内部实现细节清零（P2-7/8/11）**：lockVersion、幂等键、审计三处上屏按术语表口径改写。
4. **成功反馈节点（P2-3）**：创建成功 toast + 跳详情，替代弹窗内不可见的成功卡。
5. **演示控件收敛（P2-6）**：「演示结果」默认不渲染或收进 demo 开关，避免正式表单被测试控件污染。
6. **补移动端新建入口与分页 URL（P2-1/2）**，并统一占位符与搜索实现、去除双计数（P2-4/5/12）。
