# UX 评审报告：商品发布详情 / 刊登处理中心

> 评审视角：产品经理 / UX
> 文案基准：`docs/ui-glossary.md`（术语表 v1.2）
> 结论：P0 = 0，P1 = 4，P2 = 13，共 17 项

## 1. 页面概述

「发布对象」处理中心是商品发布（W22）的详情页：查看一个 SKU 在目标商城的发布版本族（不可变修订 + 发送记录），并对选中修订发起**准备新版本 → 核对并提交发布**、**人工暂停**、**失败发送重试**等动作，同时承载系统安全暂停（供应商停供/零库存等触发）的告警与后续处理入口。

页面结构：面包屑 + 操作（返回列表/刷新）→ 结果反馈条 → DocumentHeader（单号/主状态/三轨状态：发布内容/发送/商城确认）→「发布身份与版本」状态轨卡 → 吸顶锚点导航（概览/发布内容/媒体/固定供给/发送与版本/审计）→ 安全暂停面板 → 发布复核闸门提示 → 主内容 + 右侧 sticky 摘要栏（选中修订 / 版本对照）。

整体骨架清晰、版本概念分离（稳定发布/商城生效版/最新待确认版）做得扎实，误操作有确认框与双提交防护（requestIdRef）。主要问题集中在：**主操作禁用逻辑两处不一致**、**未保存输入在站内跳转时丢失**、以及**界面大面积泄漏英文枚举与内部 ID（违反术语表第 5 轮「必须清零」项）**。

## 2. 易用性

**顺畅的部分**
- 一屏内完成「看状态 → 看内容 → 提交新版本」：`DocumentHeader` 三轨状态（发布内容 r8 / 发送 / 商城确认 已生效 r7）+「发布身份与版本」卡，能快速回答"商城生效了吗？最新版到哪一步？"。
- 「准备新版本」点击后原地切换为表单（`publication-center-page.tsx:1095`），基线、提示（供应商起订不自动带入、销售价与供货价分开）都写在表单顶部 Alert 里，学习成本低。
- 提交前 `FormalActionConfirmDialog` 明确给出状态变化、锁定字段、影响与不可撤回项，误操作防护到位（`publication-center-page.tsx:1538-1568`）。

**受阻的部分**
- 表单内「核对并提交发布」与页头「提交发布」是同一动作的两个入口，但禁用逻辑不一致（详见问题 P1-1）：无发布权限（如 mock 中 `snack_fail` 种子，`mock/product-publications.ts:460` 的 allowedActions 无 `PUBLISH`）或安全暂停+上架组合下，页头按钮禁用而表单按钮仍可点击，用户走到确认框提交后才被服务端驳回，白费一轮操作。
- 人工暂停走原生 `window.prompt` + `window.alert`（`publication-center-page.tsx:927-935`），与全站设计语言割裂，无输入上限、无法给出常见原因快捷项，浏览器级阻塞弹窗在移动端/无头环境下体验差。
- 站内跳转丢失未保存输入（详见问题 P1-2）：`beforeunload` 只在整页刷新生效，Next.js Link 客户端跳转不触发，「返回列表」会无声丢弃整张编辑表单。

## 3. 信息密度

**过密的区域**
- 概览 DocumentSummary 混排业务项与实现项：「发布编号」「固定供给」是有业务含义的；「稳定 ID」（`pub_*` 原始 id）、「版本」（`ov-*` 乐观锁令牌）、「当前选中修订 r5」则是内部标识直出（`publication-center-page.tsx:1043-1070`），一线运营无法解读，且与右侧「选中修订」「版本对照」卡片高度重复。
- 安全暂停面板是信息重灾区（`safety-pause-panel.tsx:100-146`）：暂停操作号、来源对象/来源版本、受影响发布列表（publicationId + 暂停修订 + 发送 id + **英文 outbox** 字样）全部原始 ID 罗列，用户找不到"我该做什么"；真正的行动入口（供应商商品核对）却藏在后续任务小块里，视觉权重不足。
- 版本信息在 5 处出现（页头版本徽章、状态轨卡、概览「当前选中修订」、右侧两卡、时间线），概念未错但认知负担大；「版本 ov-tea_ss」这类令牌进一步稀释了「版本」语义（用户会以为是发布版本号）。

**过疏 / 缺失**
- 详情页没有数据新鲜度提示：`fetchPublicationDetail` 返回了 `freshness`（`api.ts:283-286`），页面完全未消费，只有手动「刷新」按钮。列表页有 DataFreshness，详情页反而没有——发送/确认状态靠服务端推进，用户无法判断当前看到的是否最新。
- 安全暂停（UNKNOWN 分支）下「不显示受影响发布、提交时间与后续任务；请按原任务号查询」（`safety-pause-panel.tsx:63-65`）——业务上是对的，但页面给出「打开接口错误处理」作为唯一出路，信息量与正常分支断崖式下降，缺乏"接下来会怎样"的预期管理。

**重点突出度**
- 主状态、商城确认轨（已生效/尚未生效）颜色与位置都突出；「待确认」态在列表与详情均有徽章，做得好。
- 但「发布身份与版本」卡描述「稳定发布对象、当前商城生效版与最新待确认版并列，不混成一个值。」（`publication-center-page.tsx:950`）是给开发看的实现说明，应改为业务语义（如「展示商城实际生效版本与最新提交版本，避免误判」）。

## 4. 交互合理性

**加载 / 空 / 错误**
- 加载骨架（`publication-center-page.tsx:645-652`）、错误态带「重试」、不存在时空态带「返回列表」——三种状态齐全，回退路径明确，做得好。
- 加载态标题「商品发布对象」（`:648`）与面包屑「商品发布」、路由 metadata「发布对象」三处用词不一，属术语漂移（P2）。

**操作按钮语义与禁用逻辑**
- 页头主操作在 dirty 时切换为「提交发布」，禁用条件含 `canPublish / gateBlocks / SAFETY_PAUSED+ON_SALE / pending`（`:893-908`），逻辑本身合理；但：
  - 表单内 `form.SubmitButton`（`:1220`）不消费同一组条件，`doPublish`（`:526`）也无 `canPublish` 前置检查 → 双入口行为矛盾（P1-1）。
  - 「准备新版本」禁用时无 title/原因说明（`:910-917`），禁用态不解释原因（术语表 §7 只读角色文案指引同样适用）。
  - 「提交发布」「重试发送」pending 期间仅 disabled、无 spinner 与文字变化（`:893-908`、`:1385-1388`），与确认框内「正在提交发布」反馈不一致。
- 重试/暂停/发布三个 mutation 的结果都统一进顶部 `FormalActionResult`，反馈可见性好；但无 toast，长页面操作后结果条在顶部，需要回滚视口才能看到（弱反馈）。

**误操作防护**
- 双提交防护（requestIdRef）、确认框锁定字段、未知结果分支（查询原请求/结算）都齐备。
- 但「演示：强制结果未知一次」复选框（`:1229-1236`）与「演示结算成功」按钮（`:809-833`）作为**故障注入/结果造假控件**与正式提交流并列在表单区和结果条里，一旦误勾选，一次正常发布会被强制置为"结果未知"，进入需要人工查询的异常分支——演示期尚可，生产环境属于高危泄漏（P2，建议按 G6 隐藏）。

**文案（对照术语表）**
- 已修正项核对通过：SKU 修订 ID→「SKU 修订编号」（`:1177`）、类目 ID→「商城类目编号」（`:1180`）、投递→「发送」（全文）、「原任务号」（替代幂等键）已落地。
- 遗留违规：英文枚举原值上屏（P1-3）、内部 ID 直出（P1-4）、「闸门版本」「不可变」「outbox」等实现词（P2）、「查询原请求」未用术语表「按原任务号查询」口径（P2）。

## 5. 问题清单

### P1（明显阻碍效率 / 违反术语表必须清零项）

**P1-1 表单内提交按钮绕过权限与闸门禁用逻辑，与页头按钮行为矛盾**
`publication-center-page.tsx:893-908`（页头禁用条件）vs `:1219-1221`（表单提交无任何禁用）。`doPublish`（`:526-605`）只检查 `data && sessionEdit`，无 `canPublish`/`gateBlocks` 前置判断。在无 `PUBLISH` 权限对象（`mock/product-publications.ts:460`）或安全暂停+选择上架（`:1165-1170` 的阻断说明在表单内，但按钮不禁用）场景下：页头禁用、表单可点 → 用户填完表单进确认框提交后被服务端驳回，精力白费且对「哪个入口才作数」产生困惑。修复：把同一组禁用条件传给 SubmitButton（或提交前拦截并提示）。

**P1-2 未保存输入在站内跳转（返回列表/面包屑）时直接丢失，防丢失保护失效**
`publication-center-page.tsx:393-401` 仅注册 `beforeunload`（整页刷新/关闭才触发）；`返回列表`（`:730-733`）、面包屑「商品发布/商城与发布」（`:715-718`）是 Next.js Link 客户端导航，不触发 beforeunload，直接丢弃未提交表单。与 `:752` 的提示文案「刷新或关闭前将提示丢失」不符——用户以为有保护。修复：dirty 时对返回类导航拦截确认（或改用 router 事件/拦截器）。

**P1-3 用户可见英文枚举原值泄漏（术语表第 5 轮 P0 类「必须清零」）**
- 安全检查状态直出 `PASSED / PENDING / FAILED`：`publication-center-page.tsx:349`（应译为 通过/检查中/未通过）。
- 编辑表单媒体区直出 `MAIN / CAROUSEL / DETAIL`：`publication-center-page.tsx:1206`（展示区已用 `MEDIA_ROLE_LABEL`，编辑区漏用）。
- 后续任务类型直出 `BUSINESS_EXCEPTION`：`safety-pause-panel.tsx:157`。
- 受影响发布行直出英文 `outbox` 字样：`safety-pause-panel.tsx:139-140`。
用户（运营/采购）无法解读，违反 §1.3 规则 7 与第 5 轮验收口径。

**P1-4 内部 ID 与实现令牌直出界面（术语表「内部 ID 不得进界面」）**
- 概览：「稳定 ID」`pub_*`（`publication-center-page.tsx:1050-1054`）、「版本」`ov-*` 乐观锁令牌（`:1058-1061`）——用户会误认为是发布版本号。
- 编辑基线：「基线修订 `rev_*`」（`:1106-1107`），应显示「基于 r7 版本」。
- 安全暂停面板整片 ID 罗列：操作号（`:102-104`）、来源对象/来源版本（`:110-118`）、后续任务 workItemId / handlerKey（`:153-169`）——处理卡上应给出业务对象名（供应商名+品名+修订版本号），而非 `sourceObjectType · sourceObjectId`。
- 确认框锁定字段、右侧卡中的 `supplierOfferingRevisionId` 原始 ID（`:1513-1517`、`:1554`）。

### P2（体验瑕疵）

**P2-1 原生弹窗三件套混用**：暂停原因用 `window.prompt`/`window.alert`（`publication-center-page.tsx:927-935`），放弃输入/切历史修订用 `window.confirm`（`:497`、`:512`）。与系统对话框风格割裂，且 prompt 无长度上限、无原因快捷项。
**P2-2 开发者口吻文案**：「不混成一个值」（`:950`）、「界面不得将其显示为商城已生效」（`:1001`）、「不得推断暂停未发生」（`safety-pause-panel.tsx:40`）——实现约束写给了用户看，应改写为业务语义。
**P2-3 演示故障注入/结算控件与正式操作并排**：「演示：强制结果未知一次」（`:1229-1236`）、「演示结算成功」（`:809-833`）——误勾选即破坏真实提交流，生产环境必须按 G6 隐藏。
**P2-4 详情页缺失数据新鲜度**：`freshness` 已返回未消费（`api.ts:283-286`），无「数据更新于…」/「数据可能不是最新」提示（对比列表页 DataFreshness）。
**P2-5 税率展示为小数**：`税率 0.13`（`publication-center-page.tsx:226-227`）应显示 13%；校验文案「0 到 1 的十进制数」（`:132`）对运营不可读。
**P2-6 动作词未对齐术语表**：「查询原请求」（`:807`）应为「按原任务号查询」；「打开错误处理」（`:1434`）、「打开接口错误处理」（`safety-pause-panel.tsx:76`）、「打开供应商商品核对」（`:185`）建议统一为「前往/去…」动作词（§3.1 模板）。
**P2-7 禁用/加载态缺乏解释与反馈**：「准备新版本」禁用无 title（`:910-917`）；「提交发布」「重试发送」pending 无 spinner（`:893-908`、`:1385-1388`）。
**P2-8 revision 参数无「回到最新」控件**：切历史修订后 URL 永久带 `?revision=`（`:509-524`）；无效 revision 静默回退最新但 URL 残留（`api.ts:236-239`）——违反 AGENTS.md「URL 参数与界面控件一一对应」。
**P2-9 页头「发送」轨参照不一致**：`deliveryTrack` 取选中修订的发送（`:707-709`、`:871-877`），而「发布内容 r8」取最新版（`:863-869`）——看历史修订时「发送：无发送」易被误读为当前状态。
**P2-10 安全暂停对象无恢复路径预期**：`safety-pause-panel.tsx:208-210` 只说「恢复未确认前上架会被系统阻断」，页面无任何「恢复功能将随恢复责任确认后开放」的指引，运营在此页是死胡同（设计上无恢复动作，但应管理预期）。
**P2-11 门禁实现词上屏**：「闸门版本 `pg-*`」（`:160-163`）——应为「发布检查已通过（版本号不展示）」。
**P2-12 错误 code 以 font-mono 原始码展示**：闸门/动作阻断/发送错误 code（`:173`、`:186`、`:197`、`:1082`、`:1456`、`safety-pause-panel.tsx:194`）——code 属错误对象 key，界面只应给中文信息。
**P2-13 零散实现词与术语漂移**：「已形成不可变发布修订与发送」（`:576`）；加载态标题「商品发布对象」（`:648`）与「商品发布/发布对象」不统一；「本页签内存」（`:752`）的「内存」一词对用户是噪声。

## 6. 改进建议（按优先级）

1. **统一主操作禁用语义（P1-1）**：把 `canPublish / gateBlocks / SAFETY_PAUSED+ON_SALE` 判定抽成单一变量，同时作用于页头按钮、表单 SubmitButton 与 `doPublish` 前置检查；表单内用「提交发布被阻断」行内提示替代可点击但必失败的行为。
2. **补齐站内导航防丢（P1-2）**：dirty 时拦截「返回列表」与面包屑 Link（改为受控点击 + confirm 或与路由跳转联动），使提示文案与行为一致。
3. **术语表清零（P1-3 / P1-4 / P2-11 / P2-12）**：补 `MEDIA_SCAN_STATUS_LABEL`、`WORK_ITEM_TYPE_LABEL` 等中文映射，媒体编辑区、安全检查徽章、暂停面板后续任务卡全部走映射；删除界面上的 `pub_* / rev_* / ov-* / outbox` 等令牌，替换为业务对象名 + 修订号。
4. **重做人工暂停输入（P2-1）**：用系统对话框（含原因必填、长度限制、常用原因快捷项）替代 `window.prompt`。
5. **隔离演示控件（P2-3）**：「强制结果未知」「演示结算成功」移到角色演示条或按 G6 统一隐藏策略处理，不得出现在正式操作区。
6. **补数据新鲜度（P2-4）**：详情页消费 `freshness`，在页头或发送区展示「数据更新于 {时间}」，发送中/待确认时提示「数据可能不是最新，请刷新」。
7. **低优先级打磨（P2-5~P2-13）**：税率百分比化、revision 参数加「回到最新」控件、页头发送轨改参照最新发送、错误 code 不上屏、动作词统一「前往/去…」。
