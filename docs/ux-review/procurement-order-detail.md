## 一、页面概述

采购单详情页（W08 对象中心）承载采购单的完整生命周期视图：页头（面包屑 + 状态 + 版本 + 单据号）、四轨状态条（审核/付款/进项票/履约）、六个子区页签（概览 / 明细与分配 / 履约 / 应付与票款 / 变更与异常 / 审计）、三种模式（view 详情 / edit 草稿编辑 / review 财务审核），并提供"提交财务审核 / 财务审核通过 / 驳回 / 发起采购变更"四个正式动作及"去付款发票 / 去对账结算 / 去交付"三个跨工作面跳转。

整体完成度高：确认对话框（状态变化 + 锁定字段 + 影响 + 下一责任部门）误操作防护完善，结果反馈（FormalActionResult）带参考编号与事实表，驳回后自动回编辑态、提交后自动进审核态，回退路径清晰；成本打码（`•••`）与角色权限意识良好。主要问题集中在三处：

1. **编辑模式无保存离开防护**（P0）：编辑中点任意子区页签即静默丢弃全部未保存修改；
2. **内部标识 / 字段名 / 枚举原值成片泄漏上屏**（违反术语表 §2「字段名/枚举原值上屏」P0 合规项，本页 10+ 处）；
3. **关键业务信息缺失**：概览页看不到金额合计，全页找不到交期（预计交期数据在契约里但没有渲染）。

## 二、易用性

| 路径 | 评价 |
| --- | --- |
| 查看详情 | 页头一次给出供应商、状态、版本、单号、来源销售单、类型、履约责任，配合四轨状态条，识别"这是谁的单、现在什么状态"路径最短；面包屑 + 返回列表双回退，顺畅 |
| 状态流转 | 提交 → 自动切 review 模式；通过 → 自动回 view；驳回 → 自动切 edit 模式，且驳回原因/说明在结果条中回显（detail-page.tsx:428-446）。流转闭环设计良好 |
| 核对明细 | 明细表列出项目/类型/数量/含税单价/税率/行含税/税额，行行右对齐等宽数字；但**概览页只放明细表、不放合计**，核对金额必须切到"明细与分配"页签（见 P1-2） |
| 进入编辑 | "编辑草稿"按钮仅在非 edit 模式显示，且移动端隐藏（detail-page.tsx:638-649）；移动端无任何替代入口，只能靠 URL 手改（P2） |
| 退出编辑 | **无"保存并退出 / 放弃修改"路径**：页签、面包屑、返回列表全部直接丢状态（见 P0-1） |
| 跨页面跳转 | "去付款/发票""去对账结算""去交付"均携带 `returnTo` 回跳本页，回跳链路好；但同一目的地（供应商往来 W12）出现 4 种不同按钮文案（见 P2-4） |

## 三、信息密度

- **突出做得好**：主状态徽章紧跟标题；"审核/付款/进项票/履约"四轨摘要常驻页头之下；先款门禁（PrepaymentGate 面板）在概览直接给出"最低有效付款金额 / 已分配 / 当前缺口 / 计算更新时间"与结论 Alert，属于本页信息密度最佳区。
- **过疏**：概览页（view 模式）只有"概览"描述列表 + 门禁 + "明细摘要"明细表，**没有系统合计（含税/不含税/税额）**——合计只在"明细与分配"页签出现（detail-page.tsx:915-949）；首屏读不到单据金额，必须多一次点击。
- **缺失字段**：`header.expectedDate`（最近预计交期）与 `line.expectedDeliveryDate`（行交期）在数据契约中齐备（types.ts:61,168；mock 种子也带），但**详情页全程未渲染**（仅预览面板有"最近预计交期"，preview-panel.tsx:154-160）。交期是采购单核对的核心信息，缺失影响判断。
- **信息冗余**："内容来源"渲染原始枚举 `SUBMISSION` 并拼接 `sha256:po01…a1` 哈希（detail-page.tsx:866-873），对用户零价值且泄漏实现词（见 P1-1）；"明细摘要"与"明细与分配"页签整表重复，可接受（概览摘要惯例），但建议概览改为 3-5 行截断 + 查看全部。

## 四、交互合理性

- **加载态**：`query.isPending` → "正在加载详情…"（detail-page.tsx:497-503），可接受；但无骨架屏，整页空白仅一行字。
- **错误/空态**：`!order` → "采购单不存在"并展示原始 `purchaseOrderId`（detail-page.tsx:505-519）。**没有区分 query error 与 not found**：网络/接口错误也会落进"不存在"，且无重试按钮，用户只能返回列表重进（见 P1-5）。
- **操作按钮语义与禁用逻辑**：提交/通过/发起变更均有确认对话框 + pending 禁用，规范；但"履约入口已阻断""发起变更不可用"两个禁用按钮的 title 仅来自 actionBlockers，当无对应 blocker 时 title 为空，用户看到禁用却无解释（detail-page.tsx:1003-1006, 1143-1149）。
- **误操作防护**：确认对话框列出锁定字段、影响、下一责任部门，防误触优秀；**但岗位分离（审核人≠提交经办人）只拦"通过"，不拦"驳回"**——同一个人可以驳回自己提交的采购单（detail-page.tsx:1631 vs 1684-1687，见 P1-3）。
- **反馈提示**：保存/提交/审核/变更结果统一走 FormalActionResult（成功/失败/结果未知/被阻断四态），并保留输入；结果未知提示"输入已保留，未切换状态"，处理严谨。
- **回退路径**：返回列表按钮 + 面包屑双入口；驳回→edit、提交→review、通过→view 的路由跳转合理。**唯一断裂点是编辑态离开**（P0-1）。
- **角色视图**：`viewerRole` 硬编码 `"procurement"`（detail-page.tsx:124），销售/仓储的 `costMasked` 分支在本页实际不可达，列表页的角色演示切换与详情页脱节（P2-9）。

## 五、问题清单（按严重度）

### P0（阻断操作）— 1 个

1. **编辑模式无保存离开防护，未保存修改静默丢失**
   - 编辑态下"明细与分配 / 履约 / …"页签链接均不携带 `mode`（detail-page.tsx:548-566，如 `?section=lines`），点击后 URL 变为无 mode 的 view，路由壳以 `key={purchaseOrderId}-{section}-{mode}` 重建整页（page.tsx:28），`draftEditToken` / `lineEdits` / 草稿表单全部重置；"返回列表"（detail-page.tsx:605）与面包屑同理。
   - 无 beforeunload 守卫、无"放弃修改"确认、无"尚未保存"提示。用户改完数量/单价直接点页签，修改全部消失且无任何提示。
   - 修复方向：编辑态离开前弹确认（未保存时），或页签链接保留 `mode=edit`，或提供"保存并返回"按钮；浏览器刷新同样建议加离开守卫。

### P1（明显阻碍效率）— 6 个

1. **内部标识 / 字段名 / 枚举原值成片泄漏上屏（违反术语表 §2「字段名/枚举原值上屏，必须清零」）**
   - 事实表直接以字段名为标签：`{ label: "lockVersion", value: … }`（detail-page.tsx:272）、数据版本值 `dch_po_01_v3` 哈希（detail-page.tsx:273）。
   - 提交成功 facts：`提交编号 = posub_01_v1`、`数据版本 = sha256:po01…a1`（detail-page.tsx:347-350）；变更成功 facts：`变更单 = poc_po_02_xxx`（detail-page.tsx:479）。
   - 概览"内容来源"渲染原始枚举 `DRAFT/SUBMISSION/REVISION` + subjectHash（detail-page.tsx:868-871）——预览面板却做了中文映射（preview-panel.tsx:223-229），两组件口径不一。
   - 审核通过确认对话框锁定字段直接写 `submissionId …` / `subjectHash …`（detail-page.tsx:1218-1221）；审核视图 Alert 显示 `submissionId …`（detail-page.tsx:1595）。
   - 明细表与编辑表渲染 `procurementConfirmationLineId`（`cl_xg_1`）（detail-page.tsx:1287-1290, 1466；preview-panel.tsx:258）；编辑卡"创建依据 `pcb_demo_01`"（detail-page.tsx:1379-1381；preview-panel.tsx:161-167）。
   - 单据号兜底展示内部 `po_*` ID（detail-page.tsx:524-527）；"采购单不存在"文案直接回显原始 ID（detail-page.tsx:510）。
   - 按术语表 §7 口径，应替换为「品名 + 数量 + 业务单号」/「数据版本」等业务表述。

2. **概览页无金额合计、全页无交期信息**
   - `DocumentTotals` 只在"明细与分配"页签渲染（detail-page.tsx:915-949），view 概览的"明细摘要"只有明细表（detail-page.tsx:1179-1183），首屏读不到含税合计。
   - `header.expectedDate` / `line.expectedDeliveryDate` 全程未渲染（对比 preview-panel.tsx:154-160 有"最近预计交期"）。采购核对"状态、金额、交期"三要素缺二。
   - 修复方向：概览加入合计（含打码态）与"最近预计交期"，明细表增加交期列。

3. **岗位分离只拦"通过"不拦"驳回"**
   - `samePerson` 判定仅作用于"通过"按钮（detail-page.tsx:1579-1581, 1631），驳回表单的"确认驳回"无任何守卫（detail-page.tsx:1684-1687，handleReject 亦无检查，detail-page.tsx:416-426），提交经办人可驳回自己的单据，审核分离形同虚设。
   - 另外 `samePerson` 用硬编码人名 `"财务 · 周敏"` 比较（detail-page.tsx:1580-1581），属演示残留，换真实身份字段后即失效。

4. **明细编辑输入与展示格式不一致，且无客户端校验**
   - 税率编辑框显示原始小数 `0.13`（detail-page.tsx:1512-1525），查看表却显示 `13%`（detail-page.tsx:1313-1315），同一字段两种格式，用户极易把 13 输成 0.13。
   - 数量/单价/税率三个输入均无格式校验（zod 只覆盖 paymentTermCode 与 note，detail-page.tsx:104-107），可输入空串、负数、非数字，错误要等保存后才以失败结果暴露。
   - 修复方向：编辑框展示与查看一致的百分比格式并做小数/正数约束，行内即时校验。

5. **加载错误态与"不存在"混淆，无重试**
   - 页面只处理 `isPending` 与 `!order` 两态（detail-page.tsx:497-519），`query.isError` 未分支：接口报错同样显示"采购单不存在"，用户无从得知是网络问题；无重试按钮，只能返回列表重进。
   - 修复方向：区分 isError（提示"加载失败"+ 重试按钮）与 not found（隐藏 ID，提示"单据不存在，可能已删除"）。

6. **付款条件保存后业务标签漂移**
   - 编辑下拉选项为简化标签"先款 100% / 货到 15 天"（detail-page.tsx:1428-1434），handleSave 又按 code 硬编码映射（detail-page.tsx:233-242），与单据原标签"先款 100% 后履约"（mock/purchase-orders.ts:314）不一致；保存后单据付款条件被替换为简化版，跨页（列表/预览/详情）标签从此漂移，且"先款 50% 后直发"这类带履约语义的标签在编辑中无法选择（下拉无此项，保持原值才有）。
   - 修复方向：下拉直接展示 `paymentTermLabel` 全集（含履约后缀），保存传原 label，不做二次映射。

### P2（体验瑕疵）— 11 个

1. **`mode=edit` / `mode=review` 调试徽标残留界面**（detail-page.tsx:798-807）：原始 URL 参数名直接上屏，应删除或改业务词（"编辑中 / 审核中"）。
2. **"模拟版本冲突"按钮留在正式界面**（detail-page.tsx:1543-1550）：演示/测试功能与"保存草稿"同排，用户误点会得到一条"保存失败"结果；演示环境按 G6 可保留但应移入演示工具栏或加"演示"徽标。
3. **实现词残留文案**："编辑信息仅保存在当前页面，不进入 URL。"（detail-page.tsx:1388-1391）、"正在编辑中 · 版本 {lockVersion}"（detail-page.tsx:1395，术语表 §2 已点名此位置应改为"正在编辑中"）、编辑卡描述"拆单维度变更需提示影响。"语义不明（detail-page.tsx:1382）。
4. **同一目的地（供应商往来）4 种按钮文案**：页头"去付款/发票"（detail-page.tsx:611）、门禁卡"去供应商往来登记付款"（detail-page.tsx:902）、履约区"先完成供应商往来付款"（detail-page.tsx:1014）、应付区"去供应商往来"（detail-page.tsx:1100），指向同一 w12PayHref（detail-page.tsx:522），统一为"去供应商往来"。
5. **状态轨颜色语义与预览面板不一致**：详情页付款/进项票 track 恒为 neutral（detail-page.tsx:759-771），预览面板同字段有 success/info 色阶（preview-panel.tsx:83-102）；"已付/完成"在本页看不出完成度。
6. **"关联对象"胶囊不可导航**（preview-panel.tsx:201-212）：销售/变更/应付均为静态 span（仅"去交付与代发"是链接），用户无法点击进入；"应付 count=1/0"仅表示有无，语义单薄。
7. **禁用按钮缺解释**：无对应 actionBlocker 时，"履约入口已阻断"（detail-page.tsx:1003-1006）与"发起变更不可用"（detail-page.tsx:1143-1149）的 title 为空，禁用原因不可见。
8. **审核模式点页签即退出审核视图**：与 P0-1 同根因（页签不携带 mode），审核员点"明细与分配"后审核卡消失，需再点"打开审核"恢复，无提示。
9. **`viewerRole` 硬编码 `"procurement"`**（detail-page.tsx:124）：成本打码分支（costMasked）在本页不可达，角色演示栏（列表页有）与详情页脱节，销售/仓储视角无法验证。
10. **驳回失败使用 blocked 语义**（detail-page.tsx:455-459）：失败结果 status 置 "blocked"，与"被阻断"（如无法进入编辑）语义混淆，应复用 rejected。
11. **移动端写操作全部不可达**：编辑草稿/打开审核/发起采购变更均 `mobileVisibility: "hide"`（detail-page.tsx:644, 656, 668），移动端无任何替代入口；另"提交前保存未成功"分支三目两臂相同（detail-page.tsx:319-321），死代码。

## 六、改进建议（按优先级）

1. **（P0）修复编辑态离开防护**：编辑模式页签/面包屑/返回列表一律拦截并弹"保存并退出 / 放弃修改 / 取消"确认；刷新/关页加 beforeunload 守卫；另提供显式"保存草稿并退出"。
2. **（P1）一次过扫清除内部标识泄漏**：`lockVersion / submissionId / subjectHash / draftContentHash / source 原值 / procurementConfirmationLineId / creationBasisId / changeId / po_* 兜底` 全部替换为业务词（单据编号、数据版本、确认分行 → 品名+数量+来源单号、创建依据 → 来源单据），对齐预览面板已有的中文映射口径。
3. **（P1）补全关键信息**：概览加系统合计（含税/不含税/税额，打码态同规则）与"最近预计交期"；明细表补行交期列。
4. **（P1）岗位分离对等化**：驳回提交同样禁用并提示"审核人不得为提交经办人"；用真实提交人字段替代硬编码人名。
5. **（P1）明细编辑体验**：税率编辑框改用百分比格式与查看一致，数量/单价/税率加正数约束与行内校验。
6. **（P1）错误态拆分**：isError → "加载失败" + 重试；not found → 不展示原始 ID。
7. **（P2）文案收敛**：统一供应商往来入口文案；删调试徽标与"模拟版本冲突"；状态轨色阶与预览面板对齐；审核模式页签保留 mode。
