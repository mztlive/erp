# UX 评审报告：主数据详情页（商品 / 供应商）

> 评审对象：`/master-data/[resource]/[stableId]`
> 对应代码：`erp-client/features/master-data/product-detail-page.tsx`（2134 行）、`supplier-detail-page.tsx`（1201 行），及关联组件

## 一、页面概述

两页采用「详情页 = 查看 + 编辑」同一页面设计：吸顶作业条（身份信息 + 停用/返回/检查/保存）、正文表单区块、
底部「历史与引用」（变更历史 / 引用与选用 / 操作记录）、停用对话框（`MasterDataDisableDialog`）。

- **商品详情**：左侧栏「填写助手 + 商品摘要」，右侧吸顶分区导航（基础信息 / 图文信息 / SKU / 生效信息 / 历史与引用），
  SKU 表格内联编辑（编码/条码/主图/价格/供给/库存/启用），供给经 HoverCard 查看并唤起「添加供应商」对话框。
- **供应商详情**：九个区块纵向堆叠（基本信息 / 商务与资质 / 资质附件 / 合同与授权 / 开票信息 / 合作评估 / 生效与原因 / 历史与引用），无分区导航、无填写助手。

整体结构清晰、版本语义（保存即新版本）表达到位，但存在一处 P0 级敏感信息泄漏，以及若干效率与一致性缺陷。

## 二、易用性

**做得好的**

- 查看与编辑合并，无模式切换心智负担；保存即新版本，区块说明文字（如「保存后形成新版本」）反复强化版本语义。
- 产品页供给入口闭环较好：SKU 行「N 家供应商」→ HoverCard 供应商列表 → 「添加供应商」（`RegisterSupplyForSkuDialog`）或「查看全部供给」跳转供应商商品库，且 `returnTo` 带回本页 SKU 区块。
- 停用操作有专门对话框（原因 + 停用时间 + 结果反馈），是良好的误操作防护。
- 填写助手点击问题项可滚动定位到对应区块（product-detail-page.tsx:1019-1044）。

**问题**

1. **供应商页无分区导航、超长滚动**：1200 行表单九个区块顺序堆叠，编辑「合作评估」需滚过合同、资质、开票六个区块；与产品页的吸顶 Tab 体验不一致（见 P1-8）。
2. **纯查看任务无路径**：两页都没有「查看模式/预览」，只想看价格、库存、供给的用户也必须滚过整个编辑表单（见 P2-13 摘要卡信息价值低）。
3. **只读角色看不到任何解释**：字段全部禁用但无「你只能查看」说明（见 P1-5）。
4. **敏感字段编辑无打码**：税号/银行账号/法人身份证以明文可编辑输入框渲染（见 P0-1），列表页与对象中心都有打码，唯独详情编辑页绕过。

## 三、信息密度

**做得好的**

- 吸顶作业条信息组织紧凑：单号、版本、生效期间、版本状态徽章一行排布（product:817-845 / supplier:431-459），关键状态（启用/停用、当前生效/待生效）始终可见。
- 产品页「商品摘要」与「商品约束」把 SPU 类型、SKU 数、基础单位、引用状态前置。

**问题**

1. **SKU 表格密度失衡**：14 列、`min-w-[88rem]`（约 1408px），常规 1440 屏可用宽度约 1000px，价格/供给/库存关键列被横向滚动挤出首屏（P1-7）。
2. **重复信息**：「商品约束」条（product:909-930）与「商品摘要」卡（product:1058-1090）都展示 SKU 数/基础单位/引用情况；「商品层级：SPU」是恒值静态项（product:1067-1069）。
3. **SKU 徽章「N / N 行已生成」恒等**：两个数永远相同，无信息量（product:1517-1519）。
4. **版本状态双徽章语义近叠**：「当前生效」状态徽章 + 生效期间文本并排，同一概念两种表达（product:828-844 / supplier:442-458）。
5. **供应商关键信息（评级/评分/结算方式/能力）埋在表单深处**，无摘要前置。

## 四、交互合理性

**做得好的**

- 提交结果用 `FormalActionResult` 分成功/阻断/冲突三种形态呈现（product:932-984 / supplier:510-562），冲突提示给出明确下一步（「关闭后刷新页面，再重新填写」）。
- 商品类型创建后只读并有原因说明（product:1200-1209）；基础单位字典联动 SKU 单位。
- 规格调整时按签名保留可匹配原 SKU 数据（product-model.ts:83-119），并提示「调整规格顺序时保留可匹配的原 SKU 数据」（product:1330）。
- 权限动作用 `allowedActions` + `actionBlockers` 驱动禁用与提示，方向正确。

**问题**

1. **无未保存离开防护**：「返回列表」是直接 Link，编辑内容静默丢弃（P1-3）。
2. **「批量设置」静默覆盖全部 SKU 价格**：无确认、无预览（P1-4）。
3. **加载/空/错误态基本合格**，但详情加载失败只有「重试」，无返回列表兜底（product:635-660 / supplier:339-364 已区分 404 与错误，此点 OK）。
4. **「填写检查」与提交校验重复**，检查通过绿条在字段被改后不失效（P2-9）。
5. **成功面板滞留**：保存成功后继续编辑新内容，旧「已保存」结果条仍显示，易误以为新改动已保存（P2-15）。
6. **校验错误条不自动定位**：在表单底部提交，错误提示出现在顶部，无滚动定位（P2-16）。
7. **SKU 直接切停用无确认**：被业务引用的 SKU 停用与资料停用（有 dialog）防护不对称（P2-17）。
8. **生效日期两页交互不一致**：产品页裸 Input，供应商页 DatePicker（P1-6）。

## 五、问题清单（按严重度）

### P0 · 阻断操作 / 权限失控

**P0-1 供应商敏感字段明文泄漏，绕过系统打码门禁**
- 位置：`supplier-detail-page.tsx:616-629`（联系电话）、`846-856`（法人身份证/食品许可证）、`892-904`（税号/开户银行/银行账号）
- 详情：`hydrateFromCenter` 从 `currentRevision.fields` 直接取原文（`data.ts:2250-2252` 存有 `91310000MA1FL0001A`、`6222000011110188`），以可编辑 Input 明文渲染。系统已设计 `sensitiveFields` + `SensitiveValue` 打码/短时查看机制（`master-data-center-page.tsx:343-368`、`copy.ts:60-61 permissionReveal`），列表页也已打码（`data.ts:841`），唯独详情编辑页整条链路绕过——任何能打开详情的角色都能直接看到身份证、税号、银行账号。

### P1 · 明显阻碍效率 / 明显违背规范

**P1-2 W21 工作面编号泄漏到用户可见文案（术语表 §2 规则 6，P1）**
- 位置：`product-detail-page.tsx:2030`（「…由 W21 的供给版本独立留痕，不写入 SKU 版本」）、`copy.ts:145`（`productSkuHint`：在 W21 独立维护）
- 建议：改为「供应商、供给方式、成本、税费和起订量按供应商商品资料独立维护，不写入商品版本」。

**P1-3 无未保存离开防护**
- 位置：`product-detail-page.tsx:871`、`supplier-detail-page.tsx:485`（「返回列表」直接 `Link` 跳转）
- 详情：编辑到一半点返回/侧栏切换，改动静默丢失；且无「放弃修改/取消」按钮，唯一的退出方式是离开页面。

**P1-4 「批量设置」静默覆盖全部 SKU 价格**
- 位置：`product-detail-page.tsx:768-783`（`applyBatchReferencePrices`）+ `1556-1568`
- 详情：已逐行填好的 SKU 价格会被批量值整体覆盖，无预览、无确认、无「仅覆盖空值」选项；误触即丢数据。

**P1-5 只读角色无解释文案（违反术语表 §7「禁用态不解释原因」）**
- 位置：`product-detail-page.tsx:1149/1285/1323/1898`（fieldset `disabled`）、`supplier-detail-page.tsx` 各 Input `disabled={!canEdit}`
- 详情：无 `CREATE_REVISION` 权限（无 blocker）时整页表单禁用但零解释；仅当存在 blocker 时才有一行小字（product:903-907）。应给出「你只能查看」式说明，而非一排无解释的禁用控件。

**P1-6 同一语义字段两页交互不一致**
- 位置：产品页 `product-detail-page.tsx:1908-1922` 生效开始/结束用裸 `Input`（无日历、无格式校验、无提示），供应商页 `supplier-detail-page.tsx:1001-1021` 用 `DatePicker`
- 详情：同族页面同一字段（生效开始/结束）两种交互，用户跨页操作需重新学习；产品页裸输入还容易产生格式错误。

**P1-7 SKU 表格横向滚动，关键列挤出首屏**
- 位置：`product-detail-page.tsx:1585`（`min-w-[88rem]`）
- 详情：14 列约 1408px，常规 1440 屏可用宽约 1000px；「公司商品池价格 / 供给 / 库存」这些用户最关心的列都要横向滚动才能看到，且滚动区无冻结首列。

**P1-8 供应商详情页无分区导航与填写助手**
- 位置：`supplier-detail-page.tsx:572-1184`
- 详情：九个区块顺序堆叠无吸顶 Tab（产品页有），无完成度/必填助手；编辑深层区块（合作评估）需要长滚动，且与产品页体验不一致。

### P2 · 体验瑕疵

**P2-9 「填写检查」冗余仪式 + 检查通过态过期**
- 位置：`product-detail-page.tsx:609-621`（`runLocalCheck`）、`876-887`、`1136-1144`
- 提交时本就执行同样校验；`checkPassed` 置真后修改字段（如删除 SKU 主图），绿色「填写检查通过」条不失效，误导用户。

**P2-10 恒等徽章「N / N 行已生成」**
- 位置：`product-detail-page.tsx:1517-1519`（`{fields.skus.length} / {fields.skus.length} 行已生成`）
- 两数恒等，纯噪声；应显示实际含义（如「共 N 个 SKU」）。

**P2-11 实现词泄漏（术语表 §1.3/§2）**
- 位置：`product-detail-page.tsx:1310`（「保存时仍写入原详情图数组」）、`:1087`（「沿用当前商品数据结构」）、`copy.ts:248`（「规格标识由系统内部派生」）
- 「数组」「数据结构」「标识」为实现词，业务用户不可读。

**P2-12 禁用词「同事务」**

**P2-13 摘要卡信息价值低 + 冗余**

**P2-14 成功面板滞留**

- `activeSection` 仅在点击时设置，手动滚动后高亮与实际位置脱节；无 IntersectionObserver/scroll spy。

## 六、改进建议（按优先级）

1. **（P0）敏感字段接入打码门禁**：供应商详情页复用 `sensitiveFields`/`SensitiveValue` 机制——只读展示打码值，编辑态按 `canRevealSensitive` 权限短时揭示，法人身份证/税号/银行账号不得默认明文；与对象中心（`master-data-center-page.tsx:343-368`）统一。
2. **（P1）离开防护 + 批量覆盖确认**：引入路由守卫/`beforeunload` 提示未保存改动，提供「放弃修改」；「批量设置」改为预览对话框（展示将被覆盖的行与旧值）或「仅填充空价格」模式。
3. **（P1）文案合规扫除**：删除两处 W21 编号（`product-detail-page.tsx:2030`、`copy.ts:145`），替换「数组/数据结构/标识/同事务」等实现词，跑术语表 §5.2 扫描。
4. **（P1）只读体验**：无编辑权限时在表单顶部给出「你只能查看」说明条（术语表 §7 模板），不摆一排无解释的禁用控件。
5. **（P1）SKU 表格可用性**：缩小 `min-w-[88rem]`（如 112rem 压到 ~1000px 内），冻结规格/编码首列，或把「供给/库存」收敛为徽章列减少列数。
6. **（P1）两页对齐**：供应商页增加吸顶分区导航与完成度助手；产品页生效日期改用 `DatePicker`，与供应商页一致。
7. **（P2）细节打磨**：移除「填写检查」冗余按钮或让检查结果随输入失效；清空成功条时机改为字段变更时；校验错误自动滚动定位；批量价格与规格删除加确认；供给数显示加载/失败态；删除恒等徽章与冗余摘要。
