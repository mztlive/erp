## 一、页面概述

该路由承载两个模式 + 两个子页面，共四个形态：

1. **列表模式（list，默认）**：供应商商品库 / 供给关系表。从商品中心（W14 固定 SKU）深链进入时，展示"当前 SKU ← 供给关系"上下文卡片、4 个概览指标和 8 列供给关系表；提供 Excel 导入、手工录入、加入公司商品池、处理来源变化等入口。
2. **队列模式（queue）**：供应商商品变化待处理。按 变化类型（需处理/停止供应/异常/新商品/关键变化/全部）× 待处理状态（待处理/稍后处理）双 Toggle 过滤；逐项展示 来源 Diff → 供应商商品资料 → 供货条件历史 → 发布影响 → 映射/草稿/替代候选/处理动作 的双栏决策工作台；异常项支持 领取→稍后处理/退回/确认解决/确认停供 完整动作链。
3. **详情/编辑页（/new、/:id）**：供应商商品中心，详情即编辑（保存形成新来源内容版本），可从列表或队列"查看详情"进入。
4. 三个写对话框：导入/手工录入（Intake）、固定 SKU 登记供给（RegisterSupplyForSku）、加入公司商品池（Promote）。

整体架构清晰、业务分层严谨（来源事实 → 采购确认成本 → 销售可见价 三权分离的文案表达很好），是四个形态里完成度较高的工作面。主要问题集中在：**内部 ID 上屏、一个"名不副实"的开关、以及"导入 Excel"入口的语义失真**。

## 二、易用性

**好的方面**

- 从商品中心深链（skuId 上下文）进入时，列表顶部用"ERP 商品 SKU → 供给到当前 SKU → N 条供给关系 / M 家供应商"卡片交代关系语义，并给出"添加供应商并登记成本"直达入口，路径顺畅（supply-relationship-list-view.tsx:450-480）。
- 列表"未入池"行直接提供"加入公司商品池"主操作，详情行有"详情"入口，主次分明（supply-relationship-list-view.tsx:357-378）。
- 队列页 58/42 双栏把"看什么"（左：diff/资料/历史/影响）与"做什么"（右：映射/草稿/动作）分离，异常项自动领取并展示处理权状态，动作链（稍后处理/退回/确认解决/确认停供）完整（supplier-catalog-page.tsx:1835-1897）。
- `returnTo` 白名单校验合理，跨页返回不会逃出商品中心域（supplier-catalog-page.tsx:233-237）。
- 空态、加载骨架、数据新鲜度、结果反馈（FormalActionResult）、操作确认对话框（lockedFields/effects/irreversibleEffects）齐全，是同类页面中反馈闭环最完整的。

**问题**

1. **列表行本身不可点**：查看一条供给的完整信息必须点右端"详情"按钮（supply-relationship-list-view.tsx:367-378），行点击无响应。表格 8 列信息密集，用户需要多次瞄准小按钮。
2. **队列页窄屏下单栏排列时，决策操作被推到长表单之后**：右栏包含 11 字段草稿表单 + 替代候选 + 处理动作，手机上处理动作在整页最底部。
3. **列表搜索与队列搜索语义不一致**：列表占位符"搜索供应商、商品名称或商品编码"（531），队列占位符"供应商商品编码 / SKU / 名称"（1030）且输入框仅 w-48 宽（192px），长编码输入困难。
4. **队列搜索输入不回填 URL 变化**：`searchInput` 只在挂载时从 `q` 初始化（supplier-catalog-page.tsx:355），浏览器后退改变 URL 后输入框不同步，且无清除按钮。

## 三、信息密度

**好的方面**

- 列表 8 列紧凑表 + 首列/操作列固定（column pinning），状态用徽章、成本用数字右对齐，扫描路径尚可；顶部 4 个指标（供应商 SKU / 已入池 / 正常供货 / 暂停或停供）给出总体脉搏。
- 队列页身份条把 变更类型、异常登记、稍后处理、成本隐藏 四个状态用徽章并排，信息完整。
- 关键辅助信息（"最小起订量是供应商的供货要求，不会复制为商城最小购买量"等边界说明）用 footer 小字给出，避免了误操作。

**问题**

1. **列表一次渲染全部行，无分页**：`showPagination={false}`（supply-relationship-list-view.tsx:555），查询侧也未传 pageSize/sort（queries.ts:37），供应商达到上百家后页面沉重、且无法翻页定位；排序是 DataTable 客户端本地状态（data-table.tsx:292），不落 URL、刷新即失。
2. **次要列与关键列视觉同权**："来源内容（媒体数/条码）"、"采购条件"、"供货范围" 与决策关键列（采购确认成本、状态）字号层级相同；成本列在无确认价时退化为小字"报价 ¥x · 待确认"，信息层级未拉开。
3. **身份条徽章冗余**：异常项同时显示"异常数据"状态徽章 + "供应商数据异常 · 待处理"次级徽章（supplier-catalog-page.tsx:1227-1236），两个徽章语义重叠。
4. **队列页左栏信息总量偏大**：diff 面板 + 10 字段资料 + 供货条件历史 + 发布影响四个卡片堆叠，配合右栏表单，单屏内容超过 30 个信息单元；无任何折叠机制。

## 四、交互合理性

**好的方面**

- URL 参数与控件对应关系整体良好：changeType/status/sourceType/q/skuId 均有控件或清除入口；`queueContextId` 缺省时自动补齐到 URL（459-490），刷新可恢复队列上下文。
- 状态切换（待处理/稍后处理）、自动领取、确认对话框的副作用描述均准确。
- 成本掩码逻辑自洽："无查看权限"替代金额，徽章"成本字段已隐藏"，diff 用 *** 掩码。

**问题**

1. **"自动下一项"开关名不副实（严重）**：开关文案承诺自动跳到下一项，但实际行为只是让结果面板出现一个"下一项"按钮（supplier-catalog-page.tsx:1087-1103），终结后也不会自动跳转（代码注释 777-779 明示"用户点「下一项」再跳"）。`autoNext=1` 存进 URL 形成持久状态，用户开启后期待自动流转却永远需要手点——违反术语表"按钮文案必须与实际行为一致"契约。
2. **"导入 Excel"并不导入（严重）**：Excel 来源对话框只把文件名记入 `sourceReference`（catalog-write-dialogs.tsx:328-335），没有上传、解析、预览步骤，后续全部字段（名称/规格/分类/双底价/起订量/图片…）仍须手工填写，对话框标题却叫"导入供应商商品 Excel"，且描述声称"按供应商模板校验 SPU/SKU、报价和规格"（332）——与实际行为不符。
3. **硬编码日期默认值**：`PromoteSupplierProductDialog` 的 `validFrom` 默认值硬编码为 `"2026-08-02"`（catalog-write-dialogs.tsx:844、917），与 Intake/Register 对话框用 `todayIso()`（66-68）不一致；日期过期后默认生成**过去的**生效日，用户不留意即提交错误供给。
4. **错误态信息过简**：队列/列表加载失败仅"加载失败 + 重试"（supplier-catalog-page.tsx:821-833），无失败原因或重试之外的建议。
5. **空态文案与原因不匹配**：`emptyReason === "FILTER_NO_RESULT"` 与 `"NO_TASKS"` 共用同一份"当前筛选项已处理完"文案（1125-1133 vs types.ts:378），筛选无结果时误导用户以为"做完了"。
6. **禁用按钮的解释不可见**：多处禁用按钮把原因写在 `title` 上（"尚未确定恢复负责人…"1543-1548、"商品关联确认功能暂未开放"1639-1648、1762-1771、1810-1820），原生 disabled 按钮不触发 hover，title 提示基本不可达；幸而所在卡片有描述文字兜底，但"（暂不可用）"后缀刷屏且无路径提示。
7. **同义按钮并存**：队列页"确认异常已解决/确认停供记录"同时出现在流程条（SequentialProcessBar）、处理动作卡、结果面板三条路径，三处行为一致但入口重复，容易让用户犹豫点击位置。

## 六、改进建议

按优先级：

1. **（P1-1）修正"自动下一项"**：要么实现真正的自动跳转（完成后停留展示结果 1.5s 再 `goToItem(neighbor(1))`），要么把开关改为"完成后显示下一项按钮"并同步改 URL 参数语义；不可保留"自动"二字。
2. **（P1-3）重做"导入 Excel"交互**：至少做到"选文件 → 上传 → 解析回填字段 → 确认保存"三步；若 demo 阶段无法解析，改按钮文案为"按 Excel 模板录入"并在描述中说明当前需手动填写。
3. **（P1-2）清零内部 ID**：`skuId`/`supplierProductId`/`queueContextId`/`publicationId` 一律通过 skuContext/商品名/编码等业务身份呈现；"队列"标识改为可读过滤描述；`filterSummary` 中 skuId 替换为商品名。
4. **（P1-4）生效日期默认值**：统一改为 `todayIso()`（与 Intake 一致），并给出"生效日期默认今天，可修改"的字段说明。
5. **（P1-5）枚举/ID 渲染治理**：为 `pauseSubResults.status`、`mapping.history[].status` 建立中文映射表（参照 `offeringStatusLabel`），`publicationId` 换为发布商品名或商品编号。
6. **（P2）列表体验**：分页（或虚拟滚动）+ 总条数展示；排序落 URL（sort 参数与控件对应）；行点击进入详情；"来源内容"列降级为可折叠列或删列，突出"确认成本 + 状态 + 起订量"三要素。
7. **（P2）空态与错误态**：区分 FILTER_NO_RESULT（"没有符合条件的供应商商品，可调整筛选"）与 NO_TASKS；错误态展示失败摘要。
8. **（P2）文案对齐**：Toggle 标签与徽章文案同源（复用 `CHANGE_TYPE_LABEL`）；"未登记/观察/来源修订/数据结构"按术语表替换；搜索占位符统一；禁用按钮原因移到卡片内可见文字（移除"（暂不可用）"后缀，改为说明"确认功能暂未开放，可先保存草稿"）。
9. **（P2）窄屏**：草稿表单与处理动作卡在移动端置顶（或提供锚点导航），避免动作沉底。
