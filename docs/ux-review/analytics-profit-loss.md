# UX 评审报告：/analytics/profit-loss（实际经营盈亏）

> 评审对象：`erp-client/features/actual-profit-loss/actual-profit-loss-page.tsx`（1835 行）及
> 同目录 `api.ts` / `queries.ts` / `types.ts`、`mock/actual-profit-loss.ts`、
> 共享组件 `components/business/{page,list,data-table,feedback,option-combobox}.tsx`
> 评审视角：产品经理 / UX；纯分析，未改动任何代码。
> 术语基准：`docs/ui-glossary.md`（禁用词表，含"枚举原值不上屏""内部 ID 不上屏""W 编号不进提示"三条硬规则）。

## 1. 页面概述

- 路由：`/analytics/profit-loss`（W16），菜单名"实际经营盈亏"，页头标题"实际经营盈亏（非卡券 · 不含税）"。
- 页面结构（自上而下）：
  1. 页头（数据新鲜度 + 刷新/导出）
  2. 统计期间与归属口径卡（期间快捷 3 预设 + 已解析期间 + 归属口径下拉）
  3. 口径未配置时的阻断 Alert + 公式说明卡
  4. 数据陈旧/重建/失败/纠错登记等条件 Alert
  5. 成本覆盖率卡（进度条 + 覆盖/未覆盖收入 + 可靠性徽章）
  6. 核心指标条（5 项 KPI）
  7. 口径说明 Alert
  8. 盈亏趋势卡（折线图 + 数据表）+ 成本构成卡（条形图 + 列表）
  9. 预计/已确认成本对照卡
  10. 明细筛选（搜索 + 覆盖下拉）、维度 Tab、明细表格
  11. 成本记录下钻抽屉（QuickPreviewSheet）
- 数据链：TanStack Query + mock API（`fetchProfitLossView` 一次性返回趋势/构成/汇总/明细），URL 查询参数驱动。

## 2. 易用性

**顺畅的部分**
- 主任务"看利润"路径极短：进页即见 KPI 条 + 覆盖率卡，数字语义完整（"亏损 -¥…"红字、覆盖/部分/未覆盖三态徽章、利润率不可用原因 title 提示）。
- 明细下钻路径清晰：盈亏/销售单号 → 销售单（新标签页），成本金额 → 成本记录抽屉；抽屉内按成本类型分片切换（`actual-profit-loss-page.tsx:1676-1690`），关闭后焦点回落到触发行（`:413-422`）。
- 键盘路径用心：`/` 快捷键聚焦搜索（`:376-394`）、表行上下箭头移动、Enter 打开（data-table.tsx:802-817），"搜索销售单号、客户（/）"占位文案提示了快捷键。
- 口径阻断态设计合理：配置缺失时页面整体阻断并给"任选一个口径"的显式按钮，杜绝静默猜口径（`:305-324`、`:968-999`）。

**阻碍效率的问题**
- **期间不可自定义**：只有"本月迄今/上月/本季迄今"三个固定预设，无日期范围选择器，任意期间查询只能靠手工改 URL。且预设日期在代码里硬编码锚定 2026-08-01（`:154-163`），"本月迄今"解析为 `2026-08-01 ~ 2026-08-01` 单日区间，与字面含义不符——分析类用户的核心动作（自选期间看利润）被截断。→ P1
- **表头排序是"假排序"**：`sort` 参数在 URL 默认 `actualProfitLossNet:asc`（`:268`），服务端按此排序（api.ts:89-103），但 `DataTable` 未接 `sorting`/`onSortingChange`（`:1571-1580`），manualSorting 下点击表头只对当前页 20 行做客户端重排；翻页后行序与表头箭头不一致，用户会误以为全局已按所选列排序。→ P1
- **维度 Tab 无实际效果**：五个维度（销售单/客户/福利场景/履约方式/成本类型）返回的是同一份销售单行集，切换后仅副标题与摘要文字变化（`:1526-1542` + api.ts 未按 dimension 重塑行），操作无数据反馈，演示中极易被认为"坏了"。→ P1
- 搜索为全量模糊匹配（销售单号/客户），无维度内二级筛选（如按成本类型筛选明细），分析深挖能力有限——属演示数据规模内的可接受简化。

## 3. 信息密度

**密度基本合理**
- 页面是典型的"指标卡 + 图表 + 明细"三层漏斗，KPI 条 5 项与明细列一一对应，术语一致（不含税收入/实际采购成本/实际履约费用/实际盈亏/利润率）。
- 成本覆盖率卡把"数据可信度"前置，符合分析决策对"这笔数能不能信"的第一追问；可靠性三态（可靠/部分可靠/不可用）贯穿 KPI detail、图表、明细覆盖徽章。

**失衡之处**
- 顶部 Alert 过多：覆盖卡、口径说明、趋势/构成、对照卡之外，条件 Alert 可同时出现 3~4 条（陈旧+纠错+口径说明），首屏在窄屏下需要滚动两次才见 KPI；"口径说明"（`:1245-1255`）内容与"公式与边界"卡（`:1001-1014`）及页脚口径重复，属于长期常驻但多数用户不会读的次要信息，建议降级为 tooltip 或可折叠。
- 明细"福利场景/履约方式"列与维度 Tab 信息重叠（切到"福利场景"维度时表内仍有该列），多列 `text-muted-foreground` 视觉上"灰成一片"，但金额列有等宽数字与红绿语义色，整体可扫读。
- **图表与汇总口径一致性有缺口**：趋势图（2026-03~08 固定序列）与成本构成图完全不随期间/覆盖筛选联动（api.ts:319-325 无条件返回 `W16_TREND`/`W16_COST_COMPOSITION`），而卡片文案明确写"与汇总同范围"（`:1262`）、表格说明写"与指标/图表同一数据范围"（`:1569`）——用户切换"上月"后 KPI 和明细变了、两张图纹丝不动，图文互证关系断裂。→ P1
- 趋势卡内图表以"万元"、下方数据表以"元"（`formatMoneyDisplay`）同卡并列，且 sr-only caption 标注"金额单位万元"与实际不符（`:1312` vs `:1327-1336`）。→ P2
- 成本构成列表保留 0 值项（平台/技术服务 0.00、线下服务 0.00），而图表过滤了 0 值行（`:677` vs `:1395`），图列项目不一致。→ P2

## 4. 交互合理性

**加载 / 空 / 错误态**
- 初载骨架、口径读取失败重试、数据加载失败重试、空态"清除筛选"均齐备（`:772-816`、`:1019-1042`、`:1544-1565`）。
- **有数据后的二次失败被静默**：`isError && !data` 才渲染失败态，refetch 失败时旧数据继续展示且无任何提示（`:1031`、`:1044`）——覆盖筛选/刷新出错时用户无法察觉。
- **筛选变更无加载反馈**：`DataTable` 未接 `loading`（data-table.tsx 的"正在刷新，当前内容会保留"横幅未被使用），切换覆盖/维度时旧数据原样停留，mock 快看不出问题，真实接口下会明显滞后。→ P2
- 抽屉内成本记录查询失败落入"当前行无可查看的成本记录（无权限或完全未覆盖）"分支（`:1697-1701`），把"加载失败"归因为"无数据"，错误归因错误。→ P2

**图表交互**
- 折线/条形图仅提供悬停 tooltip 与图例，无点击下钻、无数据点强调；趋势图 X 轴 6 个周期跨度远超当前筛选期间（如单日期间 08-01~08-01 时仍画 03~08 全序列），若无口径说明，用户会把图表误解为"当前筛选结果"。→ P1（并入 3.4 同一问题）

**下钻与误操作防护**
- **死可点**：`openCostDetail` 在 `costEntryIds.length === 0` 时静默 return（`:431-438`），但"实际采购成本/实际履约费用"金额 cell 仍渲染带 `hover:underline` 的 button（`:519-528`）——row-so-004/005 存在可点击样式但点击无任何反应，用户会反复点击以为卡顿。→ P1
- 导出是只读动作 + 水印，防误操作设计好；但**导出失败无任何用户反馈**：`handleExport` 无 try/catch（`:712-769`），`exportMutation.mutateAsync` 抛错即未处理 Promise，按钮态也不恢复（disabled 只绑 `isPending`），用户点了导出"什么都没发生"。→ P1
- 空态"清除筛选"只清了 q/customerId/salesOrderId/coverage，不清维度 Tab——可接受（Tab 是视图而非筛选）。

**按钮语义**
- 导出按钮 disabled 条件完整（口径、无数据、无权限、0 行、进行中，`:868-873`），移动端隐藏（`mobileVisibility: "hide"`），符合设计规范。
- "演示：来源纠错后等待刷新"（`:1586-1596`）是 mock QA 控件，却出现在正式页面内容流中，与相邻说明文字挤在一行；演示环境（G6 保留"演示"标记）可接受，但生产必须隐藏。

**URL 状态契约（AGENTS.md「URL 参数与界面控件一一对应」）**
- `fieldHide=cost|profit`、`freshness=stale|rebuilding|failed`、`basisConfig=missing` 三个参数被查询消费（`:269-278`、`:354-359`、`:300-302`）但无任何控件、无清除途径，用户改不动的隐形状态残留。QA 用途可保留，建议加"演示模式"统一开关或在生产构建中剥离。→ P2

**文案（对照 `docs/ui-glossary.md`）**
- **枚举原值/内部 ID 大面积上屏**：抽屉内"商品（GOODS）""非卡券履约（NON_VOUCHER_FULFILLMENT）""采购入库（PURCHASE_RECEIPT）""来源版本 v3""来源单据 pr-20260718-01""原成本引用 ce-act-001 · 商品实际成本"（`:1718-1814`）；公式文案 "cost_scope=NON_VOUCHER_FULFILLMENT 且 stage∈{ACTUAL,REDUCTION}"（mock/actual-profit-loss.ts:27）；口径说明 Alert 中 "GOODS_SERVICE、MALL_CONSUMPTION、WECHAT_COST"（mock:24）；"权限版本 pv-w16-demo-1"（`:1252`）、"公式版本 pl-formula-v1.2.0"（`:837`）。这些是财务用户不可读的实现词，术语表第 5 轮明确"枚举原值上屏必须清零"、内部 ID 不得进界面。→ P1
- **"W16"进用户提示**："W16 不执行变更确认。打开原业务对象使用变更/冲减流程…"（`:1822`），违反"工作面编号禁止出现在用户提示"（术语表 §1.6、§3.6）。→ P2
- **中英混排**：抽屉标题"成本记录 detail"（`:1615`）、表描述"点击成本金额打开成本记录 detail"（`:1569`）。→ P2
- **"亏损"误用**：成本冲减列负值经 `MoneyCell` 默认 `negativeAsText` 渲染为"亏损 -¥10,000.00"（`:572`、`:195-234`）——冲减是成本减少、正向贡献，语义完全反了，财务用户会误读。→ P1
- 导出 CSV 头部含原始枚举 `COVERED/PARTIAL/UNCOVERED` 与元数据行 `amountBasis=NET`、`businessType=GOODS_SERVICE`（`:726-743`），CSV 是用户产物，建议换成中文映射。→ P2
- 好消息：未发现"投影/租约/水位/缓存"等禁用词，新鲜度文案（"数据陈旧/数据更新中/保留旧数据"）与 freshnessText 一致；"打开销售单"（openWorkspaceLabel("W05")）符合规范。

**数据刷新**
- 手动刷新有 refreshing/refreshFailed 双态与"保留旧数据"提示（`:693-710`、`:1046-1057`），演示级刷新失败可模拟，设计完整。无自动轮询——对利润分析页合理。

## 6. 改进建议（按优先级）

1. **补齐期间选择器**（P1-1）：增加"自定义日期范围"（起止日期双输入或 DateRangePicker），URL `from/to` 与控件双向同步；预设锚点改为运行时取当前月，确保"本月迄今"跨多日。
2. **表头排序接全局状态**（P1-2）：将 `sort` 写回 URL（`actualProfitLossNet:asc|desc`），服务端分页 + 服务端排序，排序指示与翻页后的行序一致；列配置面板已具备，只差接线。
3. **统一筛选联动口径**（P1-3/P1-4）：趋势/构成图与 KPI 使用同一查询范围；维度切换按维度重塑行集（客户维度聚合客户、场景维度聚合场景）。至少让图表标题反映"未随筛选变化"，并在 mock 中消除"维度切换无变化"。
4. **消灭实现词上屏**（P1-5/P2-5/P2-8）：为抽屉字段建中文映射（费用类型/阶段/范围/来源类型/来源单据只展示中文与业务单号），删除 `（GOODS）` 类括号原文；公式文案去掉枚举条件；"W16"改"本页"；CSV 枚举转中文。用 `docs/ui-glossary.md §5.2` 的扫描命令回归。
5. **冲减列语义修正**（P1-6）：成本冲减负值禁用"亏损"前缀，改为"-¥10,000.00"并在列头注明"负值为冲减（降低成本）"；利润/收入列保留现"亏损"语义。
6. **死可点与失败反馈**（P1-7/P1-8/P2-1/P2-3）：`costEntryIds` 为空时金额 cell 不渲染 button（或渲染禁用态 + tooltip"本单暂无成本记录"）；`handleExport` 包 try/catch 并接入统一失败提示；refetch 失败在页头 DataFreshness 置 failed 态；抽屉查询失败渲染独立错误态。
7. **降低首屏密度**（§3）：口径说明与公式说明合并为可折叠/隐藏的"口径说明"；条件 Alert 允许同屏最多 2 条，其余并入页头状态区。
8. **QA 参数收敛**（P2-9）：`freshness/fieldHide/basisConfig` 移入统一的演示工具栏或仅开发构建生效，避免 URL 残留隐形状态。
