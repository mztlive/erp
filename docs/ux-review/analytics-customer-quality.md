# UX 评审报告：客户经营质量（/analytics/customer-quality）

> 评审视角：产品经理 / UX
> 评审对象：`erp-client/features/customer-quality/customer-quality-page.tsx`（1886 行）及引用的 `queries.ts`、`api.ts`、`types.ts`、`components/business`（page/values/feedback/list/domain/option-combobox/data-table）
> 术语基准：`docs/ui-glossary.md`（基线 v1.2）
> 日期：2026-08-05
> 严重度：P0 阻断操作 / P1 明显阻碍效率 / P2 体验瑕疵

---

## 一、页面概述

「客户经营质量」是 W15 分析工作面的一级页面（只读分析），面向销售/运营管理层，回答三件事：**客户整体质量如何**（核心指标条）、**客户结构如何**（规模分层 / 利润贡献 / 业务性质分布）、**单个客户如何**（客户明细表：成交、成本覆盖、盈亏、应收逾期、异常、最近业务）。

页面布局自顶向下：页头（数据新鲜度 + 期间/范围 + 刷新/导出）→ 新鲜度/刷新失败 Alert → 筛选卡（期间起止、快捷期间、票款口径、业务性质、排序、搜索）→ 卡券票款复核进度 + 成本覆盖双卡 → 核心指标条 → 双图表（规模分层 / 利润贡献，柱形可点击下钻筛选）→ 图表筛选生效提示 → 客户明细表 → 导出任务进度卡 / 经营标签说明弹窗。

整体架构质量很高：状态齐全（fresh/stale/rebuilding/failed/refresh_failed）、错误/空态细分、URL 作为唯一状态源、下钻带回程聚焦、口径一致性提示贯穿全页（成本覆盖必须与利润同屏解读、卡券不计盈亏、缺失成本不显示 0）。问题集中在**分页数据截断、双排序入口冲突、术语合规**三类。

---

## 二、易用性

**做得好的地方：**
- 无默认期间时进入「期间选择」阻断页（`customer-quality-page.tsx:813-886`），文案明确"选定期间后才会显示指标、图表与明细"，并提供快捷期间，学习成本低。
- 下钻路径设计完整：客户名 → 客户中心；成交金额 → 销售单（带期间与业务性质）；逾期 → 客户往来（overdue 视图）；实际盈亏 → 利润分析，且 `returnTo` + `focusCustomerId/focusMetric` 支持返回后定位原行（`:150-165, :421-438`）。
- 图表与等价数据表双轨呈现（`:1432-1531`），数据表每行是按钮可点击筛选，视力/鼠标偏好兼顾。
- 「当前筛选无客户结果」时指标、图表不归零并显式解释（`:1747-1779`），避免了"筛选把全局指标带崩"的常见误导。

**核心任务路径问题：**
1. **排序存在两个互相矛盾的入口**（P1，详见问题 2）：顶部「排序」下拉是全局服务端排序，表格表头点击却是当前页 20 行的局部客户端排序，两处状态互不感知。
2. **筛选变化后不回到第一页**（P1，详见问题 3）：改期间/票款口径/业务性质后若停留在第 2 页，可能看到空表或错位数据。
3. **指标卡点击语义含糊**（P2，详见问题 9）：点击成交金额/实际盈亏/逾期指标卡只是卡片高亮，不联动表格，用户会以为能筛选或定位。

## 三、信息密度

**平衡性总体良好**，与分析类用户（需要"数字 + 口径 + 可下钻"）的需求匹配：

- 核心指标条 4 列 + 可靠性徽章（部分可靠/不可用）+ 口径说明，密度适中；`MetricFilterItem` 提供选中态，可做聚焦。
- 表格 8 列、compact 密度 + 列设置（显隐/顺序/固定/拖宽，`data-table.tsx:887-1015`），专业分析工具水准。
- 覆盖率卡强制与利润口径同屏（`:1312-1338`），并把"缺失成本不显示为 0"写成提示，是数据可信度设计范例。

**信息过密/过疏的瑕疵：**
- 「异常」列用压缩缩写「退 3 · 款 2 · 拒 1 · 它 5」（`:690-698`），无图例无 tooltip，新用户要猜"退=退货？退款？"；同为高频诊断列，信息密度过高且缺解释。
- 图表的柱形颜色明确声明"仅作区分，具体数值见下方表格"（`:1428`）——颜色无语义等于放弃了一个视觉通道，是信息设计上的妥协（诚实但低效）。
- 页头 metadata 已显示「期间 x ~ y · 系统默认」（`:962-969`），筛选卡里又有一组期间控件，信息重复但无害。
- 顶部 Alert 通道被复用于四种数据状态 + 票款复核 + 图表筛选，同时最多可叠 3 条（stale + 票款复核 warning），分析首屏噪声偏大，但每条都有业务价值，属可接受。

## 四、交互合理性

**加载 / 空 / 错误状态（出色）：**
- 三阶段加载壳（期间策略加载 / 视图加载 / 全屏骨架）分层明确（`:777-918`）；刷新时保留旧内容并在表格顶部显示"正在刷新，当前内容会保留"（`data-table.tsx:655-663`）。
- 空态区分 `no-data` / `filter` / `no-scope` / `forbidden` 四种并给下一步动作（`:1239-1244, :1741-1779, :920-935`）。
- 期间策略失败显式拒绝静默降级到自然年（`:792-810`"不会静默采用自然年"），可信度细节到位。
- stale/rebuilding/refresh_failed/failed 各配独立 Alert 且不互相替代（`:1006-1040`），符合"非互斥状态不合并展示"的注释意图。

**图表交互：**
- 柱形点击筛选 + 高亮 + 表格联动 + 「图表筛选已生效」Alert + 一键清除（`:1460-1471, :1708-1738`），链路完整。
- 但柱形点击仅在 recharts `Cell.onClick` 上实现（`:1450-1472, :1577-1599`），无可聚焦语义、无键盘路径（P2）。

**按钮与误操作防护：**
- 全页为只读分析，无破坏性操作，无需二次确认；下钻跳转全部带 returnTo 且返回后可聚焦定位，误操作风险低。
- 「清除筛选」按钮在满足任一筛选条件时出现（`:1200-1230`），位置固定、语义正确。

**数据刷新：**
- 刷新 = invalidate 全部 customer-quality 查询 + refetch（`queries.ts:60-68`），刷新中按钮变「刷新中」并禁用（`:978-988`）。
- 刷新失败场景无前端反馈：`refreshMutation.mutateAsync()` 未 await/未 catch（`:985`），失败时会产生 unhandled rejection，页面只靠 `viewQuery` 的状态兜底，用户看不到"刷新失败"提示（P2）。

**可改进的交互：**
- 导出按钮禁用（无权限/无数据/导出中）无原因说明（`:995-999`），未使用 `GuardedBusinessAction` 的禁用原因层。
- 返回定位依赖双 rAF + `querySelector` + `CSS.escape`（`:421-438`）——脆弱，且若目标客户不在当前页/当前排序结果中会**静默失败**，无任何提示。
- 期间起止无先后校验（`:1048-1073`），`from > to` 会静默查出空数据。

## 五、问题清单（按严重度）

### P0（阻断操作）— 1 个

**P0-1 明细表数据在 50 行处被截断，超出部分永远无法访问**
- `customer-quality-page.tsx:376` 查询固定 `pageSize: 50`（服务端只回 50 行）；`:440-444` 客户端再按每页 20 条 `slice`；`:1789` 却把 `rowCount` 传为 `data.customers.filteredTotal`（真实总数）。
- 结果：当筛选结果 > 50 户时，「共 N 条」按真实总数显示，但第 3 页（第 40~50 条）之后表格为空，DataTable 渲染"当前筛选没有结果"（`data-table.tsx:858-871`），而分页器仍显示总页数（`data-table.tsx:1093-1095`）。客户明细是本页核心任务，多数客户静默不可见。当前 mock 仅 6 行（`mock/customer-quality.ts:69`）掩盖了该缺陷。
- 修复方向：服务端真正分页（pageIndex/pageSize 进查询参数），或去掉客户端二次分页并让服务端返回全部。

### P1（明显阻碍效率）— 6 个

**P1-1 表头排序与顶部排序下拉冲突：局部排序冒充全局排序**
- 顶部「排序」下拉（`customer-quality-page.tsx:1148-1168`）写入 `sort` URL 参数做全局排序；但 `DataTable` 未受控 `sorting`（`customer-quality-page.tsx:1785-1794` 未传 `onSortingChange`），表头点击排序（`data-table.tsx:719-736`）只对当前页 20 行做客户端局部排序，且排序状态与下拉完全脱节（用户点「实际盈亏」表头后，下拉仍显示「成交金额降序」）。
- 影响：分析用户最常用的"按列重排"动作得到的是局部错乱结果，翻页后顺序又变回全局序，且与顶部下拉状态矛盾，误导决策。

**P1-2 期间/票款口径/业务性质/排序变化后不重置分页，可停留在空页**
- 图表筛选（`:1460-1471`）、搜索（`:1183-1196`）、清除筛选（`:1212-1226`）都重置了 `pageIndex`，但期间起止（`:1048-1073`）、快捷期间（`:761-774`、`:1080-1098`）、票款口径（`:1106-1112`）、业务性质（`:1130-1133`）、排序（`:1151`）均未重置。
- 影响：用户在第二页改口径后，新结果不足 40 条时表格呈现"当前筛选没有结果"空态（指标区却仍显示总体指标），需手动回第一页才能确认，数据可达性受损。

**P1-3 `scope` 是用户改不动的隐形状态**
- `scopeId = searchParams.get("scope") ?? "scope:team:sales-east"`（`:267`）被 `analysisQuery` 消费（`:368`），但页面没有任何范围切换控件；`?scope=xxx` 会静默改变数据范围，仅在页头 metadata 显示范围标签（`:971`）。
- 违反 `AGENTS.md` §5「URL 参数与界面控件一一对应」——要么补范围选择器，要么从查询中移除该参数。

**P1-4 用户可见文案直接上屏工作面编号「W13」**
- `customer-quality-page.tsx:1284-1285`：「应收余额、逾期金额等指标标记为部分可靠。可切换「仅已复核」或前往 **W13** 复核。」——同段按钮已用 `openWorkspaceLabel("W13")`（`:1304`），描述却手写编号。
- 违反 `docs/ui-glossary.md` §2 P1 行「Wxx 工作面编号（面向业务用户的提示）」→ 应写「卡券票款复核」。

**P1-5 成本口径枚举原值上屏（ACTUAL / STANDARD / NONE）**
- 本页使用 `CostCoverageNotice`（`:1312-1338`）时直接渲染共享组件 `domain.tsx:927-938` 的标签「ACTUAL · 实际成本」「STANDARD · 标准成本」「NONE · 成本未覆盖」。
- 违反术语表「禁止把枚举原值直接渲染」；「当前成本口径」处应只显示中文。

**P1-6 导出结果文案泄露内部 ID 与枚举原值**
- 导出任务卡显示 `label: "导出任务 ${exportJob.jobId}"`（`:1818`），jobId 为 `EXP-W15-*` 内部标识（`api.ts:381`）；描述中「权限版本 `pv-w15-demo-1`」（`:1822-1823`）为内部版本 ID 上屏。
- `api.ts:391-392` 的 `amountBasisNote`：「成交金额=含税(GROSS)；实际盈亏=不含税(NET)」——GROSS/NET 原值上屏。
- 违反术语表规则 7 与内部 ID 禁入界面条款；权限版本对用户无意义。

### P2（体验瑕疵）— 10 个

**P2-1 指标卡点击只高亮不联动**（`customer-quality-page.tsx:1380-1399`）：`MetricFilterItem` 点击仅切换 `focusMetric` 高亮，页面内无滚动/聚焦表格的后续行为（聚焦 effect 只在 `focusCustomerId` 存在时执行，`:421-438`），用户以为能筛选，实际无操作结果。

**P2-2 返回定位静默失败**（`:421-438`）：双 rAF + `querySelector` 定位，若目标客户不在当前页/排序结果内则失败且无提示；建议降级为"定位失败时滚动到表格顶部"。

**P2-3 期间起止无先后校验**（`:1048-1073`）：`from > to` 静默出空数据，建议在选择时校验并提示。

**P2-4 「异常」列缩写无解释**（`:690-698`）：「退/款/拒/它」无图例、无 tooltip、无表头说明，建议改为「退货 3 · 退款 2 · 拒收 1 · 其他 5」或加 tooltip。

**P2-5 图表柱形不可键盘操作**（`:1450-1472, :1577-1599`）：点击筛选仅挂在 `Cell.onClick`，无 `role="button"`/键盘路径，无障碍与键盘用户被排除。

**P2-6 导出按钮禁用无原因**（`:995-999`）：无权限/无数据时按钮直接 disabled，未用 `GuardedBusinessAction`（`feedback.tsx:88-148`）提供原因说明。

**P2-7 刷新失败无前端反馈**（`:984-987`）：`refreshMutation.mutateAsync()` 无 catch，失败时 unhandled rejection，用户得不到"刷新失败"提示。

**P2-8 清除筛选残留状态**（`:1200-1230`）：未清除 `sort`、`focusMetric`、`periodPreset`/期间；若用户已切排序或已聚焦指标，「清除筛选」后界面状态与 URL 观感不一致（排序下拉仍显示原选项）。

**P2-9 标签按钮 aria-label 含内部版本号**（`:507`）：`aria-label="${t.label}：查看规则 ${t.ruleVersion}"` 把规则版本号暴露给读屏；版本号应放进弹窗而非可访问名称。

**P2-10 指标 `visible` 字段未被消费**（`types.ts:81`、页面 `:1365-1415`）：服务端若返回 `visible: false` 的指标，页面仍全部渲染，契约字段失效；应按 `visible` 过滤或从契约中移除。

## 六、改进建议

**P0/P1 优先（数据正确性）：**
1. **修分页截断**（P0-1）：将 `pageIndex/pageSize` 纳入查询参数做服务端分页，`rowCount` 用服务端 `filteredTotal`；若坚持一次拉取，则客户端不应再有第二层分页。
2. **统一排序**（P1-1）：取消表头局部排序，或让表头点击写入 `sort` URL 参数走全局排序（可保留少量高频列排序）；两处状态必须同源。
3. **筛选变更统一重置分页**（P1-2）：把"变更筛选 → `setPagination({pageIndex:0})`"收敛为 `patchUrl` 的统一副作用，避免漏项。
4. **清理术语违规**（P1-4/5/6）：W13 → `openWorkspaceLabel("W13")`；`CostCoverageNotice` 的 `costBasisStatus` 标签去英文原值（改共享组件时保留默认值、加 prop，遵循 `AGENTS.md` §5）；导出卡隐藏 jobId 与权限版本，`amountBasisNote` 去 GROSS/NET。
5. **scope 补控件或摘参数**（P1-3）：如产品上有范围切换机制，接入之；否则从查询中移除 `scope` 参数并固定服务端默认范围。

**P2 打磨：**
- 指标卡点击补联动（滚动/聚焦表格对应列，或改为真实筛选并修改文案）。
- 表格「异常」列加图例/tooltip；`from>to` 校验；柱形加键盘操作；导出禁用加原因；刷新失败加 toast；标签 aria-label 去掉版本号；消费 `visible` 字段。
- 降低首屏 Alert 噪声：可将 stale/rebuilding 合并为单一状态条 + 详情，保留 destructive 级别的独立展示。
