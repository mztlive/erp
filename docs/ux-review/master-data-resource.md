## 一、页面概述

`/master-data/[resource]` 是「基础资料」模块的分类主页面，`resource` 参数决定品类（公司商品池 / 商品与 SKU / 商品分类 / 品牌 / 卡券类目 / 供应商与资质 / 仓库），顶部以 tab 式导航在 7 个分类间切换。

- `resource === "categories"` 渲染**分类树页**（左树右详情，`category-tree-page.tsx`）；
- 其余资源渲染**列表工作区**（`MasterDataListWorkspace`，指标条 + 筛选 + 数据表格 + 预览 sheet / 详情页）；
- 商品（products）、供应商（suppliers）点行直达详情页（详情即编辑，`/master-data/{resource}/{stableId}?section=overview`，新建走 `/new`）；品牌（brands）点行直接打开「更新资料」弹窗；其余资源点行打开侧栏预览 sheet（`QuickPreviewSheet`）。

主要任务：在分类间浏览、搜索/筛选、查看资料、新建、更新资料（版本）、停用、导出。

整体评价：**结构清晰、文案整体业务化**（术语表执行良好，未发现「正式/租约/投影/幂等」等禁用词），列表页可访问性细节（`/` 快捷键、结果标题聚焦、焦点回移）明显优于同类页面；但**品牌资源的查看/编辑语义混用、分类树空态误导、错误态零文案**三处是本次评审最主要的效率与信任问题。

## 二、易用性

1. **分类切换路径顺畅，但反馈偏弱**：`ResourceNav` 在列表页与分类树页均有（master-data-page.tsx:74-98 / category-tree-page.tsx:60-84），切换后聚焦 sr-only 结果标题做 a11y 播报（master-data-page.tsx:123-130），细节到位。但**切换后旧筛选条件静默保留**（见问题 P1-4），用户在新分类看到空列表时无法判断是「没数据」还是「筛选残留」。
2. **查看路径按资源分裂成三种行为，一致性差**：
   - 大部分资源：点行 → 预览 sheet，双击/回车 → 详情页；
   - 商品/供应商：点行 → 详情页；
   - 品牌：点行 → 「更新资料」编辑弹窗，且行内「查看」按钮被隐藏（master-data-page.tsx:393-412）。同一列表页内三种行交互语义，用户需要试错学习（见 P1-2）。
3. **新建路径**：列表页页头「新建」（商品/供应商跳 `/new` 详情表单页，其余弹窗，master-data-page.tsx:527-534）；分类树页页头「新建根分类」+ 详情面板「新建子分类」（category-tree-page.tsx:301-308, 481-485）。子分类通过 `defaultParentId` 预填（category-tree-page.tsx:551-570），路径合理。
4. **分类树浏览**：默认只展开根节点（category-tree-page.tsx:219-222），「全部展开/全部收起」可用（348-355）；搜索/筛选结果因 `buildCategoryForest` 会把无父匹配的节点重新提升为根（category-tree-model.ts:30-38），**命中的节点总能看见**，这点处理得好。但计数与可见性不一致、选中项随筛选丢失（见 P2-4）。
5. **resource 参数反馈**：面包屑（master-data-page.tsx:487-498）、页标题、指标条 aria-label 均反映当前分类；未知参数有独立兜底页（master-data-page.tsx:132-142），但文案回显内部 key（见 P2-6）。

## 三、信息密度

1. **列表页密度适中偏紧**：9 列中「资料编号」左钉、「操作」右钉（master-data-page.tsx:692-695），density="compact"；名称列带关键事实副行（295-301），单行信息量合理。**「不可用原因」列绝大多数行为「—」**（368-375），占用一列宽度却极少有值（种子数据 7 资源 28 行仅数行有 blocker），可考虑并入启用状态列或改为悬停提示（见 P2-9）。
2. **指标条与筛选控件功能重叠**：指标条（「全部/当前启用/当前停用/待生效更新」，data.ts:2769-2795）与工具栏「启用状态」ToggleGroup 均过滤启用状态，同一事实两个控件（filter.ts:19-24 与 32-37 逻辑重复）；且指标值基于未筛选全量行计算，搜索后「全部 3」与表格实际行数矛盾（见 P2-7）。
3. **分类树页密度合适**：左树行 = 展开钮 + 图标 + 名称 + 代码 + 状态徽章（category-tree-page.tsx:107-170），代码右对齐、名称截断；右侧详情面板字段精简（路径/编号/版本/代码/上级/适用类型）。深度缩进 `0.375 + depth × 1.1rem`（119），三级以内可读。
4. **筛选到位**：搜索（编号/名称/keyFacts 全量匹配，filter.ts:44-55）、启用状态、版本状态、指标四类筛选齐全，`/` 快捷键聚焦搜索框（master-data-page.tsx:108-121）；但**分类树页没有 `/` 快捷键、没有导出**，与列表页能力不一致（见 P2-8）。

## 四、交互合理性

1. **加载态**：列表页与树页均为骨架块（master-data-page.tsx:459-467 / category-tree-page.tsx:259-267），无闪烁，合格。
2. **错误态**：两页失败时**仅渲染「重试」按钮，无任何失败原因或下一步说明**（master-data-page.tsx:469-479 / category-tree-page.tsx:269-279）。对比详情页有 `BusinessFailureState` + 文案（master-data-center-page.tsx:130-145），列表页明显降级（见 P1-1）。
3. **空态**：列表页走 DataTable 默认空态「当前筛选没有结果」（data-table.tsx:864-868），语义正确；**分类树页零匹配时却显示「暂无分类，请先新建根分类」并附新建 CTA**（category-tree-page.tsx:372-381），把「搜索无结果」误当「系统无数据」，引导用户做错误动作（见 P1-3）。
4. **树展开折叠**：展开钮 stopPropagation（category-tree-page.tsx:141-144）不与选中冲突；Enter/Space/←/→ 键盘操作可用，但**无上下键移动焦点、每个节点均可 tab 聚焦（非 roving tabindex）**，且 treeitem 内嵌可交互 button 不符合 ARIA 树规范（见 P2-3）。
5. **多选/批量**：本页无批量操作需求（主数据逐条维护合理），未做多选不扣分。
6. **按钮语义与误操作防护**：
   - 停用有原因+时间必填（master-data-action-dialog.tsx:484-487, 1125-1138），且文案明确「不是删除」（copy.ts:98-101），防护到位；
   - 禁用按钮带原因 tooltip（列表页 master-data-page.tsx:417-419, 438-439），**但分类树页同类按钮无 tooltip**（category-tree-page.tsx:478-507），同一操作两页提示不一致（见 P2-2）；
   - 仓库页「新建（暂不可用）」按钮**未禁用**，点击进入弹窗后才由 Alert 说明（master-data-page.tsx:521-526 → master-data-action-dialog.tsx:594-599）——比「摆一排禁用按钮」好，但按钮文案与"可点击"行为仍略有矛盾；
   - **品牌行点击直达编辑弹窗是最大的误操作面**：查看意图触发写界面（见 P1-2）。
7. **操作结果反馈**：新建/更新/停用弹窗内嵌 `FormalActionResult` 成功/阻断/冲突三态 + 事实表（master-data-action-dialog.tsx:601-622, 852-887, 1091-1115），冲突态给出「当前版本 vX」（885）与刷新指引（copy.ts:93-94），是页面里最完整的结果反馈链。
8. **预览 sheet**：关闭后焦点回移列表行（master-data-page.tsx:725-734），footer 操作与行内操作一致，合格。

## 五、问题清单

### P0（阻断操作）— 无

### P1（明显阻碍效率）

1. **错误态零文案：失败原因不可见**（master-data-page.tsx:469-479；category-tree-page.tsx:269-278）
   列表页与分类树页加载失败时只渲染一个「重试」按钮，无失败原因、无「数据可能不是最新，请刷新」类说明，也没有可点击的跳转。用户无从判断是网络问题、权限问题还是系统异常，反复盲点重试。同模块详情页有 `BusinessFailureState`+文案（master-data-center-page.tsx:134-142），应复用统一。

2. **品牌（brands）查看路径缺失，行点击误入编辑弹窗**（master-data-page.tsx:393-412, 702-717）
   品牌行内「查看」按钮被隐藏，行点击/回车直接 `setReviseTarget(row)` 打开「更新资料」编辑弹窗。用户只想查看品牌代码/Logo 时被迫进入写界面，且与其它资源「点行=预览/详情」的交互惯性冲突；虽然变更原因必填（resource-fields.ts:443）降低了误保存风险，但查看语义被写语义绑架，是全页最不一致的交互。

3. **分类树空结果误报「暂无分类，请先新建根分类」**（category-tree-page.tsx:372-381；copy.ts:165）
   搜索或启用状态筛选过滤后 `forest.length === 0` 时，空态与「系统从未建过分类」的首次空态共用同一文案和「新建根分类」CTA。用户搜索无匹配会被引导去创建分类——动作方向错误；应区分「无匹配结果」与「无分类」。

4. **切换资源后筛选条件静默残留，新分类首屏可能为空且无提示**（master-data-page.tsx:184-207, 209-215）
   同一路由段内切换 `resource` 参数时组件实例复用（无 key 重置），`search`/`lifecycleStatus`/`revisionTiming`/`metricKey` 状态全部保留并施加到新分类的查询上。例如在「公司商品池」搜「坚果」后切到「供应商」，新列表直接为空且没有任何「已应用筛选」横幅提示（搜索词虽可见但易被忽略，指标筛选更难察觉），用户容易误判新分类没有数据。

### P2（体验瑕疵）

1. **分类树无法进入详情中心页**（category-tree-page.tsx:399-519）
   树右侧详情面板只有概览字段与三个操作按钮，没有「打开完整资料」入口（列表页有，master-data-page.tsx:803-812）；分类的「变更历史 / 引用与选用 / 操作记录」四个中心页签（master-data-center-page.tsx:35-43）对分类用户完全不可达。

2. **分类树页禁用按钮无原因 tooltip**（category-tree-page.tsx:478-507）
   「新建子分类/更新资料/停用」禁用时无 title 说明；列表页同类按钮带 blocker 原因（master-data-page.tsx:417-419, 438-439）。同一操作两页行为不一致，停用被禁的用户在树页得不到原因。

3. **分类树键盘可达性不符合 ARIA 树规范**（category-tree-page.tsx:113-134, 136-151）
   每个 treeitem 均为 `tabIndex={0}`（非 roving tabindex），无 ArrowUp/ArrowDown 在节点间移动焦点；treeitem 内嵌可交互 button（展开钮）嵌套交互元素。键盘用户遍历大树低效。

4. **树「n 项」计数与可见节点不一致；筛选后选中项静默丢失**（category-tree-page.tsx:224-227, 367-369）
   计数基于筛选后全部行（含收起父节点下的后代），用户收起父级后「6 项」与可见数不符；同时 `selectedId` 指向的行被搜索/筛选排除后，详情面板直接退回「在左侧选择一个分类」空提示，选中状态无保留。

5. **「回车打开详情」文案与品牌行为不符**（copy.ts:33；master-data-page.tsx:708-717）
   列表描述写「回车打开详情」，但品牌资源回车实际打开的是「更新资料」弹窗（写界面），与文案语义（查看）冲突，违反「按钮文案必须与实际行为一致」契约。

6. **未知资源页回显内部 key**（master-data-page.tsx:136-138）
   `没有「${resource}」这一类基础资料` 直接回显 URL 中的英文段（如 `/master-data/xyz` 显示「没有『xyz』」），界面出现内部参数原文，术语表口径应换成「该分类不存在或链接已失效」类业务表达。

7. **指标条计数与当前筛选不同步，且与启用状态筛选功能重叠**（master-data-page.tsx:573-592；data.ts:2769-2795；filter.ts:19-24, 32-37）
   `computeMetrics` 基于未筛选全量行计算，搜索/启用状态筛选后「全部 3」等数值与表格实际行数矛盾（例如搜出 1 行仍显示「全部 3」）；同时「当前启用/当前停用」指标与工具栏 ToggleGroup 过滤同一状态，两个控件做同一件事且口径独立，容易让用户困惑哪个生效。

8. **分类树页能力弱于列表页：无 `/` 搜索快捷键、无导出入口**（category-tree-page.tsx 全文）
   列表页有 `/` 聚焦搜索（master-data-page.tsx:108-121）与「导出」按钮（516-518），分类树页两者皆无；分类字典同样有导出价值，跨资源能力不一致。

9. **「不可用原因」列信息过疏**（master-data-page.tsx:364-376）
   大部分行显示「—」，一整列多为空占位；可并入启用状态列显示或仅在有值时渲染（如悬停提示），释放列宽给关键信息。

10. **小问题集合**：
    - tablist 语义误用：`role="tablist"` 内是 `<Link>` 导航且无 tabpanel/aria-controls（master-data-page.tsx:75-98；category-tree-page.tsx:60-84）；
    - 弹窗/预览打开时按 `/` 仍会聚焦背景搜索框（master-data-page.tsx:108-121，未检查对话框焦点）；
    - 创建/更新/停用弹窗生效日期硬编码（master-data-action-dialog.tsx:539 「2026-08-01」、779 「2026-08-15」、1033 「2026-08-01」），随时间漂移后创建默认生效日在过去，应动态取业务日（同文件已有 `defaultImmediateEffectiveFrom`，resource-fields.ts:449-451 可复用）；
    - 导出 CSV 头部元数据泄漏枚举原值：`筛选条件=…启用状态=enabled…指标=pending`（master-data-page.tsx:240-249 → queries.ts:135-141），导出文件用户可见，应使用中文枚举映射。

## 六、改进建议

**P1 优先：**

1. **统一错误态**：列表页与分类树页复用 `BusinessFailureState`（参照 master-data-center-page.tsx:134-142），至少给出「加载失败，请重试」文案；区分数据错误与权限不足。
2. **品牌查看路径**：给品牌恢复只读查看能力（预览 sheet 或只读弹窗），行点击语义与其它资源对齐为「查看」，「更新资料」只保留在明确按钮上；若坚持「列表+对话框维护」，则行点击改为打开只读摘要，另置「更新资料」按钮。
3. **分类树空态分流**：区分「无分类」（引导新建根分类）与「筛选/搜索无匹配」（提示调整关键词、提供清除筛选入口），文案建议「没有匹配的分类」+「清空筛选」。
4. **资源切换重置或明示筛选**：切到新分类时重置 `search` 与 `metricKey`（保留启停/版本状态尚可接受），或在页头渲染「已应用筛选：搜索=坚果 · 指标=待生效更新 [清除]」快照条，防止空列表误判。
5. **指标条与筛选合并口径**：删除「当前启用/当前停用」指标与 ToggleGroup 的重复（保留其一），指标数值改为基于当前搜索+启停筛选后的行数计算，保持计数与表格一致。

**P2 跟进：**

6. 分类树详情面板补「打开完整资料」入口（`/master-data/categories/{id}?section=overview`）。
7. 分类树禁用按钮补 blocker tooltip；统一两页按钮提示行为。
8. 分类树实现 roving tabindex + 上下键导航；treeitem 内嵌按钮改为 treeitem 外层的独立行元素。
9. 树页补 `/` 快捷键与导出（与列表页能力对齐）；展开/收起计数改为「可见 n 项 / 共 m 项」。
10. 未知资源文案去掉内部 key 回显；CSV 元数据用中文枚举映射；弹窗默认日期改动态业务日；「回车打开详情」按资源生成实际动作文案。
11. 列表「不可用原因」列收敛为条件渲染（有值才显示）。

**正面保留项（评审确认无需改动）：** 停用/新建/更新的三态结果反馈链、预览 sheet 焦点回移、`/` 快捷键、分类树搜索结果的「重新提根」可见性处理、供应商敏感字段列表打码、仓库只读门禁的表达方式。
