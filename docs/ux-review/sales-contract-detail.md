# UX 评审：/sales/contracts/[contractId]（销售合同详情）

> 评审视角：产品经理 / UX
> 评审对象：`features/contracts/contract-detail-page.tsx`、`contract-preview-panel.tsx`、`contract-paper-dialog.tsx`、`contract-upload-dialog.tsx` 及所引用的 `components/business`（document/attachments/page/paper-document）、`mock/contracts.ts`、`mock/session-state.ts`、路由 `app/(workspace)/sales/contracts/[contractId]/page.tsx`

## 一、页面概述

销售合同详情页是合同中心的 M4 对象壳层（面包屑 + 轻动作 + `DocumentHeader` 对象身份区），以 5 个分区承载：**概览**（身份/客户/状态/版本/有效期 + 关联销售摘要）、**结算与开票**（结算主体/付款/开票快照）、**附件**（合同 PDF 电子档）、**关联销售单**（追溯版本 + 三轨进度 + 金额）、**版本与审计**（版本时间线 + 审计时间线）。

整体实现质量较高：对象壳层结构干净、状态徽章/版本徽章齐全、结算与开票快照字段完整、隔离附件有明确错误态（"已隔离，不可下载"）、上传弹窗有脏数据离开拦截 + beforeunload 防护、tab 与 `?section=` URL 参数一一对应、文案整体符合术语表（"税号（打码）"、禁词基本清零）。

主要问题集中在三处：**详情页无任何状态流转能力**（可终止的合同无终止入口、无法新增修订版本）、**错误/失败态与"不存在"混为一谈**、**原始枚举/ISO 时间戳/内部措辞上屏**。

## 二、易用性

**查看合同详情**：路径顺畅。列表行单击/回车 → 半屏预览（`ContractPreviewPanel`，左右分栏：签订有效期/客户负责人/附件摘要 | 结算开票/关联销售单）→「查看详情」进入本页；预览面板自带"30 日内将到期"警告与附件安全检查状态（contract-preview-panel.tsx:64-67、112-127），比详情页还多一个风险信号（见 P2-4）。5 个分区 tab 导航清晰，URL 参数可分享深链。

**上传纸质合同**：仅存在于列表页（`ContractUploadDialog`）。必填项 8 个，PDF 单文件 + 编号/客户/结算主体/付款条件/三日期；重复编号、有效期倒挂、非 PDF、超 20MB 均有明确错误文案；提交按钮"上传并归档/上传中…"是动作词；成功后有结果卡（列表页 handleUploadSuccess，含合同号/修订/下一步）。扣分：默认日期硬编码（P2-11）、"归档到原合同"指引指向不存在的能力（P2-12）。**详情页自身没有上传/补录入口**。

**预览**：两个按钮（页头"打印预览" + 对象头"纸质预览"）打开同一 `ContractPaperDialog`，宽幅弹窗内渲染 `PaperDocument` 打印版式（甲方/乙方/条款/金额说明/签章位），内容以系统记录为准，文案合规（"以系统记录为准"）。扣分：双入口同动作不同文案（P2-1）；打印走 `window.print()` 存在整页打印风险（P2-16）。

**操作状态流转**：**不完整**。页面只支持「新建销售单」这一流转动作（且由服务端 `allowedActions` 控制，不可用时有阻断说明）；`TERMINATE` 出现在 4 个合同的 `allowedActions` 中，但详情页与列表页均无任何"终止合同"入口（P1-4）。新增版本/修订（上传新 PDF 归档到已有合同）也没有入口。对一份合同的管理闭环（查看 → 终止/修订）缺了后半段。

## 三、信息密度

- **关键信息突出**：状态徽章、版本徽章紧跟标题；`DocumentHeader` + 页内正文分区合理，客户/结算主体/签订日/有效期/版本/负责人一个不落。
- **过疏**：
  - 概览页没有金额信息——但这是业务模型（合同级金额不存在）决定的，且用"金额仅为各销售单摘要，不汇总为合同金额"等旁白交代口径，属透明设计，可接受。
  - **30 日内到期风险信号在详情页缺失**（P2-4）：列表与预览面板都有的"将到期/30 日内将到期"，详情页只剩一行灰字有效期。
- **过密/冗余**：
  - "不含合同级金额"类口径旁白在概览、关联摘要、销售单分区、打印件、预览面板出现 5 次以上，对"用户为什么看不到合同总金额"的交代过重，可收敛到 1 处 + 悬停提示。
  - blocker 长句在禁用按钮文案和按钮下方小字重复两次（P2-2）。
  - 页头"打印预览"与对象头"纸质预览"两个同类按钮并存（P2-1）。
- **对象身份弱**（P2-9）：h1 是客户名，合同编号只出现在灰字"单号"行；用户从列表带走的记忆是"HT-2026-0312"，页面上它却不是主角。
- **版本/有效期格式不统一**（P2-6、P2-7）：同页出现"版本 3"（document.tsx:139）、"v3"（detail-page.tsx:314）、"修订 v3"（paper-dialog.tsx:207）；有效期一会"至"一会"~"。

## 四、交互合理性

**加载态**：`isPending` 仅一个页头占位（contract-detail-page.tsx:74-80），无骨架屏，数据到达时整页跳动（P2-18）。

**空/错态**：
- 查询失败与"合同不存在"被合并处理（P1-1）：`query.isError` 无分支，网络/接口错误会渲染"未找到编号为 X 的合同"，文案错误、无重试，只有"返回列表"。
- 空态处理良好：无关联销售单"暂无关联销售单。"、无修订"尚无已确认修订。"、附件空"尚未上传附件"，均有明确业务表述。

**对话框**：
- `ContractPaperDialog`：宽幅 + 滚动 + 底部"关闭/打印"，语义清晰；打印走 `window.print()`（P2-16）。
- `ContractUploadDialog`：脏数据关闭有 `DiscardConfirmDialog` 二次确认 + beforeunload，误操作防护到位；`DialogClose` 走 Base UI 的 `onOpenChange`，拦截逻辑可生效。扣分：默认日期硬编码（P2-11）、错误指引指向不存在的能力（P2-12）。

**按钮语义**：新建销售单/上传并归档/打印预览/查看关联销售单均为动作词，与术语表一致；禁用态用"已终止合同不可用于新建销售单；历史记录仍可读。"这类完整句作按钮文案，视觉上像一条长标签，且与下方重复（P2-2）。

**URL 与路由**：`?section=` 与 tab 一一对应、可深链，符合"URL 参数与控件一一对应"；但 tab 切换整页重挂载（路由 `key` 含 section，page.tsx:26），滚动位置、焦点、已打开弹窗全部重置（P2-5）。"新建销售单"链接把 `contractId`/`contractRevisionId`（如 `ctr_0312_v3`）放进 URL，内部 ID 进 URL 但不上屏（P2-17）。

**数据呈现**：
- 审计时间线直接把 `event.action` 枚举原值上屏（P1-2）。
- 关联统计时间以 ISO 8601 原值上屏（P1-3）。
- 附件"查看"（EyeIcon）实际是下载一个**空白占位 PDF**（P1-5），演示代码里标注了生产环境应换签名 URL，但当前行为与"查看"语义不符且无在线预览。
- 版本时间线 diff 展示（"付款条件：月结 15 天 → 月结 30 天"）业务化清晰，是本页亮点。

## 六、改进建议

1. **补齐错误分支（P1-1）**：`isError` 单独渲染错误卡（"加载失败，请重试"）+ 重试按钮（query.refetch），"不存在"仅在 404 语义下出现。
2. **建立状态流转闭环（P1-4）**：详情页提供"终止合同"入口（按 `allowedActions`/blocker 控制，参照"新建销售单"的禁用 + 原因模式），终止前确认对话框 + 阻断原因提示；如 TERMINATE 属预留能力，应从 `allowedActions` 与类型中移除，避免"可做却无入口"。
3. **数据上屏审计（P1-2/P1-3）**：`auditTimeline.action` 增加中文映射（上传合同 PDF / 下载附件）；`relatedSalesOrdersAsOf`/`sourceAsOf` 统一格式化（"8 月 1 日 15:55"），或直接复用 `DataFreshness`。
4. **附件查看语义修正（P1-5）**：生产路径应接入真实签名 URL 下载 + PDF 在线预览（新窗口/内嵌 viewer）；演示期至少把 aria-label 改为"下载"并提示"演示文件"。
5. **详情页补风险信号（P2-4）**：`ContractCenterView` 增加 `expiringWithin30Days`，在页头有效期旁显示"30 日内将到期"警告徽章，与列表页一致。
6. **合并重复入口与文案（P2-1/P2-2）**：删一个"打印预览"，保留对象头"纸质预览"；禁用按钮用短标签（"新建销售单"），完整原因放 tooltip 或下方一次性说明。
7. **修正矛盾文案（P2-3）**："（下列为关联明细）"改为"（见关联销售单分区）"或直接省略。
8. **URL 参数收敛（P2-5/P2-17）**：tab 切换改为 `useSearchParams` 局部更新或保留 key 但用 `router.replace`，避免整页重挂载；深链参数改为服务端可解析的稳定引用而非 `ctr_*` 修订 ID。
9. **格式统一（P2-6/P2-7）**：全站版本统一"v3"、有效期统一"至"（与打印件一致）。
10. **上传弹窗默认值与指引（P2-11/P2-12）**：日期默认取当天；错误文案改为"如为新签署版本，请联系管理员归档"或提供真实的"归档到已有合同"能力。
11. **演示残留清理（P2-13/P2-14）**：公司名改为从配置/结算主体读取；"PDF 电子档归档"徽章改为有附件且全部通过检查才显示。
