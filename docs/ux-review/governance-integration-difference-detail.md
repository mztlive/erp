# UX 评审报告：集成差异详情页（/governance/integration-errors/differences/[differenceId]）

> 评审日期：2026-08-05
> 评审对象：`erp-client/features/integration-errors/integration-error-detail-page.tsx`（IntegrationDifferenceDetailPage 分支）、`integration-errors-page.tsx`（详情页实际渲染主体）、`api.ts` / `queries.ts` / `url-state.ts` / `types.ts`、共享组件 `BusinessDiffPanel`（audit-import.tsx）、`InterfaceErrorResolutionPanel`（domain.tsx）、`SequentialProcessBar`（workflow.tsx）、`FormalActionResult`（feedback.tsx）
> 术语基线：`docs/ui-glossary.md` v1.2
> 结论：P0=0 / P1=9 / P2=11，共 20 项

---

## 1. 页面概述

详情页与列表页复用同一个组件 `IntegrationErrorsPage`：`IntegrationDifferenceDetailPage` 只做了一次包装，将 `differenceId` 作为 `forcedDifferenceId` 传入（integration-error-detail-page.tsx:15-21）。focusMode 下：

- 左侧队列隐藏（integration-errors-page.tsx:1140），右侧渲染单个差异详情；
- 页面同时发起两个请求：隐藏的队列查询（`useIntegrationQueueQuery`）与详情查询（`useIntegrationItemQuery`）；
- 差异详情 = 事实区（滞留/责任/方向/原动作）+ 「对账左右证据」diff 面板 + 证据与尝试时间线 + 处理动作区（含直接对账的「确认无误/确认有效差异」终结路径）。

页面目标用户是财务/运营经办，主路径为：查看左右证据 → 选择注册原因 → 确认无误/确认有效差异（直接对账）或 补证→解决（有关联任务）。

## 2. 易用性

### 2.1 主路径：理解差异 → 决定动作

- **理解差异**：核心是「对账左右证据」面板，左右金额/行数并列（integration-errors-page.tsx:1384-1419），caption 给出差额摘要（如"差额 ¥510.00 · 缺 3 行供应商账单金额"）。信息本身可读，但见 4.1 的语义错位问题。
- **决定动作**：直接对账项（无 work_item）的终结动作区位于页面最底部（1734-1834），需要越过 6 个卡片才能到达；处理动作卡（1595）与「接口错误处理」面板（1560）重复承载同一批动作（详见 4.3）。
- **详情页无法推进队列**：focusMode 下 `items = [item]`（221-224），`neighbor()` 恒返回 null（435-442），导致顶部连续处理条中的「下一项」（1237-1240）、操作结果条中的「下一项」（1100-1111）、自动下一项（462-478）全部静默失效——按钮可见、可点，但点了毫无反应（详见 5.1-1）。

### 2.2 页面间跳转

- 「去修复」外链按错误类别给出（如 W17 商城同步 / W21 映射修复，1421-1437），方向正确；
- 但指标条（881-920）在 focusMode 下仍渲染可点击项，点击只改写 URL 查询参数、页面内容不变（见 5.1-9）；
- 无效 differenceId 或详情查询失败时，页面给出"未选择处理项，从左侧队列选择任务或差异"（1846-1850）——但本页根本没有左栏队列（见 5.1-3）。

### 2.3 错误与反馈

- 详情页整体加载/错误/刷新全部绑定隐藏的队列查询（562-584、557-560、1070-1073），队列失败则详情不可用，且「刷新当前任务」实际不刷新当前项（见 5.1-2）；
- 自动领取在打开页面时静默进行，失败被 catch 吞掉无任何提示（380-405，见 5.2-5）。

## 3. 信息密度

### 3.1 过密

详情页纵向堆叠 6 个卡片：连续处理条 + 双"跳过"按钮行 + 业务信息卡（事实 9 项 + diff 面板 + 修复链接）+ 证据与尝试卡（尝试历史 + 2 条时间线 + 已关联证据 + 证据策略 Alert）+ 接口错误处理面板 + 处理动作卡（阻断原因 + 说明 + 全部动作 + 直接对账区 + 可操作范围摘要）。对一次"看差异→下结论"的任务而言，动作区被推到两屏之外，且「当前可操作范围」（1836-1841）与按钮区重复罗列同一批动作。建议将动作卡前移或让 diff 面板粘性跟随。

### 3.2 过疏 / 冗余

- diff 面板中「边界」「更新时间」两行变更前=变更后（1396-1408），在"变更前/变更后"表格语义下呈现为两条"未变更"伪差异行，且头部计数徽章按 4 项计（audit-import.tsx:219），误导用户以为有 4 处字段差异（见 4.1）；
- 「请求编号」事实值为硬编码"已保留"（1366），无实际信息量；
- 「第 1 / 1 条」位置徽章在详情页无意义（1210-1212）。

## 4. 交互合理性

### 4.1 差异对比视图（BusinessDiffPanel）

- **表头语义错位**：复用"字段/变更前/变更后/变更说明"四列 diff 表格承载"左右证据"对比（audit-import.tsx:224-228），`before=leftSummary`、`after=rightSummary`（1389-1395）。对账场景语义是"两侧对照"而非"变更前后"，用户第一眼会误读方向；
- **伪差异行**：边界、更新时间两行 before/after 相同（1396-1408），无法传达"这些是共同属性而非差异"；
- **原始枚举泄漏**：`differenceType` 原值（如 `AMOUNT_AND_LINE_COUNT`、`MISSING_ERP_FACT`）直接渲染在"变更说明"列（1408），违反术语表"枚举原值不得漏到界面"（见 5.1-5）。

### 4.2 处理操作反馈与误操作防护

- 无任何确认对话框：直接对账的「确认无误/确认有效差异」为终结动作（不可撤销、追加不可覆盖），点击即执行（1760-1788），缺乏误触防护；
- 终结按钮与所选原因无前置匹配校验：默认选中原因 1（时差确认无误，api.ts:654），用户改选"确认有效差异·待纠错"后点「确认无误」，按钮仍可点，提交后才弹"请选择与结论匹配的注册原因"（819-821），反馈滞后；
- 处理说明 textarea 跨项残留（370-377 只重置 actionError 和 reconReasonId，不重置 comment），上一项写的原因可能被误提交到下一项；
- 「模拟仍未知」复选框跨项残留（1082-1090），在项 A 勾选后切到项 B 发起「查询原结果」，B 会被强制模拟为仍未知（501）。

### 4.3 按钮语义

- 「处理当前」按钮在详情页只做 `headingRef.current?.focus()`（1234-1236），语义完全错位；
- 「跳过」与「先跳过（保留队列）」（1250-1270）：DEFER 实际置"已跳过"并清租约、SKIP 保持队列内——两个动作成功提示几乎相同（api.ts:765-781），用户无法区分；
- 「重新提交（保持原请求编号）」（599-608）与「重新提交」（1637-1646）同一动作两个入口、文案不一致；
- 「返回后刷新当前任务」（1441-1445）文案暗示"返回后自动刷新"，实际是当场 refetch 隐藏队列；
- 「刷新当前任务」（1070-1073）不刷新当前项（见 5.1-2）；
- 详情页打开即自动领取任务（380-405），无告知、失败静默，用户看到"未领取"时不知道为何。

### 4.4 加载/空/错误状态

- 加载骨架为"队列+详情"两栏布局（562-573），与详情页单栏终态不符；
- detailItemQuery 加载中（详情数据未到而队列已到）会闪现"未选择处理项"空态（1845-1851）；
- 无效 ID 无 404、无"未找到"错误，指向不存在的左栏队列（见 5.1-3）。

## 5. 问题清单

### P0（阻断操作）：0 项

正常路径（查看差异→确认/补证→返回）未被完全阻断，未发现 P0。

### P1（明显阻碍效率）：9 项

1. **详情页连续处理机制整体失效**：focusMode 下 `items=[item]`（integration-errors-page.tsx:221-224），`neighbor()` 恒 null（435-442），顶部「下一项」（1237-1240）、结果条「下一项」（1100-1111）、自动下一项（462-478）全部可点但无反应；「处理当前」（1234-1236）只聚焦标题。处理完一条差异后无法继续队列，只能手动返回——批量处理效率完全被断送。
2. **详情页被隐藏的队列查询绑架**：加载门（562-573）、错误门（575-584）都只看 `queueQuery`；「刷新当前任务」（557-560、1070-1073）refetch 的是隐藏队列而非 `detailItemQuery`，用户以为刷新了当前差异，实际可能基于陈旧数据继续操作。
3. **无效/未知 differenceId 与详情查询失败无兜底**：`detailItemQuery` 无 enabled 之外的处理，item undefined 时渲染"未选择处理项，从左侧队列选择任务或差异"（1845-1850），而本页无左栏队列；无 404、无"未找到该差异"提示、无详情重试。
4. **关闭重复的「替代任务」暴露内部 ID 且默认值错误**：输入框预填 `wi_iet_orig_55102`（238、1711-1730），是外部错误任务的内部 ID（违反术语表 §7"wi_* 一律不得进界面"），且为自由文本输入，无任务选择器，业务用户无法正确填写。
5. **枚举原值/内部 ID 泄漏上屏（多处以违反术语表 §5 扫描验收）**：
   - 筛选摘要渲染原始枚举 `视图=mine / 模式=all / 类别=result-unknown`（1077-1080，来源 api.ts:412-418）；
   - diff 面板"变更说明"渲染 `differenceType` 原值（1408）；
   - 证据策略 Alert 渲染 `pol_recon_potential@v1`（1539）与岗位分离枚举原值 `NONE`（1546）；
   - 队列项原因位渲染 `classification.code` 原值（1176，详情页在队列模式同样可见）。
6. **演示/模拟开关直接暴露在业务页**：「下次『查询原结果』模拟仍未知（结果仍未知 · 不自动下一项）」（1082-1090）——"模拟"字样的 mock 调试控件（501 消费）进入生产界面，且跨项残留（见 4.2），影响下一次真实查询行为。
7. **差异对比面板语义错位**：表头"变更前/变更后"实为左右证据对照（1384-1395 + audit-import.tsx:224-228）；「边界」「更新时间」两行 before==after 构成伪差异（1396-1408）；头部"4 项"计数含 2 条非差异行（audit-import.tsx:219），误导理解。
8. **处理说明跨项残留**：comment 不随 item 切换重置（370-377 仅重置 actionError/reconReasonId），上一项说明存在被误提交到下一项动作的风险（误操作防护缺口）。
9. **详情页存在无控件对应的 URL 隐形状态**：focusMode 下指标条点击（881-920）改写 view/errorClass 但页面内容不变；autoNext 开关被隐藏（1060-1075 替换为返回/刷新按钮）但 `urlState.autoNext` 仍驱动自动跳转（249、462-478）——违反"URL 参数与界面控件一一对应"契约。

### P2（体验瑕疵）：11 项

1. **实现词/内部词进入文案**：证据卡"（追加式）""只追加，不提供覆盖控件"（1454-1457）、"非终结"（1821）、"终结只能…"（1741）、"不会伪造任务完成状态"（1741）、"等待退避（禁止高频重试）"（697）、"载荷摘要"（1378）、"已关联强类型证据"（1521）、"请求编号：已保留"（1366）、直接对账结果 facts"任务已关闭：否（直接对账）"（api.ts:1114）。
2. **「跳过」与「先跳过（保留队列）」双按钮**语义重叠、成功提示几乎相同（1250-1270 + api.ts:765-782），且 DEFER 的结果标题也叫"已跳过"。
3. **动作双入口且文案不一致**：「接口错误处理」面板（1560-1592，重新提交（保持原请求编号）/ 查询原结果 / 转交 / 关联补偿 / 关闭重复）与「处理动作」卡（1627-1732）重复，用户不知道该点哪个，且同一动作两种措辞。
4. **终结动作无确认对话框**：确认无误/确认有效差异为不可撤销追加（1760-1788），一键即执行，无二次确认或危险分级。
5. **终结按钮与注册原因无前置匹配校验**：选错结论的原因后按钮仍可点，提交才报错（819-821）。
6. **详情页自动领取无告知、失败静默**（380-405）：打开即 claim，失败 catch 吞掉，用户只见"未领取"却不知原因。
7. **加载骨架两栏布局与详情页终态不符**（562-573）；detailItemQuery 加载中闪现"未选择处理项"（1845-1851）。
8. **「第 1 / 1 条」位置徽章无意义**（1210-1212），且与失效的「下一项」共同暗示不存在的队列位置。
9. **「返回后刷新当前任务」按钮名不符实**（1441-1445）：不导航、只 refetch 隐藏队列。
10. **已关联证据的 recordId 直接上屏**（1526，如 `ver_mof_55102`），属内部 ID 泄漏（术语表 §7 同类）。
11. **「当前可操作范围」摘要与按钮区重复罗列**（1836-1841），且与指标条、筛选行合计 3 处状态摘要并存，信息冗余。

## 6. 改进建议

1. **修复详情页连续处理（P1-1，优先）**：focusMode 下「下一项/自动下一项」应基于队列查询结果（queueItems）而非 `[item]` 推进（或明确隐藏连续处理条）；「处理当前」改为执行当前项唯一终结动作或删除该按钮。
2. **解耦详情页与队列查询（P1-2/3）**：加载/错误/刷新均以 `detailItemQuery` 为准；「刷新当前任务」refetch item 键；无效 ID 渲染 404 态（"未找到该差异" + 返回队列），而非指向不存在的左栏。
3. **术语清零（P1-4/5/6、P2-1/10）**：替代任务改为从队列可选的任务选择器且不显示 `wi_*`；筛选摘要/`differenceType`/证据策略 ID/岗位分离/记录 ID 全部换中文映射；删除"模拟"控件或收进仅演示环境渲染的开关。
4. **重做差异对比面板（P1-7）**：为对账场景提供"左证据 / 右证据"双列对照组件（非"变更前/后"），共同属性行移出 diff 表格；计数只计真实差异字段。
5. **误操作防护（P1-8、P2-4/5）**：终结动作前加确认对话框；按所选原因结论联动禁用不匹配的终结按钮；item 切换时重置 comment 与 forceUnknown 残留。
6. **去重与文案对齐（P2-2/3/9）**：面板与动作卡合并为单一动作入口；「跳过」二选一并统一成功文案。
