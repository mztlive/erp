# UX 评审：/governance/history-backfill（历史消费回填）

> 评审对象：`erp-client/features/history-backfill/history-backfill-page.tsx`（2041 行）+ 同目录 `types.ts` / `queries.ts` / `url-state.ts` / `api.ts` + `components/business`（feedback / document / page / list / workflow / role-demo-bar / data-table）
> 评审口径：`docs/ui-glossary.md`（v1.2）与 `erp-client/AGENTS.md` §5（界面文案/URL 契约）
> 结论：整体结构成熟（列表/详情双视图、URL 状态驱动、动作确认层齐全），主要问题集中在「内部 ID/实现词泄漏」与「明细数据不可达（截断、隐形过滤）」

---

## 一、页面概述

治理域「历史消费回填」是 W30 的运营管理页，双视图：

- **列表视图**（`/governance/history-backfill`）：任务列表 + 指标条 + 五类筛选 + 创建任务入口
- **详情视图**（`/governance/history-backfill/:jobId`）：任务身份头 + 处理阶段指示 + 后台进度条 + 成本覆盖 + 7 个分区 Tab（概览/记录结果/去重/未归集/成本口径/失败诊断/审计报告）+ 开始回填/续跑/校验来源/下载报告四个动作

状态模型把「技术处理状态」与「报告确认状态」独立成轨（`types.ts:9-24`），页面上处理状态、报告确认、下游门禁三轨并行呈现，职责边界讲得清楚。

## 二、易用性

**优点**
- 主操作路径顺畅：创建 → 提交成功自动跳转详情（`history-backfill-page.tsx:794-797`）；开始回填/续跑都经过 `FormalActionConfirmDialog`，锁定字段、影响、不可撤回影响分层呈现（`workflow.tsx:283-307`），高风险动作防御到位。
- 面包屑三级可达、返回列表按钮语义明确（1095-1098）；详情轮询只对 RUNNING/VALIDATING 开启（`queries.ts:42-46`），且 8 秒轮询下表格用「正在刷新，当前内容会保留」非破坏性提示（`data-table.tsx:655-663`）。
- 错误态齐全：列表加载失败有重试（739-749）、详情无权限/不存在有返回（992-1006）、空筛选有业务化空态（1793-1801）。

**阻碍点**
1. **列表搜索词静默渗透详情页**：列表页输入「任务号/商城」搜索后打开任意任务，`q` 会沿 URL 带入详情并过滤明细（`url-state.ts:95`、`history-backfill-page.tsx:962-976` 的 `detailQuery` 消费 `q`），而详情页 `ItemFilters`（1473-1563）完全没有 q 控件，用户看不到任何提示、也清不掉。这是 AGENTS.md 明令禁止的「被 queryFn 消费却没有控件也无法清除的隐形状态」，且 `result/factType/costBasis` 过滤还会跨任务继承——在任务 A 选了「去重」，打开任务 B 明细同样只剩去重记录。
2. **非管理员角色被静默禁操作**：列表页「创建回填任务」按钮对所有角色可见（501-509），但 `CreateBackfillSheet` 对非 SYSTEM_ADMIN 直接禁用提交按钮且**不展示原因**（819、927-933），而接口侧明明有现成文案「当前演示角色不能执行回填/续跑（仅系统管理员）」（`api.ts:376`）却没有透出。详情页对非管理员干脆隐藏开始/续跑/校验按钮，只有进到最底部阻断 Alert 才看到 `ROLE_DENIED`。
3. **「结果未知」路径是死胡同**：`RESULT_UNKNOWN` 结果提示「请按 operationId 查询」（`api.ts:408`）、「使用相同 idempotencyKey 查询最终结果」（`api.ts:412`），但页面没有任何按该键查询的入口，指引无法执行。
4. 详情错误态（992-1006）只有「返回列表」没有「重试」，偶发失败需整页回退再进。

## 三、信息密度

**总体评价：列表页密度适中（10 列紧凑表 + 5 指标），详情页偏密、双份信息重复。**

- **重复呈现**：范围起点/截止时点在详情页出现 4 处——Header meta（1140-1143）、状态轨（1164-1170）、概览卡（1584-1589）、确认对话框锁定字段（1430-1433）；创建面板中「必需历史起点」与「回填起点（固定）」两行同值（840-849），占空间无增量信息。
- **永久 Alert 堆叠**：列表页常驻「范围与敏感边界」Alert（730-737，大段文字）；详情页运行中任务会同时叠「技术完成≠确认」Alert（1230-1244）+「覆盖不足」Alert（1246-1265）+ 结果横幅 + 下载提示，加上阶段指示/进度条/成本覆盖三块大组件，首屏过载。
- **状态突出度好**：处理状态、报告确认均用 `BusinessStatusBadge` 分色徽章，运行中（info）/失败（destructive）可扫读；列表「进度」列与「处理状态」列语义上有重叠但方向不同，可接受。
- **明细数据不可达**：详情明细 `pageSize:100` 硬编码（973），`ItemsTable` 无分页控件（1816-1824），而概览卡自己写着「统计…与明细列表可能因分页存在差异」（1603）、「当前页明细 X 条」（1630）——用户明确被告知数据被截断，却没有任何翻页入口，回填数百万级记录时明细几乎不可用。

## 四、交互合理性

| 维度 | 评估 |
| --- | --- |
| 加载态 | 列表表格骨架（`loading=isPending`）、详情整页 skeleton（982-990）均可；指标条加载中显示「—」可接受 |
| 空态 | 列表 0 行走 DataTable 内置空态；筛选 0 条走业务空态（1793-1801）带解释，好 |
| 刷新机制 | 详情有手动刷新（1099-1107）+ 运行中自动轮询；**列表无任何刷新入口**，运行中任务进度列会陈旧，仅靠 DataFreshness 徽标提示「数据可能过期」无按钮 |
| 创建表单 | 非表单式确认面板（只读 Fact 展示 + 阻断 Alert），对「起点固定不可改」的约束交代充分；但提交按钮禁用原因缺失（见易用性 #2）、BLOCKED 结果横幅渲染在 Sheet 背后（540 vs 821）用户可能看不到 |
| 进度反馈 | `BackgroundJobProgress` 三段卡片（成功/跳过/失败）+ 描述行，但「失败」卡片值 = failedCount + unattributedCount（1289），与描述行「待归集 X · 失败 Y」分列（1295-1297）数字口径不一致，用户会对不上 |
| 按钮语义 | 「创建任务草稿」「开始回填」「续跑原任务」「校验来源」都是动作词，好；「下载报告」实际只弹出提示（1216-1224、1410-1414）不真的下载——demo 局限但按钮名与行为不一致 |

## 五、问题清单

### P0（阻断操作）· 0 个

无。

### P1（明显阻碍效率）· 5 个

1. **详情明细被列表搜索词静默过滤，且无控件可清除** — `history-backfill-page.tsx:962-976`（`q` 进 detailQuery）、`:1473-1563`（ItemFilters 无 q 控件）、`url-state.ts:95`。列表 q 与 result/factType/costBasis 跨任务继承，明细数据在用户不知情下被裁剪。违反 AGENTS.md「URL 参数与界面控件一一对应」。
2. **内部 ID 与实现词泄漏到用户可见文案** — 结果横幅展示 `operationId`/`idempotencyKey` 原文（`history-backfill-page.tsx:191-192`）；接口提示原文「请按 operationId 查询」（`api.ts:408`）、「使用相同 idempotencyKey 查询最终结果」（`api.ts:412`）；概览卡「原任务标识」值直接展示幂等命名空间 `mall-backfill:HB-…`（`history-backfill-page.tsx:1335-1339`）、「切换编号」展示 `cutover_east_20260801` 类内部 ID（`:1582`）。违反术语表 §2/§4（幂等键→原任务号、内部 ID 不得进界面），且被指引的操作无对应界面入口。
3. **去重证明展示内部记录/消息 ID** — `history-backfill-page.tsx:1737-1740`：`formalFactId`（`mof_pay_88921`）与 `originalMessageId`（`inbox_msg_rt_88921`）原文上屏，`mof_*`/`inbox_msg_*` 与禁用清单 `rsv_*`/`sv_*`/`wi_*` 同族，术语表明确禁止；对用户无业务含义。
4. **详情明细截断在 100 条且无分页** — `history-backfill-page.tsx:973`（pageSize:100 硬编码）、`:1816-1824`（ItemsTable 无分页）。概览卡自述「可能因分页存在差异」（`:1603`）却无翻页控件，超百条数据不可达；回填任务动辄百万级，明细浏览/导出前核对不可行。
5. **非管理员创建面板提交按钮静默禁用，无原因说明** — `history-backfill-page.tsx:819`（`blocked = !canCreateDraft || role !== "SYSTEM_ADMIN"`）、`:929`（disabled 无提示）；接口已有「仅系统管理员可创建草稿并启动回填」文案（`api.ts:421`）未透出。术语表 7-2「禁用态不解释原因」反模式。

### P2（体验瑕疵）· 12 个

1. 文案错字「**来来源更新时间**」— `history-backfill-page.tsx:1334`。
2. 进度条「失败」卡片与描述行口径不一致（失败卡 = failed + unattributed，描述分列）— `history-backfill-page.tsx:1289,1295-1297`。
3. 版本徽章展示实现词 `lv-3`（lockVersion）— `history-backfill-page.tsx:1137`；术语表要求锁版本词不出界面。
4. 「最近心跳」为内部术语 — `history-backfill-page.tsx:1299`，应改「最近更新于…」。
5. 阻断 Alert 与失败诊断展示原始错误码/枚举原值：`ROLE_DENIED`（`:1351`）、`failure.errorCode` 与阶段英文原值（`:1771-1775`）——错误说下一步不说原理。
6. 成本口径筛选下拉用裸枚举 `ACTUAL/STANDARD/NONE`（`:696-699`、`:1547-1549`），指标条「NONE 消费」（`:566`），列表「成本覆盖」列含裸 `NONE n`（`api.ts:119`）——与详情页 `COST_BASIS_LABEL`（带中文注释）不一致，且 `ItemFilters` 尾部把「URL：result / factType / costBasis」参数名原文写给用户（`:1558-1560`）。
7. 创建面板「必需历史起点」与「回填起点（固定）」同值两行重复 — `history-backfill-page.tsx:840-849`。
8. 列表页无手动刷新入口，运行中任务进度列只能靠筛选变更触发重取 — `history-backfill-page.tsx:478-771`。
9. 详情页错误态无「重试」按钮 — `history-backfill-page.tsx:992-1006`。
10. 创建被 BLOCKED 时结果横幅渲染在 Sheet 之下（页面流 540 行 vs 侧边面板 821 行），面板内无提交反馈，用户可能看不到失败原因。
11. 详情页运行中每 8 秒轮询时明细表顶部反复出现「正在刷新」条（`queries.ts:42-46` → `data-table.tsx:655-663`），视觉噪声。
12. 列表页永久「范围与敏感边界」Alert 常驻且不可关闭（`:730-737`），与「下载报告」按钮名不副实（`:1216-1224`）同属长期文案/布局负担。

## 六、改进建议

**优先（P1 对应）**
1. 详情页 `ItemFilters` 补「搜索」输入框（对齐列表 q），并将 `result/factType/costBasis` 在切换任务时重置为默认（`onOpenJob` 时丢弃明细过滤参数），杜绝隐形状态跨任务继承。
2. 结果横幅与提示统一走术语表映射：`operationId`/`idempotencyKey` 原文 → 业务任务号；`api.ts:408/412` 的「按 operationId 查询」改为「查询原任务处理结果」并提供真实查询入口（或至少给出任务号链接）。
3. 去重证明列只展示 `formalFactSummary` + 命中来源，删除 `formalFactId`/`originalMessageId` 原文；「原任务标识」「切换编号」值改为业务可读编号或直接隐藏。
4. 明细表接入服务端分页（沿用列表页 `DataTable` 分页模式），删除「可能因分页存在差异」的免责文案。
5. `CreateBackfillSheet` 对角色阻断透出原因（复用 `api.ts` 现成文案「仅系统管理员可创建回填任务」），或在详情页用 `GuardedBusinessAction` 式 tooltip 说明缺失动作的原因。

**跟进（P2 对应）**
- 修正 1334 行错字；心跳→「最近更新于」；`lv-` 前缀去掉或改「版本 3」。
- 统一成本口径文案：筛选下拉/指标条改用 `COST_BASIS_LABEL`（至少保留中文注释），移除面向用户的 URL 参数名提示。
- 进度条失败口径与描述一致（失败卡片只计 failedCount，待归集单列或在卡片注明含待归集）。
- 列表页补刷新按钮（或对含运行中任务的结果开启轻量轮询）；创建失败时在 Sheet 内直接展示 BLOCKED 原因；评估将敏感边界 Alert 改为可关闭/折叠。
- 错误码展示收敛为「错误编号」样式并附业务建议，避免裸枚举上屏。
