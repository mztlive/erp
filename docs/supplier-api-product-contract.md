# 供应商 API 商品与自动履约执行合同

## 1. 适用范围与效力

1. API 是现有供应商的接入能力。供应商身份、资质、业务编号与责任人继续使用既有供应商档案。
2. 本合同规定供应商品库、采购选品入库、公司商品资料同步与差异确认、API 自动发单及履约跟踪。
3. 本合同优先于 `erp-phase-2.md` 中“必须先建公司 SKU”“不得建立供应商商品目录或映射”及旧目录只允许匹配、不允许选品建档的限制。普通手工供给、Excel 供给导入和供应商门户继续执行各自合同。
4. 公司商品使用现有 product、sku 及修订体系；公司商品池继续作为可售查询视图。选品入库不产生库存、收货或财务事实。
5. 本次实现以当前已接入的供应商协议为首个运行对象。未支持的协议能力必须明确显示，不得模拟成功。
6. 外部业务系统后续下单须复用 ERP 商品身份与订单执行链。本次不新增商城、支付分摊、卡券消费或任意外部系统专用接口，不建设动态比价和供应商评分路由。

## 2. 业务对象与字段归属

| 对象 | 责任与数据 |
| --- | --- |
| 供应商品库 | 保存连接、供应商、外部商品和 SKU 身份、来源分类品牌、名称规格单位、图片详情、来源报价和可供事实、来源版本与观察时间；允许先同步后选品 |
| 公司商品与 SKU | 使用现有商品列表和主数据，统一承接手工、导入、门户和 API 选品；保存公司分类、展示内容、销售参考价及上架状态 |
| 供应商供给 | 连接公司 SKU、供应商、外部 SKU 与 API 连接；保存采购条件及当前可供事实 |
| 商品资料同步关系 | 指定公司商品唯一的资料来源，保存已处理来源基线、公司人工维护字段、最新来源观察及待确认差异 |
| 供应商订单 | 保存 ERP 来源单据与明细、固定供给、外部订单号、独立执行步骤、请求快照和履约结果 |

1. 外部商品和 SKU 编号不允许普通编辑；纠正关联须重新核验来源、规格与单位，不得改写历史订单身份。
2. 供应商原始资料只读；公司名称、介绍、主图、详情图允许按商品维护权限编辑。
3. 公司分类、销售参考价、内部备注和主动上下架由公司维护，供应商同步不得覆盖。
4. 来源采购报价、库存、可供和配送限制由接口同步；公司可以停用供给或收紧经营范围，不得手工伪造来源可供事实。来源采购报价与采购供给销售的一件代发含税供给价分别维护：入库时可用接口报价预填供给价，采购可以调整；提交及后续修订保存采购确认的供给价，接口同步不得覆盖。接口报价继续保存在供应商品库，作为采购参考。
5. SKU 规格身份、包装含义及基础单位变化必须重新核对，不得用展示资料覆盖操作改变已有 SKU 身份。
6. API 来源未提供集采报价与起订量时，正式供给保留为空且只支持一件代发；采购不得编造集采条款，集采流程不得使用该供给。普通手工、Excel 与门户供给继续执行既有完整报价要求。
7. 一个公司 SKU 可以有多个供给；一个公司商品同一时点只能有一个展示资料同步来源。更换来源必须明确确认并建立新基线。

## 3. 供应商品库与同步

1. 首次按供应商授权范围全量采集，后续优先增量、变更通知及定向补查；无增量能力时按周期全量校对并明确标示实际同步方式。
2. 支持新增、修改与供应商明确的撤回/不可供；只有完整覆盖且具备可靠退出语义的完整扫描才允许根据缺项判定退出。分页失败、部分覆盖和单次查不到不得解释为下架或库存为零。
3. 同步必须分页、有界并发、保存检查点及真实进度；单项映射异常须记录并跳过，同页有效项继续保存，异常不得覆盖已有资料或视为下架。页面、网络、鉴权或保存失败保留此前已提交结果，恢复不重复创建相同商品。同步记录按供应商连接隔离并显示异常总数及脱敏原因。
4. 重复消息去重，可比较旧版本不得覆盖新版本；缺少来源更新时间不得伪造。
5. 目录提供关键词、供应商、来源分类、品牌、报价区间、可供状态和选品状态筛选。字段缺失显示未知，禁止用零价、零库存或无限库存代替未知。
6. 可供与价格变化应用到关联供给时须保留采购条款历史；不得修改公司销售价格或历史订单快照。关键规格变化先阻断该供给的新增自动使用并提示核对。
7. 关键规格待核对须提供受控确认入口：核对当前来源、公司 SKU 和供给版本，由采购说明原因并确认仍为同一实际销售项及单位；不得通过该操作更换身份，实质规格改变必须新建正确 SKU 或重新处理关联。
8. API 凭据、签名和技术引用属于管理员设置，采购日常入口为供应商品库；保留连接测试、同步进度及可理解的失败原因。删除独立接口配置详情页与人工能力矩阵，商品库内提供只读能力、连接诊断和“允许自动下单”。能力以适配器实际窄 trait 为准，不再登记或逐项确认。
9. 开启自动下单自动完成当前配置的只读鉴权检查；失败不改变开关。关闭只阻止新增发单，不阻止商品同步、选品、已有订单跟踪、回调与必要履约通知。采购审批、金额复核、订单幂等和未知结果调查继续执行。

## 4. 选品入库

1. 采购可以选单项、多项、当前分类或当前筛选结果。按分类操作只作用于本次确认的结果，不自动订阅未来新增商品。
2. 批量选品先预览，返回将创建的公司商品/SKU、匹配已有商品、供给及缺失信息；筛选批量在服务端冻结选择范围，禁止前端只处理当前页冒充全部结果。
3. 入库方式由服务器自动决定，采购不得指定目标 SKU 或选择新建/关联。处理顺序为：复用来源规格既有绑定；按实际条码查询唯一归属；在已绑定公司商品内按规格及单位匹配；未绑定时按商品类型、已知品牌、完整名称、完整规格及基础单位精确匹配；无匹配且建档资料齐全时新建。同一来源商品的规格必须归属同一公司商品，条码命中不得绕过该约束。
4. 名称只统一全角 ASCII、首尾和连续空白，不删除型号、口味、系列、数字或包装词。规格只消除受支持的格式差异，不进行总容量折算；`250ml×12盒` 与 `500ml×6盒` 不得合并。单一来源规格对应公司「规格」属性，结构化来源规格必须与完整公司规格签名一致。空规格不得作为匹配证据。来源缺少品牌或品牌为“无品牌”时，不进行跨来源名称匹配；已有来源绑定和有效条码仍可使用。
5. 来源条码为可选字符串，去首尾空白并保留大小写及前导零，不转换为数字，不从商品编号或规格编号推导，不截取多码列表。超过 128 字符的输入拒绝。条码命中必须复验当前商品类型、已知品牌、完整规格及基础单位；条码不同、历史归属歧义、已删除或停用的占用者均阻断，不允许回落到新建。条码相同不构成单独合并依据。
6. 来源单位有值时，必须与所选启用公司单位的代码、名称或符号精确对应；不支持隐式数量或包装换算。来源单位缺失时由采购补充公司计量单位。品牌、公司类型、规格、单位或来源商品归属冲突，多个候选、资料不足及停用身份，均按逐项异常返回；不得取第一条或另建商品绕过异常。
7. 首次展示资料从来源带入。来源分类名称与同商品类型的公司分类名称唯一精确匹配时可预填，否则采购补齐。新建品牌按来源名称精确复用启用品牌，未命中时创建；来源缺品牌时使用“无品牌”，该占位不作为跨来源匹配证据。同一来源商品追加 SKU 沿用已绑定商品的分类、品牌和类型。进项税率默认 13%，采购可修改；价格及配送等必要信息缺失时须补齐。
8. 自动匹配结果必须展示“关联已有 SKU”“已有商品新增规格”或“新建商品及规格”。解析请求只接受建档映射和公司展示内容；确认请求仅接受 `AUTO` 目标及已查看的结果摘要，不接受 `CREATE`、`EXISTING` 或目标 SKU 参数。旧人工匹配及目标 SKU 查询路由必须移除。提交在事务内重验来源、目标身份和版本，结果发生外部变化须重新匹配，不得静默更换目标。
9. 同一批次前序已入库的商品可被后续规格自动复用，必须由同操作号的成功回执证明，且原预览为新建商品。同一来源 SKU 重复提交返回原结果；同操作号异载荷拒绝。逐项原子保存建品、条码占用、供给及来源关系，失败不留下半成品商品或供给，其他可处理行继续执行。
10. 自动匹配与商品建档、SKU 修订使用共同事务内名称写入点防止并发重复建档；条码沿用公司 SKU 的唯一占用机制。关联已有无条码 SKU 时可登记来源条码归属，不改写公司当前修订。保留停用及历史条码归属进行冲突检查；数据库冲突必须显式返回，提交结果未知时禁止自动重放。
11. 新建 SKU 保持未上架，维护销售参考价并明确上架后进入公司商品池；关联已有 SKU 保留原上架状态、销售价和展示资料。自动关联只增加供给，不建立或替换既有商品的展示资料同步来源；新建商品建立初始资料来源；新增规格仅扩展已存在的资料来源，不为原本没有同步来源的已有商品自动建立来源。
12. 选品成功后提供现有公司商品入口；异常项保留输入与原因，修正后重新匹配并重试。用户不需要逐项选择创建或关联方式。
13. 选品预览前必须校验连接类型、部署配置、适配器商品读取能力及来源商品的供应商归属，不要求开启自动下单。故障、已删除、配置缺失和归属不一致分别返回明确原因及处理指引。页面禁用不可用连接的单项、勾选和筛选入库入口，并展示连接诊断入口。自动匹配及逐项提交事务内再次校验来源资格，连接不可用时不得继续建品或建立供给。已成功入库的同操作重试仍返回原回执，不重新写入。

## 5. 展示资料自动同步与差异

### 5.1 判定

系统按字段比较已处理的来源基线、公司当前内容、供应商最新内容，维护商品名称、SKU 销售名称、介绍、主图序列、详情图序列的同步责任。商品共有资料按商品保存，SKU 名称及主图按 SKU 保存并校验各自版本。

| 情形 | 必须执行 |
| --- | --- |
| 来源未变化，公司人工编辑 | 保留公司内容，不产生来源更新待确认 |
| 来源变化，公司未人工维护该字段 | 自动更新该字段并登记修订 |
| 双方修改同一字段且不同 | 保留公司内容，保存待确认差异 |
| 双方最新内容相同 | 更新基线并消除无意义差异 |
| 修改发生在不同字段 | 未人工维护字段自动更新，人工维护字段保持公司内容 |

1. 人工修改责任按字段保存，不因其他字段变化锁定整件商品。
2. 主图、详情图按各自有序图片组处理，识别新增、删除、替换及排序。
3. 图片采用可核验内容指纹、来源可靠版本或持久化内容标识识别变化；仅 URL 相同不得证明内容未变化。无法读取或证明内容时显示待核验，不得冒充一致。
图片由独立后台任务处理，不阻断供应商品库写入和选品；选品须提示未完成的图片类型和序号，仅使用预览中已核验的图片。后台补齐须核对来源版本，遵守公司资料人工维护及差异处理规则。
4. 需要下载素材时须在数据库事务外执行，遵守既有文件资产权限、受控来源与上传约定；失败不得把现有公司图片清空。
5. 来源明确清空字段与来源未提供字段必须区分；不完整响应不得触发删除公司资料。
6. 来源文本超过公司字段容量时保留完整来源并提示人工整理，不静默截断，不阻断其他字段及其他商品的持续采集。未核验图片的提示持续保留，直至核验成功或用户明确处理。
7. 来源修订不得重新启用人工停用的商品或 SKU，不改变公司主动上下架状态。

### 5.2 提示与比较

1. 公司商品列表显示“资料更新待确认”及差异数量，支持仅筛选待确认商品。统计、列表与筛选遵守相同权限及数据范围。
2. 商品详情显示来源供应商、更新时间、涉及字段及“查看差异”入口；待确认期间继续展示公司当前内容。
3. 对比页展示公司当前版本和供应商最新版本。文本标识增删改，图片并排预览并展示排序和删除变化。
4. 普通自动同步记录进入历史，不生成无差异人工待办。

### 5.3 确认

| 操作 | 结果 |
| --- | --- |
| 采用供应商版本 | 仅覆盖选中字段，更新基线，解除该字段人工维护标记，恢复后续自动同步 |
| 保留公司版本 | 不改公司内容，更新已处理来源基线，保留人工维护责任；相同来源版本不重复提示 |
| 编辑后确认 | 保存人工整理内容，更新基线并保持人工维护责任 |

1. 支持逐字段确认和本次差异全部采用/全部保留，确认界面明确覆盖范围。
2. 确认同时提交来源版本及公司当前版本；任一版本变化拒绝并要求重新比较，不得覆盖未看过的新内容。
3. 保存商品修订、基线、差异状态、审计与命令回执必须原子；重复确认返回原结果，异载荷拒绝。
4. 权限使用现有商品读取/维护和数据范围；未经授权不得通过差异接口读取供应商成本或其他商品资料。

## 6. 自动采购与供应商发单

1. 自动发单触发于既有 ERP 销售、供给分配和采购流程已经满足执行资格之后；保留已配置审批，不因 API 能力绕过销售或采购审批。
2. 系统复用正式采购及履约记录，消除重复录单和人工向供应商发单。每次执行必须冻结来源单据/明细、供给修订、外部 SKU、数量、采购价格、收件地址与交付条件。
3. 配置默认 API 供给或使用采购已明确选择的供给；无确定供给时明确阻断。不进行动态比价、自动切换供应商或自动扩大采购金额。
4. 按供应商、地址及配送条件拆分；同单人工与 API 供给分别执行，汇总回原业务单据。
5. 下单前复核真实可供、采购价格及地址配送条件；缺货、超出已批准金额、关键资料未核验、配送不可用时进入异常处理。
6. 保存执行意图后再在事务外调用供应商；创建、地址准备、支付结果通知等步骤独立持久化。供应商不支持的步骤不得模拟成功。
7. 写请求超时或结果未知时先按原单号调查，不能直接重发；重复任务和进程重启不得重复下单。
8. 订单变更、取消必须核对已发供应商订单。未发送的旧执行与自动生成的未发货草稿可以在采购变更同一事务中退役并按新版本重排；原动作、单据与审计保留。创建或支付结果未知时不得重排。
9. 已创建订单需要取消时，接口支持则按原动作申请并追踪；接口不支持则先在供应商侧处理。仅真实查询已确认取消、该观察已应用且不存在发货或未决退款冲突时，允许沿原采购变更控制继续调整，不得凭人工声明或仅改 ERP 状态伪造取消。

### 6.1 供应商支付结果通知

1. 供应商要求的“支付结果通知”属于供应商开始履约所需的接口确认步骤。ERP 订单具备既有执行资格、供应商订单创建成功且金额核对通过后，系统自动调用并告知支付成功。
2. 本步骤不依赖客户或用户是否已经向前端业务系统付款，不新增实际采购付款或银行流水门槛。客户、用户支付资格由上游业务负责；ERP 已配置的采购审批与执行控制继续有效。
3. 通知使用稳定的履约通知业务编号和已经核对的供应商订单金额；该编号不得展示或记账为真实收付款流水。
4. 通知不生成或修改 ERP 客户回款、供应商付款、应收核销、应付核销及银行交易事实。供应商接口返回的支付状态只表示供应商侧履约确认结果。
5. 创建订单与支付结果通知分别保存请求快照、操作身份及结果；通知超时先查询原结果，不重新创建供应商订单，不因接口通知成功伪造资金支付。

## 7. 履约跟踪

1. 回调验签后持久化，后台补查并按同一状态规则应用；定时查询补偿漏推和延迟。
2. 回写外部订单号、接单状态、分包裹物流、发货及完成事实，并关联既有 ERP 采购、交付记录。接收回调成功不等于业务已应用。
3. 重复或旧结果不重复生成发货、财务或库存事实；异常及无法消解的冲突保留证据并提示处理。
4. 供应商直发不增加公司仓库库存；入仓采购通过实际收货流程确认，不以供应商发货状态直接增加库存。
5. 供应商订单完成不替代 ERP 已有客户验收及财务结算规则。

## 8. 数据兼容与发布

1. 扩展现有供应商目录与公司商品体系；既有手工商品、供给和历史订单保持原身份及行为。
2. 旧目录人工匹配不等于完成选品、正式供给或资料同步授权。必须经明确选品/关联操作建立同步基线。
3. 新字段提供诚实的缺省状态。新索引通过领域索引入口登记；需要存量改写时提供有界迁移、备份及回滚。
4. 新版 API 供给允许未提供的集采条款为空，旧版不具备该业务语义；回滚前必须停止此类新增写入并核对已有供给的旧版读取能力，不得用零价或虚构价格改写兼容。
5. 回滚停止新增同步应用和发单任务，保留商品修订、来源基线、确认回执和外部订单证据，不删除业务数据。
6. 对外路由、DTO、权限生成物和前端调用同步更新；不得保留可以绕过新规则的旧写入口。

### 8.1 自动匹配字段发布与回滚

1. 发布前停止商品建档及修订写入，并备份 `product_revisions`。新增 `match_name` 为名称的派生索引字段，不修改商品名称、版本和业务时间；历史字段缺失时自动跨来源名称匹配必须失败关闭。
2. 使用目标数据库运行 `backend/scripts/migrations/catalog-match-name.js`。默认只读核对；明确指定 `ERP_APPLY_CATALOG_MATCH_NAME=1` 才分批回填。不得连接未确认的目标库。执行后再次只读核对，`changed` 必须为零。
3. 启动新版服务，由商品领域索引入口创建名称查询索引。`catalog_match_guards` 仅保存事务并发控制计数，使用 MongoDB 自带 `_id` 唯一约束，不保存商品归属或授权事实。匹配已有商品时使用商品及 SKU 文档的 `match_guard` 计数争用写入，不增加业务版本；这些计数不参与商品展示、销售定价或身份判定。
4. 同时发布前后端；旧页面请求须被拒绝并提示刷新。已有供应商目录未提供条码时读取为缺省空；新同步提供条码时记录原文，后续缺字段不清空已观察条码，已入库条码变化触发身份核对。
5. 回滚前停止选品写入，恢复配套旧版前后端；保留条码归属、来源关联、回执、`match_name` 和并发控制记录，不删除业务数据。派生字段不影响旧版反序列化，不通过回滚释放条码占用。
