# 导入导出后台任务合同

## 1. 范围与入口

本文约束管理端和供应商门户的文件任务。任务领域固定为 `DATA_TRANSFER`，任务和逐行结果存入现有后台任务集合，不接受调用方指定执行器、权限、对象存储路径或任意 URL。

| 任务类型 | 业务入口 | 产物或执行效果 |
| --- | --- | --- |
| `product_pool_excel` | 公司商品池 Excel 导出 | 带图片的 v4 选品、配送需求、填写说明工作簿 |
| `supplier_quote_archive` | 采购询价供应商报价表 | 按供应商分组的 v3 XLSX ZIP；配送信息仅包含地区汇总 |
| `sales_orders`、`purchase_orders`、`contracts`、`customers` | 对应业务列表导出 | 当前筛选及授权范围内的 CSV |
| `inventory_balance`、`inventory_movement`、`inventory_adjustment`、`inventory_reservation` | 库存四类列表导出 | 当前筛选及授权范围内的 CSV |
| `supplier_orders` | 供应商履约订单导出 | 实际订单 CSV，不生成模拟任务号 |
| `receivables`、`supplier_payables`、`invoice_requests` | 客户往来、供应商往来、开票申请 | 原财务范围视图 CSV；未授权整单金额保持空值 |
| `profit_loss`、`customer_quality_current`、`customer_quality_history` | 经营报表导出 | 原 ReadModel 生成的报表 CSV |
| `master_data` | 商品、供应商、可售 SKU 目录导出 | 原筛选条件下的九列资料 CSV |
| `inquiry_preview`、`inquiry_creation_preview` | 询价文件上传 | 后台解析及校验预览，最终确认仍调用原原子确认接口 |
| `supplier_quote_preview` | 供应商报价回导 | 后台解析文件和生成逐行预览，最终报价登记仍调用原确认接口 |
| `supply_batch` | 管理端供给批量创建、修订、可供更新 | 复用原批量用例、逐行事务与命令回执 |
| `portal_batch` | 供应商门户批量提交及结果恢复 | 复用原门户批量用例，不改变创建后续步骤及恢复语义 |

商品、供应商既有导入和 OCR 保留原任务链路。小型字典导出、空白模板下载不新增后台任务。历史期初导入按第 7 节处理。

## 2. HTTP 合同

管理端使用已登录账号接口 `/account/data-transfers`；供应商门户使用 `/supplier-portal/data-transfers`。实际公共 API 前缀由现有路由组合确定，客户端继续使用统一 API client。

| 方法与相对路径 | 请求 | 返回 |
| --- | --- | --- |
| `POST /data-transfers` | `{request_id, kind, input}` | 真实 `BackgroundJobView` |
| `GET /data-transfers` | 原后台任务分页条件 | 仅本人提交的 `DATA_TRANSFER` 任务；服务端固定领域及归属 |
| `GET /data-transfers/{id}` | 无 | 本人任务状态及计数 |
| `GET /data-transfers/{id}/result` | 无 | `{file_name, content_type, content_base64, metadata}` |

所有返回遵循现有响应信封，设置 `Cache-Control: private, no-store`。接口不得返回内部授权依据或对象存储直链。供应商入口只接受 `portal_batch`，账号和绑定版本由服务端会话覆盖，禁止信任请求中的身份字段。

同一账号与同一 `request_id` 构成创建幂等身份；相同内容重放返回原任务，异内容返回冲突。前端创建响应丢失时，在同一浏览器会话内使用输入及当前会话摘要恢复原操作号；会话存储不保存上传文件、业务参数或 token。批量写命令始终沿用原行命令号，禁止以新的命令号恢复结果未知项。

## 3. 执行与恢复

1. 提交阶段校验权限和输入，将输入加密写入对象存储，原子登记文件资产、任务、任务项和审计记录。
2. 执行器每轮最多读取 8 个候选、并发执行 2 个任务。任务版本作为执行权凭据；每 20 秒更新心跳，120 秒无心跳允许其他实例重新认领。
3. 执行器必须重新验证原提交人当前可登录状态和业务权限。不得使用服务账号扩大业务范围。
4. 文件生成及外部存储 I/O 不进入数据库事务。私有输入、结果和图片对象读取写入使用 60 秒超时。
5. 结果文件资产、逐项状态、计数和任务终态原子保存。没有结果文件的失败任务不得显示下载成功。
6. 导出和预览按一个操作项计数；供给和门户批量任务按输入行计数。心跳不冒充业务完成进度；批量行计数在汇总结果落库时更新。
7. 批量任务必须区分全部成功、部分成功、全部失败。结果未知项计入未成功项，并保留 `outcome_unknown` 恢复提示；不得因批量函数返回而把全部行标记成功。
8. 已开始的文件导入任务不得中途取消，包括全局批量取消入口。待执行任务可以取消；导出取消通过版本竞争阻止旧执行器提交结果。取消不回滚已产生的业务事实。

关闭业务页面或中断轮询不取消服务端任务。管理端个人菜单及供应商门户均提供“我的文件任务”，允许本人查看进度和下载产物，不要求全局后台任务管理权限。导入预览 JSON 的下载不等于业务确认；需要重新进入原业务页面完成校验与确认。

### 后台任务菜单角标

1. 管理端“后台任务”菜单使用与工作台一致的数字角标，正常计数采用绿色；总数为 0 时隐藏。
2. 计数使用 `GET /admin/background-jobs?active_only=true&page=1&page_size=1` 返回的 `total`，不得对当前页求和。普通用户仅统计本人任务，管理员沿用后台任务列表的全局可见范围。
3. `active_only` 默认 `false`；为 `true` 时，状态限定为 `pending`、`running`、`partially_succeeded`，且 `finished_at` 必须为空。与其他筛选条件取交集；已结束的部分成功任务不得计入。
4. 菜单可见且页面处于前台时每 2 秒刷新，重新聚焦窗口时刷新。查询失败显示异常提示，不得以 0 替代失败。查询沿用现有状态及发起人索引，不新增存储字段。

## 4. 授权及一致性

- 所有列表查询沿用原 Service/ReadModel 和 DataScope；提交时存在的 `scope_version` 必须传入执行阶段，分页拒绝范围版本、总数变化、重复身份及不完整结果。
- 下载前重新校验本人归属、账号状态、当前业务权限、原输入范围和结果有效期。列表及报表重新计算授权内容摘要；商品 Excel、报价 ZIP 重新读取业务事实及图片资产版本摘要，不重复生成文件。
- 当前数据、任务责任、供给关系或授权范围变化时，拒绝下载旧产物并提示重新导出。
- 财务导出保留“获授权份额”和整单字段的原有区别；被脱敏的 `null` 不得转为零。
- 供应商报价包只写入报价所需商品、需求、供给和地区汇总字段；不得包含客户身份、收件人、电话和详细地址。
- CSV 字符串统一转义引号、换行及表格公式前缀；金额和数量保留服务端十进制文本，不使用 JavaScript 浮点数重算。

## 5. 文件与容量边界

| 项目 | 上限或要求 |
| --- | --- |
| 任务 JSON 业务输入 | 75 MiB，HTTP 请求体 76 MiB |
| 列表数据 | 100,000 行；每页 100 行 |
| 商品池导出 | 1—2,000 个商品；生成文件不超过 5 MiB |
| 询价导入 | XLSX，不超过 5 MiB |
| 报价导出 | 每任务 1—200 条需求、1—200 家供应商；ZIP 内文件合计不超过 50 MiB |
| 报价回导 | 1—20 个 XLSX；单文件不超过 20 MiB、合计不超过 50 MiB；单表最多 200 条商品、合计最多 1,000 条回复 |
| 工作簿展开 | 复用现有有界 ZIP/XML 解析器；拒绝宏、外链、非法路径、重复路径与展开超限 |
| 报价单元格 | 拒绝公式、超链接和 1904 日期系统；原需求、单位、数量和交付要求必须匹配 |
| 商品图片 | 原文件不超过 20 MiB，解码像素不超过 4,000 万；导出缩略图最长边 152 像素 |
| 结果文件 | 不超过 64 MiB；文件名不得包含路径和控制字符 |
| 私有资产 | 输入和结果加密保存，HMAC 校验；七天保留级别，过期禁止读取 |

商品池继续使用 v4 表结构及配送核对公式，公式中的 SKU 匹配必须转义通配符。服务器导入以业务列和服务端规则为准，不信任 Excel 辅助公式缓存。

部署时必须为配置的对象存储前缀下 `data-transfer/` 配置过期清理及历史版本清理策略，以清理到期密文和提交失败产生的孤立对象。应用中的七天有效期只负责访问拒绝，不能代替对象存储物理清理。修改桶生命周期属于部署配置操作，应在目标环境单独执行并核验。

## 6. 错误与处理

| 标记 | 处理要求 |
| --- | --- |
| `TRANSFER_FORBIDDEN` | 当前身份、权限或范围变化；重新查询业务页，不自动扩大范围 |
| `TRANSFER_INVALID` | 展示安全的校验原因，核对原数据、文件或业务版本后重新提交 |
| `TRANSFER_OUTCOME_UNKNOWN` / `outcome_unknown` | 沿用原操作号恢复，不换键重复登记 |
| `TRANSFER_FAILED` | 查询原任务并核对结果；写入重试仍须使用原行命令号 |
| 文件已过期、内容或授权摘要变化 | 重新提交生成任务，不继续暴露旧产物 |

失败记录应保留真实任务编号供排查。批量逐行详细原因在受控结果中读取。业务页不得把网络、权限或解析失败显示为空列表、零金额或导出完成。

## 7. 历史期初导入

`StartApply` 和 `RetryFailed` 在创建运行状态或任务前拒绝，提示 `LEGACY_IMPORT_EXECUTOR_UNAVAILABLE` 及“历史期初导入执行器尚未接通”。前端启动、失败重试按钮禁用并展示原因；试算、责任确认、查询和取消未应用项保留。

业务迁移执行器作为独立专项，按 [历史期初业务迁移专项执行要求](legacy-import-migration-contract.md) 实施。未满足专项验收要求前，不得解除启动阻断，不得以手工登记执行结果冒充业务单据已写入。

## 8. 发布与回退

发布必须同时包含后端执行器、路由、后台任务查询索引和前端入口。复用已有索引登记流程，不迁移或清空业务集合。

回退时停止新任务入口并停止该执行循环，保留任务、回执和私有文件；不得删除已成功写入的供给或门户业务事实。恢复运行后由执行权机制接续未完成任务。部署验收应在授权环境核对重启恢复、多实例竞争、对象存储权限及过期策略；本地库单元测试和构建不能替代这些环境验收。
