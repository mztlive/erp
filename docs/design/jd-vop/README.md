# 京东 VOP 页面执行约定

## 1. 设计基线

1. 页面实现以[关键页面状态预览](index.html)及《[京东 VOP 供应商接入技术实施方案](../../jd-vop-integration-plan.md)》第 10.2 节为依据。
2. 预览仅使用本地样例数据，不发起业务请求，不代表接口授权、资金到账、供应商执行或 ERP 履约已完成。
3. 本文件规定页面实现与验收要求，预览作为状态与信息结构基线。当前实现、未完成项及验收状态统一登记在[实施状态台账](../../jd-vop-integration-plan.md#implementation-status)；预览中的可用状态不得作为生产能力已接通的证据。
4. 连接设置、商品库、采购与销售详情复用原入口和共享组件；预存款管理挂接供应商往来，不新增京东销售或采购主流程。
5. 预览中的左侧导航仅用于设计浏览，不作为生产菜单登记依据。现有页面的未改动分区继续按原合同执行。

## 2. 页面及状态

| 页面 | 预览入口 | 必须覆盖的状态 | 主要办理入口 |
| --- | --- | --- | --- |
| 连接设置 | `index.html#connection/ready` | 只读可用、配置缺失、授权失效、消息延迟及账户待核对 | 测试连接、自动下单开关、查看账户异常 |
| 商品库 | `index.html#catalog/ready` | 有报价及起购限制、缺报价与规格待核验、不支持的附加服务、无成本权限 | 同步商品、加入选择、批量选品、原商品轻预览 |
| 履约资料补齐 | `index.html#address/ambiguous` | 多候选、缺第四级地址、已确认、地址或数量变化后原核验失效 | 保存待补齐资料、确认地址并核验、返回采购 |
| 采购履约 | `index.html#order/partial` | 部分确认及部分发货、确认未知、运费超批、占用不足、部分取消且返款待核实 | 查询原结果、查看子单物流、追加费用、付款申请、原变更入口 |
| 供应商预存款 | `index.html#funds/active` | 部分扣款与核销、银行已付未到账、自动授权失效、取消待返款、对账差异暂停新增使用 | 登记充值付款、核对到账、执行授权、账户流水及对账 |
| 销售交付 | `index.html#sales/partial` | 部分发货、销售角色隐藏成本、交付变更受下游订单约束 | 原发货记录、原客户验收、关联采购及交付变更 |

## 3. 信息和操作规则

1. 对象头只展示一份主身份，使用供应商名称、业务单号及必要次身份。内部执行身份、密钥、令牌和技术账号明文不得进入页面。
2. 连接状态必须分别展示配置缺失、授权失效、只读可用及功能缺失。已关闭自动下单不阻断商品同步、选品、调查、取消与跟踪。
3. 商品库按来源 SKU 展示。采购报价、观察时间、询价数量、起购数量、购买倍数、单位和来源类目分别表达；未取得字段显示“未取得”，不得补造默认事实。
4. 接口采购报价保持只读。选品沿用严格自动匹配和待处理规则，不提供人工指定目标 SKU 的新入口。不支持的安装、预约等流程须明确阻断自动发单。
5. 地址转换结果展示为候选。人工确认四级区域后，使用冻结数量和地址重新核验；原收货地址的业务变更返回原采购流程办理。
6. 采购履约分开展示商品批准金额、运费批准金额、有效资金占用、真实扣款核销及待核实金额。运费超批、付款未批准、授权不足、资金占用不足、远端余额不足及原请求未知分别显示原因和对应入口。
7. 供应商订单按原根单和当前有效子单展示。子单操作旁须给出目标子单、商品和数量。根单及历史父节点不重复累计数量、金额或交付。
8. 创建、确认或取消未知时，仅提供查询原结果及既有调查入口；不得提供更换原单号、重建订单或直接重发按钮。
9. 供应商取消受理、取消完成及账户返款分别表达。返款未到账时，可用余额不增加，采购核销不自动冲回。
10. 销售已发货仅汇总已应用 ERP 交付数量。预占、确认、根单完成及无商品数量证明的运单不计入已发货。供应商妥投不替代客户验收。
11. 销售角色缺少成本或供应商权限时，服务端须隐藏相应字段；页面只保留有权查看的交付数量和业务异常摘要，不通过其他金额推算被隐藏数据。

## 4. 预存款展示及办理规则

1. 账户按付款主体、供应商、外部资金账号及币种隔离；账户身份固定展示，账号只展示业务别名和脱敏尾号。
2. 财务摘要须同时给出账面余额、尚未消耗的占用、可用额度和待核对金额。待核对项说明其是否已包含在占用或其他不可用额度中，同一金额只扣减一次。
3. 充值登记须关联批准的充值申请与真实银行付款；到账核对须有可验证的供应商入账依据。银行已付未到账的充值不进入账面及可用额度。
4. 自动余额执行授权展示适用范围、单笔及累计限额、有效期、授权人和状态。充值批准不代替订单付款批准，订单付款批准不代替自动余额执行授权。
5. 订单占用不计已付；真实扣款核实后，按原资金使用完成采购核销。账户明细可追溯原充值、付款申请、采购单、订单和核销。
6. 银行充值与订单余额使用分别展示；每笔订单使用不得再次计为银行现金支出。返入供应商账户不得显示为银行现金退款。
7. 对账异常导致暂停新增使用时，账户保留原余额、占用及调查明细，不提供直接覆盖余额或删除未知占用的操作。

## 5. 交互与实现要求

1. 生产界面使用现有主题令牌、`components/business` 与 `components/ui`；本预览的独立 CSS 仅服务设计展示，不复制为 feature 私有皮肤。
2. 商品点读复用 `QuickPreviewSheet size="preview"`，完整核对使用对象中心或详细视图；表单不得塞入只读轻预览。
3. 查询使用 TanStack Query，业务表单使用 TanStack Form。金额和数量使用既有定点工具，不转浮点数。
4. 所有可交互目标使用稳定唯一的原生 `id`。输入标签、帮助、错误与字段关联；弹窗提供焦点限制、关闭和返回原焦点。
5. 桌面以现有管理端密度验收。窄窗口允许导航和工具栏换行，横向滚动限制在表格内；登记、授权和变更入口不因窗口变窄而隐藏。
6. 服务端必须复核连接、主体、采购及数据范围；预览按钮位置不代表用户具有操作权限。禁止以客户端提交的账号、父子单或资金归属替代服务端归属核验。
7. 静态结构及脚本检查不等于视觉验收；生产页面完成后，按独立授权取得真实页面和交互验收记录。
