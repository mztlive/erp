# 安全与权限测试用例

### TC-SEC-001：未登录不能访问责任规则和采购创建接口

- 用例编号：TC-SEC-001
- 所属模块：认证
- 需求来源：PRD §3.1、§3.4、§8
- 测试类型：安全 / 权限
- 优先级：P0
- 测试目标：验证所有新增读取和写入入口要求有效登录。
- 前置条件：清除认证状态。
- 测试数据：规则列表、规则创建、责任预览、创建依据和采购创建请求。
- 操作步骤：
  1. 分别访问新增页面和接口。
- 预期结果：页面跳转登录或接口返回统一未认证错误；无数据写入。
- 校验点：响应不泄露规则、账号或内部错误详情。
- 备注 / 待确认问题：无。

### TC-SEC-002：无管理权限用户不能维护责任规则

- 用例编号：TC-SEC-002
- 所属模块：采购责任规则
- 需求来源：PRD §3.1、§5.5
- 测试类型：安全 / 权限
- 优先级：P0
- 测试目标：验证普通销售和采购不能通过页面隐藏绕过后端授权。
- 前置条件：账号只有规则查看或只有采购创建权限，不具备 `procurement_responsibility:manage`。
- 测试数据：新增、编辑、停用规则请求。
- 操作步骤：
  1. 检查页面操作入口。
  2. 直接调用写接口。
- 预期结果：页面不显示维护入口；直接调用被拒绝；原规则不变。
- 校验点：后端权限校验独立生效。
- 备注 / 待确认问题：无。

### TC-SEC-003：采购不能处理其他负责人的剩余明细

- 用例编号：TC-SEC-003
- 所属模块：采购责任范围
- 需求来源：PRD §3.3、§5.6
- 测试类型：安全 / 横向越权
- 优先级：P0
- 测试目标：验证修改 URL、任务号、销售单号或创建依据不能越过责任范围。
- 前置条件：销售单分别有 A、B 负责的明细；以 A 登录。
- 测试数据：B 的任务 ID、创建依据 ID和销售明细 ID。
- 操作步骤：
  1. A 尝试读取 B 的任务详情。
  2. A 构造包含 B 明细的采购创建请求。
- 预期结果：请求被拒绝或不可见；B 的任务和数量不变。
- 校验点：服务端按登录用户和冻结责任范围校验，而非依赖页面筛选。
- 备注 / 待确认问题：无。

### TC-SEC-004：责任规则筛选参数不能注入 MongoDB 操作符

- 用例编号：TC-SEC-004
- 所属模块：采购责任规则
- 需求来源：PRD §5.5、§5.15
- 测试类型：安全
- 优先级：P1
- 测试目标：验证查询和写入 DTO 不接受对象型操作符或非法枚举。
- 前置条件：已登录且有规则查看权限。
- 测试数据：`{"$ne": null}`、`{"$where":"..."}`、超长文本和非法规则类型。
- 操作步骤：
  1. 向查询和写入入口提交恶意形态参数。
- 预期结果：返回参数校验错误；不扩大查询范围、不执行表达式、不输出栈信息。
- 校验点：数据库数据与审计日志无异常写入。
- 备注 / 待确认问题：无。

### TC-SEC-005：用户可见页面不暴露内部任务与并发术语

- 用例编号：TC-SEC-005
- 所属模块：Web 文案
- 需求来源：PRD §3.3、`docs/ui-glossary.md`
- 测试类型：安全 / 可用性
- 优先级：P1
- 测试目标：验证页面不展示内部字段名、任务实现词或底层错误。
- 前置条件：分别制造无规则、无供给、并发冲突和权限不足。
- 测试数据：任务与采购创建页面。
- 操作步骤：
  1. 触发各类错误并查看提示。
- 预期结果：使用“待采购建单”“打开单据”“可采购数量已更新，请刷新后重试”等业务文案；不出现 `work_item`、`owner_user_id`、`lock_version`、MongoDB 错误或栈信息。
- 校验点：页面文本扫描和浏览器观察均通过。
- 备注 / 待确认问题：无。

### TC-SEC-006：规则维护、任务转交和采购创建均有审计记录

- 用例编号：TC-SEC-006
- 所属模块：审计
- 需求来源：PRD §5.15、§8
- 测试类型：安全 / 数据一致性
- 优先级：P0
- 测试目标：验证关键责任与数量动作可追踪。
- 前置条件：管理员和采购账号已登录。
- 测试数据：新增/修改/停用规则、转交任务、创建采购草稿、并发失败。
- 操作步骤：
  1. 执行各动作。
  2. 查询审计记录。
- 预期结果：成功动作记录操作者、对象、动作和时间；失败的并发尝试按项目既有失败审计口径可追踪且不含敏感信息。
- 校验点：审计对象 ID 与实际规则、任务或采购单一致。
- 备注 / 待确认问题：无。
