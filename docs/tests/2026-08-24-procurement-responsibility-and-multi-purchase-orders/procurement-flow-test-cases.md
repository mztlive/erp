# 采购责任与一单多采测试用例

### TC-RESP-001：SKU 规则优先于分类和默认规则

- 用例编号：TC-RESP-001
- 所属模块：采购责任规则
- 需求来源：PRD §3.1
- 测试类型：功能
- 优先级：P0
- 测试目标：验证同一销售行同时匹配多层规则时选择最高优先级的唯一负责人。
- 前置条件：SKU、分类、商品类型和默认调度人规则均启用，负责人账号均有效且有采购创建权限。
- 测试数据：同一 SKU 分别配置 SKU 负责人 A、分类负责人 B、商品类型负责人 C、默认调度人 D。
- 操作步骤：
  1. 在销售单加入该 SKU。
  2. 请求或查看责任预览。
- 预期结果：预计采购负责人为 A，命中来源显示为 SKU 规则；B/C/D 不参与最终分配。
- 校验点：返回唯一用户 A；保存或提交后的责任范围使用 A。
- 备注 / 待确认问题：无。

### TC-RESP-002：分类按父级回退并支持分类加区域

- 用例编号：TC-RESP-002
- 所属模块：采购责任规则
- 需求来源：PRD §3.1
- 测试类型：功能 / 边界
- 优先级：P1
- 测试目标：验证子分类未配置时逐级回退，且分类加区域优先于纯分类。
- 前置条件：子分类属于父分类；父分类有纯分类负责人 B，父分类加华东区域负责人 A。
- 测试数据：子分类 SKU，服务区域分别为华东和华南。
- 操作步骤：
  1. 预览华东销售行负责人。
  2. 预览华南销售行负责人。
- 预期结果：华东命中 A，华南命中 B。
- 校验点：命中层级和负责人均正确。
- 备注 / 待确认问题：无。

### TC-RESP-003：同层多规则冲突阻止提交

- 用例编号：TC-RESP-003
- 所属模块：采购责任规则
- 需求来源：PRD §3.1、§3.2
- 测试类型：异常 / 数据一致性
- 优先级：P0
- 测试目标：验证同一优先层级命中多个启用规则时不随机选人。
- 前置条件：同一 SKU 存在两条启用规则或通过并发制造冲突数据。
- 测试数据：负责人 A、B。
- 操作步骤：
  1. 保存包含该 SKU 的销售草稿。
  2. 提交审批。
- 预期结果：草稿保存成功；提交被拒绝并逐行提示维护采购责任规则；未创建审批实例。
- 校验点：没有随机负责人；没有部分提交副作用。
- 备注 / 待确认问题：正常管理入口应通过唯一约束阻止冲突，本用例同时覆盖异常存量数据的保守处理。

### TC-RESP-004：无规则时草稿可保存但提交被阻止

- 用例编号：TC-RESP-004
- 所属模块：销售单责任预览
- 需求来源：PRD §3.2
- 测试类型：异常
- 优先级：P0
- 测试目标：验证缺少任何责任规则时的保存与提交边界。
- 前置条件：目标 SKU、分类、商品类型和默认调度人均无启用规则。
- 测试数据：一条外采商品行。
- 操作步骤：
  1. 保存草稿。
  2. 提交审批。
- 预期结果：草稿保存；页面显示“暂未确定采购负责人，请联系管理员维护采购责任规则”；提交被阻止。
- 校验点：销售单仍为草稿；没有审批实例和采购任务。
- 备注 / 待确认问题：无。

### TC-RESP-005：负责人资格失效时规则不可保存或不可使用

- 用例编号：TC-RESP-005
- 所属模块：采购责任规则
- 需求来源：PRD §3.1、§5.5
- 测试类型：权限 / 异常
- 优先级：P0
- 测试目标：验证停用、不可登录或缺少 `purchase_order:create` 的账号不能承担采购责任。
- 前置条件：准备三类不合格账号及一个合格采购账号。
- 测试数据：相同匹配范围依次选择各账号。
- 操作步骤：
  1. 管理员尝试保存不合格负责人规则。
  2. 对已有规则撤销负责人权限后提交销售单。
- 预期结果：规则保存或销售提交被明确拒绝；切换至合格账号后成功。
- 校验点：没有向不合格账号建立开放任务。
- 备注 / 待确认问题：无。

### TC-TASK-001：非末级采购审批后仅在最终生效时派发任务

- 用例编号：TC-TASK-001
- 所属模块：采购执行任务
- 需求来源：PRD §3.3、§5.1
- 测试类型：功能 / 状态流转
- 优先级：P0
- 测试目标：验证采购审批与采购执行任务完全解耦。
- 前置条件：审批流程为采购确认 → 销售负责人审批；销售行可唯一解析采购 A。
- 测试数据：一张外采销售单。
- 操作步骤：
  1. 提交销售单并由采购 A 通过采购确认。
  2. 查询采购 A 的待处理任务。
  3. 由销售负责人通过最后审批。
  4. 再次查询采购 A 的待处理任务。
- 预期结果：步骤 2 没有待采购建单任务；销售单生效后出现一条具体指派给 A 的任务。
- 校验点：任务类型、负责人、销售单、责任范围和状态正确；只建立一次。
- 备注 / 待确认问题：无。

### TC-TASK-002：同一销售单按负责人拆分任务和可见明细

- 用例编号：TC-TASK-002
- 所属模块：采购执行任务
- 需求来源：PRD §3.3、§5.6
- 测试类型：功能 / 权限
- 优先级：P0
- 测试目标：验证一张销售单可向多名采购分别派发责任范围。
- 前置条件：销售行 1 解析到采购 A，销售行 2 解析到采购 B。
- 测试数据：两条外采行。
- 操作步骤：
  1. 完成销售单审批使其生效。
  2. 分别以 A、B 登录并打开任务。
- 预期结果：形成两条任务；A 只看到行 1，B 只看到行 2。
- 校验点：两个任务均有具体负责人且责任范围不重叠、不遗漏。
- 备注 / 待确认问题：无。

### TC-TASK-003：重复生效回调不会重复建立任务

- 用例编号：TC-TASK-003
- 所属模块：采购执行任务
- 需求来源：PRD §3.3
- 测试类型：并发 / 幂等
- 优先级：P0
- 测试目标：验证销售生效动作重试时不会产生重复开放任务。
- 前置条件：销售单已生效且任务已建立。
- 测试数据：相同销售单和不可变提交版本。
- 操作步骤：
  1. 重放或并发触发两次销售生效后的任务派发。
  2. 查询开放和历史任务。
- 预期结果：同一负责人和责任范围只有一个有效任务；业务数据保持一致。
- 校验点：唯一约束/幂等结果、审计记录和返回结果可追踪。
- 备注 / 待确认问题：浏览器不稳定制造该路径，主要由服务层集成测试覆盖。

### TC-TASK-004：生效时责任解析失败则不留下部分任务

- 用例编号：TC-TASK-004
- 所属模块：采购执行任务
- 需求来源：PRD §3.3
- 测试类型：异常 / 数据一致性
- 优先级：P0
- 测试目标：验证多负责人分组中任一行解析失败时整体失败。
- 前置条件：提交后撤销其中一名负责人的采购创建权限。
- 测试数据：两条分别归属 A、B 的销售行。
- 操作步骤：
  1. 通过最后审批触发生效。
  2. 查询销售单状态、采购任务和业务异常。
- 预期结果：生效动作返回可重试错误；不只为 A 留下一条孤立任务；存在管理员可见异常记录。
- 校验点：销售生效与任务派发没有部分落库。
- 备注 / 待确认问题：无。

### TC-PO-001：第一次只采购部分数量后仍可继续建单

- 用例编号：TC-PO-001
- 所属模块：采购单创建
- 需求来源：PRD §3.4、§5.7
- 测试类型：功能
- 优先级：P0
- 测试目标：验证一张销售单可以分批建立多张采购单。
- 前置条件：销售明细数量 10，采购 A 有任务，供应商 S 有合格供给。
- 测试数据：第一张采购数量 4，第二张采购数量 6。
- 操作步骤：
  1. A 从任务进入创建页，第一笔输入 4 并建立采购草稿。
  2. 返回销售单详情和创建依据。
  3. 点击“继续建单”，第二笔输入 6 并建立另一张采购草稿。
- 预期结果：第一笔后剩余 6 且入口仍可用；第二笔后形成两张采购单，剩余为 0。
- 校验点：两张采购单 ID 不同；累计覆盖数量为 10；任务最终完成。
- 备注 / 待确认问题：无。

### TC-PO-002：不同供应商和履约责任形成独立采购单

- 需求来源：PRD §3.4

- 优先级：P1

- 测试数据：供应商 S1/S2，入仓/供应商直发。

### TC-PO-003：本次采购数量不得超过最新剩余数量

- 用例编号：TC-PO-003
- 所属模块：采购单创建
- 需求来源：PRD §3.4、§5.8
- 测试类型：边界 / 异常
- 优先级：P0
- 测试目标：验证数量上限由最新系统数据决定。
- 前置条件：销售数量 10，已有有效采购覆盖 4。
- 测试数据：本次分别输入 0、6、6.000001、7。
- 操作步骤：
  1. 依次提交各边界值并在每次前重置到相同数据。
- 预期结果：0 和超过 6 的数量被拒绝；6 成功且剩余变为 0。
- 校验点：累计有效覆盖永不超过 10；错误提示包含刷新或调整数量的下一步。
- 备注 / 待确认问题：无。

### TC-PO-004：两个会话并发创建不会超采

- 用例编号：TC-PO-004
- 所属模块：采购单创建
- 需求来源：PRD §3.4、§5.8
- 测试类型：并发 / 数据一致性
- 优先级：P0
- 测试目标：验证两个会话基于同一剩余数量同时创建时只有合法组合成功。
- 前置条件：剩余数量 6。
- 测试数据：会话 1 和会话 2 均提交数量 6。
- 操作步骤：
  1. 并发发送两次创建请求。
  2. 查询采购单、草稿行和剩余数量。
- 预期结果：最多一个请求成功；另一个收到“可采购数量已更新，请刷新后重试”。
- 校验点：累计占用为 6，不产生孤立头/行/审批绑定。
- 备注 / 待确认问题：主要由数据库集成测试覆盖。

### TC-PO-006：采购作废或生效减量后释放数量并恢复任务

- 用例编号：TC-PO-006
- 所属模块：剩余数量与任务恢复
- 需求来源：PRD §3.3、§3.4、§5.10
- 测试类型：状态流转 / 数据一致性
- 优先级：P0

### TC-TASK-005：管理员转交只影响剩余责任范围
