# 性能与稳定性测试用例

### TC-PERF-001：大量销售明细的责任预览稳定完成

- 用例编号：TC-PERF-001
- 所属模块：责任解析
- 需求来源：PRD §3.1、§3.2
- 测试类型：性能 / 稳定性
- 优先级：P1
- 测试目标：验证责任解析不会随明细和分类层级产生不可接受的逐行查询放大。
- 前置条件：测试库含 5 层分类、1,000 条规则和 200 条销售明细。
- 测试数据：SKU、分类+区域、分类、商品类型和默认规则混合命中。
- 操作步骤：
  1. 连续执行 30 次责任预览。
  2. 记录总耗时、P95、数据库查询数和错误率。
- 预期结果：P95 不高于项目同类销售草稿详情接口基线的 2 倍；错误率为 0；查询数不随“明细数 × 规则数”线性爆炸。
- 校验点：响应包含 200 条确定结果且顺序稳定。
- 备注 / 待确认问题：绝对 SLA 以当前测试环境基线记录，不进入普通 PR 阻断门禁。

### TC-PERF-002：大批量采购创建依据分页与汇总稳定

- 用例编号：TC-PERF-002
- 所属模块：采购创建依据
- 需求来源：PRD §3.4、§3.5
- 测试类型：性能 / 大数据量
- 优先级：P1
- 测试目标：验证多销售单、多采购单下剩余数量汇总可稳定查询。
- 前置条件：1,000 张生效销售单，每单 20 行，每行存在 0–5 张采购单。
- 测试数据：混合采购状态、作废和减量结果。
- 操作步骤：
  1. 以采购账号查询本人可建单依据前 50 条。
  2. 翻页并按销售单号筛选。
- 预期结果：首屏和翻页无超时，剩余数量正确；数据库不执行无索引全量扫描。
- 校验点：解释计划命中责任范围、销售单状态和采购来源行索引。
- 备注 / 待确认问题：索引解释在集成环境执行。

### TC-PERF-003：并发创建保持数量上限和数据完整

- 用例编号：TC-PERF-003
- 所属模块：采购创建
- 需求来源：PRD §3.4
- 测试类型：性能 / 并发 / 稳定性
- 优先级：P0
- 测试目标：验证并发压力下不会超采或形成孤立数据。
- 前置条件：同一销售行剩余 100，准备 20 个并发请求，每次申请 10。
- 测试数据：相同责任范围和合格供给。
- 操作步骤：
  1. 同时发起 20 个创建请求。
  2. 汇总成功、冲突和失败请求。
- 预期结果：成功覆盖总量不超过 100；其余请求收到明确冲突；所有成功采购单均有完整头、提交和行。
- 校验点：累计数量、集合一致性、任务状态和错误率。
- 备注 / 待确认问题：在隔离测试库执行，不进入浏览器 E2E。

### TC-PERF-004：重复进度查询不产生状态漂移

- 用例编号：TC-PERF-004
- 所属模块：采购进度
- 需求来源：PRD §3.5
- 测试类型：稳定性
- 优先级：P2
- 测试目标：验证持续查询销售详情、任务和创建依据不会修改业务状态或造成不一致。
- 前置条件：存在部分采购销售单。
- 测试数据：连续 500 次交错查询。
- 操作步骤：
  1. 并发查询三个读取入口。
  2. 前后比较数据库业务数据。
- 预期结果：读取结果口径一致；没有额外任务、采购单或版本变化。
- 校验点：业务集合数量和版本保持不变。
- 备注 / 待确认问题：无。
