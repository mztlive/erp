## 测试策略

1. 领域纯规则使用 Rust 单元测试覆盖：规则优先级、唯一命中、剩余数量、状态覆盖和任务完成判断。
2. 涉及 MongoDB 多集合一致性、权限、并发和任务副作用的路径使用服务层或 API 集成测试。
3. 前端派生状态、责任展示、按钮可见性和数量输入边界使用前端单元测试。
4. P0 用户主路径使用真实 Playwright 端到端测试：登录、销售提交、审批生效、采购收到任务、分两次建立采购单、进度与任务完成一致。
5. 浏览器端到端测试不得 mock 应用接口；测试数据通过现有重置脚本、真实 API 或管理页面准备。
6. 所有“已覆盖”“已执行通过”结论必须能定位到具体测试资产、测试名和核心断言。

## 覆盖维度

- 正向：规则命中、生效派发、部分采购、继续建单、全部覆盖。
- 反向：无规则、规则冲突、无权限账号、无合格供给、超出剩余数量。
- 边界：零剩余、分批最后一笔、小数数量、父分类回退、默认调度人。
- 权限：规则管理、采购创建、跨责任范围、管理员转交。
- 并发与幂等：重复生效、重复创建、两个会话抢占相同剩余数量。
- 数据一致性：销售进度、创建依据、采购任务三处口径一致；作废/减量后恢复。
- 安全：未登录、越权、NoSQL 注入形态、内部字段不上屏、审计记录。
- 性能：批量规则解析、销售单大量明细、创建依据列表和并发创建。
