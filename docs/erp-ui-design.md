# ERP 页面布局与交互设计

> **状态**：设计草案（供复核）  
> **依据**：`erp-phase-1.md`、`erp-phase-2.md` 的业务能力；`erp-client` 现有主题 token 与 `components/business` 页面模式  
> **不依据**：历史页面地图 / 交互规范的版面拆法、路由清单或「一单据一列表一详情」拆页习惯  
> **实现约束**：纯 SPA；TanStack Query / Form；业务组件只接收已授权、已计算的展示数据

本文回答三件事：

1. 用户**在哪里**完成工作（信息架构与工作台）  
2. 页面**长什么样**（布局骨架、视觉密度、主题用法）  
3. 完成一件业务时**怎么操作**（连续交互，而不是跨多页拼流程）

---

## 1. 设计目标与原则

### 1.1 目标

| 目标 | 含义 |
| --- | --- |
| **现代** | 清晰层级、克制装饰、企业标准蓝体系；状态靠文字 + 图标 + 色相同时表达 |
| **美观** | 白底内容面 + 深海军导航拉开层次；金额/数量等宽对齐；表格与单据有「账本感」但不压抑 |
| **高效率** | 键盘可达、批量连续处理、少跳转、默认落到「待我处理」而非空列表 |
| **不割裂** | 一次完整业务在同一工作面内完成；关联对象以内嵌区/侧栏/任务页签呈现，不强迫用户记忆路径 |

### 1.2 反模式（明确禁止）

以下交互视为低效、割裂，设计与评审时直接否决：

1. **为完成一步去三四个菜单**：例如「开销售单 → 回列表找单 → 进详情 → 再进变更页 → 再进审批页」。  
2. **编辑与查看拆成两个无上下文路由**：草稿编辑必须可从单据本身进入，不能「列表编辑按钮跳到另一套 URL」。  
3. **核销/分摊拆成向导式多页**：回款登记与核销、付款登记与核销必须同屏或同任务页签内闭环。  
4. **待办只给链接**：待办必须能**在队列内处理完当前项并自动进下一项**，而不是点开详情后迷路。  
5. **关联单据只给外链列表**：销售单上的采购、入库、出库、票款必须在单据中心可见进度与入口。  
6. **状态只靠色点**：禁止无文字的红黄绿圆点；与 `StatusBadge` 契约一致。

### 1.3 正向原则

| 原则 | 落地方式 |
| --- | --- |
| **对象中心，而非表单中心** | 以客户、销售单、采购单、往来主体为枢纽；表单是枢纽上的模式，不是独立世界 |
| **任务队列优先** | 采购二次确认、财务审核、票款复核、审批、接口异常 → 队列工作台 + 连续处理条 |
| **一层深入，两层内完成** | 列表/队列 → 预览或全屏工作区；第三层只用浮层（Sheet/Dialog），不再套列表 |
| **正式动作可逆感低，确认感高** | 提交/生效/作废/冲正：确认对话框 + 影响预览 + 固定结果面板，不只靠 toast |
| **读多写少的台账不伪装成单据** | 应收、库存、经营质量：只读派生，提供钻取，不提供「编辑台账」 |
| **权限表达为可用性，而非藏菜单** | 无权限动作可见但禁用并说明原因（`GuardedBusinessAction`）；避免用户猜「功能丢了」 |

### 1.4 与业务文档的关系

- 业务边界、状态机、金额口径、部门职责以 phase 文档为准。  
- 本文只定义**呈现与操作路径**，不改状态机、不发明业务单据。  
- 第一期 / 第二期能力在同一壳与同一销售单中心上**分期启用区块**，不为二期另做一套 UI 语言。

## 2. 视觉体系（对齐现有主题）

实现必须以 `erp-client/app/globals.css` 的语义 token 为准，业务组件**不接受任意颜色/任意像素尺寸 props**。

### 2.1 色彩角色

| 角色 | Token / 观感 | 用法 |
| --- | --- | --- |
| 画布 | `--background` 冷灰白 | 页面底层 |
| 内容面 | `--card` 纯白 | 列表卡片、单据主体、对话框 |
| 主色 | `--primary` `#1c65d4` | **唯一**页面级主动作、选中强调 |
| 轻强调 | `--accent` 浅蓝 | 行选中、菜单 hover 高亮（不抢主按钮） |
| 导航 | `--sidebar` 深海军 | 左侧导航；浅色模式下也保持深色 |
| 成功/警告/信息/危险 | `success` / `warning` / `info` / `destructive` 四槽位 | 状态徽章、Alert、进度 |
| 表格 | `table-header` / `row-hover` / `row-selected` / `grid` | 高密度账表 |

深色模式：蓝灰底非纯黑；主色改为浅蓝填充 + 深字，保证链接与按钮对比度。

### 2.2 尺寸密度

| Token | 值 | 用途 |
| --- | --- | --- |
| `topbar` | 48px | 全局顶栏 |
| `tabs` | 36px | 内部任务页签 |
| `row` | 36px | 标准列表行（默认密度） |
| `row-comfortable` | 44px | 多行复合单元格 |
| `nav` / `nav-icon` | 208px / 64px | 侧栏展开 / 折叠 |
| `preview` | 400px | 右侧快速预览 Sheet |
| `shell` | 1440px | 基准工作宽度（内容区可更宽，分析页可全宽） |
| 圆角 | `--radius` 4px 基线 | 单据系统严谨感，避免大圆角消费级风格 |

### 2.3 字体与数字

- 正文：系统无衬线；标题 `font-heading`。  
- 金额、数量、税率、单号：`num` 工具类（等宽数字 + 斜杠零），表格金额列右对齐。  
- 含税 / 不含税指标**不得混在同一加减式**；标签在指标旁明示口径（二期经营分析尤其强制）。

### 2.4 视觉气质（验收用语）

- **像专业账本，不像营销后台**：少插画、少渐变、少大卡片堆叠。  
- **一层纸、一条线**：主内容一张白卡压在浅灰画布上；分隔用 `border` / `grid`，少重阴影。  
- **一个主动作**：顶栏或单据头只有一个实心 primary；其余 ghost / outline / secondary。  
- **状态一眼可读**：主状态 + 多轨进度（履约 / 回款 / 开票）并排，不挤成一颗色点。

## 3. 应用壳布局

### 3.1 总骨架

```
┌──────────────────────────────────────────────────────────────────┐
│ GlobalTopbar  48px   [≡] 全局搜索 ⌘K   待办角标  用户/环境        │
├────────────┬─────────────────────────────────────────────────────┤
│            │ TaskTabs  36px   [工作台] [SO-… ✕] [核销:客户A ✕] … │
│  Sidebar   ├─────────────────────────────────────────────────────┤
│  208/64    │                                                     │
│            │  当前任务内容区（滚动容器）                           │
│  模块导航  │                                                     │
│  角色折叠  │                                                     │
│            │                                                     │
├────────────┴─────────────────────────────────────────────────────┤
│ MaintenanceBanner（仅维护窗口 / 主责迁移冻结时）                    │
└──────────────────────────────────────────────────────────────────┘
```

组件：`ErpAppShell`、`GlobalTopbar`、`TaskTabs`、`MaintenanceBanner`（`shell.tsx`）。

### 3.2 顶栏

| 区域 | 内容 |
| --- | --- |
| 左 | 侧栏开关；可选环境标签（验证 / 生产） |
| 中 | **全局搜索**：对象类型感知（客户、合同、销售单、采购单、发票号、商城单号…）；回车打开对象中心；⌘K 打开命令面板（搜页面 + 常用动作） |
| 右 | 待办总数角标（点开 = 今日工作台待办段）；通知/预警摘要；当前用户与退出 |

全局搜索**不是**全站模糊日志检索；优先稳定单号与主数据名称，结果分组展示。

### 3.3 侧栏导航（按工作面，不按物理表）

导航按「人每天打开的工作面」组织，**禁止**把每个物理单据类型平铺成 30 个一级菜单。

```
工作
  · 今日工作台
  · 待办队列（可按类型筛选；与工作台同源）

销售
  · 客户中心
  · 合同
  · 销售单（统一：卡券 + 实物服务）
  · 客户验收

采购与履约
  · 二次确认队列
  · 采购单
  · 履约作业（入库/仓发/代发/电子/服务 的统一入口）

仓储
  · 仓储作业队列
  · 库存台账

票款
  · 客户往来（应收·回款·销项发票·核销）
  · 供应商往来（应付·付款·进项发票·核销）
  · 卡券票款复核（一期重点）

主数据
  · 可销售项目
  · 商品与 SKU
  · 卡券类目
  · 供应商与资质
  · 仓库

经营
  · 客户经营质量
  · 实际经营盈亏（非卡券）
  · 卡券经营分析（二期启用）

协同与治理（二期为主，一期可只开同步监控）
  · 商城同步 / 映射差异
  · 商品发布与供给（二期）
  · 消费与供应商订单（二期）
  · 接口错误与对账中心（二期）
  · 主责迁移（二期上线窗口）

系统
  · 导入任务
  · 权限与数据范围
  · 审计查询
```

**折叠规则**：侧栏可缩到图标模式；当前模块高亮；无权限模块不展示。角色默认着陆点见第 8 章。

### 3.4 任务页签（TaskTabs）—— 解决跨页割裂的核心机制

浏览器只有一个 URL，但用户经常并行处理多张单。设计约定：

| 规则 | 说明 |
| --- | --- |
| 打开方式 | 从列表「打开」、全局搜索、待办「处理」→ **新开内部任务页签**（或聚焦已存在的同对象页签） |
| 页签身份 | 稳定对象 ID（销售单 ID、核销会话 ID），不是路由字符串临时值 |
| 页签标题 | `类型缩写 + 单号/名称`，如 `SO · XS2026…`、`核销 · 客户甲` |
| 脏状态 | 草稿/未保存显示圆点；关闭时确认 |
| 与浏览器后退 | 任务内二级状态（预览开合、子 Tab）优先用页内状态；对象切换用页签，避免后退把表单冲掉 |
| 上限 | 建议软上限 12；超出提示关闭最少使用的页签 |

**原则**：关联单据默认在**当前页签内**用子区域打开；只有用户明确「在新任务中打开」时才新开页签。

### 3.5 响应式

| 宽度 | 行为 |
| --- | --- |
| ≥1280 | 侧栏展开 + 列表可选右侧预览 |
| 1024–1279 | 侧栏可折叠；预览改为覆盖式 Sheet |
| <1024 | 侧栏抽屉；表格横向滚动；连续处理队列仍全宽优先 |

本产品主场景是桌面办公；移动端保证待办查看与简单确认，不把复杂核销作为手机主路径。

## 4. 通用页面模式

不按「108 个页面」设计 108 套布局。所有功能归入下列 **7 种模式**。新功能先选模式，再填业务插槽。

### 4.1 模式总览

| 模式 | 代号 | 适用 | 主组件 |
| --- | --- | --- | --- |
| 角色工作台 | M1 | 今日工作台、经营首页 | `PageHeader` `MetricStrip` `WorkTaskItem` |
| 高密度查询列表 | M2 | 单据列表、台账、同步批次 | `ListToolbar` `DataTable` `BusinessTableFrame` `QuickPreviewSheet` |
| 连续处理队列 | M3 | 二次确认、审批、复核、异常 | `SequentialProcessBar` `WorkTaskItem` |
| 对象中心（单据枢纽） | M4 | 销售单、采购单、客户、供应商 | `DocumentHeader` `DocumentSection` `RelatedDocumentList` … |
| 编辑工作区 | M5 | 建单/改单、行项目、分摊核销 | `EditableLineItemTable` `AllocationWorkspace` |
| 只读分析 | M6 | 经营质量、盈亏、卡券分析 | `MetricStrip` 图表 + 下钻表 |
| 治理与导入 | M7 | 映射差异、导入、错误中心 | `ImportStageIndicator` `BusinessDiffPanel` `InterfaceErrorResolutionPanel` |

### 4.2 M1 角色工作台

```
┌ PageHeader：早上好，{姓名} · {角色摘要}          [刷新] [数据水位]
├ MetricStrip：待我处理 | 今日到期 | 超期 | 同步异常 …
├ 主区两栏（可拖拽宽度）
│  ├ 左 60%：待办分组列表（按类型折叠）
│  │    每项：标题、对象引用、截止/滞留、主操作「处理」
│  └ 右 40%：预警与系统消息 / 最近打开的任务页签
└ 底部：可选「我的草稿」横滑条
```

交互要点：

- **处理** → 进入 M3 队列或直接打开 M4/M5，并带上队列上下文（下一项 ID）。  
- 指标可点：过滤待办，不跳到无关列表空页。  
- 数据水位：`DataFreshness` 标明工作台异步刷新（≤1 分钟）与台账同步域的区别。

### 4.3 M2 高密度查询列表

```
┌ PageHeader + 主新建动作
├ ListToolbar：SavedView | 搜索 | 常驻筛 | 高级筛 | 列设置 | 导出
├ SelectionScopeBar（有多选时）
├ StatusMatrix（可选：状态分布一键过滤）
├ BusinessTableFrame
│   └ DataTable（服务端分页/排序/筛；稳定 rowId）
└ QuickPreviewSheet（右侧 400px，单击行打开）
```

交互要点：

| 操作 | 行为 |
| --- | --- |
| 单击行空白 | 打开快速预览（不离开列表） |
| Enter / 「打开」 | 对象中心进任务页签 |
| 行内主按钮 | 场景动作（如「去确认」）直接进队列，不先开只读详情 |
| 多选 + 批量 | 必须 `BatchImpactPreview`；「当前筛选全部」调服务端冻结快照 |
| 刷新中 | 保留旧行 + 轻量指示；失败用 `BusinessFailureState`，不整表闪空白 |

预览 Sheet 内容：关键字段、多轨状态、最近动态、**有权限的主操作**。预览内可完成的轻操作：通过/驳回入口、复制单号、打开中心。重编辑不在预览里做。

### 4.4 M3 连续处理队列（高效率核心）

用于：采购二次确认、采购单财务审核、卡券票款复核、销售领导/运营审批、接口错误处理。

```
┌ SequentialProcessBar
│  第 3/28  · 过滤器摘要  · [上一项] [下一项]  · 可选「通过后自动下一项」
├ 当前对象只读摘要（或可编辑确认表单区）
├ 决策区：通过 / 驳回（驳回必填原因） / 暂挂
└ 侧栏或折叠：历史记录、附件、关联差异
```

交互要点：

- 进入队列时默认 **「通过后自动下一项」开启**（本地偏好可记）。  
- 驳回后也自动下一项；暂挂留在队列但跳过。  
- 用户**无需**返回列表找下一条。  
- 完成队列：明确空态「本筛选项已处理完」+ 返回工作台。  
- 与 M4 的关系：队列是「处理模式」；需要深挖时「在中心打开」新开页签，**队列上下文不丢**（页签仍在）。

### 4.5 M4 对象中心（单据枢纽）

一张销售单 = 一次客户业务的**单一事实入口**。采购、履约、票款、变更都从这里看见全貌。

```
┌ DocumentHeader
│  标题 · 单号 · 主状态 · 版本
│  多轨：履约 | 回款 | 开票（StatusTrackSummary）
│  主操作（按 allowedActions）· 更多
├ 可选：CostCoverageNotice / PrepaymentGate / 主责系统只读标签
├ 锚点子导航（横向 sticky）
│  概览 | 明细 | 履约 | 票款 | 变更与异常 | 协同（二期）| 审计
├ 内容区 DocumentSection × N
└ 底栏（编辑态）：DraftSaveIndicator · 校验摘要 · 提交
```

**概览**：`DocumentSummary` + 客户/合同引用 + 责任人 + 关键日期。  
**明细**：卡券用 `CardVoucherLineItem`（唯一明细）；实物服务用行表。  
**履约**：时间线式责任段（`ResponsibilityPanel` + `RelatedDocumentList`），展示已产生单据与「去开单」入口（权限内）。  
**票款**：应收余额、已收、已开票；内嵌登记回款/开票入口（进入 M5 核销会话，返回仍在本页签）。  
**变更与异常**：变更单、退货、冲正列表 + 创建入口。  
**协同（二期）**：执行投影状态、商城接收、消费汇总入口。  
**审计**：`AuditTimeline` 追加式，字段 diff 用 `BusinessDiffPanel`。

**只读 vs 编辑**：

- 主责在商城的卡券单：商业字段只读，映射与票款可写（一期）。  
- 草稿 / 驳回可改：中心顶部切换「编辑」，同一路由同一页签，不跳 `/edit`。  
- 已生效字段锁定；变更走变更单流程（在「变更」子区发起）。

### 4.6 M5 编辑工作区

#### 4.6.1 建单 / 改单

- 全宽任务页签；左侧表头字段，下方 `EditableLineItemTable`。  
- 选客户、合同、可销售项目：一律 `BusinessObjectCombobox`（只出有效对象）。  
- 行内即时前端校验 + 提交前 `ValidationSummary`。  
- 自动草稿保存（防抖）+ 显式「保存草稿」；`EditorPresence` 提示他人占用。  
- 提交：`FormalActionConfirmDialog` → mutation → `FormalActionResult`（含单号、下步建议）。

#### 4.6.2 分摊 / 核销（AllocationWorkspace）

同一屏幕完成「登记资金事实 + 核销到单据」，禁止：

1. 页 A 只登记回款金额  
2. 页 B 再做核销  

推荐布局：

```
┌ 往来主体头：客户/供应商 · 本次金额 · 方向
├ 左：待核销池（应收/应付列表，可多选）
├ 右：已分配明细（可改金额）
├ 底：未分配余额（必须为 0 才允许正式提交，或允许「暂挂未分配」若业务许可——以财务规则为准）
└ 提交确认
```

发票与回款/付款**分轨核销**（业务已规定分别记录）；UI 用 Tab 区分「回款核销」「发票核销」，共享往来主体上下文。

### 4.7 M6 只读分析

- 顶：`MetricStrip` + 口径说明 + 期间选择。  
- 中：构成图（chart token）+ 明细表下钻到 M4。  
- 卡券相关：强制展示票款复核进度或成本覆盖率；未覆盖不得暗示「零成本暴利」。  
- 刷新：异步水位提示。

### 4.8 M7 治理与导入

- 分阶段：`ImportStageIndicator`（上传 → 校验 → 试算 → 提交）。  
- 问题行：`ImportIssueTable` 可筛选错误码；不把成功行和失败行混成无法扫读的长表。  
- 映射差异：左右 diff + 指派责任部门动作。  
- 接口错误：`InterfaceErrorResolutionPanel`（重试 / 查询 / 转人工 / 关闭）在**同一详情**完成，不拆「错误列表页 + 另一套处理页」。

## 5. 第一期核心业务：连续路径设计

下列每条路径给出「用户目标 → 工作面 → 不做什么」。

### 5.1 销售：从意向到销售单生效

| 步骤 | 用户动作 | 界面 |
| --- | --- | --- |
| 1 | 在客户中心确认客户与合同 | M4 客户；合同可在侧栏新建（简单）或任务页签 |
| 2 | 新建实物与服务销售单 | M5；从可销售项目池选品 |
| 3 | 保存草稿 / 提交二次确认 | 同页正式动作 |
| 4 | （采购）处理二次确认 | **M3 队列**，不是邮件式链接散落 |
| 5 | 通过后销售单生效 | 结果回写；销售在中心看到状态与后续采购单 |

卡券销售单（一期）：列表与中心**与实物单统一入口**，用业务性质标签 + 主责系统标签区分；中心商业字段只读，提供「映射客户/合同/类目」「查看同步版本」「票款」能力。

### 5.2 采购：二次确认 → 采购单 → 财务审核

```
二次确认队列(M3)
  → 通过：系统生成待编采购单任务
  → 采购在「采购单」M5 按供应商拆单编辑提交
  → 财务审核队列(M3)
  → 通过：形成应付；若先款后货，票款侧提示付款闸门(PrepaymentGate)
```

采购单对象中心（M4）内嵌：付款记录、进项发票、关联销售单、履约单据。  
**禁止**用户为了「看这张采购单付过多少」去三个菜单。

### 5.3 履约：统一「履约作业」而非五张孤岛列表

侧栏一个 **履约作业** 入口（M2/M3 混合）：

- 默认视图 = 待我执行的任务（入库 / 仓发 / 代发 / 电子 / 服务）。  
- 类型用 Segmented 过滤，**不是**五个平级菜单。  
- 处理时打开轻量作业单（M5 简化版）：带出销售/采购上下文、数量、仓库；提交后回到队列下一项。  
- 需要追溯时从销售单中心「履约」子区进入同一单据。

仓储库存调整：从库存台账选 SKU → Sheet 内建调整单 → 复核人队列；简单调整不强制整页跳转。

### 5.4 验收

销售在销售单中心「履约」子区 **登记验收**（按明细）；短少/拒收直接分支到异常处理单创建（同页引导），避免「先去验收菜单找销售单」。

### 5.5 票款：客户往来工作台

**客户往来** 是财务主战场（M2 + M5），不是「回款列表 / 发票列表 / 核销列表」三张皮。

```
客户往来
├ 视图切换：应收台账 | 回款 | 销项发票 | 待核销
├ 选中客户后：右侧或下钻「客户票款会话」
│   ├ 应收明细
│   ├ 登记回款 → 同屏核销
│   └ 登记发票 → 同屏核销
└ 卡券票款复核队列（一期）：M3，逐单补已收/已开票事实
```

供应商往来对称设计。

### 5.6 变更与纠错

从**原单中心**发起变更/退货/冲正；创建后的处理单仍挂在原单「变更与异常」下。  
列表可有全局「异常处理」过滤视图，但是**创建入口在原单**，保证上下文。

### 5.7 商城同步与映射（一期）

- 系统管理员：**同步监控**（任务水位、失败、补拉）+ **映射差异队列**（M3/M7）。  
- 销售/运营：在卡券销售单中心处理**指派给自己的**映射差异，不必进运维菜单。  
- 差异未解除前，中心与应收明确「未进入经营归属」提示。

## 11. 状态、空态、失败、并发

| 场景 | 表现 |
| --- | --- |
| 初载 | Skeleton，结构与成稿一致 |
| 刷新 | 保留旧数据 + 顶部/表格轻指示（`AsyncSectionState`） |
| 空列表 | `BusinessEmptyState`：说明原因 + 一个正确下一步 |
| 失败 | `BusinessFailureState`：可重试；不清空已有缓存数据除非致命 |
| 校验失败 | `ValidationSummary` 置顶 + 字段级错误 |

## 附录 A · 与旧思路的切割说明

本设计**有意不做**的事：

1. 不为每个单据类型强制「列表页 + 详情页 + 编辑页 + 审批页」四路由。
