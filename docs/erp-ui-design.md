# ERP 页面布局与交互设计

> **依据**：`erp-phase-1.md`、`erp-phase-2.md` 的业务能力；`erp-client` 现有主题 token 与 `components/business` 页面模式  
> **不依据**：历史页面地图 / 交互规范的版面拆法、路由清单或「一单据一列表一详情」拆页习惯  
> **实现约束**：纯 SPA；TanStack Query / Form；业务组件只接收已授权、已计算的展示数据  
> **样板对照**：`erp-client` 的 `/workspace`（M1 主从工作台）、`/sales/orders`（M2）与销售单中心（M4）；三页共同验证应用壳、密度、响应式、正式动作与连续处理语言。

本文回答三件事：

1. 用户**在哪里**完成工作（信息架构与工作台）  
2. 页面**长什么样**（布局骨架、视觉密度、主题用法）  
3. 完成一件业务时**怎么操作**（连续交互，而不是跨多页拼流程）

---

## 1. 设计目标与原则

### 1.1 目标

| 目标 | 含义 |
| --- | --- |
| **现代** | 清晰层级、克制装饰、shadcn Neutral 黑白表面；状态靠文字 + 图标 + 色相同时表达 |
| **美观** | 深色侧栏 + 浅灰画布 + 发丝边框白卡片；金额/数量等宽对齐；表格与单据有「账本感」但不压抑 |
| **高效率** | 键盘可达、批量连续处理、少跳转、默认落到「待我处理」而非空列表 |
| **不割裂** | 一次完整业务在同一工作面内完成；关联对象以内嵌区/侧栏/任务页签呈现，不强迫用户记忆路径 |

### 1.2 反模式（明确禁止）

以下交互视为低效、割裂，设计与实现必须否决，禁止落地：

1. **为完成一步去三四个菜单**：例如「开销售单 → 回列表找单 → 进详情 → 再进变更页 → 再进审批页」。  
2. **编辑与查看拆成两个无上下文路由**：草稿编辑必须可从单据本身进入，不能「列表编辑按钮跳到另一套 URL」。  
3. **核销/分摊拆成向导式多页**：回款登记与核销、付款登记与核销必须同屏或同任务页签内闭环。  
4. **待办只给链接**：待办必须能**在队列内处理完当前项并自动进下一项**，而不是点开详情后迷路。  
5. **关联单据只给外链列表**：销售单上的采购、入库、出库、票款必须在单据中心可见进度与入口。  
6. **状态只靠色点**：禁止无文字的红黄绿圆点；与 `StatusBadge` 契约一致。  
7. **列表预览只有摘要、必须再点「打开中心」才能看完主事实**：核对须在列表内读完主事实（半屏 detail **或** 轻量纸质投影，见 §4.3.1 / §4.3.2）；中心留给作业。  
8. **把完整纸质单据硬塞进 400px 窄预览**：纸质投影用透明宽层 + `PaperDocument`，不套厚 Dialog 壳。

### 1.3 正向原则

| 原则 | 落地方式 |
| --- | --- |
| **对象中心，而非表单中心** | 以客户、销售单、采购单、往来主体为枢纽；表单是枢纽上的模式，不是独立世界 |
| **任务队列优先** | 单据审批、票款复核、接口异常 → W01 列表 + 详情主从，页内连续处理 |
| **一层深入，两层内完成** | 列表/队列 → 半屏详情预览或全屏工作区；第三层只用浮层（Sheet/Dialog），不再套列表 |
| **列表内先读完主事实** | 单据类列表默认半屏 detail **或** 行点 `PaperDocument` 轻量纸质层（W05 已用后者）；进度/明细/金额须可读完，不强迫进中心 |
| **正式动作可逆感低，确认感高** | 提交/生效/作废/冲正：确认对话框 + 影响预览 + 固定结果面板，不只靠 toast |
| **读多写少的台账不伪装成单据** | 应收、库存、经营质量：只读派生，提供钻取，不提供「编辑台账」 |
| **权限表达必须区分层级** | 无模块权限：入口不展示；对象状态暂不可用：动作可见但禁用并说明原因；数据范围为空：展示专用空态。禁止把四种情况都做成灰按钮或空白页 |
| **必须使用现有主题与业务组件** | 颜色/尺寸只用 `globals.css` 语义 token；页面模式优先 `components/business`，禁止业务页自造色板与平行组件库 |

### 1.4 与业务文档的关系

- 业务边界、状态机、金额口径、部门职责以 phase 文档为准。  
- 本文只定义**呈现与操作路径**，不改状态机、不发明业务单据。  
- 第一期 / 第二期只描述**业务能力可用时间与开关状态**，不作为 UI 实施裁剪或另起一套交互语言的依据；界面骨架、模式和组件按本文完整建设。

## 2. 视觉体系（对齐现有主题）

实现必须以 `erp-client/app/globals.css` 的语义 token 为准，业务组件**不接受任意颜色/任意像素尺寸 props**。

### 2.1 色彩角色

| 角色 | Token / 观感 | 用法 |
| --- | --- | --- |
| 画布 | `--background` 浅灰 | 整页底层；明确沉于白卡片一档 |
| 内容面 | `--card` 纯白 | 列表主体、对话框；靠发丝 `border` 分层，不靠灰底托卡 |
| 主色 | `--primary` 近黑 | **唯一**页面级主动作（按钮、Logo） |
| 轻强调 | `--accent` 浅灰 | 菜单选中、行悬停 |
| 导航 | `--sidebar` 近黑 | 对齐登录页品牌舞台；选中项 = 深灰底 + 近白字 + 左侧近白竖标 |
| 成功/警告/信息/危险 | `#389e0d` / `#d48806` / `#1677ff` / `#ff4d4f` 及 soft 槽 | 状态徽章、Alert、进度；**不当页面主色** |
| 表格 | `table-header` / `row-hover` / `row-selected` / `grid` | 高密度账表；选中行为中性灰，不用蓝色 |

深色模式：对齐 shadcn Neutral dark（近黑底 + 浅色主按钮 + 同系状态色）。

### 2.2 尺寸密度

| Token | 值 | 用途 |
| --- | --- | --- |
| `topbar` | 48px | 全局顶栏 |
| `tabs` | 36px | 内部任务页签 |
| `row` | 36px | 紧凑列表行（`DataTable density="compact"`） |
| `row-comfortable` | 56px | DataTable 默认行高（公司商品池 / 多行复合单元格） |
| `nav` / `nav-icon` | 240px / 64px | 侧栏固定宽度 /（已不再折叠，icon 宽度仅兼容 token） |
| `preview` | 400px（`25rem`） | 右侧**轻量**预览 Sheet：筛选、轻摘要、少量字段 |
| `detail` | 768px（`48rem`，且 ≤92vw） | 右侧**半屏详情**抽屉：列表内读完主事实（方案 A） |
| `shell` | 1440px | 基准工作宽度（内容区可更宽，分析页可全宽） |
| 圆角 | `--radius` 6px 基线 | 保持单据系统的严谨感 |

Sheet 尺寸对应 `components/ui/sheet` 的 `size="preview" | "detail"`；`QuickPreviewSheet` 同步暴露 `size`。

### 2.3 字体与数字

- 正文：系统无衬线；标题 `font-heading`。  
- 金额、数量、税率、单号：`num` 工具类（等宽数字 + 斜杠零），表格金额列右对齐。  
- 含税 / 不含税指标**不得混在同一加减式**；标签在指标旁明示口径（二期经营分析尤其强制）。

### 2.4 视觉气质（验收用语）

- **像专业账本，不像营销后台**：少插画、少渐变、少大卡片堆叠。  
- **一层纸、一条线**：白画布与白卡同色，靠 `border` / `grid` 发丝线分层，少重阴影。  
- **内容区表面收敛**：页头贴画布；主工作面 1～2 张浮起表面（`surfacePanelClassName`，约 6px 圆角）；禁止页内叠多层 `rounded-2xl` 便签式线框。  
- **一个主动作**：顶栏或单据头只有一个实心 primary；其余 ghost / outline / secondary。  
- **状态一眼可读**：主状态 + 多轨进度（履约 / 回款 / 开票）并排，不挤成一颗色点。

### 2.5 浮动画布内容区固定模式（Floating Canvas Content）

壳层已是「深色侧栏 + 浅灰画布 + 发丝边框白卡片」。业务页必须遵守下列固定模式，**禁止**各 feature 自造 padding / 重描边 / 多层 `rounded-2xl` 便签。

样板页（已落地）：`/workspace`、`/sales/orders`、`/sales/orders/[id]`。`/procurement/confirm` 已废止。

#### 2.5.1 脚手架

| 规则 | 实现 |
| --- | --- |
| 唯一内容外框 | 使用 `PageScaffold`（`default` 或列表 `density="compact"`） |
| 禁止 | 手写 `mx-auto max-w-shell flex-col gap-? p-?` 平行布局 |
| 骨架/错误态 | 同样包在 `PageScaffold` 内，圆角用 `rounded-lg` 而非 `rounded-2xl` |

```tsx
import { PageHeader, PageScaffold, surfacePanelClassName } from "@/components/business"

return (
  <PageScaffold>{/* or density="compact" for dense M2 lists */}
    <PageHeader title="…" actions={…} />
    {/* 1～2 张主表面 */}
  </PageScaffold>
)
```

#### 2.5.2 表面层级（最多两层重表面）

```
[画布 background]
  PageHeader / object-chrome     ← 贴画布，无底、无框
  MetricStrip / 处理条 / 分段切换  ← 轻控件，不另开厚卡（M1 工作台不用 MetricStrip，口径数字贴画布）
  主工作面 1～2 张                ← surfacePanelClassName
```

| Token / 类 | 用法 |
| --- | --- |
| `surfacePanelClassName` | 列表卡、任务卡、对象身份卡、正文 Tabs 外壳：`rounded-lg border border-border bg-card shadow-sm` |
| `surfaceInsetClassName` | 卡内轻提示：仅 `bg-muted/40`，**无描边** |
| `BusinessTableFrame` | 工具条贴画布；表格独立圆角描边；分页在表外。勿再外包 Card |
| `DocumentHeader` | 已内置身份浮卡；M4 不要再叠 `border-b` 裸头 |
| `MetricStrip` | 各指标独立轻卡（非拼缝网格） |

**禁止**：页内叠多层 `rounded-2xl border border-border bg-card` 便签条；用 inset 或主卡内 `border-b border-border/30` 分区。

#### 2.5.3 边框与分割线

| 元素 | 规则 |
| --- | --- |
| 浮卡外轮廓 | 发丝 `border-border` + 轻 `shadow-sm`；画布与卡片同为白底，靠线条分层 |
| 分割线 `Separator` | 全局已为 `bg-border/40`；表内可再 `/30` |
| 卡头底边 | `border-b border-border/30` |
| 表行 | 数据行用 `border-grid`；表头 `border-border/30` |

#### 2.5.4 控件层级（可点且不重）

| 角色 | 推荐 | 避免 |
| --- | --- | --- |
| 页级唯一主动作 | `default`（solid primary） | 多个 solid |
| 空态/卡内次要入口 | `secondary` 浅底 chip（`rounded-lg shadow-none`） | 一排 outline；纯 ghost 文案（易像不可点） |
| 工具刷新、次级文字操作 | `ghost` + 图标，可用 `text-muted-foreground` | 与主切换同级的 outline |
| 二选一/三选一范围 | **分段轨道**：灰底 track + 选中白底阴影 + 未选中弱字色 + 可选图标 | 整组 outline Toggle；无选中对比的 muted 条 |
| 顶栏搜索/角标 | 轻 outline（`border-border/40`） | 厚 `border-border` |

分段切换参考实现（工作台类型页签「全部 / 审批 / 履约 / 财务」）：

```tsx
<div role="group" aria-label="…" className="inline-flex rounded-lg bg-muted p-0.5 ring-1 ring-foreground/10">
  <button type="button" aria-pressed={active}
    className={cn(
      "inline-flex h-7 items-center gap-1.5 rounded-md px-2.5 text-sm transition-all",
      active
        ? "bg-card font-medium text-foreground shadow-sm ring-1 ring-foreground/10"
        : "text-muted-foreground hover:bg-foreground/5 hover:text-foreground"
    )}
  >…</button>
</div>
```

#### 2.5.5 空态嵌套

- 空态嵌在主卡内：`BusinessEmptyState` 传 `className="rounded-lg border-0 bg-transparent p-6 shadow-none ring-0"`  
- 行动区用 `secondary` chip，不用 outline 群、不用圆点分隔的纯 ghost 文字链  

#### 2.5.6 按模式骨架

| 模式 | 骨架 |
| --- | --- |
| M1 工作台 | `PageScaffold` → Header → 口径数字贴画布 → 空态贴画布 / 队列列 + 作业列（发丝分隔，无外包大卡；无独立统计卡） |
| M2 列表 | `PageScaffold` → Header → Metric → **一张** `BusinessTableFrame`（**含** `ListToolbar`，禁止 frame 外平行工具条） |
| M3 队列 | `PageScaffold` → Header → **一张 sticky 处理面**（surface：范围/类型 + `ListToolbar` + chip + 连续处理条）→ 主卡 + 侧卡 |
| M4 对象中心 | `PageScaffold` → object-chrome → `DocumentHeader` → Metric → 正文 surface（Tabs 外壳） |
| M5–M7 | 同：Header 贴画布 + 1～2 主表面；分析明细筛选项进明细 frame，期间/口径可单独成条 |

验收：1440 视口下，内容区不应出现「标题裸飘 + 三层不同圆角边框块」；分割线弱于控件边框；切换控件有明确选中块。  
筛选归属与密度细则见 `docs/ui-filter-design.md`（P10–P12、§2–§3）。

## 3. 应用壳布局

### 3.1 总骨架

```
┌──────────────────────────────────────────────────────────────────┐
│ GlobalTopbar  48px   [≡] 全局搜索 ⌘K   待办角标  用户/环境        │
├────────────┬─────────────────────────────────────────────────────┤
│            │                                                     │
│  Sidebar   │  当前页面内容区（滚动容器）                           │
│  208/64    │                                                     │
│            │                                                     │
│  模块导航  │                                                     │
│  角色折叠  │                                                     │
│            │                                                     │
├────────────┴─────────────────────────────────────────────────────┤
│ MaintenanceBanner（仅维护窗口时）                                     │
└──────────────────────────────────────────────────────────────────┘
```

组件：`ErpAppShell`、`GlobalTopbar`、`MaintenanceBanner`（`shell.tsx`）。导航靠侧栏 + URL，不使用应用内多任务页签。

### 3.2 顶栏

| 区域 | 内容 |
| --- | --- |
| 左 | 侧栏开关；可选环境标签（验证 / 生产） |
| 中 | **全局搜索**：对象类型感知（客户、合同、销售单、采购单、发票号、商城单号…）；回车打开对象中心；⌘K 打开命令面板（搜页面 + 常用动作） |
| 右 | 待办总数角标（点开 = 我的工作台）；通知/预警摘要；当前用户与退出 |

全局搜索**不是**全站模糊日志检索；优先稳定单号与基础资料名称，结果分组展示。

### 3.3 侧栏导航（按工作面，不按物理表）

导航按「人每天打开的工作面」组织，**禁止**把每个物理单据类型平铺成 30 个一级菜单。
以下分组与 `erp-client/lib/workspace-registry.ts` 的 `WORKSPACE_NAV_GROUPS` 一致（W06
客户验收在销售单内以嵌套区实现，`navHidden` 不占一级菜单）：

```
工作
  · 我的工作台

销售
  · 客户中心
  · 合同
  · 销售单（统一：卡券 + 实物服务；客户验收为销售单内嵌套区，不占一级菜单）

采购与履约
  · 二次确认
  · 采购单
  · 交付与代发（采购 lane；与仓储共用 W09 引擎）
  · 供应商供给

仓储
  · 收货与发货（入库 / 公司仓发；与采购共用 W09 引擎）
  · 库存台账

财务
  · 客户往来（应收·回款·销项发票·核销）
  · 供应商往来（应付·付款·进项发票·核销）
  · 卡券票款复核

基础资料
  · 公司商品池
  · 商品与 SKU
  · 商品分类
  · 品牌
  · 卡券类目
  · 供应商与资质
  · 仓库

分析
  · 客户经营质量
  · 实际经营盈亏（非卡券）
  · 卡券经营分析

商城与发布
  · 商品发布
  · 执行信息
  · 商城消费订单

供应商 API
  · API 连接
  · 供应商订单
  · API 结算

治理
  · 商城同步与映射
  · 导入与期初
  · 接口错误与对账
  · 历史消费回填

系统
  · 权限与审计
```

**折叠规则**：侧栏可缩到图标模式；当前模块高亮；角色默认着陆点见第 8 章。

**权限与可见性规则**：

| 情况 | 界面表达 |
| --- | --- |
| 用户没有模块权限 | 侧栏、全局命令和快捷入口均不展示该模块，直接访问 URL 返回无权限页 |
| 用户有模块权限，但当前对象状态不允许动作 | 动作保留在原位置、禁用，并用 `GuardedBusinessAction` 说明条件 |
| 能力尚未上线或功能开关关闭 | 不展示入口；不得用永久灰按钮充当路线图 |
| 用户有模块权限，但数据范围内没有记录 | 展示「当前数据范围暂无记录」空态，并提供查看范围或申请权限入口 |
| 字段级无权限 | 保留布局与字段标签，值使用 `SensitiveValue` 隐藏或掩码；不得导致列跳动 |

### 3.4 导航与 URL（无内部页签）

应用**不使用**内部多任务页签（TaskTabs）。页面切换依赖侧栏导航与浏览器 URL：

| 规则 | 说明 |
| --- | --- |
| 单页单 URL | 每个工作面/对象中心对应可复制 URL；刷新恢复当前对象与必要子区，不要求恢复临时浮层 |
| 返回路径 | 对象详情通过浏览器后退或页面内「返回列表」回到来源，不在壳层维护打开页签列表 |
| 并行处理 | 需要对照多张单时使用浏览器多标签；应用内不维护跨对象页签会话 |

草稿/未保存状态由页面自身在离开前确认；权限被收回时内容区切为无权限态，不渲染陈旧敏感值。

### 3.5 响应式

| 验收宽度 | 导航 | 主内容与详情 | 允许降级 |
| --- | --- | --- | --- |
| 1440×900（基准） | 默认展开 | 列表可开半屏 detail，列表仍保留识别上下文 | 不隐藏身份列、主状态、金额和行级主动作 |
| 1280×800 | 展开，可手动折叠 | detail 覆盖部分列表；表格可横向滚动 | 次要说明列可移入列设置 |
| 1024×768 | 默认图标模式 | detail 覆盖式；工具栏允许换行 | 可隐藏辅助指标说明，不隐藏指标值 |
| 768×1024 | 导航抽屉 | detail 改为上下分区；表格横向滚动，身份列与行级主动作固定 | 次要列默认隐藏，筛选折叠为面板 |
| 375×812 | 导航抽屉 | 只保证待办阅读、简单确认和结果查看 | 不提供复杂建单、核销、列设置和大表编辑 |

本产品主场景是桌面办公；移动端保证待办查看与简单确认，不把复杂核销作为手机主路径。

## 4. 通用页面模式

不按「108 个页面」设计 108 套布局。所有功能归入下列 **7 种模式**。新功能先选模式，再填业务插槽。

### 4.1 模式总览

| 模式 | 代号 | 适用 | 主组件 |
| --- | --- | --- | --- |
| 角色工作台 | M1 | 我的工作台 | `PageScaffold` `PageHeader` 口径数字条 + 队列/作业左右分栏 |
| 高密度查询列表 | M2 | 单据列表、台账、同步批次 | `PageScaffold` `ListToolbar` `DataTable` `BusinessTableFrame` `QuickPreviewSheet` |
| 连续处理队列 | M3 | 履约作业、票款复核、接口异常（审批已并入 W01） | `PageScaffold` `SequentialProcessBar` `WorkTaskItem` |
| 对象中心（单据枢纽） | M4 | 销售单、采购单、客户、供应商 | `PageScaffold` `PageHeader(object-chrome)` + `DocumentHeader(compact)` `DocumentSection` … |
| 编辑工作区 | M5 | 建单/改单、行项目、分摊核销 | `EditableLineItemTable` `AllocationWorkspace` |
| 只读分析 | M6 | 经营质量、盈亏、卡券分析 | `MetricStrip` 图表 + 下钻表 |
| 治理与导入 | M7 | 映射差异、导入、错误中心 | `ImportStageIndicator` `BusinessDiffPanel` `InterfaceErrorResolutionPanel` |

### 4.2 M1 角色工作台

```
┌ PageHeader：我的工作台                    [刷新] [数据更新时间]
├ 口径数字贴画布（禁止 MetricStrip 卡）：12 待我处理    2 已超期    1 受阻
├ 无任务：类型 + 搜索/排序贴画布 + 单个空态，不拆左右栏、不套大卡
├ 有任务：画布左右分栏，中间一条发丝
│    左列队列（约 20–24rem）：全部/审批/履约/财务/集成 + 搜索 + 排序 + 两行账本行
│    右列作业面：类型 kicker + 标题 + 金额 inset + 明细；决定条吸底
```

交互要点：

- 口径数字可点：过滤左列，不跳到第二个待办页；禁止用独立 `MetricStrip` 统计卡。
- 审批任务在右侧提交通过或驳回，成功后自动选中下一条。
- 非审批任务只提供「打开单据」，正式动作仍在对应业务工作面。
- 数据更新时间：页头只展示一条待办 `DataFreshness`（≤1 分钟）。
- 待办列表全页只渲染一份；窄屏详情降级为 Sheet。
- 完整页面合同见 `docs/ui-workspaces/w01-today-workspace.md`。

### 4.3 M2 高密度查询列表

```
┌ PageHeader + 主新建动作
├ MetricStrip / StatusMatrix（可选：真筛选指标，含「全部」）
├ BusinessTableFrame                          ← 唯一主表面
│   ├ title + 筛选摘要 description
│   ├ ListToolbar（卡内，禁止画布裸放）
│   │   第1层：search | 主筛≤3 | actions（计数 + 清除）
│   │   第2层：高级筛选入口 + FilterChip（有则独立次行）
│   ├ SelectionScopeBar（有多选时）
│   └ DataTable（服务端分页/排序/筛；稳定 rowId）
└ 列表内读主事实（二选一，工作面写死，禁止混用且缺一层）
    · QuickPreviewSheet size=detail（半屏业务核对）
    · 或 PaperDocument 透明宽层（账本版式核对，W05 销售单已用）
```

页级「新建 / 导出 / 列设置」优先 `PageHeader` 或 frame `headerActions`，不与主筛抢 `ListToolbar.filters`。  
密度、分层与控件选型见 `docs/ui-filter-design.md` §3。

交互要点：

| 操作 | 行为 |
| --- | --- |
| 单击行空白 | 打开列表内读主事实层（不离开列表）；形态由工作面约定（detail **或** 纸质层） |
| Enter | 默认同单击 |
| 行内「查看详情」/ 中心 / 作业按钮 | 对象中心任务页签，或直达队列 |
| 行内主按钮（如「去确认」） | 直接进 M3 队列，不先开只读中心 |
| 多选 + 批量 | 必须 `BatchImpactPreview`；「当前筛选全部」调服务端冻结快照 |
| 刷新中 | 保留旧行 + 轻量指示；失败用 `BusinessFailureState`，不整表闪空白 |

首屏效率与文案契约：

- 1440×900 基准视口中，页头、指标、工具栏和分页同时存在时，列表必须至少露出 **6–8 条有效数据行**。`DataTable` 默认使用舒适密度（56px 行高、单元格纵向 `0.75rem`），与公司商品池一致；需要挤进行数时再传 `density="compact"`（36px）。
- 身份列和行级主动作列固定；横向滚动不能让用户失去「正在看哪张单」或「下一步做什么」。
- 指标若可点击，使用按钮语义、选中态和筛选摘要；若只是展示，不使用 hover、手型或视觉选中暗示。
- 面向业务用户的文案不得出现 `PaperDocument`、`Sheet`、`M2`、服务端分页形态等实现词；统一写成「单据预览」「查看详情」「销售单列表」等任务语言。
- 工具栏所有可见控件必须可操作；未接入的能力隐藏，或明确标注不可用原因，不做无反馈的伪按钮。
- `DataTable layout="flush"` 时分页条须 `px-table-cell-inline py-2.5`，与结果卡片头和单元格对齐；只有一页时元信息收在左侧，禁止把「已全部显示」甩到最右侧。

#### 4.3.1 列表预览两档：preview 与 detail

| 档位 | 宽度 | 适用 | 正文滚动 |
| --- | --- | --- | --- |
| **preview** | `25rem` / 400px | 轻摘要、高级筛选结果瞥一眼、非单据对象 | 整区纵向滚动 |
| **detail** | `48rem` / 768px（≤92vw） | 采购单、发票等仍用半屏业务核对的正式单据 | **左右分栏，各栏独立滚动** |

**detail** 验收标准：**多数核对必须在半屏内读完主事实，不得强迫用户点「打开中心」才能看完主事实。**  
**例外（W05 销售单）**：列表默认**不**用 detail，而用 §4.3.2 的轻量纸质层作为行点读单方式；操作列文案为「查看详情」。

桌面布局（宽抽屉内，detail 档）：

```
┌ 身份 · 单号 · 版本 · 主状态 · 来源标签 ──────────────────────────┐
├─────────────────────┬────────────────────────────────────────────┤
│ 左 ~38%（独立滚）    │ 右主阅读区（独立滚）                        │
│ · 多轨进度           │ · 销售/采购明细表（可含单价、小计）          │
│ · 商务信息（紧凑）   │ · 金额与票款汇总（DocumentTotals，可贴右）  │
│ · 关联进度 chips     │                                            │
├─────────────────────┴────────────────────────────────────────────┤
│ 底栏：[关闭] [打开中心 / 查看详情]                                 │
└──────────────────────────────────────────────────────────────────┘
```

detail 预览**必须**覆盖的主事实（其它单据类推）：

- 主状态 + 履约 / 回款 / 开票（或等价多轨）  
- 表头商务字段（合同、结算主体、付款条件、履约期限、场景、负责人、备注）  
- **明细行**  
- 金额汇总（含税 / 不含税口径分离）与票款摘要  
- 关联单据数量级进度  

detail 预览**不负责**（留给对象中心或队列）：

- 行项目重编辑、提交/驳回作业流  
- 回款/付款核销会话、履约登记、变更/冲正创建  
- 完整审计时间线深挖  

**禁止**：

- 把 detail 内容做成「三五个字段 + 打开中心」，导致二次点击才能看单；  
- 在 `preview` 宽度下堆完整明细与汇总，造成多屏长卷；  
- 用窄 preview 代替 detail / 纸质层作为单据列表默认单击行为；  
- W05 再引入侧栏 Sheet 或行内「预览」「打印」按钮（与已落地交互冲突）。

#### 4.3.2 纸质投影与半屏预览的分工

| 形态 | 组件 | 容器 | 用户目标 |
| --- | --- | --- | --- |
| 半屏业务预览 | 业务面板 + `DocumentTotals` 等 | `QuickPreviewSheet` `size="detail"` | 列表内业务字段核对 |
| 轻量纸质投影 | **`PaperDocument`** `frame="bare"` | **透明宽层**（约 `sm:max-w-5xl`）：无标题栏/底栏/打印钮；角上关闭 | 账本版式阅读、双方、明细、汇总、签章位 |
| 页面内嵌纸质 | **`PaperDocument`** `frame="framed"`（默认） | 内容区浅底外框 | 对象中心或独立打印页内嵌 |

- 同一工作面的列表行点击只选 **detail 或 纸质层** 其一，禁止叠两套读单入口。  
- 纸质层金额、状态、明细**全部为服务端已确认事实**，组件不重算。  
- **默认不提供**浮层内「打印」按钮；需要系统打印时用浏览器打印或对象中心授权动作，避免演示按钮漂移成正式能力。

### 4.4 M3 连续处理队列（高效率核心）

用于：定义驱动的单据审批、卡券票款复核、接口错误处理、交付与代发 / 收货与发货（W09）。

```
┌ sticky 处理面（一张 surface 卡，禁止筛选裸飘画布）─────────────┐
│  第0层：scope / 类型或 lane 分段（可带计数）                     │
│  第1层：ListToolbar  search | 主筛≤3 | 计数 · 清除 · 自动下一项 │
│  第2层：FilterChip（来源销售单/采购单等深链锁定）               │
│  SequentialProcessBar：第 3/28 · 摘要 · [上一项] [下一项]       │
└────────────────────────────────────────────────────────────────┘
┌ 主作业区（surface）
│  当前对象只读摘要（或可编辑确认表单区）
│  决策区：通过 / 驳回（驳回必填原因） / 稍后处理
└ 侧栏或折叠：历史记录、附件、关联差异
```

队列**不**套 `BusinessTableFrame` 装任务流；与 M2 统一的是「surface + ListToolbar 槽位」，不是组件名。细则见 `docs/ui-filter-design.md` §2.3。

交互要点：

- 进入队列时默认 **「通过后自动下一项」开启**（本地偏好可记）。
- 驳回后也自动下一项；“稍后处理”只移动当前队列焦点，不改变任务状态或当前责任。
- 用户**无需**返回列表找下一条。
- 完成队列：明确空态「本筛选项已处理完」+ 返回工作台。
- 与 M4 的关系：队列是「处理模式」；需要深挖时「在中心打开」新开页签，**队列上下文不丢**（页签仍在）。
- 队列筛选参数写入 URL；当前项 ID 与自动下一项偏好按工作面约定写入 URL 或可恢复状态；刷新与从对象中心返回后仍回到原上下文。
- 正式动作提交时携带幂等键并锁定当前项；重复点击、超时重试不得重复推进业务状态。
- 动作成功后先落固定结果，再移动到下一条；结果不确定时停留当前项并提供「查询最终结果」，不得擅自判成功或跳过。
- 驳回、处理失败都必须说明当前项是否仍在本队列、下一项是否已打开，以及如何恢复。不得提供退回团队或领取。
- Sheet / Dialog 关闭后焦点返回触发源；队列切换后焦点落到新对象标题，读屏器播报队列位置变化。

### 4.5 M4 对象中心（单据枢纽）

一张销售单 = 一次客户业务的**单一事实入口**。采购、履约、票款、变更都从这里看见全貌。

#### 4.5.1 页头组合契约（与代码强制对齐）

M4 **禁止** `PageHeader(title=工作面名)` 再叠 `DocumentHeader(title=对象名)` 的双标题结构。
身份只出现一次，由 `DocumentHeader` 承担。

```
┌ PageHeader variant="object-chrome"
│  面包屑 · 可选轻量 metadata · [返回/刷新]（无工作面大标题、无 h1）
├ DocumentHeader density="compact"
│  对象标题 · 主状态
│  单号 · 版本 · meta（负责/协作等一行摘要）
│  多轨：履约 | 回款 | 开票（可内嵌 statuses 或独立 StatusTrackSummary）
│  主操作（allowedActions）· secondary 按钮 · 更多
├ 可选 MetricStrip density="compact"
│  业务风险 detailMode="inline"；口径旁白 detailMode="tooltip"|"none"
├ 可选：CostCoverageNotice / PrepaymentGate / 来源系统只读标签
├ 锚点子导航（横向 sticky）
│  概览 | 明细 | 履约 | 票款 | 变更与异常 | 协同（二期）| 审计
├ 内容区 DocumentSection × N
└ 底栏（编辑态）：DraftSaveIndicator · 校验摘要 · 提交
```

| 组件 | M4 用法 | 禁止 |
| --- | --- | --- |
| `PageHeader` | 仅 `variant="object-chrome"`：面包屑 + 返回/刷新 | `title="客户对象中心"` 等与 DocumentHeader 重复的大标题 |
| `DocumentHeader` | `density="compact"`；唯一 h1；`meta` 放负责/协作/来源 | 把长协作期、实现口径塞进 secondaryActions 文案块 |
| `MetricStrip` / `MetricItem` | `density="compact"`；风险信号 inline | 首屏默认展示「服务端聚合 / W11」等实现旁白 |
| 列表/工作台 `PageHeader` | M1/M2/M3/M6/M7 仍用默认 `variant="page"` + 工作面 title | 对象详情误用 page 变体叠双头 |

列表+对象同页的混合壳（如导入批次列表进详情）：**列表态**用 `variant="page"`；**对象/批次详情态**改 `object-chrome` + `DocumentHeader density="compact"`，不得两套 title 并存。

**边界豁免（2026-08-04 决议）**：对象详情以 `QuickPreviewSheet` / `Sheet` 浮层呈现的 M4 工作面（如 W23 执行投影列表 + 详情 Sheet）：背景保留列表态 `PageHeader variant="page"`，浮层内使用 `DocumentHeader density="compact"` 承担唯一对象身份——两套 title 分属列表与浮层两个独立视口，不构成"同页双标题"；浮层关闭即恢复列表态。此模式仅在浮层承载对象详情时允许，禁止在页面主体区同时渲染两套 title。

**概览**：`DocumentSummary` + 客户/合同引用 + 责任人 + 关键日期。  
**明细**：卡券用 `CardVoucherLineItem`（唯一明细）；实物服务用行表。  
**履约**：时间线式责任段（`ResponsibilityPanel` + `RelatedDocumentList`），展示已产生单据与「去开单」入口（权限内）。  
**票款**：应收余额、已收、已开票；内嵌登记回款/开票入口（进入 M5 核销会话，返回仍在本页签）。  
**变更与异常**：变更单、退货、冲正列表 + 创建入口。  
**协同（二期）**：执行投影状态、商城接收、消费汇总入口。  
**审计**：`AuditTimeline` 追加式，字段 diff 用 `BusinessDiffPanel`。

**只读 vs 编辑**：

- T 前商城开单（origin=MALL）的卡券单：商业字段只读，映射与票款可写（T 前）。  
- 草稿 / 驳回可改：中心顶部切换「编辑」，同一路由同一页签，不跳 `/edit`。  
- 已生效字段锁定；变更走变更单流程（在「变更」子区发起）。

### 4.6 M5 编辑工作区

#### 4.6.1 建单 / 改单

- 全宽任务页签；左侧表头字段，下方 `EditableLineItemTable`。  
- 选客户、合同、公司商品池（符合销售资格的公司 SKU 查询）、供应商、结算主体、仓库、负责人：一律使用对应业务 Combobox（`CustomerCombobox` / `ContractCombobox` / `ProductCombobox` / `SupplierCombobox` / `SettlementPartyCombobox` / `WarehouseCombobox` / `OwnerCombobox` 等，底层 `BusinessObjectCombobox`；只出有效对象）。公司商品池不产生独立业务 ID，`ProductCombobox` 返回精确 `sku_revision_id`。
- 状态、付款条件、承运方等码表：一律 `OptionCombobox` / `field.SelectField`；共享码表见 `erp-client/lib/business-options.ts`。  
- **销售建单明细例外（W05）**：非卡券**单位**取所选 SKU 基础单位，只读展示，禁止码表改写；**履约方式（仓发/直发等）**不在销售建单页选择，由采购在 W08 创建采购单时写入；明细可编交付日期。卡券单位固定「张」。含税小计行内 `MoneyValue` 不叠 `taxBasis` Badge（表头已标明口径）。完整布局与控件表见 `ui-workspaces/w05-sales-orders.md` §4.3。
- **禁止**用自由 `Input`/`TextField` 录入已有业务对象 ID 或名称；列表全文关键词搜索除外。  
- 行内即时前端校验 + 提交前 `ValidationSummary`。  
- 自动草稿保存（防抖）+ 显式「保存草稿」；`EditorPresence` 提示他人占用。  
- 提交：`FormalActionConfirmDialog` → mutation → `FormalActionResult`（含单号、下步建议）。

#### 4.6.2 分摊 / 核销（AllocationWorkspace）

同一屏幕完成「编辑资金单据 + 配置核销到单据」，禁止：

1. 页 A 只登记回款金额  
2. 页 B 再做核销  

分摊 / 核销布局必须为：

```
┌ 往来主体头：客户/供应商 · 本次金额 · 方向
├ 左：待核销池（应收/应付列表，可多选）
├ 右：已分配明细（可改金额）
├ 底：未分配余额（默认必须为 0 才允许正式提交；仅当财务规则明确允许时，可提交「暂挂未分配」）
└ 提交确认
```

`CustomerReceipt` 与 `SupplierPayment` 的提交结果必须显示“审批中”，末节点通过后才形成资金事实和核销；`Invoice` 为 `NO_APPROVAL`，强类型登记成功后直接形成发票事实和核销。组件不得把提交成功统一解释为已到账或已付款。

发票与回款/付款**分轨核销**（业务已规定分别记录）；UI 用 Tab 区分「回款核销」「发票核销」，共享往来主体上下文。

### 4.7 M6 只读分析

- 顶：`MetricStrip` + 口径说明 + 期间选择。  
- 中：构成图（chart token）+ 明细表下钻到 M4。  
- 卡券相关：强制展示票款复核进度或成本覆盖率；未覆盖不得暗示「零成本暴利」。  
- 刷新：异步水位提示。

### 4.8 M7 治理与导入

- 分阶段：`ImportStageIndicator`（上传 → 校验 → 试算 → 提交）。  
- 问题行：`ImportIssueTable` 可筛选错误码；不把成功行和失败行混成无法扫读的长表。  
- 映射差异：左右 diff + 指派责任部门动作。  
- 接口错误：`InterfaceErrorResolutionPanel`（重试 / 查询 / 转人工 / 关闭）在**同一详情**完成，不拆「错误列表页 + 另一套处理页」。

### 4.9 筛选区域统一规范

各列表页/队列页/分析页明细的搜索、筛选、分页、**布局归属与密度**必须统一遵循 `docs/ui-filter-design.md`（D1–D25 与 L1–L6 主路径已落地；新页与分析页例外见该文档 §5.2）：

**交互 / URL**

- 搜索统一为「防抖 300ms 即时 + Enter 兜底 + `/` 聚焦」，URL 参数统一 `q`；  
- 清除筛选清全部筛选参数并回第 1 页，**保留**视图/scope、排序、期间/口径与导航上下文参数；  
- 分页写 URL（`page`/`cursor`），筛选变更自动回第 1 页；筛选/分页/搜索变更恒 `router.replace`，打开/关闭详情等导航用 `push`；  
- 来源深链参数（customerId/salesOrderId/orderNo 等）以可移除的共享 `FilterChip` 显性化（第 2 层次行）；  
- 空态统一 `BusinessEmptyState`，区分无数据（no-data）/ 筛选无结果（filter，带「清除筛选」）/ 无数据范围（no-scope）；空态**不**卸载筛选区。

**布局归属（P10）**

- **M2**：筛选只在 `BusinessTableFrame.toolbar` 内，禁止 frame 外平行 `ListToolbar`；  
- **M3**：筛选与类型/范围分段收拢进**一张** sticky 处理面 surface 卡，禁止画布裸放；  
- 统一的是 surface + 槽位语言，队列不硬套表格 frame。

**密度与分层（P11–P12）**

- 第 0 层视图/范围；第 1 层搜索 + **主筛 ≤3** + 计数/清除；第 2 层高级筛选与 `FilterChip`（独立次行）；  
- 枚举选项 ≤4 可用分段/`ToggleGroup`；**≥5 必须** `OptionCombobox` 或收入高级筛选，禁止长 Toggle 横排撑满工具条。

## 5. 第一期核心业务：连续路径设计

下列每条路径给出「用户目标 → 工作面 → 不做什么」。

### 5.1 销售：从意向到销售单生效

| 步骤 | 用户动作 | 界面 |
| --- | --- | --- |
| 1 | 在客户中心确认客户与合同 | M4 客户；合同可在侧栏新建（简单）或任务页签 |
| 2 | 新建实物与服务销售单 | M5；从公司商品池选品 |
| 3 | 保存草稿 / 提交审批 | 同页正式动作 |
| 4 | 审批人在我的工作台处理 | **W01 详情内通过/驳回**，不是邮件式链接散落 |
| 5 | 最终通过后销售单生效 | 结果回写；销售在中心看到状态与后续采购单 |

卡券销售单：列表与中心**与实物单统一入口**，用业务性质标签 + 来源系统标签区分；T 前商城开单同步中的中心商业字段只读，提供「映射客户/合同/类目」「查看同步版本」「票款」能力。

### 5.2 采购：销售单生效 → 选源建单 → 采购单审批

```
W01 销售单审批最终通过
  → 采购在「采购单」M5 选源并按供应商拆单编辑提交
  → W01 采购单审批
  → 通过：形成应付；若先款后货，票款侧提示付款闸门(PrepaymentGate)
```

采购单对象中心（M4）内嵌：付款记录、进项发票、关联销售单、履约单据。  
**禁止**用户为了「看这张采购单付过多少」去三个菜单。

### 5.3 履约：同一作业引擎，岗位分入口（非五张孤岛列表）

侧栏按岗位两个入口，**底层同一 W09 队列与五类表单**（M3+M5）：

- **仓储 · 收货与发货**：默认入库 + 公司仓发。  
- **采购 · 交付与代发**：默认直发 + 电子 + 服务。  
- 类型用页内 Segmented 过滤，**不是**五个平级菜单，也不是两套业务逻辑。  
- 处理时打开轻量作业单：带出销售/采购上下文、数量、仓库；提交后回到队列下一项。  
- 需要追溯时从销售单中心「履约」子区进入同一引擎。

仓储库存调整：从库存台账选 SKU → Sheet 内建调整单 → W01 通用审批队列；简单调整不强制整页跳转。

### 5.4 验收

销售在销售单中心「履约」子区 **登记验收**（按明细）；短少/拒收直接分支到异常处理单创建（同页引导），避免「先去验收菜单找销售单」。

### 5.5 票款：客户往来工作台

**客户往来** 是财务主战场（M2 + M5），不是「回款列表 / 发票列表 / 核销列表」三张皮。

```
客户往来
├ 视图切换：应收台账 | 回款 | 销项发票 | 待核销
├ 选中客户后：右侧或下钻「客户票款会话」
│   ├ 应收明细
│   ├ 登记回款 → 同屏核销
│   └ 登记发票 → 同屏核销
└ 卡券票款复核队列（一期）：M3，逐单补已收/已开票事实
```

供应商往来对称设计。

### 5.6 变更与纠错

从**原单中心**发起变更/退货/冲正；创建后的处理单仍挂在原单「变更与异常」下。  
列表可有全局「异常处理」过滤视图，但是**创建入口在原单**，保证上下文。

### 5.7 商城同步与映射（一期）

- 系统管理员：**同步监控**（任务水位、失败、补拉）+ **映射差异队列**（M3/M7）。  
- 销售/运营：必须在卡券销售单中心处理**指派给自己的**映射差异；禁止要求业务角色进入运维菜单才能消解差异。  
- 差异未解除前，中心与应收明确「未进入经营归属」提示。

## 11. 状态、空态、失败、并发

### 11.1 通用状态契约

| 场景 | 表现 |
| --- | --- |
| 初载 | Skeleton，结构与成稿一致，避免完成后整体跳位 |
| 刷新 / 陈旧 | 保留旧数据 + 顶部/表格轻指示（`AsyncSectionState` / `DataFreshness`）；陈旧数据明确数据更新时间 |
| 空列表 | `BusinessEmptyState`：区分无数据、筛选无结果、无数据范围，并给一个正确下一步 |
| 失败 | `BusinessFailureState`：可重试；不清空已有缓存数据除非致命 |
| 保存中 / 保存失败 | 禁止重复提交；保留输入；失败信息靠近主动作并提供重试 |
| 校验失败 | `ValidationSummary` 置顶 + 字段级错误；焦点移到摘要或首个错误字段 |
| 正式动作成功 | `FormalActionResult` 固定呈现结果、对象号、时间与下一步，不只靠 toast |
| 正式动作结果不确定 | 不切换本地状态；展示查询最终结果、幂等重试或联系支持入口 |
| 版本冲突 | `ConflictResolutionDialog`（ETag），禁止静默覆盖 |
| 他人编辑 / 并发编辑冲突 | `EditorPresence` 提示数据已被他人更新；保留本地输入但禁止提交，刷新后重新校验版本 |
| 后台任务 | `BackgroundJobProgress`；导入/迁移不可假装同步秒完 |
| 敏感字段 | `SensitiveValue` 默认掩码，短时揭示；权限变化后立即清除已揭示值 |

### 11.2 模式覆盖矩阵

`✓` 表示该模式样板与正式实现必须覆盖；`—` 表示不适用。

| 状态 | M1 工作台 | M2 列表 | M3 队列 | M4 中心 | M5 编辑 | M6 分析 | M7 治理 |
| --- | :---: | :---: | :---: | :---: | :---: | :---: | :---: |
| 初载 / 刷新 / 陈旧 | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| 无数据 / 筛选无结果 | ✓ | ✓ | ✓ | — | — | ✓ | ✓ |
| 无模块权限 / 无数据范围 | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| 字段级隐藏 | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| 保存中 / 保存失败 | — | — | ✓ | ✓ | ✓ | — | ✓ |
| 正式动作成功 / 结果不确定 | — | ✓ | ✓ | ✓ | ✓ | — | ✓ |
| 版本冲突 / 处理权丢失 | — | — | ✓ | ✓ | ✓ | — | ✓ |
| 后台任务 | — | ✓ | — | ✓ | ✓ | ✓ | ✓ |

状态徽章 tone 仅允许：`neutral` `info` `success` `warning` `destructive` `void`。tone 与业务状态文案的绑定表必须按 phase 文档状态机枚举在实现库维护并与 `BusinessStatusBadge` / `StatusBadge` 一致；本文不重定义状态机，禁止无绑定文案的裸色点。

## 12. 打印与纸质投影

- 需要对外/归档观感时用 **`PaperDocument`**（A4 账本风格：双方、元数据、明细、汇总、备注、签章位）。

  - **PaperDocument**：纸质/打印投影（签章与正式版式）。

## 附录 A · 范围外与禁止事项

下列事项不在建设范围内，实现必须遵守：

1. 禁止为每个单据类型强制「列表页 + 详情页 + 编辑页 + 审批页」四路由。
