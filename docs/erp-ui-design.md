# ERP 界面设计与实现合同

## 1. 适用范围与权威来源

本合同适用于 `erp-client` 管理端、客户公开选品页及共享展示组件。新增页面、修改现有页面和扩展共享组件必须遵守本合同。

| 内容                               | 权威来源                                          | 执行要求                                 |
| ---------------------------------- | ------------------------------------------------- | ---------------------------------------- |
| 颜色、字号、尺寸、圆角、阴影的取值 | `erp-client/app/globals.css`                      | 全局主题是样式数值的唯一维护入口         |
| 展示结构与交互变体                 | `components/ui`、`components/business`            | 同一角色复用共享组件或明确的共享变体     |
| 工作面、路由、导航门控             | `lib/workspace-registry.ts`、`lib/permissions.ts` | 路由与本合同第 3 节同步维护              |
| 业务事实、状态与正式动作           | 一期基线及相应专题合同                            | 界面不得改写业务状态、金额口径或授权规则 |
| SPA、表单、请求、文案、自动化 ID   | `erp-client/AGENTS.md`                            | 必须同时遵守项目开发规范                 |

本合同规定展示职责和验收标准。前端导航显隐、按钮状态和数据展示不能代替服务端鉴权。文档与实现发生冲突时，必须定位差异并同步修正，不得继续复制冲突样式。

## 2. 主题与共享基线

### 2.1 字体、字号与颜色

默认采用中性灰白画布、白色内容表面和中性主按钮。侧栏消费 `sidebar-*` 令牌；深色模式消费 `.dark` 中的同名语义变量。字体统一使用 `font-sans` / `font-heading`；业务数字使用 `.num`，技术编号等明确需要等宽字体的内容可使用 `font-mono`。

下表按默认 16px 根字号标注对应尺寸。实现必须消费令牌或标准字号类，不得在 feature 中写 `text-[13px]`、`fontSize` 或独立 `fontFamily`。

| 文字角色                         | 样式入口                                                | 基线                         |
| -------------------------------- | ------------------------------------------------------- | ---------------------------- |
| 页面主标题                       | `PageHeader` / `ListWorkspaceHeader`、`text-page-title` | 26px / 36px 行高             |
| 页面说明、列表辅助文字、常规按钮 | `text-body-compact`                                     | 13px / 22px 行高             |
| 业务正文、输入值                 | `text-sm`                                               | 14px                         |
| 标签、次级说明、表格附注         | `text-xs`                                               | 12px                         |
| 徽章与极简辅助标注               | `text-tiny`                                             | 11px                         |
| 客户页紧凑附注                   | `text-2xs`                                              | 10px；不得用于主要操作和正文 |
| 预览核心指标                     | `text-value-summary`                                    | 32px / 40px 行高             |
| 对象中心核心金额                 | `text-value-hero`                                       | 44px / 48px 行高             |
| 登录标题                         | `text-login-title`                                      | 28px / 36px 行高             |

`text-base/lg/xl/2xl` 等 Tailwind 标准档位可用于分区层级与内容强调。同角色不得由各 feature 独立选择档位；优先通过共享组件的 `size`、`density` 或 `variant` 表达。新增字号必须同时登记到 `lib/theme-tokens.ts`，保证 `cn()` 正确区分字号与文字颜色。

| 语义                   | 令牌或组件                                            | 使用范围                                  |
| ---------------------- | ----------------------------------------------------- | ----------------------------------------- |
| 页面、卡片、控件表面   | `background`、`card`、`surface-control`               | 画布、内容表面、输入控件                  |
| 主要与次要文字         | `foreground`、`muted-foreground`                      | 信息层级                                  |
| 主要操作与选中         | `primary`、`primary-foreground`、`accent`             | 操作、焦点与交互                          |
| 完成、警告、信息、错误 | `success`、`warning`、`info`、`destructive` 色族      | 使用对应 Alert / Badge / StatusBadge 变体 |
| 单据或任务类型         | `orange/teal/violet/lime/rose/indigo/cyan` 的语义色族 | 分类标记；不得代替失败、受阻、超期状态    |
| 搜索命中               | `highlight`、`highlight-foreground`                   | 文字命中高亮                              |
| 图表系列               | `chart-1` 至 `chart-5`                                | 图表配置通过 CSS 变量引用                 |

禁止在 feature 使用 `blue-600`、`amber-700`、`bg-white` 等原始色盘以及 Hex、RGB、HSL 色值。业务条件可以选择语义 tone，不能自行配置色值或为深色模式另拼一套色盘。

### 2.2 尺寸、密度与留白

| 角色                          | 令牌 / API                                | 默认尺寸                                            |
| ----------------------------- | ----------------------------------------- | --------------------------------------------------- |
| 顶部全局栏                    | `topbar`                                  | 48px                                                |
| 按钮极小 / 紧凑 / 默认 / 强调 | `Button size="xs/sm/default/lg"`          | 24 / 32 / 36 / 40px                                 |
| 单值选择器默认 / 紧凑         | `OptionCombobox size="default/sm"`        | 36 / 32px                                           |
| 页面横向 / 纵向留白           | `page-inline`、`page-block`               | 24 / 20px                                           |
| 桌面页面横向 / 纵向留白       | `page-inline-lg`、`page-block-lg`         | 32 / 24px                                           |
| 列表工作面外缘                | `listWorkspaceStyles.page`                | 使用集中定义的 `workspace-*` 与页面留白令牌         |
| 表头高度 / 上下留白           | `table-header`、`table-header-block`      | 44 / 8px                                            |
| 紧凑行基线 / 上下留白         | `data-density="compact"`                  | 36 / 4px                                            |
| 舒适行基线 / 上下留白         | `data-density="comfortable"`              | 64 / 10px                                           |
| 表格单元格横向留白            | `table-cell-inline`                       | 16px                                                |
| 对象分区导航                  | `object-tab`、`TabsList variant="line"`   | 44px                                                |
| 列表工作视图                  | `ListWorkspaceViews`、`workspace-view`    | 最小高度 46px                                       |
| 轻预览 / 详细抽屉             | `QuickPreviewSheet size="preview/detail"` | sm 起为 400 / 768px，detail 最大 92vw；更窄窗口全宽 |
| 导航展开 / 折叠 / 抽屉        | `nav`、`nav-icon`、`nav-mobile`           | 240 / 64 / 288px                                    |

表格行高为布局基线，内容超出时允许自然增高。多行内容与编辑行使用舒适密度，禁止先声明 compact 再逐格增加 padding。`DataTable` 默认 comfortable；基础 Table 未指定密度时为 compact。`ListWorkSurface` 不再覆盖表格密度。

控件高度必须由 `size` 或控件令牌决定。禁止传入 `size="sm"` 后再加 `h-7`。树缩进、媒体比例、列内容容纳宽度、滚动视口上下限可以按业务结构设置；不得借这些布局设置改变主题字号或颜色。

### 2.3 圆角、阴影与遮罩

- 按钮、输入框、组合选择器使用 `rounded-lg`；内部面板使用 `rounded-xl`，卡片与较大表面按共享组件的圆角变体执行。
- 圆角与阴影只使用全局阶梯。禁止 feature 自写 `rounded-[…]`、`shadow-[…]`。
- 客户移动页固定底栏使用 `shadow-footer`，保持统一的上向轻投影。
- Sheet 使用 `overlay-sheet`：浅色黑 20%、深色黑 30%，不模糊。普通 Dialog 的遮罩由其共享组件负责。
- 嵌入已有作业面时取消多余外壳；不得重复套边框、阴影和页边距。

### 2.4 样式职责

全局主题负责取值，共享组件负责样式组合和交互结构，feature 负责业务内容、状态选择及必要的布局。禁止依赖 `[&>span:first-child]` 等内部选择器改变共享金额、Label、输入框或 Sheet 的主题外观。

扩展共享外观时，先添加语义变体，再由 feature 选择。`className` 用于容器布局和必要的嵌入适配，不作为重新定义主题皮肤的通道。

### 2.5 固定页面模式

| 模式                  | 用途                         | 必须复用的结构                                                               |
| --------------------- | ---------------------------- | ---------------------------------------------------------------------------- |
| M1 工作台             | 聚合当前用户任务及执行入口   | 任务列表、作业面；平面分区，不重复套卡片                                     |
| M2 列表工作面         | 查询、筛选、排序、点读       | ListWorkspaceHeader、Views、ListWorkSurface 或 BusinessTableFrame、DataTable |
| M3 连续处理队列       | 选择对象并连续处理           | 队列 + 当前作业面；保留筛选和选中对象上下文                                  |
| M4 对象中心           | 阅读主记录、状态、关联和历史 | object-chrome、DocumentHeader、分区导航、DocumentSection                     |
| M5 编辑与分配         | 创建、修订、核销、行项目编辑 | TanStack Form、共享字段、EditableLineItemTable / AllocationWorkspace         |

## 4. 信息层级与值展示

### 4.1 对象身份

列表主要信息必须让用户识别对象、判断当前状态并读到关键数值。展示业务名称、单号、规格与必要的负责人员；不以内部 ID 代替业务名称。

### 4.2 标签、说明与空值

标签与值按稳定层级排列，辅助说明使用弱化文字。无值显示 `—` 或清晰的业务占位。无规格等无信息占位不占据 Sheet description 插槽。说明不得重复标题、状态或已有标签。

### 4.3 指标与金额强调

指标使用 `MetricStrip/MetricItem`。统计项用于阅读，不直接承载筛选或跳转。金额统一使用 `MoneyValue`；需要突出金额时选择 `size="section/summary/hero"`，只放大金额主体，税口径徽章和不可用原因保持辅助字号。默认 `inherit` 保留上下文的字号及字重选择。

### 4.4 数字与口径

金额、数量、税率与日期使用 `.num`。金额、数量等数值列右对齐；编号、名称按其阅读角色对齐。格式化使用 `MoneyValue`、`QuantityValue`、`RateValue` 和 `lib/fixed-decimal.ts`，不得转成浮点后重新计算或用 epsilon 比较。

含税、不含税、税额采用共享 `taxAmountToneClass`。标签或列头已说明税口径时，不重复附加相同 Badge。成本不可见时保留后端授权结果及遮蔽显示，不得从其他摘要字段推算被隐藏金额。

### 4.5 状态

状态使用中文映射，并同时提供文字、图标和语义色。禁止只用红黄绿圆点，禁止展示枚举原值。履约、票、款等并行状态分别展示；多个状态轴使用 `StatusTrackSummary`，不得拼成一个无法解释的总状态。

## 5. M1 工作台

任务展示对象、业务单号、关键金额、期限、状态及责任上下文。执行动作落在当前任务作业面，使用真实权限与对象条件。作业面不再套整页脚手架和多层卡片。受阻、超期使用状态 tone，任务分类使用种类 tone。

## 6. M2 列表工作面

页面顺序为页头动作、工作视图、查询区、表格工具栏、结果表格和分页。视图切换决定当前口径，查询控件过滤该口径；两者不得混放。

`DataTable` 只展示调用方提供的查询结果，不自行取数。列使用 `meta.label/align/numeric/width`，宽度优先使用 reference/status/amount/quantity/rate/tracks/flex 等共享档位。禁止逐列覆盖普通单元格的主题 padding。静态导入结果或批量编辑表可使用共享 Table primitives。

列设置必须位于每张表工具栏最右侧。查询控件不承载列设置、导出或新建动作；页头动作保持可见。卡片视图不显示列设置。服务端排序仅在调用方接入真实排序入口时显示交互。

## 7. M3 连续处理队列

队列与作业面保留同一筛选上下文。提交结果后按明确的下一项规则移动，不在用户未预期时清空选择或跳转。队列滚动边界允许按视口配置，文字、状态、选中背景和动作仍消费共享主题。

## 8. M4 对象中心

`PageHeader variant="object-chrome"` 只承载返回、面包屑和轻动作；`DocumentHeader` 承载唯一对象身份。负责、协作、版本和状态放在相应插槽，金额摘要通过共享指标展示。

分区导航使用 `TabsList variant="line"`；URL 导航必须保留真实链接语义。资料、行项目、版本与关联对象按分区组织，不把完整详情移植进轻预览。

## 9. M5 编辑与分配

业务字段绑定 TanStack Form，枚举使用已注册的 `SelectField` 或 `OptionCombobox`，实体选择使用业务 Combobox。金额与数量保留十进制字符串。表单错误贴近对应字段，提交中、禁用和无权限条件保留明确说明。

正式动作使用共享确认与结果组件。核销、付款、履约等动作必须保留对象版本、权限、任务归属和后端校验，不因样式调整改变调用路径。

## 10. M6 经营分析与核对

先呈现口径，再呈现指标与维度数据。当前与历史口径必须有清晰入口；导出与界面查询采用相同条件。图表消费 `chart-*`，维度明细复用共享表格。默认筛选值、清空值、分页重置与下钻状态必须与 URL 查询合同一致。

## 11. M7 治理与异常处理

展示真实导入批次、后台任务或接口异常的状态、结果与下一步。失败、无结果和无权限分别表达。重试保留原任务及业务语义，界面不得隐瞒部分失败或把系统错误显示为空列表。

## 12. 轻预览与详细抽屉

列表点读复用 `QuickPreviewSheet`；宽度与遮罩只能由共享壳决定。禁止 feature 传入 `contentClassName/overlayClassName`，禁止覆盖头部、标题、页脚的字体或 padding。

- `preview` 用于目录点读与关键事实核对：identity → title → description → summary，正文为短资料，优先展示关键数值。
- `detail` 用于行项目、核销去向、历史记录和多栏核对。业务正文负责滚动，外缘 `px-7 py-6` 只加一次。
- 窄预览不承载编辑表单、完整时间线、纸质单据或整张行项目表。
- 页脚右对齐，次要动作关闭，主要动作打开对象资料。额外动作必须保持只读点读用途。
- 打开时记录原行，关闭后恢复焦点；右上角与页脚关闭使用不同稳定 ID。打开期间停用页面级搜索快捷键。

## 13. 纸质单据与附件

纸质核对复用 `PaperDocument`。列表纸质浮层使用透明 Dialog 壳，纸面拥有自己的排版；纸张宽度、签章位置与媒体视口不按普通卡片强制统一。纸面必须使用服务端确认的金额、状态与签章，不在浏览器重算正式单据。

附件复用共享附件组件，保留上传、扫描、失败、重试与查看状态。附件加载失败不得阻断其他可读事实。

## 14. 查询与选择器

搜索使用共享搜索框；枚举与筛选使用 `OptionCombobox`；客户、供应商、商品、合同、仓库等使用业务实体 Combobox；层级目录使用 TreeCombobox。业务页面禁止新增原生 select 或另用 Select/NativeSelect 重写选择器外观。可见文本、复选与单选控件分别使用共享 Input、Checkbox、RadioGroup。隐藏表单字段、文件上传及客户选择胶囊内的 sr-only 原生复选框允许保留原生 DOM；它们不定义独立的可见控件皮肤。

组合选择器消费全局控件高度、输入边框、表面色、焦点和禁用状态。空值映射、默认“全部”、不可清空和选项禁用由调用方按业务合同明确设置。既有选项 ID 需要保留时，使用 `getOptionId`。

## 15. 深浅主题与反馈状态

同一语义令牌必须在深浅主题下保持相同含义。成功、警告、信息和危险使用共享组件变体，不覆盖其背景、文字和边框配方。选中、悬停、键盘焦点、禁用和校验失败分别保留反馈，不能只调整静态外观。

搜索命中与任务类型颜色可以独立于业务状态，但必须来自全局命名令牌。图片、SVG 装饰允许专用结构与动画；文字字体及颜色仍使用主题类或 `currentColor`。

## 16. 响应式与客户选品

管理端按桌面作业设计。窄窗口保持导航可打开、工具栏可换行、表格可横向滚动，页面本身不得横向撑破。新建、导出、登记和调整动作不得按视口隐藏。

客户公开页 `/s/[token]` 按移动端设计，允许分类侧栏、固定上下栏、胶囊筛选与商品卡片。其颜色和字号仍使用共享语义令牌，主要操作复用共享 Button，状态使用共享变体。10/11px 只用于辅助信息，不把管理端结构移植到客户页。

## 17. 数据反馈与自动化目标

首次加载、保留旧结果的刷新、无结果、无权限和请求失败必须分别展示。刷新不清空已有结果。操作文案说动作，状态文案说结果，错误说明下一步。

所有真实交互目标必须保留稳定、唯一的原生 ID。组件替换不得丢失受控值、事件、禁用条件、label 关联和焦点行为；不得只保留 `data-testid`。列表行 ID 使用稳定业务键，不使用数组 index。

既有复选框依赖原生 `checked`、表单或 ID 点击合同的，使用共享 `NativeCheckbox`。Base UI `Checkbox/RadioGroupItem` 需要将 ID 保留在可交互根节点时，使用 `nativeButton` 与 button render；不得仅把既有 ID 移到内部隐藏 input。可访问名称不得因包装 label 重复。

## 18. 维护与质量门禁

新增主题角色按以下顺序执行：

1. 在 `globals.css` 定义取值及必要的深浅主题映射。
2. 自定义字号和尺寸同步登记 `lib/theme-tokens.ts`；共享组件通过 `cn()` 合并类。
3. 在共享组件提供语义变体或插槽，不要求调用方依赖内部 DOM 选择器。
4. 更新本合同对应表格、使用范围和验收条件，再修改 feature 调用点。

在 `erp-client/` 执行：

```bash
npm run lint
npm run format:check
npm run build
```

`lint:ui-theme` 已纳入 lint，检查生产 feature 的原始色盘、任意字号/色值/圆角/阴影、内联字体色彩、未定义极小字号、预览壳覆盖、原生可见控件与表格、金额内部选择器，以及类合并令牌登记。它不代替浏览器布局验收。

`erp-client` 没有单元测试，也不提供 `npm test`。未获当次用户明确要求时，不要新增单元测试，也不要改仓库根 `e2e/`。全栈清库、种子和生产操作必须按其各自授权范围执行，样式验收不得默认触发业务数据重置。

## 19. 验收标准

交付必须记录以下结果及实际验证范围：

- 静态检查、格式和构建的结果；失败必须明确归属，不以源码扫描替代运行验收。
- 代表页面在 1440px 与 900px 管理端宽度下的页头、操作区、筛选、表格与分页；客户页额外验证移动端宽度。
- 主标题、辅助文字、按钮、徽章和金额实际计算样式；字号与颜色不得因类合并而消失。
- compact / comfortable 表格密度、列设置唯一性、列显隐与恢复、多表隔离和窄窗口滚动。
- preview / detail 宽度、正文滚动、浅遮罩、页脚、关闭与焦点恢复。
- 选择器默认值、清除、禁用、键盘选择，以及表单值和筛选 URL 的映射。
- 金额、数量、税率与日期的等宽数字、对齐、口径标签、遮蔽与不可用说明；状态同时具备中文、图标与颜色。
- 页面路由、原生 ID、权限显隐、业务内容与正式动作合同保持一致。

仅获得 HTTP 200 或样式资源时，只能记录路由壳或资源验证通过。未连接浏览器、没有真实对象、未进入相应分支时，必须列出尚未验收的页面或交互，不能声明完整视觉或业务验收通过。
