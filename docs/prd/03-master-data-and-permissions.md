# 03 基础资料与权限

## 1. 模块定位

基础资料提供“采购责任规则”，用于把销售外采明细确定性分配到具备建采购单资格的具体采购人员。规则是销售提交门禁和销售最终生效后采购任务派发的共同责任来源。

## 2. 用户与入口

- 采购管理员、管理人员和系统管理员从基础资料菜单进入“采购责任规则”。
- Web 路径为 `/master-data/procurement-responsibilities`，菜单登记在工作面 `W14`。
- 销售和采购可通过责任预览读取解析结果，但不能因此获得规则维护权限。

## 3. 采购责任规则

### 3.1 解析顺序

系统按下列顺序逐层解析，每层唯一命中后停止：

1. 精确公司 SKU（`SKU`）。
2. 当前商品分类 + 服务区域（`CATEGORY_SERVICE_REGION`）。
3. 当前分类及其父分类逐级回退（`CATEGORY`）。
4. 商品类型（`PRODUCT_KIND`）。
5. 具体默认调度人（`DEFAULT_DISPATCHER`）。

同一选择器只能存在一条启用规则。即使异常数据或并发写入造成同一层出现多个候选，解析也保守失败，不自行挑选负责人。分类 + 服务区域只匹配当前分类；父分类回退由分类规则承担。服务区域在保存和解析时统一规范化。

### 3.2 维护与展示

规则列表展示规则类型、SKU 编号与名称或分类名称、服务区域、商品类型、负责人、启停状态、优先级含义和更新时间。规则状态持久化值为：

- `active`：参与解析。
- `disabled`：保留历史但不参与解析。

新增和编辑均使用整项保存与版本校验；版本已变化时拒绝覆盖并要求刷新。

### 3.3 负责人资格

规则负责人必须同时满足：

- 是可登录的后台账号。
- 账号当前有效。
- 具备 `purchase_order:create` 权限。

系统不接受团队、公共池、空负责人或仅有角色而没有具体账号的规则结果。最终解析结果在销售生效时再次校验账号和权限；授权策略在解析期间变化时，本次解析失败并可重试。

责任规则保存、销售生效、采购任务转交和采购建单等关键写操作，都把操作开始时的授权策略版本绑定到业务事务提交。若账号、角色或权限在提交前发生变化，整次业务动作失败并回滚，不允许“权限已经撤销但业务仍提交成功”。

## 4. 权限与菜单

| 能力 | 权限 key | 用户可见行为 |
| --- | --- | --- |
| 查询规则与责任预览 | `procurement_responsibility:list` | 查看规则、在销售行查看解析结果 |
| 新增、编辑、启用或停用规则 | `procurement_responsibility:manage` | 显示并执行规则维护操作 |
| 作为采购负责人并建立采购单 | `purchase_order:create` | 可被规则选中，并处理本人采购建单任务 |
| 管理采购任务责任 | `work_item:manage`、`work_item:reassign` | 将开放任务转交给另一名合格账号 |

菜单对具备规则查看或管理权限的账号可见；页面内写操作仍按 `procurement_responsibility:manage` 单独控制。

## 5. 可见性与数据范围

- 规则管理页按权限控制，不使用销售人员手工选择结果替代系统解析。
- 采购创建依据不因拥有规则管理权限而扩大；它始终按当前账号实际拥有的开放采购任务过滤。
- 管理员只有在授予 `work_item:manage` 的角色所对应管理数据范围覆盖任务责任组织时，才可查看或转交该任务。
- 采购任务的目标账号必须当前有效、可登录并具备 `purchase_order:create`；无需先成为销售单既有参与人，转交后的具体任务所有权就是其读取和处理该采购范围的依据。

## 6. 边界与约束

- 【设计原则】销售人员只维护销售业务事实，不手工指定采购负责人；原因是组织分工应由统一规则维护并可审计。
- 【设计原则】开放采购任务必须到具体用户；原因是团队池和空负责人会重新造成执行断点。
- 责任规则不进入全局搜索，不依赖 AI、企微、外部通知或定时任务。
- 规则维护写入审计记录；停用规则不删除历史引用。

## 7. 模块间关系

- 销售单使用本章规则进行逐行预览、提交门禁和最终生效复核，见 [`05-sales-orders.md`](05-sales-orders.md)。
- 最终解析按负责人生成工作台任务，见 [`06-workspace.md`](06-workspace.md)。
- 采购单创建再校验当前账号拥有的具体任务，见 [`08-purchase-orders.md`](08-purchase-orders.md)。
