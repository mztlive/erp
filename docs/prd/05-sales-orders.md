# 05 销售单

## 1. 模块定位

销售单记录客户需求、合同与履约事实，并在审批完成后形成可执行的销售当前版本。对于需要外部采购的商品或服务行，销售单同时承担采购责任预览、提交门禁和采购覆盖进度展示，但销售人员不选择采购负责人或最终供应商。

## 2. 用户与入口

- 销售在销售单新建、草稿续编和销售变更中维护明细。
- 审批参与人通过我的工作台处理销售审批任务。
- 销售、销售负责人及具有销售单查看权限的角色在详情页查看采购进度和关联采购单。
- 具备采购创建权限且拥有对应开放采购任务的用户，可从销售详情的“去建单/继续建单”进入采购创建入口。

## 3. 销售行采购责任

### 3.1 责任预览

每条外采商品/服务行展示只读“预计采购负责人”。预览输入包括公司 SKU 和可选服务区域；商品分类、父分类链和商品类型由当前目录事实解析。

SKU、服务区域等影响责任的字段变化后，页面重新请求逐行预览。负责人只读展示，不提供人员选择控件。非外采行不要求采购负责人，也不形成采购建单任务。

### 3.2 草稿与提交门禁

- 责任无法解析时仍允许保存草稿，以免丢失销售录入内容。
- 提交审批前，所有外采行必须唯一解析到有效且具备 `purchase_order:create` 的账号。
- 任一行无匹配、同层冲突、账号不可用或权限不足时，提交被阻止并逐行显示可执行的维护提示。
- 最终生效时重新按最新规则和授权解析，不把早先页面预览当成永久责任事实。

服务区域随草稿、提交、详情恢复、销售驳回后续编和销售变更完整保留；责任预览和最终解析使用同一字段口径。

## 4. 生效与采购任务

采购确认是普通审批节点，可位于审批流程中的任意位置。采购确认通过但后续节点未完成时：

- 销售单仍未生效。
- 不建立采购建单任务。

最后一个审批节点通过并使销售单最终生效时，系统在同一业务动作中：

1. 读取销售当前修订。
2. 重新解析全部外采行采购负责人。
3. 按负责人分组并冻结每组稳定销售行 ID。
4. 为每位负责人创建一条具体到人的开放采购建单任务。

解析或任务写入失败时，生效动作不留下部分采购任务。

## 5. 采购进度

销售详情按当前生效销售版本展示：

- 采购单数量。
- 销售总数量。
- 已覆盖数量。
- 剩余数量。
- 派生状态：待采购、部分采购、采购已覆盖。

计算口径为：

`剩余数量 = 当前生效销售数量 - 当前有效采购覆盖数量`

当剩余数量大于零且当前用户存在可处理范围时，页面显示“去建单”或“继续建单”；剩余数量为零时隐藏创建入口。进度在桌面和移动宽度下均需完整可读。

## 6. 边界与约束

- 【设计原则】采购可行性审批与销售生效后的采购执行任务相互独立；原因是审批节点顺序不能决定后续执行是否可达。
- 【设计原则】销售当前修订是采购目标数量的唯一来源；不从历史提交或旧修订累计目标数量。
- 销售不自动选择供应商，不修改既有采购单责任人或制单人。
- 通知可以作为提醒，但销售生效和采购任务存在性不依赖外部通知。
- 责任规则和采购进度不依赖 AI 或后台定时任务。
