# 08 采购单

## 1. 模块定位

采购单把已生效销售需求转为对供应商的采购计划。同一销售单可以按供应商、履约责任、付款条件和批次数量建立多张采购单；系统以逐销售稳定行的剩余数量防止遗漏和超采。

## 2. 用户与入口

- 采购人员从工作台“待采购建单”任务进入，页面自动限定到该任务。
- 采购人员也可从采购单列表或销售详情进入创建对话框；服务端仍只返回当前账号拥有的开放任务范围。
- 当前销售单或任务没有可建依据时，页面使用合并空状态提示，说明可能尚未生效、没有合格供给或待采购数量已覆盖；是否可建单以服务端返回的开放任务和依据为准，不以“已有任意采购单”作为禁止继续建单的理由。

## 3. 创建依据

每条创建依据绑定：

- 当前开放采购建单任务 ID。
- 销售单及当前销售修订。
- 任务冻结的稳定销售行范围。
- 供应商。
- 采购类型。
- 付款条件。
- 履约责任。
- 逐行销售数量、已覆盖数量、剩余数量、当前供应商最大可创建数量和供给价格事实。

依据只对当前账号拥有的开放任务生成。系统在查询供应商供给前先按任务冻结的稳定销售行过滤，其他采购负责人的行不会进入候选查询或结果。

依据 ID 包含任务身份、销售采购 guard、当前销售修订、拆分维度及逐行剩余/供给指纹。旧依据、其他任务依据或伪造任务 ID 均不能用于创建。

## 4. 一张销售单多张采购单

采购人员可以在不超过当前最大可创建数量的范围内修改本次数量。一次命令只创建一张采购草稿；创建后对剩余数量再次形成新依据，因此可继续建立第二张或更多采购单。

拆分维度包括：

- 不同供应商。
- 不同采购类型或履约责任。
- 不同付款条件。
- 同一拆分维度下分批数量。
- 同一任务范围内选择部分销售行。

已有采购草稿只占用其当前提交中的数量，不会关闭整张销售单的后续创建入口。

## 5. 覆盖与剩余数量

计算公式为：

`remaining = 当前生效销售数量 - 有效采购覆盖数量`

采购覆盖只读取每张采购单的当前指针：

| 采购状态 | 覆盖来源 | 是否占用 |
| --- | --- | --- |
| `DRAFT` | `current_submission_id` 当前提交行 | 是 |
| `IN_APPROVAL` | `current_submission_id` 当前提交行 | 是 |
| `EFFECTIVE` | `current_revision_id` 当前版本及销售分配 | 是 |
| `PARTIALLY_EXECUTED` | `current_revision_id` 当前版本及销售分配 | 是 |
| `COMPLETED` | `current_revision_id` 当前版本及销售分配 | 是 |
| `VOIDED` | 不计入 | 否 |

历史采购提交、历史采购版本和未指向销售当前修订的分配不重复累计。覆盖超过销售当前数量属于数据一致性错误，不静默截断为零。

采购草稿数量保存、采购草稿创建和采购变更生效后，系统同步销售采购进度和采购建单任务。正式采购减量生效会释放数量并在需要时创建新的开放采购任务。

## 6. 并发、权限与幂等

创建请求必须携带当前依据返回的任务 ID和幂等键。服务端在同一 MongoDB 事务中：

1. 校验任务属于当前账号、仍为开放状态、指向目标销售单且冻结范围完整。
2. 读取销售当前版本并按任务范围重算依据。
3. 推进销售采购 guard，以串行化同一销售单的并发创建。
4. 再次读取最新剩余数量并校验逐行本次数量。
5. 写入采购草稿、当前提交和命令收据。
6. 重新计算覆盖并同步采购任务。

同一幂等键与同一载荷重复提交返回原采购单；同一幂等键用于不同任务、依据或数量时冲突。并发导致剩余变化时拒绝创建并提示刷新，不允许累计有效采购覆盖超过销售数量。

采购草稿保存和采购草稿作废同样使用严格幂等命令：同键同载荷回放首次成功结果，同键异载荷返回冲突；客户端遇到“结果未知”时保留原幂等键重试，收到确定失败后下一次操作使用新键。命令收据与采购聚合、覆盖释放和任务同步处于同一事务；即使提交成功后的响应丢失，重试也不得重复保存、重复作废或重复释放数量。

## 7. 边界与约束

- 【设计原则】稳定关联键是 `sales_order_line_id`；不按 SKU、行号或当前版本行猜测跨版本关系。
- 【设计原则】草稿和审批中采购同样占用数量；否则并发草稿会造成超采。
- 系统只列出当前有效且可供的供应商供给，不自动决定最终供应商。
- 没有合格供给时保留采购任务；当前创建页通过合并空状态提示说明可能没有合格供给。
- 采购变更不重写历史采购版本；生效后切换当前版本并按新分配计算覆盖。
- 不保留旧的一单一采判断、旧创建依据格式或旧 basis ID 兼容行为。
