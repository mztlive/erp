# 06 我的工作台

## 1. 模块定位

我的工作台集中展示具体到人的待处理任务。销售单最终生效后产生的“待采购建单”属于非审批类执行任务，用于确保采购人员持续知道哪些销售需求已经可以建采购单。

## 2. 用户与入口

- 采购人员在“待我处理”中查看本人开放任务。
- 历史视图保留已完成或已关闭任务，用于追踪责任和完成时间。
- 具备任务管理权限的管理员可转交开放任务。
- 用户点击采购建单任务的“打开单据”进入采购单创建页，路由携带销售单 ID 和工作项 ID，并由目标页面重新读取授权事实。

## 3. 采购建单任务合同

任务稳定类型为 `PROCUREMENT_ORDER_CREATION`，客户端处理器为 `procurement_order_creation`，目标工作面为 `W08`。

每条开放任务必须包含：

- 销售单业务对象。
- 当前销售修订版本。
- 具体 `owner_user_id`。
- 责任来源；规则初始派发为 `SYSTEM_RULE`，管理员转交后为 `ADMIN_REASSIGN`。
- 服务端生成的责任键。
- 已排序、去重并冻结的稳定销售行 ID 范围。
- 销售单号、责任行数和当前剩余数量摘要。

任务范围最多 200 行。采购任务不能通过普通任务构造路径绕过责任键或冻结范围。

## 4. 生命周期

### 4.1 创建

销售单最终生效时按采购负责人分组，每位负责人、每个责任范围只允许存在一条开放任务。审批流程中的采购确认通过不会提前创建该任务。

### 4.2 处理中

采购草稿创建或数量编辑、采购变更生效等动作改变覆盖数量后，系统在同一事务中重新计算任务范围剩余数量：

- 剩余数量大于零：任务保持 `OPEN`，更新面向用户的剩余数量摘要。
- 范围内所有稳定销售行剩余数量为零：任务自动进入 `COMPLETED`，完成操作人记录为系统。

### 4.3 重新释放

历史终态任务不可重开。采购覆盖减少并使同一冻结范围重新出现剩余数量时，系统复制最近一条终态任务的具体负责人、责任来源和冻结行范围，创建新的 `OPEN` 任务；旧任务保持终态和原有审计记录。

同一责任键已经存在开放任务时，不再创建重复任务。

## 5. 权限与转交

- 采购任务处理需要当前账号是任务负责人且具备 `purchase_order:create`。
- 任务详情和创建依据都重新校验任务类型、销售对象、开放状态、具体负责人及冻结范围。
- 管理员转交只影响未完成责任范围；管理人的 `work_item:manage` 数据范围必须覆盖任务责任组织。
- 采购任务的目标账号必须当前有效、可登录并具备 `purchase_order:create`，无需先具备该销售单的既有参与关系。
- 转交不修改既有采购单、制单人、审批、履约或历史任务。

## 6. 边界与约束

- 【设计原则】工作台任务是持久执行事实，通知只是可选提醒；核心流程不依赖企微、邮件或其他外部通知。
- 【设计原则】终态任务不可逆；重新释放使用新任务身份，保证历史可追踪。
- 采购建单任务不是审批节点，不展示审批通过、驳回或撤回按钮。
- 不提供公共待领、团队池或空负责人任务。
- 当前剩余摘要来自采购覆盖事实，不能被销售单通用摘要覆盖。
