# 供应商连接异常处理合同

## 适用范围

本合同约束供应商接口健康检查、商品目录同步失败生成的集成异常，以及工作台嵌入式异常处理页面。

## 任务与责任

- 每次后台执行保留独立的失败记录和处理待办。原后台任务身份必须保持稳定。
- 鉴权或签名失败归系统管理岗位，初始个人处理人沿用执行操作人。
- 重复任务通过已有责任命令关闭，必须填写规定的替代任务与处理说明；不得直接删除异常或自动合并不同执行记录。
- 当前处理人、版本和允许动作必须从已授权待办接口读取。前端不得根据错误分类自行开放动作。

## 详情接口

`GET /admin/integration/error-tasks/{id}` 保留原有顶层字段，追加以下字段：

| 字段 | 约束 |
| --- | --- |
| `work_item_id` | 唯一关联待办身份；无关联时为空。多个关联必须报冲突。 |
| `connection_failure` | 原连接、执行类型、后台任务编号、失败时间与脱敏错误摘要。非连接异常为空。 |
| `audit_history` | 已授权异常及关联待办的最近 50 条结构化成功审计，展示动作名称、操作人及时间。 |

- 前端按 `work_item_id` 查询待办，并核对业务对象类型和身份；核对失败不得执行处理命令。
- 原始失败来源必须按异常稳定身份与原后台任务精确匹配，不得套用同一连接最新一次失败。
- 历史来源查询限定同连接、同任务类型、异常登记前最近 50 次失败，复用现有连接历史索引；无法匹配时明确提示原始摘要不可用。
- 新异常创建时必须登记首次失败尝试，摘要沿用脱敏错误代码和说明，最长 512 字符。
- 审计只展示登记过的结构化动作和操作人，不展示任意日志消息、凭据、请求正文或技术关联字段。

## 页面行为

- 详情必须优先展示失败操作、具体原因和接口设置入口。
- 内嵌办理页使用单一工作面与扁平分区，不叠加通用卡片、队列统计或重复标题；恢复通过使用成功状态，原始错误降为背景信息。
- 备注、技术详情、其他处理方式及执行历史按需展开。没有可执行动作时明确说明只读或阻断原因，不显示空白处理表单。
- “完成处理”直接提交，不增加确认弹窗；提交期间显示进度并禁用重复操作，服务端核验失败时在当前任务显示原因。
- 鉴权异常必须指导处理人修复授权或凭据、执行鉴权检查、返回刷新并核验完成。
- 未提供环境事实时不展示“生产”标签，不提供无效环境筛选；旧环境查询参数归一为全部。
- 未加载处理策略时，资金影响展示“待核实”。禁止把默认值展示成已确认结论。
- 仅无关联待办的对账差异可以展示“直接对账”；错误任务缺少关联时明确提示关联异常。
- 刷新必须同时更新队列和当前详情。待人工数量必须包含待处理、待人工两种状态。

## 鉴权恢复核验

连接鉴权异常仅可使用 `supplier_api_health_check_run` 类型的真实记录作为业务对象核验依据，并同时满足：

1. 异常由连接治理生成，错误分类为鉴权签名，无入站消息，连接身份一致。
2. 检查类型为鉴权，开始时间晚于异常登记时间，检查已成功且完成时间完整。
3. 检查冻结的技术配置版本与当前连接一致，当前连接最近健康结果为通过。
4. 使用最近 50 条检查中的最新鉴权检查；存在更新的失败、未知或执行中鉴权检查时，不得回退到旧成功记录。
5. 完成命令必须在原事务内重新核对连接、配置和检查状态。旧配置、其他连接、单纯连通检查均不得作为完成依据。

鉴权恢复不代表商品同步已完成。目录同步失败修复后仍须在商品库重新执行原业务所需的同步。

## 交付与兼容

- 响应字段只追加；持久化使用已有首次尝试字段，无集合或索引迁移。
- 服务端先发布，客户端后发布；旧客户端忽略追加字段，新客户端连接旧服务端时保持只读并提示关联待办缺失。
- 回退客户端不改变异常或待办状态。回退服务端后，新证据类型必须保持拒绝验证，禁止降级为未经核验完成。
- 单元测试和构建通过仅证明离线规则与编译；真实数据库事务、供应商鉴权和页面交互须分别验收。
