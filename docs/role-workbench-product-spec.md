# 岗位工作台产品需求规格

| 项目 | 内容 |
| --- | --- |
| 产品 | 福尚云 ERP |
| 版本 | V1.0 |
| 日期 | 2026-11-02 |
| 状态 | 产品需求草案，作为后续设计、接口拆分和验收的输入；不代表功能已交付 |
| 适用范围 | 内部员工岗位首页、统一待办中心、岗位业务指标与图表 |

## 1. 建设目标与边界

### 1.1 建设目标

系统采用“岗位首页 + 统一待办中心”的产品结构。不同岗位须拥有独立页面、明确的业务重点、对应的数据图表和处理入口。

岗位首页须使用户完成以下判断：

1. 查看本人或管理范围的业务进展。
2. 识别需要优先关注的异常、逾期和经营风险。
3. 进入当前岗位需要处理的任务或业务单据。

不得以同一页面替换四个数字卡片作为岗位工作台的完整交付。岗位之间须在指标、图表、异常清单和主要操作上体现职责差异。

### 1.2 本次建设范围

- 岗位工作台模板及独立页面。
- 角色与工作台的显式映射、用户默认工作台、多岗位切换。
- 统一待办入口及岗位内待办摘要。
- 岗位指标、趋势、分布、排行和异常清单。
- 指标下钻、统计期间、数据范围、数据状态及刷新规则。
- 原工作台入口及既有任务处理链接的调整。

### 1.3 不包含的内容

- 修改业务单据的审批规则、负责人规则和流转状态。
- 因新增工作台而自动扩大人员权限或数据范围。
- 自由拖拽仪表盘、用户自行编写指标、任意跨域报表生成器。
- 在缺少目标数据、事件记录或业务规则时计算目标完成率、转化率和准时交付率。
- 以工作台替代完整业务列表、专业财务报表或任务处理页面。

### 1.4 现有能力使用边界

当前本地源码包含五类业务概览、统一任务队列、业务列表汇总和经营盈亏查询，可作为建设输入。源码存在不等于生产可用；交付前须逐项核验接口、统计口径、权限及实际数据。

既有任务执行页面继续承载审批、付款、开票、收发货等操作。岗位首页负责发现问题和进入处理，不复制另一套业务执行逻辑。

## 2. 岗位与工作台目录

### 2.1 工作台模板

| 编号 | 工作台 | 适用岗位 | 默认数据范围 | 页面重点 |
| --- | --- | --- | --- | --- |
| WB-01 | 销售工作台 | 销售 | 本人负责且获授权的业务 | 客户业务、订单推进、交付与催回款 |
| WB-02 | 销售主管工作台 | 销售领导 | 获授权的团队或部门 | 团队进展、客户贡献、低毛利与审批 |
| WB-03 | 采购工作台 | 采购 | 本人负责且获授权的采购业务 | 询报价、供货落实、采购执行与延期 |
| WB-04 | 出纳工作台 | 出纳 | 获授权的资金范围；待办按实际责任 | 回款、付款、分配与近期到期资金事项 |
| WB-05 | 开票工作台 | 开票人员 | 获授权的票据范围；待办按实际责任 | 销项开票、进项匹配、红冲与票据异常 |
| WB-06 | 财务主管工作台 | 财务总监 | 获授权的财务范围 | 应收应付、账龄、盈亏、成本覆盖与审批 |
| WB-07 | 仓储与履约工作台 | 仓储及明确承担履约责任的人员 | 获授权的仓库、业务范围及本人任务 | 收发货、交付、验收与积压 |
| WB-08 | 运营工作台 | 运营 | 获授权的运营业务 | 商品资料、发布、映射和业务集成异常 |
| WB-09 | 经营管理工作台 | 管理层 | 获授权的公司、部门或业务范围 | 经营结果、业务结构、重点客户与重大风险 |
| WB-10 | 系统运行工作台 | 系统管理员 | 获授权的系统运行范围 | 后台任务、同步、接口故障及运行异常 |

“默认数据范围”仅约束展示意图，不授予数据权限。无法取得表中所需范围时，须按第 6 节处理。

仓储、直发、电子交付和服务交付须按实际职责及权限展示对应区域；不得向仓储岗位默认展示全部履约类型。

综合财务角色使用出纳、开票、财务主管三个模板中明确配置且满足权限条件的模板，不另建混合财务页面。系统运行工作台不得默认提供账号管理、角色管理、业务审批或全公司经营数据；相关入口须具备独立授权。

### 2.2 模板与角色配置

1. 工作台模板使用稳定编号，与可变的角色名称分离。
2. 角色管理支持关联一个或多个工作台模板；内建岗位提供推荐映射，自定义角色允许显式配置。
3. 模板关联不授予业务权限。服务端须同时核验角色映射、入口资格和数据授权。
4. 模板配置须声明核心模块及其最低权限条件。最低条件不满足时，该模板不得出现在可选列表中。
5. 可选模块权限不足时隐藏模块，并按模板布局收拢剩余内容；不得留下空卡片占位。
6. 新建或修改角色的工作台映射须纳入既有角色配置权限与审计规则。

### 2.3 默认首页与切换

- 单岗位用户首次登录直接进入可用岗位首页。
- 多岗位用户首次进入时选择默认工作台；后续允许在个人设置中修改。
- 无显式深链接时，进入顺序为：上次使用且仍可用的工作台、用户默认工作台、唯一可用工作台、工作台选择页。
- 上次使用的记录按账号隔离。账号切换后不得继承上一账号的选择或数据。
- 页头显示当前工作台名称，并只列出当前账号可进入的其他工作台。
- 切换时整体替换岗位内容，保留适用于目标页面的期间偏好；岗位专属筛选不得串用。
- 每个工作台具有独立地址，可收藏、可从链接直接进入。
- 无可用岗位模板时，进入具备权限的统一待办中心；无待办入口权限时显示“暂无可用工作台”及联系管理员的提示。
- 访问已失去权限的工作台深链接时，明确提示无权访问，并提供返回可用工作台的入口。

## 3. 页面结构与交互

### 3.1 通用信息结构

| 区域 | 必须展示的内容 | 交互要求 |
| --- | --- | --- |
| 页头 | 工作台名称、数据范围、适用的期间筛选、刷新入口 | 范围与期间可追踪，不得只显示“我的数据” |
| 核心指标 | 默认 4～6 项，受授权裁剪后允许更少 | 点击可进入同口径明细或关联记录 |
| 图表分析 | 标准模板配置 2～3 张有独立业务用途的图表 | 支持查看数值、时间、单位和明细 |
| 风险与异常 | 风险对象、原因、影响金额或时长、责任人、下一步 | 优先展示逾期、受阻和临近到期事项 |
| 岗位待办 | 当前岗位中本人可处理的任务摘要 | 进入既有任务处理页面；支持查看全部 |
| 常用操作 | 与岗位直接相关且用户具备权限的入口 | 操作名称与实际行为一致 |

不得为了达到卡片或图表数量展示无关信息、重复指标或虚构数据。尚未具备业务数据的模板按数据就绪规则交付，不得以空图表宣称完成。

### 3.2 页面重心

- 销售、采购、出纳、开票、仓储、运营：待办和异常为主要工作区域，图表用于解释进展与积压。
- 销售主管、财务主管：团队或财务指标、风险分析、审批任务并重。
- 经营管理：经营趋势、业务结构和重大风险为主体，个人待办作为辅助区域。
- 系统运行：故障、失败任务、运行趋势为主体，不混入经营金额指标。

### 3.3 统一待办中心

1. 全局导航保留“我的全部待办”，角标统计本人全部开放任务。
2. 全局角标不随岗位切换、业务期间和岗位筛选变化。
3. 岗位首页待办只统计与该岗位职责匹配且本人具备处理资格的任务。
4. 一个任务可能与多个岗位相关；统一待办按任务唯一标识去重，禁止把各岗位计数直接相加。
5. 团队待办与本人待办分开展示；管理范围、改派权限和执行资格分别校验。
6. 任务归属按任务类型、业务对象、处理资格和责任规则配置，不根据任务标题或前端关键词推断。
7. 首页风险清单中的业务对象不得伪装成可执行任务；查看详情与处理任务须使用不同动作文案。
8. 已完成或已失效任务不得继续提供执行动作；提交时仍以服务端资格核验结果为准。

### 3.4 下钻与返回

- 指标、图表和异常项须进入对应业务列表、分析明细或单据详情。
- 下钻须携带统计范围、期间及业务过滤条件，目标页须显示并允许清除适用的筛选。
- 指标汇总与下钻明细须使用相同权限、期间、状态和金额口径。
- 数据变化导致数值与明细不同步时，展示各自更新时间并允许刷新，不承诺跨时点数字完全一致。
- 返回首页须恢复工作台、期间和用户已应用的筛选。
- 正式审批、资金、开票和履约操作继续使用既有确认与提交流程。

## 4. 岗位内容要求

本节定义各模板的目标内容。第 8 节规定交付批次；未完成数据核验的内容不得提前发布。

| 工作台 | 核心指标 | 图表与分析 | 优先处理清单 |
| --- | --- | --- | --- |
| 销售 | 本期生效订单额、待跟进询价、待交付订单、客户应收未收、客户逾期应收 | 生效订单额趋势、订单阶段分布、客户贡献排行 | 询价新反馈、被退回单据、交付异常、到期及逾期回款 |
| 销售主管 | 团队生效订单额、团队到账回款、低毛利订单数、团队逾期应收 | 团队订单额对比、客户贡献、订单与回款趋势 | 待审批、低毛利订单、重点客户逾期、团队受阻任务 |
| 采购 | 待处理询价、待确认采购、待到货采购、逾期未到货 | 生效采购金额趋势、待到货交期分布、供应商交付表现 | 待报价、采购依据变化、供货异常、到货延期 |
| 出纳 | 今日到期待付、未来 7 日到期应付、回款待分配、付款待分配、待执行付款任务 | 实际收付款趋势、未来应付到期分布 | 已批准待执行付款、回款登记入口、待分配资金记录 |
| 开票 | 待开票金额、待开票申请、进项待匹配金额、异常票据数 | 已开票金额趋势、待开票时长分布 | 待开票、红冲处理、进项票匹配、票据异常 |
| 财务主管 | 应收未收、应付未付、逾期应收、实际经营盈亏、成本覆盖情况 | 应收账龄、实际收付款趋势、实际经营盈亏趋势 | 财务审批、异常资金单据、缺失成本、账款异常 |
| 仓储与履约 | 今日计划收货、今日计划发货、逾期交付、待验收；按责任展示适用类型 | 履约阶段分布、任务积压时长、实际交付趋势 | 今日作业、超期任务、收发货异常、验收异常 |
| 运营 | 待发布商品、资料待完善、待处理映射差异、待处理业务集成异常 | 异常类型分布、异常积压时长、发布趋势 | 商品资料完善、映射修复、业务同步异常 |
| 经营管理 | 销售收入、实际经营盈亏、到账回款、逾期应收、重大履约风险数 | 收入与盈亏趋势、客户或部门贡献、业务结构 | 亏损订单、重点客户风险、重大交付异常 |
| 系统运行 | 失败后台任务、失败同步、未解决接口异常、超期未处理故障 | 失败趋势、异常来源分布、故障积压时长 | 可重试失败任务、接口故障、需业务人员介入的异常 |

补充约束：

- 销售主管的回款须明确归属依据；无法可靠归属时不得按订单关联关系重复累计。
- “低毛利”沿用业务已有判定规则，不在工作台另设计算公式。
- “今日计划”“逾期交付”必须有可追溯的计划或承诺日期。缺少日期的记录归为“交期未设置”，不得算作按时或逾期。
- 回款登记属于常用操作。缺少独立的待登记来源记录时，不得生成“待登记回款数”。
- “重大风险”须有已批准的业务规则或人工标记；规则未建立前仅展示具体异常类型，不生成重大风险评分。
- 系统运行页的重试、忽略、取消等动作须沿用各对象的独立授权与操作条件。

## 5. 指标与图表数据合同

### 5.1 指标登记要求

每个上线指标须形成可核验的指标定义，至少包含：

| 字段 | 必填内容 |
| --- | --- |
| 标识与名称 | 稳定指标标识、用户可见名称、所属模板 |
| 业务对象 | 来源业务对象、唯一标识及去重方式 |
| 计算规则 | 纳入与排除状态、求和或计数规则、分子分母 |
| 时间规则 | 期间或时点、使用的业务日期、时区 |
| 数据范围 | 本人、团队、部门、公司或实际任务责任范围 |
| 金额规则 | 币种、单位、含税或不含税、冲正退款处理方式 |
| 特殊处理 | 草稿、取消、变更、缺失数据、权限受限的处理 |
| 核验入口 | 同口径明细、更新时间、来源接口或汇总服务 |
| 业务责任 | 负责确认口径的业务岗位及验收样例 |

未登记上述定义的指标不得作为正式工作台指标上线。

### 5.2 核心指标约束

| 指标 | 计算与展示合同 |
| --- | --- |
| 本期生效订单额 | 按订单生效业务日期统计生效事件金额；排除草稿与未生效订单。后续变更、取消须可追溯并单独定义净额口径；不得把当前订单金额重写到历史期间。生效事件金额不可取得时暂不发布该指标 |
| 新增销售单数 | 按创建日期统计；含草稿时必须明确标注。不得命名为成交订单数或业绩 |
| 应收未收、应付未付 | 使用账款服务当前未结余额，按获授权范围聚合；不得从当前分页金额求和 |
| 逾期应收 | 到期日早于当前业务日期且存在未结余额的应收金额；缺到期日单列，不计入逾期金额 |
| 今日到期待付 | 到期日等于当前业务日期的应付未结余额；与“本人可执行的付款任务”分别统计，不把到期应付当作支付授权 |
| 未来 7 日到期应付 | 按业务时区，从明日起连续 7 个自然日内到期的未结余额，明确起止日期；不包含今日与已逾期金额 |
| 到账回款、实际付款 | 使用资金业务认可的已生效收付款记录及实际业务日期；冲正退款按资金报表既有口径处理并标注。资金分配不得再次增加收付款发生额 |
| 回款待分配、付款待分配 | 使用资金服务提供的当前未分配余额，与收付款发生额分开 |
| 待办数量 | 使用任务服务计数，明确本人或管理范围、开放状态及岗位分类；与单据数量分开 |
| 实际经营盈亏 | 复用经营盈亏服务的期间、收入、成本、费用及可靠性规则；不得用销售采购价差替代实际盈亏 |
| 成本覆盖情况 | 使用经营盈亏服务的覆盖分类和可靠性结果；若展示百分比，须另行登记可核验的分子分母 |
| 账龄 | 按业务确认的账龄基准和区间分组。逾期天数与形成账款后的存续天数须明确区分，不得混用 |

### 5.3 期间、时点与比较

1. 默认业务时区为 `Asia/Shanghai`，日期边界按该时区计算。
2. 期间指标默认“本月迄今”，支持上月、本季迄今和自定义范围。
3. 日期区间包含用户选择的起止日；服务端以开始日零点至结束日次日零点的左闭右开区间查询。
4. 当前余额、当前待办、当前逾期属于时点指标，不随业务期间变化，并标注“截至当前”。
5. 趋势图与指标使用相同业务日期和范围；短期间按日、较长期间按周或月展示，图中明确粒度。
6. 本月迄今与上月比较时，使用上月同期；禁止默认与完整上月比较后标为“环比”。
7. 无可靠历史口径、同期不可比或基期为零时，不显示误导性增长百分比，使用“暂无可比数据”或绝对变化量。

### 5.4 图表要求

- 趋势使用折线图或柱状图；阶段与类型分布优先使用条形图；排行须同时显示对象、数值和排序依据。
- 每张图表须显示标题、统计期间或时点、单位、范围和更新时间。
- 金额与数量不得共用未标注的坐标轴；多币种未经明确换算不得合并。
- 排行展示前 N 项时必须说明范围；需要表达总体结构时同时提供其余项合计。
- 阶段分布须定义互斥阶段或注明可重叠；同一订单存在多行、多次履约时不得无说明重复计数。
- 图表支持键盘访问和数据表查看；不得只依靠颜色、鼠标悬停或图形面积表达结果。
- 无数据、读取失败、无权限和口径受限必须分别处理。

## 6. 权限、数据质量与刷新

### 6.1 授权规则

- 工作台入口权限、业务对象可见范围、金额字段权限、任务处理资格分别生效。
- 汇总、图表、排行和下钻由服务端执行同一授权，不得先返回全量数据再由前端隐藏。
- 不能查看利润时，不得通过收入、成本组合或图表提示额外暴露受限利润；字段组合沿用业务分析服务既有裁剪规则。
- 账号、角色、权限版本或组织范围变更后，旧授权下的缓存数据不得继续展示。
- 管理者能够看到业务汇总不代表拥有具体任务的执行资格。
- 系统管理员不得因技术岗位身份自动获得经营管理工作台或业务金额权限。

### 6.2 数据质量状态

| 状态 | 展示行为 |
| --- | --- |
| 有效零值 | 显示 0，并允许查看对应空明细 |
| 无业务记录 | 显示“当前范围暂无记录”，不生成虚构趋势点 |
| 无数据范围 | 显示“当前未配置可查看的数据范围”，不得显示 0 |
| 无字段权限 | 隐藏受限字段或按既有规范脱敏，不返回原始数值 |
| 口径未配置 | 显示具体缺项和具备权限的配置入口；普通用户提示联系责任岗位 |
| 数据覆盖不完整 | 明确覆盖范围与限制；无法可靠计算的结果显示不可用 |
| 数据待更新 | 显示原更新时间及更新状态；不得把旧值标为实时 |
| 读取失败 | 当前模块显示失败与重试入口，其他成功模块继续可用 |

实际经营盈亏当前若仅覆盖非卡券业务，首页及下钻均须标注“非卡券”。成本缺失不得按零成本处理，不得把可靠子集的盈亏标为全公司利润。

### 6.3 刷新与响应

- 首次进入按模块加载，单个图表不得阻塞整个页面。
- 页面保持可见时，待办及异常数据目标刷新间隔为 60 秒，业务统计与图表为 5 分钟；页面隐藏时停止周期刷新。
- 用户可主动刷新。已知业务操作成功后，相关待办与统计立即触发失效更新。
- 同一统计源的重复模块共享请求；不得为每个趋势点分别读取完整业务列表。
- 汇总与历史趋势由服务端提供；前端不得通过遍历分页推算全量指标。
- 显示各模块实际更新时间，不用单一页头时间掩盖来源差异。
- 验收环境须记录数据规模、并发、缓存状态和接口延迟。性能目标为首批可操作内容 2 秒内、主要模块 5 秒内；环境基线须在性能验收前固定。

## 7. 布局与交互验收要求

1. 优先按桌面工作场景设计；宽屏可使用主区域与辅助区域，窄窗口按信息优先级纵向排列。
2. 页面不得出现整体横向溢出。确需横向滚动的数据表仅在表格内部滚动。
3. 工作台切换、期间筛选、刷新和主要操作在窄窗口仍然可用。
4. 金额、数量、百分比使用系统既有格式规范；压缩金额必须可查看完整数值。
5. 异常清单至少展示业务单号、相关客户或供应商、异常原因、持续时长或到期日期、可执行下一步。
6. 默认按异常等级、到期时间、进入时间和稳定唯一标识排序，避免刷新后无规则跳动。
7. 加载、空态、失败和权限受限须分别设计；禁止用永久加载骨架掩盖错误。
8. 所有交互控件具备清晰名称、键盘焦点和稳定唯一标识；关闭弹层后焦点返回触发位置。
9. 无权限的主要操作不出现；具备入口权限但暂不满足业务执行条件的操作须说明不可执行原因。

## 8. 交付批次与数据就绪要求

### 8.1 数据就绪分类

| 分类 | 判定条件 | 交付要求 |
| --- | --- | --- |
| A：可复用 | 已有服务可提供完整统计、授权及下钻口径 | 核验后接入，仍须进行页面与数据验收 |
| B：需新增汇总 | 原始业务事实完整，但缺少汇总、趋势或分组查询 | 补充服务端统计与同口径下钻后上线 |
| C：需补业务前提 | 缺目标、承诺日期、阶段事件、归属规则或风险标准 | 先完成业务定义和数据采集，不进入本批次上线内容 |

阶段启动时，产品、业务责任岗位和研发须共同完成逐指标分类。不得把“列表里能看到字段”视为具备历史趋势或全量汇总能力。

### 8.2 第一批：岗位结构与核心业务

交付内容：

1. 模板映射、默认首页、独立地址、多岗位切换和统一待办入口。
2. 销售、采购、出纳三个完整样板页面，先验证职责差异、兼岗操作和权限边界。
3. 样板验收后扩展至其余岗位，完成每个模板本批次确认的 A 类与必要 B 类内容。
4. 指标登记、期间与范围标识、下钻、模块独立失败及刷新规则。
5. 原工作台入口导向岗位首页；原统一任务能力调整为“我的全部待办”，已有任务深链接保持可达。

第一批不得仅交付导航与空模板。每个发布模板须具有可用的核心指标、岗位处理清单，以及至少两张口径成立且用途不同的图表；无法满足时保留该模板为未发布状态。

原业务概览切换控件在新岗位入口启用后移除，避免并存两套含义不同的岗位选择。既有业务权限、审批配置、任务责任和业务单据数据不得因入口调整而改变。

### 8.3 第二批：经营深度与效率分析

- 完善账龄、积压、客户及部门贡献、资金到期结构等分析。
- 建立可靠的阶段历史后提供询价转订单分析，明确统计队列、时间窗和分母。
- 建立承诺交期及调整记录后提供供应商和履约准时率。
- 建立目标录入、归属和调整规则后提供目标完成率。
- 建立业务风险标准后提供重大风险汇总。

第二批每项内容均须满足指标登记、权限核验和明细追溯要求，不以页面展示完成代替业务口径验收。

## 9. 验收清单

| 编号 | 场景 | 通过标准 |
| --- | --- | --- |
| AC-01 | 单岗位进入 | 用户登录直接进入对应岗位首页，名称、指标、图表和处理清单均符合该岗位 |
| AC-02 | 多岗位进入 | 首次选择默认工作台，后续按进入顺序恢复；切换后整体内容变化且账号间不串用 |
| AC-03 | 自定义角色 | 显式关联模板后按实际权限提供入口；只有相似角色名或业务读权限不得自动获得模板 |
| AC-04 | 权限变更 | 移除模板或收缩范围后旧页面、深链接及缓存均不继续暴露已撤销数据 |
| AC-05 | 统一待办 | 切换岗位及业务期间后全局待办总数不变；同一任务跨岗位出现时全局去重 |
| AC-06 | 执行边界 | 本人待办、团队待办和风险对象正确区分；管理查看权限不能替代执行资格 |
| AC-07 | 指标与明细 | 固定核验时点及样本下，汇总与下钻的对象集合、金额和数量一致 |
| AC-08 | 期间边界 | 月初月末、跨年和业务时区边界正确；存量指标不被期间误筛选 |
| AC-09 | 业务变更 | 草稿、生效、取消、变更、部分履约、部分收付、退款冲正按指标合同处理，无重复累计 |
| AC-10 | 金额授权 | 无成本或利润权限账号无法从卡片、图表、提示、明细及接口获得受限字段 |
| AC-11 | 数据缺失 | 零值、无范围、缺日期、缺成本、未配置口径和读取失败分别展示，不混用零值 |
| AC-12 | 经营口径 | 非卡券范围、含税与不含税、实际与预估、成本覆盖限制在首页与下钻一致 |
| AC-13 | 局部故障 | 单个模块失败可重试，其他模块和待办操作仍可用；刷新时间真实 |
| AC-14 | 操作后更新 | 完成任务或业务操作后相关内容更新，失效任务不能重复执行 |
| AC-15 | 页面差异 | 销售、采购、出纳完整样板体现不同业务重点，不能仅替换数字和标题 |
| AC-16 | 桌面及窄窗口 | 在 1440、1024、768 像素宽度下无整体横向溢出，导航、筛选和主要操作可用 |
| AC-17 | 可访问性 | 关键操作可使用键盘完成，图表可查看数据表，异常不只靠颜色区分 |
| AC-18 | 性能 | 在已记录的验收数据规模与并发条件下检查首批内容、主要模块、刷新请求量和接口延迟 |
| AC-19 | 原入口切换 | 原工作台入口进入正确岗位，任务深链接可达，既有业务操作合同保持成立 |

验收账号须覆盖各发布岗位、兼岗人员、自定义角色、受限金额权限、无数据范围和权限被撤销人员。不得使用超级管理员一个账号替代多岗位验收。

## 10. 交付物与完成条件

每个发布批次须交付：

1. 发布岗位清单、角色映射与默认入口规则。
2. 已发布指标的完整定义、数据就绪分类、业务确认记录及同口径核验样例。
3. 页面设计与实际运行页面，包含有数据、空数据、受限和失败状态。
4. 对应接口、权限裁剪、统计与下钻能力。
5. 第 9 节验收记录及未交付内容清单。

完成条件为：对应岗位能够从首页识别业务状况和优先事项，核心数字可追溯，兼岗切换不漏办，授权边界成立，发布范围内的页面、数据与交互验收均通过。

静态检查、编译成功、接口存在和页面截图分别作为不同证据记录，不得单独替代完整岗位验收。
