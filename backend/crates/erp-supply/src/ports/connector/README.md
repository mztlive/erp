# 供应商 Connector trait 合同

状态：方案及 trait 已确认；本模块只定义可编译的 Rust 接口和值类型，未接入运行路径。
业务基线与数据兼容要求见[第二期方案第 6、7、10、13、14、17 章](../../../../../../docs/erp-phase-2.md)。

## 审阅入口

按下列顺序检查接口职责、输入输出及恢复边界。

| 文件 | 必须检查的合同 |
| --- | --- |
| [mod.rs](mod.rs) | `SupplierConnector` 绑定连接；各能力独立可选；未提供的能力返回 `None` |
| [offer.rs](offer.rs) | 商品分页、增量覆盖、两种供货报价、可供数量、完整可售地区、地址准备与配送分组 |
| [order.rs](order.rs) | 单组创建、我方单号查单、独立支付确认、取消、单笔退款及正交状态 |
| [callback.rs](callback.rs) | 原始报文验签、正文保护范围、刷新线索与完整观察事实、持久化后应答 |
| [common.rs](common.rs) | 来源版本、时间、分页、动作身份、供应商幂等保证及分类失败 |
| [settlement.rs](settlement.rs) | 具有稳定身份的扣费、退款来源，不直接形成应付 |

## 适配器职责

1. 一个实例必须绑定一个已验证的 `SupplierApiConnectionId`。服务端装配供应商账号、环境、密钥、超时及限流配置；业务载荷及回调 `channel_no` 不得切换绑定连接。
2. 适配器只执行外部协议操作并归一结果，不读取 ERP 仓储，不修改公司商品、供给条款、正式订单或财务事实。
3. 所有异步能力必须支持 `dyn Trait + Send + Sync`。实例可共享，单次请求的可变状态不得保存在无隔离的全局变量中。
4. 必须实现自己声明的能力。连接拥有接口不代表商品或当前订单允许该操作；资格、权限、来源绑定及业务启停由领域重新校验。
5. 外部 ID 按字符串保存，不转整数。`SupplierSku.spec_id` 表示实际订货规格号，`product_id` 仅承载供应商商品分组。已有公司 SKU 与外部身份必须明确绑定，不自动建品或模糊匹配。
6. 公共合同使用人民币定点值。供应商报价无法确认币种、含税口径、计量单位或费用构成时必须拒绝映射；不得舍入后静默接受。数量必须满足非负/正值及单位精度约束。
7. 收件资料、配送上下文、回调正文及订单物流资料不派生 `Debug`。原始证据由接收层按敏感数据政策保存，普通日志只写脱敏摘要及业务关联号。

## 查询与同步

1. `OfferSource::scan` 只返回目录变化。新增供给仍须通过既有正式供给用例，同事务创建首版商业条款及初始可供投影。
2. 增量能力分别声明不支持、部分覆盖、完整覆盖。分页参数固定窗口和游标；时间精度转换向外扩展。当前页及后续处理意图可靠保存后才能推进游标。空页带游标仍须继续。
3. 扫描完成不表示源端提供一致快照；列表缺项、单次查询不可见均不得解释为删除、无库存或写请求未执行。
4. 一件代发与集采报价分别保存。供应商报价变化只生成待确认条款，不覆盖公司销售价；API 目录描述只提供绑定核验依据。
5. 可供数量区分精确值、来源明确不设上限、未提供。未知负数哨兵不得映射为零或无限库存。数量与品牌、商品、规格、区域、配送时段限制共同决定可供。
6. `SourceRevision::compare` 仅用于同连接、对象、字段组。单调序号还须同 scope；等值令牌只可判等。缺失版本、不同 epoch、不同令牌均不具备新旧顺序。
7. `changed_at` 缺失须保留缺失；签名时间、接收时间、查询时间不得冒充来源变更时间。`observed_at` 只说明已收到/读取，不能证明上游缓存新鲜。
8. 轮询频率、有效期、并发配额、失败退避和告警归调度层按连接及数据类型配置，本模块不硬编码“一分钟同步”或自动重试。
9. 无版本来源的推送与查询必须按对象串行协调，结合补查、状态机及来源可信度处理。重取也无法判断的冲突转人工，不能宣称靠接收顺序保证源端有序。

## 下单与恢复

1. 调用方必须先保存动作身份、载荷指纹、完整请求快照和执行意图，再在数据库事务外调用供应商。
2. 地址准备、订单创建、支付结果确认、取消、每笔退款分别保存独立动作。适配器每次写调用至多发送一次；连接中断、超时或 Future 被取消后可能已产生外部副作用，必须保留待调查状态。
3. `DeliverySource::prepare` 只准备供应商地址/用户引用；结果未知通过 `context` 恢复。不能恢复时转人工，不静默创建第二份地址或用户。
4. `DeliverySource::options` 返回完整拆单方案：每条请求明细恰好归属一组，各组至少有一个合法选项。调用方验证覆盖与数量守恒，冻结选项、费用和有效期，并为每组分配独立我方订单号。
5. `Orders::create` 只提交一组，返回外部单号和下一步。`ConfirmPayment` 要求装配 `PaymentConfirmation`；不得把 HTTP 成功、外部订单创建成功或支付确认成功解释为供应商已接单。供应商不支持期望价格条件写入时，创建后超出批准金额仍须保留已创建结果，阻断后续支付并登记异常；已自动扣款的订单进入补偿处理，不能承诺仅靠预查保证不涨价。
6. 创建结果未知先按 `OrderKey::Merchant` 查询。`NotVisible` 只表示当前不可见；无安全重放证明不得重新提交。供应商幂等保护只在已核实窗口、同键同载荷条件内成立，ERP 自己的幂等表不提供远端保证。
7. 支付确认结果未知通过原订单查询核验支付轨道。取消结果通过订单取消轨道查询；退款通过原动作 ID 查询单笔结果。能力不足、状态未提供或证据冲突须保留未知或转人工。
8. `ActionAccepted` 只表示请求受理。取消与退款分开记录；退款完成必须有单笔稳定退款号、金额和完成证据，订单累计退款额不得反复入账。
9. 来源状态映射复用既有履约、取消及退款枚举。每条轨道缺失表示未取得，不能清空既有事实；实际状态迁移仍由正式领域规则执行。
10. 实现必须在写入前校验非空明细、唯一行号、正数量、批准金额、连接及选项绑定。公共结构体是进程内合同，不作为未经校验的 HTTP DTO，也不是新增持久化 schema。

## 回调接收

1. `Callbacks::verify` 必须使用原始报文核对绑定连接、签名和时间窗口。返回 `EnvelopeOnly` 时 `observation` 必须为空，报文只作为刷新线索。
2. 正文已认证且包含完整业务事实时可返回 `Observation`，支持仅推送供应商；接收成功仍不代表事实已生效，领域负责幂等、版本及商业审核。缺少可靠排序且无法补查的冲突必须转人工。
3. 接收层必须可靠保存原始证据、来源身份及后续处理意图，再发送 `durable_ack`。HTTP 状态及应答正文由供应商协议决定；数据库不可用时不得发送成功应答。
4. 具有来源事件 ID 时按连接和来源 ID 去重；同 ID 异载荷必须作为冲突。没有来源 ID 时不得永久按“对象 + 状态”或报文摘要去重，防止丢失 A→B→A 的合法变化。
5. 品牌、商品等上级对象变化须刷新其已有供给。上级恢复不得绕过商品、规格的独立限制及内部暂停规则。未知外部商品只保留接收证据，不隐式建立公司商品。

## 既有代码衔接与实施边界

1. 本模块尚未替换 `SupplierApiGateway`、`SupplierGateway`，未修改既有持久化字段、Handler、路由、worker 或配置。旧网关继续服务现有业务流程。
2. 后续由 `erp-processes` 装配具体适配器，并将这些协议事实送入既有领域用例；先明确每个步骤的持久化恢复点，再切换旧调用方。禁止在旧 `dispatch` 内隐藏多步下单而丢失步骤回执。
3. 旧网关注释与本合同统一为单次写发送、分类结果及编排层恢复；`catalog_sync` 保留旧调用入口，新协议接口只返回来源事实，正式供给写入由 Process 调用领域用例。切换时必须落实编排职责，不能只做返回类型转换。
4. `erp-phase-2.md` §6.3、§13.1、§13.2 统一规定重复自动去重、可证明旧版本不覆盖、无法消解的冲突转人工；§10.3 使用独立履约、取消及退款轨道。新实现及验收必须使用同一规则。
5. 当前可供实体仍要求非空 `source_updated_at`，而目标合同允许来源时间缺失。按第二期 §14.1 完成存储、旧数据读取、写入校验与回滚兼容后才能启用；按 §7.4 分开来源时间、接收/观察时间和可靠核验时效。禁止用接收时间伪造来源时间。结算无稳定流水身份时保留原始证据并转人工核对。
6. 蛋糕叔叔应使用 `spec_id` 作为订货规格号，配送规则作为分组依据，`out_order_no` 作为我方订单号，并独立调用支付结果通知。`stock=-9999999` 的含义、推送补发、时间精度、幂等保护窗口及自动售后能力均须供应商确认后才能声明。
7. 启用前必须完成供应商 HTTP 客户端、回调路由、同步调度、连接装配及数据库兼容改造，并按第二期 §17 验收。当前交付仅包含接口定义和合同修订，不代表这些运行能力已经实现。

## 验证范围

必须通过受影响 crate 的编译、库单元测试、Clippy、workspace 编译及领域边界检查。单元测试验证缺省能力关闭与版本比较规则；它们不证明任一真实供应商的签名、幂等、同步时效或履约行为。
