# 工作台任务授权与关联材料合同

## 权限及数据范围

| 接口用途 | 功能权限 | DataScope 动作 |
| --- | --- | --- |
| 列表、筛选候选、统计、履约责任队列 | `work_item:list` | `work_item/list` |
| 任务详情、任务动态入口 | `work_item:detail` | `work_item/detail` |
| 转交、转交候选、关闭、放弃驳回处理 | `work_item:manage` | `work_item/manage` |

以上动作均通过公共 `DataScopeService` 解析。负责人范围取当前有效内部组织关系；公司范围不限制负责人，空范围不允许访问。已具备功能权限且未配置人员范围时，list、detail 默认读取本人负责的任务；manage 不提供默认本人范围。本人基础由标准 DataScope 表达式解析，历史参与、原业务单据权限不得绕过任务 DataScope。

新式追加范围与本人读取基础求并。旧式显式范围、显式拒绝条件继续保留原限制，不得因发布自动放开。

“我的”和“历史”视图必须在 list DataScope 内追加本人责任或历史参与条件。“管理”视图仅表示筛选方式，不额外要求 manage 权限。detail、list、manage 互不替代。

任务控制仍须满足原领域约束：审批任务禁止通用转交与关闭；关闭仅适用于允许受控关闭的异常任务；放弃驳回处理仅允许当前责任人。转交目标资格、幂等校验和任务版本校验继续执行。

审批决定、入库确认、付款确认等业务提交继续使用各业务接口的权限及数据授权。manage 不授予业务提交资格。

## 任务与材料边界

任务列表、详情及控制冲突投影只提供任务自身信息，以及关联业务对象类型、ID 和 `subject_version`。不得序列化客户名称、金额、商品行、业务摘要、物流明细或付款资料。任务搜索不得检索这些材料字段。

前端按任务关联读取对应业务接口。审批材料必须同时匹配单据类型、ID 和提交版本；销售资料必须匹配提交号或修订 ID；履约资料必须匹配履约对象 ID 和版本。缺失版本或版本不一致时停止展示并提示刷新，不得回退到最新资料。

材料接口自行执行其授权。返回 403 时，前端仅在该材料位置显示无权限占位；任务主体和已授权任务控制保持可用。材料读取失败后不得继续展示此前缓存的材料。

## 控制命令响应

转交、关闭、放弃处理成功时，响应数据为：

```json
{"id":"work-item-id","task_version":"8"}
```

响应直接取本次命令结果，不再要求 list 或 detail 权限。转交后任务离开原管理范围不得把已提交命令改报失败。客户端收到回执后重新验证任务缓存，不得把回执当作详情缓存。

版本冲突继续返回 409。只有当前 manage DataScope 仍覆盖任务时，冲突结果才附带任务投影；否则仅保留冲突信息。

## 发布与回滚

1. 发布前为使用工作台的角色配置 list、detail 以及需要的 manage 功能权限。list/detail 缺人员范围配置时默认本人，无需逐人补写数据；扩大读取范围和所有 manage 范围必须通过人员 DataScope 显式配置。不得以业务单据权限或任务归属自动补授功能权限。
2. 旧 `work_item:reassign`、`work_item:close` 不再是控制接口的准入权限。管理者须配置 `work_item:manage`；仅允许原单编辑的用户不会自动获得放弃处理权限。
3. 后端与本次客户端必须同步发布。成功命令响应及材料字段收缩不提供旧客户端兼容窗口。
4. 本次不修改持久化字段、索引或线上权限配置。回滚时同步回滚前后端；新增的角色授权应按发布前备份恢复，禁止扩大范围补偿客户端不兼容。
