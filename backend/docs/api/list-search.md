# 列表与选择器关键词搜索执行合同

## 1. 通用要求

- `q` 为可选关键词，服务端去除首尾空白；空白等同未提供。
- `q` 最大长度为 200；超限按现有参数校验错误返回。
- 文本字段执行忽略大小写的字面量部分匹配；正则元字符不得作为表达式执行。
- 关键词多个匹配字段之间采用 OR；关键词与结构化条件、权限范围之间采用 AND。
- 数据库分页必须在筛选后执行，结果与 `total` 必须使用相同条件。
- 分页排序必须包含唯一 ID，禁止只按可能重复的时间或编号字段排序。
- 原有 API 精确字段和权限要求继续有效，不新增读取权限。

## 2. 库存台账

适用接口：`GET /admin/stock-balances`、`stock-movements`、`stock-reservations`、`stock-adjustments`。

- 四个接口的 `q` 均匹配 SKU 编码、当前 SKU 修订名称或规格。历史修订不得造成命中。
- `sku_id` 与关键词解析结果取交集；无匹配 SKU 时返回空结果，禁止去掉条件重查。
- 余额接口接受 `balance_id` 和 `availability`。可用量为 `zero` 时严格等于零，`positive` 时严格大于零，`reserved` 时存在有效或部分消耗的预占。
- 调整单接口接受 `adjustment_id` 和 `sku_id`；SKU 条件匹配任一未删除明细，不限首行。
- 前端保留服务端 `total`，不得再对返回页执行关键词、数量或定位筛选。
- 库存指标继续使用其现有独立查询范围，不得用结果页条数替代。

## 3. 合同列表

适用接口：`GET /admin/contracts`。

候选按[列表筛选候选独立查询执行合同](../../../docs/query-selector-decoupling-contract.md) 第 11 章执行；合同列表与目录分别授权。

- `q` 匹配合同号、客户编号、当前合同修订内的客户名称和结算主体名称、当前客户负责人显示名。
- `settlement_party_id` 精确匹配结算主体；`owner_user_ids` 按稳定人员 ID 匹配当前客户主负责人；已废弃的 `owner` 姓名参数按组织与范围主合同拒绝。
- `metric` 接受 `all`、`effective`、`expiring_30d`、`expired`、`terminated`。
- `expiring_30d` 要求合同状态有效且有效期止位于上海业务日当天至第 30 天，两端包含；长期合同不命中。
- 页面默认排序为到期优先、有效期止升序、ID 升序。表头排序在服务端执行。
- 保留 `items`、`total`、`page`、`page_size`、`metrics` 及范围元信息；不返回 `settlement_options`、`owner_options`；候选分别使用 `/admin/settlement-parties`、`/admin/salespeople` 及各自 selected 端点。
- 普通候选按被选择对象自身的资格与 DataScope 查询，不受合同是否存在及合同筛选条件影响。
- 指标基于合同自身 DataScope、合法历史参与、`scope` 归属范围、`org_unit_ids`／`include_descendants` 组织条件及原有 `customer_id`、`contract_no`、`status` 参数。无授权仍返回零指标；不得退回公司范围。
- `q`、`metric`、`owner_user_ids`、`settlement_party_id` 只影响结果行和 `total`，不影响 `metrics`；排序、页码及页大小也不影响指标。筛选无匹配合同时，允许列表为空而基础范围指标非零。
- 负责人匹配必须在结果分支使用当前客户主负责人事实，不能先缩小列表与指标共用的客户集合；指标分支不能复用 `ContractSearch` 筛选。
- 列表、指标和跨页版本在同一授权事务快照内读取。版本索引覆盖基础范围，最多 10000 张合同；须在读取客户搜索事实和执行聚合前检查上限。超限必须收窄客户、组织、合同号或状态条件；仅增加关键词、负责人、结算主体或快捷指标不能缩小该索引，不得以截断指标绕过上限。
- 范围版本须纳入同一批客户编号、当前主负责人 ID 及显示名；不能仅依赖合同自身版本检测负责人交接或改名。外域事实按客户 ID 稳定排序后编码，读取顺序变化不得造成假冲突。
- 负责人搜索、排序及行显示继续复用同一批当前归属事实；销售人员候选不依赖该批合同事实。
- 前端禁止固定取 100 条、对结果再次切页或从当前页生成筛选候选项。

## 4. 集成异常队列

适用接口：`GET /admin/integration/error-tasks`、`GET /admin/integration/differences`。

- 异常任务 `q` 匹配任务 ID、业务对象 ID、消息 ID、最近处理摘要、错误分类及现有中文类别标签。
- 对账差异 `q` 匹配差异 ID、业务对象 ID/类型、差异类型、两侧证据引用及“对账差异”标签。
- 两类接口保留各自权限校验，不以一个接口的权限读取另一类数据。
- 前端逐页取得接口返回的全部匹配结果，再执行视图筛选、去重与队列排序；禁止固定只取前 50 条。
- 排序依次为现有风险优先级、创建时间倒序、对象类型、ID。队列指标统计最终匹配队列。
- 正式处理责任读取必须继续翻页，不得固定只读取前 100 项。
- 翻页失败、总数变化或结果重复时整次查询失败；禁止把已读取部分显示为完整结果。
- 本次保留前端组合完整队列，不提供服务端统一队列游标。空关键词或大匹配集会增加请求数量和内存占用；不得以任意截断上限掩盖此成本。

## 5. MongoDB 关键词补全

### 5.1 接口与字段

| 接口/对象 | 通用关键词参数 | 必须匹配的字段 |
| --- | --- | --- |
| 销售单列表与选择器 | `q` | 销售单号、客户当前法定名/简称、合同号 |
| 合同选择器 | `q` | 复用合同列表关键词范围，继续叠加客户、有效状态及归属范围 |
| 客户目录与选择器 | `keyword` | 客户编号、主体当前法定名/简称、统一社会信用代码 |
| 仓库列表与选择器 | `q` | 仓库代码、当前仓库修订名称 |
| 品牌 | `q` | 品牌代码、名称 |
| 分类与分类树 | `q` | 分类代码、名称 |
| 供应商订单 | `q` | ERP 供应商订单号 `fulfillment_order_no`、外部订单号 |
| 供应商结算 | `q` | 结算单号、外部账单号、供应商当前名称 |
| 供应商 API 连接 | `q` | 连接代码、供应商当前名称 |
| 公司 SKU `/admin/skus` | `q` | SKU 编号、当前名称/规格、商品编号、当前商品名称 |
| 履约作业 | `q` | 原有销售单号、采购单号、作业摘要/作业号，以及客户、供应商当前名称 |
| 工作台责任队列 | `q` | 授权显示事实中的业务单号/标题、往来方名称，以及原有对象 ID/类型、原因码、影响摘要 |
| 我发起的审批 | 既有关键词参数 | 原有对象 ID、节点、审批人，以及精确版本快照内的单据号、往来方/客户名称 |
| 审计事件 | `q` | 操作者 ID/名称快照、动作代码、对象类型/ID/安全标题、追踪号、请求号 |

- 上表为新增或补全范围。既有专用筛选参数继续执行原有匹配规则；不得将 `warehouse_code` 等精确字段改成模糊条件。
- 仓库 `warehouse_id` 精确定位选中项；采购收货选择器发送 `require_inbound_handler=true`，在分页前要求有效状态及非空收货经办人。
- 主体、仓库、商品名称以当前修订指针为准；历史修订不得造成当前名称命中。审批历史只允许匹配版本严格一致的冻结快照，不补读当前单据名称。
- 审计 `keyword_actions` 接收界面中文动作标签对应的动作代码，只并入关键词 OR，不替代权限或高级筛选。`event_id` 精确定位；`trace_id` 精确匹配追踪号或请求号；`created_from` 包含下界，`created_before` 不包含上界。
- 导入期初批次号继续执行字面量包含搜索；提示统一为“搜索批次号”，不得宣称精确或前缀匹配。

### 5.2 客户与供应商往来

客户往来三个 Tab 的关键词统一发送 `q`。应收、回款、销项发票均支持往来主体当前名称、销售单号、回款单号、发票号。

供应商往来的应付、付款、进项发票统一发送 `q`，支持供应商当前名称、采购单号、结算单号/外部账单号、付款单号、发票号。

- 每个 Tab 只返回该 Tab 的对象；关键词通过实际登记关系查找关联对象。
- 来源销售单直接关联应收账户；来源采购单或供应商结算单按 `source_type + source_document_id` 关联应付账户。
- 收付款通过分配记录及应收/应付分录关联账户；发票通过发票分配记录关联账户。
- 关联包含未删除的已登记分配历史，包括后续冲减的历史，以及回款待审批分配。搜索命中不代表当前仍有未结金额或有效占用。
- 未登记关系的单据不得因主体相同而被视为互相关联；没有分配关系的收付款或发票仍可由自身编号、主体名称命中。
- 原应收 `q` 对账户、销售单、客户、主体内部身份的检索兼容保留。
- 专用编号、主体、状态、方向、来源单据及权限限制与关键词命中集合取交集。应付 `source_document_id` 必须与来源类型同时使用于采购单定位。
- 未命中身份必须保留空集合条件；关联读取失败必须返回错误。禁止截取前 N 个候选身份后声称结果完整。

### 5.3 实现边界与分页

- Handler 负责原有入参及权限入口；跨域名称和来源单号由 `erp-read-models` 通过各领域公开仓储解析。
- 财务自有分配关系由 `erp-finance` 仓储读取；领域 Service 不依赖其他业务领域。搜索结果不引入第二份业务存储或异步索引。
- 原有单页列表继续使用服务端分页。财务匹配身份与既有范围在仓储合并后查询 `items` 和 `total`。
- 工作台必须先读取候选的授权和显示事实，再执行关键词匹配、累计总数及截取页；列表与适用统计复用同一关键词判定。
- 履约队列在 MongoDB 聚合中关联当前主体名称，并在结果、总数和指标分支前执行关键词条件。
- 供应商往来、审计和既有全量目录页面逐页取得完整匹配集合；不得固定只读取前 50/100 条。重复记录、总数变化、空中间页或请求失败时，整次查询失败。
- 非审计视图不得为展示审计总数而下载全部审计记录。
- 全量匹配集合读取会随命中数增加请求和内存成本；MongoDB 包含正则和跨集合 ID 条件须以真实数据执行计划与响应时间单独验收。不得以静态检查宣称性能已达标。
- 本次不新增实际利润、客户质量接口；仓库中缺少对应后端 handler 的搜索范围不作已实现声明。

## 6. 验收

- 单元测试覆盖字面量元字符、空条件、筛选交集、空权限范围、分页条件与计数一致、到期日期边界。
- 前端测试覆盖第 101 条合同、库存服务端总数保留、四视图关键词传参、集成队列多页及中途失败。
- 执行仓库规定的编译、静态检查、领域边界、权限漂移及库单元测试；不得启动真实数据库集成测试。
- 真实数据性能、MongoDB 查询执行计划和登录后页面验收须单独记录，不得由单元测试通过推定。

- 补全范围测试必须覆盖关键词与高级筛选并存、字面量元字符、来源类型配对、空身份零结果、当前修订/冻结版本边界，以及第 101 条和中途失败。
